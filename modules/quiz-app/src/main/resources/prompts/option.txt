Вход:

Сгенерируй 4 варианта ответа (MCQ options). Правильный ответ не дан заранее — определи его сам.

## Правило 0 — Single-Delta (главный принцип, приоритет #1)

Все 4 варианта МАКСИМАЛЬНО похожи друг на друга. Неправильные отличаются от правильного в ОДНОЙ детали:
- Одно слово в API-имени (`@AfterReturning` vs `@AfterException` vs `@AfterError` vs `@AfterExecution`)
- Один параметр типа (`Function<Integer, String>` vs `Function<String, Integer>` vs `Function<String>` vs `Function<Integer>`)
- Перестановка тех же элементов (`A→B→C` vs `B→A→C` vs `A→C→B` vs `C→A→B`)
- Одно число отличается (`size()=3` vs `4` vs `2` vs `Exception`)
- Один метод в цепочке заменён (`.map()` vs `.filter()` vs `.flatMap()` vs `.collect()`)

ЗАПРЕЩЕНО: варианты из разных концепций/технологий (один про HashMap, другой про Redis).
ЗАПРЕЩЕНО: один вариант — короткая фраза, другой — абзац.

## Правило 1 — Информационная глубина (приоритет #2)

Каждая опция содержит ОДИНАКОВОЕ число технических утверждений (1, 2 или 3).
Если correct называет 3 факта — каждый дистрактор тоже называет 3 факта (один из них ложный).

ЗАПРЕЩЕНО: correct=4 факта + distractor=1 факт.
ЗАПРЕЩЕНО: correct=300 символов + distractor=30 символов.

## Правило 2 — Строгая доменная изоляция

Все 4 опции — только про ТОТ ЖЕ класс/API/технологию, что в вопросе.
- Вопрос про Elasticsearch → все 4 опции про Elasticsearch
- Вопрос про HashMap → все 4 опции про HashMap
НИКОГДА: вопрос про ES, а дистракторы про Cassandra, RocksDB, Redis, «графовая БД».

## Правило 3 — Тип дистрактора (обязательна классификация)

Каждый из 3 дистракторов принадлежит одному типу:
1. Partial truth — большая часть верна, одна ключевая деталь сломана
2. Common misconception — реальное заблуждение middle-разработчика
3. Adjacent API mix-up — правильные факты про соседний класс/метод
4. Outdated fact — верно до версии X, сейчас неверно
5. Scope confusion — правильный механизм, неправильный уровень (экземпляр vs класс)
6. Plausible implementation mistake — почти правильный код с одним тонким багом
7. Correct mechanics, wrong condition — верно в другом сценарии, не в описанном

ЗАПРЕЩЁННЫЕ ТИПЫ (удаляет знание вопроса без знания темы):
- Другая технология (не из области вопроса)
- Выдуманные методы/флаги которых не существует
- Грубая инверсия («X — это обёртка над Y» где реально наоборот)
- Инверсионная пара «делает X» / «не делает X»
- «Всё вышеперечисленное», «Зависит от контекста»

## Правило 4 — Длина и форма

- Опция может быть 1-3 предложения, абзацем или содержать код (если тема поведенческая).
- Синтаксис одинаков во всех 4 опциях.
- Запрещены маркеры правильности: «верно», «правильный ответ», «на самом деле», «очевидно».

## Правило 5 — Explanation

Для каждой опции explanation (2-4 предложения):
- Для correct: объясни механизм + назови частую ошибку рядом с темой.
- Для distractor: объясни ОТКУДА заблуждение + ЧТО именно неверно + К чему это утверждение относится на самом деле.
- Не начинай с «Верно», «Правильно», «Корректно».
- Без советов по карьере и интервью.

## Финальный self-check

Перед выводом проверь:
- [ ] Ровно 4 опции, ровно 1 с correct=true
- [ ] Все 4 опции — про один и тот же предмет (класс/API/сервис)
- [ ] Каждый дистрактор правдоподобен для middle-dev
- [ ] Информационная глубина одинакова (N утверждений в каждом)
- [ ] Нет инверсионных пар
