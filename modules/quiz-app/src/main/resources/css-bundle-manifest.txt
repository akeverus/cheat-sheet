# Порядок каскада CSS — единственный источник правды.
#
# Читают этот файл двое: CssBundleService (собирает /css/bundle/{page}.{hash}.css)
# и TemplateFragmentContractTest (проверяет структурный CSS). Раньше порядок жил
# в head.html списком из 33 <link>, и шапка была единственным местом, где он
# записан; теперь шапка отдаёт один <link>, а порядок — здесь.
#
# Формат строки: <гейт> <путь от корня сайта>
#   *              — на всех страницах
#   focus,result   — только на перечисленных значениях параметра page
# Значения page: focus, result, settings, stats, bookmarks, summary, error, login.
#
# Порядок строк = порядок исходника внутри слоя. Приоритет слоёв объявлен первой
# строкой tokens.css: tokens, reset, shell, components, pages, utilities, pixel.
# Многие файлы объявляют больше одного слоя (pages-focus.css — pages+components,
# shell.css — shell+pages, pages-stats.css — pages+utilities), поэтому строки
# нельзя переставлять «раз слои всё равно разведут»: внутри слоя выигрывает
# последний, и перестановка меняет картинку.

* /css/fonts-local.css

# components-pending: ожидание как система (`data-pending` + `.pending-rune`).
# Гейт `*`: ждать умеет любая страница — отправка формы, экспорт, модалка,
# ответ на вопрос, отрисовка схемы. До iter-84 «занято» было четырьмя
# независимыми системами с четырьмя видами, и одна из них жила прямо в
# components-controls.css, неся ПЯТЬ копий исключения `:not(#interview-submit)`
# ради кнопки одной страницы.
# Позиция СРАЗУ ПОСЛЕ components-controls.css обязательна: селектор
# `[data-pending="action"][aria-disabled="true"]` равен по специфичности (0,3,1)
# правилу `.btn[aria-disabled="true"]` из controls, и спор равных внутри
# @layer components решает порядок исходника. Переставить строку выше — значит
# показать занятой кнопке вид «сломана» (opacity 0.55, cursor not-allowed)
# вместо «идёт работа», хотя `aria-disabled` она ставит именно для скринридера.
* /css/components-pending.css

* /css/components-card.css

# components-icons: базовая геометрия .px-icon (@layer components, глобально).

* /css/components-icons.css
# components-tabs: вкладка как система (iter-79). Гейт `*`, а не постраничный:
# полосы вкладок есть на трёх разных экранах (материалы вопроса, настройки,
# аналитика), и вид обязан находить их тем же селектором [role="tab"], которым
# их находит поведение (js/ui/tablist.js). Постраничный гейт означал бы, что
# четвёртая полоса заработает с клавиатуры, но приедет голой.
* /css/components-tabs.css
# components-notice: сообщение как система (`.notice` + тоны). Гейт `*` — и он
# здесь не роскошь: до iter-82 две трети системы жили в страничных файлах, и
# баннер «Сессия истекла» приезжал голым на четырёх страницах из шести.
* /css/components-notice.css

# components-empty-state: пустое состояние как система (`.empty-state` + части).
# Гейт `*` по той же причине, что у notice: до iter-83 система была разбита на
# три страничных копии, и одна из них (`.stats-empty`) вообще не имела правил —
# пять состояний /stats держались на соседнем `.card` и одном отступе из
# reset-layout.css. Позиция ПОСЛЕ components-card.css обязательна: компонент
# добавляет к коробке карточки свой вертикальный запас (`padding-block`), и при
# равной специфичности внутри @layer components спор решает порядок исходника.
* /css/components-empty-state.css

# components-answer: поверхность разбора ответа (вердикт, панели пояснения, разбор
# дистракторов, раскрытие «Подробнее»). @layer components, но файл двухстраничный:
# разбор рендерится только на .focus-page (JS #result-feedback) и .result-page
# (no-JS). Гейт в @layer components законен только потому, что ни один из его 45
# классов не встречается в остальных шаблонах (.search-answer-preview на /stats —
# другой токен, .answer его не задевает); там обычно живут кросс-страничные вещи.
# Это не комментарий-обещание: то же самое проверяет scripts/css-leak-audit.py —
# он читает гейты отсюда и ищет классы файла в разметке за их пределами.
focus,result /css/components-answer.css

# components-filter-bar: полоса отбора (/stats и /bookmarks). Тот же двухстраничный
# приём, что у components-answer, и та же цена: гейт законен, пока классы файла не
# встречаются в разметке за его пределами — это проверяет css-leak-audit.py.
# Позиция ОБЯЗАНА быть после components-card.css: `.filter-bar` снимает с полосы
# коробку карточки, а `html[data-design] .card` и `html[data-design] .filter-bar`
# равны по специфичности — спорят они порядком исходника внутри @layer components.
# До iter-74 правила жили в @layer pages (pages-stats.css) и выигрывали слоем;
# теперь выигрывают порядком, и переставить строку выше — значит вернуть полосе
# фон, тень и 24px полей.
stats,bookmarks,topics /css/components-filter-bar.css
