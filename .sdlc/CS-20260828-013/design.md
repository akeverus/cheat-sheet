## Решение

Написать `.sdlc/CS-20260828-013/report.md` — инвентарную карту документации
AS-IS по 5 рубрикам §5, в формате трёх предшествующих Phase 0-отчётов.

Метод — строго статический: `find`/`grep`/`git log`/`wc` по HEAD; каждое число
сопровождается командой в Приложении A; каждый факт — якорем `path:line`.

Правила письма (наследуются от CS-20260828-004):
1. Инвентарь, а не приговор: «файла нет / дата такая / ссылка ведёт в пустоту»,
   без «это плохо». Оценка допустима только в §10 (белые пятна).
2. Расхождение «документ vs код» фиксируется тройкой: цитата документа с
   якорем → факт кода с якорем → команда-доказательство.
3. Негативные утверждения документов не считаются расхождениями: `CLAUDE.md:58`
   упоминает `AIQuestionService`/`QuestionPromptBuilder` именно как отсутствующие
   — это корректный текст, а не битая ссылка. Проверка на «упомянутый класс
   отсутствует» обязана исключать контекст отрицания.
4. Пересечения с прошлыми отчётами не копируются: конфигурация, метрики, тесты
   уже разобраны в `.sdlc/CS-20260828-004/report.md` — здесь только угол
   «что об этом написано и совпадает ли с кодом», со ссылкой вместо копии.
5. Русский язык, потолок 700 строк, §0 — сводка на один экран.

Структура отчёта (жёсткая):
`## 0` Сводка · `## 1` Инвентарь документации · `## 2` README ·
`## 3` Архитектурная документация · `## 4` Продуктовая документация ·
`## 5` Доменная документация · `## 6` API-документация ·
`## 7` Свежесть и владение · `## 8` Дельта «документ vs код» ·
`## 9` Связность и навигация · `## 10` Белые пятна · `## Приложение A` команды.

Отвергнутые альтернативы:
- Секция на каждую из 5 рубрик и ничего больше — дельта и свежесть растворяются
  по секциям, теряется главный результат разведки.
- Аудит качества текстов (читаемость, стиль) — не рубрика §5, это другая задача.
- Запуск приложения ради снятия `/v3/api-docs` — нарушает статический метод и
  инварианты worktree; вынесено в follow-up.
- Инвентарь всех 1165 `.md` шпаргалок поимённо — объём без пользы; домен
  описывается агрегатами и правилами корпуса.

## Риски

- **Дрейф репо.** Параллельные loop'ы коммитят в `docs/` (например,
  `docs/frontend-redesign-state.md` правился в день задачи). Отчёт без SHA
  станет ложью. Митигация — SHA в шапке, все числа снимаются одним проходом.
- **Ложные «битые ссылки».** Наивный поиск «упомянутый класс отсутствует» даёт
  шум: JDK-типы (`ConcurrentHashMap`), SQL-ключевые слова (`COALESCE`),
  тест-классы, имена enum-констант и намеренные отрицания в `CLAUDE.md`.
  Митигация — правило 3 и фильтр по проектным суффиксам плюс ручная проверка
  каждого кандидата перед попаданием в §8.
- **Сползание в аудит.** «Документация запущена» — оценка, не факт. Митигация —
  правило 1: наличие/отсутствие с якорем, вердикты только в §10.
- **Объём.** 117 `.md` × детализация дают 1500 строк. Митигация — потолок 700
  строк, поимённо перечисляются только корень и `docs/*.md`, вложенные каталоги
  — агрегатами.
- **Соблазн починить.** Найденные расхождения (`prompts/README.md`,
  `package-info.java`, `CLAUDE.md`) чинятся одной строкой — но это правка кода
  вне `.sdlc/`, парковка харнеса. Митигация — только follow-up.
- **Дубль с прошлыми отчётами.** README-раздел про конфигурацию пересекается
  с §3 CS-20260828-004. Митигация — правило 4: ссылка вместо копии.
