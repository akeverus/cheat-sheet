# CS-20260826-004: scripts/lint-scripts.sh — мета-гейт целостности тулбелта

## Контекст

### Проблема

В `scripts/` живёт 45 исполняемых файлов тулбелта (7 `*.sh` + 38 `*.py`, из них
8 `*.py` в подкаталоге `scripts/readability/`). Ни один гейт репозитория их не
проверяет: `.pre-commit-config.yaml` гоняет линты по `cheatsheets/`, по
MCQ-сидерам и по CSS, а `.github/workflows/ci.yml` триггерится только на
`modules/**`, `gradle/**`, `*.gradle.kts`. Скрипты — слепая зона: синтаксическая
поломка обнаруживается в момент запуска скрипта, то есть в середине волны
авторинга MCQ или аудита, а не при правке.

Ирония в том, что часть гейтов репозитория **сама реализована** этими скриптами
(`scripts/verify-mcq-json.sh`, `scripts/cheatsheet-lint.py`,
`scripts/css-leak-audit.py`, `scripts/design-token-audit.py` — все прописаны в
`.pre-commit-config.yaml:1-58`). Сломанный скрипт-гейт = молча отключённый гейт.

Комментарий в самом `.pre-commit-config.yaml:36-38` формулирует принцип репозитория:
«Гейт, который надо помнить, не гейт».

### Что уже есть

Два образцовых shell-гейта задают стиль, которому надо следовать:

- `scripts/verify-mcq-json.sh` — `#!/usr/bin/env bash`, `set -euo pipefail`,
  ANSI-цвета через `[[ -t 1 ]]`, сбор файлов в массив через
  `while IFS= read -r ... done < <(...)` (process substitution, не пайп — иначе
  счётчик ошибок теряется в subshell), счётчик `ERR`, `exit 1` при ERR>0,
  `exit 2` при отсутствии внешнего тулинга.
- `scripts/verify-md-no-mcq.sh` — та же рамка, шапка-docstring с `Usage:` и
  описанием кодов возврата.

Docstring-шапка на русском — норма и для Python (`scripts/mcq-anti-tell-scan.py:1-10`).

### Замеры окружения (сделаны в этом worktree, 2026-08-26)

Всё, что ниже, проверено запуском, а не предположено:

1. **Сегодня все 45 файлов чистые.** `bash -n` по всем 7 `*.sh` → 0 ошибок;
   `python3 -m py_compile` по 30 top-level `*.py` → rc=0; по 8
   `scripts/readability/*.py` → rc=0. Значит гейт станет зелёным сразу, без
   правки существующих файлов.

2. **Есть шум на успехе.** `scripts/cheatsheet-autofix-v2.py:7` печатает в stderr
   `SyntaxWarning: "\s" is an invalid escape sequence`, при этом rc=0. Наивный
   `python3 -m py_compile scripts/*.py` без подавления вывода нарушит требование
   «вывод только по проблемам» на каждом запуске.

3. **Коды возврата различаются.** `bash -n` на битом файле даёт **rc=2**,
   `py_compile` — **rc=1**. Проверять надо `!= 0`, а не `== 1`.

4. **`py_compile` мусорит `__pycache__` — и это не безобидно.**
   `scripts/.gitignore:1` игнорирует `__pycache__/`, но один `.pyc` попал под
   версионный контроль ещё до этого правила и **отслеживается git**:
   `git ls-files scripts/__pycache__` → `scripts/__pycache__/cheatsheet-lint.cpython-314.pyc`.
   Проверено на себе: прогон `python3 -m py_compile scripts/*.py` без изоляции
   кэша сразу дал ` M scripts/__pycache__/cheatsheet-lint.cpython-314.pyc`
   в `git status`. То есть наивный гейт грязнит рабочее дерево при каждом
   запуске и ломает pre-commit. `PYTHONPYCACHEPREFIX=<tmp>` уводит `.pyc` в
   сторону — проверено: рядом с исходником каталог не появляется, `git status`
   чист.

5. **bash здесь 3.2.57** (`/bin/bash`, macOS; `command -v bash` → `/bin/bash`).
   Отсюда жёсткие ограничения: **нет `globstar`**, **нет `mapfile`/`readarray`**,
   и под `set -u` раскрытие `"${arr[@]}"` пустого массива — ошибка «unbound
   variable». `sort -z` в системном BSD sort работает (проверено).

6. **Инфраструктуры тестов для скриптов нет вовсе**: ни `bats`, ни `shellcheck`
   в PATH, ни `pytest`/`conftest.py` вне `modules/`. Значит тест — это отдельный
   самодостаточный bash-скрипт без внешних зависимостей.

### Ограничения

- DoD-команда зафиксирована и хеширована: `bash scripts/lint-scripts.sh` **без
  аргументов**, запуск из корня репозитория. Менять её нельзя.
- Гейт линтует и сам себя (он лежит в `scripts/*.sh`) — это желаемое свойство.
- Фикстуры с намеренно битым синтаксисом **нельзя** класть в `scripts/` под git:
  гейт покраснеет навсегда. Только временный каталог из `mktemp -d`.

## Решение

Добавить `scripts/lint-scripts.sh` — bash 3.2-совместимый скрипт со следующим
контрактом.

### Поиск файлов

```
TARGET = ${1:-<каталог самого скрипта>}
find "$TARGET" -name __pycache__ -prune -o -type f \( -name '*.sh' -o -name '*.py' \) -print0
  | sort -z
```

- Каталог по умолчанию резолвится от `BASH_SOURCE[0]`
  (`cd "$(dirname "${BASH_SOURCE[0]}")" && pwd`), а не от `$PWD` — скрипт
  работает из любого cwd, при этом DoD-команда из корня репо попадает ровно в
  `scripts/`.
- Необязательный первый позиционный аргумент = каталог-цель. Нужен только
  self-тесту, чтобы натравить гейт на временные фикстуры; для человека это ещё и
  «проверь вот эту папку».
- **Рекурсивно**, а не плоским глобом `scripts/*.py`: 8 файлов
  `scripts/readability/*.py` иначе остаются непроверенными, а гейт, который
  молча пропускает пятую часть тулбелта, — false green. Расширение скоупа
  безопасно: эти 8 файлов уже компилируются чисто (замер 1).
- Чтение через `while IFS= read -r -d '' f ... done < <(...)` — process
  substitution, как в `verify-mcq-json.sh`; имена с пробелами переживают.
- `.awk` (`scripts/extract-mcq-blocks.awk`) не покрывается: дешёвого
  syntax-only чекера у awk нет (`awk -f file /dev/null` исполняет BEGIN-блок).

### Проверка

- `*.sh` → `bash -n "$f"`
- `*.py` → `python3 -m py_compile "$f"` с `PYTHONPYCACHEPREFIX` во временный
  каталог (создаётся `mktemp -d`, снимается `trap ... EXIT`).
- Вывод каждой проверки **захватывается** (`out=$(cmd 2>&1)`), а не льётся
  напрямую. Печатается только при `rc != 0`: заголовок `FAIL <путь>` + вывод
  с отступом в 4 пробела (формат `verify-mcq-json.sh:56`).
- Цикл **не прерывается** на первой ошибке: инженеру нужен полный список
  поломок, а не по одной за прогон. `set -e` не должен убивать скрипт на
  падении проверки — вызовы обёрнуты в `if ! ...; then`.

### Вывод и коды возврата

| Ситуация | stdout/stderr | exit |
|---|---|---|
| Все файлы валидны, не-TTY (CI, pre-commit, DoD) | пусто | 0 |
| Все файлы валидны, stdout = TTY | одна строка-сводка `lint-scripts: N file(s) OK` | 0 |
| Есть поломки | `FAIL <файл>` + текст ошибки на каждую, затем `lint-scripts: K error(s)` | 1 |
| Каталог-цель не существует / найдено 0 файлов | строка с объяснением | 1 |
| Нет `python3` в PATH, а `.py` найдены | строка с объяснением | 2 |

«Вывод только по проблемам» соблюдается буквально в машинном режиме; TTY-ветка
через `[[ -t 1 ]]` (идиома уже используется в обоих shell-гейтах репо) даёт
человеку подтверждение, что скрипт отработал, и при этом не засоряет логи.

Пустой скоуп = ошибка, а не успех: молчаливый `exit 0` при нуле найденных файлов
маскирует запуск не из того каталога и опечатку в пути — самый вероятный способ
получить вечно-зелёный мёртвый гейт.

### Интеграция в pre-commit

В `.pre-commit-config.yaml` добавить хук (в конец списка):

```yaml
      - id: lint-scripts
        name: Тулбелт — синтаксис всех scripts/*.sh и scripts/**/*.py
        entry: bash scripts/lint-scripts.sh
        language: system
        pass_filenames: false
        files: ^scripts/.*\.(sh|py)$
        stages: [pre-commit]
```

`pass_filenames: false` — скрипт сам обходит каталог (та же мотивация, что у
`css-leak-audit` в `.pre-commit-config.yaml:41-48`); сигнатура остаётся ровно
DoD-командой. Безопасно включать сразу: сегодня все файлы зелёные (замер 1).

### Отвергнутые альтернативы

- **Плоские глобы `scripts/*.sh` / `scripts/*.py`** — буквальнее формулировки
  задачи, но оставляет `scripts/readability/` (8 файлов) вне гейта.
- **`shellcheck` вместо `bash -n`** — не установлен, даёт стилистические
  замечания и покрасит гейт на 45 существующих файлах.
- **`python3 -m compileall scripts`** — короче, но кэш пишется рядом с
  исходниками и вывод не гранулируется по файлам.
- **Флаг `--verbose` для сводки** — лишний интерфейс; `[[ -t 1 ]]` решает ту же
  задачу без аргументов.
- **Полностью немой `exit 0` даже в TTY** — буква требования, но человек не
  отличает «прошло» от «не запустилось».
- **Отдельная job в `.github/workflows/ci.yml`** — CI триггерится только на
  `modules/**`; добавление путей и job'ы вне заявленного скоупа задачи.
- **`git ls-files` вместо `find`** — не находит новый неотслеживаемый скрипт,
  то есть ровно тот, который чаще всего и сломан.

## Acceptance Criteria

1. Файл `scripts/lint-scripts.sh` существует; `bash scripts/lint-scripts.sh`
   из корня репозитория завершается с кодом 0 и **не печатает ничего** при
   перенаправленном stdout (не-TTY).
2. Гейт покрывает все 45 файлов: 7 `scripts/*.sh`, 30 `scripts/*.py`,
   8 `scripts/readability/*.py` — включая вложенные каталоги.
3. Любой `*.sh` с ошибкой синтаксиса даёт `exit 1`, и путь этого файла
   присутствует в выводе.
4. Любой `*.py` с ошибкой синтаксиса даёт `exit 1`, и путь этого файла
   присутствует в выводе.
5. `scripts/cheatsheet-autofix-v2.py` (даёт `SyntaxWarning`, но компилируется)
   гейт **не** роняет и его предупреждение в вывод не попадает.
6. При нескольких поломанных файлах в выводе перечислены **все**, а не первый.
7. Запуск гейта не создаёт и не изменяет ни одного файла в рабочем дереве
   (`git status --porcelain` до и после совпадает — в частности отслеживаемый
   `scripts/__pycache__/cheatsheet-lint.cpython-314.pyc` остаётся нетронутым);
   новых каталогов `__pycache__` в `scripts/` не появляется.
8. Гейт запускается из произвольного cwd и всё равно проверяет `scripts/`
   своего репозитория.
9. Скрипт исполняется системным `/bin/bash` 3.2.57 без ошибок про
   `globstar`/`mapfile`/unbound variable.
10. В `.pre-commit-config.yaml` есть хук `lint-scripts`; `pre-commit run
    lint-scripts --all-files` проходит.
11. Сам `scripts/lint-scripts.sh` и его self-тест проходят собственный гейт
    (лежат в `scripts/`, синтаксически валидны).

## Тест-контракт

Инфраструктуры тестов для скриптов в репо нет (нет bats/shellcheck/pytest вне
`modules/`), поэтому тест — самодостаточный bash-скрипт без внешних
зависимостей: набор функций-кейсов + мини-раннер, ассерты на `exit code`,
пустоту вывода и наличие подстроки. Каждый кейс поднимает свои фикстуры в
`mktemp -d` и убирает их `trap ... EXIT`.

**Жёсткое требование к телам:** битые фикстуры создаются только внутри
временного каталога. Ни один намеренно сломанный `.sh`/`.py` не должен
появиться под `scripts/` в git — иначе гейт краснеет навсегда.

- [new] `lint_whenPythonSyntaxBroken_thenExitsOneAndNamesThatFile`
- [new] `lint_whenSeveralFilesBroken_thenListsEveryBrokenFileNotJustFirst`

- [new] `lint_whenPreCommitConfigRead_thenContainsLintScriptsHookWithDodCommand`

## Риски

- **bash 3.2.** Самый вероятный способ сломать реализацию — написать
  `mapfile`/`globstar`/`${arr[@]}` под `set -u` на пустом массиве. Проверять
  запуском именно `/bin/bash`, а не homebrew-версией.
- **`set -e` глотает прогон.** Незавёрнутый `bash -n` на первом же битом файле
  завершит скрипт, и остальные поломки не будут показаны (нарушение AC 6).
  Проверки обязаны стоять в `if ! ...; then`.
- **`sort -z`.** Есть в BSD sort на этой машине (проверено) и в GNU coreutils;
  на экзотическом окружении без него сортировку можно снять — она нужна только
  для детерминированного порядка вывода, не для корректности.
- **Расширение скоупа до рекурсивного.** Если в `scripts/` когда-нибудь появится
  vendored-каталог (venv, node_modules), гейт начнёт линтовать чужой код.
  Сейчас такого нет; при появлении добавляется `-prune` по имени каталога —
  такой же, как уже заложенный для `__pycache__`.
- **pre-commit-хук блокирует коммиты.** Риск снят замером: все 45 файлов сегодня
  проходят; хук включается на заведомо зелёном дереве.
- **Фикстуры self-теста.** Если тела тестов положат битый файл под `scripts/`,
  DoD-гейт станет красным и не восстановится сам. См. жёсткое требование выше.
