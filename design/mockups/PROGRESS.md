## ГЛОБАЛЬНЫЙ МАНДАТ: полная ширина (юзер, it.11) — приоритет над центрированием

Требование юзера дословно: «При просмотре веба любого разрешения не должно быть
пустот справа и слева экрана, мы должны использовать его весь».

Следствие для ВСЕХ экранов:
- Хром (шапка/бары/фоны секций) — **edge-to-edge**, только внутренний `--gutter`-паддинг.
- **НИКАКИХ** центрированных `max-width` колонок с симметричными пустыми полями.
- Горизонталь широких экранов наполняем **реальным контентом** (app-shell: основная
  зона + правый/левый рельс), а не растягиванием строки прозы. Проза держит меру по
  `ch` ВНУТРИ зоны, структура тянется на всю ширину.
- Проверка (getBoundingClientRect): `leftVoid`/`rightVoid` = только gutter и симметрично;
  хром `span` = 100% vw.
- Реализация: `.wrap { width:100%; padding-inline: var(--gutter) }` + `.focus-grid`
  (main + `.focus-aside`, брейк 1080px). Отменяет прежний it.7-фикс с центрированной
  `.col` в clamp-шелле (тот оставлял боковые пустоты).

## Правки из UI/UX-критики (it.3) — что сделано

Источник: `~/Downloads/ui-ux-critique-focus-screen.md` (юзер). Разбито по приоритетам критика.

**P0**
- Состояния разведены: макет-переключатель (active / result / empty / done) — на экране
  ровно одно состояние (JS `[hidden]`). Убрано одновременное «вопрос + пусто».
- Код к вопросу показан сразу (`<details open>`); вопрос самодостаточен («…по коду ниже?»),
  один teal-токен вместо двух код-баннеров.
- Мобильная шапка компактная: нав → ☰, тема → иконка, одна строка (без второй «не влезло»).
- Keyboard-hints скрыты на touch/узких (`hover+pointer+min-width` гейт).

**P1**
- Мобильный заголовок меньше (clamp floor 2.1→1.75rem), hero line-height 1.2, `nowrap`
  вокруг токена, код в герое без плашки (mono+teal, не «баннер»).
- Разведены selected/correct/incorrect/focus: индикатор-кружок → галочка (форма, не
  только цвет); в разборе green-галочка / red-крест + теги «верный ответ» / «ваш ответ»;
  отдельное focus-кольцо; нативная radio-семантика.
- Основное действие — sticky нижняя панель на мобиле (safe-area), full-width.
- Убрано отладочное «состояние: нет вопросов».

**P2**
- Единый контейнер `.wrap` (60rem) для шапки и контента; читаемая колонка прижата к
  левому краю контейнера (одна композиция).
- Светлая тема: усилены тональные ступени (surface/surface-2/line/line-strong).
- Контраст мелких подписей поднят (ink-3 обе темы; бордеры карточек в тёмной).
- Кнопки без подчёркивания (`text-decoration:none`), ссылки — текстовые; радиусы едины.

**Мелочи:** «тема: авто» → контрол `◐ Авто`; `Ø` → иконка-воронка (пусто) / галочка (done);
прогресс толще (6px) и контрастнее; стрик приглушён; «Завершить сессию» → бордер-пилюля;
лейблы «Изменить фильтры» / «Начать новую тренировку»; варианты выровнены по длине/детализации.

   решим на проводке). Не баг — отметка.
6. **Touch-гейт подсказок** проверен только логикой media-query (эмулятор chrome не
   переключает pointer при resize) — на реальном тач-устройстве перепроверить.
7. **Порядок фокуса в app-shell (it.13, НА РЕШЕНИЕ ЮЗЕРУ).** После полноширинного
   релейаута (it.11) `.focus-aside` (с кнопкой «Завершить сессию») идёт в DOM ПЕРЕД
   `.focus-main`. На широких экранах рельс визуально СПРАВА, но Tab начинается с него
   (первый фокус = «Завершить сессию»), потом прыгает к вопросу слева — нюанс WCAG 2.4.3
   (порядок фокуса). Варианты фикса: (a) DOM main-first → вопрос первым по Tab на десктопе,
   но на мобиле прогресс уходит под вопрос ИЛИ кнопка «Завершить» визуально-сверху/таб-поздно;
   (b) оставить как есть (совпадает с мобильным «прогресс сверху», лёгкая десктоп-странность);
   (c) main-first + прогресс ПОД вопросом на мобиле (полностью консистентно «вопрос первый»,
   меняет мобильную раскладку). Рекомендация: (c) для чистого a11y, (a) если сохранять
   «прогресс сверху» на мобиле. Код НЕ трогал (UX-решение вынесено юзеру).
