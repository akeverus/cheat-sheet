## REF-001

- **ID:** REF-001
- **DATE:** 2026-08-22
- **OBJECTIVE:** Phase A — полный аудит текущего состояния фронтенда восемью параллельными направлениями (product-ux, ia-nav, visual-design, responsive, a11y-keyboard, tech-arch, assets-motion, history-decisions) и синтез в единый консолидированный документ с дедуплицированным бэклогом и STATE для Phase B.
- **PROBLEM:** Программа редизайна накопила 168 итераций и два расходящихся леджера (24_PROGRESS.md устарел на 108 итераций относительно frontend-redesign-state.md); скриншотный архив устарел на целую палитру (teal-эпоха при действующей «мастерской гильдии»); не существовало единой актуальной картины «что есть сейчас»: разрывы ядра цикла (optionless-тупик сессий, TRAINING без завершения), IA-долги (session-start под «Настройками», нерадресуемый вопрос), недотемизированный pixel-слой в light, мобильный фолд, 71% комментариев в CSS-корпусе и хвосты чистки ассетов были рассеяны по направлениям без приоритизации и дедупа.
- **EVIDENCE:** 144 сырых находки от 8 направлений аудита; все замеры — по живому приложению localhost:8080 (GET-only, обе темы, до 12 вьюпортов) и read-only SQL к живой БД; после дедупликации — 108 строк бэклога: 1×P0 (условный), 10×P1, 48×P2, 49×P3; плюс 26 позиций history-направления (14 инвариантов, 5 rejected/moot-решений, процессные грабли) вынесены в STATE.
- **DECISION:** Зафиксировать Phase A как завершённую; консолидировать находки в docs/frontend-refoundation-audit.md со строгой структурой (20 секций + сводный бэклог P0–P3 + STATE); дедуплицировать межнаправленные дубли (10 слияний, отмечены «также замечено»); противоречия между аудиторами (hero на главной vs REJECTED BASE-04; «невидимый» XP-флоатер vs мёртвый код) не решать молча, а зафиксировать в §15 как decision-gated; первым bottleneck выбрать UX-01 (optionless-тупик EXAM/MARATHON/STUDY) — единственный P0, детерминированная блокировка core-задачи, high confidence; квотные недоборы направлений зафиксировать честно (секция §152 с квотами в репозитории отсутствует — сверка по фактическим counts).
- **IMPLEMENTATION:** Созданы два файла: `docs/frontend-refoundation-audit.md` (шапка с источниками; секции 1–20: product model, visual language, IA, navigation, task model, responsive, components, tokens, pixel-art, motion, a11y, testing, strengths, weaknesses, contradictions, UX/visual/architecture debt, opportunities, redesign candidates; сводный бэклог 108 строк с ID-схемой UX-/IA-/VIS-/RSP-/A11Y-/ARCH-/AST-/HIST-; STATE с фазой, концептом, 14 инвариантами, rejected-списком, граблями, open problems, next bottleneck и квотами) и `docs/frontend-refoundation-changelog.md` (этот файл, запись REF-001).
- **TESTS:** n/a — итерация документационная, код и тесты не менялись.
- **VISUAL REVIEW:** По скриншотам прошлого цикла (work/redesign/artifacts) — ограниченно: весь архив снят в бирюзовой teal-эпохе и не соответствует действующему CSS «мастерской гильдии» (введён 2026-08-11); факт зафиксирован находкой VIS-11 (P2) с требованием переснять полный baseline (9 страниц × 2 темы × 3+ вьюпорта) первым шагом следующего цикла. Визуальные находки аудита опирались на свежие live-снимки аудиторов (обе темы, 1440/~500px и матрица до 2560), а не на устаревший архив; страницы result/session-summary визуально не покрыты (GET-only ограничение) — зафиксировано VIS-12.
- **ACCESSIBILITY:** Findings зафиксированы: 1×P1 (клавиатурная недоступность горизонтального скролла кода, WCAG 2.1.1), 3×P2 (угнанные хоткеи ↑/↓, потеря фокуса после оценки уверенности через native disabled, Space-раскрытие флешкарты), 5×P3 (недискаверабельная справка «?», h3 среди h2, мёртвые no-JS контролы, две цели вне ранговой системы, Esc без анонса) + межнаправленный дубль по pixel-motion-parity (нарушение контракта data-motion=on, слит в AST-08). ## REF-002

- **ID:** REF-002
- **DATE:** 2026-08-22
- **OBJECTIVE:** Закрыть UX-01 — детерминированный тупик вопроса без MCQ-вариантов внутри EXAM/MARATHON/STUDY-сессии.
- **PROBLEM:** Optionless-вопрос в сессии форсит `flashcardMode=true` (`FocusTrainingPageService:123-125`), что гасит форму `/answer` вместе с её escape-hatch «Не знаю ответа» (`focus-training.html`, гейт `!flashcardMode`). Оставался только browse-блок с GET-ссылкой «Следующий вопрос» — но при активной сессии ветка `interviewSession` приоритетна и GET рендерит `session.currentQuestionId()` снова. Ни один POST на странице не двигал сессию: выходы — сдаться (`/finish`) или пауза.
- **EVIDENCE:** Живой POST-репро: EXAM count=5 по `preparation/interview-preparation` → вопрос 9518, «Вопрос 1 из 5»; переход по `/?topic=…&mode=EXAM&excludeQuestionId=9518` → снова 9518, «Вопрос 1 из 5»; формы на странице — только `/question/note`, `/finish`, `/pause`. SQL: в топике 42 вопроса, **0** с вариантами (тема целиком флешкарточная). P0 подтверждён безусловно.
- **DECISION:** Альтернатива A (JOIN-фильтр optionless из состава сессии) ОТКЛОНЕНА: тема 42/42 optionless давала бы пустой экзамен — тупик заменялся тупиком. Выбрана B: внутри активной сессии заменить мёртвую GET-ссылку на form POST `/skip` — реюз готового механизма «честный UNKNOWN» MCQ-ветки (идемпотентность, ограниченный штрафной пул экзамена: penalty-запрос исключает вопросы сессии, пул темы исчерпаем). В STUDY-фазе LEARN форма не показывается (там «Проверить себя»; повторный skip зациклил бы LEARN). Альтернатива C (само-оценка «Знал/Не знал» с зачётом) — decision-gated: меняет скоринг экзамена, вынесена владельцу.
- **IMPLEMENTATION:** `focus-training.html` — browse-блок разведён на два контекста: GET-ссылка только при `interviewSession == null or finished`; при активной сессии — `form POST /skip` (`.flashcard-session-skip`, hidden questionId, авто-`_csrf`, кнопка «Не знаю — следующий вопрос →» с title-пояснением зачёта). `pages-focus.css` — зеркальные правила отступа и open-акцента для новой формы (токены, без литералов).
- **TESTS:** Новый контракт-тест `InterviewControllerTest.optionlessQuestionInsideExamSessionOffersSkipAndAdvances` (TDD: RED до фикса — mutation-доказательство, GREEN после): optionless-фикстура в EXAM обязана нести `action="/skip"`, не имеет права нести `flashcard-browse-next`, после skip односложная сессия завершена. Попутно починен хрупкий `statsFilterBandIsSingleFormOverSingleEndpoint`: якорь «единой системы кнопок» `btn next-btn` жил только в empty-state ветках /stats и молча зависел от порядка методов (первая записанная попытка наполняла user_topic_stats — ассерт падал); заменён на всегда-рендерящийся submit полосы отбора. Класс целиком GREEN.
- **VISUAL REVIEW:** Живой рендер обеих тем (Chromium): dark — кнопка в родной системе `.btn secondary-btn` с латунным open-акцентом под раскрытым ответом; light — computed охра/чернила на пергаменте. Скриншоты: `work/redesign/artifacts/refoundation/ux01-after-{dark,light}.png`.
- **ACCESSIBILITY:** Путь «дальше» стал нативной формой — работает без JS (проверено curl-ом: чистый no-JS POST двигает сессию), с клавиатуры (обычный submit-button), title поясняет следствие клика (§79 микрокопия); никаких новых live-регионов/JS-обработчиков.
- **REGRESSION:** Живой e2e после фикса: вопрос 9524 → skip → 9527, «Вопрос 2 из 8» (8 = 3 + 5 штрафных: exam-penalty на UNKNOWN работает, пул ограничен). Побочный эффект репро: 2 UNKNOWN-попытки (вопросы 9518-эпохи до фикса не записывались — форм не было; после фикса записана попытка на 9524 и одна на 9520 в браузерной проверке) в живой статистике темы preparation. Чужая in-flight дельта (print.css, session-summary.html, seed/mcq) не тронута — коммит строгим pathspec.
- **RESULT:** UX-01 закрыт: сессия из optionless-вопросов проходима на всех поверхностях (экзамен по теме preparation теперь можно пройти до итогов). Следующий bottleneck — **IA-01** (session-start похоронен под «Настройками»: все CTA «Собрать сессию» ведут в раздел с именем и h1 «Настройки»).

## REF-005

- **ID:** REF-005
- **DATE:** 2026-08-22
- **OBJECTIVE:** Закрыть VIS-01 (нечитаемый прогресс-чарт /stats) + вскрытый по пути VIS-02 (вкладки «меняют» классы, но не контент).
- **PROBLEM:** (1) VIS-01 сужен по §258: модуль topic-charts.js зрелее аудиторской формулировки (бюджет подписей с эллипсисом, autoSkip off осознанно, top-по-активности, цветовые пороги точности) — реальный дефект в том, что стек «Выучено + Осталось» не показывал прогресс: на живых данных learned 0–4 против total до 54 сегмент прогресса ≤7% высоты бара и на большинстве тем невидим; график отвечал «сколько осталось», а не «как я иду» (§84). (2) VIS-02 подтверждён как настоящий механический баг: pre-paint стиль восстановления вкладок (head.html) несёт правило с ID-специфичностью `:has(#панель) [role="tabpanel"]:not(#панель){display:none}` — сильнее component-`.is-active` — и живёт всю жизнь страницы; со ВТОРОЙ загрузки (ключ появляется после первого init) любые вкладки любой страницы пиннятся: клик менял классы, контент — нет; канвас «Динамики» инициализировался в панели с display:none (0×0).
