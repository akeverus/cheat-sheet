# Журнал UI/UX-рефакторинга

Единый источник состояния автономного loop-рефакторинга (skill `superpowers` +
`frontend-design` в режиме `ITERATE_EXISTING`). Одна итерация = одно завершённое,
проверенное, реальное улучшение. Перед каждой итерацией читать этот файл; сначала
чинить регрессии/недоделки, затем брать следующий приоритет. Держать компактным —
устаревшее вычищать, не превращать в бесконечный лог.

Полный технический бэклог с ID-шниками и коммитами — `work/superpowers/01_UIUX_VISIBLE_PASSES.md`
(gitignored). Здесь — только актуальная сводка.

## Стек и инварианты

- Spring Boot 3.3.2 + Thymeleaf (SSR) + vanilla ES-модули (`static/js/{core,ui,quiz,content,settings}`).
- Дизайн «instrument»: `html[data-design=instrument]`, `data-theme` dark/light, teal-акцент,
  функциональная (Dieter Rams) философия — рамки вместо теней, сдержанная палитра.
- CSS: `@layer tokens, reset, shell, components, pages, utilities, pixel` (порядок в `tokens.css`).
  Токены размеров — фикс. rem (`--font-size-xl`=1.75rem и т.д.). Кэшбастинг — content-hash (OPS-004),
  `?v=` НЕ бампать вручную.
- Проверка без Docker: чистые шаблон/CSS/JS-правки верифицируются живым рендером (bootRun UP),
  без gradle. Backend-правки требуют рекомпиляции → окно gradle только при погашенном bootRun.
- Live-sync: после правки `static/**` копировать source → `build/resources/main/...`, перезагружать
  с `ignoreCache`.

## Целевые уровни качества (проверено зрелым)

Эти поверхности осмотрены живьём (desktop+mobile, обе темы) и признаны зрелыми — не переделывать
без новой причины:

- Главная `/` (тренировка): MCQ- и флешкарта-режимы, чипы/мета/reason-строка.
- Поток ответа на MCQ (`quiz/interview.js`): защита от двойной отправки, loading («Проверяю…» +
  `aria-busy`), обработка `!ok`/timeout/network с инлайн-алертами, SR-анонс вердикта, клавиатура.
- `core/api-client.js`: CSRF, timeout, AbortController, ProblemDetail-нормализация ошибок.
- Тело разбора (контент): интро → таблицы (GFM) → списки → task-list чекбоксы → закрытие; рендер
  через `MarkdownRenderService.toHtml` (единственный prod-вызыватель — ответы/пояснения, НЕ шпаргалки).
- Страница ошибки `error.html`: статус-специфичные тексты 400/401/403/404/500, dev-details, действия.
- `/stats`, `/settings`, `/review`, `/bookmarks`: осмотрены, зрелые (см. леджер, UIUX-01…28).

## Открытые проблемы (приоритет)

1. **UIUX-05** (a11y, невидимый) — тумблер темы: в light `aria-pressed="true"` + `aria-label="Включить
   тёмную тему"` (противоречие + WCAG 2.5.3 Label-in-Name). JS `shell-scripts.html`. Не брал: durable-
   фидбэк требует ВИДИМЫХ улучшений; невидимый a11y-микрофикс откладывается.
2. **UIUX-21** (a11y, полу-видимый) — heading-order H1→H3 в теле разбора (перепрыг уровня). Fixable в
   `MarkdownRenderService.toHtml` (нормализация min-heading→h2) + `.answer h*` CSS для сохранения
   визуального масштаба. Требует backend-рекомпиляции + кросс-поверхностного QA. Отложено (тяжело для
   одного тика, низкая видимость).
3. **UIUX-16** (визуал, P3) — `/stats` «Что делать дальше»: большие числа 3 карточек на разной базовой
   линии (у карточки 3 доп-строка). Нужен взгляд — возможно намеренно.
4. **UIUX-02** (i18n, decision-gated) — англ. Title-Case у leaf-slug'ов таксономии («Design patterns»).
   Перевод техтерминов — продуктовое решение.
5. **UIUX-D1** (debt) — недетерминированная флакость `InterviewControllerTest` (общая Testcontainers-БД,
   нет cleanup между тестами; вопрос без MCQ форсит флешкарту). Нужна выделенная сессия.

## Итерации

### 2026-07-30 · Адаптивная шкала заголовков тела разбора (мобильная иерархия)

- **Проблема:** заголовок-вопрос `.focus-question` = `clamp(1.75rem, 1.2rem+2.4vw, 3rem)` на узком
  экране упирается в пол 1.75rem (28px), а заголовки-секции тела ответа фиксированы на
  `--font-size-xl`=1.75rem (28px, `reset.css`). Замер 390px: h1-вопрос=28.08px, h3-секция=28px →
  секции разбора визуально ⩾ вопроса, иерархия «вопрос → его разбор» схлопывалась.
- **Первопричина:** тело ответа наследовало ФИКС. базовый heading-масштаб, не масштабируемый под
  сужение экрана, тогда как вопрос — fluid clamp.
- **Решение:** дать `.answer h2/h3/h4` собственную fluid-шкалу (`clamp`), которая на десктопе упирается
  в те же reset-значения (десктоп-вид не меняется), а на мобильном плавно уменьшается. `@layer components`
  ниже `reset` → перебивает без `!important`.
- **Слои:** только CSS. `components-answer.css` (+18 строк). Backend/JS/шаблоны не тронуты.
- **Проверки:** живой рендер dark 390/753/1440 + light 768; консоль чистая; git diff = 1 файл.
  Десктоп 1440 идентичен (h1=48/h2=36/h3=28/h4=22 — упор в reset). Мобильный 390: h1=28.08 > h2=26.26 >
  h3=22.28 > h4=20.16 (иерархия восстановлена, отношение вопрос/секция 1.00→1.26).
- **Файлы:** `modules/quiz-app/src/main/resources/static/css/components-answer.css`.
- **Стало лучше:** на мобильном/планшете разбор читается как подчинённый вопросу; единый ритм
  заголовков на всех трёх поверхностях разбора (flashcard-browse, JS-feedback, no-JS result).
