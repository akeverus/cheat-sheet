# UXD-001 — Session-start: собственная поверхность `/train`

**Дата:** 2026-08-22 · **Статус:** ACCEPTED · **Итерация:** REF-003 · **Закрывает:** IA-01 (+ смежно IA-03 для deep-link'ов конструктора)

## Decision

Конструктор сессии выделяется из `/settings` в собственную поверхность **`GET /train`** («Собрать сессию»). `/settings` остаётся честными «Настройками» (вкладки «Оформление» и «Данные»). Нового пункта первого уровня навигации НЕ появляется: `/train` — поверхность-действие; активный раздел на ней — «Тренировка» (прецедент `/review`, см. javadoc NavSection).

## Problem

Все CTA с интентом сборки (7 входов: topics ×2, stats, session-summary, error, focus-empty, recoverable-banner) вели в раздел с именем пункта нав, `<title>` и h1 «Настройки». Information scent сломан (§167): пользователь жмёт «Собрать сессию» — попадает в «Настройки». Это же — нереализованный P1 целевой IA прошлого цикла (05_INFORMATION_ARCHITECTURE.md: «Тренировка (start): конструктор в /settings → Выделить session-start», target-маршрут `/train — собрать сессию`).

## Alternatives

1. **Переименовать раздел** («Настройки» → «Сессия и настройки» и т.п.) — ОТКЛОНЕНО: одна поверхность несёт две задачи (собрать сессию / настроить оформление и данные), одно имя не может быть честным для обеих; ярлык-кентавр ухудшает оба сцента.
2. **Собственная поверхность `/train`** — ВЫБРАНО: совпадает с валидированной целевой IA; убирает и IA-03-гонку для deep-link'ов конструктора (страница без вкладок — restore-механике нечего перебивать; `:has()`-правило самоприцельное и на /train не матчит).
3. **Контекстный заголовок /settings по интенту захода** — ОТКЛОНЕНО: URL и имя раздела продолжают лгать, ломается инвариант «навигация одна и из одного источника».

## Ключевые следствия

- `GET /train` принимает те же параметры префилла (topic/group/important/onlyWrong/shuffle/weakTopics/ordered/mode); конвейер модели — тот же, что у settings (resolveSettingsContext → buildSurfaceState).
- Легаси deep-link'и `GET /settings?<builder-параметры>` получают 302 → `/train?…` (сохранённые ссылки не ломаются; чистый `/settings` остаётся настройками).
- Все 7 CTA перенацелены на `/train`; в шапке /settings остаётся тихий мост «Собрать сессию →» (мышечная память).
- Form-ID конструктора (`filters-form`, `session-form`) сохраняются байт-в-байт — контракты POST `/start`/`/finish` не меняются.
- Вкладки /settings: 3 → 2, дефолтная активная — «Оформление».

## Tradeoffs / Migration cost

Правки в 4 контракт-классах UI-тестов (вкладки/фрагменты/панели) — легитимный §89-90 UPDATE (старое решение «конструктор = первая вкладка настроек» → REOPENED → SUPERSEDED этим документом). FRD-ссылка: решение «вкладки /settings Сессия/Оформление/Данные» (редизайн 2026-06-25, commit 0eb762a5) — SUPERSEDED BY UXD-001 в части вкладки «Сессия».

## Validation plan

Контракт-тесты: /train содержит h1 «Собрать сессию» + `session-form`; /settings НЕ содержит `session-form` и держит 2 вкладки; редирект легаси-ссылок; CTA-цели. Живой рендер обеих тем + мобильный 390; no-JS (формы серверные); POST /start с /train работает e2e.
