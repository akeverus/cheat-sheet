## Изменения теории

Q6 описывает конкретную таблицу **PIT 1.30.2 MATH**: `IMUL` заменяется на
`IDIV`, а не одновременно на сложение, вычитание и деление. Другая таблица
возможна у другого семейства, например AOR. Разобраны различающие `(5, 4)`,
совпадающие `(0, 2)` и исключение при целочисленном делении на ноль.
Неожиданное исключение может обнаружить мутант без явного сравнения результата.
[MATH 1.30.2](https://github.com/hcoles/pitest/blob/1.30.2/pitest/src/main/java/org/pitest/mutationtest/engine/gregor/mutators/MathMutator.java),
[PIT mutators](https://pitest.org/quickstart/mutators/),
[JLS 21, integer division](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html#jls-15.17.2).

Q9 предлагает разбирать изменение, покрывающие тесты, различающий сценарий
и наблюдение эффекта. Выживание не объявлено автоматическим доказательством
слабого assertion. Эквивалентность, пробел и принятый риск разделены;
ручная отметка не превращает surviving в killed и не пересчитывает score.

Q10 определяет эквивалентность на всей объявленной области входов и условий.
Пример `x + 0`/`x - 0` ограничен Java int. Старая пара `i < 10`/`i <= 9`
сохранена по смыслу, но явно содержит две правки. Одиночная boundary-подмена
`i <= 10` даёт 11 итераций вместо 10. Убрано автоматическое вычитание
equivalent из знаменателя.
[JLS 21, numeric addition/subtraction](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html#jls-15.18.2),
[PIT basic concepts](https://pitest.org/quickstart/basic_concepts/),
[Stryker equivalent mutants](https://stryker-mutator.io/docs/mutation-testing-elements/equivalent-mutants/),
[Stryker metrics](https://stryker-mutator.io/docs/mutation-testing-elements/mutant-states-and-metrics/).

## Все варианты и пояснения

Подробно проверены **12 вариантов и 51 точное пояснение** текущих трёх блоков.
Самопроверка автора и независимый результат сохранены отдельно.

- **Q6:** A/B описывают обнаружение или входы, но не преобразование MATH.
  C даёт полную ошибочную подмену сложением, D — верную подмену делением.
  A.if_it_were_true описывает фактически завершившиеся вызовы без проверки;
  связь с гипотезой «одного вызова достаточно» нуждается в ясной формулировке.
- **Q9:** C рассматривает только equivalent. D предлагает count-only анализ;
  автор допускает его как цельную ложную методику, reviewer сначала назвал
  частичным. Расхождение сохранено. Опровержимость wrong не доказывает ANSC.
- **Q10:** B/D обсуждают score и автоматизацию вместо определения термина.
  В D.if автоматическое разделение equivalent и пробелов ошибочно приравнено
  к отсутствию equivalent среди каждого surviving. Отчёт мог бы помечать обе
  подкатегории, сохраняя общий статус.

В пояснениях Q6/Q9 нужна редактура пробелов: `PIT1.30.2`, `даёт20`,
`Для(5,4)`, `значение18`. Корректное локальное related/source/how не обязано
заново отвечать всему вопросу. Правильный ключ не даёт RU/SFPL/ANSC PASS.
[Авторская проверка](evidence/mutation-math-equivalence-2026-11-06/author-review.json).

## Независимость и качество ревью

Свежий **gpt-6-luna / medium / fork_turns=none** сначала видел только
немаркированные варианты. Выборы **Q6 D / Q9 A / Q10 C** запечатаны CLI
до отдельного reveal; все совпали с ключами. После раскрытия рассмотрены
все варианты, 17 точных полей на блок, семь общих осей и первоисточники.

Ошибки самих отчётов не скрыты:

- Q6 C.what_actually ошибочно прочитан как неверный visible C, хотя это
  верное исправление IMUL→IDIV. Отдельный adjudication исправляет атрибуцию.
- Q6 raw содержит повторные общие OPEN-рубрики осей внутри полей. Они не
  засчитаны отдельными содержательными проверками; получен отдельный разбор
  семи общих осей. Неудавшаяся первая попытка без файла не засчитана отчётом.
- Q9 ANSC PASS был мотивирован только опровержимостью wrong при PARTIAL
  в оценках опций. Противоречие устранено отдельным решением OPEN.
- Q10 причины первых восьми полей сместились относительно цитат. Эти причины
  отклонены; исправления записаны по fieldID и сверены с точными текстами.
  Общий SECTIONS PASS отозван: ASSESSED означает чтение, а не принятие.

Счёт символов используется только для проверки утверждений ревьюера:
в Q9 A — 136 против B/C/D — 143/159/160, поэтому ключ не самый длинный.
В Q10 D — 101, C — 89. Ни длина, ни правильность не доказывают отсутствие
или наличие подсказки. SFPL остаётся OPEN.

## Проверки и ограничения

Переиспользованы четыре релевантные исторические JVM-проверки: различающие
арифметические входы, исключение без проверки значения, одиночная и двойная
подмена цикла, `int` identity на перечисленных значениях. Хеши всех трёх
исходников совпали с сохранённой квитанцией. Тела старых Q6/Q9/Q10 не менялись
между исходной квитанцией и началом текущего пакета.

Это **не четыре новых запуска** и не исполнение PIT. Несколько значений сами
не доказывают произвольную эквивалентность; для `int x ± 0` используется
правило арифметики. PIT 1.30.2 — версия прочитанного исходника, не движка.
Сборки, CI, Stryker, PIT и интерфейс пользователя не запускались.
[Проверка переиспользования](evidence/mutation-math-equivalence-2026-11-06/semantic-revalidation.json).

Производственный код и тесты не менялись; Java-схемы заменены таблицами
и пояснениями. IntelliJ не использовалась. Исторические code artifacts
сохранены в предыдущем коммите без нового форматирования.
