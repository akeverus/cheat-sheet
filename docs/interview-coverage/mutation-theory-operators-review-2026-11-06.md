# Mutation Testing: операторы, Q4/Q7

Исправлены только тела теории Q4/Q7. Общий пролог, остальные 18 тел, ID и заголовки, метаданные, оглавление и See also сохранены. Production MCQ JSON не менялся. Автор и отдельный бюджетный LLM-рецензент рассмотрели восемь опций и 34 поля пояснений. Общей приёмки темы нет.

Q4 теперь объясняет оператор как правило локальной подмены, показывает сравнения, арифметику, инкремент, возврат и void-вызов. Примеры конкретных механизмов привязаны к PIT 1.30.2. Уточнены границы INCREMENTS для локального iinc, числовые и boolean-возвраты, различие доступного и включённого оператора. Учтены байт-код, область и фильтры: похожая строка исходника не гарантирует мутантов, несколько операторов/инструкций не гарантируют несколько вариантов от каждого одного правила.

Q7 различает NEGATE_CONDITIONALS и варианты REMOVE_CONDITIONALS с true/false. Таблица чистого условия показывает: forced true отличается на исходном false, forced false на true; инверсию в этом примере можно обнаружить одним различающим входом при проверке эффекта. Посещение обеих веток не объявлено обязательным условием обнаружения любого условного мутанта. Современные операторы возврата отделены от старого RETURN_VALS. Для void-вызова показано наблюдение состояния без обязательного mock; логирование ограничено фильтрами PIT.

В Q7 каждый вариант называет семейство и предлагает механизм. Один содержательный пример достаточен: видимый вопрос не задаёт минимального числа операторов. B/C/D дают полноценные ложные модели; их ложность не делает их неполными. A верен, B приписывает число void-вызову, C переворачивает различающие входы, D смешивает возврат с аргументами. Видимые каркасы сопоставимы, ключ A не самый длинный: 142/148/131/160 символов.

Свежий `gpt-6-luna/medium` выбрал C/A до reveal. Фактические ответы запечатаны и не менялись. После раскрытия он проверил блоки по отдельности с текущей теорией. Пустые попытки записи не засчитаны; задача уменьшена до JSON-суждений, которые рецензент действительно вернул. Все 8 цитат опций и 34 fieldID/цитаты сопоставлены с замороженным production-снимком; пустые входные каркасы не считаются ревью.

Сам LLM-разбор также проверен. Рецензент сначала ошибочно не заметил имя Return Values в D Q7 и отозвал замечание о неполноте. В отчёте перепутаны истинность C Q7 и правильность новой теории: C как whole-утверждение ложно, что ожидаемо для wrong; это не ошибка ключа. Для Q4 A.if первая причина перевернула цитату, следующая отвергала контрфактуал реальным механизмом; узкая поправка оставляет только обоснованный вопрос к обязательности class-rewrite. Исходные ответы, противоречивые метки и поправки сохранены отдельно. Они не импортированы как формальная приёмка.

Q5/Q6 проверены по прежним принятым телам, Q4/Q7 — в текущем пакете. Q19 существует как ссылка об ограничениях, но его полная сверка ещё впереди. Навигация не дополняет неполную видимую опцию до выбора.

## Проверки и остаток

Все предварительные проверки прошли: schema, YAML (9 полей), anti-tell, отсутствие inline MCQ, diff check, current-run guard; linkage — 0 ошибок и 0 предупреждений. Зелёные сканеры не дают FINAL. Сохранены все 15 прежних приёмок, пары хешей MCQ/теории и PASS, а также исторические mutation scoped-final записи.

На локальном JDK выполнена малая ручная Java-модель: две строки таблицы чистого условия, состояние 1 против 0 после void-вызова/его пропуска и локальный инкремент/декремент от 5 до 6/4. Исходник, команды и stdout сохранены. Это проверка наблюдаемых последствий модели, а не генерация или исполнение PIT-мутантов, не проверка фильтров, score или CI. PIT/Stryker, установки, приложение, сборки, сервисы, Docker и IntelliJ-форматирование не запускались. UI не использовался; production-код и тесты не менялись.
