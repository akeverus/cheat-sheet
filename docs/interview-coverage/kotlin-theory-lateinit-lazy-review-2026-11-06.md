## Исправленные утверждения

| Прежнее утверждение | Новое поведение и доказательство |
|---|---|
| Для lateinit значение должно прийти извне | Требуется явное присваивание до чтения. Новый пример присваивает значение методом того же экземпляра, затем показывает повторную запись. DI и setup остаются примерами применения, а не условиями языка. |
| Lazy всегда инициализирован при доступе; блок вызывается один раз | Сохраняется успешный результат. После исключения следующий доступ повторяет вычисление. Пример проверяет false у Lazy.isInitialized после сбоя, успешную повторную попытку и последующее кэширование. Отдельно оговорён PUBLICATION. |

Таблица различает `Lazy<T>.isInitialized()` и проверку `lateinit`
`::property.isInitialized`, её область доступа, стандартный val-делегат и
var-хранилище объекта Lazy. Код с неопределёнными классами тестового сервиса
заменён самодостаточным `DeferredState`.

Проверены первоисточники Kotlin:
[ограничения lateinit](https://kotlinlang.org/docs/properties.html#late-initialized-properties-and-variables),
[getValue/setValue](https://kotlinlang.org/docs/delegated-properties.html),
[lazy API 2.4](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin/lazy.html),
[Lazy.isInitialized](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin/-lazy/is-initialized.html),
[PUBLICATION](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin/-lazy-thread-safety-mode/-p-u-b-l-i-c-a-t-i-o-n/)
и [NONE](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin/-lazy-thread-safety-mode/-n-o-n-e/).
Оговорки о синхронизации относятся к Kotlin/JVM; инициализация не делает
сам возвращённый изменяемый объект потокобезопасным.
