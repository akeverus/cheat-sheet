## Выводы по теории

1. **Блокирующих фактических ошибок не обнаружено.** Интерпретатор Python сам не обеспечивает соответствие аргументов аннотациям. Различие в Q1 между обычным немедленным вычислением аннотаций до Python 3.14, строковым хранением при `from __future__ import annotations` и отложенным вычислением по умолчанию начиная с 3.14 соответствует официальной документации. `annotationlib.get_annotations()` поддерживает форматы VALUE, FORWARDREF и STRING; вычисление в формате VALUE может завершиться ошибкой, а интроспекция аннотаций способна выполнить произвольный код. Теория правильно предупреждает об этом и не представляет аннотации как проверку внешнего ввода.
2. **Утверждения о generics и variance подтверждаются.** Синтаксис generic-функций Python 3.12 и прежняя форма с `TypeVar` корректны. `Sequence` ковариантен, изменяемые коллекции, например `list`, инвариантны; вывод variance применяется к generic-классам с новым синтаксисом. Пример не утверждает, что типовая аннотация гарантирует непустую последовательность.
3. **Ограничения Protocol описаны верно.** Q3 говорит о структурной совместимости без явного наследования и уточняет, что `@runtime_checkable`/`isinstance` не проверяют сигнатуры методов. Runtime-проверки протокола отделены от статического анализа и валидации входа.
4. **Утверждения о TypedDict в Python 3.15 подтверждаются.** Q4 правильно описывает `closed=True` и `extra_items=...` как взаимоисключающие контракты статической типизации, добавленные PEP 728 для Python 3.15. Дополнительные значения ограничены указанным типом, а типы объявленных полей сохраняются. Текст различает структурную открытость и требования анализатора к литералу/конструктору TypedDict, а также не приписывает этим параметрам разбор или runtime-валидацию JSON.
5. **Утверждения о TypeForm подтверждаются.** Q5 правильно указывает, что `TypeForm[T]` представляет допустимые выражения типа, включая объединения и параметризованные типы, которые шире `type[T]`; он статически связывает выражение схемы с `T`, но не реализует валидатор. PEP 747 определяет, что `TypeForm(x)` при выполнении возвращает `x` без изменений. Поддержка в стандартной библиотеке с Python 3.15 подтверждается.

Исправления теории, блокирующие прохождение, не требуются. Описание открытости Q4 сформулировано с нужными оговорками: PEP 728 и спецификация typing отдельно описывают структурную совместимость и проверку конструктора/литерала. Термины вроде «runtime-валидация» понятны в контексте.

## Первичные источники

Проверены 2026-11-05:

- Python 3.15 `annotationlib`, раздел «Annotation semantics» и предупреждение о безопасности: https://docs.python.org/3.15/library/annotationlib.html#annotation-semantics — обычное немедленное вычисление по умолчанию до 3.14, строковая семантика future-import, отложенное вычисление по умолчанию с 3.14; форматы `VALUE`, `FORWARDREF`, `STRING`; интроспекция может выполнять произвольный код.
- Python 3.15 `typing`: https://docs.python.org/3.15/library/typing.html — аннотации не обеспечиваются интерпретатором; семантика и добавление TypeForm в 3.15; определение `closed`/дополнительных ключей TypedDict и их взаимоисключение.
- Спецификация typing, generics: https://typing.python.org/en/latest/spec/generics.html — `TypeVar`, новый синтаксис generics, правила и вывод variance.
- Спецификация typing, Protocol: https://typing.python.org/en/latest/spec/protocol.html — структурная совместимость и runtime-checkable протоколы.
- Спецификация typing, TypedDict: https://typing.python.org/en/latest/spec/typeddict.html — открытость, обязательность ключей, дополнительные ключи и структурное поведение.
- PEP 728: https://peps.python.org/pep-0728/ — принятые для Python 3.15 `closed` и `extra_items`, их статический и runtime-контекст.
- PEP 747: https://peps.python.org/pep-0747/ — принятый TypeForm для Python 3.15, контракт для анализаторов и identity-поведение при выполнении.
