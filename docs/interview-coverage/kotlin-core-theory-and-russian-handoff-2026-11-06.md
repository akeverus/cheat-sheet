# Kotlin: передача замечаний теории и русскому тексту

## Требуется синхронизация теории

- **Q16 — подтверждённый дефект.** Первичный конструктор необязателен у класса со вторичными. Требование достичь первичного через this действует, если первичный объявлен. Иначе возможны this/super, а при единственном Any явное делегирование необязательно. Тело вторичного может содержать логику; init выполняется и без первичного. MCQ исправлен отдельным пакетом, теория Q16 ещё не исправлялась этим автором. Источник: [Kotlin specification](https://kotlinlang.org/spec/declarations.html#constructor-declaration).
- **Q24 — подтверждённое расхождение, ещё не исправлялось.** Теория слишком противопоставляет Kotlin declaration-site и Java use-site. Kotlin также поддерживает use-site projections: Array<out Any>, Array<in String>. MCQ C.sections.what_actually прямо отрицает use-site; B объясняет только место объявления и не раскрывает полностью дженерики и работу обоих модификаторов; A.sections сужает out до простого возвращаемого типа. Нужен отдельный полный проход, с учётом вложенных позиций и проекций, без упрощения всей вариантности до одного синтаксиса. Источник: [официальные generics docs, declaration-site и type projections](https://kotlinlang.org/docs/generics.html).
- **Q12 — языковая и содержательная очередь.** Схему `let/also → it, run/apply/with → this` можно пояснить естественным русским, сохранив имена API и возможность явно переименовать аргумент. Следует различать объектный run и перегрузку без объекта. A/D if_it_were_true делают недоказанные выводы о невозможности builder-паттерна и ненужности пяти функций. Варианты нужно оценить на полноту видимого вопроса, а не только перевести одну строку. Источник: [scope functions](https://kotlinlang.org/docs/scope-functions.html).
- **Q20 — следующий содержательный проход, ещё не исправлялся.** Краткую формулу lazy/lateinit следует раскрыть по-русски. Уточнять именно делегирование val через by lazy; не запрещать хранение самого Lazy-объекта в var. Ограничения потокобезопасности и внешней инициализации нельзя переносить на все платформы и все способы присваивания без проверки. В данном пакете этот вопрос не принимается.
