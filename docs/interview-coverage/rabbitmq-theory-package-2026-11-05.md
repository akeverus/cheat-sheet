Сохранены и проверены прежние изменения Streams. Дополнительно исправлены

- Для RabbitMQ 4.3 relative memory watermark по умолчанию 0.6, то есть
  60% обнаруженной RAM. Resource alarm блокирует publishing connections;
  consume-only соединения продолжают работу. В кластере alarm влияет
  на публикацию через все узлы. Transient flow control описан отдельно.
- По одной паре publish/ack rates нельзя доказать неизбежный рост backlog:
  важны scope счётчиков, auto-ack, TTL, overflow, reject/dead-letter и
  семантика queue/Stream. Таблица теперь даёт диагностические признаки,
  а не обещает однозначно определить утечку или зависание.
- Ссылки Q40/Q42 закреплены на RabbitMQ 4.3. API firstOffset проверен
  по исходнику Java Stream Client v1.12.0; добавлен NoOffsetException
  для stream без доступного offset. Unversioned RabbitMQ docs уже
  показывают 4.4, а stable Java API — 1.13.1, поэтому их не выдали
  за доказательство предыдущих версий.
