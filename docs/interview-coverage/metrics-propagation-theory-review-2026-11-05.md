## Исправления теории

**Q31:** формат version 00 отделён от правил обработки будущих версий; удалено «версия всегда 00». Поля примера согласованы с Q8/Q23. Убраны обещания сквозной трассировки без потерь от одного стандарта: нужны инструментация и корректные inject/extract. Sampled bit не гарантирует запись всех spans. [W3C Recommendation](https://www.w3.org/TR/trace-context/).

Разделены три режима настройки: ручной SDK builder, SDK autoconfigure и Boot/Agent. В **Java 1.37.0** OpenTelemetrySdkBuilder содержит no-op propagators по умолчанию; default tracecontext,baggage относится к autoconfigure. Убрано универсальное утверждение о W3C «из коробки с Java SDK 1.x». [Builder 1.37.0](https://github.com/open-telemetry/opentelemetry-java/blob/v1.37.0/sdk/all/src/main/java/io/opentelemetry/sdk/OpenTelemetrySdkBuilder.java), [Java configuration](https://opentelemetry.io/docs/languages/java/configuration/#properties-general).

**Q40:** W3C traceparent/tracestate названы прямо в собственном разделе. Показаны эквивалентные single/multi B3 как альтернативы; удалён self-parent X-B3-ParentSpanId. Для OTel B3 отдельно указаны запрет повторно использовать входящий span ID как новый server span и запрет inject X-B3-ParentSpanId. Это требования OTel, а не запрет optional parent header во всех исторических B3 реализациях. [B3](https://github.com/openzipkin/b3-propagation), [OTel B3 requirements](https://opentelemetry.io/docs/specs/otel/context/api-propagators/#b3-requirements).

Пример **Boot 3.3.2** принимает w3c/b3/b3_multi и отправляет w3c. Свойство type перекрывает оба тонких consume/produce; aws_xray не является значением enum этого свойства. Это подтверждено source, cached metadata/bytecode и реальным Binder на версии 3.3.2, без распространения вывода на все Boot версии. [TracingProperties 3.3.2](https://github.com/spring-projects/spring-boot/blob/v3.3.2/spring-boot-project/spring-boot-actuator-autoconfigure/src/main/java/org/springframework/boot/actuate/autoconfigure/tracing/TracingProperties.java).

Standalone Java Agent настраивается через otel.propagators / OTEL_PROPAGATORS и свои источники properties; Boot management.tracing.* не объявлен настройкой Agent. Composite выполняет propagators в заданном порядке и не обещает согласовать конфликтующие IDs. [Agent configuration](https://opentelemetry.io/docs/zero-code/java/agent/configuration/), [Propagators API](https://opentelemetry.io/docs/specs/otel/context/api-propagators/).

Неподтверждённый ContextPropagatingExecutorService заменён документированным **Context.taskWrapping(ExecutorService)** из Java Context API 1.37.0; явно описаны захват при submit, активный context, imports, фрагмент метода и shutdown. Пример только получает context из worker, а не сам доказывает его содержимое. Наличие auto-instrumentation может уже закрывать поддерживаемые пути: текущая таблица Agent содержит Java Executors и Kafka, поэтому гарантировать разрыв всех async/Kafka без ручного wrapper тоже нельзя. [Context 1.37.0](https://github.com/open-telemetry/opentelemetry-java/blob/v1.37.0/context/src/main/java/io/opentelemetry/context/Context.java), [supported libraries](https://opentelemetry.io/docs/zero-code/java/agent/supported-libraries/).
