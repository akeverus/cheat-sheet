## Что исправлено

Q5 теперь описывает таблицу `CONDITIONALS_BOUNDARY` **PIT 1.30.2**: меняется
включение равенства, а не числовой литерал. У подходящей инструкции задан
один counterpart. Подмены `>=` на `==`/`!=` не приписываются этому оператору.
Таблица для 17/18/19 показывает различие `>= 18` и `> 18` только на 18;
наблюдение эффекта отделено от простого выполнения условия. Исправлено прежнее
утверждение, будто 17 различает `>= 18` и `== 18`: для этого подходит 19.
[Исходник PIT 1.30.2](https://github.com/hcoles/pitest/blob/1.30.2/pitest/src/main/java/org/pitest/mutationtest/engine/gregor/mutators/ConditionalsBoundaryMutator.java),
[basic concepts](https://pitest.org/quickstart/basic_concepts/).

Q8 привязан к документированной модели **Stryker**: `detected = killed + timeout`,
`valid = detected + survived + no coverage`. Пример даёт 70%; отдельная метрика
по покрытому коду для тех же чисел — около 77,8%. Это вычисления по статусам,
а не запуск Stryker. Убраны автоматическое вычитание equivalent, запрет 100%
для любого набора и неподтверждённые процентные нормы качества.
[Статусы и метрики Stryker](https://stryker-mutator.io/docs/mutation-testing-elements/mutant-states-and-metrics/),
[эквивалентные мутанты](https://stryker-mutator.io/docs/mutation-testing-elements/equivalent-mutants/).

## Проверка MCQ и самого ревью

Автор перечитал весь Markdown и парный JSON для контекста. Текущий подробный
экзаменационный проход ограничен **двумя блоками: 8 вариантов и 34 пояснения**.
Это не повторная приёмка всех 20 блоков.

Свежий `gpt-6-luna / medium / fork_turns=none` получил сначала только
немаркированные варианты. Q5 B и Q8 NO_VALID_OPTION запечатаны CLI до reveal.
Рецензент ошибочно исключил timeout из detected; после чтения документации
признал ошибку. Исходный выбор Q8 не заменён на B и не объявлен blind PASS.
Начальная ошибка формата form_signals исправлена только обёрткой строки в
список; содержание, выборы и исходный файл сохранены.

Первые 34 оценки пояснений были одной шаблонной рубрикой. Они не засчитаны
содержательным разбором: отдельно получены exact follow-ups с каждой цитатой
и конкретной причиной. Ошибки этих follow-ups также сохранены:

- Q5 A ошибочно приписано верное утверждение о равенстве из теории.
  Видимый A утверждает различие на далёких значениях и ложен.
- Q5 B приписан полный список четырёх пар из explanation. В видимом B только
  две пары; пояснения не считаются видимой подсказкой.
- Q8 A.what_actually ошибочно получил FAIL, хотя цитата прямо даёт правильные
  detected/valid и отсутствие автоматического удаления equivalent.
  Этот вердикт отклонён при проверке точного текста.
- Длина не подтверждает тезис «ключ длиннее»: Q5 B/D — по 122 символа;
  Q8 B — 125, A — 131, C — 126, D — 140. Эти числа сами по себе не дают SFPL PASS.

В Q5 A остаётся вопрос полноты: он описывает ошибочное расположение
различающих входов, но не саму трансформацию. Законченное ложное предложение
не автоматически отвечает на «как работает». C даёт полную ложную модель
изменения числа: для целого `>= 19` может совпасть по поведению с `> 18`,
но это не подтверждает механизм PIT.

В Q8 D.if_it_were_true нужно ограничить контрфактуал ровно **100%**.
Видимый D обещает доказательство только при 100%, а пояснение отрицает
возможность любого высокого score при неверном правиле. Например, 99%
сама эта гипотеза не исключает. Это точнее первоначальной причины рецензента,
который смешивал принятую гипотезу с реальным поведением тестов.

В обоих блоках нужны пробелы в пояснениях: `при18`, `значения17`, `PIT1.30.2`,
`из10 valid`, `Даже100%`. JSON оставлен владельцу MCQ. Правильность ключей
не закрывает ANSC, SFPL или RU.
