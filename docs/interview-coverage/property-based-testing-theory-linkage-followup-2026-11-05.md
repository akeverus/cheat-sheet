## Воспроизведение дефекта Q2/Q18

В `reproduce_mutation_gap.py` извлечены действительные определения из Markdown без Hypothesis-декораторов. В локальном namespace вместо вызываемой сортировки подставлена функция, которая сортирует исходный список, удаляет один элемент и возвращает тот же список.

На `[2, 1, 2]` она вернула `[1, 2]`. Прежние Q2/Q18 прошли: `Counter(result) == Counter(values)` сравнивал результат с тем же уже изменённым входом. Результат упорядочен, но потеряно одно вхождение `2`. Для контроля Q7/Q17, уже использовавшие снимок Counter до вызова, отвергли ту же подмену. Воспроизведение сохранено **до изменения Q2/Q18** в `mutation-gap-before.json`, снимок MD `ab45f077eb97682d06026cd035582b0c7e5f6a6b9efa3e93fabf0d20eb44ae0d`: он уже включает новую прозу Q1, но ещё старые fences Q2/Q18.

Исправление обоих примеров:

```python
before = Counter(values)
result = sort_under_test(values)
assert Counter(result) == before
```

Этот фрагмент — схема изменения, не самостоятельный тест: реальные проверенные функции и их импорты находятся в Q2/Q18. Порядок результата проверяется отдельно. Сохранность исходного порядка входного списка не требуется: допустимая in-place сортировка, сохраняющая состав, проходит этот контракт. Для объектов со сложными ключами/состоянием потребовалось бы отдельно определить глубину снимка; текущий домен — целые числа.
