<a id="pixel-nav-badges-e01"></a>
## pixel-nav-badges-e01 · pixel-nav-badges.css:30

**Контекст:** `html[data-design] .sidebar .nav a:hover .px-icon,`

Цвет иконок — семантические токены, а НЕ фиксированные --px-*.
   Замер на живой странице: --px-* объявлены на `html[data-design]` одним набором
   тёмных значений без светлой ветки, поэтому в светлой теме иконки навигации
   красились тёмно-темовыми цветами по светлому фону: #f7b83f = 1.65:1,
   #35c987 = 2.00:1, #5db8ff = 2.01:1 при полу WCAG 1.4.11 в 3:1 для значимых
   элементов интерфейса. Цвет здесь — единственная кодировка разделов, то есть
   он значим, а не декоративен.
   Семантические токены несут обе ветки и дают 4.99–5.63:1 в светлой при
   ПОБАЙТОВО тех же значениях в тёмной (#f7b83f, #35c987, #5db8ff — это и есть
   их тёмные значения). Тёмная тема не меняется вовсе, светлая выходит на AA.

## pixel-nav-badges-e02 · pixel-nav-badges.css:52

**Контекст:** `html[data-design] .sidebar .nav a.active:focus-visible {`

АКТИВНЫЙ ПУНКТ ТОЖЕ ОБЯЗАН ПОКАЗЫВАТЬ ФОКУС. Маркер выше и кольцо фокуса
   (shell.css) рисуются ОДНИМ свойством box-shadow, а box-shadow не складывается
   каскадом: правило-победитель заменяет список целиком. Слой pixel идёт последним,
   поэтому маркер перебивал кольцо, и ровно у того пункта, на котором человек стоит
   сейчас, фокус переставал быть видимым (WCAG 2.4.7). Замер до правки (Chromium,
   Tab по рельсу на /topics): у «Тренировки» box-shadow — двухслойное кольцо,
   у активных «Тем» — только `inset 4px` маркера.
   Чинится составлением списка, а не отменой одного из двух: видны и маркер, и кольцо.
