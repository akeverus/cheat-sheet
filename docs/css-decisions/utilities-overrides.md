# utilities-overrides.css — досье решений (ARCH-02)

Полные доводы и история правил, вынесенные из комментариев `utilities-overrides.css`
(REF-009): эссе читают при ПЕРЕСМОТРЕ решения, а не при каждом чтении файла.
У правила в CSS остаётся указатель с тезисом; якоря ниже — цель указателей.
Рабочие инварианты («НЕ менять», пороги) остаются в CSS.

<a id="utilities-overrides-e01"></a>
## utilities-overrides-e01 · utilities-overrides.css:107

**Контекст:** `html[data-design] .stats-page .topic-table thead {`

Шапка на телефоне — полоса сортировки над карточками, а НЕ спрятанный thead.
     Раньше её клипали как visually-hidden (подписи колонок несут data-label ячеек),
     и это было верно, пока заголовок был просто подписью. С iter-81 в заголовке
     живёт единственный на странице орган управления порядком строк — и замер
     (WebKit@3, 390×844) показал, во что превратился клип: ссылка «Тема» — 1×24px,
     то есть указателем в неё не попасть в принципе. Сортировка существовала только
     для клавиатуры, через `thead:focus-within`, который её на время раскрывал.
     Телефон терял половину контроля над таблицей: объём («Показать все темы») ему
     доступен, порядок — нет.
     Вторую копию полосы рядом не заводим (§24): те же <th>, другая раскладка.

<a id="utilities-overrides-e02"></a>
## utilities-overrides-e02 · utilities-overrides.css:186

**Контекст:** `html[data-design] .stats-page .topic-table td[data-label] {`

Строка «ПОДПИСЬ — значение» внутри карточки.
     Была сеткой `minmax(90px, 0.42fr) minmax(0, 1fr)` + `justify-self: end` у
     значения. Замер (WebKit@2, 360×780, root=25px — телефон при 200% текста):
     ячейка 158px, подпись держит свой пол 90px, значению остаётся 43px, а ссылка
     «Тренировать» — цельное слово шириной 139px. Перенос ей запрещён, ужаться она
     не может, а `justify-self: end` прибивает её ПРАВЫЙ край к правому краю колонки
     — поэтому лишнее уезжает ВЛЕВО и ложится поверх подписи «ДЕЙСТВИЕ». Текст
     поверх текста, читать нельзя (WCAG 1.4.4 Resize text).
     Флексом та же пара переносится: не хватило места рядом — значение уходит на
     свою строку, а `margin-left: auto` держит его у правого края и там. Подпись при
     этом остаётся на своём месте в любом случае.

<a id="utilities-overrides-e03"></a>
## utilities-overrides-e03 · utilities-overrides.css:220

**Контекст:** `html[data-design] .stats-page .topic-table td[data-label="Прогресс"] .topic-progress {`

У «Прогресса» значение — не полоса, а колонка `.topic-progress` (полоса + строка
     «N из M»). Тянуть надо именно её: это прямой ребёнок ячейки, а полоса лежит на
     уровень глубже. Первая попытка целилась в полосу — и промахнулась дважды: во-первых
     мимо флекс-контейнера ячейки, во-вторых `.topic-progress` сама выложена колонкой,
     где `flex-basis` задаёт ВЫСОТУ. Замер показал ровно это: полоса 120×60 вместо
     120×6 — вместо полоски получилась «таблетка».
     Колонке отдаём остаток строки, полосе внутри — всю ширину колонки; базу 120px
     держим прежней, чтобы на узком экране полоса переносилась целой, а не огрызком.

<a id="utilities-overrides-e04"></a>
## utilities-overrides-e04 · utilities-overrides.css:303

**Контекст:** `html[data-design] .stats-page .learning-metrics-grid {`

P0.4: свод «Метрики обучения» получил 5-ю группу «Попытки» (всего/верных/ошибочных).
   Прежний фиксированный repeat(4) (стр. ~1913) + брейкпоинт-правила 4→2→1 (стр.
   ~3888/3900) оставляли 5-ю карточку «сиротой» на своей строке. auto-fit + minmax
   само-балансируют раскладку на любой ширине (широкий экран → сколько влезет,
   узкий → 1 колонка), поэтому переопределяем их одним правилом в конце файла —
   отдельным помеченным блоком, чтобы не пересекаться с параллельными правками
   base.css. Правило без @media: минимальная колонка 190px, min(100%,…) даёт
   корректный single-column на телефоне без горизонтального переполнения.
