# components-code-highlight.css — досье решений (ARCH-02)

Полные доводы и история правил, вынесенные из комментариев `components-code-highlight.css`
(REF-009): эссе читают при ПЕРЕСМОТРЕ решения, а не при каждом чтении файла.
У правила в CSS остаётся указатель с тезисом; якоря ниже — цель указателей.
Рабочие инварианты («НЕ менять», пороги) остаются в CSS.

## components-code-highlight-e01 · components-code-highlight.css:1

**Контекст:** `@layer components {`

@layer components — тема подсветки синтаксиса (highlight.js).
   ---------------------------------------------------------------------------
   Заменяет вендорную `vendor/hljs/styles/atom-one-dark.min.css`. Причина замены
   не в эстетике: та тема зашивала восемь HEX-констант и `background:#282c34`, то
   есть НЕ реагировала на тумблер темы. Замер на светлой теме (фон панели
   #f7fbfa): жёлтый `#e6c07b` давал ~1.4:1 — подсветка делала код ХУЖЕ, чем
   отсутствие подсветки. Плюс чужая тёмная подложка внутри панели, у которой уже
   есть свой `--color-bg-tertiary`, — тот же класс дефекта, что и «кто владеет
   холстом» (см. design-system.md §3).

   Здесь цвета берутся из палитры продукта: код подсвечивается теми же teal/
   амбер/пурпур/blue, что и остальной интерфейс, и переключается вместе с ним.
   Правило то же, что для диаграмм: «Диаграммы — часть системы, а не картинки».

   Токены `--code-*` определены в tokens.css в обеих темах и откалиброваны на
   AA (≥4.5:1) против трёх поверхностей, на которых реально лежит код:
   --color-bg-tertiary (панель «Пример кода»), --color-surface-soft и
   --color-bg-secondary. Худшие пары: dark keyword 5.06, light comment 5.51.

   Классы hljs 11.x. Группировка — вендорная (её знает грамматика), значения —
   наши. `.hljs` без фона: подложку задаёт панель, в которой лежит листинг.
