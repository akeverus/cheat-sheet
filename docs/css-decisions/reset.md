# reset.css — досье решений (ARCH-02)

Полные доводы и история правил, вынесенные из комментариев `reset.css`
(REF-009): эссе читают при ПЕРЕСМОТРЕ решения, а не при каждом чтении файла.
У правила в CSS остаётся указатель с тезисом; якоря ниже — цель указателей.
Рабочие инварианты («НЕ менять», пороги) остаются в CSS.

<a id="reset-e01"></a>
## reset-e01 · reset.css:113

**Контекст:** `html[data-design] ul,`

Меры чтения здесь НЕТ — сознательно. `p` всегда несёт прозу, поэтому мера на
   теге верна. `ul`/`ol` в этом приложении прозой почти не бывают: разметочный
   аудит дал 8 рукописных <ul> в шаблонах, и все 8 — структура (сетка тем,
   список закладок, карточки ошибок, навигация). Прозаические списки приходят
   только из markdown и живут внутри .markdown-content — там мера и стоит.
   Пока мера была на теге, она резала ровно те случаи, для которых не
   предназначалась: замер @2560 давал .topic-catalog-grid 818px при родителе
   1120px (4 ряда вместо 2) и .bookmark-list 818px одной колонкой. Каждая
   страница чинила это своим `max-width: none` — к iter-63 таких исключений
   накопилось три. Правило снято, исключения удалены.
