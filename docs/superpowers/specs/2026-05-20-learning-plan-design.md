# Дизайн: персональный план самообучения (B) + cleanup заметок Здоровья (A)

**Дата:** 2026-05-20
**Статус:** утверждён в брейнсторминге
**Скоуп этой сессии:** только (B) — план самообучения. (A) Здоровье — следующей сессией.

## 1. Контекст и цель

Пользователь — senior-разработчик с пробелами в знаниях, которые сам не может точно назвать. Хочет:

1. Цельный план самообучения, построенный на:
   - шпаргалках `cheatsheets/interview/` (25 категорий, 171 файл)
   - общих шпаргалках `cheatsheets/*` (16 категорий, 526 файлов)
   - функционале `quiz-app` (Spring Boot приложение для генерации MCQ)
   - сохранённых ссылках в Google Chrome (Profile 3, 253 КБ)
   - заметках в SingularityApp (особенно в проекте «Учёба»)
2. Чтобы план был **цельный и логичный**, не «избранное на все темы».

**Жёсткие ограничения**, заданные пользователем:
- Бюджет: **1 час в будний день** = 5 ч/неделю = ~20 ч/месяц.
- Это значит максимум 1 тема за неделю; план на 6 месяцев = ~20-25 тем.
- Цель смешанная: подготовка к интервью + ритм роста + закрытие конкретных пробелов («ответ 1+2+3, я уже сеньор»).

## 2. Архитектура

Трёхфазная структура:

```
Phase 0 (эта сессия)        Phase 1 (артефакты)             Phase 2 (рутина)
──────────────────          ───────────────────             ─────────────────
Я: диагностика  ──────────► Markdown-план в репе       ──► Ты: 1ч/день × 5 дней
   аудит шпаргалок,            ├─ контекст & бюджет           по фиксированному
   букмарок, заметок,          ├─ что я нашёл (gaps)          weekly-ритуалу
   quiz-app данных             ├─ backlog 8-10 тем            
                               ├─ формат недельного цикла   Singularity:
                               └─ источники по темам          таски на текущую
                                                              тему (Пн-Пт)
```

**Ключевые свойства:**
- План — **статичный документ**, не TODO-лист. Backlog меняется редко, цикл повторяется.
- Singularity = **execution layer** только текущей недели. 6-месячный план в задачах не храним.
- Жёсткое правило: 1 цикл = 1 неделя = 5 часов = 1 тема.
- **YAGNI:** тема попадает в backlog только если на неё указывают ≥ 2 сигнала. Без conviction — не включаем.

## 3. Диагностика — методология

Шесть сигналов, каждый по отдельности слабый, пересечение даёт уверенность:

| # | Сигнал | Где | Что означает «пробел» |
|---|---|---|---|
| 1 | `interview/TOC.md` | 40 КБ структурированный список | какие темы пользователь сам считает важными |
| 2 | Размер `interview/*.md` | `wc -l` по 171 файлу | < 200 строк = поверхностно проработан |
| 3 | Дата последней правки | `git log --format=%ai` по файлу | старое + тонкое = заброшено |
| 4 | Asymmetry interview vs general | пересечение каталогов | тема есть в `interview/`, но нет в `cheatsheets/*` без `interview/` = знаю «для собеседования», но не «для работы» |
| 5 | Chrome bookmarks (Profile 3) | парсинг `Bookmarks` JSON | много букмарок без шпаргалки = «читал, но не консолидировал» — главный сигнал |
| 6 | Singularity заметки | поиск keyword'ов учёбы | прямые сигналы намерения («Поучить X», «Высоконагруженные приложения») |

**Бонус:** `quiz-app` SQLite/Postgres — если в БД есть трекинг неправильных ответов или историй сессий, это сильнейший сигнал. Если данных нет — фиксируем в плане «нет evidence из quiz-app».

**Правило агрегации:** тема попадает в backlog только если ≥ 2 сигнала. Например: тонкая шпаргалка (#2) + 5 букмарок в Profile 3 (#5) → твёрдый кандидат. Только #1 (есть в TOC) — недостаточно.

## 4. Структура plan-документа

Один файл: `docs/learning-plan/2026-05-20-self-learning-plan.md`. Семь разделов:

1. **Контекст** — уровень, цель, бюджет, горизонт, жёсткое правило.
2. **Диагностика** — таблица источников сигналов (что взято, дата снимка) + таблица найденных пробелов (тема → сигналы → rank).
3. **Backlog** — 8-10 тем, приоритизированных. Для каждой: Why (evidence), Done-when, источники (свои шпаргалки + букмарки + внешнее).
4. **Формат недельного цикла** — фиксированный 5-дневный паттерн (Пн: чтение, Вт: holes, Ср: hands-on, Чт: MCQ, Пт: расширить cheatsheet + commit).
5. **Singularity integration** — id проекта, id таск-группы, шаблон названия тасков, правила обновления.
6. **Правила пересмотра** — что делать если 2 недели подряд не закрыл цикл, месячный re-run диагностики.
7. **Источники** — свои шпаргалки по темам backlog, букмарки сгруппированные по темам, внешние ссылки только если из букмарок.

Главное свойство: **evidence-driven**. Каждая тема в backlog имеет видимые в таблице сигналы — пользователь может оспорить любую.

## 6. Граничные случаи и риски

| Риск | Как обрабатываем |
|---|---|
| `quiz-app` DB пустая / нет session-таблиц | Отмечаем в плане «no quiz-app evidence», idёт без сигнала #7 |
| Chrome Profile 3 — не активный профиль | Спросим, если найдём странности (например, все букмарки 2024 года) |
| Тонкая шпаргалка, но это потому что тема простая | Rank-формула учитывает только пересечение с другими сигналами (#5 / #6) |
| Слишком много кандидатов (>15) | Берём top-10 по rank, остальные — в «дополнительный backlog» |
| Слишком мало (< 5) | Расширяем порог «<200 строк» до «<400» и заново |

### 9.3 Pattern цикла (фиксированный, 5 micro-task)

Каждый цикл в master-чеклисте имеет одинаковую структуру:

```
☐ 1. Прочитать свою шпаргалку <X>
☐ 2. Просмотреть закладки <Y> → выписать holes
☐ 3. Закрыть holes — точечное чтение
☐ 4. Hands-on (код / диаграмма / writeup)
☐ 5. 20 MCQ через quiz-app ≥80% + commit cheatsheet
```

Pattern определяется один раз в шапке master-страницы и НЕ дублируется per cycle. В цикле — только title + 5 чекбоксов.

### 9.4 Backlog (~67 циклов в 22 phases)

Phase 1 (priority, из диагностики) = 9 циклов. Phases 2-22 = покрытие всего: алгоритмы, Java/Kotlin/Go, Spring, БД, архитектура, DE, messaging, API, cloud, DevOps, observability, security, testing, performance, JVM, code-quality+patterns, behavioral+leadership, тренажёры (SQL/Git/Docker/K8s/DSA), misc.

Полный список — в `docs/learning-plan/2026-05-20-self-learning-plan.md` секция 3.

**Горизонт:** ~16 месяцев чистого времени при 5h/неделю; реалистично ~2 года с пропусками.

### 9.5 Анти-паттерны (что мы НЕ делаем)

- Не создаём 5 задач на цикл (был §5).
- Не дублируем micro-task в каждом цикле (pattern определён единожды).
- Не помещаем источники (URL букмарок, пути файлов) в Singularity — они в repo markdown.
- Не трогаем T-c9b610cc (старый backlog из 2025-01) — оставляем legacy.
- Не делаем sub-задач, time-stats, тегов на циклах.
