# Аудит MCQ — состояние на 2026-09-14

Обновление корпуса **не завершено и не принято целиком**. Структурная проверка всех
318 JSON проходит. Исторические 176 отметок `AUDITED` не подтверждают полноценную
приёмку текущего содержания. По согласованному с пользователем экономному скоупу
прочитаны 44 блока; остальные 4 972 блока обновлённого множества оставлены в точной очереди.
После правок теории четыре из 44 требуют повторного ревью.

Уточнение приоритета: [действующий план](../PLAN_INTERVIEW.md) выделяет отдельную
проверку **SFPL/ANSC** — чтобы correct не выделялся формой и полнотой на фоне wrong.
Добавлен `form_review_queue`: все 5 016 обновлённых блоков, с приоритетом автоматических
SKEL/anti-tell сигналов. Это отдельный скоуп, который не сокращается общей вычиткой 44
блоков; подтверждённого отдельного покрытия формы пока нет. Само содержание корпуса
в этом уточнении не переписывалось.
Автосигналы есть у 2 717 из 5 016 блоков; оставшиеся 2 299 также требуют сравнительного
ревью. Сигналы включают предупреждения и не считаются автоматически доказанными дефектами.

По следующему уточнению добавлен самостоятельный критерий **RU** — человекочитаемость
на русском. [Протокол](mcq-quality/russian-readability-rules.md) охватывает видимые вопросы,
теорию, все варианты и объяснения. Существующие readability-эвристики повторно используются
в инвентаре; дополнительно сканируются вопрос/теория и проза `example`/`related`.
[Таблица проверок всех 318 файлов](mcq-quality/file-checklist.md) генерируется из того же
JSON-снимка и показывает обязательные проверки по каждой теме. Редакторская приёмка RU
остаётся UNVERIFIED до реальной вычитки в выделенном пакете, независимо от автосигналов.

Работа выполнена локально на `master`, исходный HEAD
`24fe6f6f9b370c30165ca9eb02895a8389f869a6`. Commit/push не выполнялись.
Все 146 исходно изменённых путей сохранены без изменения их SHA-256.

## Содержание: вычитанные блоки и находки

Три дешёвых агента `gpt-5.6-luna`, отдельные контексты, по одной теме. Прочитаны видимые Q,
тела, все A/B/C/D и sections: Java functional interfaces — 14, Spring transactions — 15,
Hibernate caching — 15. Выборка не случайная и не репрезентативная: на весь корпус её
результаты не распространяются. Первоначальные замечания к заведомо неверным wrong
перепроверены; их ложность сама по себе исключена из дефектов.

| Исправлено | Изменение | Доказательство / ограничение |
|---|---|---|
| Spring transactions Q5 | NESTED rollback возвращает к savepoint; исправлена противоположная ячейка таблицы | [Spring transaction propagation](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/tx-propagation.html) |
| Spring transactions Q14 | Новый поток не наследует родительскую TX; repository.save может открыть собственную | [Transactional API](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/transaction/annotation/Transactional.html) описывает границу thread-bound TX; режим repository требует отдельной конфигурационной оговорки |
| Spring transactions Q15 | Уже committed REQUIRES_NEW не откатывается вместе с внешней тестовой TX; нужен cleanup | [Spring test transactions](https://docs.spring.io/spring-framework/reference/testing/testcontext-framework/tx.html), [propagation](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/tx-propagation.html) |
| Java functional interfaces Q4 | Runnable/Callable явно названы сравнением из java.lang/java.util.concurrent, а не членами java.util.function | [Java SE 21 package API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/function/package-summary.html) |
| Java types Q2, две sections | NUL заменён на буквальное обозначение `\u0000` | Runtime уже удалял NUL; проблема была в потере обозначения символа, а не в доказанном падении текущего импортера |

JSON трёх вычитанных тем не переписывались. Последняя правка Java types найдена
структурным сканированием, не входит в 44 содержательно прочитанных блока.
Остальной неестественный язык, например архаизированные формулировки Java types,
не исправлялся массово и не объявлен качественным.

**Четыре повторных проверки:** Spring transactions Q5:B0, Q14:B0, Q15:B0 и Java functional
interfaces Q4:B0. Исходные review-хеши сохранены; отдельно записаны resolution и новые
хеши. По блочным зависимостям прежняя проверка остальных 40 блоков остаётся CURRENT.
CURRENT означает применимость вычитки, а не отсутствие замечаний и не AUDITED.

**Семь открытых замечаний для проверки по источникам:** functional interfaces Q3
(граница JLS и реализации invokedynamic); Spring transactions Q2, Q7, Q8, Q12
(Java/XML конфигурация, СУБД/isolation, phantom и readOnly/Hibernate); Hibernate caching
Q10 и Q12 (provider serialization и различие consistency/isolation). Их степень
подтверждения и следующий шаг указаны в `issue_queue`; это не автоматически семь
доказанных неверных ключей. Они сохраняются даже для уже прочитанных блоков.

## Как продолжить экономно

1. По следующему согласованному бюджету взять небольшой пакет из `form_review_queue`
   или `readability_review_queue`, выполнить [сравнительный протокол SFPL/ANSC](mcq-quality/surface-parity-rules.md)
   и отдельный [RU-проход](mcq-quality/russian-readability-rules.md).
   Зафиксировать каркас и полноту всех A/B/C/D, отдельно от правильности ключа.
   Автосигналы определяют приоритет, но их отсутствие не доказывает готовность.
2. Закрыть четыре STALE и семь конкретных замечаний; можно совместить с пакетом формы.
3. Отдельно решить runtime-контракт нескольких блоков Q3/Q8 CompletableFuture.
4. По согласованному бюджету брать следующие блоки из `review_queue`. Там все
   4 972 ещё не вычитанных блока и четыре STALE, всего 4 976; ID содержит путь/Q/B.
   Множество 142 TODO не смешано с этой очередью и остаётся в `files`.
5. Для каждого пакета: авторская правка → структурные проверки → разбор сигналов формы
   и linkage → независимое содержательное ревью → настоящий слепой пакет/проверка формы
   там, где это требуется приёмкой → фиксация coverage, источников и хешей.
6. Полная приёмка файла требует покрытия всех его блоков. Новую модель не заставлять
   повторно читать закрытые неизменённые блоки только из-за смены провайдера.

Блочная привязка включает JSON блока (включая sections), Q/slug, видимый заголовок,
тело соответствующего Q и общий пролог темы. Изменение пролога инвалидирует все Q.
Межвопросные смысловые зависимости и смену стандарта рецензент оценивает отдельно:
хеширование не является доказательством отсутствия таких зависимостей.
Восстановление исходных блочных хешей сделано только из байтов, совпавших с полными
SHA-256, записанными агентами; новые правки не выданы за старое ревью.
