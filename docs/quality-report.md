# Отчёт о качестве

Состояние на момент последней верификации. Не журнал — снимок. Все числа получены
прогоном, а не оценкой.

## 1. Как воспроизвести

```bash
docker compose up -d postgres

# полная верификация (тесты + jacoco-гейт)
JAVA_TOOL_OPTIONS=-Dapi.version=1.41 \
DOCKER_HOST=unix://$HOME/.orbstack/run/docker.sock \
./gradlew check --no-daemon

# отчёт о покрытии (в check не входит — только гейт)
./gradlew :quiz-app:jacocoTestReport --no-daemon

# статические гейты фронта
python3 scripts/css-leak-audit.py
python3 scripts/design-token-audit.py

./gradlew bootRun          # http://localhost:8080
```

Оба CSS-гейта заведены в `.pre-commit-config.yaml` (рядом с тремя существующими
проверками шпаргалок и MCQ-сидеров) — раньше они существовали только как «запусти
руками», а гейт, который надо помнить, не гейт. **Локально они всё ещё не
срабатывают**: `pre-commit` не установлен ни как CLI, ни как `.git/hooks/pre-commit`,
поэтому ни один из пяти хуков сейчас не выполняется. Чтобы включить:

```bash
pip install pre-commit && pre-commit install
```

Пока это не сделано, гейты честнее считать ручными — команды выше остаются
единственным способом их прогнать.

Две переменные окружения обязательны на OrbStack: Testcontainers 1.19.8 договаривается
на Docker API 1.32, OrbStack отдаёт ≥1.40, и без пина версии падают все 39
интеграционных тестов. `--no-daemon` — потому что живой `bootRun` держит демона и
следующий Gradle-запуск встаёт намертво; порядок «убить Java → собрать → поднять».

Инвариант постраничного файла: каждый селектор лежит под `.{page}-page`. Без гейта
такой файл нельзя гейтить в ленте — правила молча исчезнут на других экранах,
и обнаружится это визуально, через недели.

Два файла из слоя `components` заскоуплены не префиксом, а **фактом употребления**:
селекторы у них плоские (`.answer`, `.hljs`), но классы встречаются только в
разметке `focus-training.html` и `result.html`. Для них прогон делает вторую
проверку — ищет классы файла в шаблонах за пределами гейта. Она ловит
положительное нарушение («взял `.answer` на `/stats`»), но не доказывает
отсутствие для классов, которые вешает JS, поэтому в отчёте помечена отдельно
(`OK usage`), а не выдаётся за `leak=0`.

Список проверяемых файлов больше **не ведётся руками**: гейты берутся из
`css-bundle-manifest.txt`, а соответствие «страница ↔ шаблон» — из
`th:with="page='…'"` в самих шаблонах, с транзитивным разворотом `th:replace`.
Поводом был дрейф — гейт держал восемь файлов, а условных `<link>` в шаблоне было
девять. Ирония: сам гейт на этом же и умер. Источником у него была шапка со
списком `<link>`, лента их вытеснила — и прогон стал молча падать с «условных
`<link>` не найдено», то есть был красным независимо от состояния CSS. Два
вырожденных исхода деривации закрыты явными ошибками: пустой список кандидатов
(разбор разошёлся с форматом манифеста) и строка на несуществующий файл — оба
валят прогон, а не дают «0 файлов, 0 утечек».

**Гейт дополнен проверкой синтаксиса** (`syntax: OK (38 файлов)` — идёт первой
строкой и валит прогон отдельно от leak-проверки). Причина: leak-аудит
регулярочный, он ищет селекторы текстом, а не спрашивает у CSS-движка, что
реально применилось, — и на сломанном файле честно рапортует «0 утечек». Оба
случая пойманы на живой правке, оба прошли старый гейт:

| Дефект | Что было видно | Чем ловится теперь |
|---|---|---|
| лишний `*/` — комментарий закрыт дважды, весь хвост файла уехал в текст правил | `249 селекторов, 0 утечек`, при этом ни одно правило ниже не применялось | `лишняя */` |
| `@layer pages {` не закрыт до конца файла | ничего: браузер доклеивает `}` на EOF, страница рендерится верно | `не закрыто блоков: 1` |

Второй случай — латентный: он существовал в `pages-focus.css` и до этой сессии.
Вреда не наносил ровно до момента, когда кто-нибудь допишет правило в конец файла
— оно молча попало бы внутрь слоя. Проверяются все 38 файлов, а не только
page-scoped: поломка в общем `base`/`components` ломает страницы так же.
Скобки внутри строк и комментариев (`content: "{"`, `calc(2 * 4px)`) не считаются —
покрыто негативными кейсами.

**`design-token-audit.py` — `VERDICT: CLEAN` (hard-fails=0, completeness=0,
large-warn=0).** Контраст пар токенов, полнота light/dark, отсутствие хардкодов в
`base.css` (0 hex, 0 rgb/rgba).

Гейт правился: он выдавал 17 ложных MISS на токенах-алиасах вида
`--color-teal: var(--color-accent-primary)`. Такой токен не хранит цвет, а
разыменовывается при использовании и потому следует за темой сам; требовать его
переопределения в light-блоке — требовать дублирования сопоставления в двух местах.
Гейт, который врёт семнадцать раз подряд, перестают читать — это и было главной
проблемой, а не сами 17 строк.

### 4.1 Палитра пиксельного слоя — два гейта, растр и стили

`design-token-audit.py` стережёт `base.css`, но пиксельный слой живёт двумя
наборами сразу: PNG-спрайты и семейство `pixel-*.css`. Набор без гейта разъезжается,
причём молча — обе половины подтвердили это на живом примере.

| Гейт | Что держит | Форма проверки |
|---|---|---|
| `PixelSpriteContractTest` | PNG в `static/img/pixel/` | каждый цвет спрайта — значение токена из `tokens.css`; потолок цветов на спрайт; происхождение файла (чанки `IHDR/IDAT/IEND`, альфа строго 0 или 255); ни одной `--pixel-*` роли без рисующего её спрайта |
| `PixelCssPaletteTest` | семейство `pixel-*.css` | HEX допустим ТОЛЬКО как акт именования (`--имя: #hex;` целиком); замороженные `--px-*` сверяются с тёмной веткой своего семантического токена **по имени**; объявленный `--px-*` обязан кем-то потребляться; один селектор получает `box-shadow` ровно из одного файла |

Ключевое в обоих: **рампа сверяется по ИМЕНАМ токенов, а не по списку HEX**. Список
HEX внутри теста — вторая копия палитры, то есть ровно тот дефект, который гейт и
должен ловить. Обе стороны читаются из файлов; HEX-литералов в тестах нет.

Второй гейт появился потому, что первый вылечил ровно половину проблемы и тут же
показал вторую: нормализатор снял с 36 спрайтов дрейфующий `#0a1a20`, а в
`pixel-*.css` тот же оттенок остался написанным руками — в светлой теме он клал
почти чёрную грань поверх светлого фона. Растр вылечен, его двойник в стилях — нет.
Набор надо закрывать с обеих сторон, иначе копия просто переезжает.

Перед любым замером палитры комментарии вырезаются: файлы объясняют прозой, ПОЧЕМУ
выбран оттенок, и приводят замеры контраста с конкретными HEX. Без вырезания гейт
краснеет на объяснениях того, что стережёт.

### 4.2 Серверное перечисление против таблицы стилей

`ReviewReasonPaletteTest` держит соответствие `ReviewReason.Type` и палитры
точек-маркеров в `pages-focus.css`. Мотив — найденный дефект: констант пять, правил
было три, и `NEW` с `BOOKMARK` молча падали в базовый серый `::before`. Ничего не
ломалось — чип рендерился и выглядел рабочим, просто две причины из пяти теряли
категорию. Проверяются обе стороны (константа без правила и правило без константы),
различимость цветов между категориями и потребление через `var()` с объявленным
токеном.

Форма дефекта та же, что у мёртвых спрайт-листов (`SpriteAnimationContractTest`), но
с обратным знаком: там правило существовало без активации, здесь активация — без
правила. Ни то, ни другое не видит `StaticAssetInventoryTest`: файлов тут нет вообще,
расходятся перечисление и таблица стилей.

**Гейт намеренно не обобщён на все enum-атрибуты.** Исчерпывающий контракт уместен
только там, где атрибут — единственный носитель смысла: точка несёт категорию, текст
рядом несёт формулировку, поэтому «категория без своего цвета» — дефект по
определению. Соседний `data-content-type` (`BlockType`) устроен наоборот: `MERMAID`
получает вьюпорт, `CODE` — тулбар, а `MARKDOWN`/`IMAGE`/`CALLOUT` правил не имеют и
иметь не должны. Общий гейт «каждая константа обязана иметь правило» покраснел бы там
на решении, а не на дефекте.

### 4.3 Бюджет содержимого и число назначений на итогах сессии

Два независимых гейта на одном экране, оба выросли из настоящих дефектов.

`SessionSummaryTest` держит **бюджет содержимого**: `getAccuracyRounded()` не длиннее
`100%` (четыре знака) и не имеет права округлить сессию с ошибкой до идеала
(`Math.round(99.6) = 100` — ровно там, где смысл экрана в различии этих двух исходов);
`getCompactDuration()` даёт таймерную запись `м:сс`/`ч:мм:сс` без пробела, чтобы KPI-тайл
фиксированной ширины не переносил длительность на вторую строку. Полная форма
(`getFormattedDuration()`) отдельно закреплена как остающаяся — она живёт в свободной
строке метрик, где ширина не зажата.

`SummaryRoutingContractTest` держит **число различимых назначений**: каждый
`NextActionType` либо маршрутизирован явно, либо остаётся единственным fallback;
дедупликация «Продолжить тренировку» идёт по `Destination`, а не по имени типа; в меню
«Подробнее» ссылка не повторяется (счётчик вхождений ждёт ровно два). До этого роутинг
решался строк-матчем по имени константы, и вопрос «сколько на экране разных
назначений» был невыразим — `REVIEW_DUE` и `KEEP_GOING` вели в одно место, а понижённый
дубль лежал ещё и в `<details>`.

Что тесты **не** ловят и почему это принято: сам факт переполнения на экране. Числа
бюджета (просвет кольца `0.8 × размер`, ~145px на текст в тайле) записаны комментариями
у правил в `shell.css`, замеряются в браузере и подтверждаются доменной гарантией на
длину строки. Автоматический замер отрисованной ширины потребовал бы headless-браузера в
сборке — цена выше пользы, пока класс дефекта закрыт с двух сторон.

### 4.4 Бюджет подписей на графике — гейт там, где замер невозможен

Продолжение 4.3 на поверхности, где приём «замерить в браузере» не работает: канвас
невидим для DOM. Проверка охватом это подтвердила — обход `scrollWidth > clientWidth`
на `/`, `/stats` и экране вопроса при 390 и 1440 дал ноль настоящих срабатываний (только
`visually-hidden` с клипом 1px by design), а KPI-чипы `/stats` выдержали подстановку
худших достижимых строк (`1800,0 с` из `MAX_RESPONSE_TIME_MS`, `100,0%`, `99999`).
Дефекты класса нашлись именно на графиках и именно потому, что были невидимы: Chart.js по
умолчанию **удаляет** непомещающиеся подписи (`ticks.autoSkip`). Вкладка «Темы» рисовала
25 столбцов при 13 подписях, отдав оси 151px из 320px. На «Динамике точности» предел был
константой `maxTicksLimit: 7`, не связанной ни с шириной графика, ни с шириной подписи, —
ошибка в обе стороны сразу: на 1440 семь дат из четырнадцати при 981px свободных, на 390
те же семь с зазором 5.4px до столкновения.

Гейты держат не внешний вид, а **источник числа**.
`TemplateFragmentContractTest#topicChartsRecordLabelBudgetForXAxisLabels`: число столбцов
из бюджета, а не из константы, `autoSkip` выключен, обрезка помечена многоточием, полное
имя остаётся в тултипе и в таблице (мутационно доказан четырьмя подменами: `autoSkip:
true`, возврат `.slice(0, MAX_BARS)`, пустое многоточие, замер канваса вместо родителя).
`#canvasChartsDeriveTickBudgetFromTheBoxTheyAreBuiltWith` покрывает оба канваса разом:
замер у обёртки (канвас без атрибутов размера даёт интринсик 300×150), нулевая коробка
как «размер неизвестен», а не как ноль, предел оси дат из геометрии, и — контракт
пересчёта.

Пересчёт оказался вторым дефектом, глубже первого: механизм существовал, выглядел
исправным и не работал ни разу. Он сверял текущий бюджет со **снимком**, снятым на строку
позже постройки графика, а конструктор Chart.js сам проставляет канвасу размеры и меняет
коробку. Ось строилась по 585px (11 подписей), «эталоном» записывались устоявшиеся 1027px
(14) — расхождение с первой секунды считалось нормой, и ни поворот экрана, ни
переключение вкладки его не чинили. Правило, которое из этого следует: **бюджет, снятый
после `new Chart(...)`, описывает другую коробку, чем та, с которой график построен —
сверять `applied` против `current`, никогда против снимка времени подписки**. Сигнал —
`ResizeObserver` на обёртке, а не `window.resize`: окно не покрывает ни раскрытие скрытой
панели, ни догрузку шрифта, ни устаканивание layout. Всего семь мутаций красят гейт.

Как и в 4.3, сама отрисованная ширина не проверяется сборкой; проверяется, что бюджет
записан и выведен из геометрии. Расхождение объявленного с фактическим ловится
замером в браузере — первая версия формулы давала 0.36 при объявленных 0.32, потому что
Chart.js добавляет к проекции подписи собственные отступы оси.

### 4.5 Ось «движение» не слышала систему — отказ, замаскированный собственной CSS-половиной

Второй дефект 4.4 (механизм, выглядящий исправным) задал класс для перебора: подписки,
которые сами запоминают «как было». Обход `static/js/` этот класс исчерпал — три
оставшихся места (`chart-theme` `lastKey`, `mermaid-renderer` `lastTheme`, ось темы)
замером оказались корректны; гипотеза про `getBBox` в скрытой вкладке была снята пробой,
показавшей идентичный `viewBox` до, во время и после переключения. Дефект нашёлся
соседний и обратный по форме: не устаревший снимок, а **отсутствие подписки вовсе**.

Две оси персонализации разрешают `auto` системной настройкой. Тема подписана на
`prefers-color-scheme` и перекрашивается на лету. Движение спрашивало
`prefers-reduced-motion` один раз на загрузке. Замер — перехват `matchMedia` через
`initScript` со счётчиком подписчиков — дал 1 у темы и **0** у движения.

Отказ был **частичным, поэтому невидимым**. CSS-медиа (семь файлов) гасила анимации
корректно, и по наблюдаемому результату ось выглядела рабочей. Молчала JS-половина:
`applyIntensityLayers` не вызывался, 14 декоративных узлов оставались на месте, слушатель
`pointermove` продолжал сыпать след курсора, `chartAnimation()` не пересобиралась. Для
человека, который включает системную настройку **потому что** ему плохо от движения, это
не косметика. Потребителей менять не пришлось — они читают значение вживую, им не хватало
уведомления; лечение — подписка там же, где живёт ось, и то же событие `motionchange`, что
у переключателя. После правки: декор 15 → 0 → 15, след снимается и возвращается, без
перезагрузки; явный `on`/`off` системную смену игнорирует (0 событий).

Гейт `osResolvedAxesSubscribeToTheMediaQueryTheyRead` сформулирован **как класс**: он
вынимает из `head.html` все `matchMedia` и требует `addEventListener('change'` от каждой,
плюс проверяет, что у сигнала есть адресат. Новая ось без подписки покраснеет сама, без
правки теста. Пять мутаций красят гейт: снятая подписка движения, снятая подписка темы,
переименованное событие, глухой `pixel-fx`, глухой график.

Правило, которое из этого следует: **отсутствие подписки — тот же класс, что устаревший
снимок** (потребитель работает с состоянием, которое больше не описывает реальность), а
**асимметрия соседних осей — сильнейший сигнал дефекта**: рабочая ось рядом даёт эталон
для сравнения. Читается такой дефект не глазами по коду, а перехватом `matchMedia` —
CDP-эмуляции этой медиа-фичи в доступных инструментах нет.

### 4.6 Бейдж, который стоял на каждом вопросе

`DifficultyBadgeContractTest` (7 тестов) закрывает продолжение §4.2: перебор всех мест,
где имя серверной константы уходит в DOM, дал один живой дефект — бейдж сложности.

Находка установлена замером, а не осмотром: `SELECT difficulty, count(*) FROM questions
GROUP BY difficulty` → **`MEDIUM` 9818 из 9818**. Подпись «Средний» висела в шапке
каждого вопроса банка и не различала ничего. При этом `Difficulty.fromString` сводит к
`MEDIUM` и `null`, и пустую строку, и любой нераспознанный уровень — значит «Средний»
неотличим от «уровень неизвестен» и утверждением про конкретный вопрос быть не может.
Продукт уже отвечал на этот вопрос дважды в одну сторону: `StatsPageService` прячет
донат сложности, когда уровень в банке один, и из этой же шапки раньше убрали «Часть
экзаменационной сессии». **Признак дефекта здесь не «выглядит плохо», а «на соседнем
экране это уже названо неинформативным».**

Второй дефект был в разметке: подпись собиралась тернарником
`diff == 'EASY' ? … : (diff == 'HARD' ? … : 'Средний')`, и четвёртая константа не
сломала бы сборку — она молча печаталась бы как «Средний». Тот же класс тихой подмены,
что `ReviewReason.Type` в §4.2. Лечение — критерий и подпись в домене
(`Difficulty.label()` / `informative()`), в разметке остались `th:if` и `th:text`.

Контракт палитры **исчерпывающий, но узкий, и это обосновано**: модификатор
`badge--difficulty-*` вешается на каждый показанный бейдж, а бейдж без правила падает в
тихую серую базу шапки — заливку, задуманную для ярлыков, которые стоят всегда.
Показанный бейдж стоит не всегда, значит «сигнал, выглядящий как фон» здесь — дефект по
определению. Требуется ровно совпадение с множеством `informative()`-уровней: правило
под `MEDIUM` столь же вредно, сколько его отсутствие под `HARD`.

Побочная находка: **`border-color` на `.badge` мёртв по всему проекту.**
`pixel-nav-badges.css` гасит рамку без условий и рисует контур четырьмя тенями по
`currentColor`, поэтому ручка ровно одна — `color`. Тест сначала утверждает, что
безусловное правило ещё существует, и лишь затем требует отсутствия `border-color`.

Контраст замерен в браузере в обеих темах: easy **5.35 / 9.56**, hard **5.08 / 6.02** —
AA с запасом. Восемь мутаций красят гейт: удалённое правило `hard`; добавленное правило
`medium`; один цвет на оба уровня; hex вместо токена; `informative()`, возвращающий
`true` всегда; тернарник обратно в разметку; две константы с одной подписью;
восстановленный мёртвый `border-color`.

### 4.7 Имя константы в строковом литерале

`EnumLabelSourceContractTest` (6 тестов) закрывает тот же класс с другой стороны. В §4.6
подпись **собиралась** в шаблоне и новая константа печаталась как старая; здесь
константа **сравнивается со строкой**, и её переименование не ломает сборку — компилятор
литерал не видит, ветка просто перестаёт выбираться.

Замер до правки: **15 вхождений** `X.name() == 'ЛИТЕРАЛ'` в шаблонах (`InterviewMode` —
11, `BlockType`/`'MERMAID'` — 4), плюс объект `MODE_CTA` в `settings/session-form.js`,
где именами констант были ключи. Проявления были бы разными и все — тихими: из
выпадающего списка пропадает режим; над формой развёрнутого ответа не остаётся ни одной
подписи (из четырёх взаимоисключающих `th:if` не срабатывает ни один); схема остаётся на
экране, но рендерится псевдографикой вместо mermaid; кнопка старта откатывается к
нейтральному «Начать сессию». Отдельно `result.html` печатал через `th:case="*"` сырое
английское имя `ReviewResult` в полностью русском интерфейсе.

Что проверяется: литералов `.name() == '…'` в шаблонах нет; порядок показа
`ModeUtils.options` перечисляет все константы `InterviewMode` ровно по разу (забытый
режим недостижим из интерфейса и не роняет ничего); подписи и `startAction` непусты,
различны и не содержат имени константы; `ReviewResult` умеет назвать себя по-русски.

Существенная деталь методики: гейт «ни одного вхождения подписи вне `ModeUtils`»
**отвергнут замером**, а не вкусом. Подписи режимов — обычные русские слова, и поодиночке
они законно встречаются в другом смысле: «Тренировка» — пункт навигации, «Интенсив» живёт
внутри «Интенсивности arcade-эффектов», «Изучение» стоит в подписи учебной фазы. Гейт с
растущим списком исключений перестаёт быть гейтом, поэтому ловится **таблица** — файл,
перечисляющий ≥4 режима из 8. Прозе четыре режима сразу не нужны.

Побочная находка: `data-default-count` в разметке противоречил правилу, на которое сам
ссылался. `SessionFlowService.resolveSessionTotal` — это `EXAM → examCount(20)`, иначе
`marathonCount(50)`; разметка давала 20 и для `TYPED_RECALL`/`INTERVIEW`/`CODE_CHALLENGE`.
Вывод из `AppProperties` по `EXAM || usesTypedInput()` воспроизводит 7 из 8 рукописных
значений; единственный сдвиг (`TRAINING` 20→50) невидим — у безлимитного режима поле
счётчика скрыто.

### 4.8 Копия набора, которую прикрывает снисходительный сервер

Продолжение §4.7 в `static/js/`, где гейт по шаблонам не работает по определению. Обход
дал две настоящие копии — `REPORT_CATEGORIES` в `ui/modals.js` (пять пар имя+подпись) и
`colorByLevel` в `stats/difficulty-donut.js` (уровень → CSS-токен) — и третью, в прозе
`ValidIssueCategory.message()`.

Различие с §4.7 не в форме копии, а в **способе отказа**. `QuestionIssueCategory.fromString`
намеренно снисходителен (неизвестное → `OTHER`, чтобы жалоба не потерялась), поэтому
расхождение имён не роняет запрос и не пишет в лог: пользователь выбирает «Опечатка», на
проверку уезжает «Другое». Это не тихая поломка, а **тихая переклассификация** — она не
чинится ни гейтом на ошибки, ни чтением логов, и обнаруживается только по перекосу
статистики жалоб. Правило отсюда общее: чем мягче парсер, тем строже должен быть запрет
на вторую копию его словаря.

Донат сложности отказывал иначе — **не отказывал вовсе**. Таблица «уровень → токен» в JS
и CSS-классы легенды (`difficulty-easy`) совпадали на честном слове; разъезд дал бы
сектор одного цвета и кружок рядом с ним другого, что видно только глазами и только если
смотреть. Лечение убирает саму возможность: цвет берётся `getComputedStyle` с уже
отрисованного кружка легенды — источник ровно один, тот, который CSS показал
пользователю. Работает потому, что график пересобирается на смену темы (`liveChart`);
без этого условия приём был бы заменой одной рассинхронизации на другую.

⏸ Приземлена пока **серверная половина** — `label()` в домене и перечень из `values()` в
тексте ошибки валидатора. Правки `modals.js`, `focus-training.html`,
`MvcModelAttributeMapper` и доната лежат поверх неприземлённой миграции `/api/*` на
JSON-тело (`modals.js` зависит от `apiPostJson`, которого нет в `HEAD`) и едут вместе с
ней. Инвариант подписей при этом уже действует: он **перенесён из гейта в доменный
`QuestionIssueCategoryTest`**, где ему и место, — гейт по `static/js/` красен на `master`
до приземления, а доменный тест зелен независимо от фронта.

Побочный дефект, найденный при разборе копии, — **предвыбранная первая радиокнопка**.
Формально удобство, фактически подстановка мнения: каждая жалоба, которую пользователь не
классифицировал осознанно, уезжала как «Неверный ответ» — самая тревожная из пяти
категорий. Снято; Tab-порядок не пострадал (в незаполненной радиогруппе первая кнопка
остаётся фокусируемой — замерено).

## 5. HTTP-контракт (живая проверка)

12 маршрутов, все коды ожидаемые. Существенное:

- `/nonexistent-page` → **404** (а не 500): `NoResourceFoundException` маппится явно.
  Без этого опечатка в URL давала пятисотку и ложную тревогу в мониторинге.
- `/api/nope` → **404**, `Content-Type: application/problem+json`, тело RFC 7807 с
  `errorCode: RESOURCE_NOT_FOUND` и `correlationId`.
- `POST /api/favorite` без CSRF → **403** ProblemDetail `errorCode: FORBIDDEN`,
  не редирект на форму логина.

Известное и оставленное осознанно: `?mode=NOPE` не отвергается, а тихо деградирует в
`TRAINING` (`InterviewMode.fromString`). Для параметра, приходящего из закладки
пользователя, мягкая деградация лучше страницы ошибки.

## 6. Доступность

Живой аудит `/` на 1440 px. Чисто: горизонтального переполнения нет (документ 1425 px
при вьюпорте 1440), ровно один `h1`, нет картинок без `alt`, нет контролов без
доступного имени, нет дублирующихся `id`, набор лендмарков корректен
(`nav[Основная навигация]`, `header`, `main`, `nav[Мобильная навигация]`).

Два дефекта найдены и закрыты **в рендерере, а не в контенте**:

1. **Разрыв уровней заголовков h1 → h3** (WCAG 1.3.1). Фрагмент ответа встраивается
   под страничный `h1` (вопрос), а авторы markdown начинают с `###`.
   `normalizeHeadingLevels` сдвигает всю лестницу так, чтобы верхний уровень стал `h2`;
   относительная глубина сохраняется, уровни за `h6` зажимаются. Правка в 300+
   исходных файлах дала бы тот же результат и требовала бы дисциплины от каждого
   будущего автора.
2. **Чекбоксы GFM-тасклистов без доступного имени** (6 штук на странице).
   `labelTaskListCheckboxes` проставляет `aria-label` со **статусом** — «выполнено» /
   «не выполнено». Именно статус, а не текст пункта: текст лежит в том же `<li>` и
   был бы прочитан скринридером дважды.

Оба поведения закреплены тестами: `givesTaskListCheckboxesAccessibleNameFromState`,
`shiftsHeadingsSoFragmentStartsAtH2`, `keepsHeadingsWhenFragmentAlreadyStartsAtH2`,
`clampsDeepHeadingsAtH6`.

Третий дефект — **контраст приглушённых вариантов после ответа** (`.option-dimmed`).
`opacity: 0.55` на всей строке роняла разом текст дистрактора до 3.71:1 и буквенный
чип до 2.36:1 — при том что собственный цвет чипа даёт ~7:1, то есть виновата была
именно сплошная прозрачность, а не палитра. Формально вариант после ответа —
неактивный контрол (`input.disabled`) и подпадает под исключение WCAG 1.4.3, но по
сути это учебный текст: сравнить неверный вариант с верным и есть смысл разбора,
а вердикт вдобавок ссылается на варианты по буквам («Ты выбрал A. Правильный
ответ D»), из-за чего чип работает якорем сопоставления. Рецессивность
переведена с `opacity` на цвет (`--color-text-tertiary`):

| | текст | чип |
|---|---|---|
| было (обе темы через opacity) | 3.71 | 2.36 |
| стало, светлая | **4.62** | **5.66** |
| стало, тёмная | **5.98** | **8.96** |

Числа — по **худшей** точке фона: `body` залит `linear-gradient(135deg, …)`, светлая тема
идёт 245→255, тёмная 7,17,22→11,23,29. Против чистого белого те же пары дают 4.93 и
6.05 — мерить надо по тёмному концу градиента, иначе отчёт завышает запас.

Иерархия сохранена: активные варианты 15.11–17.38:1 против 4.62:1 у приглушённых.
Рамку правило не трогает намеренно — `@layer pixel` держит
`border-color: currentcolor !important`, и она следует за приглушённым текстом сама;
отдельная декларация была бы мёртвым кодом.

Замечание по инструменту: правка ловится только замером в браузере. Селектор
пришлось поднимать до `(1,3,2)` — базовое `html[data-design] #interview-options label`
задаёт `color` со специфичностью `(1,2,1)` и молча съедало «плоское»
`.option-dimmed` `(0,3,1)` в том же слое `@pages`.

Обе правки живут в одном проходе Jsoup (`postProcess`): фрагмент ответа бывает
большим, и повторный parse/serialize на каждый шаг стоил бы столько же, сколько сам
рендер.

## 7. Архитектурные инварианты

`LayeredArchitectureTest` (ArchUnit) — часть `check`, то есть границы модулей
проверяются, а не декларируются:

- `domain` не зависит от `api` / `service` / `persistence` / `config`;
- `service` не зависит от контроллеров и классов безопасности;
- `persistence` не зависит от `api`.

`TemplateFragmentContractTest` держит разметку фрагментов: лендмарки, `aria-current`,
единственность тоггла темы.

## 8. Что не покрыто автотестами

- **Фронтенд.** Сборщика нет, тест-раннера для JS нет. Контракты шаблонов проверяются
  на уровне разметки (`TemplateFragmentContractTest`) и живой проверкой в браузере.
- **Режим `app.security.mode=multi`.** OAuth2 + owner-скоупинг реализованы, но режим
  выключен и живой проверкой не покрыт. Юнит-тесты на `OwnerContextFilter` есть,
  сквозного сценария нет.
- **E2E.** Нет. Сквозные сценарии проверяются интеграционными тестами на уровне
  MockMvc + Testcontainers, что покрывает контракт, но не браузерное поведение.

## 9. Известный долг

- **Флакость `InterviewControllerTest`.** Класс делит один Testcontainers-инстанс с
  остальными тестами `quiz-app` и не чистит банк вопросов между собственными
  сценариями. Из-за этого какой вопрос попадёт в `/` зависит от порядка выполнения:
  вопрос без MCQ-вариантов форсит флешкарту, и ассерты на MCQ-разметку иногда
  срабатывают, иногда нет. Часть проверок поэтому написана условно
  (`if (body.contains(...))`) — это не «мягкая» проверка по смыслу, а обход
  недетерминизма. Лечится фиксированной фикстурой вопроса на класс, а не ретраями.
