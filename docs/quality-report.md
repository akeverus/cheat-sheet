# Отчёт о качестве

Состояние на момент последней верификации. Не журнал — снимок. Все числа получены
прогоном, а не оценкой.

## 1. Как воспроизвести

```bash
docker compose up -d postgres

# полная верификация (тесты + jacoco-гейт)
JAVA_TOOL_OPTIONS=-Dapi.version=1.41 \
DOCKER_HOST=unix://$HOME/.orbstack/run/docker.sock \
./gradlew check --no-daemon

# отчёт о покрытии (в check не входит — только гейт)
./gradlew :quiz-app:jacocoTestReport --no-daemon

# статические гейты фронта
python3 scripts/css-leak-audit.py
python3 scripts/design-token-audit.py

./gradlew bootRun          # http://localhost:8080
```

Оба CSS-гейта заведены в `.pre-commit-config.yaml` (рядом с тремя существующими
проверками шпаргалок и MCQ-сидеров) — раньше они существовали только как «запусти
руками», а гейт, который надо помнить, не гейт. **Локально они всё ещё не
срабатывают**: `pre-commit` не установлен ни как CLI, ни как `.git/hooks/pre-commit`,
поэтому ни один из пяти хуков сейчас не выполняется. Чтобы включить:

```bash
pip install pre-commit && pre-commit install
```

Пока это не сделано, гейты честнее считать ручными — команды выше остаются
единственным способом их прогнать.

Две переменные окружения обязательны на OrbStack: Testcontainers 1.19.8 договаривается
на Docker API 1.32, OrbStack отдаёт ≥1.40, и без пина версии падают все 39
интеграционных тестов. `--no-daemon` — потому что живой `bootRun` держит демона и
следующий Gradle-запуск встаёт намертво; порядок «убить Java → собрать → поднять».

Инвариант постраничного файла: каждый селектор лежит под `.{page}-page`. Без гейта
такой файл нельзя гейтить в ленте — правила молча исчезнут на других экранах,
и обнаружится это визуально, через недели.

Два файла из слоя `components` заскоуплены не префиксом, а **фактом употребления**:
селекторы у них плоские (`.answer`, `.hljs`), но классы встречаются только в
разметке `focus-training.html` и `result.html`. Для них прогон делает вторую
проверку — ищет классы файла в шаблонах за пределами гейта. Она ловит
положительное нарушение («взял `.answer` на `/stats`»), но не доказывает
отсутствие для классов, которые вешает JS, поэтому в отчёте помечена отдельно
(`OK usage`), а не выдаётся за `leak=0`.

Список проверяемых файлов больше **не ведётся руками**: гейты берутся из
`css-bundle-manifest.txt`, а соответствие «страница ↔ шаблон» — из
`th:with="page='…'"` в самих шаблонах, с транзитивным разворотом `th:replace`.
Поводом был дрейф — гейт держал восемь файлов, а условных `<link>` в шаблоне было
девять. Ирония: сам гейт на этом же и умер. Источником у него была шапка со
списком `<link>`, лента их вытеснила — и прогон стал молча падать с «условных
`<link>` не найдено», то есть был красным независимо от состояния CSS. Два
вырожденных исхода деривации закрыты явными ошибками: пустой список кандидатов
(разбор разошёлся с форматом манифеста) и строка на несуществующий файл — оба
валят прогон, а не дают «0 файлов, 0 утечек».

**Гейт дополнен проверкой синтаксиса** (`syntax: OK (38 файлов)` — идёт первой
строкой и валит прогон отдельно от leak-проверки). Причина: leak-аудит
регулярочный, он ищет селекторы текстом, а не спрашивает у CSS-движка, что
реально применилось, — и на сломанном файле честно рапортует «0 утечек». Оба
случая пойманы на живой правке, оба прошли старый гейт:

| Дефект | Что было видно | Чем ловится теперь |
|---|---|---|
| лишний `*/` — комментарий закрыт дважды, весь хвост файла уехал в текст правил | `249 селекторов, 0 утечек`, при этом ни одно правило ниже не применялось | `лишняя */` |
| `@layer pages {` не закрыт до конца файла | ничего: браузер доклеивает `}` на EOF, страница рендерится верно | `не закрыто блоков: 1` |

Второй случай — латентный: он существовал в `pages-focus.css` и до этой сессии.
Вреда не наносил ровно до момента, когда кто-нибудь допишет правило в конец файла
— оно молча попало бы внутрь слоя. Проверяются все 38 файлов, а не только
page-scoped: поломка в общем `base`/`components` ломает страницы так же.
Скобки внутри строк и комментариев (`content: "{"`, `calc(2 * 4px)`) не считаются —
покрыто негативными кейсами.

**`design-token-audit.py` — `VERDICT: CLEAN` (hard-fails=0, completeness=0,
large-warn=0).** Контраст пар токенов, полнота light/dark, отсутствие хардкодов в
`base.css` (0 hex, 0 rgb/rgba).

Гейт правился: он выдавал 17 ложных MISS на токенах-алиасах вида
`--color-teal: var(--color-accent-primary)`. Такой токен не хранит цвет, а
разыменовывается при использовании и потому следует за темой сам; требовать его
переопределения в light-блоке — требовать дублирования сопоставления в двух местах.
Гейт, который врёт семнадцать раз подряд, перестают читать — это и было главной
проблемой, а не сами 17 строк.

### 4.1 Палитра пиксельного слоя — два гейта, растр и стили

`design-token-audit.py` стережёт `base.css`, но пиксельный слой живёт двумя
наборами сразу: PNG-спрайты и семейство `pixel-*.css`. Набор без гейта разъезжается,
причём молча — обе половины подтвердили это на живом примере.

| Гейт | Что держит | Форма проверки |
|---|---|---|
| `PixelSpriteContractTest` | PNG в `static/img/pixel/` | каждый цвет спрайта — значение токена из `tokens.css`; потолок цветов на спрайт; происхождение файла (чанки `IHDR/IDAT/IEND`, альфа строго 0 или 255); ни одной `--pixel-*` роли без рисующего её спрайта |
| `PixelCssPaletteTest` | семейство `pixel-*.css` | HEX допустим ТОЛЬКО как акт именования (`--имя: #hex;` целиком); замороженные `--px-*` сверяются с тёмной веткой своего семантического токена **по имени**; объявленный `--px-*` обязан кем-то потребляться; один селектор получает `box-shadow` ровно из одного файла |

Ключевое в обоих: **рампа сверяется по ИМЕНАМ токенов, а не по списку HEX**. Список
HEX внутри теста — вторая копия палитры, то есть ровно тот дефект, который гейт и
должен ловить. Обе стороны читаются из файлов; HEX-литералов в тестах нет.

Второй гейт появился потому, что первый вылечил ровно половину проблемы и тут же
показал вторую: нормализатор снял с 36 спрайтов дрейфующий `#0a1a20`, а в
`pixel-*.css` тот же оттенок остался написанным руками — в светлой теме он клал
почти чёрную грань поверх светлого фона. Растр вылечен, его двойник в стилях — нет.
Набор надо закрывать с обеих сторон, иначе копия просто переезжает.

Перед любым замером палитры комментарии вырезаются: файлы объясняют прозой, ПОЧЕМУ
выбран оттенок, и приводят замеры контраста с конкретными HEX. Без вырезания гейт
краснеет на объяснениях того, что стережёт.

## 5. HTTP-контракт (живая проверка)

12 маршрутов, все коды ожидаемые. Существенное:

- `/nonexistent-page` → **404** (а не 500): `NoResourceFoundException` маппится явно.
  Без этого опечатка в URL давала пятисотку и ложную тревогу в мониторинге.
- `/api/nope` → **404**, `Content-Type: application/problem+json`, тело RFC 7807 с
  `errorCode: RESOURCE_NOT_FOUND` и `correlationId`.
- `POST /api/favorite` без CSRF → **403** ProblemDetail `errorCode: FORBIDDEN`,
  не редирект на форму логина.

Известное и оставленное осознанно: `?mode=NOPE` не отвергается, а тихо деградирует в
`TRAINING` (`InterviewMode.fromString`). Для параметра, приходящего из закладки
пользователя, мягкая деградация лучше страницы ошибки.

## 6. Доступность

Живой аудит `/` на 1440 px. Чисто: горизонтального переполнения нет (документ 1425 px
при вьюпорте 1440), ровно один `h1`, нет картинок без `alt`, нет контролов без
доступного имени, нет дублирующихся `id`, набор лендмарков корректен
(`nav[Основная навигация]`, `header`, `main`, `nav[Мобильная навигация]`).

Два дефекта найдены и закрыты **в рендерере, а не в контенте**:

1. **Разрыв уровней заголовков h1 → h3** (WCAG 1.3.1). Фрагмент ответа встраивается
   под страничный `h1` (вопрос), а авторы markdown начинают с `###`.
   `normalizeHeadingLevels` сдвигает всю лестницу так, чтобы верхний уровень стал `h2`;
   относительная глубина сохраняется, уровни за `h6` зажимаются. Правка в 300+
   исходных файлах дала бы тот же результат и требовала бы дисциплины от каждого
   будущего автора.
2. **Чекбоксы GFM-тасклистов без доступного имени** (6 штук на странице).
   `labelTaskListCheckboxes` проставляет `aria-label` со **статусом** — «выполнено» /
   «не выполнено». Именно статус, а не текст пункта: текст лежит в том же `<li>` и
   был бы прочитан скринридером дважды.

Оба поведения закреплены тестами: `givesTaskListCheckboxesAccessibleNameFromState`,
`shiftsHeadingsSoFragmentStartsAtH2`, `keepsHeadingsWhenFragmentAlreadyStartsAtH2`,
`clampsDeepHeadingsAtH6`.

Третий дефект — **контраст приглушённых вариантов после ответа** (`.option-dimmed`).
`opacity: 0.55` на всей строке роняла разом текст дистрактора до 3.71:1 и буквенный
чип до 2.36:1 — при том что собственный цвет чипа даёт ~7:1, то есть виновата была
именно сплошная прозрачность, а не палитра. Формально вариант после ответа —
неактивный контрол (`input.disabled`) и подпадает под исключение WCAG 1.4.3, но по
сути это учебный текст: сравнить неверный вариант с верным и есть смысл разбора,
а вердикт вдобавок ссылается на варианты по буквам («Ты выбрал A. Правильный
ответ D»), из-за чего чип работает якорем сопоставления. Рецессивность
переведена с `opacity` на цвет (`--color-text-tertiary`):

| | текст | чип |
|---|---|---|
| было (обе темы через opacity) | 3.71 | 2.36 |
| стало, светлая | **4.62** | **5.66** |
| стало, тёмная | **5.98** | **8.96** |

Числа — по **худшей** точке фона: `body` залит `linear-gradient(135deg, …)`, светлая тема
идёт 245→255, тёмная 7,17,22→11,23,29. Против чистого белого те же пары дают 4.93 и
6.05 — мерить надо по тёмному концу градиента, иначе отчёт завышает запас.

Иерархия сохранена: активные варианты 15.11–17.38:1 против 4.62:1 у приглушённых.
Рамку правило не трогает намеренно — `@layer pixel` держит
`border-color: currentcolor !important`, и она следует за приглушённым текстом сама;
отдельная декларация была бы мёртвым кодом.

Замечание по инструменту: правка ловится только замером в браузере. Селектор
пришлось поднимать до `(1,3,2)` — базовое `html[data-design] #interview-options label`
задаёт `color` со специфичностью `(1,2,1)` и молча съедало «плоское»
`.option-dimmed` `(0,3,1)` в том же слое `@pages`.

Обе правки живут в одном проходе Jsoup (`postProcess`): фрагмент ответа бывает
большим, и повторный parse/serialize на каждый шаг стоил бы столько же, сколько сам
рендер.

## 7. Архитектурные инварианты

`LayeredArchitectureTest` (ArchUnit) — часть `check`, то есть границы модулей
проверяются, а не декларируются:

- `domain` не зависит от `api` / `service` / `persistence` / `config`;
- `service` не зависит от контроллеров и классов безопасности;
- `persistence` не зависит от `api`.

`TemplateFragmentContractTest` держит разметку фрагментов: лендмарки, `aria-current`,
единственность тоггла темы.

## 8. Что не покрыто автотестами

- **Фронтенд.** Сборщика нет, тест-раннера для JS нет. Контракты шаблонов проверяются
  на уровне разметки (`TemplateFragmentContractTest`) и живой проверкой в браузере.
- **Режим `app.security.mode=multi`.** OAuth2 + owner-скоупинг реализованы, но режим
  выключен и живой проверкой не покрыт. Юнит-тесты на `OwnerContextFilter` есть,
  сквозного сценария нет.
- **E2E.** Нет. Сквозные сценарии проверяются интеграционными тестами на уровне
  MockMvc + Testcontainers, что покрывает контракт, но не браузерное поведение.

## 9. Известный долг

- **Флакость `InterviewControllerTest`.** Класс делит один Testcontainers-инстанс с
  остальными тестами `quiz-app` и не чистит банк вопросов между собственными
  сценариями. Из-за этого какой вопрос попадёт в `/` зависит от порядка выполнения:
  вопрос без MCQ-вариантов форсит флешкарту, и ассерты на MCQ-разметку иногда
  срабатывают, иногда нет. Часть проверок поэтому написана условно
  (`if (body.contains(...))`) — это не «мягкая» проверка по смыслу, а обход
  недетерминизма. Лечится фиксированной фикстурой вопроса на класс, а не ретраями.
