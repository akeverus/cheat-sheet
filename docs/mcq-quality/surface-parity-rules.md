# Surface Parity Rules — структура / формат / пунктуация / длина

**Назначение.** Отдельный, измеримый стандарт «поверхностного паритета» четырёх опций
MCQ-блока. Проверяет НЕ смысл, а **форму**: можно ли угадать correct глазами, не зная темы,
по длине, пунктуации, backtick-плотности, опорному токену, числу клауз или «ощущению
полного конспекта». Введён 2026-07-13 после того, как в `java-concurrency-interview.json`
correct визуально отличался от дистракторов по формату и структуре, хотя контент-аудит был
пройден.

**Главный тезис (one-line test).** Убери поле `correct` — правильный ответ обязан быть
**неотличим по форме** от трёх остальных. Отличается только истинность. Всё остальное
(длина, пунктуация, код-плотность, зачин, число клауз, «выглядит как готовый ответ») —
одинаково у всех четырёх.

**Направление правки — всегда вверх.** Паритет достигают, ПОДНИМАЯ дистракторы до формы
correct (полный правдоподобный mental model с одной подменённой деталью), а НЕ ужимая correct
до уровня заглушек и НЕ штампуя карбон-копии (см. anti-pattern «stamped-clone»). Текст correct
по СМЫСЛУ неизменен; допускается только форматирование (backticks) ради паритета. У каждого
дистрактора сохраняется его ось-заблуждение, чтобы пост-ответные секции оставались валидны.

---

## Шесть правил

### R1 — Backtick discipline (формат)
Каждый код-идентификатор, API/класс/метод/аннотация/ключевое слово/литерал обёрнут в
`backticks` — и **одинаково во всех 4 опциях**. Если в correct `Thread`/`start()`/`Runnable`
в backticks, то и в каждом дистракторе тоже. Ни одна опция не может быть голой прозой, когда
соседи код-плотные. Гейт: backtick-count по опциям в пределах одного бакета (0 / 1–2 / 3+).

### R2 — Length parity (длина)
Длиннейшая опция ≤ 1.25× короткой; **correct не должен быть единственным длиннейшим**.
CV длины ≤ ~0.12. Если correct содержательно полнее — поднять дистракторы правдоподобной,
но ложной параллельной деталью (не ужимать correct; переизбыток уводить в `sections`,
которые рендерятся после ответа).

### R3 — Sentence-structure parity (структура)
Все 4 опции по одному синтаксическому скелету: одинаковый **зачин** (все с `backtick`-токена
или все с прозы), одинаковое **число клауз** (±1), одинаковая **форма сказуемого** (все именные
«X — это…» или все глагольные), одинаковая роль связки. Дистрактор отличается ровно одной
подменённой деталью, а не формой предложения.

### R4 — Punctuation parity (знаки препинания)
Один и тот же тире-глиф `—` в той же роли; наличие `;` зеркалится (если correct перечисляет
через `;`, то ВСЕ перечисляющие опции через `;`, остальные — без); терминальная пунктуация
единообразна (все с `.` или все без); один разделитель для списков; одинаковые скобочные
уточнения. Ни одна опция не единственный носитель `:`, `;`, `→`, нумерации `1) 2)` или скобки.

### R5 — Enumeration / catalog parity (структура списков)
Для вопросов «перечислите / какие из / что входит» все 4 опции — **равно полные каталоги**,
отличающиеся одним подменённым/неверным элементом. Запрещено «полный correct-список против
короткого списка + ложный тезис»: это самый частый визуальный tell.

### R6 — One-line acceptance (приёмка)
После R1–R5 прогнать слепой style-review: угадать correct **только по форме** нельзя
(`guessable_by_form = false`). Если у дефиниционного вопроса остаётся «lone-complete» —
проверить, что это **семантика** (единственный истинный тезис при выровненной форме), а не
форма; такой intrinsic-tell допустим и документируется в sidecar.

correct не lone-longest, backtick-паритет, слепой BST=false). Красный любой под-проверки → `◐`/`⬜`.

## Answer Completeness (отдельное измерение — колонка `ANSC`)

Введено 2026-07-13 по прямому указанию пользователя. Проверяет НЕ форму, а **содержательную
полноту каждого варианта**: и правильный, и все неправильные обязаны **полноценно и по существу
отвечать на поставленный вопрос**. Неправильный вариант отличается не тем, что он «обрезан»,
абсурден или уводит в смежную тему, а тем, что содержит одну содержательную, но неочевидную
ошибку при сопоставимой с correct структуре, объёме и глубине.

**Главный тезис.** Дистрактор — это полный правдоподобный ответ знающего-поверхностно кандидата,
внутри которого спрятана ровно одна ошибка. Не «случайная нерелевантная фраза», не «заглушка»,
не «набор несвязанных неточностей».

**Виды допустимой ошибки в дистракторе (одна основная на вариант):**
- неверно указан один из принципов/механизмов;
- перепутаны условия применения;
- пропущено важное ограничение или исключение;
- слишком широкое обобщение частично верного тезиса;
- механизм описан верно, но сделан неверный вывод;
- смешаны похожие понятия, версии API или уровни абстракции.

**Per-option чек-лист `ANSC` (каждый из 4 вариантов):**

| Проверка | Требование |
|---|---|
| Прямой ответ | Вариант отвечает именно на вопрос стема, а не на смежный |
| Самодостаточность | Понятен без сравнения с другими вариантами |
| Полнота | Есть основные условия / механизм / обоснование, нужные для ответа |
| Содержательность ошибки | Неправильность — конкретная тех. ошибка или значимый пропуск (для дистракторов) |
| Правдоподобность | Может показаться корректным поверхностно знающему тему |
| Нет очевидных маркеров | Нет абсурда, категоричных слов, искусственного упрощения, заметно меньшего объёма |
| Структурное соответствие | Сопоставим с correct по длине, детализации, терминологии, стилю |
| Единственность ошибки | Неправильность из-за одной основной ошибки, а не набора неточностей |

**Недопустимо** (отбрасывается без знания темы): `Observable` работает по HTTP и берёт элементы
из БД. — не отвечает на вопрос по существу.
**Допустимо**: полноценный ответ про pull-модель RxJava с одной конкретной ошибкой (поведение
`Flowable` с backpressure ошибочно распространено на обычный `Observable`).

**Связь с формой.** `ANSC` и `SFPL` ортогональны: `SFPL` требует, чтобы correct нельзя было
угадать по форме; `ANSC` требует, чтобы дистрактор был содержательно полным. На практике они
тянут в одну сторону — «поднимаем дистрактор до полного ответа» одновременно выравнивает и форму,
и содержательную полноту. Приёмка `ANSC`: слепой reviewer возвращает `completeness_ok = true`
(все 4 варианта — полноценные правдоподобные ответы) **и** `guessable_by_form = false`.

| Правило | Колонка | Измеримый пре-чек |
|---|---|---|
| Answer Completeness | **`ANSC`** (новая) | слепой reviewer `completeness_ok=true` + ручной чек-лист по 4 вариантам |
