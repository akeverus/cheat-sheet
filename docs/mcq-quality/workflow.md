# Полная перегенерация production MCQ одной моделью

Действующий процесс с 21 ноября 2026. Он заменяет пакеты Q/B, структурные и
эвристические гейты и обязательные фазы A/B. Исторические evidence и старые статусы
остаются справкой, но не служат руководством к запуску старых инструментов.

1. Координатор сверяет последний завершённый пакет и новые замечания, выбирает
   одну свободную тему в существующем [плане](../../PLAN_INTERVIEW.md). Не доверяет
   старому `LLM_READY` после новых замечаний и не назначает одну пару двум авторам.
2. Собирает [единый промпт](../../PROMPT_PLAN_INTERVIEW.md), целый production JSON
   из `modules/quiz-app/src/main/resources/seed/mcq/`, парный Markdown из
   `cheatsheets/interview/` и текущие замечания. Промпт задаёт структуру, факты,
   ключ, форму, смысл, пунктуацию, объяснения и связь с теорией.
3. При любом изменении, даже в одном вопросе, одна LLM заново генерирует
   **весь файл** в рамках одной задачи, сама перечитывает готовый результат и
   возвращает один полный JSON. Чтение порциями допустимо только для навигации.
   Чужие куски, точечные патчи и черновики, накопленные диапазонами, не принимаем.
   Без скриптов
   генерации, исправления, структурных или смысловых проверок, локальных/CI-гейтов.
   Код тренажёра, его загрузчик, схема как описание формата и обычные тесты
   приложения не заменяются LLM и не относятся к редакционному процессу.
4. Заменяем только назначенный JSON полным результатом. Парную теорию, если она
   требует изменений, отдельно отдаём автору шпаргалки; после её правки заново
   генерируем весь зависимый JSON. В пилоте сначала показываем Сергею один файл,
   массово не меняем корпус.
5. Отмечаем в существующем плане тему, версию, охват и `LLM_READY`, только если
   модель перегенерировала и перечитала весь файл и не осталось существенных замечаний. Это статус
   готовности по оценке модели, не доказательство независимой приёмки. При
   открытом замечании тема возвращается в очередь: добавляем его в промпт и
   снова получаем целый файл. Никаких обязательных промежуточных отчётов.

Роли: существующий координатор Cheat Sheet (Sol Low), автор шпаргалок (Sol Low),
автор MCQ (Sol Medium). Работу с кодом и UI вести отдельно от редакции контента;
для неё Sol Low. Не открывать новый чат взамен уже существующего без необходимости.

## Цель для существующего координатора

> /goal Продолжай улучшение Cheat Sheet в существующих чатах проекта и веди
> очередь в `PLAN_INTERVIEW.md`. Назначай одну тему одному автору, передавай
> полные исходные JSON и Markdown, единый промпт и замечания. Принимай от MCQ-чата
> один JSON, заново сгенерированный целиком за одну задачу, даже при замечании
> к одному вопросу. Не принимай склейку из правок диапазонов. Сохраняй форму по Jackson DTO и `seed/mcq-schema.json`.
> Предыдущий `LLM_READY` не снимает конкретного нового замечания: верни весь файл
> с обновлённым промптом. Чат шпаргалок владеет Markdown и передаёт изменения
> видимых вопросов в MCQ-очередь. UI/код не меняет материалы и не возвращает
> скриптовые гейты. Не открывай новые рабочие чаты взамен существующих.
> После готовой темы создай отдельный локальный коммит только по её файлам.
> Не включай чужие правки, не делай push без отдельного поручения. Если нужен
> следующий пакет, продолжи по плану, а при конкретном противоречии фактов уточни
> его в проектном чате. Результаты, файлы и приёмку веди только в чатах проекта.

Под капотом `McqJsonLoader` по-прежнему сверяет вход с runtime-схемой и читает DTO
Jackson. Это защита самого приложения, не проверка в редакционном процессе.
Не меняй DTO, загрузчик или схему ради нового текста и не добавляй статус в JSON.
