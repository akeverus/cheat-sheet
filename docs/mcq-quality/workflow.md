# Полная перегенерация production MCQ одной моделью

Действующий процесс с 21 ноября 2026. Он заменяет пакеты Q/B, структурные и
эвристические гейты и обязательные фазы A/B. Исторические evidence и старые статусы
остаются справкой, но не служат руководством к запуску старых инструментов.

1. Координатор выбирает одну тему в [плане](../../PLAN_INTERVIEW.md) и передаёт
   MCQ-чату [единый промпт](../../PROMPT_PLAN_INTERVIEW.md), полный исходный
   production JSON и весь парный Markdown. Не составляет замечания по вопросам.
2. Одна LLM генерирует заново всю тему одной задачей и возвращает один полный
   JSON для прямой замены. Без патчей, склейки диапазонов и редакционных скриптов.
3. Координатор сохраняет переданный полный JSON целиком и без изменений. Он
   не принимает отдельные вопросы, не проверяет вопросы, варианты, пояснения
   или JSON и не запускает повторную вычитку, другую модель, валидаторы и гейты.
   `LLM_READY` в существующем плане означает, что автор вернул полный результат.

Роли: существующий координатор Cheat Sheet (Sol Low), автор шпаргалок (Sol Low),
автор MCQ (Sol Medium). Работу с кодом и UI вести отдельно от редакции контента;
для неё Sol Low. Не открывать новый чат взамен уже существующего без необходимости.

## Цель для существующего координатора

> /goal Координируй существующие чаты Cheat Sheet. Для MCQ выбери тему по
> `PLAN_INTERVIEW.md` и передай автору полный исходный JSON, всю парную теорию
> и `PROMPT_PLAN_INTERVIEW.md`. Не составляй списки замечаний по вопросам.
> Сохрани один полный JSON целиком и как есть. Не принимай и не проверяй
> отдельные вопросы, варианты или пояснения. Не проверяй сам JSON и не запускай
> отдельную вычитку или гейты. Без патчей и склейки. Не включай чужие правки,
> не пушь и не создавай новые чаты.
>
> /goal для автора MCQ: получай от координатора весь исходный JSON, всю парную
> теорию и единый промпт. Одной задачей перегенерируй каждый вопрос, блок,
> вариант и пояснение, сохрани контракт Jackson и верни один полный JSON.
> Автор шпаргалок передаёт всю теорию через координатора. Инженер отвечает
> за runtime и UI. Оба работают в своём скоупе без отдельной проверки MCQ.

## Правило для всех этапов

Готовый файл LLM принимается целиком и как есть. Применяй требования к тексту
и формату сразу при генерации. Отдельной самопроверки, вычитки, сверки SHA-256,
повторной генерации ради проверки и валидаторов в процессе нет. Сборка, CI и
приложение также должны обходиться без специальных проверок MCQ-файлов.
Обычная десериализация JSON нужна для чтения данных приложением.

Снятие существующих проверок в сборке и загрузчике — отдельная инженерная
задача. Этот документ задаёт правило и не подтверждает, что код уже изменён.
