## Открытые находки по содержанию и полноте вариантов

1. Security Q17: A путает at rest/in transit, D приписывает TLS шифрование диска. Это близкие модели ошибки; для трёх содержательно разных дистракторов нужен отдельный ANSC-проход. Correct C и его пояснения почти не раскрывают выбор слоя шифрования и границы угроз. OWASP связывает выбор слоя с threat model и отделяет key management от шифрования: [Cryptographic Storage](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html). Это не новая настройка реальной системы.
2. Теория Security Q17, строки 912–913: «Transparent Data Encryption в PostgreSQL, Oracle» и KMS как шифрование файлов требуют версии/дистрибутива/провайдера и разделения ролей. Документация PostgreSQL18 описывает pgcrypto для столбцов и файловое/блочное шифрование; сам исходный текст не уточняет реализацию TDE. Вывод этого ревью: требование уточнения, а не доказательство отсутствия TDE во всех дистрибутивах. [PostgreSQL18 encryption options](https://www.postgresql.org/docs/18/encryption-options.html).
3. Security Q36 B.text и D.text содержат «якобы», что подсказывает неверность формулировки; A.text содержит лишнюю точку с запятой внутри определения. Это конкретные RU/SFPL-замечания, которые не выявил общий parity PASS. Для следующей редакции убрать маркеры недостоверности и сохранить исходные ошибочные модели «перед релизом дешевле» / «аутентифицированному вводу доверяют».
4. Security Q36 correct C.text, B.what_actually, C.edge_cases и теория:1698 обещают экономию «кратно»/«на порядки», а исправление на дизайне стоит «копейки». Без условий и измерения это нельзя принимать как универсальный факт. Предлагается оставить определение подхода — требования безопасности входят в проектирование и жизненный цикл — без обязательного множителя стоимости. [OWASP security principles](https://devguide.owasp.org/en/02-foundations/03-security-principles/).
5. Rate Limiter Q20 correct B.text и A/D.sections, теория:854–855: sub-ms и «80%+ DDoS» представлены без условий. Нельзя переносить это на каждую архитектуру. Correct B также фиксирует shared Redis и три слоя как обязательное устройство вместо конкретного примера; вопрос и теория должны явно задавать выбранный сценарий.
6. Rate Limiter Q20 C: общий тезис, что edge не делает более точных проверок по идентичности/endpoint, чрезмерен. Cloudflare поддерживает rate-limit characteristics по path, заголовкам, cookie и JWT claims; набор зависит от тарифа. Это опровергает универсальный вывод «edge — только IP», но не означает, что можно доверять произвольному клиентскому заголовку. [Cloudflare parameters](https://developers.cloudflare.com/waf/rate-limiting-rules/parameters/). Текущий русский перевод привязан только к показанной схеме; полный вопрос остаётся UNVERIFIED.
7. Rate Limiter Q20 A/C/D.text включают собственные негативные последствия и объяснения заблуждения. Например, A после своего тезиса объясняет, что весь DDoS бил бы в один кластер; C объясняет, почему перепутаны слои; D описывает выжигание compute. Дистракторы выдают своё опровержение. Следующая содержательная редакция должна оставить четыре сопоставимых архитектурных предложения, перенести разбор в sections и убрать непроверенные проценты.
8. Test Strategies Q25 C.what_actually безусловно запрещает ручную регрессию, B.what_actually и D.edge_cases требуют exploratory каждый спринт. TDD/BDD/contract в примере не следует выдавать за обязательный набор Scrum. Scrum Guide требует качества по Definition of Done и оставляет контекстные техники команде. [Scrum Guide](https://scrumguides.org/scrum-guide.html). Нужна синхронизация с теорией:1053–1054; перевод примера сам по себе эти ошибки не устраняет.
9. Test Strategies Q34: общие советы о слоях/Page Objects поданы как универсальные утверждения. Нужны условия задачи (например, повторяющиеся UI/API сценарии с дорогими изменениями селекторов) и явное различие осмысленного минимализма и избыточной абстракции. D о запасе расширения и B о прямом доступе не следует отвергать только за философский стиль — необходимо сделать неверный выбор опровержимым условиями задачи. Это finding ANSC/полноты, а не автоматически доказанный FACTS FAIL любой прямой структуры.
