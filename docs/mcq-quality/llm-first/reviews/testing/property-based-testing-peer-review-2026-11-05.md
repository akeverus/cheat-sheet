## Конкретные замечания

- **Q1 (MAJOR, OPEN):** Случайная генерация — не единственный режим PBT. Конечный прогон не доказывает свойство на всём домене; shrinking не гарантирует глобальный минимум, может быть выключен.
- **Q2 (MAJOR, OPEN):** D допускает истинный случай: сформулировать свойство иногда проще примеров. Double reverse — инволюция, не идемпотентность; имя test_reverse_idempotent неверно.
- **Q3 (MAJOR, OPEN):** Fuzzing может проверять assertions/properties, не только падения. Автоматическое сохранение и повтор контрпримеров зависят от инструмента и конфигурации, не универсальны.
- **Q4 (MAJOR, OPEN):** Правдоподобный C: optimized может быть проверенным oracle для исследуемого naive. Не гарантировать шаблон для практически любой функции. Стабильность сортировки не равна идемпотентности.
- **Q5 (MAJOR, OPEN):** C верен для подходящих example-тестов Unicode/NaN. Round-trip требует домена и отношения эквивалентности. В данном генераторе integer values NaN не бывает; неограниченный int может превысить лимит десятичного преобразования CPython.
- **Q6 (MAJOR, OPEN):** Идемпотентность f(f(x))=f(x) требует замкнутости домена. Double reverse — иное свойство. Повторяемый результат не доказывает стабильность сортировки равных ключей.
- **Q7 (BLOCKER, OPEN):** Ключ A ошибочен: инвариант зависит от контракта операции; оговорка «независимо от того, что делает функция» неверна. C не определяет инвариант вообще. Длина/сумма недостаточны: [1,3] -> [2,2].
- **Q8 (MINOR, OPEN):** Уточнить историческое утверждение о QuickCheck статьёй Claessen/Hughes ICFP2000; не обобщать происхождение и устройство всех PBT-фреймворков как буквальные порты.
- **Q9 (MAJOR, OPEN):** Ключ B безусловно обещает диск и первый запуск. Есть in-memory/disabled DB, explicit phase может предшествовать reuse; cache не заменяет обязательный regression. Upper/lower пример ломается уже на ASCII A; contains_special не определён.
- **Q10 (MAJOR, OPEN):** jqwik — отдельный JUnit Platform engine, не Jupiter lifecycle. Допустимы custom @Provide, не только аннотации диапазона; не заявлять API runtime без зависимости. Избавиться от сравнительного рейтинга без источника.
- **Q11 (MAJOR, OPEN):** fc.property строит property, fc.assert исполняет. .join сравнение подходит не любой структуре; reverse может менять исходный массив. Для async нужен asyncProperty. Маркетинговый D лучше заменить конкретной неверной моделью API.
- **Q12 (MAJOR, OPEN):** Генератор не обязан быть только случайным: constant/enumerated и иные режимы допустимы. st.from_regex по умолчанию ищет совпадение, не fullmatch. Не обещать исчерпывающий охват.
- **Q13 (BLOCKER, OPEN):** C может описывать допустимую зависимую композицию в обратном направлении: сначала список, потом зависимое число. Стем не ограничивает конкретный пример. Теория/пример D используют st.integers() для min_size/max_size, включая отрицательные размеры.
- **Q14 (MAJOR, OPEN):** draw получает значение стратегии; бизнес-валидность задаёт автор. UUID уже поддержан st.uuids, не является общим примером строки с контрольной суммой. 12 произвольных цифр + checksum ещё не гарантируют валидный ISBN: нужны prefix и прочие элементы/область проверки.
- **Q15 (BLOCKER, OPEN):** Учебная демонстрация shrinking невозможна: [42,-7,100,13] проходит sorted(lst)[-1]>=sorted(lst)[0], а [] даёт IndexError; указанного большого падающего примера нет. Не обещать глобальную минимальность или безусловное исчерпание всех упрощений.
- **Q16 (MAJOR, OPEN):** Сравнительное «Hypothesis особенно силён» и «половина пользы» без метрики не проверяемы. Упрощение помогает диагностике, но не гарантирует немедленно ясную причину; пределы/бюджет/воспроизводимость имеют значение.
- **Q17 (BLOCKER, OPEN):** len+set+order пропускают [1,1,2] -> [1,2,2]. Swap-only-ends удовлетворяет всем трём данным reverse свойствам, но не разворачивает [1,2,3,4]. Набор свойств не является доказательством полной корректности; одно достаточно сильное свойство тоже возможно.
- **Q18 (MAJOR, OPEN):** Совместное использование примеров и PBT корректно; один класс допустим, не обязателен. Генерация не исполняет бесконечно много входов, и класс сам по себе не объединяет lifecycle разных engine.
- **Q19 (MAJOR, OPEN):** D не заведомо ошибочен: модель/эталонная реализация можно сравнивать симметрично при обоснованном oracle. Пример не импортирует invariant, не задаёт Stack/запуск .TestCase. Разработчик задаёт assertions и model: фреймворк не выводит их автоматически.
- **Q20 (MAJOR, OPEN):** Чистота облегчает изоляцию и исполнение, но не даёт монотонной гарантии большей пользы: stateful/DB/сеть могут быть важными целями. Определяющие условия — проверяемый контракт, управляемое состояние, стоимость, воспроизводимость.
- **Q21 (MAJOR, OPEN):** «Главный барьер» и универсальное сравнение сложности с примерами контекстны; C иногда правдоподобен. Убрать неподтверждённый mainstream/популярность2025, не исключать UI/интеграцию категорически.

Все четыре варианта сопоставлялись по смыслу. Указанные AMBIGUOUS/NO_VALID_OPTION — дефекты задания, а не незнание выбранного ключа. Для исправления нужны объективные границы вопроса и одна основная ошибочная модель каждого wrong. В частности, Q4 C/Q5 C/Q13 C/Q19 D нельзя опровергать условием, которого нет в видимом вопросе. Смена только sections оставит неоднозначные тексты ответов. Q21 также нельзя проверять как универсальный рейтинг трудностей.

SFPL/ANSC/RU требуют повторной оценки на исправленном пакете: исходные варианты часто противопоставляют короткую категоричную ошибку развёрнутому правильному ответу, используют неограниченные «всегда», «все», «лишь», «не зависит». Механическое выравнивание длины, снятие backticks ради regex или замена терминов не решит смысловые дефекты. Сам по себе красный pre-check не заменяет редакторскую оценку, а зелёный не устраняет неоднозначность.

## Первичные источники и пределы утверждений

На дату аудита прочитаны [Hypothesis6.170.14 strategies](https://hypothesis.readthedocs.io/en/latest/reference/strategies.html): constant/enum стратегии, `flatmap`/`composite`, `from_regex(fullmatch=False)`, `uuids`, shrinking структур; [API](https://hypothesis.readthedocs.io/en/latest/reference/api.html): настраиваемые фазы, explicit/reuse, example DB как cache, in-memory backend. Эти настройки опровергают безусловное обещание диска и «первого» запуска. [Stateful guide](https://hypothesis.readthedocs.io/en/latest/stateful.html) описывает цепочки rules, invariants, preconditions и запуск TestCase; проверяющие assertions пишет автор. [External fuzzers](https://hypothesis.readthedocs.io/en/latest/how-to/external-fuzzers.html) показывает совместимость property-теста и fuzz target.

В [jqwik1.9.3 guide](https://jqwik.net/docs/1.9.3/user-guide.html) проверены отдельный JUnit Platform engine, `@Example`, собственный lifecycle, `@Provide`, exhaustive generation и bounded shrinking. Ограниченный по времени режим опровергает универсальную гарантию глобального минимума для любого PBT. Это документационная сверка конкретной версии, не компиляция с jqwik. В [fast-check Getting Started](https://fast-check.dev/docs/introduction/getting-started/) проверены разделение `fc.property`/`fc.assert` и `fc.asyncProperty`. [International ISBN Agency](https://www.isbn-international.org/content/what-isbn/10) указывает prefix978/979 и другие элементы ISBN; одной вычисленной контрольной цифры недостаточно для обещания валидного номера. История QuickCheck сверена с [авторской страницей](https://www.cse.chalmers.se/~rjmh/QuickCheck/) и статьёй Claessen/Hughes ICFP2000.
