## Q12

Видимый вопрос: «Что такое scope-функции (`let`, `run`, `with`, `apply`, `also`)?». Прежние A/B проверяли только отдельную функцию, а контрфакты A/D необоснованно выводили невозможность builder или ненужность пяти функций. Новые тексты описывают все пять функций по двум осям и явно относятся к вызовам с объектом.

| Вариант | Полнота, верность и попытка защиты |
|---|---|
| A | Полная модель доступа и возврата. Доступ описан верно, группы возвратов переставлены; результат последнего выражения не является контрактом возврата любой функции. |
| B | Полная модель обеих осей. Группы аргументов/получателей переставлены; конкретный let с явно названным аргументом опровергает модель. |
| C | Полный защитимый ключ. Let/also используют аргумент, объектные run/with/apply — получателя; apply/also возвращают объект, остальные — результат лямбды. |
| D | Полная ложная модель одинакового возврата объекта всеми пятью функциями. У let/run/with возможен результат другого типа. |

Все пояснения перечитаны после замены текстов. Имя it не объявляется обязательным, with отличён как обычный аргумент функции и получатель внутри её блока. Перегрузка run без объекта вынесена в границы применимости; она не является скрытым условием, поскольку видимые варианты сами описывают вызовы с объектом. Общая теория Q12 прямо раскрывает две проверяемые оси и таблицу поведения.

## Q20

Видимый вопрос: «В чём разница между `lazy` и `lateinit`?». Удалена самоподсказка «ровно наоборот их назначению». Каждый вариант теперь сравнивает оба механизма, а не только одно из свойств lazy или lateinit.

| Вариант | Полнота, верность и попытка защиты |
|---|---|
| A | Полная модель с переставленными val/var. Для стандартного делегата отсутствует setValue; lateinit применяется к var. Пользовательский extension setValue не дан в условиях и не оправдывает wrong. |
| B | Полная модель, неверно снимающая ограничения nullable/primitive у lateinit по аналогии с результатом lazy. |
| C | Полная модель пересчёта lazy при каждом чтении, смешанная с верным явным присваиванием lateinit. Retry после исключения не оправдывает пересчёт при каждом успешном чтении. |
| D | Полный защитимый ключ: lazy вычисляет и сохраняет результат val, lateinit требует явного присваивания var до чтения; источник присваивания не обязан быть внешним. |

Пояснения различают var, хранящий Lazy<T>, и var by lazy; успешное кэширование и повтор после исключения; синхронизацию Kotlin/JVM по умолчанию и возможные повторные вызовы при PUBLICATION. У lateinit оговорены non-null непримитивный тип, допустимая область isInitialized и отсутствие добавленной модификатором синхронизации.

**Теория Q20 остаётся блокером.** В первом абзаце «извне» / «значение придёт снаружи» поданы как определяющее условие; таблица содержит «Всегда инициализирован при доступе». Нужно заменить первое на явное более позднее присваивание, включая метод того же объекта, а второе — на условие успешного вычисления и повтор инициализации после исключения. Это FACTS/LINKAGE, а не автоматический дефект русского языка или формы вариантов. Точная передача — в `theory-owner-handoff.json` нового run. Исправленный JSON Q20 не объявляется FINAL до синхронизации и повторной независимой проверки.
