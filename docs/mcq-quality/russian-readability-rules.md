# Человекочитаемость на русском языке — RU

Самостоятельный обязательный критерий [стандарта MCQ](../mcq-quality-standard.md).
Относится к каждому файлу и каждому блоку. Читатель — человек, изучающий техническую
тему; ему не должно требоваться расшифровывать искусственный язык ради выбора ответа.

## Что проверять

- Видимый вопрос из `## Q<N>` Markdown: понятная задача, явные условия, однозначные связи слов.
- Тело соответствующего Q: объяснение читается последовательно, термины используются устойчиво.
- Все A/B/C/D: одинаково естественный русский язык и профессиональный уровень изложения.
- Все `sections`: включая прозу в `example` и `related`, а также русские пояснения к коду.

Правильный и неправильные ответы проходят одни языковые требования. Ошибка wrong должна
быть технической/содержательной, а не распознаваться по плохому русскому языку.
JSON `question_text` не подменяет проверку видимой формулировки вопроса.

## Критерии редакторского прохода

| Проверка | Требование |
|---|---|
| Понятность первого чтения | Понятно, кто/что действует, при каком условии и что получается; не приходится угадывать пропущенные связи |
| Естественная терминология | Обычные для области слова; без искусственных замен вроде «поле-голое значение», «родится пустотою» или неопределённого «тела» вместо объекта |
| Грамматика | Согласование, управление, падежи, порядок слов и местоименные отсылки однозначны |
| Связность | Условия, причины, следствия и исключения соединены логично; нет обрубленных фрагментов и машинных цепочек |
| Сложность | Длина фразы оправдана смыслом; вложенные условия разделены, когда это облегчает чтение |
| Конкретность | Формулировка говорит о механизме; отсутствуют пустые зачины, канцелярит и искусственная академичность |
| Нормальный русский технический текст | Английская проза не заменяет русское объяснение; API, код, имена продуктов и общепринятые термины сохраняются |
| Единообразие | Одна сущность называется одинаково в вопросе, вариантах и объяснениях; термин объяснён, если аудитория может его не знать |
| Оформление | Орфография, пунктуация, списки и inline-код помогают чтению; нет повреждённых символов и случайной разметки |

Нельзя повышать «русскость» заменой `primitive`, `null`, имен API или известных терминов
непонятными авторскими метафорами. Доля кириллицы не является критерием приёмки.
Краткий кодовый ответ допустим, если его требует вопрос. Сложная техническая мысль
не обязана укладываться в фиксированное число слов.

## Автоматическая часть уже существует

`scripts/audit-mcq-parity.py --readability` проверяет варианты и часть прозаических
sections: английскую прозу, пустые зачины, перегруженные предложения, стрелки,
разделители и некоторые пунктуационные проблемы. В старом режиме не проверяются
видимый вопрос/теория, а `example` и `related` исключены целиком.

Полный текущий инвентарь **повторно использует те же эвристики**, расширяя охват:

```bash
python3 scripts/mcq-audit.py \
  --output docs/mcq-quality/audit-state.json \
  --checklist-output docs/mcq-quality/file-checklist.md
```

В `readability_precheck` каждой темы — сигналы с Q/B и точным полем. Проверяются видимый
заголовок, тело Q, все опции и проза каждого поля sections. Fenced-код исключается из
языковой статистики, таблицы/списки не склеиваются в одно длинное предложение.
Комментарии внутри кода, текст диаграмм, общий пролог темы и связность между абзацами
остаются частью редакторского прохода: автоматическое покрытие этих областей не заявлено.

`SIGNALS` / `NO_SIGNALS` описывают только диагностику. Даже короткая, грамматически
правильная фраза может быть нечитаемой из-за неестественных терминов; regex не способен
надёжно принять такой текст. Порог в 45 слов и списки клише — сигналы для разбора,
а не требование механически сократить предложение или удалить конкретное слово.

## Независимое решение RU

Рецензент читает полный оговорённый пакет как учебный текст. По каждому Q/B возвращает:

1. `RU: PASS / FAIL / UNVERIFIED` отдельно от фактов, SFPL и ANSC.
2. Перечень прочитанных поверхностей: вопрос, теория, A/B/C/D, все sections.
3. Для дефекта — label/поле, точную цитату, объяснение затруднения и предложенную редакцию.
4. Итог разбора автоматических сигналов и оставшиеся непроверенные области.
5. Пути, исходные хеши JSON/Markdown, версию стандарта, вид прохода и ревьюера.

PASS возможен только после чтения всего заявленного покрытия. При частичной проверке
фиксируются конкретные Q/B и UNVERIFIED для оставшегося скоупа. Общая отметка AUDITED,
успешный ответ на MCQ и отсутствие предупреждений не подтверждают RU.

Редакторская правка сохраняет исходный технический смысл и ошибочную модель wrong.
После неё проверяются ключ, опровержимость wrong, согласованность sections и сравнительная
форма всех четырёх опций. Нельзя случайно превратить wrong в правильный ответ или сделать
correct единственным хорошо написанным вариантом.

[Таблица файлов](file-checklist.md) содержит отдельную обязательную RU-проверку для всех
318 тем. `readability_review_queue` задаёт приоритет 176 уже обновлённых тем, не исключая
блоки без сигналов. Фактическая редакторская вычитка выполняется только в выделенных
бюджетных пакетах; текущий скан не выдаёт себя за такую вычитку.
