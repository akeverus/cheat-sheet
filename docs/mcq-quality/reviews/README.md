# Исторические review-sidecars

Для новых результатов используйте [переносимый workflow](../workflow.md) и
`scripts/mcq-workflow.py`: он создаёт актуальные хеши и черновик, фиксирует две фазы,
проверяет результат перед добавлением. Схема ниже остаётся общей для любой LLM.

Файлы тем содержат заявления разных раундов и разной структуры. Поле AUDITED,
дата или список агентов сами по себе не доказывают полноту проверки.

Действующий стандарт: [mcq-quality-standard](../../mcq-quality-standard.md).
Процесс: [PROMPT_PLAN_INTERVIEW](../../../PROMPT_PLAN_INTERVIEW.md).
Текущая проверка применимости: [audit-state.json](../audit-state.json).
Новые evidence текущего аудита: [audit-evidence.json](../audit-evidence.json).

Старые записи не переписываются в PASS нового стандарта. Хеши пары и покрытие
проверяются отдельно; изменение контента инвалидирует зависимые результаты.

## Результаты текущих проверок

`scripts/mcq_evidence.py` загружает компактные записи `checks/*.json`.
`mcq-audit.py` вычисляет из них `files[].checks`, общий `check_queue` и покрытие
каждой проверки в `summary.check_coverage`. Общая очередь включает TODO после AUDITED.
Указание в протоколе SFPL/ANSC «отдельной схемы пока нет» описывает исходное
состояние до этого продолжения; подключение первого пакета теперь выполнено.
Содержательные критерии протокола не менялись.
Старые `audit-evidence.json.reviews` сохраняют факт чтения и его актуальность;
они не превращаются в новые PASS. Отдельные очереди формы и RU относятся к обновлённому
множеству и исключают только принятые блоки соответствующей проверки.

Рабочий пример полной записи: [пилот Q1–Q5](checks/2026-09-14-functional-pilot.json).
Обязательные поля: `review_id`, `reviewer`, `author`, `model` (null для неизвестной),
`date` с часовым поясом, `kind`, `paths`, исходные полные `sha256`, `rules_sha256`,
`coverage`, `findings`, `sources`, `limitations`. Допустимые виды прохода:
`author`, `independent`, `independent_two_phase`, `human`.

Каждый элемент `coverage` содержит `q_number`, `block_idx`, блочную пару `sha256`
из `mcq-audit.block_hashes` и `checks`. В checks указываются только реально выполненные
проверки с `{status, reason}`; остальные остаются NOT_RUN. Технические имена:
`content_review`, `factual_correctness`, `source_linkage`, `sections_consistency`,
`sfpl`, `ansc`, `russian_readability`, `independent_review`, `blind_review`,
`final_acceptance`. SCHEMA выполняется при генерации и привязывается к хешам пары,
валидатора и его диагностике. Для BLOCKED обязателен конкретный `blocker`.

Полные хеши сохраняют исходный снимок; применимость определяется по блоку, телу Q
и прологу. Дополнительные смысловые зависимости указываются в
`coverage[].dependencies` как `{relative_path: sha256}`. Правка другого блока
не обнуляет текущий результат, изменение зависимого текста или правил даёт STALE.
Изменение общих правил требует нового результата или явной оценки их применимости;
само совпадение даты/модели не сохраняет приёмку.

Результаты упорядочиваются по ISO timestamp. Открытая находка имеет приоритет над PASS:
`{id, check, blocks: ["Q1:B0"], status: "OPEN", reason}`. Чтобы закрыть её, новая
запись указывает тот же id/check/blocks, `status: "RESOLVED"`, причину и актуальный
PASS после перепроверки. Старые unresolved findings не теряются при смене хешей.
Исторические `audit-evidence.json.open_issues` закрываются явно с resolution/evidence;
runtime-находки блокируют FINAL затронутых вопросов.

Независимый ревьюер отличается от автора. Для слепого прохода `phase_a` ссылается
на сохранённый JSON с SHA-256, содержащий reviewer, kind=blind_phase_a, recorded_at,
input `{path, sha256}` и answers с выбором по Q/B. `revealed_at` обязан быть позже
recorded_at и не позже даты итогового ревью. Проверяется содержимое экспорта:
только видимый вопрос, метки и тексты, без ключа и sections; оно должно совпадать
с текущими вариантами. `blind_input_archive` позволяет хранить копию исходного
экспорта в репозитории, сохранив первоначальный артефакт фазы A неизменным.
`review_artifact` связывает результат с полным независимым разбором.

FACTS требует не пустого списка URL, а записей `{url, used_for, version, checked_at}`.
`checked_at` — реальная календарная дата ISO (`YYYY-MM-DD`) либо ISO timestamp
с часовым поясом; произвольный текст не принимается.
Само наличие этих полей не заменяет чтение первичного источника исполнителем.
SFPL/ANSC/RU требуют отдельных вердиктов и сравнительных наблюдений в артефакте.
FINAL требует явного вердикта и PASS всех остальных проверок конкретного блока.
Частичный успех не принимает файл целиком; в снимке видны passed_blocks,
remaining_blocks, block_statuses, open_findings и evidence каждой проверки.
`block_statuses` хранит только выполненные/проблемные результаты; для отсутствующего
в нём блока из `all_block_ids` действует явный `default_block_status: NOT_RUN`.
Это компактное представление, а не исключение блока из охвата: remaining_blocks
по-прежнему перечисляет весь незакрытый скоуп.

Для экономного обновления одной темы:

```bash
python3 scripts/mcq-audit.py \
  --topic programming-languages/java/java-functional-interface-interview.json \
  --output work/mcq-audit/topic.json
```

Частичный снимок помечен `partial_snapshot: true`; команда запрещает перезапись им
глобальной таблицы или `audit-state.json`. Полная регенерация выполняется на контрольных
точках. Ошибочный JSON evidence, неизвестный Q/B и неверная пара отклоняются, а не
превращаются в PASS. Отсутствие evidence даёт NOT_RUN.
