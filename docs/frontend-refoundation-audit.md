**Назначение.** Консолидированный аудит текущего состояния фронтенда Cheat Sheet — Phase A программы рефаундации. Итог — дедуплицированный бэклог P0–P3 и секция STATE для Phase B.

## 1. Current product model

Продукт — одиночный тренажёр подготовки к техническим интервью: банк **9818 вопросов** импортируется из `cheatsheets/interview/**/*.md`, MCQ-варианты — из seed-JSON (`OptionLookupService`); AI-генерации нет как свойства кода. Поверх банка — SRS-планировщик (SM-2/FSRS), XP/уровни/ранги «гильдии», серия дней, закладки с заметками, журнал занятий (агрегаты, V29).

Ядро — цикл «вопрос → ответ → вердикт → разбор → следующий». Режимов восемь (`InterviewMode.java:20-45`), из них четыре — recall-семейство с одной механикой и разной поверхностью ввода. Дефолтный режим TRAINING работает **без сессии** («идёт, пока не остановишь», `ModeUtils.java:243`); сессии EXAM/MARathon/STUDY собираются конструктором, живущим на `/settings`.

Три разрыва модели, найденные аудитом:
- **Тупик optionless-вопросов**: 42 из 9818 вопросов в живой БД не имеют MCQ-вариантов; внутри EXAM/MARATHON/STUDY такой вопрос форсит flashcard-режим без единого POST, двигающего сессию — «Следующий вопрос» возвращает тот же вопрос (UX-01, код-трасса `FocusTrainingPageService.java:123-126`, `focus-training.html:648-662`, `InterviewService.java:169-176`).
- **Дефолтный поток не имеет завершения**: до `/session-summary` (лучший ориентационный экран продукта) из TRAINING не доехать; тренировка без сессии не попадает в журнал (IA-07, `focus-training.html:216`, live: GET /session-summary → 302).
- **Жизненный цикл сессии без защит**: resume-баннер не имеет «Отбросить» (`PauseService.discard()` — 0 вызовов), повторный «Начать тренировку» молча затирает активную сессию без записи итогов (UX-02, UX-03).

Прогрессия (XP/уровни) начисляется в каждом ответе, но шкала видна только на /stats и в итогах — в основном ежедневном цикле она невидима (UX-05).

## 2. Current visual language

Действующее арт-направление — **«мастерская гильдии»** (FRD-063…066, введено 2026-08-11): латунь/тёплый камень в тёмной теме, пергамент/чернила в светлой. Светлая тема — полноценный второй материал, а не перекраска (пергамент #ece4d3 / лист #fdfaf2 / охра #8a6414), семантика статусов и AA-калибровка выдержаны в обеих темах (`tokens.css:460-539`). Типографический голос состоялся: Literata на вопросах, разделах и крупных числах; Inter в контролах — дисциплина ролей соблюдена (`tokens.css:174-194`).

Pixel-язык дозрел до art-direction: маски-глифы 16×16 на currentColor, герб-щит, XP-бар, угловые брекеты, пиксель-ступени прогресса, радиусы 0 через токены. Прежний teal-«instrument» и аркадный словарь (монеты/черепа/жизни) сняты целиком (FRD-102/104).

Дыры визуального языка:
- **Pixel-слой недотемизирован в light**: `pixel-fx.css` заводит вторую палитру из 5 hex-дубликатов токенов (VIS-05); вердикт-рамки MCQ в светлой теме 1.71:1/2.35:1 при пороге 3:1 (VIS-06); запрет темизации `--pixel-gold`/`--pixel-flame` держится на устаревшем доводе «PNG не знает темы» при нуле PNG (VIS-14).
- **Аналитика визуально сломана**: пустые графики с нечитаемыми подписями (VIS-01), вкладка «Динамика» не меняет контент (VIS-02), два противоречащих числа точности 23% и 8,1% (VIS-04), мёртвая зона ~640×700px (VIS-03).
- **Числовой HUD глушит вопрос**: 7+ числовых групп над заголовком экрана тренировки (VIS-07).
- Хвосты: ~14 токенов-сирот, motion-шкала схлопнулась до одной скорости 120ms, чужой Material-красный #B3261E в трёх fallback (VIS-15/VIS-08/VIS-18).

## 3. Current information architecture

Первый уровень — 5 разделов из единого источника `NavSection` (enum + бин `@nav`): Тренировка `/`, Темы `/topics`, Аналитика `/stats`, Закладки `/bookmarks`, Настройки `/settings`. Рельс и мобильный док читают один список, паритет и aria-current подтверждены живым DOM.

Главные структурные долги — ровно нереализованные P1-пункты целевой IA (`work/redesign/docs/05_INFORMATION_ARCHITECTURE.md:26-28`):
- **Session-start похоронен под «Настройками»** (IA-01): все дороги «Собрать сессию» (topics, stats, error, summary) ведут в раздел с именем и h1 «Настройки», где первая вкладка — конструктор. Ярлык раздела и словарь CTA не совпадают.
- **«Вопрос» как объект не имеет адреса** нигде, кроме закладок (IA-04): поиск, «Последние ошибки», ошибки итогов ведут на тему — хотя `/(questionId=…)` существует и данные (questionId) уже в моделях.
- **Разбор ошибок раздвоен**: два адреса (`/review` и `/?onlyWrong=true`) с разным обрамлением и 4-5 именами; на одной карточке /stats оба CTA рядом (IA-05, IA-10).
- **Поиск раздроблен**: полнотекстовый поиск вопросов — внутри «Аналитики», поиск тем — на /topics; глобального нет (IA-09).
- Главная = сразу случайный вопрос без ориентации «что делать сейчас» — блок next-action живёт на /stats (IA-06; конфликт с REJECTED-решением прошлого цикла — см. §15).

Дубли поверхностей: «Темы» — имя и раздела /topics, и вкладки в /stats (IA-13); «Тренировка» — и раздел, и один из восьми режимов (IA-14).

## 4. Current navigation model

Сильная основа: `NavSection` — единственный источник первого уровня с гейтами-тестами; легаси-маршрут `/training → /` канонизирован 302-редиректом с whitelist-переносом параметров (проверено live); контекстный вход в разбор ошибок появляется только при наличии ошибок и несёт число.

Дефекты навигационного слоя:
- **localStorage перебивает deep-link'и конструктора** (IA-03): pre-paint скрипт восстанавливает последнюю вкладку /settings без учёта `?topic=`/`?group=` — клик «Собрать сессию по разделу» может показать панель «Оформление» (`head.html:88-103`, `ui/tablist.js:89-100`).
- **Клик по теме означает разное**: в «Аналитике» — тренирует в 1 клик, в «Темах» — уводит в конструктор, 3 шага (IA-08).
- error.html на любой ошибке подсвечивает «Тренировка» как aria-current (IA-11); готовые hash-deep-links вкладок аналитики (#errors, #dynamics) не использует ни одна внутренняя ссылка (IA-12); журнал занятий — тупик без drill-down (IA-15).
- Ссылки, выглядящие как конкретный вопрос (похожие вопросы, список ошибок), ведут на тему — открывается не тот вопрос, по которому кликнули (слито в IA-04).

## 5. Current task model

Ключевые задачи пользователя и их состояние:
- **«Ответить на вопрос»** (ядро): путь силён (no-JS паритет, порядок вердикт→мета→действие→разбор согласован, sticky CTA), но на телефоне-портрете вопрос под фолдом за 437px хрома (RSP-01), а optionless-вопрос в сессии — тупик (UX-01).
- **«Собрать сессию»**: спрятана под «Настройки» (IA-01), deep-link ломается localStorage (IA-03), число «20» зашито в шаблон и не запоминается (UX-12), запуск молча затирает активную сессию (UX-03).
- **«Разобрать ошибки»**: два адреса, 4-5 имён, включая ссылку на несуществующую кнопку в подсказке итогов (IA-05, IA-10).
- **«Повторить закладки»**: главный CTA страницы тренирует не показанную коллекцию, а ~4000 seed-«(!)»-вопросов — самая грубая ложь интерфейса текущей IA (IA-02, `bookmarks.html:90` → `important=true`, `MarkdownQuestionParser.java:134`); CTA игнорирует и активный отбор коллекции.
- **«Понять, что делать дальше»**: ответ живёт на /stats («Что делать дальше», честные счётчики) — но из дефолтного TRAINING туда не ведёт ни завершение (его нет, IA-07), ни главная (IA-06).
- **«Найти вопрос про X»**: надо догадаться пойти в «Аналитику» (IA-09).

## 6. Current responsive model

Контейнерная система зрелая: единая шкала `--max-width-page: min(100%,112rem)` после снятия четырёх замороженных капов; культура content-failure — пороги выбраны по замеру поломки контента и задокументированы в комментариях; ultrawide ≥2240 — настоящая трёхзонная композиция (проверено live на 2560: колонки 960/640/352, код влезает целиком). Горизонтального оверфлоу нет нигде (замеры на 12 вьюпортах × 6 страниц).

Провалы — по краям и в середине диапазона:
- **375 портрет**: перед вопросом 437px дашборд-хрома (resume-banner + session-rail), первый вариант ответа — на втором экране (RSP-01, скрин `train-375-fold.png`).
- **Ландшафт телефона**: хром съедает 48% высоты, окно контента 194px; orientation/max-height-запросов в CSS ноль (RSP-02).
- **901–1279**: варианты и CTA под фолдом при одноколонке — sticky CTA невидим, fixed он только ≤900 (RSP-04).
- **1280–1440** (самые массовые ноутбуки): сплит включается, но листингу не хватает ширины — до 180px кода обрезано (RSP-03).
- **safe-area мёртв**: 30 использований `env(safe-area-inset-bottom)` в 8 файлах не работают без `viewport-fit=cover` в head.html (RSP-05).
- Немонотонность на границе 1200px: окно растёт, полоса сужается на 46px (RSP-06). Канона шкалы брейкпоинтов нет: 29 значений, кластеры 760/767/768, 1199/1200, 1279/1280 (слито в ARCH-07).

## 7. Current component model

Компонентные системы единственны и защищены решениями прошлого цикла: одна система полей `.field`, кнопка 3 роли/6 рангов с единой фокус-идиомой, одно сообщение `.notice`, одно пустое состояние (11 состояний под `EmptyStateSystemContractTest`), таблица + `.table-scroll`, ARIA-вкладки одной реализацией (`ui/tablist.js`), модалки с inert/focus-restore. Дублирования разметки между шаблонами ноль (поиск общих 8-строчных окон дал 0), 39 ES-модулей по каталогам со страничными кластерами через динамический import.

Долги компонентного слоя — в способе выражения состояний:
- **Машина состояний экрана вопроса живёт в :has()-селекторах**: 96 из 124 `:has()` всего CSS — в одном pages-focus.css; режимы вычисляются каскадом из структуры DOM, а не объявляются сервером (ARCH-09).
- **Конкурирующие определения**: одно свойство задаётся дважды на дистанции 1500+ строк, 20 селекторов-дублей в pages-focus.css (ARCH-08).
- Отдельные компоненты выпадают из систем: `.bookmark-remove-btn` 42×23 ниже минимума 24px, summary заметки без coarse-ранга (A11Y-08); заголовки вопросов в закладках — Inter вместо Literata (VIS-22).

## 8. Current design tokens

`tokens.css` — образцовый токен-слой: каждое значение с обоснованием и замером контраста, задокументированные удаления, единственный слой определения цвета, потребление через var(), rgba-литералы запрещены гейтом. НО:

- **Подтверждённый дефект**: сломанный комментарий `tokens.css:445-450` (строка `--radius-*/` закрывает комментарий досрочно) — сырая проза утекает в `:root` каждого из 9 страничных бандлов, а syntax-гейт `css-leak-audit.py` горит вечным «BROKEN (44 файлов)» — alarm fatigue обесценивает сам гейт (ARCH-01). Любой токен, дописанный в конец :root, будет молча съеден.
- **Вторая палитра**: `pixel-fx.css:13-21` дублирует 5 токенов сырыми hex — сам файл формулирует запрет на это (VIS-05); из-за этого pixel-слой не получает светлые ветки.
- **Сироты**: 14 токенов без потребителей, включая мёртвые density-переопределения (VIS-15); тень-шкала sm/md/lg имеет 1/3/2 потребителя — глубину несут px-edge-контуры (VIS-16); motion-токены: `--duration-fast` 34 потребителя, slow 3, normal 1, остальные 0 (VIS-08).
- Кросс-темная неконсистентность: в dark две пары ролей делят один hex (accent-secondary==warning, link==accent-strong), в light расходятся (VIS-17); чужой Material-красный #B3261E в трёх fallback-декларациях (VIS-18).

## 9. Current pixel-art system

Система пережила радикальную чистку (iter-118/119): все 20+ PNG из img/pixel/ удалены, глифы переведены на SVG-маски 16×16 + currentColor, целочисленный масштаб, сцены 40×25 (×8/×4). Ось `data-pixel` (low/med/high) работает как задумано: тяжёлые FX под high, low срезает декор, дефолт med. В инлайн-спрайтах состояний ноль сирот.

Чистка не доведена по трём осям:
- **10 стикеров разделов осиротели** (единственные оставшиеся PNG, 3496 байт, внутренне безупречны): их рендерер снесён коммитом d0b79953 при переносе каталога на /topics; yaml→Java-цепочка, палитровый тест и доки обслуживают мёртвую систему; в живом DOM ноль `<img>` (AST-01). `StaticAssetInventoryTest` слеп к этому классу смерти (yaml-самоссылка).
- **Мёртвый код**: ~30% pixel-animations.css — FX снятого слоя pixel-fx.js (burst/floaters/coin-rain/portal — 0 инжекторов, AST-03); celebration на summary мёртв — `.is-celebrating` никто не ставит (AST-04); вестигиальные sprite-keyframes двигают background-position несуществующих растров (AST-07).
- **Дефект каскада**: стрей-скобка `pixel-animations.css:552` преждевременно закрывает `@layer pixel` — строки 554-620 живут вне слоя и бьют любой layer (AST-02).

Плюс: `arrowNudge` — единственная бесконечная анимация без гейта плотности, дёргается на всех primary CTA всегда, вопреки собственной доктрине «постоянная анимация читается как неисправность» (AST-05). Доки и провенанс разъехались с диском: заявлено «pixel/ — 20 шт.» при нуле PNG (AST-06).

## 10. Current motion system

Архитектура правильная: трёхзначная ось `data-motion` (auto/on/off) + универсальный kill в `reset-layout.css:141-160` с уважением пользовательского форса `:not([data-motion="on"])` и поддержкой prefers-contrast. Тяжёлые вендоры и FX гейтованы по плотности.

Дефекты:
- **Parity-файл нарушает контракт оси**: `pixel-motion-parity.css` глушит pixel-анимации при OS-reduce БЕЗ учёта явного «Движение: вкл» — контракт трёх состояний нарушен в одном из двух файлов (AST-08, также замечено a11y-аудитом); заодно гасит статичное зерно холста, которое не движется (AST-09); внутри — дубль строки и пропуск `.streak-progress-fill::after`.
- **Шкала схлопнулась**: фактически одна скорость 120ms на всё; slow/bounce/in — сироты; хореографии (вердикт на slow, hover на fast) нет (VIS-08).
- Celebration-этаж (единственное место, где движение-сцена уместна по курсу) — мёртв (AST-04).

## 11. Current accessibility model

На редкость зрелая база: скип-линки с контекстными подписями на всех 9 страницах; единый ARIA-tablist с roving tabindex (проверен live); SR-цикл ответа образцовый — краткий вердикт-live `#result-announce` отдельно от большого разбора, фокус явно переносится в приёмник; единый polite-«голос ожидания»; inert-модалки с focus-restore; серверный aria-sort; canvas role=img со связанными таблицами; **0 безымянных контролов, 0 дублей id, 0 висячих aria-ссылок** по живому DOM-скану; ранговая система touch-целей с coarse-разжатием до 44px.

Оставшиеся дыры:
- **Горизонтальный скролл кода недоступен с клавиатуры** (A11Y-01, P1): реальный скроллер `pre.question-code` не фокусируем, focusability-синк проверяет только вертикаль, на result.html механизма нет вовсе — WCAG 2.1.1 их же формулировкой из комментария кода.
- **Хоткеи с побочными эффектами**: ↑/↓ с фокуса на код-регионе выбирают вариант вместо скролла (A11Y-02, live-репро); Space с body мгновенно и необратимо раскрывает флешкарту (A11Y-04); Esc тихо снимает выбор без анонса (A11Y-09).
- **Потеря фокуса после оценки уверенности**: native disabled на сфокусированной кнопке — нарушение их же документированного принципа из pending.js (A11Y-03).
- Полировка: справка «?» недискаверабельна (A11Y-05); h3 среди h2 на /stats (A11Y-06); мёртвые видимые JS-контролы в no-JS против собственного паттерна hidden-until-JS (A11Y-07); две цели вне ранговой системы размеров (A11Y-08).

## 12. Current testing model

Сюита на чистом checkout полностью зелёная: 2190 тестов к iter-168 (путь падений 42→0 задокументирован). Плотная сеть контрактных гейтов с обязательным **мутационным доказательством** (палитра растра и CSS, autofocus/title, print, empty-state, досягаемость действий, бюджеты подписей канвасов) — каждый укушен красным до принятия. ## 19. Opportunities

Возможности с несоразмерно высоким отношением эффекта к цене (данные аудиторов, не фантазии):

- **5 var() → light бесплатно**: перевод pixel-fx.css на токены автоматически даёт светлые ветки всему px-слою (VIS-05→VIS-06/13).
- **Данные уже в моделях**: прямые ссылки `/(questionId=…)` для поиска/ошибок — правка только шаблонов (IA-04); ранг-строка в focus-рельс — готовым fragment'ом progression (UX-05); next-action карточки для ориентации — уже реализованы на /stats (IA-06, при положительном решении).
- **Образцы внутри продукта**: канонизация /review по образцу /training→/ (IA-05); дедуп CTA по месту назначения с итогов — донести до вкладки «Ошибки»; условная загрузка hljs по образцу mermaid (ARCH-05).
- **Готовые ассеты**: 10 внутренне безупречных стикеров возвращаются одним `<img th:src>` — вся серверная цепочка жива (AST-01, decision-gated).
- **Архитектурные развязки**: core/page-разрез CSS-ленты (@layer уже делает порядок явным, ARCH-03); спрайты наружу с content-hash — механика ResourceUrlProvider есть (ARCH-04); JS-strip симметрично CSS (ARCH-06); `data-mode` от сервера вместо :has()-археологии — сервер уже знает режим (ARCH-09); комментарии-эссе → docs/css-decisions с якорями, source худеет в ~3,5 раза (ARCH-02).
- **Дешёвые каноны**: шкала брейкпоинтов документом + белый список в leak-audit (ARCH-07); сведение 760/767/768.
