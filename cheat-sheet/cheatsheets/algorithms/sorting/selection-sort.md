## Описание алгоритма

Сортировка выбором начинается с элемента в 1-й позиции несортированного массива и просматривает последующие элементы, чтобы найти наименьший элемент. После нахождения наименьший элемент заменяется элементом в 1-й позиции.

Затем алгоритм переходит к элементу во 2-й позиции и просматривает последующие элементы, чтобы найти индекс 2-го наименьшего элемента. После нахождения второй наименьший элемент заменяется элементом на 2-й позиции.

Этот процесс продолжается до тех пор, пока мы не достигнем n-1-го элемента массива, который помещает n-1-й наименьший элемент в n-1-ю позицию. Последний элемент автоматически встает на место, на n-1-й итерации, тем самым сортируя массив.

Мы можем найти самый большой элемент вместо самого маленького элемента, чтобы отсортировать массив в порядке убывания.

## Пример работы

Давайте посмотрим на пример несортированного массива и отсортируем его в порядке возрастания, чтобы наглядно понять алгоритм.

Рассмотрим следующий несортированный массив:

```java
int[] arr = { 5, 4, 1, 6, 2 }
```

### Итерация 1

Учитывая приведенную выше работу алгоритма, мы начинаем с элемента в 1-й позиции - 5 - и сканируем все последующие элементы, чтобы найти наименьший элемент - 1. Затем мы меняем наименьший элемент с элементом в 1-й позиции.

Измененный массив теперь выглядит так:

```java
{ 1, 4, 5, 6, 2 }
```

Всего произведено сравнений: 4

### Итерация 2

Во второй итерации мы переходим ко 2-му элементу - 4 - и сканируем последующие элементы, чтобы найти второй наименьший элемент - 2. Затем мы меняем местами второй наименьший элемент с элементом на 2-й позиции.

Измененный массив теперь выглядит так:

```java
{ 1, 2, 5, 6, 4 }
```

Всего произведено сравнений: 3

### Итерация 3

```java
{ 1, 2, 4, 6, 5 }
```

Всего произведено сравнений: 2

### Итерация 4

```java
{ 1, 2, 4, 5, 6 }
```

Всего произведено сравнений: 1

## Java Implementation

Давайте реализуем сортировку выбором, используя пару циклов for:

```java
public static void sortAscending(final int[] arr) {
    for (int i = 0; i < arr.length - 1; i++) {
        int minElementIndex = i;
        
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[minElementIndex] > arr[j]) {
                minElementIndex = j;
            }
        }
        
        if (minElementIndex != i) {
            int temp = arr[i];
            arr[i] = arr[minElementIndex];
            arr[minElementIndex] = temp;
        }
    }
}
```

Конечно, чтобы обратить это, мы могли бы сделать что-то очень похожее:

```java
public static void sortDescending(final int[] arr) {
    for (int i = 0; i < arr.length - 1; i++) {
        int maxElementIndex = i;
        
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[maxElementIndex] < arr[j]) {
                maxElementIndex = j;
            }
        }
        
        if (maxElementIndex != i) {
            int temp = arr[i];
            arr[i] = arr[maxElementIndex];
            arr[maxElementIndex] = temp;
        }
    }
}
```

И с немного большим количеством локтя, мы могли бы объединить их с помощью `Comparator`:

```java
public static void sort(final int[] arr, final Comparator<Integer> comparator) {
    for (int i = 0; i < arr.length - 1; i++) {
        int elementIndex = i;
        
        for (int j = i + 1; j < arr.length; j++) {
            if (comparator.compare(arr[elementIndex], arr[j]) > 0) {
                elementIndex = j;
            }
        }
        
        if (elementIndex != i) {
            int temp = arr[i];
            arr[i] = arr[elementIndex];
            arr[elementIndex] = temp;
        }
    }
}
```

### Функциональный стиль

```kotlin
fun selectionSortFunctionalK(arr: IntArray): IntArray {
    val result = arr.copyOf()
    for (i in 0 until result.size - 1) {
        val minIndex = (i + 1 until result.size)
            .minByOrNull { result[it] } ?: i
        if (minIndex != i) {
            result[i] = result[minIndex].also { result[minIndex] = result[i] }
        }
    }
    return result
}
```

### Пример использования

```kotlin
fun main() {

    println(arr.contentToString()) // [1, 2, 4, 5, 6]
    
    // Функциональный стиль
    val sorted = selectionSortFunctionalK(intArrayOf(5, 4, 1, 6, 2))
    println(sorted.contentToString()) // [1, 2, 4, 5, 6]
}
```

## Сложность

В примере, который мы видели ранее, для выбора наименьшего элемента потребовалось всего (n-1) сравнений с последующей перестановкой его на 1-ю позицию. Точно так же выбор следующего наименьшего элемента требует всего (n-2) сравнений с последующей перестановкой во 2-й позиции и так далее.

Таким образом, начиная с индекса 0, мы выполняем n-1, n-2, n-3, n-4…. 1 сравнений. Последний элемент автоматически встает на место благодаря предыдущим итерациям и перестановкам.

Математически сумма первых n-1 натуральных чисел скажет нам, сколько сравнений нам нужно, чтобы отсортировать массив размера n с помощью сортировки выбором.

Формула суммы n натуральных чисел: `n(n+1)/2`.

В нашем случае нам нужна сумма первых n-1 натуральных чисел. Поэтому мы заменим n на n-1 в приведенной выше формуле, чтобы получить:

```
(n-1)(n-1+1)/2 = (n-1)n/2 = (n² - n)/2
```

Поскольку n² заметно растет с ростом n, мы рассматриваем более высокую мощность n в качестве эталона производительности, что делает этот алгоритм временной сложностью O(n²).

### Временная сложность

- **Худший случай:** O(n²)
- **Средний случай:** O(n²)
- **Лучший случай:** O(n²)

Сложность одинакова во всех случаях, поскольку алгоритм должен сканировать каждый элемент для поиска минимального значения, независимо от исходного порядка элементов.

### Пространственная сложность

- **Все случаи:** O(1) - требуется одна дополнительная переменная для временного хранения значения для замены

## Особенности

- **Простота:** Сортировка выбором - это очень простой для понимания и реализации алгоритм сортировки
- **Стабильность:** Selection Sort не является стабильным алгоритмом (может менять относительный порядок элементов с одинаковыми значениями)
- **In-place:** Сортировка выполняется на месте, не требует дополнительной памяти
- **Минимум обменов:** Алгоритм делает минимум обменов (максимум n-1 обменов)

## Недостатки

К сожалению, квадратичная временная сложность делает его дорогостоящим методом сортировки. Кроме того, поскольку алгоритм должен сканировать каждый элемент, временная сложность в лучшем, среднем и худшем случаях одинакова.

Другие методы сортировки, такие как сортировка вставками и сортировка Шелла, также имеют квадратичную временную сложность в худшем случае, но они работают лучше в лучшем и среднем случаях.

## Применение

Selection Sort полезен в следующих случаях:

- Когда количество элементов невелико
- Когда стоимость записи в память высока (минимум обменов)
- Для обучения основам алгоритмов сортировки
- Когда простота реализации важнее производительности

## Сравнение с другими алгоритмами

| Алгоритм | Лучший случай | Средний случай | Худший случай | Стабильность |
|----------|---------------|----------------|--------------|--------------|
| Selection Sort | O(n²) | O(n²) | O(n²) | Нет |
| Bubble Sort | O(n) | O(n²) | O(n²) | Да |
| Insertion Sort | O(n) | O(n²) | O(n²) | Да |
