## Описание алгоритма

Quicksort - это алгоритм сортировки, использующий принцип «разделяй и властвуй». Он имеет среднюю сложность O(n*log(n)) и является одним из наиболее часто используемых алгоритмов сортировки, особенно для больших объемов данных.

Важно помнить, что быстрая сортировка не является стабильным алгоритмом. Алгоритм стабильной сортировки - это алгоритм, в котором элементы с одинаковыми значениями появляются в отсортированном выводе в том же порядке, в каком они появляются во входном списке.

## Принцип работы

Входной список разделен на два подсписка с помощью элемента, называемого опорным (pivot); один подсписок с элементами меньше, чем опорный элемент, а другой - с элементами больше, чем опорный элемент. Этот процесс повторяется для каждого подсписка.

Наконец, все отсортированные подсписки объединяются, чтобы сформировать окончательный результат.

Алгоритм работает следующим образом:

1. **Выбор опорного элемента:** мы выбираем элемент из списка, который называется опорным (pivot)
2. **Разделение:** мы переупорядочиваем все элементы вокруг опорной точки - элементы с меньшим значением помещаются перед ней, а все элементы, превышающие опорную, - после нее
3. **Рекурсия:** мы применяем описанные выше шаги рекурсивно к обоим подспискам слева и справа от опорного элемента

Как мы видим, быстрая сортировка по своей природе является рекурсивным алгоритмом, как и любой подход «разделяй и властвуй».

### Пример работы

Давайте возьмем простой пример, чтобы лучше понять этот алгоритм.

`Arr[] = {5, 9, 4, 6, 5, 3}`

Предположим, мы выбрали 5 в качестве опорной точки для простоты.

1. Сначала мы поместим все элементы меньше 5 в первую позицию массива: `{3, 4, 5, 6, 5, 9}`
2. Затем мы повторим это для левого подмассива `{3, 4}`, взяв 3 в качестве точки поворота
3. Нет элементов меньше 3
4. Мы применяем быструю сортировку к подмассиву справа от опорной точки, т. е. `{4}`
5. Этот подмассив состоит только из одного отсортированного элемента
6. Мы продолжаем работать с правой частью исходного массива `{6, 5, 9}`, пока не получим окончательный упорядоченный массив

## Выбор опорного элемента

Важным моментом в QuickSort является выбор наилучшего опорного значения. Средний элемент, конечно, лучший, так как он разделил бы список на два равных подсписка.

Но найти средний элемент из неупорядоченного списка сложно и долго, поэтому мы берем в качестве точки опоры:

- Первый элемент
- Последний элемент
- Медиану
- Случайный элемент

Выбор опорного элемента влияет на производительность алгоритма. В худшем случае (когда опорный элемент всегда является минимальным или максимальным) сложность становится O(n²).

## Java Implementation

Первый метод - это `quickSort()`, который принимает в качестве параметров массив для сортировки, первый и последний индекс. Сначала мы проверяем индексы и продолжаем, только если есть еще элементы для сортировки.

Мы получаем индекс отсортированного опорного элемента и используем его для рекурсивного вызова метода `partition()` с теми же параметрами, что и у метода `quickSort()`, но с другими индексами:

```java
public void quickSort(int arr[], int begin, int end) {
    if (begin < end) {
        int partitionIndex = partition(arr, begin, end);
        quickSort(arr, begin, partitionIndex - 1);
        quickSort(arr, partitionIndex + 1, end);
    }
}
```

Давайте продолжим с методом `partition()`. Для простоты эта функция принимает последний элемент в качестве опорного. Затем проверяет каждый элемент и меняет его местами перед поворотом, если его значение меньше.

К концу разбиения все элементы, меньшие опорной точки, находятся слева от нее, а все элементы, превышающие опорную точку, - справа от нее. Опорная точка находится в своей конечной отсортированной позиции, и функция возвращает эту позицию:

```java
private int partition(int arr[], int begin, int end) {
    int pivot = arr[end];
    int i = (begin - 1);
    
    for (int j = begin; j < end; j++) {
        if (arr[j] <= pivot) {
            i++;
            int swapTemp = arr[i];
            arr[i] = arr[j];
            arr[j] = swapTemp;
        }
    }
    
    int swapTemp = arr[i + 1];
    arr[i + 1] = arr[end];
    arr[end] = swapTemp;
    
    return i + 1;
}
```

## Kotlin Implementation

В Kotlin алгоритм Quick Sort может быть реализован следующим образом:

```kotlin
fun quickSort(arr: IntArray, begin: Int = 0, end: Int = arr.size - 1) {
    if (begin < end) {
        val partitionIndex = partition(arr, begin, end)
        quickSort(arr, begin, partitionIndex - 1)
        quickSort(arr, partitionIndex + 1, end)
    }
}

private fun partition(arr: IntArray, begin: Int, end: Int): Int {
    val pivot = arr[end]
    var i = begin - 1

    for (j in begin until end) {
        if (arr[j] <= pivot) {
            i++
            arr[i] = arr[j].also { arr[j] = arr[i] }
        }
    }

    arr[i + 1] = arr[end].also { arr[end] = arr[i + 1] }
    return i + 1
}
```

Использование:

```kotlin
fun main() {
    val array = intArrayOf(5, 9, 4, 6, 5, 3)
    quickSort(array)
    println(array.contentToString()) // [3, 4, 5, 5, 6, 9]
}
```

### Функциональный стиль

В Kotlin можно также использовать более функциональный подход:

```kotlin
fun quickSortFunctional(arr: List<Int>): List<Int> {
    if (arr.size <= 1) return arr
    
    val pivot = arr[arr.size / 2]
    val less = arr.filter { it < pivot }
    val equal = arr.filter { it == pivot }
    val greater = arr.filter { it > pivot }
    
    return quickSortFunctional(less) + equal + quickSortFunctional(greater)
}
```

Использование:

```kotlin
fun main() {
    val list = listOf(5, 9, 4, 6, 5, 3)
    val sorted = quickSortFunctional(list)
    println(sorted) // [3, 4, 5, 5, 6, 9]
}
```

## Сложность

### Временная сложность

- **Лучший случай:** O(n*log(n)) - когда опорный элемент всегда делит массив пополам
- **Средний случай:** O(n*log(n)) - в большинстве случаев
- **Худший случай:** O(n²) - когда опорный элемент всегда является минимальным или максимальным элементом

В лучшем случае алгоритм разделит список на два подсписка одинакового размера. Таким образом, для первой итерации полного списка размером n требуется O(n). Сортировка оставшихся двух подсписков с n/2 элементами занимает 2*O(n/2) каждый. В результате алгоритм QuickSort имеет сложность O(n*log(n)).

В худшем случае алгоритм будет выбирать только один элемент на каждой итерации, поэтому O(n) + O(n - 1) + … + O(1), что равно O(n²).

В среднем QuickSort имеет сложность O(n*log(n)), что делает его подходящим для больших объемов данных.

### Пространственная сложность

- **Средний случай:** O(log(n)) - глубина рекурсии
- **Худший случай:** O(n) - в случае несбалансированного разделения

## Сравнение с Merge Sort

Давайте обсудим, в каких случаях мы должны выбрать QuickSort вместо MergeSort.

Хотя и быстрая сортировка, и сортировка слиянием имеют среднюю временную сложность O(n*log(n)), быстрая сортировка является предпочтительным алгоритмом, поскольку имеет пространственную сложность O(log(n)). С другой стороны, сортировка слиянием требует O(n) дополнительной памяти, что делает ее довольно дорогой для массивов.

Быстрая сортировка требует доступа к различным индексам для своих операций, но такой доступ невозможен напрямую в связанных списках, поскольку непрерывных блоков нет; поэтому, чтобы получить доступ к элементу, мы должны перебирать каждый узел с начала связанного списка. Кроме того, Mergesort реализован без дополнительного места для LinkedLists.

В таком случае обычно предпочтительнее увеличение накладных расходов для быстрой сортировки и сортировки слиянием.

## Особенности

- **Нестабильность:** Quick Sort не является стабильным алгоритмом
- **In-place:** Сортировка выполняется на месте (не требует дополнительной памяти для массивов)
- **Практическая эффективность:** В среднем работает быстрее, чем Merge Sort и Heap Sort
- **Использование в Java:** Метод `Arrays.sort()` использует QuickSort для сортировки массивов примитивов

## Применение

Quicksort - это элегантный алгоритм сортировки, очень полезный в большинстве случаев.

Как правило, это алгоритм «на месте» со средней временной сложностью O(n*log(n)).

Еще один интересный момент, о котором следует упомянуть, заключается в том, что метод Java `Arrays.sort()` использует Quicksort для сортировки массивов примитивов. Реализация использует два опорных элемента и работает намного лучше, чем наше простое решение, поэтому для производственного кода обычно лучше использовать библиотечные методы.

### Когда использовать Quick Sort

- Для больших массивов примитивных типов
- Когда важна производительность в среднем случае
- Когда доступна память ограничена (in-place сортировка)
- Для массивов, где случайный доступ эффективен

### Когда не использовать Quick Sort

- Когда требуется стабильная сортировка
- Для связанных списков (лучше использовать Merge Sort)
- Когда худший случай O(n²) недопустим
