## Обзор

В этом уроке мы поговорим о том, что означает нотация Big O. Мы рассмотрим несколько примеров, чтобы исследовать их влияние на время выполнения вашего кода.

Мы часто слышим о производительности алгоритма, описанного с помощью Big O Notation.

Изучение производительности алгоритмов - или алгоритмической сложности - относится к области анализа алгоритмов. Алгоритмический анализ отвечает на вопрос, сколько ресурсов, таких как дисковое пространство или время, потребляет алгоритм.

Мы будем рассматривать время как ресурс. Как правило, чем меньше времени требуется алгоритму для завершения, тем лучше.

## Что такое Big O?

Как этот входной размер алгоритма влияет на время его работы? Ключом к пониманию Big O является понимание скорости, с которой все может расти. Здесь речь идет о времени, затраченном на размер ввода.

Big O - это то, что известно как асимптотическая функция. Все это означает, что он занимается производительностью алгоритма на пределе, то есть когда на него поступает много входных данных.

Big O не заботится о том, насколько хорошо ваш алгоритм работает с входными данными небольшого размера. Это связано с большими входными данными (подумайте о сортировке списка из миллиона чисел по сравнению с сортировкой списка из 5 чисел).

## Java Implementation

### O(1) - Постоянное время

Рассмотрим этот простой фрагмент кода:

```java
int n = 1000;
System.out.println("Hey - your input is: " + n);
```

Ясно, что не имеет значения, что такое n выше. Этот фрагмент кода требует постоянного времени для выполнения. Это не зависит от размера n.

Сходным образом:

```java
int n = 1000;
System.out.println("Hey - your input is: " + n);
System.out.println("Hmm.. I'm doing more stuff with: " + n);
System.out.println("And more: " + n);
```

Приведенный выше пример также является постоянным временем. Даже если это займет в 3 раза больше времени, это не зависит от размера входных данных, n. Мы обозначаем алгоритмы с постоянным временем следующим образом: **O(1)**. Обратите внимание, что O(2), O(3) или даже O(1000) означают одно и то же.

Нас не волнует точное время выполнения, важно только то, что это занимает постоянное время.

**Примеры:**
- Доступ к элементу массива по индексу
- Вставка/удаление в начале связанного списка
- Операции со стеком (push/pop)

### O(log n) - Логарифмическое время

Алгоритмы с постоянным временем (асимптотически) самые быстрые. Логарифмическое время является следующим самым быстрым. К сожалению, их немного сложнее представить.

Одним из распространенных примеров алгоритма логарифмического времени является алгоритм бинарного поиска.

Здесь важно то, что время выполнения растет пропорционально логарифму входных данных (в данном случае записывайте по основанию 2):

```java
for (int i = 1; i < n; i = i * 2) {
    System.out.println("Hey - I'm busy looking at: " + i);
}
```

Если n равно 8, вывод будет следующим:

```
Hey - I'm busy looking at: 1
Hey - I'm busy looking at: 2
Hey - I'm busy looking at: 4
```

Наш простой алгоритм запускался log(8) = 3 раза.

**Примеры:**
- Бинарный поиск
- Поиск в сбалансированном бинарном дереве
- Операции в куче (heap)

### O(n) - Линейное время

После алгоритмов логарифмического времени мы получаем следующий самый быстрый класс: алгоритмы линейного времени.

Если мы говорим, что что-то растет линейно, мы имеем в виду, что оно растет прямо пропорционально размеру его входов.

Подумайте о простом цикле for:

```java
for (int i = 0; i < n; i++) {
    System.out.println("Hey - I'm busy looking at: " + i);
}
```

Сколько раз выполняется цикл for? n раз, конечно! Мы не знаем точно, сколько времени это займет, и мы не беспокоимся об этом.

Что мы знаем, так это то, что простой алгоритм, представленный выше, будет расти линейно с размером его входных данных.

Мы бы предпочли время выполнения 0.1n, чем (1000n + 1000), но оба алгоритма по-прежнему являются линейными; они оба растут прямо пропорционально размеру их вложений.

Опять же, если алгоритм был изменен на следующий:

```java
for (int i = 0; i < n; i++) {
    System.out.println("Hey - I'm busy looking at: " + i);
    System.out.println("Hmm.. Let's have another look at: " + i);
    System.out.println("And another: " + i);
}
```

Время выполнения по-прежнему будет линейным по размеру входных данных n. Обозначим линейные алгоритмы следующим образом: **O(n)**.

Как и в случае алгоритмов с постоянным временем, нас не волнуют особенности среды выполнения. O(2n+1) совпадает с O(n), поскольку нотация Big O связана с ростом размеров входных данных.

**Примеры:**
- Поиск в несортированном массиве
- Обход связанного списка
- Поиск в несбалансированном дереве

### O(n log n) - Линейно-логарифмическое время

n*log(n) - следующий класс алгоритмов. Время работы растет пропорционально n*log(n) входных данных:

```java
for (int i = 1; i <= n; i++) {
    for (int j = 1; j < n; j = j * 2) {
        System.out.println("Hey - I'm busy looking at: " + i + " and " + j);
    }
}
```

Например, если n равно 8, то этот алгоритм будет выполняться 8 * log(8) = 8 * 3 = 24 раза. Есть ли у нас строгое неравенство или нет в цикле for, не имеет значения для нотации Big O.

**Примеры:**
- Эффективные алгоритмы сортировки (Merge Sort, Quick Sort, Heap Sort)
- Некоторые алгоритмы поиска
- Операции в некоторых структурах данных

## O(n²) - Квадратичное время

Далее у нас есть алгоритмы с полиномиальным временем. Эти алгоритмы еще медленнее, чем алгоритмы n*log(n).

Термин полиномиальный является общим термином, который включает квадратичные (n²), кубические (n³), четвертые (n⁴) и т.д. функции. Важно знать, что O(n²) быстрее, чем O(n³), который быстрее, чем O(n⁴) и т.д.

Давайте посмотрим на простой пример алгоритма квадратичного времени:

```java
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= n; j++) {
        System.out.println("Hey - I'm busy looking at: " + i + " and " + j);
    }
}
```

Этот алгоритм будет выполняться n² раз. Обратите внимание: если бы мы вложили еще один цикл for, это стало бы алгоритмом O(n³).

**Примеры:**
- Пузырьковая сортировка
- Сортировка выбором
- Сортировка вставками
- Умножение матриц (наивный алгоритм)
- Поиск всех пар в массиве

## O(2ⁿ) - Экспоненциальное время

Теперь мы попадаем на опасную территорию; эти алгоритмы растут пропорционально некоторому коэффициенту, возведенному в степень от размера входных данных.

Например, алгоритмы O(2ⁿ) удваиваются с каждым дополнительным вводом. Итак, если n = 2, эти алгоритмы будут выполняться четыре раза; если n = 3, они будут выполняться восемь раз (что-то вроде противоположности алгоритмам логарифмического времени).

O(3ⁿ) алгоритмов утраивается с каждым дополнительным входом, O(kⁿ) алгоритмов будет увеличиваться в k раз с каждым дополнительным входом.

Давайте посмотрим на простой пример алгоритма времени O(2ⁿ):

```java
for (int i = 1; i <= Math.pow(2, n); i++) {
    System.out.println("Hey - I'm busy looking at: " + i);
}
```

Этот алгоритм будет работать 2ⁿ раз. Для n = 8 это будет 2⁸ = 256 раз.

**Примеры:**
- Рекурсивное вычисление чисел Фибоначчи (наивный подход)
- Решение задачи о рюкзаке (полный перебор)
- Генерация всех подмножеств

## O(n!) - Факториальное время

В большинстве случаев это настолько плохо, насколько это возможно. Этот класс алгоритмов имеет время выполнения, пропорциональное факториалу входного размера.

Классический пример - решение задачи о коммивояжере методом грубой силы.

Вместо этого давайте рассмотрим простой алгоритм O(n!):

```java
for (int i = 1; i <= factorial(n); i++) {
    System.out.println("Hey - I'm busy looking at: " + i);
}
```

где factorial(n) просто вычисляет n!

Если n равно 8, этот алгоритм будет работать 8! = 40320 раз.

**Примеры:**
- Задача коммивояжера (полный перебор)
- Генерация всех перестановок
- Некоторые задачи планирования

## Сравнение сложностей

Вот визуальное сравнение роста различных сложностей:

```
n    | O(1) | O(log n) | O(n) | O(n log n) | O(n²) | O(2ⁿ) | O(n!)
-----|------|----------|------|------------|-------|-------|-------
1    | 1    | 1        | 1    | 1          | 1     | 2     | 1
10   | 1    | 3        | 10   | 30         | 100   | 1024  | 3,628,800
100  | 1    | 7        | 100  | 700        | 10,000| 10³⁰  | огромное
1000 | 1    | 10       | 1000 | 10,000     | 10⁶   | 10³⁰¹ | невообразимо
```

## Другие асимптотические функции

Следует также отметить, что существуют и другие асимптотические функции. Большой Θ (тета) и большой Ω (омега) также описывают алгоритмы на пределе.

Чтобы понять различия между этими тремя важными функциями, нам сначала нужно знать, что каждая из Big O, Big Θ и Big Ω описывает набор (то есть набор элементов).

Здесь членами наших наборов являются сами алгоритмы:

- **Big O** описывает множество всех алгоритмов, которые работают не хуже определенной скорости (это верхняя граница)
- **Big Ω** описывает набор всех алгоритмов, которые работают не лучше определенной скорости (это нижняя граница)
- **Big Θ** описывает множество всех алгоритмов, работающих с определенной скоростью (это как равенство)

Определения, которые мы привели выше, не являются математически точными, но они помогут нашему пониманию.

Обычно вы слышите о вещах, описываемых с помощью Big O, но не помешает узнать о Big Θ и Big Ω.

## Практические советы

1. **Избегайте O(n²) и выше** для больших наборов данных
2. **Используйте O(n log n)** для сортировки больших массивов
3. **O(log n)** идеально для поиска в отсортированных данных
4. **O(1)** - цель для частых операций
5. **Избегайте O(2ⁿ) и O(n!)** если возможно

## Kotlin Implementation

### O(1) - Постоянное время

```kotlin
fun constantTimeExampleK(n: Int) {
    println("Hey - your input is: $n")
}

// Доступ к элементу массива
fun getArrayElementK(arr: IntArray, index: Int): Int {
    return arr[index] // O(1)
}
```

### O(log n) - Логарифмическое время

```kotlin
fun logarithmicTimeExampleK(n: Int) {
    var i = 1
    while (i < n) {
        println("Hey - I'm busy looking at: $i")
        i *= 2
    }
}

// Бинарный поиск
fun binarySearchK(arr: IntArray, target: Int): Int {
    var left = 0
    var right = arr.size - 1
    
    while (left <= right) {
        val mid = left + (right - left) / 2
        when {
            arr[mid] == target -> return mid
            arr[mid] < target -> left = mid + 1
            else -> right = mid - 1
        }
    }
    return -1
}
```

### O(n) - Линейное время

```kotlin
fun linearTimeExampleK(n: Int) {
    for (i in 0 until n) {
        println("Hey - I'm busy looking at: $i")
    }
}

// Поиск в массиве
fun findElementK(arr: IntArray, target: Int): Int {
    for (i in arr.indices) {
        if (arr[i] == target) {
            return i
        }
    }
    return -1
}
```

### O(n log n) - Линейно-логарифмическое время

```kotlin
fun nLogNTimeExampleK(n: Int) {
    for (i in 0 until n) {
        var j = 1
        while (j < n) {
            println("Processing: $i, $j")
            j *= 2
        }
    }
}

// Сортировка слиянием
fun mergeSortK(arr: IntArray, left: Int, right: Int) {
    if (left < right) {
        val mid = left + (right - left) / 2
        mergeSortK(arr, left, mid)
        mergeSortK(arr, mid + 1, right)
        mergeK(arr, left, mid, right)
    }
}
```

### O(n²) - Квадратичное время

```kotlin
fun quadraticTimeExampleK(n: Int) {
    for (i in 0 until n) {
        for (j in 0 until n) {
            println("Processing: $i, $j")
        }
    }
}

// Пузырьковая сортировка
fun bubbleSortK(arr: IntArray) {
    val n = arr.size
    for (i in 0 until n - 1) {
        for (j in 0 until n - i - 1) {
            if (arr[j] > arr[j + 1]) {
                val temp = arr[j]
                arr[j] = arr[j + 1]
                arr[j + 1] = temp
            }
        }
    }
}
```

### O(2ⁿ) - Экспоненциальное время

```kotlin
fun exponentialTimeExampleK(n: Int): Int {
    return when (n) {
        0, 1 -> n
        else -> exponentialTimeExampleK(n - 1) + exponentialTimeExampleK(n - 2)
    }
}

// Рекурсивное вычисление Фибоначчи (неэффективно)
fun fibonacciK(n: Int): Long {
    return when (n) {
        0, 1 -> n.toLong()
        else -> fibonacciK(n - 1) + fibonacciK(n - 2)
    }
}
```

### O(n!) - Факториальное время

```kotlin
fun factorialTimeExampleK(n: Int): Int {
    return if (n <= 1) {
        1
    } else {
        n * factorialTimeExampleK(n - 1)
    }
}

// Генерация всех перестановок
fun generatePermutationsK(elements: List<Int>): List<List<Int>> {
    if (elements.size <= 1) {
        return listOf(elements)
    }
    
    val result = mutableListOf<List<Int>>()
    for (i in elements.indices) {
        val current = elements[i]
        val remaining = elements.filterIndexed { index, _ -> index != i }
        val permutations = generatePermutationsK(remaining)
        
        for (perm in permutations) {
            result.add(listOf(current) + perm)
        }
    }
    return result
}
```

## Резюме

В этом уроке мы рассмотрели различные классы сложности алгоритмов и их практическое значение.

Ключевые моменты:
- Big O описывает рост времени выполнения относительно размера входных данных
- Постоянное время O(1) - самое быстрое
- Логарифмическое время O(log n) очень эффективно
- Линейное время O(n) приемлемо для большинства задач
- Квадратичное время O(n²) и выше может быть проблематичным для больших данных
- Экспоненциальное и факториальное время следует избегать

Понимание Big O помогает выбирать правильные алгоритмы и структуры данных для ваших задач.
