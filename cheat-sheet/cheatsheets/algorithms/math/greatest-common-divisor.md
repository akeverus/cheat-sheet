## Описание алгоритма

В математике НОД двух целых чисел, не равных нулю, - это наибольшее положительное целое число, на которое каждое из целых чисел делится без остатка.

В этом уроке мы рассмотрим три подхода к нахождению наибольшего общего делителя (НОД) двух целых чисел. Далее мы рассмотрим их реализацию на Java.

### Примеры

- НОД(12, 18) = 6
- НОД(48, 18) = 6
- НОД(17, 5) = 1 (взаимно простые числа)

## Java Implementation

### Подход 1: Грубая сила

Для нашего первого подхода мы итерируем от 1 до наименьшего заданного числа и проверяем, делятся ли заданные целые числа на индекс. Наибольший индекс, который делит данные числа, - это НОД данных чисел:

```java
int gcdByBruteForce(int n1, int n2) {
    int gcd = 1;
    for (int i = 1; i <= n1 && i <= n2; i++) {
        if (n1 % i == 0 && n2 % i == 0) {
            gcd = i;
        }
    }
    return gcd;
}
```

Как мы видим, сложность приведенной выше реализации составляет O(min(n1, n2)), потому что нам нужно пройти цикл n раз (эквивалентно меньшему числу), чтобы найти НОД.

### Оптимизированная версия (обратный порядок)

```java
int gcdByBruteForceOptimized(int n1, int n2) {
    int gcd = 1;
    int min = Math.min(Math.abs(n1), Math.abs(n2));
    
    for (int i = min; i >= 1; i--) {
        if (n1 % i == 0 && n2 % i == 0) {
            return i;
        }
    }
    return gcd;
}
```

## Подход 2: Алгоритм Евклида

Во-вторых, мы можем использовать алгоритм Евклида, чтобы найти НОД. Алгоритм Евклида не только эффективен, но и прост для понимания и легко реализуем с помощью рекурсии в Java.

Метод Евклида основан на двух важных теоремах:

1. Во-первых, если мы вычтем меньшее число из большего числа, НОД не изменится, поэтому, если мы продолжим вычитать число, мы в конце концов получим их НОД.
2. Во-вторых, когда меньшее число точно делит большее число, меньшее число является НОД двух заданных чисел.

Обратите внимание, что в нашей реализации мы будем использовать модуль по модулю вместо вычитания, так как в основном это много вычитаний за раз:

```java
int gcdByEuclidsAlgorithm(int n1, int n2) {
    if (n2 == 0) {
        return n1;
    }
    return gcdByEuclidsAlgorithm(n2, n1 % n2);
}
```

Также обратите внимание, как мы используем n2 в позиции n1 и используем остаток в позиции n2 в рекурсивном шаге алгоритма.

Кроме того, сложность алгоритма Евклида составляет O(Log(min(n1, n2))), что лучше по сравнению с методом грубой силы, который мы видели ранее.

### Итеративная версия

```java
int gcdByEuclidsAlgorithmIterative(int n1, int n2) {
    while (n2 != 0) {
        int temp = n2;
        n2 = n1 % n2;
        n1 = temp;
    }
    return Math.abs(n1);
}
```

### Версия с обработкой отрицательных чисел

```java
int gcdByEuclidsAlgorithmSafe(int n1, int n2) {
    n1 = Math.abs(n1);
    n2 = Math.abs(n2);
    
    while (n2 != 0) {
        int temp = n2;
        n2 = n1 % n2;
        n1 = temp;
    }
    return n1;
}
```

## Подход 3: Алгоритм Штейна

Наконец, мы можем использовать алгоритм Штейна, также известный как алгоритм бинарного НОД, чтобы найти НОД двух неотрицательных целых чисел. Этот алгоритм использует простые арифметические операции, такие как арифметические сдвиги, сравнение и вычитание.

Алгоритм Штейна неоднократно применяет следующие основные тождества, связанные с НОД, для нахождения НОД двух неотрицательных целых чисел:

1. НОД(0, 0) = 0, НОД(n1, 0) = n1, НОД(0, n2) = n2
2. Когда n1 и n2 оба являются четными целыми числами, тогда gcd(n1, n2) = 2 * gcd(n1/2, n2/2), так как 2 является общим делителем
3. Если n1 - четное целое число, а n2 - нечетное целое число, то gcd(n1, n2) = gcd(n1/2, n2), поскольку 2 не является общим делителем, и наоборот
4. Если n1 и n2 оба являются нечетными целыми числами и n1 >= n2, то gcd(n1, n2) = gcd((n1 - n2)/2, n2) и наоборот

Мы повторяем шаги 2-4, пока n1 не станет равным n2 или n1 = 0. НОД равен (2^n) * n2. Здесь n - это количество раз, когда 2 встречается в числах n1 и n2 при выполнении шага 2:

```java
int gcdBySteinsAlgorithm(int n1, int n2) {
    if (n1 == 0) {
        return n2;
    }
    
    if (n2 == 0) {
        return n1;
    }
    
    int n;
    for (n = 0; ((n1 | n2) & 1) == 0; n++) {
        n1 >>= 1;
        n2 >>= 1;
    }
    
    while ((n1 & 1) == 0) {
        n1 >>= 1;
    }
    
    do {
        while ((n2 & 1) == 0) {
            n2 >>= 1;
        }
        
        if (n1 > n2) {
            int temp = n1;
            n1 = n2;
            n2 = temp;
        }
        
        n2 = (n2 - n1);
    } while (n2 != 0);
    
    return n1 << n;
}
```

Мы видим, что мы используем арифметические операции сдвига, чтобы разделить или умножить на 2. Далее, мы используем вычитание, чтобы уменьшить заданные числа.

Сложность алгоритма Штейна при n1 > n2 равна O((log₂n1)²), тогда как когда n1 < n2, это O((log₂n2)²).

## Сравнение подходов

| Подход | Временная сложность | Пространственная сложность | Когда использовать |
|--------|---------------------|----------------------------|-------------------|
| Грубая сила | O(min(n1, n2)) | O(1) | Малые числа |
| Алгоритм Евклида | O(log(min(n1, n2))) | O(1) | Общий случай |
| Алгоритм Штейна | O((log n)²) | O(1) | Большие числа |

## Сложность

### Временная сложность

- **Грубая сила:** O(min(n1, n2)) - линейная
- **Алгоритм Евклида:** O(log(min(n1, n2))) - логарифмическая
- **Алгоритм Штейна:** O((log n)²) - квадратично-логарифмическая

### Пространственная сложность

- **Все подходы:** O(1) - только константная память (итеративные версии)
- **Рекурсивный Евклид:** O(log(min(n1, n2))) - для стека вызовов

## Особенности

- **Эффективность:** Алгоритм Евклида наиболее эффективен
- **Простота:** Грубая сила проще всего понять
- **Практичность:** Алгоритм Штейна хорош для больших чисел

public int gcdArray(int[] numbers) {
    int result = numbers[0];

### Вариант 2: Расширенный алгоритм Евклида

```java
public class ExtendedEuclidean {
    public static int[] extendedGcd(int a, int b) {
        if (b == 0) {
            return new int[]{a, 1, 0};
        }
        
        int[] result = extendedGcd(b, a % b);
        int gcd = result[0];
        int x1 = result[1];
        int y1 = result[2];
        
        int x = y1;
        int y = x1 - (a / b) * y1;
        
        return new int[]{gcd, x, y};
    }
}
```

### Вариант 3: НОД с использованием BigInteger

public BigInteger gcdBigInteger(BigInteger n1, BigInteger n2) {
    return n1.gcd(n2);
}

## Kotlin Implementation

### Подход 1: Грубая сила

```kotlin
fun gcdByBruteForceK(n1: Int, n2: Int): Int {
    var gcd = 1
    for (i in 1..minOf(n1, n2)) {
        if (n1 % i == 0 && n2 % i == 0) {
            gcd = i
        }
    }
    return gcd
}
```

### Подход 2: Алгоритм Евклида

```kotlin
fun gcdByEuclideanAlgorithmK(n1: Int, n2: Int): Int {
    var a = Math.abs(n1)
    var b = Math.abs(n2)
    while (b != 0) {
        val temp = b
        b = a % b
        a = temp
    }
    return a
}

fun gcdByEuclideanAlgorithmRecursiveK(n1: Int, n2: Int): Int {
    if (n2 == 0) {
        return Math.abs(n1)
    }
    return gcdByEuclideanAlgorithmRecursiveK(n2, n1 % n2)
}
```

### Подход 3: Алгоритм Штейна

```kotlin
fun gcdBySteinAlgorithmK(n1: Int, n2: Int): Int {
    if (n1 == 0) return n2
    if (n2 == 0) return n1
    
    var num1 = n1
    var num2 = n2
    var n = 0
    
    while (((num1 or num2) and 1) == 0) {
        num1 = num1 shr 1
        num2 = num2 shr 1
        n++
    }
    
    while ((num1 and 1) == 0) {
        num1 = num1 shr 1
    }
    
    do {
        while ((num2 and 1) == 0) {
            num2 = num2 shr 1
        }
        
        if (num1 > num2) {
            val temp = num1
            num1 = num2
            num2 = temp
        }
        
        num2 -= num1
    } while (num2 != 0)
    
    return num1 shl n
}
```

## Когда использовать

### Используйте грубую силу, когда:

- Числа очень маленькие
- Нужна простота
- Производительность не критична

### Используйте алгоритм Евклида, когда:

- Общий случай
- Нужна максимальная эффективность
- Работаете с целыми числами

### Используйте алгоритм Штейна, когда:

- Очень большие числа
- Нужна оптимизация для четных чисел
- Работаете с битовыми операциями
