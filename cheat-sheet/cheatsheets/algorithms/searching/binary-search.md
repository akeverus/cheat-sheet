# Binary Search

Кратко: бинарный поиск - это эффективный алгоритм поиска элемента в отсортированном массиве, который работает за время O(log(n)), деля область поиска пополам на каждой итерации.

## Описание алгоритма

Допустим, мы занимаемся продажей вина, и миллионы покупателей посещают наше приложение каждый день.

Через наше приложение клиент может отфильтровать товары, цена которых ниже n долларов, выбрать бутылку из результатов поиска и добавить их в свою корзину. У нас есть миллионы пользователей, каждую секунду ищущих вина по ограниченной цене. Результаты должны быть быстрыми.

На бэкенде наш алгоритм выполняет линейный поиск по всему списку вин, сравнивая предел цены, введенный покупателем, с ценой каждой бутылки вина в списке.

Затем он возвращает товары, цена которых меньше или равна предельной цене. Этот линейный поиск имеет временную сложность O(n).

Это означает, что чем больше количество винных бутылок в нашей системе, тем больше времени это займет. Время поиска увеличивается пропорционально количеству введенных новых элементов.

Если мы начнем сохранять элементы в отсортированном порядке и искать элементы с помощью бинарного поиска, мы можем достичь сложности O(log(n)).

При бинарном поиске время, затрачиваемое на результаты поиска, естественно увеличивается с размером набора данных, но не пропорционально.

## Преимущества перед линейным поиском

Проще говоря, алгоритм сравнивает значение ключа со средним элементом массива; если они не равны, половина, частью которой не может быть ключ, исключается, и поиск оставшейся половины продолжается до тех пор, пока он не увенчается успехом.

Помните - ключевым аспектом здесь является то, что массив уже отсортирован.

Если поиск заканчивается тем, что оставшаяся половина пуста, ключа нет в массиве.

### Сравнение с линейным поиском

| Характеристика | Линейный поиск | Бинарный поиск |
|----------------|----------------|----------------|
| Временная сложность | O(n) | O(log(n)) |
| Требования | Любой массив | Отсортированный массив |
| Простота | Проще | Сложнее |
| Применение | Малые массивы | Большие отсортированные массивы |

## Java Implementation

### Итеративная реализация

```java
public int runBinarySearchIteratively(int[] sortedArray, int key, int low, int high) {
    int index = Integer.MAX_VALUE;
    
    while (low <= high) {
        int mid = low + ((high - low) / 2);
        
        if (sortedArray[mid] < key) {
            low = mid + 1;
        } else if (sortedArray[mid] > key) {
            high = mid - 1;
        } else if (sortedArray[mid] == key) {
            index = mid;
            break;
        }
    }
    
    return index;
}
```

Метод `runBinarySearchIteratively` принимает в качестве аргументов `sortedArray`, ключ и нижний и верхний индексы `sortedArray`. Когда метод запускается в первый раз, `low`, первый индекс `sortedArray`, равен 0, а `high`, последний индекс `sortedArray`, равен его длине - 1.

`Middle` - это средний индекс `sortedArray`. Теперь алгоритм запускает цикл while, сравнивая ключ со значением массива среднего индекса `sortedArray`.

Обратите внимание, как генерируется средний индекс `(int mid = low + ((high - low) / 2))`. Это необходимо для чрезвычайно больших массивов. Если средний индекс генерируется просто путем получения среднего индекса `(int mid = (low + high) / 2)` может произойти переполнение для массива, содержащего 2³⁰ или более элементов, поскольку сумма `low + high` может легко превысить максимальное положительное значение int.

### Пример использования

```java
int[] sortedArray = {1, 3, 5, 7, 9, 11, 13, 15};
int key = 7;
int index = runBinarySearchIteratively(sortedArray, key, 0, sortedArray.length - 1);
// index = 3
```

## Рекурсивная реализация

Теперь давайте также посмотрим на простую рекурсивную реализацию:

```java
public int runBinarySearchRecursively(int[] sortedArray, int key, int low, int high) {
    int middle = low + ((high - low) / 2);
    
    if (high < low) {
        return -1;
    }
    
    if (key == sortedArray[middle]) {
        return middle;
    } else if (key < sortedArray[middle]) {
        return runBinarySearchRecursively(sortedArray, key, low, middle - 1);
    } else {
        return runBinarySearchRecursively(sortedArray, key, middle + 1, high);
    }
}
```

Метод `runBinarySearchRecursively` принимает `sortedArray`, ключ, нижний и верхний индексы `sortedArray`.

### Сравнение итеративного и рекурсивного подходов

Использовать ли рекурсивный или итеративный подход для написания алгоритма, в основном зависит от личных предпочтений. Но все же есть несколько моментов, о которых мы должны знать:

1. **Рекурсия неудобна для стека.** Это может вызвать `StackOverflowException` при обработке больших наборов данных
2. **Итеративный подход** обычно более эффективен по памяти
3. **Рекурсивный подход** может быть более читаемым для некоторых разработчиков

## Kotlin Implementation

В Kotlin алгоритм Binary Search может быть реализован следующим образом:

### Итеративная реализация

```kotlin
fun runBinarySearchIteratively(sortedArray: IntArray, key: Int, low: Int = 0, high: Int = sortedArray.size - 1): Int {
    var left = low
    var right = high
    var index = -1

    while (left <= right) {
        val mid = left + (right - left) / 2

        when {
            sortedArray[mid] < key -> left = mid + 1
            sortedArray[mid] > key -> right = mid - 1
            else -> {
                index = mid
                break
            }
        }
    }

    return index
}
```

Использование:

```kotlin
fun main() {
    val sortedArray = intArrayOf(1, 3, 5, 7, 9, 11, 13, 15)
    val key = 7
    val index = runBinarySearchIteratively(sortedArray, key)
    println(index) // 3
}
```

### Рекурсивная реализация

```kotlin
fun runBinarySearchRecursively(sortedArray: IntArray, key: Int, low: Int = 0, high: Int = sortedArray.size - 1): Int {
    if (high < low) return -1

    val middle = low + (high - low) / 2

    return when {
        key == sortedArray[middle] -> middle
        key < sortedArray[middle] -> runBinarySearchRecursively(sortedArray, key, low, middle - 1)
        else -> runBinarySearchRecursively(sortedArray, key, middle + 1, high)
    }
}
```

Использование:

```kotlin
fun main() {
    val sortedArray = intArrayOf(1, 3, 5, 7, 9, 11, 13, 15)
    val key = 7
    val index = runBinarySearchRecursively(sortedArray, key)
    println(index) // 3
}
```

## Использование стандартных библиотек

### Arrays.binarySearch()

```java
int index = Arrays.binarySearch(sortedArray, key);
```

`sortedArray` и ключ `int`, который нужно искать в массиве целых чисел, передаются в качестве аргументов методу `binarySearch` класса Java `Arrays`.

### Collections.binarySearch()

```java
int index = Collections.binarySearch(sortedList, key);
```

`sortedList` и ключ `Integer`, который нужно искать в списке объектов Integer, передаются в качестве аргументов методу `binarySearch` класса Java `Collections`.

### Возвращаемые значения

Оба метода возвращают:
- Индекс элемента, если он найден
- `-(insertion point) - 1`, если элемент не найден, где `insertion point` - позиция, где элемент должен быть вставлен

## Сложность

В идеале бинарный поиск будет выполнять меньше сравнений по сравнению с линейным поиском для больших значений n. Для меньших значений n линейный поиск может работать лучше, чем бинарный поиск.

Следует знать, что этот анализ является теоретическим и может варьироваться в зависимости от контекста.

Кроме того, алгоритм бинарного поиска нуждается в отсортированном наборе данных, который также имеет свою стоимость. Если мы используем алгоритм сортировки слиянием для сортировки данных, к нашему коду добавляется дополнительная сложность n*log(n).

### Временная сложность

- **Лучший случай:** O(1) - элемент находится в середине массива
- **Средний случай:** O(log(n))
- **Худший случай:** O(log(n)) - элемент не найден или находится на краю

### Пространственная сложность

- **Итеративная версия:** O(1) - только константная дополнительная память
- **Рекурсивная версия:** O(log(n)) - для стека вызовов

## Особенности

- **Требует отсортированный массив:** Бинарный поиск работает только с отсортированными данными
- **Эффективность:** Намного быстрее линейного поиска для больших массивов
- **Детерминированность:** Всегда находит элемент за O(log(n)) шагов
- **Применимость:** Широко используется в реальных приложениях

## Применение

Бинарный поиск используется в:

- Поиске в базах данных
- Поиске в отсортированных коллекциях
- Реализации структур данных (TreeSet, TreeMap)
- Алгоритмах оптимизации
- Игровых движках (поиск в отсортированных списках объектов)

## Когда использовать

### Используйте бинарный поиск, когда:

- Массив отсортирован
- Нужен быстрый поиск в больших массивах
- Часто выполняются операции поиска
- Память ограничена (итеративная версия)

### Используйте линейный поиск, когда:

- Массив не отсортирован
- Массив очень мал
- Нужно найти все вхождения элемента
- Сортировка дороже, чем несколько поисков

## Важные замечания

Итак, сначала нам нужно хорошо проанализировать наши требования, а затем принять решение о том, какой алгоритм поиска лучше всего соответствует нашим требованиям.

### Предварительная сортировка

Если данные не отсортированы, нужно учесть стоимость сортировки:
- Сортировка: O(n*log(n))
- Бинарный поиск: O(log(n))
- **Общая стоимость:** O(n*log(n)) для первого поиска, O(log(n)) для последующих

Если выполняется только один поиск, линейный поиск O(n) может быть быстрее, чем сортировка + бинарный поиск.

int index = Arrays.binarySearch(arr, key);
