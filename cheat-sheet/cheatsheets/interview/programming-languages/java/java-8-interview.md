## Q1. Какие новые функции были добавлены в Java 8?

Java 8** поставляется с несколькими новыми функциями, наиболее важными из которых являются следующие:

1. Lambda Functions** новая функция языка, позволяющая нам рассматривать действия как объекты.
2. Method’s Links** позволяют нам определять лямбда-выражения, ссылаясь на методы напрямую, используя их имена.
3. **Optional** — специальный класс-оболочка, используемый для выражения необязательности.
4. **Functional Interface** — интерфейс с максимум одним абстрактным методом; реализация может быть предоставлена с использованием лямбда-выражения
5. **Default Methods** — дают нам возможность добавлять полные реализации в интерфейсы помимо абстрактных методов.
6. **Nashorn, JavaScript Engine** — движок на основе **Java** для выполнения и оценки кода **JavaScript**.
7. **Stream API** — специальный класс итератора, который позволяет нам функционально обрабатывать коллекции объектов.
8. **Date API** — улучшенный, неизменяемый **API Date**, вдохновленный **JodaTime**.

Наряду с этими новыми функциями, множество внутренних улучшений функций реализовано как на уровне компилятора, так и на уровне **JVM**.



## Q2. Что такое ссылка на метод?


Ссылка на метод — это специальный тип данных в **Java**, который позволяет передавать методы как аргументы или возвращать их из других методов. Вместо вызова метода напрямую, мы можем создать ссылку на него и использовать эту ссылку для вызова метода.

Ссылка на метод может быть создана в двух формах: ссылка на статический метод или ссылка на метод экземпляра.

Ссылка на статический метод используется для ссылки на метод, объявленный как статический. Формат ссылки на статический метод **ClassName::methodName. Например, Math::max.

Ссылка на метод экземпляра используется для ссылки на метод, объявленный в классе экземпляра. Формат ссылки на метод экземпляра **objectReference::methodName. Например, String::length.

Ссылки на методы могут быть переданы в методы высшего порядка, такие как **Stream API**, для обработки коллекций данных или для создания функциональных интерфейсов с одним абстрактным методом.

Ссылки на методы позволяют улучшить читаемость кода и сделать его более компактным и выразительным. Они являются частью функционального программирования в **Java** и мощным инструментом, упрощающим работу с методами как с данными.

## Q4. Что такое Optional? Как его можно использовать?

**Optional** — это новый класс в **Java 8**, который инкапсулирует необязательное значение, то есть значение, которое либо есть, либо нет. Это оболочка вокруг объекта, и мы можем думать о ней как о контейнере из нуля или одного элемента. **Optional** имеет специальное значение `Optional.empty()` вместо обернутого `null`. Таким образом, во многих случаях его можно использовать вместо значений, допускающих `null`, чтобы избавиться от **NullPointerException**.

Основная цель **Optional**, задуманная его создателями, состоит в том, чтобы быть возвращаемым типом методов, которые ранее возвращали бы `null`. Такие методы потребовали бы от нас написания шаблонного кода для проверки возвращаемого значения, и иногда мы могли забыть сделать защитную проверку. В **Java 8**, **Optional** как возвращаемый тип явно требует, чтобы мы по-разному обрабатывали обернутые значения `null` или `non-null`.

Например, метод **Stream.min()** вычисляет минимальное значение в потоке значений. Но что, если поток пуст? Если бы не **Optional**, метод вернул бы **null** или выдал бы исключение.

Однако он возвращает **Optional**, которое может быть **Optional.empty()** (второй случай). Это позволяет нам легко обрабатывать такие случаи:

int min1 = Arrays.stream(new int\[\]{1, 2, 3, 4, 5}).min().orElse(0);

assertEquals(1, min1);

int min2 = Arrays.stream (new int\[\]{}).min().orElse (0);

assertEquals (0, min2);

Стоит отметить, что **Optional** не является классом общего назначения, как **Option** в **Scala**. Не рекомендуется использовать его в качестве значения поля в классах сущностей, на что явно указывает то, что он не реализует интерфейс **Serializable**.



## Q5. (ВАЖНО) - Какие есть функциональные интерфейсы в стандартной библиотеке?


В стандартной библиотеке **Java** имеется набор предопределенных функциональных интерфейсов, которые были введены в **JDK 8** и дополнительные функциональные интерфейсы, добавленные в последующих версиях **JDK**. Некоторые из них включают:

1. **Predicate&lt;T&gt;**: Принимает один аргумент и возвращает логическое значение `true` или `false`. Используется для фильтрации элементов коллекций или проверки условий.
2. **Function&lt;T, R&gt;**: Принимает один аргумент типа **T** и возвращает значение типа **R**. Используется для преобразования объектов одного типа в другой.
3. **Consumer&lt;T&gt;**: Принимает один аргумент типа **T** и не возвращает результат. Используется, чтобы выполнить операции над объектом типа **T**.
4. **Supplier&lt;T&gt;**: Не принимает аргументов и возвращает объект типа **T**. Используется для поставки (получения) значения.
5. **BiPredicate&lt;T, U&gt;**: Принимает два аргумента типа **T** и **U** и возвращает логическое значение `true` или `false`.
6. **BiFunction&lt;T, U, R&gt;**: Принимает два аргумента типа **T** и **U** и возвращает значение типа **R**.
7. **BiConsumer&lt;T, U&gt;**: Принимает два аргумента типа **T** и **U** и не возвращает результат.

Это только несколько примеров функциональных интерфейсов из стандартной библиотеки **Java**. В **JDK** также имеются другие функциональные интерфейсы, а также возможность создания пользовательских функциональных интерфейсов. Функциональные интерфейсы в **Java** позволяют использовать функциональное программирование и лямбда-выражения.



## Q6. (ВАЖНО) - Что такое функциональный интерфейс?


Функциональный интерфейс — это интерфейс с одним-единственным абстрактным методом (методы по умолчанию не в счет), ни больше, ни меньше.

Если требуется экземпляр такого интерфейса, вместо него можно использовать лямбда-выражение. Говоря более формально: функциональные интерфейсы предоставляют целевые типы для лямбда-выражений и ссылок на методы.

Аргументы и тип возвращаемого значения такого выражения полностью совпадают с таковыми у единственного абстрактного метода.

Например, интерфейс **Runnable** это функциональный интерфейс, поэтому вместо:

Thread thread = new Thread(new Runnable() {

public void run() {

System.out.println("Hello World!");

}

});

Мы могли бы просто сделать:

Thread thread = new Thread(() -> System.out.println("Hello World!"));

Функциональные интерфейсы обычно снабжаются аннотацией **@FunctionalInterface, которая является информативной и не влияет на семантику.



## Q7. Что такое метод по умолчанию и когда мы его используем?


Метод по умолчанию это метод с реализацией, которую можно найти в интерфейсе.

Мы можем использовать метод по умолчанию для добавления новой функциональности в интерфейс, сохраняя при этом обратную совместимость с классами, которые уже реализуют интерфейс:

public interface Vehicle{

public void move();

default void hoot() {

System.out.println("peep!");

}

}

Обычно, когда мы добавляем в интерфейс новый абстрактный метод, все реализующие классы ломаются до тех пор, пока не реализуют новый абстрактный метод. В **Java 8** эта проблема была решена с помощью метода по умолчанию.

Например, в интерфейсе **Collection** нет объявления метода **forEach**. Таким образом, добавление такого метода просто сломает весь **API** коллекций.

В **Java 8** введен метод по умолчанию, так что интерфейс **Collection** может иметь реализацию метода **forEach** по умолчанию, не требуя, чтобы классы, реализующие этот интерфейс, реализовывали то же самое.



## Q8. Будет ли компилироваться следующий код?


@FunctionalInterface

public interface Function2&lt;T, U, V&gt; {

public V apply (T t, U u);

}

Да, код будет скомпилирован, потому что он следует спецификации функционального интерфейса, определяющей только один абстрактный метод. Второй метод **count** это метод по умолчанию, который не увеличивает количество абстрактных методов.



## Q9. Что такое лямбда-выражение?


Лямбда-выражение — это компактный способ представления анонимной функции, которую можно передать как аргумент или присвоить переменной. Оно позволяет создавать небольшие, одноразовые функции "на лету" без необходимости явного объявления метода.

В **Java** лямбда-выражения были представлены в **JDK 8** вместе с функциональными интерфейсами. Они представляют удобный и мощный инструмент для функционального программирования.

Синтаксис лямбда-выражения в **Java** имеет следующую структуру:

```
(parameter1, parameter2, ...) -> expression
```

Лямбда-выражение состоит из следующих элементов:

1. Параметры: список параметров, которые принимает функция.
2. Стрелка: стрелка (`->`) разделяет параметры и тело выражения.
3. Тело выражения: выражение или блок кода, который выполняется внутри лямбда-функции.

Лямбда-выражения используются в **Java** для работы с функциональными интерфейсами, чтобы предоставить компактный и элегантный способ реализовать методы функциональных интерфейсов. Они позволяют писать более читаемый и гибкий код, упрощают обработку коллекций данных, асинхронную обработку событий, обработку запросов и многое другое.

Лямбда-выражения также позволяют сократить объем кода и избежать необходимости объявления и реализации отдельного метода для каждой операции или обработки данных.



## Q10. Что такое Stream?

**Stream** — это новый функциональный **API**, введенный в **JDK 8**, который позволяет эффективно и удобно выполнять операции с коллекциями и другими данными. Он предоставляет возможности для функционального программирования, обработки данных параллельно и лениво (отложенно).

Основные отличия между **Stream** и **Collection**:

1. Спецификация данных: Коллекция — это структура данных, которая хранит и управляет набором элементов в определенном порядке. **Stream** представляет логическую последовательность элементов, скомбинированную с набором операций, которые можно применять к этой последовательности.
2. Цель использования: Коллекции предназначены для хранения и доступа к набору элементов. **Stream** используется для выполнения и трансформации операций над элементами в коллекции или других источниках данных, без изменения исходных данных.
3. Доступ к данным: Коллекции обеспечивают прямой доступ к элементам по их индексу и позволяют выполнять операции вставки, удаления и обновления элементов. **Stream** не имеет прямого доступа к элементам и не позволяет изменять исходные данные. Вместо этого **Stream** выполняет операции над элементами и возвращает новый поток с результатами.
4. Обработка операций: Коллекции выполняют операции над элементами непосредственно в памяти, что требует модификации коллекции. **Stream** выполняет операции "на лету" (лениво), по требованию, без изменения исходных данных. Он использует конвейерную обработку, где каждая операция выполняется только при необходимости.
5. Параллельная обработка: **Stream** обеспечивает легкую параллельную обработку данных с помощью методов **parallel()** и **parallelStream()**. Коллекции не имеют встроенной поддержки параллельной обработки.

**Stream** предоставляет богатый набор операций для фильтрации, преобразования, сортировки, ограничения, сведения, агрегации и других операций над данными. Он предоставляет элегантный и функциональный подход к работе с данными, что делает его мощным инструментом в функциональном программировании и обработке коллекций в **Java**.



## Q11. (ВАЖНО) - В чем разница между промежуточными и терминальными операциями?


Различие между промежуточными и терминальными операциями в **Stream** заключается в их целях и результате выполнения.

Промежуточные операции это операции, которые применяются к элементам потока и возвращают новый поток в результате своего выполнения. Они не выполняются немедленно при вызове, а откладываются и выполняются только при наличии терминальной операции. Примеры промежуточных операций: filter(), map(), sorted(), distinct().

Терминальные операции это операции, которые приводят к окончательному результату и завершают выполнение потока. После выполнения терминальной операции нельзя использовать поток еще раз. Примеры терминальных операций: forEach(), count(), collect(), reduce(), anyMatch(), allMatch(), noneMatch().

Главная разница между промежуточными и терминальными операциями заключается в том, что промежуточные операции выполняются лениво и работают с элементами потока, создавая новый поток, в то время как терминальные операции немедленно вызываются и приводят к фактическому выполнению операции и получению конечного результата.

Важно отметить, что терминальная операция является обязательной для выполнения потока. Без вызова терминальной операции промежуточные операции не будут выполнены и результат не будет получен.



## Q12. В чем разница между map() и flatMap()?


Разница между операциями **map()** и **flatMap()** в **Stream** состоит в том, как они обрабатывают и представляют элементы в потоке.

Метод **map()** применяет функцию к каждому элементу потока и возвращает новый поток, содержащий результаты преобразования. Это значит, что каждый элемент входного потока будет преобразован в один элемент выходного потока. Результатом работы **map()** является поток элементов такого же типа.

Пример использования map():

List&lt;String&gt; names = List.of("John", "Jane", "Jack");

List&lt;String&gt; upperCaseNames = names.stream().map(String::toUpperCase).collect(Collectors.toList());

В этом примере **map()** применяет функцию **toUpperCase()** к каждому элементу списка и возвращает поток, содержащий преобразованные значения "JOHN", "JANE" и "JACK". Затем результат собирается в список **upperCaseNames**.

Метод **flatMap()** работает с элементами потока так же, как **map()**, но в отличие от **map()**, **flatMap()** получает в качестве аргумента функцию, которая возвращает поток элементов. Затем **flatMap()** "разворачивает" каждый полученный поток элементов в поток "плоского" типа. В результате **flatMap()** объединяет все потоки элементов в один выходной поток. Результатом работы **flatMap()** является поток элементов нового типа.

Пример использования flatMap():

List&lt;List<Integer&gt;> numbers = List.of(List.of(1, 2), List.of(3, 4), List.of(5, 6));

List&lt;Integer&gt; flattenedNumbers = numbers.stream().flatMap(List::stream).collect(Collectors.toList());

В этом примере **flatMap()** применяет метод **stream()** к каждому элементу списка и "разворачивает" каждый поток элементов в один плоский поток чисел. Результатом будет список **flattenedNumbers**, содержащий числа [1, 2, 3, 4, 5, 6].

Таким образом, основное отличие между **map()** и **flatMap()** заключается в том, что **map()** возвращает поток элементов, а **flatMap()** возвращает "развернутый" поток элементов из вложенных потоков. В зависимости от требуемого результата и типов данных использование **map()** или **flatMap()** может быть более подходящим.



## Q13. Что такое Stream Pipelining?

**Stream Pipelining (конвейеризация потоков)** — это процесс последовательного применения нескольких операций к элементам потока данных в **Java 8 Stream API**. Конвейер состоит из промежуточных и терминальных операций, которые работают вместе, чтобы преобразовать и обработать данные.

При использовании **Stream Pipelining, каждая операция применяется к элементам потока и передает результат следующей операции. Это позволяет создавать цепочки операций, выполняющих различные преобразования и фильтрации данных.Пример использования Stream Pipelining:

List&lt;String&gt; names = List.of("John", "Jane", "Jack", "Jill", "James");

List&lt;String&gt; result = names.stream().filter(name -> name.length() > 3).map(String::toUpperCase).sorted().collect(Collectors.toList());

В этом примере мы создаем поток из списка имен, фильтруем имена, оставляя только те, чья длина больше **3** символов, затем преобразуем оставшиеся имена в верхний регистр, сортируем имена в алфавитном порядке и, наконец, собираем результаты в новый список. Каждая операция в конвейере применяется последовательно, используя результат предыдущей операции.Stream Pipelining** позволяет нам использовать лаконичный и выразительный код для обработки и преобразования данных. Он также способствует ленивому выполнению операций, что может привести к более эффективной обработке больших объемов данных.



## Q14. Опишите новый Date API


В **Java 8** был представлен новый **API** для работы с датами и временем **java.time**. Этот **API** предоставляет более удобные и гибкие средства для работы с датами, временем, промежутками времени и временными зонами.

В основе **API** даты и времени **Java 8** находятся следующие классы и интерфейсы:

1. **LocalDate** — представляет дату без времени в виде года, месяца и дня.
2. **LocalTime** — представляет время без даты в виде часа, минуты, секунды и наносекунды.
3. **LocalDateTime** — представляет дату и время без временной зоны.
4. **ZonedDateTime** — представляет дату, время и временную зону.
5. **OffsetDateTime** — представляет дату, время и смещение относительно **UTC**.
6. **Instant** — представляет момент времени в мировом координированном времени (UTC).
7. **Duration** — представляет промежуток времени в виде количества секунд и наносекунд.
8. **Period** — представляет промежуток времени в виде количества лет, месяцев и дней.
9. **DateTimeFormatter** — представляет формат даты и времени для преобразования строк в объекты даты и времени и обратно.
10. **ZoneId** — представляет временную зону, например, "Europe/Paris".
11. **ZoneOffset** — представляет смещение относительно **UTC**, например, "+02:00".

**Java 8 Date API** улучшает производительность, позволяет более легко обрабатывать смену даты и времени и имеет более интуитивный и гибкий интерфейс. Также **API** предлагает множество методов для выполнения операций над датами и временем, таких как получение следующего рабочего дня, сравнение дат, добавление промежутков времени и многое другое.

Пример использования нового **Date API:

LocalDate currentDate = LocalDate.now();

LocalTime currentTime = LocalTime.now();

LocalDateTime dateTime = LocalDateTime.of(currentDate, currentTime);

ZonedDateTime zonedDateTime = ZonedDateTime.of(dateTime, ZoneId.of("Europe/Paris"));

Duration duration = Duration.ofHours(2);

LocalDateTime resultDateTime = dateTime.plus(duration);

System.out.println("Текущая дата: " + currentDate);

System.out.println("Текущее время: " + currentTime);

System.out.println("Комбинированная дата и время: " + dateTime);

System.out.println("Дата, время и временная зона: " + zonedDateTime);

System.out.println("Результат после добавления промежутка времени: " + resultDateTime);

Это лишь небольшой пример использования нового **API** даты и времени. Он предлагает мощные и удобные инструменты для работы с датами и временем в **Java 8**.

## Best Practices для Java 8

### 1. Использование Lambda Expressions

**✅ Правильно:**
```java
// Использование лямбда-выражений для краткости и читаемости
List<String> names = users.stream()
    .filter(user -> user.isActive())
    .map(User::getName)
    .collect(Collectors.toList());
```

**❌ Неправильно:**
```java
// Избегайте излишне сложных лямбда-выражений
List<String> names = users.stream()
    .filter(user -> {
        if (user == null) return false;
        if (!user.isActive()) return false;
        if (user.getName() == null) return false;
        return true;
    })
    .map(user -> {
        String name = user.getName();
        return name != null ? name : "Unknown";
    })
    .collect(Collectors.toList());
```

### 2. Использование Optional

**✅ Правильно:**
```java
// Использование Optional для возвращаемых значений методов
public Optional<User> findUser(Long id) {
    return userRepository.findById(id);
}

// Обработка Optional
findUser(id).ifPresent(user -> processUser(user));
```

**❌ Неправильно:**
```java
// Не используйте Optional как поле класса
public class User {
    private Optional<String> email; // ❌ Неправильно!
}

// Не используйте Optional для параметров методов
public void processUser(Optional<User> user) { // ❌ Неправильно!
}
```

### 3. Использование Stream API

**✅ Правильно:**
```java
// Использование Stream для обработки коллекций
List<String> activeUserEmails = users.stream()
    .filter(User::isActive)
    .map(User::getEmail)
    .collect(Collectors.toList());
```

**❌ Неправильно:**
```java
// Не используйте Stream для простых операций
for (User user : users) { // Простой цикл лучше для простых операций
    if (user.isActive()) {
        processUser(user);
    }
}
```

### 4. Использование Method References

**✅ Правильно:**
```java
// Использование Method References когда возможно
users.stream()
    .map(User::getName) // Method Reference
    .map(String::toUpperCase) // Method Reference
    .collect(Collectors.toList());
```

**❌ Неправильно:**
```java
// Избегайте излишнего использования лямбда, когда есть Method Reference
users.stream()
    .map(user -> user.getName()) // Можно заменить на User::getName
    .map(name -> name.toUpperCase()) // Можно заменить на String::toUpperCase
    .collect(Collectors.toList());
```

## Troubleshooting Java 8

### Проблема 1: NullPointerException при использовании Optional

**Симптомы:
```java
Optional<User> user = findUser(id);
String email = user.get().getEmail(); // NullPointerException если Optional.empty()
```

**Решение:
```java
// Используйте безопасные методы Optional
String email = findUser(id).map(User::getEmail).orElse("default@example.com");

// Или используйте orElseThrow для явного исключения
String email = findUser(id).map(User::getEmail).orElseThrow(() -> new UserNotFoundException("User not found"));
```

### Проблема 2: Stream уже использован

**Симптомы:
```java
Stream<String> stream = names.stream();
List<String> filtered = stream.filter(s -> s.length() > 3).collect(Collectors.toList());
List<String> mapped = stream.map(String::toUpperCase).collect(Collectors.toList()); // IllegalStateException
```

**Решение:
```java
// Создавайте новый Stream для каждой операции
List<String> names = Arrays.asList("John", "Jane", "Jack");
List<String> filtered = names.stream().filter(s -> s.length() > 3).collect(Collectors.toList());

List<String> mapped = names.stream() // Новый Stream.map(String::toUpperCase).collect(Collectors.toList());
```

### Проблема 3: Проблемы с производительностью Stream

**Симптомы:
- Медленная обработка больших коллекций
- Высокое потребление памяти

**Решение:
```java
// Используйте parallelStream для больших коллекций
List<String> processed = largeCollection.parallelStream().filter(item -> item.isValid()).map(Item::process).collect(Collectors.toList());

// Но будьте осторожны - parallelStream не всегда быстрее
// Используйте только для действительно больших коллекций (> 10000 элементов)
```

### Проблема 4: Ошибки компиляции с Lambda

**Симптомы:
```java
// Ошибка: Target type of a lambda conversion must be an interface
Object lambda = () -> System.out.println("Hello"); // ❌ Ошибка компиляции
```

**Решение:
```java
// Указывайте явный тип функционального интерфейса
Runnable lambda = () -> System.out.println("Hello"); // ✅ Правильно

// Или используйте явное приведение типа
Object lambda = (Runnable) () -> System.out.println("Hello"); // ✅ Правильно
```

### Проблема 5: Неправильное использование Default Methods

**Симптомы:
- Конфликты при множественном наследовании интерфейсов
- Неожиданное поведение при переопределении default методов

**Решение:
```java
// Если два интерфейса имеют default методы с одинаковой сигнатурой,
// класс должен явно переопределить метод
public interface InterfaceA {
 default void method() {
 System.out.println("InterfaceA");
 }
}

public interface InterfaceB {
 default void method() {
 System.out.println("InterfaceB");
 }
}

// Класс должен явно переопределить метод
public class MyClass implements InterfaceA, InterfaceB {
 @Override
 public void method() {
 // Явное указание, какой метод использовать
 InterfaceA.super.method(); // Вызов default метода из InterfaceA
 // или собственная реализация
 }
}
```
