## Введение в Scala

**Scala** (Scalable Language) — это современный язык программирования, который объединяет объектно-ориентированное и функциональное программирование. **Scala** работает на платформе **Java Virtual Machine** (JVM) и полностью совместима с **Java**.

### Основные характеристики Scala:

1. **Объектно-ориентированное программирование**: Каждое значение является объектом, каждый оператор — методом
2. **Функциональное программирование**: Функции являются объектами первого класса, поддержка неизменяемых структур данных
3. **Статическая типизация**: Система типов помогает предотвращать ошибки во время компиляции
4. **Вывод типов**: Компилятор может автоматически определять типы в большинстве случаев
5. **Краткость кода**: **Scala** позволяет писать более компактный код по сравнению с **Java**

### Преимущества Scala:

- **Краткость**: Меньше кода для выражения тех же идей
- **Безопасность типов**: Мощная система типов предотвращает множество ошибок
- **Функциональное программирование**: Поддержка функциональных парадигм
- **Совместимость с Java**: Можно использовать **Java**-библиотеки напрямую
- **Производительность**: Компилируется в байт-код **JVM**, сравнимая производительность с **Java**

## Установка и настройка

### Установка Scala

**Scala** можно установить несколькими способами:**

1. **Через sbt (Scala Build Tool)** — рекомендуемый способ
2. **Через SDKMAN**
3. **Через `Homebrew` (macOS)**
4. **Вручную с официального сайта**

### Базовая настройка проекта

**Для создания нового проекта **Scala** используется **sbt**:**

```bash
sbt new scala/scala-seed.g8
```

**Или создать проект вручную:**

```bash
mkdir my-project
cd my-project
mkdir -p src/main/scala
```

**Структура проекта:**

```text
# Стандартная структура sbt-проекта
my-project/
├── build.sbt
└── src/
    └── main/
        └── scala/
            └── Main.scala
```


## Базовый синтаксис

Синтаксис **Scala** сочетает объектно-ориентированные и функциональные парадигмы, обеспечивая выразительность и безопасность типов. **Scala** компилируется в байт-код **JVM**, что обеспечивает полную совместимость с **Java** и доступ к экосистеме **Java** библиотек.

### Hello World

Простейшая программа на **Scala** демонстрирует основные элементы языка. В **Scala** 2 используется традиционный подход с объектом и методом **main**, который принимает массив строк аргументов. Это обеспечивает совместимость с **Java** и стандартным способом запуска приложений на **JVM**.

**Простейшая программа на **Scala**:**

```scala
// Scala 2 синтаксис
// object создает singleton объект, который содержит точку входа в программу
// main метод является стандартной точкой входа для JVM приложений
object HelloWorld {
  def main(args: Array[String]): Unit = {
    println("Hello, World!")
  }
}
```

В **Scala** 3 можно использовать более простой синтаксис с аннотацией `@main`, которая автоматически генерирует метод **main**. Это упрощает создание простых программ и скриптов, уменьшая **boilerplate** код.

**В **Scala** 3 можно использовать более простой синтаксис:**

```scala
// Scala 3 синтаксис
// @main аннотация автоматически создает точку входа в программу
// Это более лаконичный способ создания простых программ
@main def hello() = println("Hello, World!")
```

### Основные элементы синтаксиса

**Scala** предоставляет богатый набор конструкций для создания программ. Понимание основных элементов синтаксиса критично для эффективного использования языка.

- **Объекты (Objects)**: **Singleton**-объекты, содержат методы и значения. Объекты создаются один раз при первом обращении и используются для хранения статических методов, значений и как точки входа в приложения. Они обеспечивают функциональность, аналогичную статическим методам в **Java**, но с более мощными возможностями.

- **Классы (Classes)**: Шаблоны для создания объектов. Классы определяют структуру и поведение объектов. В **Scala** классы могут иметь параметры конструктора, которые автоматически становятся полями класса, что упрощает определение классов данных.

- **Методы (Methods)**: Функции, определенные внутри классов или объектов. Методы могут быть определены с явным указанием типа возвращаемого значения или с выводом типа. **Scala** поддерживает методы без параметров, методы с несколькими списками параметров (currying) и методы с параметрами по умолчанию.

- **Значения (Values)**: Неизменяемые переменные (объявляются через `val`). Значения являются предпочтительным способом хранения данных в **Scala**, так как неизменяемость упрощает рассуждения о коде и предотвращает ошибки, связанные с неожиданными изменениями состояния.

- **Переменные (Variables)**: Изменяемые переменные (объявляются через `var`). Переменные используются реже, чем значения, и только когда действительно необходимо изменять состояние. Использование `var` должно быть обосновано, так как изменяемость усложняет код и может привести к ошибкам в многопоточных программах.

## Типы данных

### Примитивные типы

**Scala** не имеет примитивных типов в том смысле, как **Java**. Все типы являются объектами:**

- `Byte` — 8-битное целое число со знаком
- `Short` — 16-битное целое число со знаком
- `Int` — 32-битное целое число со знаком
- `Long` — 64-битное целое число со знаком
- `Float` — 32-битное число с плавающей точкой
- `Double` — 64-битное число с плавающей точкой
- `Char` — 16-битный **Unicode**-символ
- `Boolean` — логический тип (true/false)
- `String` — последовательность символов

### Примеры использования типов

```scala
// Объявление неизменяемых значений с явным типом
val number: Int = 42
val pi: Double = 3.14159
val name: String = "Scala"
val isActive: Boolean = true
val letter: Char = 'A'
```

### Вывод типов

**Scala** может автоматически определять типы:**

```scala
val number = 42        // тип Int выводится автоматически
val pi = 3.14159      // тип Double выводится автоматически
val name = "Scala"    // тип String выводится автоматически
```

## Переменные и значения

### Val (неизменяемое значение)

**`val` создает неизменяемое значение:**

```scala
val x = 10
// x = 20  // Ошибка компиляции! val нельзя переназначить
```

### Var (изменяемая переменная)

**`var` создает изменяемую переменную:**

```scala
var y = 10
y = 20  // OK, var можно переназначить
```

### Рекомендации

- **Используйте `val` по умолчанию** — это способствует функциональному стилю программирования
- Используйте `var` только когда действительно нужно изменять значение
- Неизменяемость помогает избежать ошибок и упрощает параллельное программирование

## Функции

Функции в **Scala** являются объектами первого класса, что означает, что их можно передавать как параметры, возвращать из других функций и хранить в переменных. Это обеспечивает мощные возможности для функционального программирования и создания абстракций высокого уровня.

### Определение функций

Определение функции в **Scala** начинается с ключевого слова `def`, за которым следует имя функции, параметры с типами и тип возвращаемого значения. Тело функции может быть выражением или блоком кода. **Scala** поддерживает вывод типов для возвращаемого значения, что позволяет опускать явное указание типа в некоторых случаях.

**Базовый синтаксис определения функции:**

```scala
// Полная форма с явным указанием типа возвращаемого значения
def functionName(param1: Type1, param2: Type2): ReturnType = {
  // тело функции
  expression
}

// Форма с выводом типа возвращаемого значения
def functionName(param1: Type1, param2: Type2) = {
  expression
}
```

Явное указание типа возвращаемого значения рекомендуется для публичных методов, так как это улучшает читаемость кода и помогает компилятору обнаруживать ошибки. Вывод типа полезен для внутренних методов и простых функций, где тип очевиден из контекста.

### Простые функции

Простые функции демонстрируют различные способы определения функций в **Scala**. Однострочные функции могут быть определены без фигурных скобок, что делает код более лаконичным. Многострочные функции требуют фигурных скобок и могут содержать несколько выражений, где последнее выражение является возвращаемым значением.

```scala
// Многострочная функция с явным указанием типа
def add(a: Int, b: Int): Int = {
  a + b
}

// Однострочная функция (более лаконичная форма)
// Фигурные скобки можно опустить для однострочных функций
def add(a: Int, b: Int): Int = a + b

// Вывод типа возвращаемого значения
// Компилятор автоматически определяет тип возвращаемого значения как Int
// Это полезно для простых функций, где тип очевиден
def multiply(a: Int, b: Int) = a * b
```

Выбор между явным указанием типа и выводом типа зависит от контекста. Для публичных **API** рекомендуется явное указание типов, так как это улучшает читаемость и документирует интерфейс. Для внутренних функций вывод типа может сделать код более лаконичным.

### Функции без параметров

```scala
// Функция без параметров, возвращает строку
def greet(): String = {
  "Hello, Scala!"
}

// Скобки можно опустить при вызове
val message = greet  // или greet()
```

### Функции без возвращаемого значения (Unit)

```scala
// Функция с побочным эффектом (Unit — аналог void)
def printMessage(msg: String): Unit = {
  println(msg)
}

// Unit можно опустить
def printMessage(msg: String) = {
  println(msg)
}
```

### Функции высшего порядка

Функции высшего порядка — это функции, которые принимают другие функции в качестве параметров или возвращают функции. В **Scala** функции являются объектами первого класса, что означает, что их можно передавать как значения, хранить в переменных и возвращать из других функций. Это обеспечивает мощные возможности для создания абстракций и переиспользуемого кода.

Функции высшего порядка являются основой функционального программирования и позволяют создавать обобщенные алгоритмы, которые работают с различными функциями. Это устраняет необходимость в дублировании кода и делает программы более выразительными.

**Функции являются объектами первого класса:**

```scala
// Функция высшего порядка принимает функцию как параметр
// f: Int => Int означает функцию, которая принимает Int и возвращает Int
def applyFunction(f: Int => Int, x: Int): Int = {
  f(x)  // Применяет функцию f к значению x
}

// Функция может быть сохранена в переменной
val double = (x: Int) => x * 2

// Функция передается как параметр в функцию высшего порядка
val result = applyFunction(double, 5)  // результат: 10
// double применяется к 5, что дает 5 * 2 = 10
```

Функции высшего порядка позволяют создавать обобщенные алгоритмы, которые работают с различными функциями, что делает код более гибким и переиспользуемым.

### Анонимные функции

Анонимные функции (lambda функции) — это функции, определенные без имени. Они особенно полезны для передачи небольших функций в методы коллекций и другие функции высшего порядка. Анонимные функции делают код более лаконичным и выразительным, позволяя определять поведение непосредственно в месте использования.

```scala
// Анонимные функции могут быть сохранены в переменных
val add = (x: Int, y: Int) => x + y
val multiply = (x: Int) => x * 2

// Использование в методах коллекций
// Анонимная функция передается напрямую в метод map
// x => x * 2 означает функцию, которая умножает каждый элемент на 2
List(1, 2, 3).map(x => x * 2)  // List(2, 4, 6)

// Анонимные функции особенно полезны для коротких операций
// Они делают код более читаемым, так как логика находится рядом с использованием
```

Анонимные функции являются основой для работы с коллекциями в функциональном стиле, позволяя выразительно трансформировать данные без необходимости определять именованные функции для каждой операции.

## Классы и объекты

Классы в **Scala** определяют структуру и поведение объектов. В отличие от **Java**, параметры конструктора класса могут быть объявлены как `val` или `var`, что автоматически создает поля класса. Это упрощает определение классов данных и уменьшает **boilerplate** код.

Классы могут наследовать от других классов и **traits**, поддерживая объектно-ориентированное программирование. **Scala** также поддерживает **singleton** объекты, которые являются единственным экземпляром класса и используются для хранения статических методов и значений.

### Определение класса

Определение класса в **Scala** начинается с ключевого слова `class`, за которым следует имя класса и параметры конструктора. Параметры конструктора, объявленные как `val` или `var`, автоматически становятся полями класса. Это позволяет определять классы данных более лаконично, чем в **Java**.

```scala
// Параметры конструктора с val создают неизменяемые поля
// Параметры с var создают изменяемые поля
// Параметры без val/var являются только параметрами конструктора
class Person(val name: String, var age: Int) {
  // Методы класса могут использовать поля, созданные из параметров
  def greet(): String = {
    s"Hello, my name is $name and I am $age years old"
  }
}

// Использование
// Ключевое слово new используется для создания экземпляров класса
val person = new Person("Alice", 30)
println(person.greet())
println(person.name)  // val параметр становится геттером
person.age = 31       // var параметр имеет геттер и сеттер
```

### Класс с методами

```scala
// Простой класс с методом
class Calculator {
  def add(a: Int, b: Int): Int = a + b
  def subtract(a: Int, b: Int): Int = a - b
  def multiply(a: Int, b: Int): Int = a * b
  def divide(a: Double, b: Double): Double = {
    if (b != 0) a / b
    else throw new IllegalArgumentException("Division by zero")
  }
}
```

### Объекты (Singleton)

**Объекты в **Scala** — это **singleton**-объекты:**

```scala
// Singleton-объект (один экземпляр на JVM)
object Logger {
  def log(message: String): Unit = {
    println(s"[LOG] $message")
  }
}

// Использование
Logger.log("Application started")
```

## Case классы

**Case** классы — это специальный тип классов в **Scala**, который автоматически генерирует много полезного кода. **Case** классы оптимизированы для использования в функциональном программировании и **pattern matching**. Они являются неизменяемыми по умолчанию и предоставляют структурное равенство вместо ссылочного, что делает их идеальными для представления данных.

**Case** классы особенно полезны для создания моделей данных, **DTO** (`Data Transfer Objects`) и для использования в **pattern matching**. Они автоматически генерируют методы, которые обычно требуют написания **boilerplate** кода в других языках, что делает код более лаконичным и безопасным.

```scala
// Определение case класса
// Все параметры автоматически становятся неизменяемыми полями
case class Point(x: Int, y: Int)

// Автоматически получаем:
// - Конструктор: Point(1, 2)
// - Геттеры для всех параметров: point.x, point.y
// - Методы equals и hashCode: сравнение по значению, а не по ссылке
// - Метод toString: удобное представление для отладки
// - Метод copy: создание копии с измененными полями
// - Объект-компаньон с методом apply: позволяет создавать экземпляры без new
```

Автоматическая генерация кода в **case** классах значительно упрощает работу с данными. Методы `equals` и `hashCode` реализованы на основе значений полей, что обеспечивает корректное сравнение объектов по значению, а не по ссылке. Это критично для использования **case** классов в коллекциях и для **pattern matching**.

### Использование case классов

**Case** классы предоставляют удобный синтаксис для создания и работы с данными. Метод `apply` в объекте-компаньоне позволяет создавать экземпляры без ключевого слова `new`, что делает код более читаемым. Метод `copy` позволяет создавать новые экземпляры с измененными полями, сохраняя неизменяемость данных.

```scala
case class Person(name: String, age: Int)

// Создание экземпляров
// apply вызывается автоматически, ключевое слово new не требуется
val person1 = Person("Alice", 30)  // apply вызывается автоматически
val person2 = Person("Alice", 30)

// Сравнение по значению (не по ссылке)
// equals сравнивает значения полей, а не ссылки на объекты
// Это означает, что два объекта с одинаковыми значениями считаются равными
println(person1 == person2)  // true - объекты равны по значению

// Автоматический toString
// toString генерируется автоматически и показывает структуру объекта
println(person1)  // Person(Alice,30) - удобно для отладки

// Копирование с изменением
// copy создает новый объект с измененными полями
// Исходный объект остается неизменным, что обеспечивает неизменяемость
val person3 = person1.copy(age = 31)  // Person(Alice,31)
// person1 остается Person(Alice,30)
```

**Case** классы идеально подходят для функционального программирования, так как они неизменяемы и поддерживают структурное равенство. Это делает их безопасными для использования в многопоточных программах и упрощает рассуждения о поведении кода.

## Паттерн-матчинг

Паттерн-матчинг — мощная функция **Scala** для сопоставления с образцом, которая позволяет декомпозировать данные и обрабатывать различные случаи элегантным способом. **Pattern matching** является более мощной альтернативой **switch**-конструкциям в других языках, поддерживая декомпозицию сложных структур данных, **guards** (условия) и извлечение значений из структур.

**Pattern matching** в **Scala** проверяется на полноту компилятором, что означает, что компилятор может предупредить, если не все возможные случаи обработаны. Это особенно полезно при работе с **sealed** классами и **traits**, где компилятор гарантирует, что все подтипы обработаны.

### Базовый pattern matching

Базовый **pattern matching** позволяет сопоставлять значения с различными образцами. Каждый `case` представляет собой образец, с которым сравнивается значение. Если образец совпадает, выполняется соответствующий код. Символ `_` используется как **wildcard** для обработки всех остальных случаев.

```scala
// Pattern matching с целыми числами
// Каждый case проверяет значение и возвращает соответствующую строку
def matchNumber(x: Int): String = x match {
  case 0 => "zero"      // Точное совпадение с 0
  case 1 => "one"       // Точное совпадение с 1
  case 2 => "two"       // Точное совпадение с 2
  case _ => "many"      // default case - обрабатывает все остальные значения
}

// Pattern matching выполняется сверху вниз
// Первое совпадение определяет, какой код будет выполнен
```

**Pattern matching** более выразителен, чем **if-else** цепочки, так как он явно показывает все возможные случаи и обеспечивает проверку полноты на этапе компиляции.

### Pattern matching с case классами

**Pattern matching** особенно мощный при работе с **case** классами, так как позволяет декомпозировать объекты и извлекать значения полей. Это делает код более читаемым и выразительным, чем использование геттеров и условий.

```scala
case class Person(name: String, age: Int)

def greetPerson(person: Person): String = person match {
  // Декомпозиция с конкретным значением имени
  // Переменная age извлекается из объекта
  case Person("Alice", age) => s"Hello Alice, you are $age years old"

  // Декомпозиция с guard (условием)
  // if age < 18 проверяет дополнительное условие
  case Person(name, age) if age < 18 => s"Hello $name, you are too young"

  // Общий случай - извлекает оба поля
  case Person(name, age) => s"Hello $name, you are $age years old"
}

// Pattern matching позволяет элегантно обрабатывать различные случаи
// Компилятор проверяет полноту pattern matching
```

Декомпозиция **case** классов в **pattern matching** позволяет извлекать значения полей напрямую в образце, что делает код более лаконичным и читаемым, чем использование геттеров.

### Pattern matching со списками

**Pattern matching** со списками использует оператор `::` для декомпозиции списков на **head** (первый элемент) и **tail** (остальные элементы). Это позволяет элегантно обрабатывать различные случаи: пустой список, список с одним элементом и список с несколькими элементами.

```scala
// Pattern matching с декомпозицией списков
// Nil представляет пустой список
// head :: tail декомпозирует список на первый элемент и остальные
def describeList(list: List[Int]): String = list match {
  case Nil => "empty list"                    // Пустой список
  case head :: Nil => s"single element: $head"  // Список с одним элементом
  case head :: tail => s"head: $head, tail: ${tail.mkString(", ")}"  // Список с несколькими элементами
}

// Pattern matching со списками особенно полезен для рекурсивной обработки
// Оператор :: позволяет декомпозировать список без явного использования методов head и tail
```

**Pattern matching** со списками является основой для рекурсивной обработки данных в функциональном стиле, позволяя элегантно обрабатывать различные структуры данных.

## Traits

**Traits** — это механизм для композиции поведения в **Scala**, аналогичный интерфейсам в **Java**, но с более мощными возможностями. **Traits** могут содержать как абстрактные методы (без реализации), так и конкретные методы (с реализацией). Это позволяет создавать переиспользуемые компоненты поведения, которые можно комбинировать в классах.

**Traits** поддерживают множественное наследование через **mixin composition**, что позволяет классу наследовать поведение от нескольких **traits**. Это обеспечивает гибкость в композиции функциональности без проблем алмаза наследования, которые возникают в других языках, благодаря линейному разрешению методов (linearization).

```scala
// Абстрактный trait - определяет интерфейс без реализации
trait Greeting {
  def greet(): String
}

// Конкретный trait - предоставляет реализацию метода
trait FormalGreeting extends Greeting {
  def greet(): String = "Good day"
}

// Другой конкретный trait с другой реализацией
trait FriendlyGreeting extends Greeting {
  def greet(): String = "Hey!"
}

// Класс наследует trait и может переопределить методы
// super.greet() вызывает реализацию из trait
class Person(val name: String) extends FriendlyGreeting {
  override def greet(): String = s"${super.greet()} I'm $name"
}
```

**Traits** позволяют создавать модульные компоненты поведения, которые можно комбинировать различными способами. Это обеспечивает гибкость в дизайне классов и позволяет избежать дублирования кода.

### Mixin composition

**Mixin composition** позволяет классу наследовать поведение от нескольких **traits** одновременно. Это обеспечивает мощный механизм композиции функциональности, где каждый **trait** добавляет определенное поведение к классу. **Scala** использует линейное разрешение методов (linearization) для определения порядка вызова методов при множественном наследовании.

```scala
// Traits определяют отдельные аспекты поведения
trait Speaker {
  def speak(): String = "Speaking"
}

trait Writer {
  def write(): String = "Writing"
}

// Класс наследует несколько traits через ключевое слово with
// Каждый trait добавляет свое поведение к классу
class Author(val name: String) extends Speaker with Writer {
  // Класс может использовать методы из обоих traits
  def introduce(): String = s"I'm $name, ${speak()} and ${write()}"
}

// Mixin composition позволяет создавать классы с комбинированным поведением
// Порядок traits важен для разрешения конфликтов методов
```

**Mixin composition** является мощным инструментом для создания гибких и модульных дизайнов. **Traits** можно комбинировать различными способами, создавая классы с нужным набором функциональности без необходимости создавать сложные иерархии наследования.

## Объекты-компаньоны

**Объект-компаньон — это объект с тем же именем, что и класс:**

```scala
class Person(val name: String, val age: Int)

object Person {
  def apply(name: String, age: Int): Person = new Person(name, age)

  def fromBirthYear(name: String, birthYear: Int): Person = {
    val currentYear = 2024
    new Person(name, currentYear - birthYear)
  }
}

// Использование
val person1 = Person("Alice", 30)  // используется apply
val person2 = Person.fromBirthYear("Bob", 1990)
```

## Generics (Обобщенные типы)

**Scala** поддерживает обобщенные типы для создания переиспользуемого кода. **Generics** позволяют создавать типобезопасный код, работающий с различными типами, не теряя при этом информацию о типах на этапе компиляции.

### Простые Generics

```scala
// Простой generic класс
class Box[T](var content: T) {
  def get: T = content
  def set(value: T): Unit = {
    content = value
  }
}

// Использование
val intBox = new Box[Int](42)
val stringBox = new Box[String]("Hello")

// Generic функции
def identity[A](x: A): A = x

def first[A](list: List[A]): Option[A] = list.headOption
```

**Generics** позволяют создавать типобезопасный код, работающий с различными типами, обеспечивая переиспользование кода без потери типобезопасности.

### Ограничения типов

```scala
// Верхняя граница (upper bound)
class Container[T <: Comparable[T]](val value: T) {
  def compare(other: T): Int = value.compareTo(other)
}

// Нижняя граница (lower bound)
def process[A >: String](value: A): Unit = {
  println(value)
}

// View bound (устаревший, используется implicit)
class Container2[T <% Ordered[T]](val value: T) {
  def compare(other: T): Boolean = value < other
}
```

Ограничения типов позволяют накладывать требования на типы параметров, обеспечивая доступ к определенным методам или свойствам.

### Variance (Вариантность)

**Scala** поддерживает три вида вариантности, которые определяют, как отношения между типами влияют на отношения между обобщенными типами:**

```scala
// Covariant (ковариантность) - обозначается +
// Если A <: B, то List[A] <: List[B]
class CovariantBox[+T](val content: T)

// Contravariant (контравариантность) - обозначается -
// Если A <: B, то Function[-B, R] <: Function[-A, R]
class ContravariantBox[-T]

// Invariant (инвариантность) - без обозначения
// Нет отношения подтипов между обобщенными типами
class InvariantBox[T]
```

Понимание вариантности критично для работы с **generics** в **Scala**. Ковариантность позволяет использовать более конкретные типы там, где ожидаются более общие, что особенно полезно для **immutable** коллекций.

### Примеры использования вариантности

```scala
// List ковариантен
val list: List[Any] = List(1, 2, 3)  // List[Int] может быть присвоен List[Any]

// Function контравариантен по параметрам и ковариантен по возвращаемому значению
val func: (Any => String) = (x: String) => x.toString  // String => String может быть присвоен Any => String
```

Вариантность обеспечивает типобезопасность при работе с обобщенными типами и позволяет создавать более гибкие **API**.

## Implicit (Неявные параметры и преобразования)

**Implicit** механизм в **Scala** позволяет автоматически передавать параметры и преобразовывать типы, что делает код более лаконичным и выразительным. Это инструмент, который требует осторожного использования.

### Implicit параметры

**Implicit** параметры позволяют автоматически передавать значения из неявного контекста:**

```scala
def greet(name: String)(implicit greeting: String): String = {
  s"$greeting, $name!"
}

implicit val defaultGreeting = "Hello"

greet("Alice")  // "Hello, Alice!" - greeting передается автоматически

// Явная передача все еще возможна
greet("Bob")("Hi")  // "Hi, Bob!"
```

**Implicit** параметры особенно полезны для передачи контекстной информации, такой как **ExecutionContext**, **Logger** или конфигурация, без явного указания в каждом вызове функции.

### Implicit conversions

**Implicit conversions** позволяют автоматически преобразовывать типы, расширяя функциональность существующих типов:**

```scala
implicit def intToString(x: Int): String = x.toString

def printString(s: String): Unit = println(s)

printString(42)  // 42 автоматически преобразуется в String

// Implicit class для extension methods
implicit class RichInt(val x: Int) extends AnyVal {
  def isEven: Boolean = x % 2 == 0
  def isOdd: Boolean = x % 2 != 0
}

5.isEven  // false
6.isEven  // true
```

**Implicit conversions** следует использовать осторожно, так как они могут сделать код менее явным и затруднить понимание.

### Scala 3: given и using

**В **Scala** 3 **implicit** заменены на `given` и `using` для большей ясности:**

```scala
// Scala 3 синтаксис
def greet(name: String)(using greeting: String): String = {
  s"$greeting, $name!"
}

given defaultGreeting: String = "Hello"

greet("Alice")  // "Hello, Alice!"
```

Новый синтаксис делает использование **implicit** более явным и понятным.

## Higher-Order Functions (Функции высшего порядка)

Функции высшего порядка принимают или возвращают другие функции. Это одна из фундаментальных концепций функционального программирования, которая позволяет создавать более абстрактный и переиспользуемый код.

### Функции как параметры

**Когда функция принимает другую функцию как параметр, она становится более универсальной, так как поведение может быть настроено через передаваемую функцию:**

```scala
// Функция, принимающая функцию
def applyTwice(f: Int => Int, x: Int): Int = {
  f(f(x))
}

applyTwice(_ + 1, 5)  // 7 (5 + 1 + 1)

// Функция с несколькими параметрами-функциями
def combine(f: Int => Int, g: Int => Int, x: Int): Int = {
  g(f(x))
}

combine(_ + 1, _ * 2, 5)  // (5 + 1) * 2 = 12
```

Функции высшего порядка делают код более гибким и переиспользуемым, позволяя настраивать поведение через передаваемые функции.

### Функции как возвращаемые значения

**Функция, возвращающая функцию, позволяет создавать специализированные функции из общих:**

```scala
// Функция, возвращающая функцию
def multiplyBy(factor: Int): Int => Int = {
  (x: Int) => x * factor
}

val double = multiplyBy(2)
val triple = multiplyBy(3)

double(5)  // 10
triple(5)  // 15

// Функция, возвращающая функцию с несколькими параметрами
def createAdder(x: Int): Int => Int = {
  (y: Int) => x + y
}

val add5 = createAdder(5)
add5(3)  // 8
```

Возврат функций позволяет создавать специализированные функции из общих, что является основой каррирования и частичного применения.

### Комбинирование функций

**Функции высшего порядка могут комбинировать несколько функций:**

```scala
// Композиция функций
def compose[A, B, C](f: B => C, g: A => B): A => C = {
  (x: A) => f(g(x))
}

val addOne = (x: Int) => x + 1
val multiplyByTwo = (x: Int) => x * 2

val composed = compose(multiplyByTwo, addOne)
composed(5)  // (5 + 1) * 2 = 12
```

Функции высшего порядка являются основой функционального программирования в **Scala**, позволяя создавать композируемые и переиспользуемые решения.

## Currying (Каррирование)

Каррирование позволяет преобразовать функцию с несколькими аргументами в цепочку функций с одним аргументом. Это инструмент функционального программирования, который позволяет создавать специализированные функции из общих.

### Базовое каррирование

```scala
// Обычная функция
def add(x: Int, y: Int): Int = x + y

// Каррированная функция
def addCurried(x: Int)(y: Int): Int = x + y

// Использование
val add5 = addCurried(5)
add5(3)  // 8
add5(10) // 15

// Частичное применение
def multiply(x: Int)(y: Int): Int = x * y
val multiplyBy10 = multiply(10)_
multiplyBy10(5)  // 50
```

Каррирование позволяет создавать специализированные функции из общих, что делает код более модульным и переиспользуемым.

### Автоматическое каррирование

**Scala** поддерживает автоматическое каррирование через множественные списки параметров:**

```scala
// Функция с несколькими списками параметров автоматически каррирована
def process(x: Int)(y: Int)(z: Int): Int = x + y + z

val step1 = process(1)      // Int => Int => Int
val step2 = step1(2)         // Int => Int
val result = step2(3)        // 6

// Можно применять частично
val processWith1And2 = process(1)(2)_
processWith1And2(3)  // 6
```

Автоматическое каррирование упрощает создание специализированных функций и улучшает композицию.

### Преобразование функций

```scala
// Преобразование обычной функции в каррированную
def curry[A, B, C](f: (A, B) => C): A => B => C = {
  (a: A) => (b: B) => f(a, b)
}

// Преобразование каррированной функции в обычную
def uncurry[A, B, C](f: A => B => C): (A, B) => C = {
  (a: A, b: B) => f(a)(b)
}

// Использование
val add = (x: Int, y: Int) => x + y
val addCurried = curry(add)
val addUncurried = uncurry(addCurried)
```

Преобразование между каррированными и обычными функциями позволяет адаптировать функции к различным контекстам использования.

## Partial Functions (Частичные функции)

**Частичные функции определены только для части входных значений:**

```scala
val divide: PartialFunction[(Int, Int), Int] = {
  case (x, y) if y != 0 => x / y
}

divide.isDefinedAt((10, 0))  // false
divide.isDefinedAt((10, 2))  // true
divide((10, 2))  // 5
```

Частичные функции полезны для обработки только определенных случаев.

## Type Classes

**Type classes** позволяют добавлять поведение к типам без изменения их определения:**

```scala
// Определение type class
trait Show[A] {
  def show(a: A): String
}

// Реализации для различных типов
implicit val intShow: Show[Int] = (a: Int) => s"Int($a)"
implicit val stringShow: Show[String] = (a: String) => s"String($a)"

// Функция, использующая type class
def print[A](a: A)(implicit show: Show[A]): Unit = {
  println(show.show(a))
}

print(42)      // "Int(42)"
print("hello") // "String(hello)"
```

**Type classes** обеспечивают полиморфизм без наследования.

## Enumerations (Перечисления)

**Scala** 3 предоставляет улучшенную поддержку перечислений через ключевое слово `enum`. **Enumerations** в **Scala** 3 являются более мощными, чем в **Scala** 2, поддерживая параметры, методы и реализацию интерфейсов. Они обеспечивают типобезопасность и интеграцию с **pattern matching**, что делает их идеальными для представления фиксированного набора значений.

**Enumerations** особенно полезны для представления состояний, типов, категорий и других ограниченных наборов значений. Они предотвращают ошибки, связанные с использованием неправильных значений, так как компилятор проверяет корректность использования **enum** значений.

```scala
// Scala 3 enum
// Простое перечисление без параметров
// Каждый case является отдельным значением enum
enum Color {
  case Red, Green, Blue
}

// Enum с параметрами
// Параметры позволяют хранить дополнительные данные для каждого значения
// Это делает enum более выразительным, чем простые константы
enum Planet(mass: Double, radius: Double) {
  case Mercury extends Planet(3.303e+23, 2.4397e6)
  case Venus   extends Planet(4.869e+24, 6.0518e6)
  case Earth   extends Planet(5.976e+24, 6.37814e6)
}

// Использование
// Enum значения можно использовать как обычные значения
val color = Color.Red
val planet = Planet.Earth

// Pattern matching с enum
color match {
  case Color.Red => println("Red color")
  case Color.Green => println("Green color")
  case Color.Blue => println("Blue color")
}
```

**Enumerations** обеспечивают типобезопасные перечисления с поддержкой **pattern matching**. Компилятор может проверить полноту **pattern matching** для **enum**, что предотвращает ошибки при добавлении новых значений **enum**.

## Sealed Classes и Traits

**Sealed** классы и **traits** ограничивают наследование определенным набором классов:**

```scala
sealed trait Shape
case class Circle(radius: Double) extends Shape
case class Rectangle(width: Double, height: Double) extends Shape
case class Square(side: Double) extends Shape

def area(shape: Shape): Double = shape match {
  case Circle(r) => math.Pi * r * r
  case Rectangle(w, h) => w * h
  case Square(s) => s * s
  // Компилятор гарантирует, что все случаи обработаны
}
```

**Sealed** классы обеспечивают исчерпывающий анализ в **pattern matching**, повышая безопасность кода.

## Value Classes

**Value classes** позволяют создавать типобезопасные обертки без накладных расходов на создание объектов. **Value classes** компилятор оптимизирует, удаляя обертки на этапе компиляции, оставляя только базовое значение. Это позволяет создавать типобезопасные **API** без потери производительности, что особенно важно для примитивных типов, которые используются часто.

**Value classes** полезны для предотвращения ошибок, связанных с перепутыванием типов с одинаковым базовым типом. Например, **UserId** и **OrderId** оба могут быть **Long**, но **value classes** предотвращают их смешивание, обеспечивая типобезопасность на этапе компиляции.

```scala
// Value classes должны наследоваться от AnyVal
// Они могут иметь только один параметр val
// Компилятор оптимизирует их, избегая создания объектов
class UserId(val value: Long) extends AnyVal
class Email(val value: String) extends AnyVal

def processUser(id: UserId, email: Email): Unit = {
  // Компилятор оптимизирует value classes, избегая создания объектов
  // На уровне байт-кода используются только базовые типы (Long, String)
  println(s"User $id with email $email")
}

val userId = new UserId(123L)
val email = new Email("user@example.com")
processUser(userId, email)

// Компилятор предотвращает смешивание типов
// processUser(email, userId)  // Ошибка компиляции - неправильный порядок типов
```

**Value classes** обеспечивают типобезопасность без потери производительности. Они особенно полезны для создания типобезопасных **API**, где важно различать типы с одинаковым базовым типом, таких как идентификаторы различных сущностей или единицы измерения.

## Extractor Objects

**Extractor objects** позволяют создавать пользовательские паттерны:**

```scala
object Email {
  def apply(user: String, domain: String): String = s"$user@$domain"

  def unapply(email: String): Option[(String, String)] = {
    val parts = email.split("@")
    if (parts.length == 2) Some(parts(0), parts(1))
    else None
  }
}

val email = "user@example.com"
email match {
  case Email(user, domain) => println(s"User: $user, Domain: $domain")
  case _ => println("Invalid email")
}
```

**Extractor objects** позволяют создавать выразительные паттерны для извлечения данных из сложных структур.

## Lazy Evaluation

### Практические примеры: Traits для композиции поведения

```scala
// Traits для композиции поведения
trait Logger {
  def log(message: String): Unit = println(s"[LOG] $message")
}

trait Timestamped {
  def timestamp(): Long = System.currentTimeMillis()
}

trait Validatable[A] {
  def validate(value: A): Boolean
}

// Композиция traits
class UserService extends Logger with Timestamped with Validatable[User] {
  def validate(user: User): Boolean = {
    val isValid = user.name.nonEmpty && user.email.contains("@")
    if (!isValid) log(s"Validation failed for user: ${user.name}")
    isValid
  }

  def createUser(name: String, email: String): Option[User] = {
    val user = User(generateId(), name, email, 0)
    if (validate(user)) {
      log(s"User created: $name at ${timestamp()}")
      Some(user)
    } else None
  }

  private def generateId(): Long = timestamp()
```

## Лучшие практики

- **Неизменяемость:** предпочитать `val` и неизменяемые коллекции (`List`, `Map`, `Set` из `scala.collection.immutable`); изменяемые — только при явной необходимости.
- **Case классы:** использовать для **DTO**, моделей данных и паттерн-матчинга; не наследовать **case** классы от **case** классов; учитывать равенство по значению.
- **Паттерн-матчинг:** применять для разбора вариантов (sealed traits, case classes); избегать неполного матчинга — компилятор предупреждает для **sealed**.
- **Option вместо `null`:** использовать `Option[T]` для опциональных значений; не вызывать `.get` без проверки; предпочитать `map`, `flatMap`, `getOrElse`, `fold`.
- **Traits и композиция:** предпочитать композицию через **traits** над глубокой иерархией; использовать **self-types** и **abstract members** для зависимостей.
- **Функциональный стиль:** предпочитать методы коллекций (map, filter, `flatMap`, fold); избегать мутаций и побочных эффектов в чистой логике; использовать **for-comprehensions** для читаемости.
- **Совместимость с `Java`:** учитывать различие коллекций **Scala** и **Java**; использовать `scala.jdk.CollectionConverters` для конвертации; аннотировать для межоперабельности при необходимости.

## Решение проблем

При «value X is not a member of» проверьте импорты и наличие неявных преобразований. При медленной компиляции используйте инкрементальную компиляцию `sbt` и отключите неиспользуемые макросы. При ошибках типов в `for`-comprehension добавьте явные аннотации типов для промежуточных значений.

## Частые вопросы

**Когда использовать `val` или `var`?** — Предпочитайте `val` везде; `var` только при явной необходимости мутации (например, аккумулятор в цикле).

**Scala 2 или Scala 3?** — Для новых проектов выбирайте Scala 3: улучшенная система типов, `given`/`using` вместо `implicit`, `enum` вместо sealed traits с case objects.
