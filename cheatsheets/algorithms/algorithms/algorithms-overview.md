## Введение

Алгоритмы — фундамент **Computer Science**. Понимание алгоритмов и их сложности помогает писать эффективный код и решать задачи на собеседованиях и в практике. В данном разделе — обзор; конкретные алгоритмы находятся в подразделах: [сортировка](../sorting/), [поиск](../searching/), [графы](../graphs/), [парадигмы](../algorithmic-paradigms/).


## Классификация по сложности

### Линейные алгоритмы O(n)
Последовательный перебор за один проход. Пример — линейный поиск.

### Логарифмические алгоритмы O(log n)
Двоичный поиск в отсортированном массиве — классический пример.

### Квадратичные алгоритмы O(n²)
Пузырьковая сортировка, простые вложенные циклы.

### Другие классы
O(n log n) — эффективные сортировки; O(2^n), O(n!) — экспоненциальные и факториальные (избегать для больших n).


## Классификация по подходу

**Итеративные** — циклы. **Рекурсивные** — вызов самой себя с базовым случаем. Оба подхода взаимозаменяемы; выбор по читаемости и ограничениям стека.

## Решение проблем

| Симптом | Возможная причина | Решение |
|--------|-------------------|---------|
| Решение не укладывается по времени | Сложность выше допустимой (напр. O(n²) вместо O(n log n)) | Оценить сложность; см. [[problem-solving-overview#анализ-сложности|Анализ сложности]]; выбрать другой алгоритм или структуру данных |
| Переполнение стека при рекурсии | Слишком глубокая рекурсия | Переписать итеративно или увеличить лимит; для DP — табуляция вместо мемоизации |
| Неочевидно, какой алгоритм применить | Незнание типов задач и парадигм | См. [[problem-solving-overview#стратегии-решения|Стратегии решения]]; определять по признакам (подзадачи, оптимальная подструктура и т.д.) |


## Частые вопросы

**Как быстро оценить сложность алгоритма?** Считать вложенные циклы по размеру ввода, рекурсию — по дереву вызовов и количеству подзадач. Линейный проход — O(n), бинарный поиск — O(log n), два вложенных цикла по n — O(n²). Подробнее в разделе [[problem-solving-overview|Решение задач]].

**Где практиковать алгоритмы?** LeetCode, HackerRank, Codewars; начинать с простых задач по темам (массивы, строки, графы, DP), затем увеличивать сложность.

**Как выбрать парадигму: жадный алгоритм или DP?** Если локально оптимальный выбор ведёт к глобальному оптимуму — жадный. Если подзадачи перекрываются и нужно комбинировать их решения — DP. Проверка на контрпримерах помогает отсечь неверный жадный выбор.
