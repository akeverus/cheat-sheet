## Описание алгоритма

Задача — округлить число до ближайшей сотни. Примеры: 99 100, 200.2 300, 400 400, 150 200, 149 100. В зависимости от требований используют округление вверх (до большей сотни), вниз или до ближайшей.

### Примеры

99 100; 200.2 300; 400 400; 150 200; 149 100.

## Реализация на Java

### Реализация

`Math.ceil(input)` даёт наименьшее целое ≥ аргумента (например, для 200.2 получится 201). К результату прибавляют 99 и делят на 100 с целочисленным делением — так отсекается дробная часть. Произведение частного на 100 даёт округление вверх до сотни.

```java
// Округление вверх до ближайшей сотни: ceil + сдвиг 99 и целочисленное деление на 100
static long round(double input) {
    long i = (long) Math.ceil(input);
    return ((i + 99) / 100) * 100;
}
```

Проверка в тесте:

```java
// Проверка округления вверх: 99→100, 200.2→300, 400 без изменений
@Test
public void givenInput_whenRound_thenRoundUpToTheNearestHundred() {
    assertEquals("Rounded up to hundred", 100, RoundUpToHundred.round(99));
    assertEquals("Rounded up to three hundred", 300, RoundUpToHundred.round(200.2));
    assertEquals("Returns same rounded value", 400, RoundUpToHundred.round(400));
}
```

### Альтернативная реализация с Math.round()

Округление до ближайшей сотни: делим на 100, округляем, умножаем на 100.

```java
// Округление до ближайшей сотни через Math.round
static long roundAlternative(double input) {
    return Math.round(input / 100.0) * 100;
}
```

### Реализация с округлением вниз

Используем `Math.floor` и целочисленное деление на 100.

```java
// Округление вниз до сотни: floor и деление на 100
static long roundDown(double input) {
    long i = (long) Math.floor(input);
    return (i / 100) * 100;
}
```

### Реализация с округлением до ближайшего

Та же формула, что и в альтернативе: деление на 100, `Math.round`, умножение на 100.

```java
// До ближайшей сотни (половины округляются вверх)
static long roundNearest(double input) {
    return Math.round(input / 100.0) * 100;
}
```

## Варианты задачи

### Вариант 1: Округление до произвольного разряда

Разряд задаётся степенью 10; формула та же: деление на множитель, округление, умножение.

```java
// Округление до 10^place (сотни, тысячи и т.д.)
static long roundToNearest(long input, int place) {
    long multiplier = (long) Math.pow(10, place);
    return Math.round((double) input / multiplier) * multiplier;
}
```

### Вариант 2: Округление до ближайшей тысячи

Тот же приём, что для сотни: сдвиг 999 и целочисленное деление на 1000.

```java
// Округление вверх до тысячи
static long roundToNearestThousand(double input) {
    long i = (long) Math.ceil(input);
    return ((i + 999) / 1000) * 1000;
}
```

### Вариант 3: Округление с указанием направления

Один метод с перечислением: вверх, вниз или до ближайшего.

```java
// Направление округления: вверх, вниз, до ближайшего
public enum RoundDirection {
    UP, DOWN, NEAREST
}

static long roundWithDirection(double input, RoundDirection direction) {
    switch (direction) {
        case UP:
            long i = (long) Math.ceil(input);
            return ((i + 99) / 100) * 100;
        case DOWN:
            long j = (long) Math.floor(input);
            return (j / 100) * 100;
        case NEAREST:
            return Math.round(input / 100.0) * 100;
        default:
            return Math.round(input / 100.0) * 100;
    }
}
```

## Реализация на Kotlin

### Основная реализация

Те же формулы: округление вверх (ceil + 99/100), до ближайшего (round), вниз (floor).

```kotlin
// Округление вверх до сотни
fun roundK(input: Double): Long {
    val i = Math.ceil(input).toLong()
    return ((i + 99) / 100) * 100
}

fun roundAlternativeK(input: Double): Long = Math.round(input / 100.0) * 100

fun roundDownK(input: Double): Long {
    val i = Math.floor(input).toLong()
    return (i / 100) * 100
}

fun roundNearestK(input: Double): Long = Math.round(input / 100.0) * 100
```

### Варианты задачи

```kotlin
// До произвольного разряда 10^place и вверх до тысячи
fun roundToNearestK(input: Long, place: Int): Long {
    val multiplier = Math.pow(10.0, place.toDouble()).toLong()
    return Math.round(input.toDouble() / multiplier) * multiplier
}

fun roundToNearestThousandK(input: Double): Long {
    val i = Math.ceil(input).toLong()
    return ((i + 999) / 1000) * 1000
}
```

### Округление с указанием направления

```kotlin
// Перечисление направления и единый метод when
enum class RoundDirectionK {
    UP, DOWN, NEAREST
}

fun roundWithDirectionK(input: Double, direction: RoundDirectionK): Long {
    return when (direction) {
        RoundDirectionK.UP -> {
            val i = Math.ceil(input).toLong()
            ((i + 99) / 100) * 100
        }
        RoundDirectionK.DOWN -> {
            val i = Math.floor(input).toLong()
            (i / 100) * 100
        }
        RoundDirectionK.NEAREST -> {
            Math.round(input / 100.0) * 100
        }
    }
}
```

### Пример использования

```kotlin
fun main() {
    println(roundK(99.0)) // 100
    println(roundK(200.2)) // 300
    println(roundK(400.0)) // 400
    println(roundNearestK(150.0)) // 200
    println(roundNearestK(149.0)) // 100
}
```

## Сложность

Все варианты имеют константную временную и пространственную сложность `O(1)`: несколько арифметических операций и вызовов `Math`.

## Особенности

Алгоритм прост, выполняется за константное время и легко обобщается на другие разряды (тысячи, десятки) заменой множителя и сдвига.

## Применение

Округление до сотни (или другого разряда) применяется в финансовых расчётах, отчётности, статистике, визуализации и при агрегации данных, когда нужны «круглые» числа.

## Когда использовать

Подход с `Math.ceil()` удобен, когда нужно именно округление вверх до сотни и работа идёт с неотрицательными числами. `Math.round()` подходит, когда нужно округление до ближайшей сотни (половинки обычно округляются вверх). Для округления вниз используют `Math.floor()` и целочисленное деление.

## Лучшие практики

Семантику стоит зафиксировать явно: округление вверх (`roundUpToHundred`), вниз (`roundDownToHundred`) или до ближайшего (`roundToNearestHundred`) — и давать методам соответствующие имена. Результат лучше возвращать в `long`, чтобы избежать переполнения при больших значениях; для денег уместны `BigDecimal` и масштабирование. Поведение для отрицательных чисел нужно определить (симметрично по модулю или отдельно) и покрыть тестами. При работе с `double` учитывайте погрешность представления; при необходимости используйте допуск или целочисленную арифметику. Магические числа 99 и 100 лучше вынести в константы с поясняющими комментариями.

## Решение проблем

| Симптом | Возможная причина | Решение |
|---------|-------------------|---------|
| Неверный результат для 150 | Используется округление вверх вместо «до ближайшего» | Для «до ближайшего» применять `Math.round(input/100.0)*100` |
| Переполнение при больших числах | Результат в `int` или умножение в `int` | Использовать `long` для промежуточных и итоговых значений |
| Ошибки для отрицательных чисел | Не учтена семантика для отрицательных | Явно задать правило (например, round к нулю) и протестировать |
| Погрешность для 99.999... | Представление `double` | Округлять после приведения к целому или использовать допуск |

## Частые вопросы

**Почему в формуле округления вверх используется 99?** Сдвиг на 99 при целочисленном делении на 100 даёт эффект «округления вверх»: любое число от 1 до 99 после (i+99)/100 даёт 1, от 100 до 199 — 2 и т.д.

**Чем округление вверх до сотни отличается от «до ближайшего»?** Вверх — всегда к большей сотне (149 200). До ближайшего — 149 100, 150 200 по правилам арифметического округления.

**Как округлить до тысяч?** Тот же приём: для вверх — `(long)Math.ceil(input)`, затем `((i+999)/1000)*1000`; для ближайшего — `Math.round(input/1000.0)*1000`.

## Заключение

В документе разобрано округление числа до ближайшей сотни: вверх через `Math.ceil()` и целочисленное деление, вниз через `Math.floor()`, до ближайшего через `Math.round()`. Те же идеи переносятся на тысячи и произвольный разряд.
