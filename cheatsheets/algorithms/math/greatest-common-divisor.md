# Наибольший общий делитель (`Greatest Common Divisor`)

**Дата последнего обновления:** 2026-02-06

НОД двух целых чисел — наибольшее положительное целое, делящее оба числа без остатка. В документе описаны три подхода: перебор делителей (грубая сила), алгоритм Евклида (рекомендуется) и бинарный алгоритм Штейна.

## Описание алгоритма

В математике НОД двух целых чисел, не равных нулю, - это наибольшее положительное целое число, на которое каждое из целых чисел делится без остатка.

Ниже — три подхода и их реализация на `Java` и Kotlin.

### Примеры

НОД(12, 18) = 6, НОД(48, 18) = 6, НОД(17, 5) = 1 (взаимно простые числа).

## Реализация на Java

### Подход 1: Грубая сила (Java)

Перебор делителей от 1 до min(n1, n2); последний общий делитель — НОД. Сложность O(min(n1, n2)).

```java
// Грубая сила: перебор делителей от 1 до min(n1,n2)
int gcdByBruteForce(int n1, int n2) {
    int gcd = 1;
    for (int i = 1; i <= n1 && i <= n2; i++) {
        if (n1 % i == 0 && n2 % i == 0) {
            gcd = i;
        }
    }
    return gcd;
}
```

Оптимизация: итерация от min вниз к 1 с ранним выходом при первом общем делителе.

```java
// Обратный порядок: от min к 1, return при первом совпадении
int gcdByBruteForceOptimized(int n1, int n2) {
    int gcd = 1;
    int min = Math.min(Math.abs(n1), Math.abs(n2));
    
    for (int i = min; i >= 1; i--) {
        if (n1 % i == 0 && n2 % i == 0) {
            return i;
        }
    }
    return gcd;
}
```

## Подход 2: Алгоритм Евклида

Алгоритм Евклида: НОД не меняется при замене (a, b) на (b, a mod b); базовый случай — b = 0, тогда НОД = a. Используем остаток от деления вместо многократного вычитания. Сложность O(log(min(n1, n2))).

```java
// Рекурсивный Евклид: gcd(n2, n1 % n2) до n2==0
int gcdByEuclidsAlgorithm(int n1, int n2) {
    if (n2 == 0) {
        return n1;
    }
    return gcdByEuclidsAlgorithm(n2, n1 % n2);
}
```

### Итеративная версия

Без рекурсии: цикл с обменом (n1, n2) ← (n2, n1 % n2). В конце берём модуль для отрицательных.

```java
// Итеративный Евклид: без стека вызовов
int gcdByEuclidsAlgorithmIterative(int n1, int n2) {
    while (n2 != 0) {
        int temp = n2;
        n2 = n1 % n2;
        n1 = temp;
    }
    return Math.abs(n1);
}
```

### Версия с обработкой отрицательных чисел

Сначала приводим аргументы к абсолютным значениям — НОД по определению неотрицателен.

```java
// С явным приведением к |n1|, |n2|
int gcdByEuclidsAlgorithmSafe(int n1, int n2) {
    n1 = Math.abs(n1);
    n2 = Math.abs(n2);
    
    while (n2 != 0) {
        int temp = n2;
        n2 = n1 % n2;
        n1 = temp;
    }
    return n1;
}
```

## Подход 3: Алгоритм Штейна

Алгоритм Штейна (бинарный НОД) использует сдвиги и вычитание. Идея: gcd(2a,2b)=2·gcd(a,b); для чётного и нечётного — делить только чётное на 2; для двух нечётных — gcd(n1,n2)=gcd((n1−n2)/2, n2). Сложность O((log n)²). Подходит для больших чисел и частых чётных.

```java
// Бинарный НОД: сдвиги и вычитание, без деления
int gcdBySteinsAlgorithm(int n1, int n2) {
    if (n1 == 0) {
        return n2;
    }
    
    if (n2 == 0) {
        return n1;
    }
    
    int n;
    for (n = 0; ((n1 | n2) & 1) == 0; n++) {
        n1 >>= 1;
        n2 >>= 1;
    }
    
    while ((n1 & 1) == 0) {
        n1 >>= 1;
    }
    
    do {
        while ((n2 & 1) == 0) {
            n2 >>= 1;
        }
        
        if (n1 > n2) {
            int temp = n1;
            n1 = n2;
            n2 = temp;
        }
        
        n2 = (n2 - n1);
    } while (n2 != 0);
    
    return n1 << n;
}
```

## Сравнение подходов

| Подход | Временная сложность | Пространственная сложность | Когда использовать |
|--------|---------------------|----------------------------|-------------------|
| Грубая сила | O(min(n1, n2)) | O(1) | Малые числа |
| Алгоритм Евклида | O(log(min(n1, n2))) | O(1) | Общий случай |
| Алгоритм Штейна | O((log n)²) | O(1) | Большие числа |

## Сложность

Грубая сила — O(min(n1, n2)) по времени, O(1) по памяти. Евклид — O(log(min(n1, n2))) по времени; итеративная версия O(1) по памяти, рекурсивная — O(log(min(n1, n2))) из-за стека. Штейн — O((log n)²) по времени, O(1) по памяти.

## Особенности

Алгоритм Евклида даёт лучший баланс простоты и скорости. Грубая сила самая наглядная, но медленная. Штейн удобен для очень больших чисел и при частых чётных аргументах.

## Применение

НОД используется в криптографии (в том числе RSA), при приведении дробей, для вычисления НОК по формуле |a·b|/НОД(a,b), в теории чисел и во многих алгоритмах.

## Варианты задачи

### Вариант 1: НОД для массива чисел

Последовательное применение НОД к элементам массива.

```java
// НОД(a1, a2, ..., an) = gcd(gcd(...gcd(a1,a2), ...), an)
public int gcdArray(int[] numbers) {
    int result = numbers[0];
    for (int i = 1; i < numbers.length; i++) {
        result = gcdByEuclidsAlgorithm(result, numbers[i]);
    }
    return result;
}
```

### Вариант 2: Расширенный алгоритм Евклида

Возвращает (gcd, x, y) такие, что ax + by = gcd; полезно для решения линейных диофантовых уравнений и обратного по модулю.

```java
// Расширенный Евклид: коэффициенты Безу
public class ExtendedEuclidean {
    public static int[] extendedGcd(int a, int b) {
        if (b == 0) {
            return new int[]{a, 1, 0};
        }
        
        int[] result = extendedGcd(b, a % b);
        int gcd = result[0];
        int x1 = result[1];
        int y1 = result[2];
        
        int x = y1;
        int y = x1 - (a / b) * y1;
        
        return new int[]{gcd, x, y};
    }
}
```

### Вариант 3: НОД с использованием BigInteger

Для чисел вне диапазона `long` используйте `BigInteger.gcd()`.

```java
// Встроенный НОД для произвольно больших чисел
public BigInteger gcdBigInteger(BigInteger n1, BigInteger n2) {
    return n1.gcd(n2);
}
```

## Реализация на Kotlin

### Подход 1: Грубая сила (Kotlin)

```kotlin
// Перебор делителей (аналог Java)
fun gcdByBruteForceK(n1: Int, n2: Int): Int {
    var gcd = 1
    for (i in 1..minOf(n1, n2)) {
        if (n1 % i == 0 && n2 % i == 0) {
            gcd = i
        }
    }
    return gcd
}
```

### Подход 2: Алгоритм Евклида

```kotlin
// Итеративный и рекурсивный Евклид
fun gcdByEuclideanAlgorithmK(n1: Int, n2: Int): Int {
    var a = Math.abs(n1)
    var b = Math.abs(n2)
    while (b != 0) {
        val temp = b
        b = a % b
        a = temp
    }
    return a
}

fun gcdByEuclideanAlgorithmRecursiveK(n1: Int, n2: Int): Int {
    if (n2 == 0) {
        return Math.abs(n1)
    }
    return gcdByEuclideanAlgorithmRecursiveK(n2, n1 % n2)
}
```

### Подход 3: Алгоритм Штейна

```kotlin
// Бинарный НОД (сдвиги и вычитание)
fun gcdBySteinAlgorithmK(n1: Int, n2: Int): Int {
    if (n1 == 0) return n2
    if (n2 == 0) return n1
    
    var num1 = n1
    var num2 = n2
    var n = 0
    
    while (((num1 or num2) and 1) == 0) {
        num1 = num1 shr 1
        num2 = num2 shr 1
        n++
    }
    
    while ((num1 and 1) == 0) {
        num1 = num1 shr 1
    }
    
    do {
        while ((num2 and 1) == 0) {
            num2 = num2 shr 1
        }
        
        if (num1 > num2) {
            val temp = num1
            num1 = num2
            num2 = temp
        }
        
        num2 -= num1
    } while (num2 != 0)
    
    return num1 shl n
}
```

### НОД с использованием BigInteger

```kotlin
// BigInteger.gcd() для больших чисел
import java.math.BigInteger

fun gcdBigIntegerK(n1: BigInteger, n2: BigInteger): BigInteger {
    return n1.gcd(n2)
}
```

### Пример использования

```kotlin
fun main() {
    println(gcdByBruteForceK(12, 18)) // 6
    println(gcdByEuclideanAlgorithmK(48, 18)) // 6
    println(gcdBySteinAlgorithmK(100, 25)) // 25
    println(gcdByEuclideanAlgorithmRecursiveK(17, 5)) // 1
}
```

## Когда использовать

Грубая сила уместна только для очень малых чисел. В общем случае используйте алгоритм Евклида (итеративный предпочтительнее из-за отсутствия риска переполнения стека). Алгоритм Штейна имеет смысл для очень больших чисел и когда много чётных аргументов.

## Лучшие практики

Для продакшена выбирайте итеративный алгоритм Евклида. Учитывайте нули: НОД(a, 0) = |a|, НОД(0, b) = |b|; для отрицательных используйте абсолютные значения. Для чисел вне диапазона `long` — `BigInteger.gcd()`. В тестах проверяйте пары (0, n), (n, 0), (1, n), (n, n), взаимно простые (17, 5).

## Решение проблем

| Симптом | Возможная причина | Решение |
|---------|-------------------|---------|
| StackOverflowError при рекурсии | Слишком большие числа для рекурсивного Евклида | Использовать итеративную версию или BigInteger |
| Отрицательный результат | НОД по определению неотрицателен | Привести аргументы к Math.abs или использовать версию Safe |
| Переполнение при умножении для НОК | a*b не помещается в long | Считать НОК через (a/gcd)*b или BigInteger |

## Частые вопросы

**Почему итеративный Евклид предпочтительнее рекурсивного?** Рекурсия потребляет стек; при больших числах возможен StackOverflowError. Итеративная версия использует O(1) памяти.

**Как вести себя с нулём?** По определению НОД(a, 0) = НОД(0, a) = |a|. В коде часто обрабатывают нули в начале и возвращают второй аргумент по модулю.

**Когда использовать алгоритм Штейна?** Когда работаете с очень большими целыми и многие из них чётные (бинарный НОД эффективно выносит двойки); в типичных задачах достаточно Евклида.

## Заключение

В документе рассмотрены три способа вычисления НОД в `Java` и Kotlin: грубая сила, алгоритм Евклида и алгоритм Штейна. Рекомендуется итеративный алгоритм Евклида; для произвольно больших чисел — `BigInteger.gcd()`.
