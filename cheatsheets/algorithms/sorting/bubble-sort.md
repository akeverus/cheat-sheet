# Пузырьковая сортировка (Bubble Sort)

Пузырьковая сортировка (`Bubble Sort`) — один из самых простых алгоритмов сортировки, который сравнивает и меняет местами соседние элементы массива до полной сортировки. Алгоритм получил своё название из-за того, что меньшие элементы «всплывают» наверх списка, подобно пузырькам воздуха в воде. Несмотря на простоту реализации, пузырьковая сортировка имеет квадратичную временную сложность `O(n²)` в среднем и худшем случаях, что делает её неэффективной для больших массивов данных. Однако алгоритм имеет линейную сложность `O(n)` в лучшем случае, когда массив уже отсортирован, и может быть оптимизирован для раннего завершения при отсутствии обменов. Алгоритм является стабильным и выполняет сортировку на месте, не требуя дополнительной памяти. В этом документе рассматриваются принципы работы пузырьковой сортировки, её реализация на `Java` и `Kotlin`, оптимизации и практические рекомендации по применению.

## Описание алгоритма

Это один из самых простых алгоритмов сортировки; основная идея состоит в том, чтобы продолжать менять местами соседние элементы массива, если они находятся в неправильном порядке, до тех пор, пока коллекция не будет отсортирована.

Мелкие элементы «всплывают» в верхней части списка по мере того, как мы итерируем структуру данных. Следовательно, этот метод известен как пузырьковая сортировка.

Поскольку сортировка выполняется путем замены, мы можем сказать, что она выполняет сортировку на месте.

Кроме того, если два элемента имеют одинаковые значения, порядок результирующих данных будет сохранен, что делает сортировку стабильной.

Как упоминалось ранее, для сортировки массива мы перебираем его, сравнивая соседние элементы и при необходимости меняя их местами. Для массива размера n мы выполняем n — 1 таких итераций.

### Пример работы алгоритма

Давайте рассмотрим пример, чтобы понять методологию. Мы хотели бы отсортировать массив в порядке возрастания:

```text
4 2 1 6 3 5
```

Мы начинаем первую итерацию со сравнения 4 и 2; они определённо не в надлежащем порядке. Замена приведёт к:

```text
[2 4] 1 6 3 5
```

Теперь повторяем то же самое для 4 и 1:

```text
2 [1 4] 6 3 5
```

Продолжаем до конца:

```text
2 1 [4 6] 3 5
2 1 4 [3 6] 5
2 1 4 3 [5 6]
```

Как мы видим, в конце первой итерации мы получили последний элемент на своём законном месте. Теперь всё, что нам нужно сделать, это повторить ту же процедуру в следующих итерациях. Кроме того, мы исключаем элементы, которые уже отсортированы, что оптимизирует работу алгоритма.

Во второй итерации мы будем перебирать весь массив, кроме последнего элемента. Точно так же для 3-й итерации мы опускаем последние 2 элемента. Как правило, для k-й итерации мы итерируем до индекса `n-k` (исключая). В конце `n-1` итераций мы получим отсортированный массив. Это гарантирует, что каждый элемент будет на своём правильном месте после завершения всех итераций.

## Реализация на Java

Реализация пузырьковой сортировки на `Java` демонстрирует простоту алгоритма и его основные принципы работы. Рассмотрим базовую реализацию с использованием подхода `Java` 8 и традиционный императивный подход.

Давайте реализуем сортировку для примера массива, который мы обсуждали, используя подход `Java` 8:

```java
// Пузырьковая сортировка: сравнение и обмен соседних элементов до полной упорядоченности (O(n²))
void bubbleSort(Integer[] arr) {
    int n = arr.length;
    IntStream.range(0, n - 1)
        .flatMap(i -> IntStream.range(1, n - i))
        .forEach(j -> {
            if (arr[j - 1] > arr[j]) {
                int temp = arr[j];
                arr[j] = arr[j - 1];
                arr[j - 1] = temp;
            }
        });
}
```

Эта реализация использует потоки `Java` 8 для создания вложенных циклов и выполнения сравнений и обменов. Однако для лучшей производительности рекомендуется использовать традиционный императивный подход с вложенными циклами `for`.

И быстрый тест `JUnit` для алгоритма:

```java
// Тест для проверки корректности работы пузырьковой сортировки
@Test
void whenSortedWithBubbleSort_thenGetSortedArray() {
    // Исходный неотсортированный массив
    Integer[] array = { 2, 1, 4, 6, 3, 5 };
    // Ожидаемый результат после сортировки
    Integer[] sortedArray = { 1, 2, 3, 4, 5, 6 };
    // Создаём экземпляр класса с методом сортировки
    BubbleSort bubbleSort = new BubbleSort();
    // Выполняем сортировку
    bubbleSort.bubbleSort(array);
    // Проверяем, что массив отсортирован корректно
    assertArrayEquals(array, sortedArray);
}
```

Этот тест проверяет корректность работы алгоритма на примере массива с различными значениями. Алгоритм должен правильно отсортировать массив в порядке возрастания.

## Реализация на Kotlin

В `Kotlin` алгоритм `Bubble Sort` может быть реализован следующим образом:

```kotlin
// Базовая реализация пузырьковой сортировки на Kotlin
fun bubbleSort(arr: IntArray) {
    val n = arr.size // Размер массива
    // Внешний цикл: n-1 итераций (после каждой итерации наибольший элемент "всплывает" в конец)
    for (i in 0 until n - 1) {
        // Внутренний цикл: сравниваем соседние элементы, уменьшаем диапазон на каждой итерации
        for (j in 1 until n - i) {
            // Если левый элемент больше правого, меняем их местами
            if (arr[j - 1] > arr[j]) {
                val temp = arr[j] // Временная переменная для обмена
                arr[j] = arr[j - 1]
                arr[j - 1] = temp
            }
        }
    }
}
```

Эта реализация использует вложенные циклы `for` для сравнения и обмена соседних элементов. Синтаксис `Kotlin` делает код более читаемым и лаконичным по сравнению с `Java`.

Использование:

```kotlin
// Пример использования базовой версии пузырьковой сортировки
fun main() {
    // Исходный неотсортированный массив
    val array = intArrayOf(2, 1, 4, 6, 3, 5)
    // Выполняем сортировку
    bubbleSort(array)
    // Выводим отсортированный массив
    println(array.contentToString()) // [1, 2, 3, 4, 5, 6]
}
```

### Оптимизированная версия

Оптимизированная версия использует флаг для раннего завершения, если массив уже отсортирован:

```kotlin
// Оптимизированная версия пузырьковой сортировки с ранним завершением
// Использует флаг для определения, были ли выполнены обмены в текущей итерации
fun optimizedBubbleSort(arr: IntArray) {
    val n = arr.size // Размер массива
    var i = 0 // Счётчик итераций внешнего цикла
    var swapNeeded = true // Флаг: нужны ли обмены в текущей итерации

    // Продолжаем, пока есть итерации и нужны обмены
    while (i < n - 1 && swapNeeded) {
        swapNeeded = false // Сбрасываем флаг перед началом итерации
        // Внутренний цикл: сравниваем соседние элементы
        for (j in 1 until n - i) {
            // Если левый элемент больше правого, меняем их местами
            if (arr[j - 1] > arr[j]) {
                // Идиоматичный обмен в Kotlin с использованием функции also
                arr[j] = arr[j - 1].also { arr[j - 1] = arr[j] }
                swapNeeded = true // Отмечаем, что был выполнен обмен
            }
        }
        // Если обменов не было, массив уже отсортирован - выходим
        if (!swapNeeded) break
        i++ // Переходим к следующей итерации
    }
}
```

Эта версия использует идиоматичный синтаксис `Kotlin` для обмена элементов с помощью функции `also`, что делает код более элегантным и читаемым.

Использование:

```kotlin
// Пример использования оптимизированной версии пузырьковой сортировки
fun main() {
    // Исходный неотсортированный массив
    val array = intArrayOf(2, 1, 4, 6, 3, 5)
    // Выполняем оптимизированную сортировку
    optimizedBubbleSort(array)
    // Выводим отсортированный массив
    println(array.contentToString()) // [1, 2, 3, 4, 5, 6]
}
```

## Оптимизация

Тщательно проанализировав решение, мы можем увидеть, что если в итерации не найдено ни одного обмена, нам не нужно продолжать итерацию. Это важная оптимизация, которая может значительно улучшить производительность алгоритма для уже отсортированных или почти отсортированных массивов.

В случае рассмотренного ранее примера после 2-й итерации получаем:

```text
1 2 3 4 5 6
```

В третьей итерации нам не нужно менять местами никакие пары соседних элементов. Таким образом, мы можем пропустить все оставшиеся итерации, что экономит время и ресурсы. Это особенно полезно для массивов, которые уже частично отсортированы или становятся отсортированными в процессе выполнения алгоритма.

В случае отсортированного массива в самой первой итерации подкачка не понадобится — значит, мы можем остановить выполнение. Это наилучший сценарий, и временная сложность алгоритма составляет `O(n)`, что делает оптимизированную версию эффективной для таких случаев.

Теперь давайте реализуем оптимизированное решение:

```java
// Оптимизированная версия пузырьковой сортировки с ранним завершением
// Использует флаг для определения, были ли выполнены обмены в текущей итерации
public void optimizedBubbleSort(Integer[] arr) {
    int i = 0; // Счётчик итераций внешнего цикла
    int n = arr.length; // Размер массива
    boolean swapNeeded = true; // Флаг: нужны ли обмены в текущей итерации

    // Продолжаем, пока есть итерации и нужны обмены
    while (i < n - 1 && swapNeeded) {
        swapNeeded = false; // Сбрасываем флаг перед началом итерации
        // Внутренний цикл: сравниваем соседние элементы
        for (int j = 1; j < n - i; j++) {
            // Если левый элемент больше правого, меняем их местами
            if (arr[j - 1] > arr[j]) {
                int temp = arr[j - 1]; // Временная переменная для обмена
                arr[j - 1] = arr[j];
                arr[j] = temp;
                swapNeeded = true; // Отмечаем, что был выполнен обмен
            }
        }
        // Если обменов не было, массив уже отсортирован - выходим
        if(!swapNeeded) {
            break;
        }
        i++; // Переходим к следующей итерации
    }
}
```

Эта оптимизированная версия использует флаг `swapNeeded` для отслеживания того, были ли выполнены какие-либо обмены в текущей итерации. Если обменов не было, это означает, что массив уже отсортирован, и мы можем завершить выполнение алгоритма досрочно.

Давайте проверим вывод для оптимизированного алгоритма:

```java
@Test
void givenIntegerArray_whenSortedWithOptimizedBubbleSort_thenGetSortedArray() {
    Integer[] array = { 2, 1, 4, 6, 3, 5 };
    Integer[] sortedArray = { 1, 2, 3, 4, 5, 6 };
    BubbleSort bubbleSort = new BubbleSort();
    bubbleSort.optimizedBubbleSort(array);
    assertArrayEquals(array, sortedArray);
}
```

Этот тест проверяет корректность работы оптимизированной версии алгоритма и подтверждает, что она правильно сортирует массив, используя раннее завершение для улучшения производительности.

## Сложность

Как мы видим, для среднего и наихудшего случая временная сложность составляет `O(n²)`. Это происходит потому, что алгоритм выполняет вложенные циклы, где внешний цикл проходит `n — 1` раз, а внутренний цикл проходит от `1` до `n — i` раз для каждой итерации внешнего цикла. В результате общее количество сравнений составляет примерно `n * (n — 1) / 2`, что даёт квадратичную сложность.

Кроме того, пространственная сложность даже в худшем случае составляет `O(1)`, так как алгоритм пузырьковой сортировки не требует дополнительной памяти, а сортировка происходит в исходном массиве. Это делает алгоритм эффективным по использованию памяти, что может быть важно для систем с ограниченными ресурсами.

### Временная сложность

Временная сложность пузырьковой сортировки варьируется в зависимости от состояния входных данных. В худшем и среднем случаях, когда массив находится в обратном порядке или элементы расположены случайным образом, временная сложность составляет `O(n²)`. Это происходит потому, что алгоритм должен выполнить максимальное количество сравнений и обменов для сортировки массива.

В лучшем случае, когда массив уже отсортирован, временная сложность составляет `O(n)` для оптимизированной версии алгоритма. Это происходит потому, что алгоритм может завершить выполнение после первого прохода, когда обнаруживает, что никаких обменов не требуется. Однако для неоптимизированной версии даже в лучшем случае сложность остаётся `O(n²)`, так как алгоритм всё равно выполняет все итерации независимо от состояния массива.

### Пространственная сложность

Пространственная сложность пузырьковой сортировки составляет `O(1)` во всех случаях, так как сортировка выполняется на месте. Алгоритм использует только постоянное количество дополнительной памяти для хранения временных переменных, таких как индексы циклов и флаги, независимо от размера входного массива. Это делает алгоритм эффективным по использованию памяти и подходящим для систем с ограниченными ресурсами.

## Применение

Алгоритм популярен в компьютерной графике из-за его способности обнаруживать небольшие ошибки при сортировке. Например, в почти отсортированном массиве нужно поменять местами только два элемента, чтобы получить полностью отсортированный массив. Пузырьковая сортировка может исправить такие ошибки (т. е. отсортировать этот массив) за линейное время, что делает её полезной для таких случаев.

Однако для большинства практических применений пузырьковая сортировка не является оптимальным выбором из-за её квадратичной временной сложности. Алгоритм в основном используется в образовательных целях для демонстрации основных концепций сортировки и понимания работы алгоритмов сравнения. Для продакшена предпочтительнее использовать более эффективные алгоритмы, такие как быстрая сортировка, сортировка слиянием или библиотечные методы, такие как `Arrays.sort()`.

## Лучшие практики

При использовании пузырьковой сортировки важно следовать нескольким лучшим практикам. Используйте алгоритм только для учебных целей или очень малых массивов (`n < 10`); для продакшена предпочтите `QuickSort`, `MergeSort` или библиотечные методы (`Arrays.sort`). Это гарантирует оптимальную производительность для реальных приложений.

При отсутствии обменов за проход массив уже отсортирован — прерывайте цикл (флаг `swapped`); это даёт `O(n)` в лучшем случае. Эта оптимизация может значительно улучшить производительность для уже отсортированных или почти отсортированных массивов.

При равенстве элементов используйте `>=` для сравнения соседних, чтобы не менять местами равные — сохраняется стабильность сортировки. Это важно для приложений, где относительный порядок равных элементов имеет значение.

Граничные случаи, такие как пустой массив или один элемент, не требуют итераций; проверяйте длину перед циклом. Это предотвращает ненужные вычисления и улучшает производительность алгоритма.

При тестировании проверьте уже отсортированный массив, обратный порядок, дубликаты, один элемент. Это поможет убедиться, что реализация корректно обрабатывает все граничные случаи и различные состояния входных данных.

## Решение проблем

При работе с пузырьковой сортировкой могут возникать различные проблемы. Если алгоритм работает медленнее, чем ожидалось, убедитесь, что вы используете оптимизированную версию с ранним завершением. Для больших массивов данных пузырьковая сортировка может быть очень медленной из-за квадратичной временной сложности, поэтому рассмотрите возможность использования более эффективных алгоритмов, таких как быстрая сортировка или сортировка слиянием.

Если возникают проблемы с производительностью на реальных данных, помните, что пузырьковая сортировка эффективна только для очень малых массивов или уже отсортированных данных. Для типичных случаев использования предпочтительнее использовать алгоритмы с лучшей временной сложностью, такие как быстрая сортировка (`O(n log n)` в среднем случае) или сортировка слиянием (`O(n log n)` во всех случаях).

Если алгоритм нестабилен и это вызывает проблемы, убедитесь, что вы используете правильный оператор сравнения. Для сохранения стабильности используйте `>=` вместо `>` при сравнении элементов, чтобы не менять местами равные элементы.

При проблемах с памятью помните, что пузырьковая сортировка имеет пространственную сложность `O(1)`, что делает её эффективной по использованию памяти. Однако если вам нужна лучшая производительность, рассмотрите возможность использования других алгоритмов, которые могут требовать дополнительной памяти, но работать быстрее.

## Частые вопросы

**Вопрос:** Почему пузырьковая сортировка имеет квадратичную временную сложность?

**Ответ:** Пузырьковая сортировка имеет квадратичную временную сложность `O(n²)` в среднем и худшем случаях, потому что алгоритм выполняет вложенные циклы. Внешний цикл проходит `n — 1` раз, а внутренний цикл проходит от `1` до `n — i` раз для каждой итерации внешнего цикла. В результате общее количество сравнений составляет примерно `n * (n — 1) / 2`, что даёт квадратичную сложность.

**Вопрос:** Когда следует использовать пузырьковую сортировку?

**Ответ:** Пузырьковая сортировка следует использовать только для учебных целей или очень малых массивов (`n < 10`). Для продакшена предпочтительнее использовать более эффективные алгоритмы, такие как быстрая сортировка, сортировка слиянием или библиотечные методы, такие как `Arrays.sort()`. Алгоритм также может быть полезен для почти отсортированных массивов, где требуется исправить только несколько ошибок.

**Вопрос:** Как оптимизировать пузырьковую сортировку?

**Ответ:** Основная оптимизация пузырьковой сортировки заключается в использовании флага для раннего завершения, если массив уже отсортирован. Если в итерации не было выполнено ни одного обмена, это означает, что массив уже отсортирован, и мы можем завершить выполнение алгоритма досрочно. Это даёт линейную временную сложность `O(n)` в лучшем случае.

**Вопрос:** Является ли пузырьковая сортировка стабильной?

**Ответ:** Да, пузырьковая сортировка является стабильной, если используется правильный оператор сравнения. Для сохранения стабильности используйте `>=` вместо `>` при сравнении элементов, чтобы не менять местами равные элементы. Это гарантирует, что относительный порядок равных элементов будет сохранён после сортировки.

**Вопрос:** Можно ли распараллелить пузырьковую сортировку?

**Ответ:** Пузырьковая сортировка плохо подходит для параллелизации из-за последовательной природы алгоритма. Каждая итерация зависит от результатов предыдущей итерации, что делает параллелизацию сложной и неэффективной. Для параллельной сортировки предпочтительнее использовать алгоритмы, которые можно эффективно разделить на независимые части, такие как сортировка слиянием или быстрая сортировка.

**Вопрос:** Почему пузырьковая сортировка называется «пузырьковой»?

**Ответ:** Пузырьковая сортировка получила своё название из-за того, что меньшие элементы «всплывают» наверх списка, подобно пузырькам воздуха в воде. На каждом проходе наибольший неотсортированный элемент «всплывает» на своё правильное место в конце массива, что делает алгоритм интуитивно понятным и простым для понимания.

## Глоссарий терминов

`Bubble Sort` (пузырьковая сортировка) — простой алгоритм сортировки, который сравнивает и меняет местами соседние элементы массива до полной сортировки. Алгоритм получил своё название из-за того, что меньшие элементы «всплывают» наверх списка.

`In-place сортировка` — тип алгоритма сортировки, который выполняет сортировку непосредственно в исходном массиве без использования дополнительной памяти. Пузырьковая сортировка является примером in-place сортировки.

`Стабильная сортировка` — свойство алгоритма сортировки сохранять относительный порядок равных элементов после сортировки. Пузырьковая сортировка является стабильной, если используется правильный оператор сравнения.

`Оптимизация раннего завершения` — техника оптимизации, которая позволяет завершить выполнение алгоритма досрочно, если массив уже отсортирован. Это улучшает производительность для уже отсортированных или почти отсортированных массивов.

`Квадратичная сложность` — временная сложность `O(n²)`, которая означает, что время выполнения алгоритма пропорционально квадрату размера входных данных. Пузырьковая сортировка имеет квадратичную сложность в среднем и худшем случаях.

`Линейная сложность` — временная сложность `O(n)`, которая означает, что время выполнения алгоритма пропорционально размеру входных данных. Оптимизированная пузырьковая сортировка имеет линейную сложность в лучшем случае.

`Сравнение элементов` — операция сравнения двух элементов массива для определения их относительного порядка. В пузырьковой сортировке сравниваются соседние элементы для определения необходимости их обмена.

`Обмен элементов` — операция замены местами двух элементов массива. В пузырьковой сортировке обмен происходит, когда соседние элементы находятся в неправильном порядке.

## Дополнительные примеры использования

Рассмотрим несколько практических примеров использования пузырьковой сортировки в различных сценариях.

### Пример 1: Сортировка объектов по нескольким полям

Пример сортировки объектов по нескольким полям с использованием пузырьковой сортировки:

```java
public static class Person {
    String name;
    int age;

    Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
}

public static void bubbleSortPersons(Person[] arr) {
    int n = arr.length;
    boolean swapped;

    for (int i = 0; i < n - 1; i++) {
        swapped = false;
        for (int j = 0; j < n - i - 1; j++) {
            // Сначала по возрасту, затем по имени
            if (arr[j].age > arr[j + 1].age ||
                (arr[j].age == arr[j + 1].age &&
                 arr[j].name.compareTo(arr[j + 1].name) > 0)) {
                Person temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
                swapped = true;
            }
        }
        if (!swapped) break;
    }
}
```

### Пример 2: Сортировка строк по длине

Пример сортировки массива строк по длине с использованием пузырьковой сортировки:

### Пример 3: Двунаправленная пузырьковая сортировка (Cocktail Sort)

Пример оптимизированной версии пузырьковой сортировки, которая проходит в обоих направлениях:

```java
public static void cocktailSort(int[] arr) {
    boolean swapped = true;
    int start = 0;
    int end = arr.length;

    while (swapped) {
        swapped = false;

        // Проход слева направо
        for (int i = start; i < end - 1; i++) {
            if (arr[i] > arr[i + 1]) {
                int temp = arr[i];
                arr[i] = arr[i + 1];
                arr[i + 1] = temp;
                swapped = true;
            }
        }

        if (!swapped) break;

        swapped = false;
        end--;

        // Проход справа налево
        for (int i = end - 1; i >= start; i--) {
            if (arr[i] > arr[i + 1]) {
                int temp = arr[i];
                arr[i] = arr[i + 1];
                arr[i + 1] = temp;
                swapped = true;
            }
        }

        start++;
    }
}
```

Эта версия может быть более эффективной для некоторых типов данных, так как она может быстрее перемещать элементы на их правильные позиции.

### Пример 4: Сортировка с пользовательским компаратором

Пример сортировки с использованием пользовательского компаратора:

```java
public static <T> void bubbleSortWithComparator(T[] arr, Comparator<T> comparator) {
    int n = arr.length;
    boolean swapped;

    for (int i = 0; i < n - 1; i++) {
        swapped = false;
        for (int j = 0; j < n - i - 1; j++) {
            if (comparator.compare(arr[j], arr[j + 1]) > 0) {
                T temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
                swapped = true;
            }
        }
        if (!swapped) break;
    }
}

// Использование

    Comparator.comparing(Student::getAge)
              .thenComparing(Student::getName));
```

Эта реализация позволяет использовать пузырьковую сортировку с любым типом данных и любым правилом сравнения, что делает алгоритм более гибким и применимым к различным сценариям.

    int[] arr1 = data.clone();

private static void bubbleSortUnoptimized(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }

    for (int i = 0; i < n - 1; i++) {

        for (int j = 0; j < n - i - 1; j++) {

                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
                swapped = true;
            }
        }

Этот пример демонстрирует важность оптимизации и показывает, как раннее завершение может улучшить производительность алгоритма, особенно для уже отсортированных или почти отсортированных массивов.

Рекурсивная реализация демонстрирует альтернативный подход к реализации алгоритма, хотя итеративная версия обычно более эффективна из-за отсутствия накладных расходов на вызовы функций.

### Пример 7: Сортировка списков

Пример сортировки `List` с использованием пузырьковой сортировки:

```java
public static <T extends Comparable<T>> void bubbleSortList(List<T> list) {
    int n = list.size();
    boolean swapped;

    for (int i = 0; i < n - 1; i++) {
        swapped = false;
        for (int j = 0; j < n - i - 1; j++) {
            if (list.get(j).compareTo(list.get(j + 1)) > 0) {
                T temp = list.get(j);
                list.set(j, list.get(j + 1));
                list.set(j + 1, temp);
                swapped = true;
            }
        }
        if (!swapped) break;
    }
}
```

Эта реализация работает с любыми типами данных, которые реализуют интерфейс `Comparable`, что делает её универсальной и применимой к различным коллекциям.

## Когда использовать

Выбор между пузырьковой сортировкой и другими алгоритмами сортировки зависит от конкретных требований приложения. Используйте пузырьковую сортировку только для учебных целей или очень малых массивов (`n < 10`), когда простота реализации важнее производительности, или когда массив уже почти отсортирован и требуется исправить только несколько ошибок.

Пузырьковая сортировка может быть полезной для демонстрации основных концепций сортировки и понимания работы алгоритмов сравнения. Однако для большинства практических применений предпочтительнее использовать более эффективные алгоритмы, такие как быстрая сортировка или сортировка слиянием, которые имеют лучшую временную сложность `O(n log n)` в среднем случае.

Не используйте пузырьковую сортировку для больших массивов данных, когда производительность критична, для продакшена без тщательного анализа требований, или когда доступны более эффективные алгоритмы, такие как библиотечные методы `Arrays.sort()` или `Collections.sort()`. В таких случаях использование пузырьковой сортировки может привести к значительному ухудшению производительности и проблемам с масштабируемостью.
