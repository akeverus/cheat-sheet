# Быстрая сортировка (`Quick Sort`)

Быстрая сортировка — это эффективный алгоритм сортировки, использующий принцип «разделяй и властвуй», который выбирает опорный элемент и разделяет массив на части относительно этого элемента.

## Описание алгоритма

`Quicksort` — это алгоритм сортировки, использующий принцип «разделяй и властвуй». Он имеет среднюю сложность `O(n log n)` и является одним из наиболее часто используемых алгоритмов сортировки, особенно для больших объёмов данных.

Важно помнить, что быстрая сортировка не является стабильным алгоритмом. Алгоритм стабильной сортировки - это алгоритм, в котором элементы с одинаковыми значениями появляются в отсортированном выводе в том же порядке, в каком они появляются во входном списке.

## Принцип работы

Входной список разделён на два подсписка с помощью элемента, называемого опорным (`pivot`); один подсписок с элементами меньше, чем опорный элемент, а другой — с элементами больше, чем опорный элемент. Этот процесс повторяется для каждого подсписка.

Наконец, все отсортированные подсписки объединяются, чтобы сформировать окончательный результат.

Алгоритм работает следующим образом. Сначала мы выбираем элемент из списка, который называется опорным (`pivot`). Затем мы переупорядочиваем все элементы вокруг опорной точки — элементы с меньшим значением помещаются перед ней, а все элементы, превышающие опорную, — после неё. После этого мы применяем описанные выше шаги рекурсивно к обоим подспискам слева и справа от опорного элемента.

Как мы видим, быстрая сортировка по своей природе является рекурсивным алгоритмом, как и любой подход «разделяй и властвуй».

### Пример работы

Давайте возьмем простой пример, чтобы лучше понять этот алгоритм.

`Arr[] = {5, 9, 4, 6, 5, 3}`

Предположим, мы выбрали 5 в качестве опорной точки для простоты.

Сначала мы поместим все элементы меньше `5` в первую позицию массива: `{3, 4, 5, 6, 5, 9}`. Затем мы повторим это для левого подмассива `{3, 4}`, взяв `3` в качестве точки поворота. Нет элементов меньше `3`, поэтому мы применяем быструю сортировку к подмассиву справа от опорной точки, т. е. `{4}`. Этот подмассив состоит только из одного отсортированного элемента. Мы продолжаем работать с правой частью исходного массива `{6, 5, 9}`, пока не получим окончательный упорядоченный массив.

## Выбор опорного элемента

Важным моментом в `QuickSort` является выбор наилучшего опорного значения. Средний элемент, конечно, лучший, так как он разделил бы список на два равных подсписка. Но найти средний элемент из неупорядоченного списка сложно и долго, поэтому мы берём в качестве точки опоры первый элемент, последний элемент, медиану или случайный элемент. Выбор опорного элемента влияет на производительность алгоритма. В худшем случае, когда опорный элемент всегда является минимальным или максимальным, сложность становится `O(n²)`.

## Реализация на Java

Первый метод — это `quickSort()`, который принимает в качестве параметров массив для сортировки, первый и последний индекс. Сначала мы проверяем индексы и продолжаем, только если есть ещё элементы для сортировки. Мы получаем индекс отсортированного опорного элемента и используем его для рекурсивного вызова метода `partition()` с теми же параметрами, что и у метода `quickSort()`, но с другими индексами:

```java
// Рекурсивная быстрая сортировка: выбираем опорный элемент, делим массив и рекурсивно сортируем левую и правую части
public void quickSort(int arr[], int begin, int end) {
    if (begin < end) {
        int partitionIndex = partition(arr, begin, end);
        quickSort(arr, begin, partitionIndex - 1);
        quickSort(arr, partitionIndex + 1, end);
    }
}
```

Давайте продолжим с методом `partition()`. Для простоты эта функция принимает последний элемент в качестве опорного. Затем проверяет каждый элемент и меняет его местами перед поворотом, если его значение меньше. К концу разбиения все элементы, меньшие опорной точки, находятся слева от неё, а все элементы, превышающие опорную точку, — справа от неё. Опорная точка находится в своей конечной отсортированной позиции, и функция возвращает эту позицию:

```java
// Разбиение массива: элементы <= pivot переносим влево, элементы > pivot — вправо, возвращаем позицию pivot
private int partition(int arr[], int begin, int end) {
    int pivot = arr[end];
    int i = (begin - 1);
    
    for (int j = begin; j < end; j++) {
        if (arr[j] <= pivot) {
            i++;
            int swapTemp = arr[i];
            arr[i] = arr[j];
            arr[j] = swapTemp;
        }
    }
    
    int swapTemp = arr[i + 1];
    arr[i + 1] = arr[end];
    arr[end] = swapTemp;
    
    return i + 1;
}
```

## Реализация на Kotlin

В `Kotlin` алгоритм `Quick Sort` может быть реализован следующим образом:

```kotlin
fun quickSort(arr: IntArray, begin: Int = 0, end: Int = arr.size - 1) {
    if (begin < end) {
        val partitionIndex = partition(arr, begin, end)
        quickSort(arr, begin, partitionIndex - 1)
        quickSort(arr, partitionIndex + 1, end)
    }
}

private fun partition(arr: IntArray, begin: Int, end: Int): Int {
    val pivot = arr[end]
    var i = begin - 1

    for (j in begin until end) {
        if (arr[j] <= pivot) {
            i++
            arr[i] = arr[j].also { arr[j] = arr[i] }
        }
    }

    arr[i + 1] = arr[end].also { arr[end] = arr[i + 1] }
    return i + 1
}
```

**Использование:**

```kotlin
fun main() {
    val array = intArrayOf(5, 9, 4, 6, 5, 3)
    quickSort(array)
    println(array.contentToString()) // [3, 4, 5, 5, 6, 9]
}
```

### Функциональный стиль

В `Kotlin` можно также использовать более функциональный подход:

```kotlin
fun quickSortFunctional(arr: List<Int>): List<Int> {
    if (arr.size <= 1) return arr
    
    val pivot = arr[arr.size / 2]
    val less = arr.filter { it < pivot }
    val equal = arr.filter { it == pivot }
    val greater = arr.filter { it > pivot }
    
    return quickSortFunctional(less) + equal + quickSortFunctional(greater)
}
```

Использование:

```kotlin
fun main() {
    val list = listOf(5, 9, 4, 6, 5, 3)
    val sorted = quickSortFunctional(list)
    println(sorted) // [3, 4, 5, 5, 6, 9]
}
```

## Сложность

### Временная сложность

Временная сложность `QuickSort` зависит от выбора опорного элемента. В лучшем случае, когда опорный элемент всегда делит массив пополам, временная сложность составляет `O(n log n)`. В этом случае алгоритм разделит список на два подсписка одинакового размера. Для первой итерации полного списка размером `n` требуется `O(n)`. Сортировка оставшихся двух подсписков даёт рекурсию по двум половинам, итоговая сложность `O(n log n)`.

В среднем случае временная сложность также составляет `O(n log n)`, что делает `QuickSort` подходящим для больших объёмов данных. В большинстве случаев опорный элемент будет достаточно хорошо разделять массив, что обеспечивает хорошую производительность.

В худшем случае, когда опорный элемент всегда является минимальным или максимальным элементом, временная сложность составляет `O(n²)`. В этом случае алгоритм будет выбирать только один элемент на каждой итерации, поэтому `O(n)` + `O(n - 1)` + … + `O(1)`, что равно `O(n²)`.

### Пространственная сложность

Пространственная сложность `QuickSort` зависит от глубины рекурсии. В среднем случае пространственная сложность составляет `O(log n)` из‑за глубины рекурсии. В худшем случае, в случае несбалансированного разделения, пространственная сложность может достигать `O(n)`.

## Сравнение с Merge Sort

Давайте обсудим, в каких случаях мы должны выбрать `QuickSort` вместо `MergeSort`. Хотя и быстрая сортировка, и сортировка слиянием имеют среднюю временную сложность `O(n log n)`, быстрая сортировка является предпочтительным алгоритмом, поскольку имеет пространственную сложность `O(log n)`. С другой стороны, сортировка слиянием требует `O(n)` дополнительной памяти, что делает её довольно дорогой для массивов.

Быстрая сортировка требует доступа к различным индексам для своих операций, но такой доступ невозможен напрямую в связанных списках, поскольку непрерывных блоков нет. Поэтому, чтобы получить доступ к элементу, мы должны перебирать каждый узел с начала связанного списка. Кроме того, `Mergesort` реализован без дополнительного места для `LinkedLists`. В таком случае обычно предпочтительнее увеличение накладных расходов для быстрой сортировки и сортировки слиянием.

## Особенности

`Quick Sort` не является стабильным алгоритмом, что означает, что элементы с одинаковыми значениями могут изменить свой относительный порядок после сортировки. Сортировка выполняется на месте (`in-place`), что означает, что она не требует дополнительной памяти для массивов. В среднем `Quick Sort` работает быстрее, чем `Merge Sort` и `Heap Sort`, что делает его предпочтительным выбором для большинства практических случаев. В `Java` метод `Arrays.sort()` использует `QuickSort` для сортировки массивов примитивов, что демонстрирует его практическую эффективность.

## Применение

`Quicksort` — это элегантный алгоритм сортировки, очень полезный в большинстве случаев. Как правило, это алгоритм «на месте» со средней временной сложностью `O(n log n)`. Ещё один интересный момент, о котором следует упомянуть, заключается в том, что метод `Java` `Arrays.sort()` использует `Quicksort` для сортировки массивов примитивов. Реализация использует два опорных элемента и работает намного лучше, чем наше простое решение, поэтому для производственного кода обычно лучше использовать библиотечные методы.

### Когда использовать Quick Sort

`Quick Sort` следует использовать для больших массивов примитивных типов, когда важна производительность в среднем случае, когда доступная память ограничена (`in-place` сортировка), и для массивов, где случайный доступ эффективен. `Quick Sort` особенно эффективен для массивов, где можно быстро получить доступ к любому элементу по индексу.

### Когда не использовать Quick Sort

`Quick Sort` не следует использовать, когда требуется стабильная сортировка, так как он не является стабильным алгоритмом. Для связанных списков лучше использовать `Merge Sort`, так как `Quick Sort` требует случайного доступа к элементам, что неэффективно для связанных списков. `Quick Sort` также не следует использовать, когда худший случай `O(n²)` недопустим, так как в худшем случае производительность может значительно ухудшиться.

## Лучшие практики

Выбор опорного элемента критически важен для производительности алгоритма. Для снижения риска `O(n²)` следует использовать случайный элемент, медиану из трёх (первый, средний, последний) или медиану медиан. Последний или первый элемент — простой вариант, но уязвим к уже отсортированным данным, что может привести к худшему случаю.

При разбиении (`partition`) необходимо сохранять инвариант «слева ≤ `pivot`, справа > `pivot`» (или наоборот). При равенстве элементов `pivot` необходимо решать однозначно (например, всегда слева), чтобы избежать бесконечной рекурсии при дубликатах.

Рекурсия требует проверки `begin < end` перед разбиением. Для малых подмассивов (например, `n < 10`) можно переключиться на `insertion sort` для снижения накладных расходов, так как для малых массивов `insertion sort` может быть эффективнее из‑за меньших накладных расходов.

`In-place` реализация имеет `O(log n)` стековых вызовов в среднем. При глубокой рекурсии следует сортировать меньшую часть рекурсивно, большую — в цикле, чтобы ограничить глубину стеком `O(log n)` и избежать переполнения стека.

Тестирование должно включать проверку пустого массива, одного элемента, уже отсортированного массива, массива с дубликатами, и обратного порядка. Эти тесты помогают убедиться, что алгоритм правильно обрабатывает все граничные случаи и различные входные данные.

## Что выбрать: Quick Sort vs Merge Sort vs Heap Sort

| Алгоритм | Когда обычно лучше | Ограничения |
|---|---|---|
| `Quick Sort` | массивы в памяти, важна средняя производительность и `in-place` сортировка | в худшем случае `O(n²)`, алгоритм нестабильный |
| `Merge Sort` | нужна стабильность сортировки или работа со связанными списками/внешними данными | требует `O(n)` дополнительной памяти для массивов |
| `Heap Sort` | нужен гарантированный `O(n log n)` без доп.памяти как у merge | часто медленнее quick sort на практике из-за cache-locality |

Практическое правило: для production-кода чаще используют стандартную библиотеку языка, а ручную реализацию выбирают в учебных целях или для специализированных ограничений.

## Решение проблем

| Проблема | Причина | Что делать |
|---|---|---|
| `StackOverflowError` на больших массивах | глубокая рекурсия при неудачном pivot | выбирать pivot случайно/median-of-three, рекурсивно сортировать меньшую часть |
| Частые деградации до `O(n²)` | pivot стабильно выбирается с краю на почти отсортированных данных | использовать рандомизацию pivot или `introsort`-подход |
| Неправильная сортировка с дубликатами | некорректный инвариант в `partition` | использовать 3-way partition (`<`, `=`, `>`) |
| Медленнее библиотечной сортировки | наивная реализация без оптимизаций | переключаться на insertion sort для малых подмассивов и применять tail-recursion optimization |

## Частые вопросы

**Почему quick sort часто быстрее merge sort, если обе имеют `O(n log n)` в среднем?**  
Из-за лучшей локальности данных и меньших накладных расходов по памяти при `in-place` обработке.

**Можно ли сделать quick sort стабильным?**  
Можно, но это обычно требует дополнительной памяти и усложняет реализацию, теряя одно из ключевых преимуществ.

**Когда не стоит писать quick sort вручную?**  
Почти всегда в production лучше использовать `Arrays.sort()`/`Collections.sort()` (или аналоги), если нет особых требований к алгоритму.

**Что делать, если данные почти отсортированы?**  
Избегать фиксированного pivot (первый/последний), использовать median-of-three или гибридный алгоритм.
