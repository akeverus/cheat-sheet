# Сортировка выбором (`Selection Sort`)

Сортировка выбором — это простой алгоритм сортировки, который находит минимальный элемент в неотсортированной части массива и помещает его в начало отсортированной части. Алгоритм работает путём последовательного выбора наименьшего элемента из оставшихся неотсортированных элементов и размещения его в правильной позиции. Хотя сортировка выбором имеет квадратичную временную сложность `O(n²)` во всех случаях, она обладает важным преимуществом — минимальным количеством обменов элементов (максимум `n-1` обменов), что делает её полезной в ситуациях, где стоимость записи в память высока. В этом документе рассматриваются различные реализации алгоритма на `Java` и `Kotlin`, анализ его сложности, особенности применения и сравнение с другими алгоритмами сортировки.

## Описание алгоритма

Сортировка выбором начинается с элемента в 1-й позиции несортированного массива и просматривает последующие элементы, чтобы найти наименьший элемент. После нахождения наименьший элемент заменяется элементом в 1-й позиции.

Затем алгоритм переходит к элементу во 2-й позиции и просматривает последующие элементы, чтобы найти индекс 2-го наименьшего элемента. После нахождения второй наименьший элемент заменяется элементом на 2-й позиции.

Этот процесс продолжается до тех пор, пока мы не достигнем `n-1`-го элемента массива, который помещает `n-1`-й наименьший элемент в `n-1`-ю позицию. Последний элемент автоматически встаёт на место на `n-1`-й итерации, тем самым сортируя массив.

Мы можем найти самый большой элемент вместо самого маленького элемента, чтобы отсортировать массив в порядке убывания.

## Реализация на Java

Реализация сортировки выбором на `Java` использует два вложенных цикла `for`. Внешний цикл проходит по массиву от начала до предпоследнего элемента, а внутренний цикл находит минимальный элемент в оставшейся неотсортированной части массива. После нахождения минимального элемента он обменивается с элементом на текущей позиции внешнего цикла.

```java
// Сортировка выбором: на каждой итерации минимум неотсортированной части ставится на место (O(n²))
public static void sortAscending(final int[] arr) {
    for (int i = 0; i < arr.length - 1; i++) {
        int minElementIndex = i;
        
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[minElementIndex] > arr[j]) {
                minElementIndex = j;
            }
        }
        
        if (minElementIndex != i) {
            int temp = arr[i];
            arr[i] = arr[minElementIndex];
            arr[minElementIndex] = temp;
        }
    }
}
```

Для сортировки по убыванию используется аналогичный подход, но вместо поиска минимального элемента мы ищем максимальный элемент в неотсортированной части массива:

```java
public static void sortDescending(final int[] arr) {
    for (int i = 0; i < arr.length - 1; i++) {
        int maxElementIndex = i;
        
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[maxElementIndex] < arr[j]) {
                maxElementIndex = j;
            }
        }
        
        if (maxElementIndex != i) {
            int temp = arr[i];
            arr[i] = arr[maxElementIndex];
            arr[maxElementIndex] = temp;
        }
    }
}
```

Для создания универсальной реализации, которая может работать как по возрастанию, так и по убыванию, можно использовать `Comparator`, который определяет порядок сортировки:

```java
public static void sort(final int[] arr, final Comparator<Integer> comparator) {
    for (int i = 0; i < arr.length - 1; i++) {
        int elementIndex = i;
        
        for (int j = i + 1; j < arr.length; j++) {
            if (comparator.compare(arr[elementIndex], arr[j]) > 0) {
                elementIndex = j;
            }
        }
        
        if (elementIndex != i) {
            int temp = arr[i];
            arr[i] = arr[elementIndex];
            arr[elementIndex] = temp;
        }
    }
}
```

## Реализация на Kotlin

Реализация сортировки выбором на `Kotlin` следует тем же принципам, что и реализация на `Java`, но использует более идиоматичный синтаксис `Kotlin`. Рассмотрим различные варианты реализации, включая базовую сортировку по возрастанию и убыванию, универсальную реализацию с `Comparator` и функциональный стиль.

### Сортировка по возрастанию

```kotlin
fun sortAscendingK(arr: IntArray) {
    for (i in 0 until arr.size - 1) {
        var minElementIndex = i
        
        for (j in i + 1 until arr.size) {
            if (arr[minElementIndex] > arr[j]) {
                minElementIndex = j
            }
        }
        
        if (minElementIndex != i) {
            val temp = arr[i]
            arr[i] = arr[minElementIndex]
            arr[minElementIndex] = temp
        }
    }
}
```

### Сортировка по убыванию

```kotlin
fun sortDescendingK(arr: IntArray) {
    for (i in 0 until arr.size - 1) {
        var maxElementIndex = i
        
        for (j in i + 1 until arr.size) {
            if (arr[maxElementIndex] < arr[j]) {
                maxElementIndex = j
            }
        }
        
        if (maxElementIndex != i) {
            val temp = arr[i]
            arr[i] = arr[maxElementIndex]
            arr[maxElementIndex] = temp
        }
    }
}
```

### Универсальная реализация с Comparator

```kotlin
fun sortK(arr: IntArray, comparator: Comparator<Int>) {
    for (i in 0 until arr.size - 1) {
        var elementIndex = i
        
        for (j in i + 1 until arr.size) {
            if (comparator.compare(arr[elementIndex], arr[j]) > 0) {
                elementIndex = j
            }
        }
        
        if (elementIndex != i) {
            val temp = arr[i]
            arr[i] = arr[elementIndex]
            arr[elementIndex] = temp
        }
    }
}
```

### Функциональный стиль

```kotlin
fun selectionSortFunctionalK(arr: IntArray): IntArray {
    val result = arr.copyOf()
    for (i in 0 until result.size - 1) {
        val minIndex = (i + 1 until result.size)
            .minByOrNull { result[it] } ?: i
        if (minIndex != i) {
            result[i] = result[minIndex].also { result[minIndex] = result[i] }
        }
    }
    return result
}
```

### Пример использования

```kotlin
fun main() {
    val arr = intArrayOf(5, 4, 1, 6, 2)
    
    // Сортировка по возрастанию
    sortAscendingK(arr)
    println(arr.contentToString()) // [1, 2, 4, 5, 6]
    
    // Функциональный стиль
    val sorted = selectionSortFunctionalK(intArrayOf(5, 4, 1, 6, 2))
    println(sorted.contentToString()) // [1, 2, 4, 5, 6]
}
```

## Сложность

Анализ сложности сортировки выбором показывает, что алгоритм имеет квадратичную временную сложность во всех случаях. Для выбора наименьшего элемента требуется `n-1` сравнений с последующей перестановкой его на первую позицию. Выбор следующего наименьшего элемента требует `n-2` сравнений с последующей перестановкой во вторую позицию, и так далее.

Таким образом, начиная с индекса `0`, мы выполняем `n-1`, `n-2`, `n-3`, `n-4`, ..., `1` сравнений. Последний элемент автоматически встаёт на место благодаря предыдущим итерациям и перестановкам.

Математически сумма первых `n-1` натуральных чисел показывает, сколько сравнений нужно для сортировки массива размера `n` с помощью сортировки выбором. Формула суммы `n` натуральных чисел: `n(n+1)/2`. В нашем случае нужна сумма первых `n-1` натуральных чисел, поэтому заменяем `n` на `n-1` в формуле: `(n-1)(n-1+1)/2 = (n-1)n/2 = (n² - n)/2`.

Поскольку `n²` заметно растёт с ростом `n`, мы рассматриваем более высокую степень `n` в качестве эталона производительности, что делает этот алгоритм временной сложностью `O(n²)`.

### Временная сложность

Временная сложность сортировки выбором одинакова во всех случаях: худший случай `O(n²)`, средний случай `O(n²)`, лучший случай `O(n²)`. Это происходит потому, что алгоритм должен сканировать каждый элемент для поиска минимального значения, независимо от исходного порядка элементов. Даже если массив уже отсортирован, алгоритм всё равно выполняет все сравнения, так как не может заранее знать, что массив уже упорядочен.

Такое поведение отличает сортировку выбором от других алгоритмов, таких как сортировка вставками или пузырьковая сортировка, которые могут работать быстрее на частично отсортированных данных. Однако сортировка выбором имеет важное преимущество — минимальное количество обменов элементов, что может быть критично в ситуациях, где стоимость записи в память высока.

### Пространственная сложность

Пространственная сложность сортировки выбором составляет `O(1)` во всех случаях, так как алгоритм требует только одну дополнительную переменную для временного хранения значения при обмене элементов. Это делает сортировку выбором эффективной по использованию памяти и подходящей для систем с ограниченными ресурсами.

## Особенности

Сортировка выбором обладает несколькими важными особенностями, которые определяют её применимость в различных ситуациях. Во-первых, это очень простой для понимания и реализации алгоритм сортировки, что делает его отличным выбором для обучения основам алгоритмов сортировки. Простота реализации также означает, что алгоритм легко отлаживать и модифицировать для конкретных потребностей.

Во-вторых, сортировка выбором не является стабильным алгоритмом, что означает, что она может менять относительный порядок элементов с одинаковыми значениями. Это происходит потому, что при обмене минимального элемента с элементом на текущей позиции относительный порядок равных элементов может измениться. Если стабильность важна для вашего приложения, следует использовать стабильные алгоритмы, такие как сортировка вставками или сортировка слиянием.

В-третьих, сортировка выполняется на месте (in-place), не требуя дополнительной памяти, пропорциональной размеру массива. Алгоритм требует только константную дополнительную память для хранения временных переменных, что делает его эффективным по использованию памяти.

В-четвёртых, алгоритм делает минимальное количество обменов элементов — максимум `n-1` обменов. Это важное преимущество в ситуациях, где стоимость записи в память высока, например, при работе с данными на внешних носителях или в системах с ограниченной пропускной способностью памяти.

## Недостатки

К сожалению, квадратичная временная сложность делает сортировку выбором дорогостоящим методом сортировки для больших массивов. Кроме того, поскольку алгоритм должен сканировать каждый элемент для поиска минимального значения, временная сложность в лучшем, среднем и худшем случаях одинакова и составляет `O(n²)`. Это означает, что даже для уже отсортированного массива алгоритм выполняет все сравнения, не используя преимуществ предварительной упорядоченности данных.

Другие методы сортировки, такие как сортировка вставками и сортировка Шелла, также имеют квадратичную временную сложность в худшем случае, но они работают лучше в лучшем и среднем случаях благодаря способности использовать частичную упорядоченность данных. Сортировка вставками может достичь линейной временной сложности `O(n)` для уже отсортированных данных, а сортировка Шелла имеет среднюю временную сложность `O(n^1.5)` с последовательностью `Shell`.

Ещё одним недостатком является то, что алгоритм не является стабильным, что может быть проблемой в приложениях, где важно сохранить относительный порядок равных элементов. Кроме того, для больших массивов сортировка выбором значительно медленнее, чем более эффективные алгоритмы, такие как быстрая сортировка или сортировка слиянием, которые имеют временную сложность `O(n log(n))` в среднем случае.

## Применение

Сортировка выбором полезна в нескольких специфических случаях, где её особенности дают преимущества перед другими алгоритмами. Во-первых, алгоритм подходит для массивов с небольшим количеством элементов, где квадратичная сложность не является критическим фактором. Для массивов размером менее `10-20` элементов разница в производительности между различными алгоритмами сортировки незначительна, и простота реализации сортировки выбором может быть предпочтительнее.

Во-вторых, сортировка выбором особенно полезна, когда стоимость записи в память высока, так как алгоритм делает минимальное количество обменов элементов — максимум `n-1` обменов. Это делает её подходящей для работы с данными на внешних носителях, где операции записи значительно дороже операций чтения, или в системах с ограниченной пропускной способностью памяти.

В-третьих, алгоритм отлично подходит для обучения основам алгоритмов сортировки благодаря своей простоте и понятности. Студенты могут легко понять принцип работы алгоритма и реализовать его самостоятельно, что помогает заложить фундамент для изучения более сложных алгоритмов.

В-четвёртых, когда простота реализации важнее производительности, сортировка выбором может быть предпочтительнее более сложных алгоритмов. В прототипах, небольших проектах или ситуациях, где производительность не является критическим фактором, простота реализации и отладки может перевесить недостатки в производительности.

## Сравнение с другими алгоритмами

Сравнение сортировки выбором с другими алгоритмами сортировки показывает её преимущества и недостатки. Сортировка выбором имеет временную сложность `O(n²)` во всех случаях (лучший, средний и худший), требует `O(1)` дополнительной памяти и не является стабильной. Пузырьковая сортировка имеет лучший случай `O(n)`, средний и худший случаи `O(n²)`, требует `O(1)` памяти и является стабильной. Сортировка вставками имеет лучший случай `O(n)`, средний и худший случаи `O(n²)`, требует `O(1)` памяти и является стабильной.

Основное отличие сортировки выбором от пузырьковой сортировки и сортировки вставками заключается в том, что она не может использовать преимущества частично отсортированных данных. Пузырьковая сортировка и сортировка вставками могут работать быстрее на уже отсортированных или частично отсортированных данных, достигая линейной временной сложности в лучшем случае. Сортировка выбором всегда выполняет все сравнения, независимо от исходного порядка элементов.

Однако сортировка выбором имеет важное преимущество — минимальное количество обменов элементов. В то время как пузырьковая сортировка может выполнять множество обменов соседних элементов, сортировка выбором делает максимум `n-1` обменов, что может быть критично в ситуациях, где стоимость записи в память высока.

## Лучшие практики

При реализации сортировки выбором важно следовать нескольким лучшим практикам для обеспечения корректности и оптимальной производительности. Во-первых, используйте сортировку выбором только для учебных целей или очень малых массивов. Для продакшена предпочтительнее использовать более эффективные алгоритмы, такие как `QuickSort`, `MergeSort` или `Arrays.sort`, которые обеспечивают лучшую производительность для больших массивов. Однако преимущество сортировки выбором — минимум обменов (до `n-1`), что может быть важно, если запись в память дорога.

Во-вторых, помните, что сортировка выбором нестабильна — при обмене минимума с текущей позицией относительный порядок равных элементов может измениться. Если стабильность важна для вашего приложения, используйте стабильные алгоритмы сортировки, такие как сортировка вставками или сортировка слиянием.

В-третьих, обрабатывайте граничные случаи корректно: пустой массив и массив с одним элементом не требуют итераций, поэтому проверяйте длину массива перед циклом. Это поможет избежать ненужных операций и потенциальных ошибок.

В-четвёртых, можно реализовать двунаправленную версию алгоритма, которая одновременно ищет минимум и максимум за один проход, сокращая количество итераций вдвое. Однако это усложняет код и увеличивает константу времени выполнения, поэтому такой подход оправдан только в специфических случаях.

В-пятых, при тестировании важно проверить различные случаи: уже отсортированный массив, обратный порядок, дубликаты, один элемент, пустой массив. Это поможет выявить потенциальные проблемы и обеспечить корректную работу алгоритма во всех ситуациях. Особое внимание следует уделить тестированию граничных случаев, таких как массив с двумя элементами, массив, где все элементы одинаковы, и массив, где все элементы уже отсортированы в обратном порядке.

## Решение проблем

При работе с сортировкой выбором могут возникать различные проблемы. Если алгоритм работает слишком медленно, убедитесь, что размер массива не превышает несколько десятков элементов. Для больших массивов рассмотрите возможность использования более эффективных алгоритмов, таких как быстрая сортировка или сортировка слиянием, которые обеспечивают лучшую производительность для больших объёмов данных.

Если алгоритм не сортирует массив правильно, проверьте логику поиска минимального элемента во внутреннем цикле. Убедитесь, что вы правильно обновляете индекс минимального элемента при сравнении и корректно выполняете обмен элементов. Также проверьте граничные условия, такие как пустой массив или массив с одним элементом, которые не требуют выполнения циклов.

При проблемах с нестабильностью сортировки помните, что сортировка выбором не сохраняет относительный порядок равных элементов. Если стабильность важна для вашего приложения, используйте стабильные алгоритмы сортировки, такие как сортировка вставками или сортировка слиянием.

Если вы работаете с данными на внешних носителях и стоимость записи критична, убедитесь, что вы используете оптимизированную версию алгоритма, которая минимизирует количество обменов. Также рассмотрите возможность использования двунаправленной версии алгоритма, которая может сократить количество итераций вдвое, хотя это усложняет реализацию.

## Частые вопросы

**Вопрос:** Почему сортировка выбором имеет одинаковую временную сложность во всех случаях?

**Ответ:** Сортировка выбором всегда должна сканировать каждый элемент в неотсортированной части массива для поиска минимального значения, независимо от исходного порядка элементов. Даже если массив уже отсортирован, алгоритм не может заранее знать об этом и выполняет все сравнения. Это отличает её от других алгоритмов, таких как сортировка вставками, которая может использовать преимущества частично отсортированных данных.

**Вопрос:** Когда стоит использовать сортировку выбором вместо других алгоритмов?

**Ответ:** Сортировка выбором стоит использовать только для учебных целей или очень малых массивов (менее `10-20` элементов). Также она может быть полезна в ситуациях, где стоимость записи в память высока, так как алгоритм делает минимальное количество обменов элементов. Для продакшена предпочтительнее использовать более эффективные алгоритмы, такие как быстрая сортировка или сортировка слиянием.

**Вопрос:** Можно ли сделать сортировку выбором стабильной?

**Ответ:** Стандартная реализация сортировки выбором не является стабильной, так как при обмене минимального элемента с элементом на текущей позиции относительный порядок равных элементов может измениться. Можно модифицировать алгоритм для сохранения стабильности, используя вставку вместо обмена, но это значительно усложняет реализацию и увеличивает количество операций. В таких случаях лучше использовать изначально стабильные алгоритмы, такие как сортировка вставками или сортировка слиянием.

**Вопрос:** Как оптимизировать сортировку выбором?

**Ответ:** Основная оптимизация сортировки выбором — это двунаправленная версия, которая одновременно ищет минимум и максимум за один проход, сокращая количество итераций вдвое. Однако это усложняет код и увеличивает константу времени выполнения. Для значительного улучшения производительности лучше использовать более эффективные алгоритмы, такие как быстрая сортировка или сортировка слиянием.

**Вопрос:** Почему сортировка выбором делает минимальное количество обменов?

**Ответ:** Сортировка выбором делает максимум `n-1` обменов, потому что на каждой итерации она находит минимальный элемент в неотсортированной части и обменивает его с элементом на текущей позиции. После `n-1` итераций все элементы, кроме последнего, уже находятся на своих правильных позициях, и последний элемент автоматически встаёт на место. Это минимальное количество обменов среди всех алгоритмов сортировки, что делает сортировку выбором полезной в ситуациях, где стоимость записи в память высока.

**Вопрос:** Можно ли использовать сортировку выбором для сортировки объектов?

**Ответ:** Да, можно модифицировать алгоритм для работы с объектами, используя `Comparator` для определения порядка сортировки. Однако помните, что алгоритм не является стабильным, поэтому относительный порядок объектов с одинаковыми ключами может измениться. Если стабильность важна, используйте стабильные алгоритмы сортировки.

## Глоссарий терминов

`Сортировка выбором` — алгоритм сортировки, который находит минимальный элемент в неотсортированной части массива и помещает его в начало отсортированной части. Алгоритм работает путём последовательного выбора наименьшего элемента из оставшихся неотсортированных элементов и размещения его в правильной позиции.

`In-place алгоритм` — алгоритм, который выполняет сортировку непосредственно в исходном массиве без использования дополнительной памяти, пропорциональной размеру массива. Сортировка выбором является in-place алгоритмом и требует только константную дополнительную память для хранения временных переменных.

`Стабильность сортировки` — свойство алгоритма сортировки сохранять относительный порядок равных элементов после сортировки. Сортировка выбором не является стабильным алгоритмом, что означает, что относительный порядок равных элементов может измениться после сортировки.

`Временная сложность` — количество операций, которое выполняет алгоритм в зависимости от размера входных данных. Сортировка выбором имеет временную сложность `O(n²)` во всех случаях (лучший, средний и худший).

`Пространственная сложность` — количество дополнительной памяти, необходимое алгоритму для работы. Сортировка выбором имеет пространственную сложность `O(1)`, так как требует только константную дополнительную память для хранения временных переменных.

`Минимум обменов` — важное преимущество сортировки выбором, которое заключается в том, что алгоритм делает максимум `n-1` обменов элементов. Это делает её полезной в ситуациях, где стоимость записи в память высока.

`Двунаправленная сортировка выбором` — оптимизированная версия алгоритма, которая одновременно ищет минимум и максимум за один проход, сокращая количество итераций вдвое. Однако это усложняет реализацию и увеличивает константу времени выполнения.

`Comparator` — интерфейс в `Java`, который определяет порядок сортировки элементов. Использование `Comparator` позволяет создать универсальную реализацию сортировки выбором, которая может работать как по возрастанию, так и по убыванию.

## Дополнительные примеры использования

Рассмотрим несколько практических примеров использования сортировки выбором в различных сценариях.

### Пример 1: Сортировка с пользовательским Comparator

Реализуем версию для сортировки объектов с использованием `Comparator`:

```java
public static <T> void sort(T[] array, Comparator<T> comparator) {
    for (int i = 0; i < array.length - 1; i++) {
        int minIndex = i;
        
        for (int j = i + 1; j < array.length; j++) {
            if (comparator.compare(array[minIndex], array[j]) > 0) {
                minIndex = j;
            }
        }
        
        if (minIndex != i) {
            T temp = array[i];
            array[i] = array[minIndex];
            array[minIndex] = temp;
        }
    }
}
```

### Пример 2: Двунаправленная сортировка выбором

Реализуем оптимизированную версию, которая одновременно ищет минимум и максимум:

```java
public static void sortBidirectional(int[] arr) {
    int left = 0;
    int right = arr.length - 1;
    
    while (left < right) {
        int minIndex = left;
        int maxIndex = right;
        
        // Находим минимум и максимум в текущем диапазоне
        for (int i = left; i <= right; i++) {
            if (arr[i] < arr[minIndex]) {
                minIndex = i;
            }
            if (arr[i] > arr[maxIndex]) {
                maxIndex = i;
            }
        }
        
        // Обмениваем минимум с левым концом
        if (minIndex != left) {
            int temp = arr[left];
            arr[left] = arr[minIndex];
            arr[minIndex] = temp;
        }
        
        // Если максимум был на позиции left, он переместился на minIndex
        if (maxIndex == left) {
            maxIndex = minIndex;
        }
        
        // Обмениваем максимум с правым концом
        if (maxIndex != right) {
            int temp = arr[right];
            arr[right] = arr[maxIndex];
            arr[maxIndex] = temp;
        }
        
        left++;
        right--;
    }
}
```

### Пример 3: Сортировка с измерением производительности

Реализуем версию с измерением времени выполнения и количества сравнений:

```java
public static class SortResult {
    public long executionTime;
    public int comparisons;
    public int swaps;
}

public static SortResult sortWithMetrics(int[] arr) {
    SortResult result = new SortResult();
    long startTime = System.nanoTime();
    
    for (int i = 0; i < arr.length - 1; i++) {
        int minIndex = i;
        
        for (int j = i + 1; j < arr.length; j++) {
            result.comparisons++;
            if (arr[minIndex] > arr[j]) {
                minIndex = j;
            }
        }
        
        if (minIndex != i) {
            result.swaps++;
            int temp = arr[i];
            arr[i] = arr[minIndex];
            arr[minIndex] = temp;
        }
    }
    
    result.executionTime = System.nanoTime() - startTime;
    return result;
}
```

public static void sortWithVisualization(int[] arr) {

### Пример 5: Сортировка с ранним завершением

Реализуем оптимизированную версию, которая проверяет, отсортирован ли массив, и завершает работу досрочно:

```java
public static boolean isSorted(int[] arr) {
    for (int i = 0; i < arr.length - 1; i++) {
        if (arr[i] > arr[i + 1]) {
            return false;
        }
    }
    return true;
}

public static void sortWithEarlyExit(int[] arr) {
    if (isSorted(arr)) {
        System.out.println("Массив уже отсортирован, пропускаем сортировку");
        return;
    }
    
    for (int i = 0; i < arr.length - 1; i++) {
        int minIndex = i;
        boolean foundSmaller = false;
        
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[minIndex] > arr[j]) {
                minIndex = j;
                foundSmaller = true;
            }
        }
        
        if (!foundSmaller && isSorted(arr)) {
            System.out.println("Массив отсортирован на итерации " + (i + 1));
            break;
        }
        
        if (minIndex != i) {
            int temp = arr[i];
            arr[i] = arr[minIndex];
            arr[minIndex] = temp;
        }
    }
}
```

Хотя эта оптимизация может помочь в некоторых случаях, важно отметить, что проверка отсортированности массива сама по себе имеет сложность `O(n)`, что может не дать значительного улучшения производительности для сортировки выбором, так как алгоритм всё равно должен выполнить все сравнения для поиска минимального элемента.

Сортировка выбором, несмотря на свои ограничения, остаётся ценным инструментом в арсенале разработчика благодаря своей простоте, минимальному количеству обменов и эффективному использованию памяти. Эти особенности делают её подходящей для специфических случаев использования, где другие алгоритмы могут быть избыточными или неоптимальными.
