# Сортировка бусинами (Bead Sort) / гравитационная сортировка (Gravity Sort)

Сортировка бусинами (`bead sort`), также известная как гравитационная сортировка (`gravity sort`), — это «естественный» алгоритм, который имитирует падение бусин под действием гравитации. На практике он применим только к неотрицательным целым числам и требует матрицу размера `n × m` (где `n` — число элементов, `m` — максимальное значение), поэтому чаще используется как учебный пример и для визуализации. При этом алгоритм хорошо объясняет идею распределительных методов и связь «унарного» представления чисел с подсчётами по столбцам (по смыслу близко к `counting sort`).

## Описание алгоритма

`Bead Sort` (гравитационная сортировка, `Gravity Sort`) — алгоритм сортировки неотрицательных целых чисел, который моделирует «счёты» (`abacus`). Каждое число кодируется набором бусин: если значение равно `k`, то в соответствующей строке размещаются `k` бусин слева направо. Дальше мы «включаем гравитацию»: в каждом столбце бусины падают вниз и заполняют самые нижние доступные клетки. После такого «падения» количество бусин в каждой строке образует уже отсортированную последовательность.

Ключевой практический момент в том, что алгоритм использует двумерную матрицу размера `n × m`, где `n` — число элементов, `m` — максимальное значение. Поэтому при больших значениях `m` метод становится непрактичным: он требует много памяти и времени на инициализацию и перенос/перестановку бусин. Из-за этих ограничений `bead sort` чаще рассматривают как наглядный пример распределительных алгоритмов и как мысленный эксперимент о том, как физический процесс можно превратить в вычисление.

## Принцип работы

Рассмотрим входной список `[4, 2]`. Сначала размещаем бусины в строках (символ `●` — бусина, `·` — пусто):

```text
4: ● ● ● ●
2: ● ● · ·
```

Дальше в каждом столбце бусины «падают» вниз: если в столбце есть одна бусина, она окажется в нижней строке; если две — займут обе строки. После «падения» получаем:

```text
2: ● ● · ·
4: ● ● ● ●
```

Если теперь прочитать строки сверху вниз и посчитать бусины, получится `[2, 4]`, то есть массив отсортирован. В физической метафоре все бусины падают одновременно, но в коде это обычно делают либо имитацией перемещений, либо (быстрее) подсчётом бусин в каждом столбце и перезаполнением столбца.

## Реализация на Java

Ниже показан один из удобных способов реализовать `Bead Sort` в коде: мы представляем «счёты» как матрицу `boolean[][]`, где `true` означает наличие бусины. Важно заранее проверить вход: алгоритм корректен только для неотрицательных целых чисел.

### Шаг 1: Поиск максимального значения

Во-первых, нам нужно определить ширину матрицы. Количество столбцов `m` равно максимальному значению во входном массиве. Это именно та часть, которая делает алгоритм непрактичным при больших числах: если `m` велико, матрица становится огромной.

```java
// Ширина «счётов» равна максимальному значению: иначе мы не сможем разместить бусины.
static int findMaxNonNegative(int[] a) {
    int max = 0;
    for (int v : a) {
        if (v < 0) {
            throw new IllegalArgumentException("Bead sort supports only non-negative integers");
        }
        if (v > max) {
            max = v;
        }
    }
    return max;
}
```

Теперь мы можем вычислить `m`:

```java
// Пример использования: находим максимальное значение для определения ширины матрицы
int[] a = {1, 3, 4, 2};
int m = findMaxNonNegative(a); // m = 4, значит матрица будет иметь 4 столбца
```

### Шаг 2: Создание счетов

Теперь с помощью `m` создаём представление счётов. Значение `k` превращается в `k` бусин в своей строке (слева направо). Для этого воспользуемся методом `setupAbacus()`:

```java
// Создание начального состояния «счётов»: каждое число преобразуется в соответствующее количество бусин
static boolean[][] setupAbacus(int[] a, int m) {
    // Создаём матрицу размером n × m, где n — количество элементов, m — максимальное значение
    boolean[][] abacus = new boolean[a.length][m];

    // Для каждого элемента массива размещаем бусины в строке слева направо
    for (int row = 0; row < a.length; row++) {
        int beads = a[row]; // Количество бусин равно значению элемента
        // Ставим бусины в первых 'beads' столбцах текущей строки
        for (int col = 0; col < beads; col++) {
            abacus[row][col] = true; // true означает наличие бусины
        }
    }

    return abacus;
}
```

Метод `setupAbacus()` возвращает начальное состояние счётов. Мы не заполняем все `n × m` ячеек — только ставим бусины в первых `k` столбцах строки, потому что это ровно соответствует идее «унарного» представления.

Создадим счёты:

```java
// Создаём начальное состояние счётов для входного массива
boolean[][] abacus = setupAbacus(a, m);
```

### Шаг 3: Падение бусин

Теперь мы готовы «включить гравитацию» и опустить бусины в самые нижние возможные положения. Ниже — наивная имитация падения (она наглядна, но может быть медленной из‑за множества мелких перемещений):

```java
// Наивная имитация падения бусин: пошаговое перемещение каждой бусины вниз
// Внимание: этот метод медленный (O(n² · m)), используется только для демонстрации
static void dropBeadsSimulatingGravity(boolean[][] abacus) {
    int n = abacus.length; // Количество строк
    int m = abacus[0].length; // Количество столбцов

    // Обрабатываем каждый столбец независимо
    for (int col = 0; col < m; col++) {
        // Проходим снизу вверх, ищем пустые клетки
        for (int row = n - 1; row >= 0; row--) {
            // Если клетка уже занята бусиной, пропускаем
            if (abacus[row][col]) {
                continue;
            }

            // Ищем ближайшую бусину сверху в этом столбце
            int k = row - 1;
            while (k >= 0 && !abacus[k][col]) {
                k--;
            }
            // Если нашли бусину, перемещаем её вниз
            if (k >= 0) {
                abacus[row][col] = true; // Ставим бусину в нижнюю клетку
                abacus[k][col] = false; // Убираем бусину из верхней клетки
            }
        }
    }
}
```

В этом варианте мы обрабатываем каждый столбец и «протягиваем» бусины вниз в свободные клетки. Физический смысл понятен, но по стоимости такой подход легко превращается в `O(n² · m)` из‑за внутреннего поиска ближайшей бусины сверху.

### Шаг 4: Преобразование в отсортированный массив

Наконец, нам нужно преобразовать конечное состояние счётов в отсортированный массив. После «падения» число бусин в каждой строке и есть значение элемента. Если мы читаем строки сверху вниз, получаем возрастающий порядок:

```java
// Преобразование конечного состояния счётов в отсортированный массив
// После «падения» количество бусин в строке равно значению элемента
static void toSortedArray(boolean[][] abacus, int[] a) {
    // Проходим по каждой строке сверху вниз
    for (int row = 0; row < abacus.length; row++) {
        int beads = 0;
        // Считаем подряд идущие бусины слева направо (они всегда лежат слева после падения)
        while (beads < abacus[0].length && abacus[row][beads]) {
            beads++;
        }
        // Записываем количество бусин как значение элемента
        a[row] = beads;
    }
}
```

Здесь мы просто считаем подряд идущие `true` в строке: бусины всегда лежат слева, поэтому этот подсчёт корректен и не требует проходить весь столбец до конца.

### Оптимизация: «падение» подсчётом по столбцам

Физически бусины падают «сразу», и в программной модели это удобно реализовать подсчётом: в каждом столбце считаем количество бусин и затем просто заполняем этим количеством нижнюю часть столбца. Это убирает необходимость в множестве перестановок и даёт время `O(n · m)` для стадии «падения»:

```java
// Оптимизированное «падение» бусин через подсчёт: O(n · m) вместо O(n² · m)
// Вместо пошагового перемещения считаем бусины в столбце и заполняем столбец снизу
static void dropBeadsByCounting(boolean[][] abacus) {
    int n = abacus.length; // Количество строк
    int m = abacus[0].length; // Количество столбцов

    // Обрабатываем каждый столбец независимо
    for (int col = 0; col < m; col++) {
        // Считаем общее количество бусин в текущем столбце
        int beads = 0;
        for (int row = 0; row < n; row++) {
            if (abacus[row][col]) {
                beads++;
            }
        }

        // Заполняем столбец снизу: так мы воспроизводим «гравитацию» без пошаговых перестановок
        // Бусины занимают нижние 'beads' строк столбца
        for (int row = 0; row < n; row++) {
            abacus[row][col] = row >= n - beads; // true для нижних 'beads' строк
        }
    }
}
```

### Полная реализация

В практической реализации обычно сразу используют подсчётный вариант «падения», потому что он проще для анализа и заметно быстрее на тех входах, где сам `bead sort` вообще имеет смысл:

```java
// Класс для реализации гравитационной сортировки (Bead Sort)
public final class GravitySort {

    // Приватный конструктор: класс утилитный, создавать экземпляры не нужно
    private GravitySort() {
    }

    // Основной метод сортировки: сортирует массив неотрицательных целых чисел на месте
    public static void sort(int[] a) {
        // Проверка на пустой массив или null
        if (a == null || a.length == 0) {
            return;
        }

        // Находим максимальное значение (одновременно валидируем, что все числа неотрицательные)
        int m = findMaxNonNegative(a);
        // Если все элементы равны нулю, массив уже отсортирован
        if (m == 0) {
            return;
        }

        // Создаём матрицу «счётов» и выполняем сортировку
        boolean[][] abacus = setupAbacus(a, m); // Преобразуем числа в бусины
        dropBeadsByCounting(abacus); // «Включаем гравитацию»: бусины падают вниз
        toSortedArray(abacus, a); // Читаем отсортированный результат
    }

    // Ширина «счётов» равна максимальному значению: иначе мы не сможем разместить бусины
    // Одновременно проверяем, что все числа неотрицательные
    static int findMaxNonNegative(int[] a) {
        int max = 0;
        for (int v : a) {
            // Валидация: алгоритм работает только с неотрицательными числами
            if (v < 0) {
                throw new IllegalArgumentException("Bead sort supports only non-negative integers");
            }
            // Обновляем максимум
            if (v > max) {
                max = v;
            }
        }
        return max;
    }

    // Создание начального состояния «счётов»: каждое число преобразуется в соответствующее количество бусин
    static boolean[][] setupAbacus(int[] a, int m) {
        // Создаём матрицу размером n × m
        boolean[][] abacus = new boolean[a.length][m];

        // Для каждого элемента размещаем бусины в строке слева направо
        for (int row = 0; row < a.length; row++) {
            int beads = a[row]; // Количество бусин равно значению элемента
            // Ставим бусины в первых 'beads' столбцах
            for (int col = 0; col < beads; col++) {
                abacus[row][col] = true; // true означает наличие бусины
            }
        }

        return abacus;
    }

    // Оптимизированное «падение» бусин через подсчёт
    static void dropBeadsByCounting(boolean[][] abacus) {
        int n = abacus.length; // Количество строк
        int m = abacus[0].length; // Количество столбцов

        // Обрабатываем каждый столбец независимо
        for (int col = 0; col < m; col++) {
            // Считаем количество бусин в столбце
            int beads = 0;
            for (int row = 0; row < n; row++) {
                if (abacus[row][col]) {
                    beads++;
                }
            }

            // Заполняем столбец снизу: бусины занимают нижние 'beads' строк
            for (int row = 0; row < n; row++) {
                abacus[row][col] = row >= n - beads;
            }
        }
    }

    // Преобразование конечного состояния счётов в отсортированный массив
    static void toSortedArray(boolean[][] abacus, int[] a) {
        // Проходим по каждой строке и считаем бусины
        for (int row = 0; row < abacus.length; row++) {
            int beads = 0;
            // Считаем подряд идущие бусины слева направо
            while (beads < abacus[0].length && abacus[row][beads]) {
                beads++;
            }
            // Записываем количество бусин как значение элемента
            a[row] = beads;
        }
    }
}
```

### Тестирование

Мы можем подтвердить, что алгоритм работает, создав модульные тесты (пример для `JUnit` 5):

```java
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.assertArrayEquals;
import static org.junit.jupiter.api.Assertions.assertThrows;

// Класс для тестирования гравитационной сортировки
class GravitySortTest {

    // Тест основной функциональности: проверяем, что массив корректно сортируется
    @Test
    void givenIntegerArray_whenSortedWithGravitySort_thenGetSortedArray() {
        // Исходный массив с различными значениями, включая дубликаты и нули
        int[] actual = {9, 9, 100, 3, 57, 12, 3, 78, 0, 2, 2, 40, 21, 9};
        // Ожидаемый результат: отсортированный массив по возрастанию
        int[] expected = {0, 2, 2, 3, 3, 9, 9, 9, 12, 21, 40, 57, 78, 100};
        // Выполняем сортировку
        GravitySort.sort(actual);
        // Проверяем, что результат соответствует ожидаемому
        assertArrayEquals(expected, actual);
    }

    // Тест валидации: проверяем, что отрицательные числа вызывают исключение
    @Test
    void givenNegativeValue_whenSorted_thenThrow() {
        // Массив содержит отрицательное число
        int[] actual = {3, -1, 2};
        // Ожидаем исключение IllegalArgumentException
        assertThrows(IllegalArgumentException.class, () -> GravitySort.sort(actual));
    }
}
```

## Реализация на Kotlin

В `Kotlin` удобно сделать реализацию максимально похожей на `Java`: функция сортирует `IntArray` на месте и валидирует вход (только неотрицательные значения).

### Вспомогательные методы

```kotlin
// Поиск максимального значения с валидацией неотрицательных чисел
private fun findMaxNonNegative(a: IntArray): Int {
    var max = 0
    for (v in a) {
        // Валидация: алгоритм работает только с неотрицательными числами
        require(v >= 0) { "Bead sort supports only non-negative integers" }
        // Обновляем максимум
        if (v > max) {
            max = v
        }
    }
    return max
}

// Создание начального состояния «счётов»: каждое число преобразуется в соответствующее количество бусин
private fun setupAbacus(a: IntArray, m: Int): Array<BooleanArray> {
    // Создаём матрицу размером n × m
    val abacus = Array(a.size) { BooleanArray(m) }

    // Для каждого элемента размещаем бусины в строке слева направо
    for (row in a.indices) {
        val beads = a[row] // Количество бусин равно значению элемента
        // Ставим бусины в первых 'beads' столбцах
        for (col in 0 until beads) {
            abacus[row][col] = true // true означает наличие бусины
        }
    }

    return abacus
}

// Оптимизированное «падение» бусин через подсчёт
private fun dropBeadsByCounting(abacus: Array<BooleanArray>) {
    val n = abacus.size // Количество строк
    val m = abacus[0].size // Количество столбцов

    // Обрабатываем каждый столбец независимо
    for (col in 0 until m) {
        // Считаем количество бусин в столбце
        var beads = 0
        for (row in 0 until n) {
            if (abacus[row][col]) {
                beads++
            }
        }

        // Заполняем столбец снизу: бусины занимают нижние 'beads' строк
        for (row in 0 until n) {
            abacus[row][col] = row >= n - beads
        }
    }
}

// Преобразование конечного состояния счётов в отсортированный массив
private fun toSortedArray(abacus: Array<BooleanArray>, a: IntArray) {
    // Проходим по каждой строке и считаем бусины
    for (row in a.indices) {
        var beads = 0
        // Считаем подряд идущие бусины слева направо
        while (beads < abacus[0].size && abacus[row][beads]) {
            beads++
        }
        // Записываем количество бусин как значение элемента
        a[row] = beads
    }
}
```

// Объект для реализации гравитационной сортировки (Bead Sort)
object GravitySort {

    // Основной метод сортировки: сортирует массив неотрицательных целых чисел на месте
    fun sort(a: IntArray) {
        // Проверка на пустой массив
        if (a.isEmpty()) return

        // Находим максимальное значение (одновременно валидируем, что все числа неотрицательные)
        val m = findMaxNonNegative(a)
        // Если все элементы равны нулю, массив уже отсортирован
        if (m == 0) return

        val abacus = setupAbacus(a, m) // Преобразуем числа в бусины
        dropBeadsByCounting(abacus) // «Включаем гравитацию»: бусины падают вниз
        toSortedArray(abacus, a) // Читаем отсортированный результат
    }
}

## Сложность

Для `bead sort` важно понимать, что сложность зависит не только от количества элементов `n`, но и от максимального значения `m`. По сути мы работаем с «картинкой» `n × m`, поэтому если `m` велико, алгоритм становится непрактичным даже теоретически.

### Временная сложность

В реализации с подсчётным «падением» (см. `dropBeadsByCounting()`) основная стоимость — проходы по матрице:

| Этап | Время | Почему так |
|------|-------|-----------|
| Поиск `m` | `O(n)` | один проход по массиву |
| Построение матрицы | `O(n · m)` в худшем | если значения близки к `m`, «бусин» почти `n · m` |
| «Падение» подсчётом | `O(n · m)` | на каждый столбец считаем бусины и перезаполняем столбец |
| Чтение результата | `O(n · m)` | в каждой строке считаем подряд идущие `true` |

Итого: по порядку `O(n · m)`.

Если вместо подсчёта использовать пошаговую имитацию перемещений (как `dropBeadsSimulatingGravity()`), время может вырасти до `O(n² · m)` на неблагоприятных входах, потому что для каждой пустой клетки мы делаем поиск ближайшей бусины сверху и выполняем много мелких перемещений.

### Пространственная сложность

Основная память — матрица `n × m`, то есть `O(n · m)`. Именно поэтому алгоритм редко применяют на практике: даже при умеренных `n`, но больших `m` память «взрывается».

Если тема интересует именно как модель, а не как «реальный» алгоритм сортировки, обычно обсуждают варианты хранения:

- матрица `boolean[][]` — проще всего понять и отладить;
- упаковка в биты (например, `BitSet`) — та же идея, но существенно меньше памяти;
- аппаратная реализация — в ней «гравитация» фактически выполняется физикой, а не CPU.

## Особенности

Главная особенность `Bead Sort` в том, что это не алгоритм сравнения: он не сравнивает пары элементов и не строит порядок на основе `Comparator`. Вместо этого он преобразует числа в «геометрию» — набор бусин — и выполняет операцию, которая похожа на распределение по столбцам.

Алгоритм легко визуализировать: именно поэтому он часто встречается в образовательных материалах. Эта визуальность полезна для объяснения того, что сложность может зависеть от величины значений, а не только от количества элементов.

При этом ограничения у метода жёсткие. Он работает только с неотрицательными целыми числами и требует много памяти. Поэтому в программной практике `bead sort` почти всегда заменяют на `counting sort`, `radix sort` или обычные алгоритмы сравнения.

## Применение

На практике `Bead Sort` используют в основном как демонстрацию «естественных» алгоритмов и как способ наглядно показать связь между представлением данных и сложностью вычислений. В прикладной разработке он может быть интересен разве что как часть разговора об аппаратных ускорителях или о параллельной обработке: столбцы в модели независимы, и «падение» можно распараллелить по столбцам.

Если же цель — просто отсортировать массив, то в большинстве случаев правильным выбором будет стандартная сортировка (`Arrays.sort()` / `Collections.sort()`), либо специализированные распределительные методы (`counting sort`, `radix sort`) в зависимости от типа и диапазона данных.

## Ограничения

Основное ограничение — зависимость от `m`. Даже если `n` небольшой, но максимальное значение велико (например, `m = 10^9`), построить матрицу невозможно. Поэтому алгоритм применим только в ситуациях, где значения гарантированно малы.

Также алгоритм определён для чисел, а не для объектов с «полезной нагрузкой». Если пытаться «перенести» идею на объекты, неизбежно возникает вопрос стабильности и сохранения идентичности элементов. В классической формулировке `bead sort` просто возвращает отсортированные значения и не сохраняет связь с исходными позициями.

## Сравнение с другими алгоритмами

| Алгоритм | Временная сложность | Пространственная сложность | Применение |
|----------|---------------------|----------------------------|------------|
| `Bead Sort` | `O(n · m)` (или `O(n² · m)` для наивной симуляции) | `O(n · m)` | Учебные примеры, визуализация |
| `Bubble Sort` | `O(n²)` | `O(1)` | Учебные примеры, очень маленькие массивы |
| `Quick Sort` | `O(n log n)` в среднем, `O(n²)` в худшем | `O(log n)` стек (в среднем) | Алгоритм общего назначения |
| `Counting Sort` | `O(n + k)` | `O(k)` | Целые числа в ограниченном диапазоне |

## Лучшие практики

Если вы реализуете `Bead Sort` ради демонстрации идеи, есть несколько практических советов, которые делают пример «честным» и удобным для чтения.

Во-первых, валидируйте вход: поддерживаются только неотрицательные целые числа. Это лучше делать явно (как в `findMaxNonNegative()` / `require(v >= 0)`), чтобы ошибку было легко диагностировать.

Во-вторых, используйте подсчётный вариант «падения» (`dropBeadsByCounting()`), потому что он ближе к физической интерпретации «всё падает одновременно» и проще по сложности. Пошаговая симуляция годится для визуализации, но как реализация она обычно только усложняет код.

В-третьих, не пытайтесь применять алгоритм на данных с большим `m`. Если вы видите, что диапазон значений большой, почти всегда лучше использовать `counting sort` (если диапазон ограничен), `radix sort` (если числа целые), или библиотечные сортировки.

Наконец, покрывайте тестами типовые случаи: пустой массив, один элемент, массив с нулями, дубликаты, уже отсортированный массив и наличие отрицательного значения (ожидаем исключение).

## Решение проблем

| Симптом | Возможная причина | Что делать |
|--------|-------------------|-----------|
| `OutOfMemoryError` / резкий рост памяти | `m` слишком большое, матрица `n × m` не помещается | Не использовать `bead sort` для таких данных; перейти на `Arrays.sort()` / `counting sort` / `radix sort` |
| Очень долго работает даже на умеренном `n` | Значения близки к `m`, матрица почти полностью заполнена | Использовать подсчётное «падение» и маленькие диапазоны; иначе выбрать другой алгоритм |
| Исключение про отрицательные числа | Во входе есть `v < 0` | Нормализовать данные или выбрать другой алгоритм |
| «Сортировка» меняет порядок связанных объектов | Алгоритм определён для чисел; «идентичность» не переносится | Для объектов использовать алгоритмы сравнения и `Comparator` |

## Частые вопросы

**Вопрос:** Почему `Bead Sort` нельзя напрямую применить к отрицательным числам?
**Ответ:** Представление через бусины — это унарное кодирование: число `k` соответствует `k` бусинам. Для отрицательных значений такое представление требует смещения диапазона (например, прибавить `|min|`), что увеличивает `m` и делает матрицу ещё больше. На практике проще выбрать другой алгоритм.

**Вопрос:** Это стабильная сортировка?
**Ответ:** В классической формулировке алгоритм работает с числами и возвращает отсортированные значения, не сохраняя «личность» элементов. Если вы попытаетесь привязать к числам объекты, то стабильность не гарантируется — вы теряете информацию о том, какой именно объект соответствовал конкретной «бусине».

**Вопрос:** Почему сложность зависит от `m`, а не только от `n`?
**Ответ:** Потому что алгоритм строит структуру `n × m`. Даже если `n` маленькое, но `m` большое, объём работы и памяти растёт пропорционально `m`.

**Вопрос:** Чем это похоже на `counting sort`?
**Ответ:** По духу оба алгоритма распределительные и используют «подсчёты». В `Bead Sort` подсчёт происходит на уровне столбцов матрицы (сколько бусин в каждом столбце), а в `counting sort` — на уровне значений (сколько элементов каждого значения).

**Вопрос:** Есть ли практический смысл реализовывать `Bead Sort` в продакшене?
**Ответ:** Почти никогда. Даже при подсчётном «падении» требование `O(n · m)` памяти делает его хуже альтернатив. Исключение — образовательные/демо‑проекты и специфические аппаратные реализации.

**Вопрос:** Можно ли распараллелить алгоритм?
**Ответ:** Да, в модели с подсчётом каждый столбец независим. Но даже параллелизм не решает фундаментальную проблему памяти при большом `m`.

**Вопрос:** Что будет, если массив уже отсортирован?
**Ответ:** Для `bead sort` это почти ничего не меняет: матрицу всё равно нужно построить, а «падение» всё равно проходит по столбцам. В отличие от некоторых алгоритмов сравнения, «раннего выхода» по сути нет.

**Вопрос:** Почему в примерах используется `boolean[][]`, а не числа?
**Ответ:** Потому что это самый прозрачный способ показать идею. В оптимизациях можно упаковывать данные в биты (`BitSet`), но смысл алгоритма от этого не меняется.

## Глоссарий терминов

`Bead Sort` — сортировка, моделирующая падение бусин в матрице `n × m` для сортировки неотрицательных целых чисел.

`Gravity Sort` — другое название `Bead Sort`, подчёркивающее метафору «гравитации».

`abacus` — «счёты»; в контексте алгоритма — двумерная матрица, где наличие бусины в клетке кодируется значением `true`.

`n` — количество элементов во входном массиве.

`m` — максимальное значение во входном массиве; определяет количество столбцов в матрице.

`Унарное представление` — способ кодирования числа `k` как `k` одинаковых «единиц» (в данном случае — бусин).

`Распределительный алгоритм` — алгоритм сортировки, который не сравнивает элементы попарно, а распределяет их по группам/ячейкам на основе значений.

## Дополнительные примеры использования

Ниже — несколько небольших фрагментов, которые помогают сделать демонстрационную реализацию удобнее для изучения и отладки.

### Печать «счётов» для отладки

Такой вывод полезен только для маленьких `n` и `m`, но помогает быстро проверить, что «падение» работает как ожидается:

```java
// Вспомогательный метод для визуализации состояния «счётов» (только для отладки)
// Полезен только для маленьких n и m, помогает проверить корректность работы алгоритма
static void printAbacus(boolean[][] abacus) {
    // Проходим по каждой строке матрицы
    for (boolean[] row : abacus) {
        StringBuilder sb = new StringBuilder();
        // Преобразуем каждую клетку в символ: ● для бусины, · для пустой клетки
        for (boolean cell : row) {
            sb.append(cell ? "● " : "· ");
        }
        // Выводим строку без лишних пробелов в конце
        System.out.println(sb.toString().trim());
    }
}
```

### Параллельное «падение» по столбцам

Колонки независимы, поэтому подсчётный вариант можно распараллелить. Это имеет смысл только если `m` умеренное, а CPU действительно простаивает:

```java
// Параллельная версия «падения» бусин: столбцы обрабатываются независимо
// Имеет смысл только если m умеренное и CPU простаивает
static void dropBeadsByCountingParallel(boolean[][] abacus) {
    int n = abacus.length; // Количество строк
    int m = abacus[0].length; // Количество столбцов

    // Обрабатываем столбцы параллельно через Stream API
    java.util.stream.IntStream.range(0, m).parallel().forEach(col -> {
        // Считаем количество бусин в текущем столбце
        int beads = 0;
        for (int row = 0; row < n; row++) {
            if (abacus[row][col]) {
                beads++;
            }
        }
        // Заполняем столбец снизу: бусины занимают нижние 'beads' строк
        for (int row = 0; row < n; row++) {
            abacus[row][col] = row >= n - beads;
        }
    });
}
```

### Упаковка в биты (`BitSet`) как идея оптимизации памяти

Если хочется поэкспериментировать с памятью, вместо `boolean[][]` можно хранить строки как `BitSet`. Логика не меняется, но одна клетка занимает 1 бит вместо байта/слова. Такой вариант сложнее кода, зато хорошо демонстрирует, что «узкое место» здесь — память:

```java
// Идея оптимизации памяти: хранить строку как битовую маску вместо boolean[]
// Это не делает алгоритм практичным при большом m, но уменьшает константы памяти
// Один бит вместо байта/слова на клетку — полезно как учебный пример оптимизации
java.util.BitSet row = new java.util.BitSet(m);
// Устанавливаем первые 'beads' битов в true (эквивалент размещения бусин слева)
row.set(0, beads);
```

## Когда использовать

Используйте `Bead Sort`, когда ваша цель — понять и объяснить идею «естественной» сортировки, показать зависимость сложности от диапазона значений или построить визуализацию «падения» бусин. Алгоритм также интересен как повод поговорить о параллельности (независимость столбцов) и об аппаратных моделях вычислений.

Не используйте его как «рабочий» алгоритм сортировки в продакшене: требование памяти `O(n · m)` и зависимость от `m` делают его хуже практически любых альтернатив. Если нужны распределительные методы для целых чисел, чаще всего выбирают `counting sort` или `radix sort`; если нужны универсальные методы — стандартные сортировки библиотек.

## Заключение

`Bead Sort` (`Gravity Sort`) — наглядный, но редко применимый на практике алгоритм сортировки. Он показывает, как физическая метафора («бусины падают под действием гравитации») превращается в вычисление над матрицей `n × m`. В программной реализации ключевыми становятся не сравнения элементов, а построение структуры данных и операции подсчёта по столбцам.

Главный вывод: сложность алгоритма зависит от диапазона значений, а не только от количества элементов. Поэтому даже при небольшом `n` метод может оказаться невозможным при большом `m`. Для реальных задач сортировки почти всегда лучше использовать `Arrays.sort()` / `Collections.sort()`, а для целых чисел в ограниченном диапазоне — `counting sort` или `radix sort`.
