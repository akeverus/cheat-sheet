# Блочная сортировка (`Bucket Sort`)

Блочная сортировка (`bucket sort`) — это алгоритм сортировки, который распределяет элементы по нескольким «ведрам» (`buckets`), сортирует каждое ведро отдельно, а затем объединяет результаты в отсортированный массив. Алгоритм особенно эффективен, когда входные данные равномерно распределены по диапазону значений, что позволяет достичь линейной временной сложности `O(n)` в среднем случае. В отличие от алгоритмов сравнения, блочная сортировка использует распределительный подход, который может быть быстрее для определённых типов данных. Алгоритм часто используется для сортировки чисел с плавающей точкой в диапазоне [0, 1) и может быть эффективно распараллелен. В этом документе рассматриваются принципы работы блочной сортировки, её реализация на `Java` и `Kotlin`, анализ сложности и практические рекомендации по применению.

## Описание алгоритма

`Bucket sort`, иногда называемая сортировкой контейнеров, представляет собой особый алгоритм сортировки. Сортировка работает путём распределения элементов, которые мы хотим отсортировать, по нескольким индивидуально отсортированным сегментам. Делая это, мы можем уменьшить количество сравнений между элементами и сократить время сортировки. Алгоритм особенно эффективен, когда входные данные равномерно распределены по диапазону значений, что позволяет достичь линейной временной сложности `O(n)` в среднем случае.

Блочная сортировка использует распределительный подход, который отличается от алгоритмов сравнения, таких как быстрая сортировка или сортировка слиянием. Вместо сравнения элементов между собой, алгоритм распределяет их по ведрам на основе их значений, затем сортирует каждое ведро отдельно и объединяет результаты. Это делает алгоритм особенно эффективным для определённых типов данных, таких как числа с плавающей точкой в диапазоне [0, 1) или целые числа с ограниченным диапазоном.

## Принцип работы

Давайте кратко рассмотрим шаги, необходимые для выполнения сортировки ведра. Во-первых, настраиваем массив наших изначально пустых `bucket` (ведёр). Количество ведёр обычно выбирается как квадратный корень из размера входного массива или на основе диапазона значений. Затем распределяем наши элементы по соответствующим `bucket` на основе их значений, используя функцию хеширования или распределения. После этого сортируем каждое `bucket` отдельно, используя подходящий алгоритм сортировки, такой как сортировка вставками для малых ведёр или быстрая сортировка для больших ведёр. Наконец, объединяем отсортированные сегменты вместе, чтобы воссоздать полный список в отсортированном порядке.

Хотя этот алгоритм не зависит от языка, мы будем реализовывать сортировку в `Java`. Давайте шаг за шагом пройдёмся по приведённому выше списку и напишем код для сортировки списка целых чисел. Каждый шаг будет детально рассмотрен с примерами кода и объяснениями.

## Реализация на Java

Реализация блочной сортировки на `Java` демонстрирует эффективное использование ведёр для распределения элементов и последующей их сортировки. Рассмотрим основные компоненты реализации, включая функцию хеширования для распределения элементов, создание ведёр, распределение элементов и их сортировку.

### Шаг 1: Определение функции хеширования

Во-первых, нам нужно определить алгоритм хеширования, чтобы решить, какие из наших элементов помещаются в какое ведро. Функция хеширования должна равномерно распределять элементы по ведрам на основе их значений:

```java
// Распределение элемента по ведру по значению относительно максимума
private int hash(int i, int max, int numberOfBuckets) {
    return (int) ((double) i / max * (numberOfBuckets - 1));
}
```

Эта функция распределяет элементы по ведрам на основе их значения относительно максимального значения. Элементы с меньшими значениями попадают в ведра с меньшими индексами, а элементы с большими значениями — в ведра с большими индексами. Это обеспечивает равномерное распределение элементов по ведрам при равномерном распределении входных данных.

### Шаг 2: Создание ведёр

Определив наш хэш-метод, мы теперь можем указать количество бинов как квадратный корень из размера входного списка. Это количество ведёр обеспечивает баланс между количеством ведёр и размером каждого ведра, что оптимизирует производительность алгоритма:

```java
final int numberOfBuckets = (int) Math.sqrt(initialList.size());
List<List<Integer>> buckets = new ArrayList<>(numberOfBuckets);

for(int i = 0; i < numberOfBuckets; i++) {
    buckets.add(new ArrayList<>());
}
```

Количество ведёр, равное квадратному корню из размера массива, является хорошим компромиссом между использованием памяти и временем сортировки. Слишком много ведёр увеличивает использование памяти, а слишком мало ведёр увеличивает время сортировки внутри каждого ведра.

### Шаг 3: Поиск максимального значения

Наконец, нам нужен короткий метод для определения максимального целого числа в нашем списке ввода. Максимальное значение используется функцией хеширования для равномерного распределения элементов по ведрам:

```java
private int findMax(List<Integer> input) {
    int m = Integer.MIN_VALUE;
    for (int i : input) {
        m = Math.max(i, m);
    }
    return m;
}
```

Этот метод проходит по всем элементам входного списка и находит максимальное значение, которое затем используется для нормализации значений элементов при распределении по ведрам.

### Шаг 4: Распределение элементов

Теперь, когда мы определили наши корзины, мы можем распределить каждый элемент нашего входного списка в соответствующие корзины, используя метод хеширования. Это делается путём вычисления индекса ведра для каждого элемента и добавления элемента в соответствующее ведро:

```java
int max = findMax(initialList);
for (int i : initialList) {
    buckets.get(hash(i, max, numberOfBuckets)).add(i);
}
```

Этот шаг распределяет элементы по ведрам на основе их значений. Элементы с близкими значениями попадают в одно и то же ведро или соседние ведра, что упрощает последующую сортировку.

### Шаг 5: Сортировка каждого ведра

Определив наши корзины и заполнив их целыми числами, давайте воспользуемся компаратором для их сортировки. Каждое ведро сортируется отдельно, что позволяет эффективно обрабатывать элементы внутри каждого ведра:

```java
Comparator<Integer> comparator = Comparator.naturalOrder();
for(List<Integer> bucket : buckets) {
    bucket.sort(comparator);
}
```

Для сортировки каждого ведра можно использовать различные алгоритмы сортировки в зависимости от размера ведра. Для малых ведёр эффективна сортировка вставками, для больших ведёр — быстрая сортировка или сортировка слиянием.

### Шаг 6: Объединение результатов

Наконец, нам нужно собрать наши корзины вместе, чтобы воссоздать единый список. Поскольку наши корзины отсортированы, нам нужно только один раз пройтись по каждой корзине и добавить элементы в основной список:

```java
List<Integer> sortedArray = new LinkedList<>();
for(List<Integer> bucket : buckets) {
    sortedArray.addAll(bucket);
}
return sortedArray;
```

Этот шаг объединяет отсортированные ведра в один отсортированный список. Поскольку ведра уже отсортированы и элементы распределены по ведрам на основе их значений, объединение ведёр в порядке их индексов даёт полностью отсортированный список.

### Полная реализация (Java)

```java
public class BucketSort {
    public static List<Integer> sort(List<Integer> initialList) {
        final int numberOfBuckets = (int) Math.sqrt(initialList.size());
        List<List<Integer>> buckets = new ArrayList<>(numberOfBuckets);

        for(int i = 0; i < numberOfBuckets; i++) {
            buckets.add(new ArrayList<>());
        }

        int max = findMax(initialList);

        for (int i : initialList) {
            buckets.get(hash(i, max, numberOfBuckets)).add(i);
        }

        Comparator<Integer> comparator = Comparator.naturalOrder();
        for(List<Integer> bucket : buckets) {
            bucket.sort(comparator);
        }

        List<Integer> sortedArray = new LinkedList<>();
        for(List<Integer> bucket : buckets) {
            sortedArray.addAll(bucket);
        }

        return sortedArray;
    }

    private static int hash(int i, int max, int numberOfBuckets) {
        return (int) ((double) i / max * (numberOfBuckets - 1));
    }

    private static int findMax(List<Integer> input) {
        int m = Integer.MIN_VALUE;
        for (int i : input) {
            m = Math.max(i, m);
        }
        return m;
    }
}
```

## Реализация на Kotlin

Реализация блочной сортировки на `Kotlin` следует тем же принципам, что и реализация на `Java`, но использует более идиоматичный синтаксис `Kotlin`. Рассмотрим различные варианты реализации, включая базовую версию, функциональный стиль и in-place версию для массивов.

### Полная реализация (Kotlin)

```kotlin
fun bucketSortK(initialList: List<Int>): List<Int> {
    val numberOfBuckets = Math.sqrt(initialList.size.toDouble()).toInt()
    val buckets = MutableList(numberOfBuckets) { mutableListOf<Int>() }

    val max = findMaxK(initialList)

    // Распределение элементов по ведрам
    for (i in initialList) {
        buckets[hashK(i, max, numberOfBuckets)].add(i)
    }

    // Сортировка каждого ведра
    buckets.forEach { it.sort() }

    // Объединение результатов
    return buckets.flatten()
}

private fun hashK(i: Int, max: Int, numberOfBuckets: Int): Int {
    return (i.toDouble() / max * (numberOfBuckets - 1)).toInt()
}

private fun findMaxK(input: List<Int>): Int {
    return input.maxOrNull() ?: Int.MIN_VALUE
}
```

### Функциональный стиль

```kotlin
fun bucketSortFunctionalK(initialList: List<Int>): List<Int> {
    if (initialList.isEmpty()) return emptyList()

    val numberOfBuckets = Math.sqrt(initialList.size.toDouble()).toInt()
    val max = initialList.maxOrNull() ?: return initialList

    return initialList
        .groupBy { hashK(it, max, numberOfBuckets) }
        .values
        .map { it.sorted() }
        .flatten()
}
```

### In-place версия для массивов

```kotlin
fun bucketSortArrayK(arr: IntArray) {
    if (arr.isEmpty()) return

    val numberOfBuckets = Math.sqrt(arr.size.toDouble()).toInt()
    val buckets = Array(numberOfBuckets) { mutableListOf<Int>() }
    val max = arr.maxOrNull() ?: return

    // Распределение
    arr.forEach { element ->
        buckets[hashK(element, max, numberOfBuckets)].add(element)
    }

    // Сортировка каждого ведра
    buckets.forEach { it.sort() }

    // Объединение обратно в массив
    var index = 0
    buckets.forEach { bucket ->
        bucket.forEach { element ->
            arr[index++] = element
        }
    }
}
```

### Пример использования

```kotlin
fun main() {
    val unsorted = listOf(80, 50, 60, 30, 20, 10, 70, 0, 40, 500, 600, 602, 200, 15)

    // Базовая версия
    val sorted = bucketSortK(unsorted)
    println(sorted)
    // [0, 10, 15, 20, 30, 40, 50, 60, 70, 80, 200, 500, 600, 602]

    // Функциональный стиль
    val sorted2 = bucketSortFunctionalK(unsorted)
    println(sorted2)

    // In-place для массива
    val arr = intArrayOf(80, 50, 60, 30, 20, 10, 70, 0, 40)
    bucketSortArrayK(arr)
    println(arr.contentToString())
}
```

## Сложность

Давайте кратко рассмотрим временную сложность выполнения сортировки ведром. Временная сложность алгоритма сильно зависит от распределения входных данных по ведрам, что делает анализ сложности более сложным, чем для алгоритмов сравнения.

### Временная сложность

Временная сложность блочной сортировки варьируется в зависимости от распределения элементов по ведрам. В лучшем случае, когда элементы равномерно распределены по ведрам, временная сложность составляет `O(n)`. В среднем случае, при равномерном распределении, временная сложность также составляет `O(n)`, так как каждый шаг алгоритма требует только одной итерации по входным данным и ведрам.

В худшем случае, когда все элементы попадают в одно ведро, временная сложность деградирует до `O(n²)`. В этом сценарии мы находим все наши элементы в одном и том же сегменте и в обратном порядке. Когда происходит этот случай, мы сокращаем нашу сортировку ведра до простой сортировки, в которой каждый элемент сравнивается с каждым другим элементом, что даёт временную сложность `O(n²)`.

В нашем среднем случае мы обнаруживаем, что элементы относительно равномерно распределены между нашими входными сегментами. Поскольку каждый из наших шагов требует только одной итерации по нашим входным сегментам, мы обнаруживаем, что наша сортировка по сегментам завершается за время `O(n)`. Это делает алгоритм особенно эффективным для данных с равномерным распределением.

### Пространственная сложность

Пространственная сложность блочной сортировки составляет `O(n)` для хранения ведёр и элементов во всех случаях. Это связано с тем, что алгоритм создаёт массив ведёр и распределяет все элементы входного массива по этим ведрам. Дополнительное пространство требуется для хранения ведёр и элементов внутри них, что делает пространственную сложность линейной относительно размера входных данных.

## Особенности

Блочная сортировка имеет несколько важных особенностей, которые отличают её от других алгоритмов сортировки. `Bucket Sort` является распределительным алгоритмом сортировки, что означает, что она не сравнивает элементы напрямую, а распределяет их по ведрам на основе их значений. Это позволяет алгоритму достичь линейной временной сложности `O(n)` в среднем случае при равномерном распределении данных.

Производительность алгоритма сильно зависит от распределения входных данных. Когда данные равномерно распределены по диапазону значений, алгоритм работает очень эффективно. Однако при неравномерном распределении производительность может значительно ухудшиться, вплоть до деградации до `O(n²)` в худшем случае.

Стабильность алгоритма зависит от используемого алгоритма сортировки внутри ведёр. Если алгоритм сортировки внутри ведёр является стабильным (например, сортировка вставками), то блочная сортировка также будет стабильной. Это важно в приложениях, где относительный порядок равных элементов имеет значение.

Алгоритм лучше всего работает, когда входные данные равномерно распределены по диапазону. Это делает его особенно эффективным для определённых типов данных, таких как числа с плавающей точкой в диапазоне [0, 1) или целые числа с ограниченным диапазоном.

## Применение

`Bucket Sort` особенно полезен в следующих случаях. Когда входные данные равномерно распределены по диапазону, алгоритм может достичь линейной временной сложности `O(n)`, что делает его очень эффективным для таких случаев. Для сортировки чисел с плавающей точкой в диапазоне [0, 1) алгоритм особенно эффективен, так как такие данные обычно равномерно распределены. Когда нужно отсортировать данные, которые можно разделить на «ведра» на основе их значений, блочная сортировка может быть хорошим выбором. В комбинации с другими алгоритмами сортировки блочная сортировка может использоваться как часть более сложных алгоритмов для оптимизации производительности.

Однако стоит отметить, что для типичных случаев использования, где распределение данных неизвестно или неравномерно, предпочтительнее использовать алгоритмы сравнения, такие как быстрая сортировка или сортировка слиянием, которые не зависят от распределения данных.

## Ограничения

Блочная сортировка имеет несколько важных ограничений, которые следует учитывать при выборе алгоритма. Алгоритм требует знания диапазона входных данных для правильного распределения элементов по ведрам. Может быть неэффективным, если элементы неравномерно распределены, так как это может привести к тому, что большинство элементов попадут в одно или несколько ведёр, что увеличит время сортировки внутри этих ведёр. В худшем случае деградирует до `O(n²)`, когда все элементы попадают в одно ведро, что делает алгоритм неэффективным для таких случаев. Требует дополнительной памяти для ведёр, что может быть проблематичным для больших массивов данных или систем с ограниченной памятью.

Эти ограничения делают блочную сортировку непригодной для использования в качестве алгоритма сортировки общего назначения, но очень эффективной для специфических случаев, где входные данные соответствуют требованиям алгоритма.

## Сравнение с другими алгоритмами

Сравнение блочной сортировки с другими алгоритмами показывает важные различия в их характеристиках и применении. `Bucket Sort` имеет временную сложность `O(n)` в лучшем и среднем случаях, но `O(n²)` в худшем случае, пространственную сложность `O(n)` и особенно эффективна при равномерном распределении данных. `Counting Sort` имеет временную сложность `O(n+k)` во всех случаях, пространственную сложность `O(k)` и особенно эффективна при ограниченном диапазоне значений. `Radix Sort` имеет временную сложность `O(d*(n+k))`, где `d` — количество разрядов, пространственную сложность `O(n+k)` и работает только с целыми числами.

Выбор между этими алгоритмами зависит от конкретных требований приложения. Блочная сортировка предпочтительна, когда данные равномерно распределены по диапазону значений. Сортировка подсчётом предпочтительна, когда диапазон значений ограничен и известен заранее. Поразрядная сортировка предпочтительна для целых чисел с большим количеством разрядов.

## Преимущества и недостатки

### Преимущества

Блочная сортировка имеет несколько важных преимуществ. Алгоритм очень быстрый в среднем случае (`O(n)`), когда данные равномерно распределены по диапазону значений. Это делает его особенно эффективным для таких случаев, превосходя алгоритмы сравнения благодаря отсутствию необходимости в сравнении элементов. Алгоритм хорошо работает с равномерно распределёнными данными, что делает его идеальным для определённых типов данных, таких как числа с плавающей точкой в диапазоне [0, 1). Алгоритм может быть параллелизован, так как сортировка каждого ведра может выполняться независимо, что позволяет использовать многопроцессорные системы для улучшения производительности.

### Недостатки

Однако блочная сортировка также имеет несколько недостатков. В худшем случае временная сложность составляет `O(n²)`, когда все элементы попадают в одно ведро, что делает алгоритм неэффективным для таких случаев. Алгоритм требует дополнительной памяти для хранения ведёр и элементов, что может быть проблематичным для больших массивов данных или систем с ограниченной памятью. Производительность алгоритма сильно зависит от распределения данных, что делает его непредсказуемым для данных с неизвестным распределением. Алгоритм не подходит для неравномерно распределённых данных, так как это может привести к деградации производительности до худшего случая.

## Лучшие практики

При использовании блочной сортировки важно следовать нескольким лучшим практикам. `Bucket sort` эффективен при равномерном распределении ключей; при неравномерном возможен худший случай `O(n²)`. Поэтому важно анализировать распределение данных перед выбором алгоритма и использовать блочную сортировку только когда данные действительно равномерно распределены.

Число ведёр обычно берут как квадратный корень из размера массива (`√n`) или порядка `n`. Слишком много ведёр увеличивает использование памяти, а слишком мало ведёр увеличивает время сортировки внутри ведёр. Важно найти баланс между количеством ведёр и размером каждого ведра для оптимизации производительности.

Внутри ведра используйте стабильную сортировку (например, `insertion sort`) для малых размеров или алгоритмы сравнения для больших размеров. Это позволяет оптимизировать производительность сортировки внутри каждого ведра в зависимости от его размера.

Алгоритм подходит для чисел с плавающей точкой в диапазоне [0, 1) и целых с ограниченным диапазоном. Для произвольных типов данных нужна хорошая хэш-функция, которая равномерно распределяет элементы по ведрам.

При тестировании покройте случаи: равномерное и неравномерное распределение, уже отсортированный массив, дубликаты. Это поможет убедиться, что реализация корректно обрабатывает все граничные случаи и различные распределения данных.

## Решение проблем

При работе с блочной сортировкой могут возникать различные проблемы. Если алгоритм работает медленнее, чем ожидалось, проверьте распределение данных. Если данные неравномерно распределены, большинство элементов может попасть в одно или несколько ведёр, что увеличит время сортировки внутри этих ведёр и может привести к деградации производительности до `O(n²)`.

Если возникают проблемы с памятью, убедитесь, что количество ведёр не слишком велико. Пространственная сложность `O(n)` может быть проблематичной для больших массивов данных. Рассмотрите возможность использования других алгоритмов сортировки для таких случаев или уменьшите количество ведёр, если это возможно без значительного ухудшения производительности.

Если алгоритм нестабилен и это вызывает проблемы, убедитесь, что вы используете стабильный алгоритм сортировки внутри ведёр, такой как сортировка вставками. Это гарантирует, что блочная сортировка также будет стабильной и сохранит относительный порядок равных элементов.

При проблемах с производительностью на реальных данных помните, что блочная сортировка эффективна только при равномерном распределении данных. Для типичных случаев использования, где распределение данных неизвестно или неравномерно, предпочтительнее использовать алгоритмы сравнения, такие как быстрая сортировка или сортировка слиянием.

## Частые вопросы

**Вопрос:** Почему блочная сортировка работает за линейное время в среднем случае?

**Ответ:** Блочная сортировка работает за линейное время `O(n)` в среднем случае, когда данные равномерно распределены по ведрам. Это происходит потому, что каждый шаг алгоритма требует только одной итерации по входным данным и ведрам, а сортировка внутри каждого ведра выполняется быстро благодаря небольшому количеству элементов в каждом ведре.

**Вопрос:** Что произойдёт, если все элементы попадут в одно ведро?

**Ответ:** Если все элементы попадут в одно ведро, временная сложность алгоритма деградирует до `O(n²)`, так как сортировка внутри этого ведра будет эквивалентна обычной сортировке всех элементов. Это худший случай для блочной сортировки, и в таких случаях предпочтительнее использовать другие алгоритмы сортировки.

**Вопрос:** Как выбрать оптимальное количество ведёр?

**Ответ:** Оптимальное количество ведёр обычно выбирается как квадратный корень из размера массива (`√n`) или порядка `n`. Слишком много ведёр увеличивает использование памяти, а слишком мало ведёр увеличивает время сортировки внутри ведёр. Важно найти баланс между количеством ведёр и размером каждого ведра для оптимизации производительности.

**Вопрос:** Можно ли использовать блочную сортировку для других типов данных, кроме чисел?

**Ответ:** Блочная сортировка может использоваться для других типов данных, если можно определить хорошую функцию распределения, которая равномерно распределяет элементы по ведрам. Однако для произвольных типов данных это может быть сложно, и в таких случаях предпочтительнее использовать алгоритмы сравнения.

**Вопрос:** Когда следует использовать блочную сортировку вместо быстрой сортировки?

**Ответ:** Используйте блочную сортировку, когда данные равномерно распределены по диапазону значений, когда нужно отсортировать числа с плавающей точкой в диапазоне [0, 1), или когда алгоритм используется как часть более сложных алгоритмов. Для типичных случаев использования предпочтительнее использовать быструю сортировку или другие алгоритмы сравнения, которые не зависят от распределения данных.

**Вопрос:** Можно ли распараллелить блочную сортировку?

**Ответ:** Да, блочная сортировка может быть эффективно распараллелена, так как сортировка каждого ведра может выполняться независимо. Это позволяет использовать многопроцессорные системы для улучшения производительности, распределяя сортировку различных ведёр между различными процессорами или ядрами.

## Глоссарий терминов

`Bucket Sort` (блочная сортировка) — алгоритм сортировки, который распределяет элементы по нескольким ведрам на основе их значений, сортирует каждое ведро отдельно и объединяет результаты в отсортированный массив.

`Ведро` (`bucket`) — контейнер, используемый для группировки элементов с близкими значениями перед их сортировкой. Количество ведёр обычно выбирается как квадратный корень из размера массива.

`Функция хеширования` — функция, которая определяет, в какое ведро должен попасть каждый элемент на основе его значения. Функция должна равномерно распределять элементы по ведрам для оптимальной производительности.

`Распределительная сортировка` — тип алгоритма сортировки, который не сравнивает элементы напрямую, а распределяет их по группам на основе их значений. Блочная сортировка является примером распределительной сортировки.

`Равномерное распределение` — свойство данных, при котором элементы равномерно распределены по диапазону значений. Блочная сортировка особенно эффективна для данных с равномерным распределением.

`Стабильность сортировки` — свойство алгоритма сортировки сохранять относительный порядок равных элементов после сортировки. Блочная сортировка может быть стабильной, если используемый алгоритм сортировки внутри ведёр является стабильным.

`Параллелизация` — процесс разделения алгоритма на независимые части, которые могут выполняться одновременно на разных процессорах или ядрах. Блочная сортировка может быть эффективно распараллелена, так как сортировка каждого ведра может выполняться независимо.

`Деградация производительности` — ухудшение производительности алгоритма в худшем случае. Для блочной сортировки деградация происходит, когда все элементы попадают в одно ведро, что приводит к временной сложности `O(n²)`.

## Дополнительные примеры использования

Рассмотрим несколько практических примеров использования блочной сортировки в различных сценариях.

### Пример 1: Сортировка чисел с плавающей точкой

Пример сортировки чисел с плавающей точкой в диапазоне [0, 1):

```java
public static double[] bucketSortDoubles(double[] arr) {
    if (arr.length == 0) return new double[0];

    int n = arr.length;
    List<List<Double>> buckets = new ArrayList<>(n);

    // Инициализация ведёр
    for (int i = 0; i < n; i++) {
        buckets.add(new ArrayList<>());
    }

    // Распределение элементов по ведрам
    for (double num : arr) {
        int bucketIndex = (int) (n * num);
        buckets.get(bucketIndex).add(num);
    }

    // Сортировка каждого ведра
    for (List<Double> bucket : buckets) {
        Collections.sort(bucket);
    }

    // Объединение результатов
    double[] sorted = new double[n];
    int index = 0;
    for (List<Double> bucket : buckets) {
        for (double num : bucket) {
            sorted[index++] = num;
        }
    }

    return sorted;
}
```

### Пример 2: Сортировка объектов по целочисленному полю

Пример сортировки объектов по целочисленному полю с использованием блочной сортировки:

```java
public static class Student {
    int grade;
    String name;

    Student(int grade, String name) {
        this.grade = grade;
        this.name = name;
    }
}

public static Student[] sortByGrade(Student[] students, int maxGrade) {
    int numberOfBuckets = (int) Math.sqrt(students.length);
    List<List<Student>> buckets = new ArrayList<>(numberOfBuckets);

    for (int i = 0; i < numberOfBuckets; i++) {
        buckets.add(new ArrayList<>());
    }

    // Распределение по ведрам
    for (Student student : students) {
        int bucketIndex = (student.grade * numberOfBuckets) / (maxGrade + 1);
        buckets.get(bucketIndex).add(student);
    }

    // Сортировка каждого ведра
    for (List<Student> bucket : buckets) {
        bucket.sort(Comparator.comparingInt(s -> s.grade));
    }

    // Объединение результатов
    Student[] sorted = new Student[students.length];
    int index = 0;
    for (List<Student> bucket : buckets) {
        for (Student student : bucket) {
            sorted[index++] = student;
        }
    }

    return sorted;
}
```

### Пример 3: Оптимизированная версия с выбором алгоритма сортировки

Пример оптимизированной версии с выбором алгоритма сортировки в зависимости от размера ведра:

```java
public static List<Integer> bucketSortOptimized(List<Integer> arr) {
    int n = arr.size();
    int numberOfBuckets = (int) Math.sqrt(n);
    List<List<Integer>> buckets = new ArrayList<>(numberOfBuckets);

    for (int i = 0; i < numberOfBuckets; i++) {
        buckets.add(new ArrayList<>());
    }

    int max = Collections.max(arr);

    // Распределение элементов
    for (int num : arr) {
        int bucketIndex = hash(num, max, numberOfBuckets);
        buckets.get(bucketIndex).add(num);
    }

    // Сортировка каждого ведра с выбором алгоритма
    for (List<Integer> bucket : buckets) {
        if (bucket.size() < 10) {
            // Используем сортировку вставками для малых ведёр
            insertionSort(bucket);
        } else {
            // Используем быструю сортировку для больших ведёр
            bucket.sort(Comparator.naturalOrder());
        }
    }

    // Объединение результатов
    List<Integer> sorted = new ArrayList<>();
    for (List<Integer> bucket : buckets) {
        sorted.addAll(bucket);
    }

    return sorted;
}

private static void insertionSort(List<Integer> list) {
    for (int i = 1; i < list.size(); i++) {
        int key = list.get(i);
        int j = i - 1;
        while (j >= 0 && list.get(j) > key) {
            list.set(j + 1, list.get(j));
            j--;
        }
        list.set(j + 1, key);
    }
}
```

## Когда использовать

Выбор между блочной сортировкой и другими алгоритмами сортировки зависит от конкретных требований приложения. Используйте блочную сортировку, когда входные данные равномерно распределены по диапазону значений, когда нужно отсортировать числа с плавающей точкой в диапазоне [0, 1), когда данные можно эффективно разделить на ведра на основе их значений, или когда алгоритм используется как часть более сложных алгоритмов для оптимизации производительности.

Блочная сортировка особенно эффективна для случаев, где количество различных значений невелико по сравнению с общим количеством элементов и где данные равномерно распределены. Это делает её идеальной для сортировки данных с ограниченным диапазоном значений и равномерным распределением, таких как оценки студентов, возраст людей или другие данные с небольшим диапазоном возможных значений и равномерным распределением.

Не используйте блочную сортировку, когда данные неравномерно распределены по диапазону значений, когда распределение данных неизвестно заранее, когда требуется гарантированная производительность без зависимости от распределения данных, или когда дополнительная память `O(n)` является проблемой. В таких случаях предпочтительнее использовать алгоритмы сравнения, такие как быстрая сортировка или сортировка слиянием, которые не зависят от распределения данных и могут быть более эффективными по использованию памяти.

## Заключение

Блочная сортировка — это эффективный алгоритм сортировки для случаев, где входные данные равномерно распределены по диапазону значений. Алгоритм обеспечивает линейную временную сложность `O(n)` в среднем случае при равномерном распределении данных, что делает его быстрее алгоритмов сравнения для таких случаев. Возможность параллелизации и эффективная работа с определёнными типами данных делают его полезным инструментом в арсенале разработчика.

Однако важно понимать ограничения алгоритма. Блочная сортировка требует знания диапазона входных данных, может быть неэффективной для неравномерно распределённых данных и деградирует до `O(n²)` в худшем случае. Для типичных случаев использования, где распределение данных неизвестно или неравномерно, предпочтительнее использовать алгоритмы сравнения, такие как быстрая сортировка или сортировка слиянием.

Понимание принципов работы блочной сортировки, её преимуществ и ограничений, а также умение выбирать подходящий алгоритм для конкретной задачи является важным навыком для разработчика. Выбор между блочной сортировкой и другими алгоритмами должен основываться на конкретных требованиях приложения, характеристиках данных и доступных ресурсах.

Важно также помнить, что эффективность алгоритма зависит не только от его временной и пространственной сложности, но и от конкретных характеристик данных и их распределения. Для данных с равномерным распределением блочная сортировка может показать отличную производительность, превосходя алгоритмы сравнения благодаря линейной временной сложности. Однако для типичных случаев использования, где распределение данных неизвестно или неравномерно, предпочтительнее использовать алгоритмы сравнения, которые не зависят от распределения данных и могут быть более эффективными по использованию памяти.

Умение анализировать требования приложения, характеристики данных и доступные ресурсы для выбора оптимального алгоритма отличает опытного разработчика от начинающего и позволяет создавать эффективные и надёжные решения для различных задач обработки данных. Понимание различных подходов к сортировке и их влияния на производительность и использование памяти является важной частью образования разработчика и помогает принимать обоснованные решения при реализации алгоритмов для конкретных приложений.
