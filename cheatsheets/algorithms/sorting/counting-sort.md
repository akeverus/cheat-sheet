# Сортировка подсчётом (`Counting Sort`)

**Дата последнего обновления:** 2026-02-06

Сортировка подсчётом — это алгоритм сортировки, который работает за линейное время `O(n+k)`, когда диапазон входных данных ограничен. В отличие от алгоритмов сравнения, он не сравнивает элементы, а использует подсчёт частоты элементов. Это делает его особенно эффективным для сортировки целых чисел в небольшом диапазоне, где `k` (максимальное значение) не слишком велико по сравнению с количеством элементов `n`. Алгоритм является стабильным, что означает, что элементы с одинаковыми значениями сохраняют свой относительный порядок в отсортированном массиве. Сортировка подсчётом часто используется как часть более сложных алгоритмов, таких как поразрядная сортировка (`Radix Sort`). В этом документе рассматриваются принципы работы сортировки подсчётом, её реализация на `Java` и `Kotlin`, анализ сложности и практические рекомендации по применению.

## Описание алгоритма

Алгоритмы сортировки общего назначения, такие как сортировка слиянием, не делают предположений о входных данных, поэтому они не могут превзойти `O(n log(n))` в худшем случае. Сортировка подсчётом, напротив, имеет предположение о входных данных, что делает его алгоритмом линейной сортировки по времени. Это предположение заключается в том, что входные элементы являются целыми числами в ограниченном диапазоне [0, k], где `k` не слишком велико по сравнению с количеством элементов `n`.

Сортировка подсчётом, в отличие от большинства классических алгоритмов сортировки, не сортирует входные данные путём сравнения элементов. Вместо этого она использует подсчёт частоты каждого элемента и затем размещает элементы в правильном порядке на основе их частоты и позиций. Когда `k = O(n)`, сортировка подсчётом будет выполняться за время `O(n)`, что делает её быстрее алгоритмов сравнения для таких случаев.

Обратите внимание, что мы не можем использовать сортировку подсчётом в качестве алгоритма сортировки общего назначения, так как она требует знания диапазона входных данных заранее и работает только с целыми числами. Однако, когда ввод соответствует этому предположению, алгоритм работает очень быстро и эффективно, обеспечивая линейную временную сложность.

## Принцип работы

Предположим, мы собираемся отсортировать входной массив со значениями в диапазоне [0, 5]. Алгоритм сортировки подсчётом работает в три основных этапа: подсчёт частоты элементов, вычисление кумулятивных сумм для определения позиций и размещение элементов в правильном порядке.

### Шаг 1: Подсчёт частоты

Во-первых, мы должны подсчитать появление каждого числа во входном массиве. Если мы представим подсчёты массивом C, то C[i] представляет частоту числа i во входном массиве. Это делается путём однократного прохода по входному массиву и увеличения соответствующего элемента массива C для каждого встреченного значения.

Например, поскольку 5 встречается во входном массиве 3 раза, значение индекса 5 равно 3. После этого этапа массив C содержит частоту каждого значения в диапазоне [0, k], что позволяет нам знать, сколько раз каждое значение встречается во входном массиве.

### Шаг 2: Вычисление позиций

Теперь, имея массив C, мы должны определить, сколько элементов меньше или равно каждому входному элементу. Например, один элемент меньше или равен нулю, или, другими словами, существует только одно нулевое значение, равное C[0]. Два элемента меньше или равны единице, что равно C[0] + C[1]. Четыре значения меньше или равны двум, что равно C[0] + C[1] + C[2].

Итак, если мы продолжим вычислять сумму n последовательных элементов в C, мы сможем узнать, сколько элементов меньше или равно числу `n-1` во входном массиве. Применяя эту простую формулу, мы можем обновить C следующим образом: для каждого индекса `i` мы вычисляем `C[i] = C[i] + C[i-1]`, что даёт нам кумулятивные суммы, показывающие, сколько элементов меньше или равно каждому значению. Эти кумулятивные суммы используются для определения правильной позиции каждого элемента в отсортированном массиве.

### Шаг 3: Размещение элементов

Теперь мы можем использовать вспомогательный массив C для сортировки входного массива. Вот как работает сортировка подсчётом. Алгоритм перебирает входной массив в обратном порядке, что важно для обеспечения стабильности сортировки. Для каждого элемента `i` значение `C[i] - 1` представляет расположение числа `i` в отсортированном массиве. Это связано с тем, что существует `C[i]` элементов, меньших или равных `i`, и мы используем индекс `C[i] - 1` для размещения элемента (так как массивы индексируются с нуля). Затем алгоритм уменьшает `C[i]` в конце каждого раунда, чтобы следующее вхождение того же значения было размещено в правильной позиции.

Чтобы отсортировать образец входного массива, мы должны сначала начать с числа 5, так как это последний элемент. Согласно C[5], существует 11 элементов, меньших или равных числу 5. Итак, 5 должен быть 11-м элементом в отсортированном массиве, следовательно, индекс 10. Поскольку мы переместили 5 в отсортированный массив, мы должны уменьшить C[5], чтобы следующее вхождение числа 5 было размещено в правильной позиции. Следующий элемент в обратном порядке равен 2. Поскольку есть 4 элемента, меньших или равных 2, это число должно быть 4-м элементом в отсортированном массиве. Точно так же мы можем найти правильное место для следующего элемента, который равен 0. Если мы продолжим итерацию в обратном порядке и соответствующим образом переместим каждый элемент, мы получим отсортированный массив.

Важно отметить, что перебор в обратном порядке критически важен для обеспечения стабильности алгоритма. Если мы перебираем массив в прямом порядке, элементы с одинаковыми значениями могут изменить свой относительный порядок, что делает алгоритм нестабильным. Обратный порядок гарантирует, что последнее вхождение каждого значения размещается первым в группе равных элементов, сохраняя их относительный порядок из исходного массива.

## Реализация на Java

Реализация сортировки подсчётом на `Java` демонстрирует эффективное использование массива для подсчёта частоты элементов и последующего размещения их в правильном порядке. Рассмотрим основные компоненты реализации, включая подсчёт частоты элементов и саму сортировку.

Во-первых, учитывая входной массив элементов и k, мы должны вычислить массив C:

```java
// Подсчёт частот элементов в [0..k], затем префиксные суммы для позиций (O(n+k))
int[] countElements(int[] input, int k) {
    int[] c = new int[k + 1];
    Arrays.fill(c, 0);
    
    for (int i : input) {
        c[i] += 1;
    }
    
    for (int i = 1; i < c.length; i++) {
        c[i] += c[i - 1];
    }
    
    return c;
}
```

Разберём сигнатуру метода. Параметр `input` представляет массив чисел, которые мы собираемся сортировать. Входной массив представляет собой массив целых чисел в диапазоне [0, k], таким образом, `k` представляет собой максимальное число на входе. Тип возвращаемого значения — массив целых чисел, представляющий массив C с кумулятивными суммами частот.

А вот как работает метод `countElements`. Во-первых, мы инициализировали массив C. Поскольку диапазон [0, k] содержит `k+1` чисел, мы создаём массив, способный содержать `k+1` чисел. Затем для каждого числа во входных данных мы вычисляем частоту этого числа, увеличивая соответствующий элемент массива C. И, наконец, мы складываем последовательные элементы вместе, чтобы узнать, сколько элементов меньше или равно определённому числу. Это преобразует массив частот в массив кумулятивных сумм, который используется для определения позиций элементов в отсортированном массиве.

Кроме того, мы можем убедиться, что метод `countElements` работает должным образом:

```java
@Test
void countElements_GivenAnArray_ShouldCalculateTheFrequencyArrayAsExpected() {
    int k = 5;
    int[] input = { 4, 3, 2, 5, 4, 3, 5, 1, 0, 2, 5 };
    int[] c = CountingSort.countElements(input, k);
    int[] expected = { 1, 2, 4, 6, 8, 11 };
    assertArrayEquals(expected, c);
}
```

Теперь, когда мы можем вычислить массив частот, мы должны иметь возможность сортировать любой заданный набор чисел:

```java
int[] sort(int[] input, int k) {
    int[] c = countElements(input, k);
    int[] sorted = new int[input.length];
    
    for (int i = input.length - 1; i >= 0; i--) {
        int current = input[i];
        sorted[c[current] - 1] = current;
        c[current] -= 1;
    }
    
    return sorted;
}
```

Вот как работает метод сортировки. Во-первых, он вычисляет массив C с кумулятивными суммами частот, который показывает, сколько элементов меньше или равно каждому значению. Затем он перебирает входной массив в обратном порядке и для каждого элемента на входе находит правильное место в отсортированном массиве. i-й элемент во входных данных должен быть C[i]-м элементом в отсортированном массиве. Поскольку массивы `Java` имеют нулевой индекс, запись `C[i] - 1` является элементом C[i]-го, например, `sorted[5]` является шестым элементом в отсортированном массиве. Каждый раз, когда мы находим совпадение, соответствующее значение `C[i]` уменьшается на единицу, чтобы следующее вхождение того же значения было размещено в правильной позиции.

Обратный порядок обхода критически важен для обеспечения стабильности алгоритма. При обходе массива в обратном порядке последнее вхождение каждого значения размещается первым в группе равных элементов в отсортированном массиве, что сохраняет их относительный порядок из исходного массива. Это делает алгоритм стабильным, что важно в приложениях, где относительный порядок равных элементов имеет значение.

Точно так же мы можем убедиться, что метод сортировки работает должным образом:

```java
@Test
void sort_GivenAnArray_ShouldSortTheInputAsExpected() {
    int k = 5;
    int[] input = { 4, 3, 2, 5, 4, 3, 5, 1, 0, 2, 5 };
    int[] sorted = CountingSort.sort(input, k);
    Arrays.sort(input);
    assertArrayEquals(input, sorted);
}
```

## Реализация на Kotlin

Реализация сортировки подсчётом на `Kotlin` следует тем же принципам, что и реализация на `Java`, но использует более идиоматичный синтаксис `Kotlin`. Рассмотрим различные варианты реализации, включая базовую версию, версию с автоматическим определением диапазона и функциональный стиль.

### Подсчёт элементов

```kotlin
fun countElementsK(input: IntArray, k: Int): IntArray {
    val c = IntArray(k + 1) { 0 }
    
    for (i in input) {
        c[i] += 1
    }
    
    for (i in 1 until c.size) {
        c[i] += c[i - 1]
    }
    
    return c
}
```

### Основная функция сортировки

```kotlin
fun countingSortK(input: IntArray, k: Int): IntArray {
    val c = countElementsK(input, k)
    val sorted = IntArray(input.size)
    
    for (i in input.size - 1 downTo 0) {
        val current = input[i]
        sorted[c[current] - 1] = current
        c[current] -= 1
    }
    
    return sorted
}
```

### Улучшенная версия с автоматическим определением k

Улучшенная версия с автоматическим определением диапазона значений позволяет использовать алгоритм без явного указания максимального значения:

```kotlin
fun countingSortAutoK(input: IntArray): IntArray {
    if (input.isEmpty()) return intArrayOf()
    
    val min = input.minOrNull() ?: 0
    val max = input.maxOrNull() ?: 0
    val k = max - min
    
    // Сдвигаем значения для работы с неотрицательными индексами
    val shifted = input.map { it - min }.toIntArray()
    val sorted = countingSortK(shifted, k)
    
    // Возвращаем сдвиг обратно
    return sorted.map { it + min }.toIntArray()
}
```

Эта версия автоматически определяет минимальное и максимальное значения во входном массиве, вычисляет диапазон `k` и использует сдвиг для работы с неотрицательными индексами. После сортировки сдвинутых значений алгоритм возвращает сдвиг обратно, восстанавливая исходные значения. Это делает алгоритм более удобным в использовании, так как не требует знания диапазона значений заранее.

### Функциональный стиль

```kotlin
fun countingSortFunctionalK(input: IntArray, k: Int): IntArray {
    val counts = input.groupingBy { it }.eachCount()
    val cumulative = IntArray(k + 1) { 0 }
    
    for (i in 1..k) {
        cumulative[i] = cumulative[i - 1] + (counts[i] ?: 0)
    }
    
    val sorted = IntArray(input.size)
    for (i in input.size - 1 downTo 0) {
        val value = input[i]
        sorted[cumulative[value] - 1] = value
        cumulative[value]--
    }
    
    return sorted
}
```

### Пример использования

Примеры использования различных версий сортировки подсчётом на `Kotlin`:

```kotlin
fun main() {
    val k = 5
    val input = intArrayOf(4, 3, 2, 5, 4, 3, 5, 1, 0, 2, 5)
    
    // Базовая версия с явным указанием диапазона
    val sorted = countingSortK(input, k)
    println(sorted.contentToString()) // [0, 1, 2, 2, 3, 3, 4, 4, 5, 5, 5]
    
    // Автоматическое определение диапазона
    val input2 = intArrayOf(10, 8, 9, 10, 7, 8)
    val sorted2 = countingSortAutoK(input2)
    println(sorted2.contentToString()) // [7, 8, 8, 9, 10, 10]
    
    // Функциональный стиль с использованием группировки
    val sorted3 = countingSortFunctionalK(input, k)
    println(sorted3.contentToString()) // [0, 1, 2, 2, 3, 3, 4, 4, 5, 5, 5]
    
    // Демонстрация стабильности
    val input3 = intArrayOf(2, 1, 2, 1, 0)
    val sorted4 = countingSortK(input3, 2)
    println(sorted4.contentToString()) // [0, 1, 1, 2, 2] - сохраняет порядок равных элементов
}
```

Эти примеры демонстрируют различные способы использования сортировки подсчётом в зависимости от конкретных требований приложения. Базовая версия требует явного указания диапазона значений, версия с автоматическим определением диапазона вычисляет его автоматически, а функциональный стиль использует более декларативный подход с группировкой элементов.

## Сложность

Большинство классических алгоритмов сортировки, таких как сортировка слиянием, сортируют любой заданный ввод, просто сравнивая входные элементы друг с другом. Этот тип алгоритмов сортировки известен как сортировка сравнением. В худшем случае сортировка сравнением должна занимать не менее `O(n log(n))` для сортировки n элементов, что является нижней границей для алгоритмов сортировки сравнением.

С другой стороны, сортировка подсчётом не сортирует входные данные путём сравнения входных элементов, так что это явно не алгоритм сортировки сравнением. Это позволяет ей преодолеть нижнюю границу `O(n log(n))` для алгоритмов сравнения и достичь линейной временной сложности при определённых условиях.

Посмотрим, сколько времени уходит на сортировку ввода. Алгоритм вычисляет массив C за время `O(n+k)`: он один раз перебирает входной массив размера n за `O(n)`, а затем перебирает C за `O(k)`, так что это будет `O(n+k)` за время общее. После вычисления C он сортирует входные данные, перебирая входной массив и выполняя несколько примитивных операций на каждой итерации. Таким образом, фактическая операция сортировки занимает `O(n)`.

В общей сложности сортировка подсчёта занимает `O(n+k)` времени:

```text
O(n + k) + O(n) = O(2n + k) = O(n + k)
```

Если предположить, что `k = O(n)`, то алгоритм сортировки подсчётом сортирует входные данные за линейное время `O(n)`. В отличие от алгоритмов сортировки общего назначения, сортировка с подсчётом делает предположение о входных данных и требует для выполнения меньше, чем нижняя граница `O(n log(n))` для алгоритмов сравнения.

### Временная сложность

Временная сложность сортировки подсчётом составляет `O(n+k)` во всех случаях: лучшем, среднем и худшем. Это связано с тем, что алгоритм всегда выполняет одинаковые операции независимо от порядка входных данных. Когда `k = O(n)`, временная сложность становится линейной `O(n)`, что делает алгоритм очень эффективным для таких случаев.

### Пространственная сложность

Пространственная сложность сортировки подсчётом составляет `O(k)` для хранения массива подсчётов. Это дополнительное пространство требуется для массива C размером `k+1`, который хранит частоты и кумулятивные суммы элементов. Если `k` велико по сравнению с `n`, это может быть проблематичным, и в таких случаях предпочтительнее использовать другие алгоритмы сортировки.

## Особенности

Сортировка подсчётом имеет несколько важных особенностей, которые отличают её от других алгоритмов сортировки. Понимание этих особенностей важно для правильной реализации и использования алгоритма.

### Почему обратный порядок?

Несколько мгновений назад мы установили несколько своеобразных правил о механике сортировки подсчётом, но так и не прояснили их причину. Чтобы быть более конкретным, почему мы должны перебирать входной массив в обратном порядке, и почему мы уменьшаем значение `C[i]` каждый раз, когда используем его?

Давайте повторим с самого начала, чтобы лучше понять первое правило. Предположим, мы собираемся отсортировать простой массив целых чисел. В первой итерации мы должны найти отсортированное местоположение для первого 1. Таким образом, первое вхождение числа 1 получает последний индекс в отсортированном массиве. Пропустив число 0, давайте посмотрим, что произойдёт со вторым вхождением числа 1. Порядок появления элементов с одним и тем же значением во входном и отсортированном массиве разный, поэтому алгоритм нестабилен, когда мы итерируем с самого начала. Перебор в обратном порядке гарантирует, что элементы с одинаковыми значениями сохраняют свой относительный порядок, что делает алгоритм стабильным.

### Почему уменьшаем C[i]?

Что произойдёт, если мы не будем уменьшать значение `C[i]` после каждого использования? Давайте посмотрим. Оба вхождения числа 1 занимают последнее место в отсортированном массиве. Поэтому, если мы не будем уменьшать значение `C[i]` после каждого использования, мы потенциально можем потерять несколько чисел при их сортировке! Уменьшение `C[i]` гарантирует, что каждое вхождение элемента размещается в правильной позиции, и следующее вхождение того же значения будет размещено в предыдущей позиции.

### Стабильность

Сортировка подсчётом является стабильным алгоритмом сортировки, когда мы перебираем входной массив в обратном порядке. Это означает, что элементы с одинаковыми значениями сохраняют свой относительный порядок в отсортированном массиве. Стабильность важна в приложениях, где относительный порядок равных элементов имеет значение, например, при сортировке записей по нескольким полям.

## Применение

Сортировка подсчётом особенно полезна в следующих случаях. Когда диапазон входных данных ограничен (`k = O(n)`), алгоритм обеспечивает линейную временную сложность `O(n)`, что делает его очень эффективным для таких случаев. Когда нужно отсортировать целые числа в небольшом диапазоне, алгоритм работает быстрее алгоритмов сравнения благодаря отсутствию необходимости в сравнении элементов. Когда требуется стабильная сортировка за линейное время, сортировка подсчётом обеспечивает стабильность при правильной реализации с обратным порядком обхода. Как часть более сложных алгоритмов, например, `Radix Sort`, сортировка подсчётом используется как подпрограмма для сортировки элементов по отдельным разрядам.

Однако стоит отметить, что для типичных случаев использования, где диапазон значений велик или неизвестен заранее, предпочтительнее использовать алгоритмы сравнения, такие как быстрая сортировка или сортировка слиянием, которые не требуют знания диапазона входных данных.

## Ограничения

Сортировка подсчётом имеет несколько важных ограничений, которые следует учитывать при выборе алгоритма. Алгоритм работает только с целыми числами (или объектами, которые можно преобразовать в целые числа), что ограничивает его применение для других типов данных. Требует знания диапазона входных данных заранее, что может быть проблематичным, если диапазон неизвестен или изменяется динамически. Может быть неэффективным, если диапазон `k` очень большой по сравнению с количеством элементов `n`, так как пространственная сложность `O(k)` может стать проблемой. Требует дополнительной памяти `O(k)` для хранения массива подсчётов, что может быть проблематичным для больших диапазонов значений.

Эти ограничения делают сортировку подсчётом непригодной для использования в качестве алгоритма сортировки общего назначения, но очень эффективной для специфических случаев, где входные данные соответствуют требованиям алгоритма. Важно тщательно анализировать характеристики данных перед выбором алгоритма сортировки, чтобы убедиться, что выбранный алгоритм действительно является оптимальным для конкретного случая использования.

При работе с данными, где диапазон значений ограничен и известен заранее, сортировка подсчётом может показать отличную производительность, превосходя алгоритмы сравнения благодаря линейной временной сложности. Однако для типичных случаев использования, где диапазон значений велик или неизвестен заранее, предпочтительнее использовать алгоритмы сравнения, которые не требуют знания диапазона входных данных и могут быть более эффективными по использованию памяти.

## Сравнение с другими алгоритмами

Сравнение сортировки подсчётом с другими алгоритмами показывает важные различия в их характеристиках и применении. `Counting Sort` имеет временную сложность `O(n+k)` и пространственную сложность `O(k)`, является стабильным алгоритмом, но работает только с ограниченным диапазоном значений. `Merge Sort` имеет временную сложность `O(n log(n))` и пространственную сложность `O(n)`, является стабильным алгоритмом и не имеет ограничений на входные данные. `Quick Sort` имеет среднюю временную сложность `O(n log(n))` и пространственную сложность `O(log(n))`, не является стабильным алгоритмом и не имеет ограничений на входные данные. `Radix Sort` имеет временную сложность `O(d*(n+k))`, где `d` — количество разрядов, и пространственную сложность `O(n+k)`, является стабильным алгоритмом и работает только с целыми числами.

Выбор между этими алгоритмами зависит от конкретных требований приложения. Сортировка подсчётом предпочтительна, когда диапазон значений ограничен и известен заранее, когда требуется стабильная сортировка за линейное время, или когда алгоритм используется как часть более сложных алгоритмов, таких как поразрядная сортировка. Для типичных случаев использования предпочтительнее использовать быструю сортировку или сортировку слиянием, которые не требуют знания диапазона входных данных и могут быть более эффективными по использованию памяти для больших диапазонов значений.

Важно также учитывать влияние различных факторов на производительность, таких как размер данных, диапазон значений и доступная память. Для данных с ограниченным диапазоном значений сортировка подсчётом может показать отличную производительность, превосходя алгоритмы сравнения благодаря линейной временной сложности. Однако для типичных случаев использования, где диапазон значений велик или неизвестен заранее, предпочтительнее использовать алгоритмы сравнения, которые не требуют знания диапазона входных данных и могут быть более эффективными по использованию памяти.

## Лучшие практики

При использовании сортировки подсчётом важно следовать нескольким лучшим практикам. Используйте алгоритм только при ограниченном диапазоне значений (`k = O(n)` или не слишком велик). При больших `k` предпочтительнее использовать алгоритмы сравнения (`QuickSort`, `MergeSort`), которые не требуют дополнительной памяти пропорциональной диапазону значений.

Если минимум не равен 0, сдвиньте индексы: используйте `c[arr[i] - min]` вместо `c[arr[i]]`. Для отрицательных чисел используйте сдвиг на `-min`, чтобы все индексы были неотрицательными. Это позволяет обрабатывать массивы с отрицательными числами или массивы, начинающиеся не с нуля.

Для обеспечения стабильности обходите исходный массив в обратном порядке при размещении элементов в выходной массив. Это сохраняет относительный порядок равных элементов и делает алгоритм стабильным.

Помните, что массив подсчёта имеет размер `k+1`. При очень большом `k` рассмотрите использование поразрядной сортировки (`radix sort`) по разрядам или блочной сортировки (`bucket sort`), которые могут быть более эффективными для таких случаев.

При тестировании проверьте пустой массив, один элемент, все элементы равны, диапазон [0..k], отрицательные числа (со сдвигом). Это поможет убедиться, что реализация корректно обрабатывает все граничные случаи.

## Решение проблем

При работе с сортировкой подсчётом могут возникать различные проблемы. Если алгоритм работает медленнее, чем ожидалось, проверьте, правильно ли определён диапазон значений `k`. Если `k` очень велико по сравнению с `n`, алгоритм может быть неэффективным, и в таких случаях предпочтительнее использовать алгоритмы сравнения.

Если возникают проблемы с памятью, убедитесь, что диапазон значений `k` не слишком велик. Пространственная сложность `O(k)` может быть проблематичной для больших диапазонов значений. Рассмотрите возможность использования поразрядной сортировки или блочной сортировки для таких случаев.

Если алгоритм нестабилен и это вызывает проблемы, убедитесь, что вы перебираете входной массив в обратном порядке при размещении элементов в выходной массив. Это критически важно для обеспечения стабильности алгоритма.

При проблемах с отрицательными числами или массивами, начинающимися не с нуля, используйте сдвиг индексов. Вычислите минимум массива и сдвиньте все значения на `-min`, чтобы все индексы были неотрицательными. После сортировки верните сдвиг обратно, вычитая `min` из каждого элемента отсортированного массива.

## Частые вопросы

**Вопрос:** Почему сортировка подсчётом работает за линейное время?

**Ответ:** Сортировка подсчётом работает за линейное время `O(n+k)`, потому что она не сравнивает элементы между собой, а использует подсчёт частоты элементов и размещение их в правильном порядке на основе частоты. Когда `k = O(n)`, временная сложность становится линейной `O(n)`, что быстрее нижней границы `O(n log(n))` для алгоритмов сравнения.

**Вопрос:** Можно ли использовать сортировку подсчётом для других типов данных, кроме целых чисел?

**Ответ:** Сортировка подсчётом работает только с целыми числами или объектами, которые можно преобразовать в целые числа. Для других типов данных, таких как строки или объекты с несколькими полями, необходимо использовать другие алгоритмы сортировки или преобразовать данные в целые числа перед сортировкой.

**Вопрос:** Что произойдёт, если диапазон значений очень велик?

**Ответ:** Если диапазон значений `k` очень велик по сравнению с количеством элементов `n`, пространственная сложность `O(k)` может стать проблематичной, и алгоритм может быть неэффективным. В таких случаях предпочтительнее использовать алгоритмы сравнения, такие как быстрая сортировка или сортировка слиянием, или рассмотреть возможность использования поразрядной сортировки.

**Вопрос:** Почему важно перебирать массив в обратном порядке?

**Ответ:** Перебор массива в обратном порядке критически важен для обеспечения стабильности алгоритма. Это гарантирует, что элементы с одинаковыми значениями сохраняют свой относительный порядок в отсортированном массиве. Если перебирать массив в прямом порядке, алгоритм становится нестабильным.

**Вопрос:** Как обработать отрицательные числа?

**Ответ:** Для обработки отрицательных чисел вычислите минимум массива и сдвиньте все значения на `-min`, чтобы все индексы были неотрицательными. После сортировки верните сдвиг обратно, вычитая `min` из каждого элемента отсортированного массива.

**Вопрос:** Когда следует использовать сортировку подсчётом вместо быстрой сортировки?

**Ответ:** Используйте сортировку подсчётом, когда диапазон значений ограничен (`k = O(n)`) и известен заранее, когда требуется стабильная сортировка за линейное время, или когда алгоритм используется как часть более сложных алгоритмов, таких как поразрядная сортировка. Для типичных случаев использования предпочтительнее использовать быструю сортировку или другие алгоритмы сравнения.

## Глоссарий терминов

`Counting Sort` (сортировка подсчётом) — алгоритм сортировки, который работает за линейное время `O(n+k)` путём подсчёта частоты элементов и размещения их в правильном порядке без сравнения элементов между собой.

`Диапазон значений` — разница между максимальным и минимальным значением в массиве. Для сортировки подсчётом диапазон должен быть ограничен и известен заранее.

`Массив подсчётов` — массив размером `k+1`, который хранит частоту каждого элемента в диапазоне [0, k]. Используется для определения позиций элементов в отсортированном массиве.

`Кумулятивные суммы` — суммы последовательных элементов массива подсчётов, показывающие, сколько элементов меньше или равно каждому значению. Используются для определения правильных позиций элементов в отсортированном массиве.

`Стабильность сортировки` — свойство алгоритма сортировки сохранять относительный порядок равных элементов после сортировки. Сортировка подсчётом является стабильной при правильной реализации с обратным порядком обхода.

`Алгоритм сравнения` — алгоритм сортировки, который сравнивает элементы между собой для определения их порядка. Сортировка подсчётом не является алгоритмом сравнения, так как она не сравнивает элементы напрямую.

`Линейная временная сложность` — временная сложность `O(n)`, которая растёт линейно с размером входных данных. Сортировка подсчётом достигает линейной сложности, когда `k = O(n)`.

`Сдвиг индексов` — техника обработки массивов с отрицательными числами или массивами, начинающимися не с нуля, путём сдвига всех значений на минимальное значение для получения неотрицательных индексов.

## Дополнительные примеры использования

Рассмотрим несколько практических примеров использования сортировки подсчётом в различных сценариях.

### Пример 1: Сортировка массива с отрицательными числами

Пример обработки массива с отрицательными числами с использованием сдвига индексов:

```java
public static int[] countingSortWithNegatives(int[] arr) {
    if (arr.length == 0) return new int[0];
    
    int min = Arrays.stream(arr).min().orElse(0);
    int max = Arrays.stream(arr).max().orElse(0);
    int range = max - min + 1;
    
    // Сдвигаем значения для работы с неотрицательными индексами
    int[] count = new int[range];
    for (int num : arr) {
        count[num - min]++;
    }
    
    // Вычисляем кумулятивные суммы
    for (int i = 1; i < range; i++) {
        count[i] += count[i - 1];
    }
    
    // Размещаем элементы в обратном порядке для стабильности
    int[] sorted = new int[arr.length];
    for (int i = arr.length - 1; i >= 0; i--) {
        sorted[count[arr[i] - min] - 1] = arr[i];
        count[arr[i] - min]--;
    }
    
    return sorted;
}
```

### Пример 2: Сортировка символов

Пример сортировки массива символов с использованием сортировки подсчётом:

```java
public static char[] countingSortChars(char[] arr) {
    int[] count = new int[256]; // ASCII диапазон
    
    // Подсчитываем частоту каждого символа
    for (char c : arr) {
        count[c]++;
    }
    
    // Вычисляем кумулятивные суммы
    for (int i = 1; i < 256; i++) {
        count[i] += count[i - 1];
    }
    
    // Размещаем элементы в обратном порядке
    char[] sorted = new char[arr.length];
    for (int i = arr.length - 1; i >= 0; i--) {
        sorted[count[arr[i]] - 1] = arr[i];
        count[arr[i]]--;
    }
    
    return sorted;
}
```

### Пример 3: Нахождение k наиболее частых элементов

Эффективное нахождение k наиболее частых элементов с использованием сортировки подсчётом:

```java
public static int[] findKMostFrequent(int[] arr, int k) {
    // Находим диапазон значений
    int min = Arrays.stream(arr).min().orElse(0);
    int max = Arrays.stream(arr).max().orElse(0);
    int range = max - min + 1;
    
    // Подсчитываем частоту каждого элемента
    int[] count = new int[range];
    for (int num : arr) {
        count[num - min]++;
    }
    
    // Создаём массив пар (значение, частота) и сортируем по частоте
    List<int[]> pairs = new ArrayList<>();
    for (int i = 0; i < range; i++) {
        if (count[i] > 0) {
            pairs.add(new int[]{i + min, count[i]});
        }
    }
    
    // Сортируем по частоте (по убыванию)
    pairs.sort((a, b) -> Integer.compare(b[1], a[1]));
    
    // Возвращаем k наиболее частых элементов
    return pairs.stream()
                .limit(k)
                .mapToInt(pair -> pair[0])
                .toArray();
}
```

Этот пример демонстрирует, как можно использовать подсчёт частоты элементов для решения других задач, таких как нахождение наиболее частых элементов. Алгоритм сначала подсчитывает частоту каждого элемента, затем создаёт пары значений и их частот и сортирует их по частоте для определения наиболее частых элементов.

### Пример 4: Сортировка объектов по целочисленному полю

Пример сортировки объектов по целочисленному полю с использованием сортировки подсчётом:

```java
public static class Person {
    int age;
    String name;
    
    Person(int age, String name) {
        this.age = age;
        this.name = name;
    }
}

public static Person[] sortByAge(Person[] people, int maxAge) {
    // Подсчитываем частоту каждого возраста
    int[] count = new int[maxAge + 1];
    for (Person p : people) {
        count[p.age]++;
    }
    
    // Вычисляем кумулятивные суммы
    for (int i = 1; i <= maxAge; i++) {
        count[i] += count[i - 1];
    }
    
    // Размещаем элементы в обратном порядке для стабильности
    Person[] sorted = new Person[people.length];
    for (int i = people.length - 1; i >= 0; i--) {
        sorted[count[people[i].age] - 1] = people[i];
        count[people[i].age]--;
    }
    
    return sorted;
}
```

Этот пример показывает, как можно использовать сортировку подсчётом для сортировки объектов по целочисленному полю. Алгоритм сохраняет стабильность, что означает, что объекты с одинаковым возрастом сохраняют свой относительный порядок из исходного массива.

## Когда использовать

Выбор между сортировкой подсчётом и другими алгоритмами сортировки зависит от конкретных требований приложения. Используйте сортировку подсчётом, когда диапазон входных данных ограничен (`k = O(n)`) и известен заранее, когда нужно отсортировать целые числа в небольшом диапазоне, когда требуется стабильная сортировка за линейное время, или когда алгоритм используется как часть более сложных алгоритмов, таких как поразрядная сортировка.

Сортировка подсчётом особенно эффективна для случаев, где количество различных значений невелико по сравнению с общим количеством элементов. Это делает её идеальной для сортировки данных с ограниченным диапазоном значений, таких как оценки студентов, возраст людей или другие данные с небольшим диапазоном возможных значений.

Не используйте сортировку подсчётом, когда диапазон значений очень велик по сравнению с количеством элементов, когда диапазон значений неизвестен заранее, когда нужно сортировать данные других типов, кроме целых чисел, или когда дополнительная память `O(k)` является проблемой. В таких случаях предпочтительнее использовать алгоритмы сравнения, такие как быстрая сортировка или сортировка слиянием.
