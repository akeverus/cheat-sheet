# Пары с заданной суммой (`Pairs with Given Sum`)

Поиск всех пар чисел в массиве, сумма которых равна заданному числу — классическая задача в алгоритмике и программировании. Рассматриваются два основных подхода: поиск всех пар (включая дубликаты) и поиск только уникальных пар. Каждый подход имеет свои преимущества и ограничения в зависимости от требований задачи. Для поиска всех пар используется метод грубой силы с вложенными циклами, который имеет временную сложность `O(n²)`, но прост в реализации. Для поиска уникальных пар используется оптимизированный подход с `HashMap`, который имеет временную сложность `O(n)` и более эффективен по использованию памяти. В этом документе рассматриваются различные реализации алгоритма на `Java` и `Kotlin`, анализ сложности, альтернативные решения и практические рекомендации по выбору подходящего подхода.

## Описание алгоритма

В этом руководстве мы рассмотрим, как реализовать алгоритм поиска всех пар чисел в массиве, сумма которых равна заданному числу. Задача возникает в различных контекстах: от алгоритмических задач на собеседованиях до практических приложений в анализе данных и оптимизации запросов.

Мы сосредоточимся на двух основных подходах к решению проблемы. При первом подходе мы найдём все такие пары независимо от их уникальности, что может быть полезно, когда важна каждая комбинация элементов, включая их позиции в массиве. Во втором подходе мы найдём только уникальные комбинации чисел, удалив избыточные пары, что более эффективно по использованию памяти и времени выполнения.

Для каждого подхода мы представим две реализации: традиционную реализацию с использованием циклов `for` и вторую с использованием `Java` 8 `Stream API`. Это позволит сравнить императивный и функциональный стили программирования и выбрать подходящий для конкретной задачи.

Для наших демонстраций мы будем искать все пары чисел, сумма которых равна 6, используя следующий входной массив:

```java
// Пример входного массива для демонстрации алгоритма
int[] input = { 2, 4, 3, 3 };
// Ожидаемые пары с суммой 6: {2,4}, {4,2}, {3,3}, {3,3} (все пары)
// Или: {2,4}, {3,3} (уникальные пары)
```

## Реализация на Java

### Подход 1: Поиск всех пар (Java)

Мы будем перебирать массив целых чисел, находя все пары (`i` и `j`), которые в сумме дают заданное число (`sum`), используя подход грубой силы с вложенным циклом. Этот алгоритм будет иметь сложность времени выполнения `O(n²)`, так как для каждого элемента мы проверяем все остальные элементы массива.

При таком подходе наш алгоритм должен возвращать все возможные комбинации пар, включая дубликаты и пары с одинаковыми элементами в разном порядке:

```text
{2,4}, {4,2}, {3,3}, {3,3}
```

В каждом из алгоритмов, когда мы находим целевую пару чисел, сумма которых равна целевому числу, мы добавляем пару в результирующий список. Это позволяет сохранить информацию о всех комбинациях элементов, которые удовлетворяют условию задачи.

### Реализация с циклами for

Первый способ реализации решения — использование традиционного цикла `for`:

```java
// Поиск всех пар элементов с заданной суммой: вложенные циклы O(n²)
// Проверяем все возможные комбинации элементов массива
public List<int[]> findAllPairs(int[] input, int sum) {
    // Список для хранения найденных пар
    List<int[]> pairs = new ArrayList<>();
    
    // Внешний цикл: перебираем все элементы массива
    for (int i = 0; i < input.length; i++) {
        // Внутренний цикл: перебираем все элементы для сравнения с текущим
        for (int j = 0; j < input.length; j++) {
            // Проверяем, что индексы разные и сумма равна заданному числу
            if (j != i && (input[i] + input[j]) == sum) {
                // Добавляем найденную пару в результат
                pairs.add(new int[]{input[i], input[j]});
            }
        }
    }
    
    return pairs;
}
```

### Реализация с Java 8 Stream API

Здесь мы используем метод `IntStream.range` для создания последовательного потока чисел. Затем мы фильтруем их по нашему условию: число 1 + число 2 = сумма:

```java
// Функциональный подход с использованием Stream API
public List<int[]> findAllPairsStream(int[] input, int sum) {
    // Список для хранения найденных пар
    List<int[]> pairs = new ArrayList<>();
    
    // Создаём поток индексов от 0 до длины массива
    IntStream.range(0, input.length)
        // Для каждого индекса i создаём вложенный поток индексов j
        .forEach(i -> IntStream.range(0, input.length)
            // Фильтруем: оставляем только те j, где i != j и сумма равна sum
            .filter(j -> i != j && input[i] + input[j] == sum)
            // Для каждого подходящего j добавляем пару в список
            .forEach(j -> pairs.add(new int[]{input[i], input[j]}))
        );
    
    return pairs;
}
```

## Подход 2: Поиск уникальных пар

Для этого примера нам придётся разработать более умный алгоритм, который возвращает только уникальные комбинации чисел, опуская избыточные пары. Это особенно важно, когда нам не нужны дубликаты и порядок элементов в паре не имеет значения.

Для этого мы добавим каждый элемент в хеш-карту (без сортировки), предварительно проверив, была ли уже показана пара. Если пара уже была найдена, мы помечаем её как обработанную (устанавливаем значение как `null`), чтобы избежать повторного добавления. Это позволяет нам эффективно отслеживать уже найденные пары и избегать дубликатов.

Соответственно, используя тот же входной массив, что и раньше, и целевую сумму 6, наш алгоритм должен возвращать только различные комбинации чисел:

```text
{2,4}, {3,3}
```

### Реализация с циклами for

Если мы используем традиционный цикл `for`, у нас будет следующая реализация:

```java
// Поиск уникальных пар с заданной суммой: оптимизированный подход O(n)
public List<int[]> findUniquePairs(int[] input, int sum) {
    // Список для хранения уникальных пар
    List<int[]> pairs = new ArrayList<>();
    // HashMap для отслеживания уже найденных пар
    // Ключ: элемент массива, Значение: его дополнение до sum (или null, если пара уже найдена)
    Map<Integer, Integer> pairsMap = new HashMap<>();
    
    // Проходим по массиву один раз
    for (int i : input) {
        // Если текущий элемент уже есть в карте как ключ
        if (pairsMap.containsKey(i)) {
            // Если значение не null, значит пара ещё не была добавлена
            if (pairsMap.get(i) != null) {
                // Добавляем пару в результат
                pairs.add(new int[]{i, sum - i});
            }
            // Помечаем пару как обработанную (устанавливаем null)
            pairsMap.put(sum - i, null);
        } 
        // Если элемента нет в карте и его дополнение тоже не встречалось
        else if (!pairsMap.containsValue(i)) {
            // Сохраняем дополнение элемента до sum
            pairsMap.put(sum - i, i);
        }
    }
    
    return pairs;
}
```

Обратите внимание, что эта реализация улучшает предыдущую сложность, поскольку мы используем только один цикл `for`, поэтому у нас будет `O(n)` временная сложность вместо `O(n²)`. Это достигается за счёт использования `HashMap` для отслеживания уже обработанных элементов и их дополнений.

### Реализация с Java 8 Stream API

Теперь решим задачу с помощью `Java` 8 и `Stream API`:

```java
// Функциональный подход с использованием Stream API для поиска уникальных пар
public List<int[]> findUniquePairsStream(int[] input, int sum) {
    // Список для хранения уникальных пар
    List<int[]> pairs = new ArrayList<>();
    // HashMap для отслеживания уже найденных пар
    Map<Integer, Integer> pairsMap = new HashMap<>();
    
    // Создаём поток индексов и обрабатываем каждый элемент
    IntStream.range(0, input.length).forEach(i -> {
        // Если текущий элемент уже есть в карте как ключ
        if (pairsMap.containsKey(input[i])) {
            // Если значение не null, значит пара ещё не была добавлена
            if (pairsMap.get(input[i]) != null) {
                // Добавляем пару в результат
                pairs.add(new int[]{input[i], sum - input[i]});
            }
            // Помечаем пару как обработанную
            pairsMap.put(sum - input[i], null);
        } 
        // Если элемента нет в карте и его дополнение тоже не встречалось
        else if (!pairsMap.containsValue(input[i])) {
            // Сохраняем дополнение элемента до sum
            pairsMap.put(sum - input[i], input[i]);
        }
    });
    
    return pairs;
}
```

## Реализация на Kotlin

Реализация на `Kotlin` демонстрирует более лаконичный и идиоматичный синтаксис по сравнению с `Java`. Рассмотрим все подходы:

### Подход 1: Поиск всех пар (Kotlin)

```kotlin
// Базовая реализация поиска всех пар с использованием вложенных циклов
fun findAllPairsK(input: IntArray, sum: Int): List<IntArray> {
    val pairs = mutableListOf<IntArray>()
    
    // Внешний цикл: перебираем все элементы массива
    for (i in input.indices) {
        // Внутренний цикл: перебираем все элементы для сравнения
        for (j in input.indices) {
            // Проверяем, что индексы разные и сумма равна заданному числу
            if (j != i && input[i] + input[j] == sum) {
                // Добавляем найденную пару в результат
                pairs.add(intArrayOf(input[i], input[j]))
            }
        }
    }
    
    return pairs
}

// Функциональный подход с использованием встроенных функций Kotlin
fun findAllPairsFunctionalK(input: IntArray, sum: Int): List<IntArray> {
    // Используем flatMap для создания списка всех подходящих пар
    return input.indices.flatMap { i ->
        input.indices
            // Фильтруем: оставляем только те j, где i != j и сумма равна sum
            .filter { j -> i != j && input[i] + input[j] == sum }
            // Преобразуем индексы в пары элементов
            .map { j -> intArrayOf(input[i], input[j]) }
    }
}
```

### Подход 2: Поиск уникальных пар

```kotlin
// Реализация поиска уникальных пар с использованием HashMap
fun findUniquePairsK(input: IntArray, sum: Int): List<IntArray> {
    val pairs = mutableListOf<IntArray>()
    // HashMap для отслеживания уже найденных пар
    val pairsMap = mutableMapOf<Int, Int?>()
    
    // Проходим по массиву один раз
    for (i in input) {
        // Если текущий элемент уже есть в карте как ключ
        if (pairsMap.containsKey(i)) {
            // Если значение не null, значит пара ещё не была добавлена
            if (pairsMap[i] != null) {
                // Добавляем пару в результат
                pairs.add(intArrayOf(i, sum - i))
            }
            // Помечаем пару как обработанную
            pairsMap[sum - i] = null
        } 
        // Если элемента нет в карте и его дополнение тоже не встречалось
        else if (!pairsMap.containsValue(i)) {
            // Сохраняем дополнение элемента до sum
            pairsMap[sum - i] = i
        }
    }
    
    return pairs
}

// Функциональный подход с использованием when для условной логики
fun findUniquePairsFunctionalK(input: IntArray, sum: Int): List<IntArray> {
    val pairs = mutableListOf<IntArray>()
    val pairsMap = mutableMapOf<Int, Int?>()
    
    // Используем forEach для обработки каждого элемента
    input.forEach { i ->
        when {
            // Если элемент уже есть в карте и значение не null
            pairsMap.containsKey(i) && pairsMap[i] != null -> {
                // Добавляем пару и помечаем как обработанную
                pairs.add(intArrayOf(i, sum - i))
                pairsMap[sum - i] = null
            }
            // Если элемента нет в карте и его дополнение тоже не встречалось
            !pairsMap.containsValue(i) -> {
                // Сохраняем дополнение элемента до sum
                pairsMap[sum - i] = i
            }
        }
    }
    
    return pairs
}
```

### Оптимизированный подход с HashMap

```kotlin
// Оптимизированная версия с использованием Set для отслеживания уже просмотренных элементов
fun findPairsOptimizedK(input: IntArray, sum: Int): List<Pair<Int, Int>> {
    val pairs = mutableListOf<Pair<Int, Int>>()
    // Set для хранения уже просмотренных элементов
    val seen = mutableSetOf<Int>()
    
    // Проходим по массиву один раз
    for (num in input) {
        // Вычисляем дополнение текущего элемента до sum
        val complement = sum - num
        // Если дополнение уже было просмотрено, значит мы нашли пару
        if (seen.contains(complement)) {
            // Добавляем пару в нормализованном виде (меньший элемент первым)
            pairs.add(Pair(minOf(num, complement), maxOf(num, complement)))
        }
        // Добавляем текущий элемент в множество просмотренных
        seen.add(num)
    }
    
    // Удаляем дубликаты (на случай, если одна и та же пара была найдена несколько раз)
    return pairs.distinct()
}
```

## Сравнение подходов

Сравнение двух подходов показывает их различия в производительности, использовании памяти и применении:

| Характеристика | Подход 1 (все пары) | Подход 2 (уникальные пары) |
|----------------|---------------------|----------------------------|
| Временная сложность | `O(n²)` | `O(n)` |
| Пространственная сложность | `O(n²)` | `O(n)` |
| Результат | Все пары, включая дубликаты | Только уникальные пары |
| Применение | Когда нужны все комбинации | Когда нужны только уникальные |

Подход 1 обеспечивает полную информацию о всех возможных комбинациях элементов, что может быть полезно, когда важна каждая пара, включая её позицию в массиве. Однако он требует квадратичного времени и памяти, что делает его непрактичным для больших массивов.

Подход 2 значительно более эффективен, так как использует линейное время и память. Он подходит для случаев, когда нам нужны только уникальные комбинации элементов, и порядок элементов в паре не имеет значения.

## Сложность

Анализ сложности показывает значительные различия между подходами в зависимости от требований задачи.

### Подход 1: Поиск всех пар

Временная сложность составляет `O(n²)`, так как мы используем два вложенных цикла для проверки всех возможных комбинаций элементов. Для каждого из `n` элементов мы проверяем все остальные `n` элементов, что даёт общее количество операций `n × n = n²`.

Пространственная сложность также составляет `O(n²)` в худшем случае, когда все элементы могут образовывать пары с суммой, равной заданному числу. Это происходит потому, что мы храним все найденные пары в списке, и в худшем случае количество пар может быть пропорционально квадрату размера массива.

### Подход 2: Поиск уникальных пар

Временная сложность составляет `O(n)`, так как мы используем только один проход по массиву. Каждая операция с `HashMap` (проверка наличия ключа, добавление элемента) выполняется за `O(1)` в среднем случае, что даёт общую сложность `O(n)`.

Пространственная сложность составляет `O(n)` для хранения `HashMap`, которая содержит не более `n` записей (по одной для каждого уникального элемента). Это значительно эффективнее по использованию памяти по сравнению с первым подходом.

## Особенности

Оба подхода имеют свои особенности, которые делают их подходящими для различных сценариев. Два подхода предоставляют разные решения для разных требований: первый подход подходит, когда нужны все комбинации элементов, включая дубликаты и различные порядки, а второй подход оптимален, когда нужны только уникальные комбинации.

Оптимизация второго подхода делает его значительно быстрее первого, особенно для больших массивов. Использование `HashMap` позволяет избежать необходимости проверять все возможные комбинации элементов, что значительно улучшает производительность.

Гибкость реализации позволяет использовать как традиционные циклы, так и `Stream API` в зависимости от стиля программирования и требований проекта. Это даёт разработчикам возможность выбрать подходящий стиль кода для конкретной задачи.

## Применение

Поиск пар с заданной суммой используется в различных областях. В задачах на собеседованиях эта задача часто встречается как классический пример алгоритмического мышления и работы со структурами данных. В алгоритмах двух указателей поиск пар является основой для более сложных алгоритмов, таких как поиск трёх элементов с заданной суммой или поиск подмассивов с заданной суммой.

В поиске подмассивов с заданной суммой алгоритм поиска пар может быть адаптирован для работы с префиксными суммами, что позволяет эффективно находить подмассивы с заданной суммой. В оптимизации запросов поиск пар может использоваться для нахождения оптимальных комбинаций параметров запросов или для кэширования результатов запросов.

В анализе данных поиск пар с заданной суммой может использоваться для выявления корреляций между различными метриками или для группировки данных по определённым критериям.

## Альтернативные решения

Помимо основных подходов, существуют альтернативные решения, которые могут быть более эффективными в определённых ситуациях.

### Использование HashSet

Подход с использованием `HashSet` для отслеживания уже просмотренных элементов является простым и эффективным решением:

```java
// Поиск пар с использованием HashSet для отслеживания просмотренных элементов
public List<int[]> findPairsWithHashSet(int[] input, int sum) {
    List<int[]> pairs = new ArrayList<>();
    // Set для хранения уже просмотренных элементов
    Set<Integer> seen = new HashSet<>();
    
    // Проходим по массиву один раз
    for (int num : input) {
        // Вычисляем дополнение текущего элемента до sum
        int complement = sum - num;
        // Если дополнение уже было просмотрено, значит мы нашли пару
        if (seen.contains(complement)) {
            // Добавляем пару в результат
            pairs.add(new int[]{num, complement});
        }
        // Добавляем текущий элемент в множество просмотренных
        seen.add(num);
    }
    
    return pairs;
}
```

Этот подход имеет временную сложность `O(n)` и пространственную сложность `O(n)`, что делает его эффективным для большинства случаев. Однако он может находить дубликаты пар, если один и тот же элемент встречается несколько раз в массиве.

### Сортировка и два указателя

Подход с сортировкой и двумя указателями эффективен, когда массив можно отсортировать и когда порядок элементов не важен:

```java
// Поиск пар с использованием сортировки и двух указателей
// Эффективен, когда массив можно отсортировать
public List<int[]> findPairsWithTwoPointers(int[] input, int sum) {
    // Сортируем массив для использования техники двух указателей
    Arrays.sort(input);
    List<int[]> pairs = new ArrayList<>();
    // Два указателя: один в начале, другой в конце массива
    int left = 0, right = input.length - 1;
    
    // Продолжаем, пока указатели не встретятся
    while (left < right) {
        // Вычисляем сумму элементов на текущих позициях указателей
        int currentSum = input[left] + input[right];
        
        if (currentSum == sum) {
            // Если сумма равна заданному числу, добавляем пару
            pairs.add(new int[]{input[left], input[right]});
            // Сдвигаем оба указателя для поиска следующих пар
            left++;
            right--;
        } else if (currentSum < sum) {
            // Если сумма меньше заданного числа, увеличиваем левый указатель
            // (так как массив отсортирован, это увеличит сумму)
            left++;
        } else {
            // Если сумма больше заданного числа, уменьшаем правый указатель
            // (это уменьшит сумму)
            right--;
        }
    }
    
    return pairs;
}
```

Этот подход имеет временную сложность `O(n log n)` из-за сортировки, но пространственную сложность `O(1)` дополнительной памяти (не считая памяти для результата). Он особенно эффективен, когда массив уже отсортирован или когда можно позволить себе сортировку.

## Решение проблем

При работе с поиском пар с заданной суммой могут возникать различные проблемы. Если алгоритм работает медленнее, чем ожидалось, проверьте, используете ли вы оптимальный подход для вашего случая. Для больших массивов избегайте вложенных циклов `O(n²)` и используйте подходы с `HashMap` или двумя указателями, которые имеют лучшую временную сложность.

Если возникают проблемы с памятью, убедитесь, что вы используете подход с линейной пространственной сложностью `O(n)` вместо подхода с квадратичной сложностью `O(n²)`. Это особенно важно для больших массивов, где разница в использовании памяти может быть значительной.

Если результаты не соответствуют ожиданиям, проверьте обработку граничных случаев. Убедитесь, что ваш код корректно обрабатывает случаи, когда массив пуст, содержит один элемент, все элементы одинаковы, или когда нет пар с заданной суммой. Также проверьте обработку переполнения при суммировании больших чисел.

## Частые вопросы

**Вопрос:** Какой подход выбрать для несортированного массива?

**Ответ:** Для несортированного массива рекомендуется использовать подход с `HashMap` или `HashSet`, который имеет временную сложность `O(n)`. Если массив можно отсортировать, можно использовать подход с двумя указателями, который имеет временную сложность `O(n log n)` из-за сортировки, но более эффективен по использованию памяти.

**Вопрос:** В чём разница между поиском всех пар и поиском уникальных пар?

**Ответ:** Поиск всех пар возвращает все возможные комбинации элементов, включая дубликаты и пары с одинаковыми элементами в разном порядке. Поиск уникальных пар возвращает только уникальные комбинации элементов, исключая дубликаты. Выбор зависит от требований задачи.

**Вопрос:** Можно ли использовать эти подходы для поиска трёх элементов с заданной суммой?

**Ответ:** Да, подходы можно адаптировать для поиска трёх элементов с заданной суммой. Можно использовать вложенные циклы или комбинировать подход с двумя указателями с подходом с `HashMap` для достижения временной сложности `O(n²)`.

**Вопрос:** Как обрабатывать переполнение при суммировании больших чисел?

**Ответ:** При работе с большими числами важно проверять переполнение. Можно использовать `long` вместо `int` для хранения сумм или проверять переполнение перед суммированием. Также можно использовать библиотечные методы для безопасного суммирования.

**Вопрос:** Можно ли использовать эти подходы для работы с отрицательными числами?

**Ответ:** Да, все подходы работают с отрицательными числами без изменений. Алгоритмы корректно обрабатывают отрицательные значения, так как они основаны на сравнении сумм, а не на абсолютных значениях элементов.

**Вопрос:** Как оптимизировать алгоритм для работы с отсортированным массивом?

**Ответ:** Для отсортированного массива наиболее эффективен подход с двумя указателями, который имеет временную сложность `O(n)` и пространственную сложность `O(1)` дополнительной памяти. Это позволяет избежать необходимости в использовании дополнительных структур данных.

## Глоссарий терминов

`Pairs with Given Sum` — задача поиска всех пар чисел в массиве, сумма которых равна заданному числу.

`HashMap` — структура данных, которая хранит пары ключ-значение и обеспечивает быстрый доступ к значениям по ключу. Используется для отслеживания уже обработанных элементов и их дополнений.

`HashSet` — структура данных, которая хранит уникальные элементы и обеспечивает быстрый доступ для проверки наличия элемента. Используется для отслеживания уже просмотренных элементов.

`Два указателя` — техника алгоритмики, использующая два индекса для прохода по массиву с разных сторон. Эффективна для отсортированных массивов.

`Дополнение` — число, которое нужно прибавить к элементу, чтобы получить заданную сумму. Для элемента `a` и суммы `sum` дополнение равно `sum - a`.

`Уникальные пары` — пары элементов, которые отличаются друг от друга либо значениями, либо порядком элементов в паре.

`Грубая сила` — подход к решению задачи путём проверки всех возможных комбинаций элементов. Прост в реализации, но может быть неэффективен по времени выполнения.

## Дополнительные примеры использования

### Пример 1: Поиск пар товаров с заданной общей стоимостью

```java
// Поиск пар товаров, сумма цен которых равна заданному значению
public static List<Pair<Product, Product>> findProductPairs(List<Product> products, int targetPrice) {
    List<Pair<Product, Product>> pairs = new ArrayList<>();
    Map<Integer, Product> priceMap = new HashMap<>();
    
    // Проходим по списку товаров
    for (Product product : products) {
        int price = product.getPrice();
        int complement = targetPrice - price;
        
        // Если найдено дополнение, значит есть пара товаров с нужной суммой
        if (priceMap.containsKey(complement)) {
            pairs.add(new Pair<>(product, priceMap.get(complement)));
        }
        
        // Сохраняем товар в карте по его цене
        priceMap.put(price, product);
    }
    
    return pairs;
}
```

### Пример 2: Поиск пар чисел с заданной суммой в отсортированном массиве

```java
// Оптимизированная версия для отсортированного массива
public static List<int[]> findPairsInSortedArray(int[] sortedArray, int sum) {
    List<int[]> pairs = new ArrayList<>();
    int left = 0;
    int right = sortedArray.length - 1;
    
    // Используем два указателя для эффективного поиска
    while (left < right) {
        int currentSum = sortedArray[left] + sortedArray[right];
        
        if (currentSum == sum) {
            // Найдена пара с заданной суммой
            pairs.add(new int[]{sortedArray[left], sortedArray[right]});
            // Пропускаем дубликаты для избежания повторений
            while (left < right && sortedArray[left] == sortedArray[left + 1]) {
                left++;
            }
            while (left < right && sortedArray[right] == sortedArray[right - 1]) {
                right--;
            }
            left++;
            right--;
        } else if (currentSum < sum) {
            // Увеличиваем сумму, сдвигая левый указатель
            left++;
        } else {
            // Уменьшаем сумму, сдвигая правый указатель
            right--;
        }
    }
    
    return pairs;
}
```

### Пример 3: Поиск всех уникальных пар с обработкой дубликатов

```java
// Поиск уникальных пар с использованием Set для избежания дубликатов
public static Set<Pair<Integer, Integer>> findUniquePairsSet(int[] input, int sum) {
    Set<Pair<Integer, Integer>> uniquePairs = new HashSet<>();
    Set<Integer> seen = new HashSet<>();
    
    for (int num : input) {
        int complement = sum - num;
        
        // Если дополнение уже было просмотрено, добавляем пару
        if (seen.contains(complement)) {
            // Нормализуем пару (меньший элемент первым) для избежания дубликатов
            int min = Math.min(num, complement);
            int max = Math.max(num, complement);
            uniquePairs.add(new Pair<>(min, max));
        }
        
        seen.add(num);
    }
    
    return uniquePairs;
}
```

## Когда использовать

Выбор подходящего подхода зависит от конкретных требований задачи и характеристик данных.

Используйте подход с вложенными циклами (`O(n²)`), когда нужны все пары, включая дубликаты, массив небольшой, или когда простота реализации важнее производительности. Этот подход прост в понимании и реализации, но неэффективен для больших массивов.

Используйте подход с `HashMap` или `HashSet` (`O(n)`), когда нужны только уникальные пары, массив большой, или когда важна производительность. Этот подход обеспечивает оптимальную производительность для большинства практических случаев.

Используйте подход с двумя указателями (`O(n log n)`), когда массив можно отсортировать, порядок элементов не важен, или когда важна эффективность по использованию памяти. Этот подход особенно эффективен для отсортированных массивов, где он имеет временную сложность `O(n)`.

## Лучшие практики

При реализации поиска пар с заданной суммой важно следовать нескольким лучшим практикам. Выбор подхода зависит от характеристик данных: для несортированного массива используйте хеш-карту для подсчёта пар за `O(n)`, для отсортированного массива используйте два указателя после сортировки `O(n log n)` или `O(n)` если массив уже отсортирован.

Уникальность пар требует особого внимания: уточняйте, нужны ли все пары или только уникальные комбинации. При уникальных используйте `Set` или хеш-карту для отслеживания уже найденных пар и избежания дубликатов.

Граничные случаи требуют тщательной обработки: проверяйте `null`, пустой массив и переполнение при суммировании (`int`/`long`). Также обрабатывайте случаи, когда нет пар с заданной суммой, все элементы одинаковы, или массив содержит один элемент.

Производительность важна для больших массивов: избегайте вложенных циклов `O(n²)` при больших `n`. Предпочтительны два указателя или хеш-карта, которые обеспечивают лучшую временную сложность. Для очень больших массивов рассмотрите возможность использования параллельной обработки или распределённых алгоритмов.
