# K-й наименьший в двух отсортированных массивах (Kth Smallest in Two Sorted Arrays)
Поиск k-го наименьшего элемента в объединении двух отсортированных массивов — классическая задача с тремя основными подходами: сортировка объединённого массива `O((n+m) log(n+m))`, слияние до k-го элемента `O(k)` и бинарный поиск по «разрезу» `O(log(min(n,m)))`. В документе рассмотрены реализации на Java и Kotlin, критерии остановки бинарного поиска, обработка граничных случаев и рекомендации по выбору подхода.

## Описание алгоритма

Мы ищем k-й наименьший элемент в объединении двух отсортированных массивов. Рассматриваются три подхода: сортировка объединённого массива, слияние до k-й позиции и бинарный поиск по «разрезу» двух массивов. Для демонстрации используются примеры и код на `Java` и `Kotlin`; алгоритмы применимы ко всем сравнимым типам данных.

Чтобы задать задачу формально, пусть есть два отсортированных массива `a` и `b`, возможно разной длины. Нужно вернуть элемент, который окажется k-м при гипотетическом слиянии и сортировке обоих массивов. Пример: `a = [3, 4, 6, 10, 11, 15]`, `b = [1, 5, 8, 12, 14, 19]`. Объединённый отсортированный массив `c = [1, 3, 4, 5, 6, 8, 10, 11, 12, 14, 15, 19]`, где 1-й элемент — `1`, а 4-й — `5`. В расчёте учитываются все вхождения, то есть дубликаты считаются отдельными элементами; это важно для корректной индексации k.

## Подход 1: Сортировка

Самый простой способ найти k-й наименьший элемент — соединить массивы, отсортировать их и вернуть элемент на позиции k в объединении:

```java
// k-й наименьший в двух отсортированных массивах: слияние и сортировка O((n+m)*log(n+m)), возврат элемента k-1.
int getKthElementSorted(int[] list1, int[] list2, int k) {
    int length1 = list1.length, length2 = list2.length;
    int[] combinedArray = new int[length1 + length2];

    System.arraycopy(list1, 0, combinedArray, 0, list1.length);
    System.arraycopy(list2, 0, combinedArray, list1.length, list2.length);
    Arrays.sort(combinedArray);

    return combinedArray[k - 1];
}
```

Если `n` — длина первого массива, а `m` — длина второго массива, общая длина `c = n + m`. Сортировка объединения стоит `O((n+m) · log(n+m))`, поэтому итоговая сложность совпадает, а память `O(n+m)` расходуется на копию данных. Недостаток подхода в том, что мы копируем оба массива и сортируем всё, даже если нужен только один элемент.

## Подход 2: Слияние (Merge)

Подобно одному шагу алгоритма сортировки слиянием, мы можем объединить два массива, а затем напрямую получить k-й элемент.

Основная идея алгоритма слияния состоит в том, чтобы начать с двух указателей, которые указывают на первые элементы первого и второго массивов (a).

Затем мы сравниваем два элемента (3 и 4) по указателям, добавляем меньший элемент (3) к результату и перемещаем этот указатель на одну позицию вперед (b). Снова сравниваем элементы по указателям и добавляем к результату меньший (4).

Продолжаем таким же образом, пока все элементы не будут добавлены в полученный массив. Если один из входных массивов не имеет больше элементов, мы просто копируем все оставшиеся элементы другого входного массива в результирующий массив.

Мы можем улучшить производительность, если не будем объединять полные массивы, а остановимся, когда в результирующем массиве будет k элементов. Нам даже не нужно создавать дополнительный массив для объединенного массива, а можно работать только с исходными массивами.

### Реализация

Вот реализация на Java:

```java
public static int getKthElementMerge(int[] list1, int[] list2, int k) {
    int i1 = 0, i2 = 0;

    while (i1 < list1.length && i2 < list2.length && (i1 + i2) < k) {
        if (list1[i1] < list2[i2]) {
            i1++;
        } else {
            i2++;
        }
    }

    if ((i1 + i2) < k) {
        return i1 < list1.length ? list1[k - i2 - 1] : list2[k - i1 - 1];
    } else if (i1 > 0 && i2 > 0) {
        return Math.max(list1[i1 - 1], list2[i2 - 1]);
    } else {
        return i1 == 0 ? list2[i2 - 1] : list1[i1 - 1];
    }
}
```

Несложно понять, что временная сложность этого алгоритма составляет `O(k)`. Преимущество этого алгоритма в том, что его можно легко адаптировать для учета повторяющихся элементов только один раз.

## Подход 3: Бинарный поиск

Можем ли мы сделать лучше, чем `O(k)`? Ответ заключается в том, что мы можем. Основная идея состоит в том, чтобы выполнить алгоритм бинарного поиска по двум массивам.

Чтобы это работало, нам нужна структура данных, которая обеспечивает постоянный доступ для чтения ко всем ее элементам. В Java это может быть массив или ArrayList.

### Скелет метода

Давайте определим скелет метода, который мы собираемся реализовать:

```java
int findKthElement(int k, int[] list1, int[] list2)
    throws NoSuchElementException, IllegalArgumentException {
    // Реализация
}
```

Здесь мы передаем k и два массива в качестве аргументов. Во-первых, мы проверим ввод; во-вторых, мы обрабатываем некоторые особые случаи, а затем выполняем бинарный поиск.

### Принцип работы

Стандартный бинарный поиск, когда мы ищем определенный элемент, имеет два возможных результата: либо мы находим искомый элемент, и поиск завершается успешно, либо мы его не находим, и поиск завершается неудачно. В нашем случае все по-другому, когда мы хотим найти k-й наименьший элемент. Здесь у нас всегда есть результат.

Мы начинаем наш поиск с определенного количества элементов из первого массива. Назовем этот номер `nElementsList1`. Поскольку всего нам нужно k элементов, число `nElementsList2` равно:

```java
int nElementsList2 = k - nElementsList1;
```

Например, пусть k = 8. Начнем с четырех элементов из первого массива и четырех элементов из второго массива (а).

Если 4-й элемент в первом массиве больше, чем 4-й элемент во втором массиве, мы знаем, что мы взяли слишком много элементов из первого массива, и можем уменьшить `nElementsList1` (b). В противном случае мы знаем, что взяли слишком мало элементов и можем увеличить `nElementsList1` (b').

Мы продолжаем, пока не достигнем критерия остановки.

### Реализация бинарного поиска

```java
int right = k;
int left = 0;

do {
    nElementsList1 = ((left + right) / 2) + 1;
    nElementsList2 = k - nElementsList1;

    if (nElementsList2 > 0) {
        if (list1[nElementsList1 - 1] > list2[nElementsList2 - 1]) {
            right = nElementsList1 - 2;
        } else {
            left = nElementsList1;
        }
    }
} while (!kthSmallestElementFound(list1, list2, nElementsList1, nElementsList2));
```

### Критерии остановки

Мы можем остановиться в двух случаях. Во-первых, мы можем остановиться, если максимальный элемент, который мы берем из первого массива, равен максимальному элементу, который мы берем из второго (c). В этом случае мы можем просто вернуть этот элемент.

Во-вторых, мы можем остановиться, если выполняются следующие два условия (d):

1. Самый большой элемент, который нужно взять из первого массива, меньше, чем самый маленький элемент, который мы не берем из второго массива (11 < 100).
2. Самый большой элемент, который нужно взять из второго массива, меньше, чем самый маленький элемент, который мы не берем из первого массива (21 < 27).

Вот код для критериев остановки:

Полезно держать в голове два инварианта. Первое: сумма выбранных элементов всегда равна k (`nElementsList1 + nElementsList2 = k`). Второе: левые части обоих массивов должны образовывать корректный разрез, в котором максимум слева не превышает минимум справа. Если этот инвариант нарушен и левый максимум первого массива больше правого минимума второго, значит, взяли слишком много из первого — сдвигаем правую границу. Если наоборот, увеличиваем левую границу. Благодаря этому маятниковому движению границы сходятся логарифмически, и за `O(log(min(n,m)))` достигается корректный разрез.

Пример: `list1 = [1,4,7,10]`, `list2 = [2,3,6,8,9]`, `k = 5`. Стартуем с `nElementsList1 = 3`, `nElementsList2 = 2`, сравниваем `7` и `3` и понимаем, что взяли слишком много из первого. Пересчитываем: `nElementsList1 = 2`, `nElementsList2 = 3`; теперь максимум левой части (`4` и `6`) не превышает минимум правой (`7` и `8`), критерий выполнен, и ответ — максимум слева, то есть `6`.

```java
private static boolean foundCorrectNumberOfElementsInBothLists(
        int[] list1, int[] list2, int nElementsList1, int nElementsList2) {

    if (nElementsList2 < 1) {
        return true;
    }

    if (list1[nElementsList1 - 1] == list2[nElementsList2 - 1]) {
        return true;
    }

    if (nElementsList1 == list1.length) {
        return list1[nElementsList1 - 1] <= list2[nElementsList2];
    }

    if (nElementsList2 == list2.length) {
        return list2[nElementsList2 - 1] <= list1[nElementsList1];
    }

    return list1[nElementsList1 - 1] <= list2[nElementsList2]
        && list2[nElementsList2 - 1] <= list1[nElementsList1];
}
```

### Возврат результата

Наконец, нам нужно вернуть правильное значение. Здесь у нас есть три возможных случая:

1. Мы не берем элементы из второго массива, поэтому целевое значение находится в первом массиве (e)
2. Целевое значение находится в первом массиве (e')
3. Целевое значение находится во втором массиве (e")

Давайте посмотрим на это в коде:

```java
return nElementsList2 == 0
    ? list1[nElementsList1 - 1]
    : Math.max(list1[nElementsList1 - 1], list2[nElementsList2 - 1]);
```

### Адаптация границ

До сих пор мы инициализировали правую и левую границу для первого массива с помощью k и 0:

```java
int right = k;
int left = 0;
```

Однако в зависимости от значения k нам необходимо адаптировать эти границы.

Во-первых, если k превышает длину первого массива, нам нужно взять последний элемент в качестве правой границы. Причина этого довольно проста, так как мы не можем взять из массива больше элементов, чем есть.

Во-вторых, если k больше, чем количество элементов во втором массиве, мы точно знаем, что нам нужно взять как минимум (k — length(list2)) из первого массива.

Вот код для адаптированных левой и правой границ:

```java
int left = k < list2.length ? 0 : k - list2.length - 1;
int right = Math.min(k - 1, list1.length - 1);
```

### Обработка особых случаев

Прежде чем приступить к собственно бинарному поиску, мы можем обработать несколько особых случаев, чтобы сделать алгоритм чуть менее сложным и избежать исключений:

```java
if (k == 1) {
    return Math.min(list1[0], list2[0]);
}

if (list1.length + list2.length == k) {
    return Math.max(list1[list1.length - 1], list2[list2.length - 1]);
}

if (k <= list2.length && list2[k - 1] < list1[0]) {
    int[] temp = list1;
    list1 = list2;
    list2 = temp;
}
```

### Проверка ввода

Давайте сначала посмотрим на проверку ввода. Чтобы предотвратить сбой алгоритма и выброс, например, NullPointerException или ArrayIndexOutOfBoundsException, мы хотим убедиться, что три параметра соответствуют следующим условиям:

1. Оба массива не должны быть нулевыми и содержать хотя бы один элемент
2. k должен быть >= 0 и не может быть больше, чем длина двух массивов вместе

Вот наша проверка в коде:

```java
void checkInput(int k, int[] list1, int[] list2)
    throws NoSuchElementException, IllegalArgumentException {

    if (list1 == null || list2 == null || k < 1) {
        throw new IllegalArgumentException();
    }

    if (list1.length == 0 || list2.length == 0) {
        throw new IllegalArgumentException();
    }

    if (k > list1.length + list2.length) {
        throw new NoSuchElementException();
    }
}
```

### Полная реализация

Вот полный код алгоритма, который мы только что описали:

```java
public static int findKthElement(int k, int[] list1, int[] list2)
    throws NoSuchElementException, IllegalArgumentException {

    checkInput(k, list1, list2);

    if (k == 1) {
        return Math.min(list1[0], list2[0]);
    }

    if (list1.length + list2.length == k) {
        return Math.max(list1[list1.length - 1], list2[list2.length - 1]);
    }

    if (k <= list2.length && list2[k - 1] < list1[0]) {
        int[] temp = list1;
        list1 = list2;
        list2 = temp;
    }

    int left = k < list2.length ? 0 : k - list2.length - 1;
    int right = Math.min(k - 1, list1.length - 1);
    int nElementsList1, nElementsList2;

    do {
        nElementsList1 = ((left + right) / 2) + 1;
        nElementsList2 = k - nElementsList1;

        if (nElementsList2 > 0) {
            if (list1[nElementsList1 - 1] > list2[nElementsList2 - 1]) {
                right = nElementsList1 - 2;
            } else {
                left = nElementsList1;
            }
        }
    } while (!foundCorrectNumberOfElementsInBothLists(list1, list2, nElementsList1, nElementsList2));

    return nElementsList2 == 0
        ? list1[nElementsList1 - 1]
        : Math.max(list1[nElementsList1 - 1], list2[nElementsList2 - 1]);
}
```

## Сравнение подходов

| Характеристика | Сортировка | Слияние | Бинарный поиск |
|----------------|------------|---------|----------------|
| Временная сложность | `O(nlog(n)`) | `O(k)` | `O(log(n)`) |
| Пространственная сложность | `O(n)` | `O(1)` | `O(1)` |
| Простота | Простая | Средняя | Сложная |
| Применение | Малые массивы | Средние k | Большие массивы |

## Реализация на Kotlin

### Подход 1: Сортировка

```kotlin
fun getKthElementSortedK(list1: IntArray, list2: IntArray, k: Int): Int {
    val combinedArray = (list1 + list2).sortedArray()
    return combinedArray[k - 1]
}
```

### Подход 2: Слияние

```kotlin
fun getKthElementMergeK(list1: IntArray, list2: IntArray, k: Int): Int {
    var i1 = 0
    var i2 = 0

    while (i1 < list1.size && i2 < list2.size && (i1 + i2) < k) {
        if (list1[i1] < list2[i2]) {
            i1++
        } else {
            i2++
        }
    }

    return when {
        (i1 + i2) < k -> if (i1 < list1.size) list1[k - i2 - 1] else list2[k - i1 - 1]
        i1 > 0 && i2 > 0 -> maxOf(list1[i1 - 1], list2[i2 - 1])
        i1 == 0 -> list2[i2 - 1]
        else -> list1[i1 - 1]
    }
}
```

### Пример использования

```kotlin
fun main() {
    val list1 = intArrayOf(3, 4, 6, 10, 11, 15)
    val list2 = intArrayOf(1, 5, 8, 12, 14, 19)

    val kth1 = getKthElementSortedK(list1, list2, 4)
    println("4th element (sorted): $kth1") // 5

    val kth2 = getKthElementMergeK(list1, list2, 4)
    println("4th element (merge): $kth2") // 5
}
```

## Сложность

У подхода с сортировкой временная сложность `O((n+m)·log(n+m))`, потому что требуется отсортировать объединённый массив, а дополнительная память `O(n+m)` расходуется на копию данных. Слияние до k-й позиции работает за `O(k)` и использует только константную память, так как хранит лишь индексы в обоих массивах. Бинарный поиск по «разрезу» даёт `O(log(min(n,m)))` времени и `O(1)` памяти, поскольку двигает границы в меньшем массиве и читает элементы по индексам без выделений.

## Особенности

Алгоритм через бинарный поиск оптимален по времени для больших массивов, но заметно сложнее в реализации и требует тщательной обработки границ и критериев остановки. Сортировка объединения даёт простой и понятный код ценой высокой асимптотики и дополнительной памяти. Слияние до k-й позиции остаётся компромиссом: простой контроль индексов, линейное время по k и константная память, что подходит для умеренных значений k.

## Применение

Поиск k-го элемента в двух отсортированных массивах встречается в вычислении медианы (частный случай при k = (n+m)/2), в статистических задачах выбора порядковых статистик, в алгоритмах ранжирования и агрегации результатов, а также в обработке больших данных, где нужно быстро получать k-й минимум без полной сортировки. Подход особенно полезен, когда массивы уже отсортированы, а дополнительная память ограничена.

Практическая деталь — нормализация входа. Если один массив существенно длиннее другого, для бинарного поиска выгодно всегда работать по меньшему: меняйте массивы местами, чтобы минимизировать глубину поиска. Ещё одна оптимизация — ранний выход: если k меньше длины первого массива и первый элемент первого массива меньше первого второго, для маленьких k иногда достаточно взять префикс первого массива. Тем не менее, общий алгоритм бинарного поиска остаётся надёжнее и чище.

## Лучшие практики

Выбирайте подход исходя из ограничения по времени и памяти: сортировка объединения проста, но дорога; слияние до k даёт `O(k)` без лишних копий; бинарный поиск минимизирует время до `O(log(min(n,m)))`, но требует аккуратного кода. Всегда фиксируйте, является ли k 1-based или 0-based, и корректно используйте индекс `k-1` при обращении к массиву. Согласуйте политику учёта дубликатов заранее: считать каждое вхождение или уникальные значения — это влияет на критерии остановки и тесты. Для медианы подставляйте k = `(n+m)/2` (или два центральных значения при чётной длине) и обрабатывайте граничные случаи явно. Перед запуском проверяйте сортировку входных массивов и допустимость k, чтобы избежать выходов за границы.

## Решение проблем

Если бинарный поиск возвращает неверный элемент, проверьте корректность границ `left/right` и вычисления `nElementsList1`/`nElementsList2`: ошибка на единицу смещает итоговую позицию. При выходе за границы убедитесь, что k не превышает `n+m` и что массивы не пустые. Для слияния до k частая проблема — неправильный расчёт условной остановки `(i1 + i2) < k`; убедитесь, что сравнение идёт до тех пор, пока не набрали k элементов. Если производительность проседает, убедитесь, что не сортируете массивы повторно и не создаёте лишних копий в горячих циклах.

Ещё одна типичная ошибка — переполнение индексов при суммировании `i1 + i2` на очень больших массивах; используйте `long` для промежуточных вычислений. Убедитесь, что входные массивы действительно отсортированы: несортированный вход ломает бинарный поиск, и единственный способ защититься — предусмотреть предварительную проверку или контракт метода. При работе с обобщёнными типами следите за компаратором: несогласованные сравнения приводят к нарушению транзитивности и неверным результатам.

## Частые вопросы

Вопрос: Почему бинарный поиск двигает границы только в меньшем массиве? Ответ: Это ограничивает количество шагов `O(log(min(n,m)))` и упрощает проверку условий, сохраняя корректные индексы во втором массиве через k — nElementsList1.
Вопрос: Можно ли использовать подходы для массивов разной природы (например, списки)? Ответ: Да, если обеспечен `O(1)` доступ по индексу; иначе стоимость обращений делает бинарный поиск менее эффективным.
Вопрос: Как обрабатывать k, равный 1 или n+m? Ответ: Возвращайте минимум первых элементов при k=1 и максимум последних при k=n+m, чтобы избежать лишней логики в бинарном поиске.
Вопрос: Нужно ли копировать массивы перед сортировкой? Ответ: Да, если нельзя изменять исходные данные; копия предотвращает побочные эффекты и сохраняет контракт метода.
Вопрос: Что делать с дубликатами? Ответ: Определите политику заранее; по умолчанию считаете каждое вхождение отдельным элементом, иначе придётся изменять критерии остановки и слияния.

## Глоссарий терминов

`k-th order statistic` — k-я порядковая статистика, элемент, который стоит на k-й позиции в отсортированной последовательности.
`Merge` — поэлементное слияние двух отсортированных коллекций в один отсортированный поток.
`Partition` или «разрез» — выбор числа элементов из первого массива так, чтобы остаток k брался из второго, формируя две части объединения.
`Boundary conditions` — граничные случаи, включающие пустые массивы, экстремальные значения k и совпадающие элементы на границе разреза.
`Idempotent read` — доступ к элементам без изменения коллекции; важно для работы бинарного поиска без копирования.

## Дополнительные примеры использования

### Пример 1: Быстрая оценка медианы

Если нужно вычислить медиану двух логов метрик, используйте бинарный поиск с k = `(n+m)/2`, обрабатывая чётную длину как максимум левых частей двух разрезов или среднее двух центральных элементов, если требуется дробная медиана. Упрощённый фрагмент:

```java
double medianTwoArrays(int[] a, int[] b) {
    int total = a.length + b.length;
    boolean even = (total % 2 == 0);
    int k1 = (total + 1) / 2;
    int left = findKthElement(k1, a, b);
    if (!even) return left;
    int right = findKthElement(k1 + 1, a, b);
    return (left + right) / 2.0;
}
```

### Пример 2: k-й минимум в потоках

При поступлении двух отсортированных потоков (например, результаты двух сервисов) можно поддерживать индексы и выполнять слияние до k, не храня весь объединённый поток; это уменьшает память до константной и даёт предсказуемое время.

```java
int kthFromStreams(IntStream s1, IntStream s2, int k) {
    PrimitiveIterator.OfInt it1 = s1.iterator();
    PrimitiveIterator.OfInt it2 = s2.iterator();
    boolean has1 = it1.hasNext(), has2 = it2.hasNext();
    int v1 = has1 ? it1.nextInt() : Integer.MAX_VALUE;
    int v2 = has2 ? it2.nextInt() : Integer.MAX_VALUE;

    for (int consumed = 1; consumed < k; consumed++) {
        if (v1 <= v2) {
            has1 = it1.hasNext();
            v1 = has1 ? it1.nextInt() : Integer.MAX_VALUE;
        } else {
            has2 = it2.hasNext();
            v2 = has2 ? it2.nextInt() : Integer.MAX_VALUE;
        }
    }
    return Math.min(v1, v2);
}
```

### Пример 3: Смешанные типы данных

Алгоритм обобщается на любые сравнимые типы. При использовании дженериков обеспечьте компаратор и избегайте автоупаковки в горячих циклах, чтобы не потерять производительность.

```java
public static <T> T kthGeneric(int k, List<T> a, List<T> b, Comparator<T> cmp) {
    if (a.isEmpty() || b.isEmpty()) throw new IllegalArgumentException();
    // Для краткости используем копию и сортировку
    List<T> merged = new ArrayList<>(a.size() + b.size());
    merged.addAll(a);
    merged.addAll(b);
    merged.sort(cmp);
    return merged.get(k - 1);
}
```

## Проверка и тестирование

Надёжность алгоритма зависит от покрытия граничных случаев. Для единичных тестов в `Java` удобно использовать `JUnit` с проверкой разных значений k и размеров массивов:

```java
@Test
void findKth_handlesBorders() {
    int[] a = {1, 3, 8};
    int[] b = {2, 4, 6, 10};

    assertEquals(1, findKthElement(1, a, b));
    assertEquals(4, findKthElement(4, a, b));
    assertEquals(10, findKthElement(7, a, b));
}

@Test
void findKth_handlesDuplicates() {
    int[] a = {1, 1, 3};
    int[] b = {1, 2, 2, 4};
    assertEquals(1, findKthElement(2, a, b));
    assertEquals(2, findKthElement(5, a, b));
}
```

Для Kotlin-проектов можно оформить аналогичные проверки с `kotest` или `JUnit`:

```kotlin
class KthElementTest {
    @Test

        val a = intArrayOf(1, 3, 8)
```

Для дополнительной уверенности полезно сделать property-based тест: сгенерировать два случайных отсортированных массива, случайное k, и сравнить результат бинарного поиска с результатом простого слияния и сортировки. Это снижает риск ошибок в обработке границ и дубликатов.

Для оценки производительности удобно использовать `JMH`. Небольшой пример бенчмарка для сравнения слияния и бинарного поиска:

Запуск такого бенчмарка покажет, при каких размерах массивов бинарный поиск начинает выигрывать у линейного слияния и насколько критичны накладные расходы на сортировку.

Для Kotlin можно вынести валидацию входа в отдельную функцию и переиспользовать во всех реализациях:

```kotlin
fun validateInput(k: Int, a: IntArray, b: IntArray) {
    require(k in 1..(a.size + b.size)) { \"k out of range\" }
    require(a.isNotEmpty() && b.isNotEmpty()) { \"Arrays must be non-empty\" }
}
```

Такие небольшие утилиты помогают унифицировать проверки и уменьшить количество условного кода внутри основного алгоритма.

## Когда использовать

Подход с сортировкой подходит для небольших массивов и одноразовых вычислений, где простота важнее. Слияние до k целесообразно, когда k мало относительно размеров массивов и нужно минимум памяти. Бинарный поиск предпочтителен при больших массивах и произвольных k, когда критична скорость и доступ по индексу дешев. Во всех случаях убедитесь, что входные массивы отсортированы и политика обработки дубликатов согласована.

Для потоковых или распределённых сценариев выбирайте слияние до k: его проще распараллелить и подать на несколько воркеров. Если входы поступают порциями, поддерживайте текущие индексы и обновляйте k-ю позицию инкрементально, избегая полной переработки данных.

## Заключение

Мы рассмотрели три подхода к поиску k-го наименьшего элемента в двух отсортированных массивах: сортировку объединения, слияние до k-й позиции и бинарный поиск по разрезу. Каждый метод балансирует простоту, время и память по-своему. Для большинства прикладных сценариев достаточно слияния до k или сортировки; когда требуется строгая оптимальность по времени, бинарный поиск даёт лучший результат при цене более сложной реализации. Явно фиксируйте индексацию k, обработку дубликатов и граничные случаи — это убережёт от ошибок и обеспечит предсказуемое поведение.

В реальных системах итоговый выбор часто определяется не только асимптотикой, но и требованиями к поддерживаемости. Если команда реже сталкивается с двоичным разрезом, оставьте подробные комментарии и тесты, чтобы алгоритм было легко сопровожать. Согласованные контракты на вход и чёткие тесты делают решение надёжным и предсказуемым.
