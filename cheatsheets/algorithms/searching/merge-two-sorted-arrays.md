# Слияние двух отсортированных массивов (`Merge Two Sorted Arrays`)

Объединение двух отсортированных массивов в один отсортированный — классическая операция с временной сложностью `O(n + m)` при использовании двух указателей. Алгоритм является базовым шагом сортировки слиянием и применяется при слиянии результатов из разных источников, в операциях с базами данных и при обработке больших данных. В документе рассмотрены реализации на Java и Kotlin, варианты in-place и без дубликатов, объединение k массивов через min-heap, сравнение сложности и практические рекомендации.

## Описание алгоритма

Объединение двух отсортированных массивов — классическая операция, лежащая в основе сортировки слиянием (`merge sort`). Это фундаментальный приём, который используется во многих алгоритмах сортировки и обработки данных: при слиянии результатов из разных источников, в операциях с базами данных и при распределённой обработке.

## Идея алгоритма

Используются два указателя: на каждом шаге сравниваются текущие элементы двух массивов и в результирующий массив записывается меньший, после чего соответствующий указатель сдвигается. Имеем два массива `foo` и `bar`, создаём массив `merged` длиной `foo.length + bar.length`, двигаем указатели `fooPosition` и `barPosition`, добавляя в `merged` меньший из текущих элементов. Когда один из массивов исчерпан, оставшиеся элементы второго копируются в конец результата.

### Пример работы

Ниже показана пошаговая трассировка слияния двух коротких массивов. На каждом шаге сравниваются текущие элементы (по одному из каждого массива), меньший записывается в результат, соответствующий указатель сдвигается. Когда один массив исчерпан, оставшиеся элементы второго копируются в конец без сравнения.

```text
foo = [3, 7]
bar = [4, 8, 11]

Шаг 1: Сравниваем 3 и 4 → добавляем 3
merged = [3]

Шаг 2: Сравниваем 7 и 4 → добавляем 4
merged = [3, 4]

Шаг 3: Сравниваем 7 и 8 → добавляем 7
merged = [3, 4, 7]

Шаг 4: foo закончился → копируем остаток bar
merged = [3, 4, 7, 8, 11]
```

## Реализация на Java

### Реализация

```java
// Слияние двух отсортированных массивов за O(n+m): два указателя, выбор меньшего элемента.
public static int[] merge(int[] foo, int[] bar) {
    int fooLength = foo.length;
    int barLength = bar.length;
    int[] merged = new int[fooLength + barLength];
    
    int fooPosition = 0;
    int barPosition = 0;
    int mergedPosition = 0;
    
    while (fooPosition < fooLength && barPosition < barLength) {
        if (foo[fooPosition] < bar[barPosition]) {
            merged[mergedPosition++] = foo[fooPosition++];
        } else {
            merged[mergedPosition++] = bar[barPosition++];
        }
    }
    
    while (fooPosition < fooLength) {
        merged[mergedPosition++] = foo[fooPosition++];
    }
    
    while (barPosition < barLength) {
        merged[mergedPosition++] = bar[barPosition++];
    }
    
    return merged;
}
```

### Объяснение реализации

При инициализации создаётся результирующий массив и три указателя: по одному на каждый из входных массивов и один на позицию записи в результат. В основном цикле, пока оба массива не исчерпаны, сравниваются текущие элементы и в `merged` записывается меньший, после чего сдвигается соответствующий указатель. После выхода из цикла остаток того массива, который ещё не закончился, копируется в конец результата одним или двумя циклами.

### Альтернативная реализация (in-place для одного массива)

Если нужно объединить две отсортированные части одного массива (например, левую `[left..mid]` и правую `[mid+1..right]`), используется временный массив для слияния с последующим копированием обратно в исходный массив.

```java
// Слияние двух частей одного массива [left..mid] и [mid+1..right] во временный массив, затем копирование обратно
public static void mergeInPlace(int[] arr, int left, int mid, int right) {
    int[] temp = new int[right - left + 1];
    int i = left, j = mid + 1, k = 0;

    while (i <= mid && j <= right) {
        if (arr[i] <= arr[j]) {
            temp[k++] = arr[i++];
        } else {
            temp[k++] = arr[j++];
        }
    }
    while (i <= mid) {
        temp[k++] = arr[i++];
    }
    while (j <= right) {
        temp[k++] = arr[j++];
    }
    System.arraycopy(temp, 0, arr, left, temp.length);
}
```

## Реализация на Kotlin

### Основная реализация

```kotlin
// Слияние двух отсортированных массивов: два указателя, на каждом шаге — меньший элемент
fun mergeK(foo: IntArray, bar: IntArray): IntArray {
    val fooLength = foo.size
    val barLength = bar.size
    val merged = IntArray(fooLength + barLength)
    var fooPosition = 0
    var barPosition = 0
    var mergedPosition = 0

    while (fooPosition < fooLength && barPosition < barLength) {
        if (foo[fooPosition] < bar[barPosition]) {
            merged[mergedPosition++] = foo[fooPosition++]
        } else {
            merged[mergedPosition++] = bar[barPosition++]
        }
    }
    while (fooPosition < fooLength) {
        merged[mergedPosition++] = foo[fooPosition++]
    }
    while (barPosition < barLength) {
        merged[mergedPosition++] = bar[barPosition++]
    }
    return merged
}
```

### Объединение без дубликатов

```kotlin
// Слияние без дубликатов: добавляем элемент только если он не равен последнему в result
fun mergeWithoutDuplicatesK(foo: IntArray, bar: IntArray): IntArray {
    val result = mutableListOf<Int>()
    var i = 0
    var j = 0

    while (i < foo.size && j < bar.size) {
        when {
            foo[i] < bar[j] -> {
                if (result.isEmpty() || result.last() != foo[i]) result.add(foo[i])
                i++
            }
            foo[i] > bar[j] -> {
                if (result.isEmpty() || result.last() != bar[j]) result.add(bar[j])
                j++
            }
            else -> {
                if (result.isEmpty() || result.last() != foo[i]) result.add(foo[i])
                i++
                j++
            }
        }
    }
    while (i < foo.size) {
        if (result.isEmpty() || result.last() != foo[i]) result.add(foo[i])
        i++
    }
    while (j < bar.size) {
        if (result.isEmpty() || result.last() != bar[j]) result.add(bar[j])
        j++
    }
    return result.toIntArray()
}
```

## Сложность

### Временная сложность

Во всех случаях временная сложность составляет `O(n + m)`, где `n` и `m` — длины двух массивов. Каждый элемент из обоих массивов посещается ровно один раз: в основном цикле мы всегда сдвигаем один из двух указателей, поэтому суммарное число итераций не превышает `n + m`. Дополнительные циклы копирования остатка также выполняют не более `n + m` присваиваний.

### Пространственная сложность

При использовании дополнительного массива требуется `O(n + m)` для результирующего массива. In-place версия также использует временный массив длины `O(n + m)` для слияния перед копированием обратно.

## Особенности

Алгоритм стабилен: при равенстве элементов сохраняется относительный порядок (обычно сначала берётся элемент из первого массива). Временная сложность линейная `O(n + m)`, реализация проста и хорошо масштабируется. Операция слияния двух отсортированных массивов является основным шагом алгоритма сортировки слиянием (`Merge Sort`).

## Применение

Объединение отсортированных массивов используется в сортировке слиянием (`Merge Sort`) как основной шаг; при объединении результатов из разных источников (например, из нескольких отсортированных потоков); при слиянии отсортированных списков в одном приложении; в операциях с базами данных (например, `UNION` с сортировкой); при обработке больших данных в стиле `MapReduce`, когда отдельные части уже отсортированы. В распределённых системах слияние по ключу (например, по времени события) позволяет собирать данные с нескольких узлов без полной пересортировки. В поисковых и рекомендательных системах слияние отсортированных по релевантности списков даёт единый ранжированный результат.

## Варианты задачи

### Вариант 1: Объединение без дубликатов

```java
// Слияние двух отсортированных массивов без дубликатов: не добавляем элемент, если он равен последнему в result
public static int[] mergeWithoutDuplicates(int[] foo, int[] bar) {
    List<Integer> result = new ArrayList<>();
    int i = 0, j = 0;

    while (i < foo.length && j < bar.length) {
        if (foo[i] < bar[j]) {
            if (result.isEmpty() || result.get(result.size() - 1) != foo[i]) result.add(foo[i]);
            i++;
        } else if (foo[i] > bar[j]) {
            if (result.isEmpty() || result.get(result.size() - 1) != bar[j]) result.add(bar[j]);
            j++;
        } else {
            if (result.isEmpty() || result.get(result.size() - 1) != foo[i]) result.add(foo[i]);
            i++;
            j++;
        }
    }
    // Копируем остатки из foo и bar (здесь опущено для краткости; в полной версии — два цикла + toArray)
    return result.stream().mapToInt(x -> x).toArray();
}
```

### Вариант 2: Объединение k отсортированных массивов

Для объединения k отсортированных массивов можно последовательно объединять по два массива — тогда суммарная сложность будет `O(k * n)`. Более эффективный вариант — использовать приоритетную очередь (min-heap): в куче хранятся пары (значение, индекс массива, индекс в массиве). На каждом шаге из кучи извлекается минимальный элемент, он записывается в результат, и в кучу добавляется следующий элемент из того же массива (если он есть). Каждый из n элементов обрабатывается один раз, операции с кучей — O(log k), итого `O(n * log k)`. Это стандартный подход при слиянии k отсортированных потоков или файлов.

Идея реализации с min-heap на Java: в приоритетную очередь помещаются элементы вида (значение, номер массива, индекс в массиве), упорядоченные по значению. Инициализация — первые элементы каждого массива. В цикле извлекаем минимум, записываем в результат, и если в том массиве есть следующий элемент — добавляем его в кучу. Использование `PriorityQueue` с компаратором по значению даёт нужную сложность.

## Частые ошибки

Копирование остатка только из одного массива: после основного цикла нужно скопировать остаток и из первого, и из второго массива (два цикла или два вызова `arraycopy`). Путаница границ в in-place версии: индексы должны быть `left..mid` и `mid+1..right`, длина временного массива — `right - left + 1`. Забывание проверки на `null` и пустые массивы приводит к `NullPointerException` или некорректному результату. При слиянии без дубликатов важно сравнивать новый элемент с последним добавленным в результат, а не только с текущим в другом массиве.

## Альтернативные решения

Вместо слияния двух отсортированных массивов можно объединить их конкатенацией и затем отсортировать результат. Такой подход даёт сложность `O((n + m) log(n + m))` и оправдан только если входные массивы не отсортированы или сортировка уже требуется для других целей. Если оба массива уже отсортированы, слияние за `O(n + m)` всегда предпочтительнее. Для одного массива с двумя отсортированными половинами используется in-place слияние с временным массивом длины слияния — это стандартный шаг в сортировке слиянием.

## Сравнение с другими операциями

| Операция | Временная сложность | Применение |
|----------|---------------------|------------|
| Объединение двух массивов | `O(n + m)` | `Merge Sort`, объединение результатов |
| Объединение k массивов | `O(n * log k)` | Слияние множества источников |
| Сортировка массива | `O(n log n)` | Общая сортировка |

Слияние двух массивов выгодно именно когда порядок уже есть: мы используем его, а не пересчитываем заново.

## Оптимизации

Перед слиянием стоит проверять пустые массивы: если один из массивов пуст, возвращается копия другого. Если все элементы одного массива меньше всех элементов другого, результат по сути уже задан — можно скопировать оба массива подряд без пошагового сравнения. Для копирования остатков предпочтительно использовать `System.arraycopy` вместо циклов — это быстрее и короче.

## Лучшие практики

Проверяйте входные данные на `null` и пустые массивы; при одном пустом возвращайте копию другого. При сдвиге указателей сохраняйте инвариант: текущий префикс `merged` всегда отсортирован. Оставшиеся элементы копируйте одним вызовом `System.arraycopy` или одним циклом, а не поэлементно. Для стабильного слияния при равенстве элементов берите элемент из первого массива.

## Решение проблем

| Симптом | Возможная причина | Решение |
|--------|-------------------|---------|
| Результат не отсортирован | Указатели сдвигаются неверно или остаток не скопирован | Проверить условия в основном цикле и два цикла копирования остатков |
| `ArrayIndexOutOfBoundsException` | Выход за границу при копировании остатка | Убедиться, что индексы в пределах `foo.length` и `bar.length` |
| Дубликаты в результате | Требуется объединение без дубликатов | Использовать вариант `mergeWithoutDuplicates` с проверкой `result.last() != value` |
| NullPointerException | Один из массивов `null` | В начале метода проверять `foo == null` и `bar == null`, возвращать копию другого или пустой массив |

## Частые вопросы

**Нужно ли проверять, что массивы отсортированы?** Алгоритм не проверяет порядок; если входные массивы не отсортированы, результат тоже будет неверным. В отладочном режиме можно добавить проверку.

**Когда использовать in-place версию?** In-place вариант нужен, когда две отсортированные части лежат в одном массиве (например, после рекурсивного слияния в `Merge Sort`). Для двух отдельных массивов обычно используют вариант с новым массивом.

**Как объединить более двух массивов?** Либо последовательно вызывать слияние по два (проще, но `O(k*n)`), либо использовать min-heap с указателями на текущие позиции в каждом массиве — сложность `O(n * log k)`.

**Сохраняется ли стабильность сортировки?** Да, если при равенстве элементов всегда брать элемент из первого массива — относительный порядок равных элементов сохраняется.

**Что делать, если массивы очень большие?** Для данных, не помещающихся в память, используется внешнее слияние: части читаются из файлов или потоков, сливаются в буфер и записываются. При k источниках применяется k-way merge с min-heap.

**Нужно ли копировать остаток поэлементно?** Нет. В Java предпочтительно использовать `System.arraycopy`, в Kotlin — `copyInto` или цикл. Один вызов копирует весь хвост быстрее, чем поэлементный цикл.

## Глоссарий терминов

- **Два указателя (two pointers)** — приём, при котором по двум массивам (или последовательностям) двигаются два индекса и на каждом шаге выполняется сравнение текущих элементов и сдвиг одного из указателей. Используется в слиянии, поиске пары с заданной суммой и во многих других задачах.
- **In-place** — алгоритм, использующий только O(1) дополнительной памяти поверх входных данных. В контексте слияния двух частей одного массива допускается временный массив длины слияния, после чего результат копируется обратно в исходный массив.
- **Merge Sort** — сортировка слиянием; алгоритм сортировки, в котором массив делится пополам, части рекурсивно сортируются, затем объединяются слиянием двух отсортированных массивов. Слияние двух массивов — его ключевая подоперация.
- **Min-heap** — куча с минимумом в корне; используется для слияния k отсортированных последовательностей за O(n log k): в куче хранятся текущие элементы из каждой последовательности, на каждом шаге извлекается минимум и в кучу добавляется следующий элемент из той же последовательности.
- **Стабильность сортировки** — свойство сохранять относительный порядок равных элементов. При слиянии стабильность достигается выбором элемента из первого массива при равенстве.

## Дополнительные примеры использования

**Слияние ответов из двух API.** Два микросервиса возвращают списки событий, отсортированные по времени. На агрегаторе достаточно вызвать слияние двух массивов по полю времени — результат будет отсортирован без полной пересортировки.

**Объединение логов с нескольких серверов.** Каждый сервер пишет лог, локально отсортированный по timestamp. При сборе логов в центр достаточно последовательно сливать потоки (или использовать min-heap при k потоках), чтобы получить единый отсортированный поток без загрузки всего в память и сортировки заново.

**Внешняя сортировка.** При сортировке файла, не помещающегося в память, данные разбиваются на чанки, каждый чанк сортируется и записывается во временный файл. Финальный этап — многопутевое слияние (k-way merge) этих отсортированных файлов; базовый шаг — слияние двух отсортированных последовательностей.

**Объединение результатов поиска.** Несколько индексов возвращают отсортированные по релевантности списки идентификаторов. Чтобы получить единый ранжированный список без потери порядка, можно сливать эти списки (с учётом весов при необходимости), используя тот же приём двух указателей или k-way merge.

**Слияние двух отсортированных списков (коллекций).** Если данные представлены в виде `List<Integer>` или `List<Long>`, алгоритм тот же: два индекса, сравнение, сдвиг. Результат можно собирать в новый список или в массив. В Kotlin удобно использовать итераторы по двум спискам и выбирать меньший элемент до исчерпания обоих — это по сути то же слияние без явных индексов.

**Внешняя сортировка: роль слияния.** При сортировке данных, не помещающихся в оперативную память, файл разбивается на блоки, каждый блок сортируется и записывается во временный файл. Финальный этап — многопутевое слияние (k-way merge) этих отсортированных файлов: на каждом шаге из k текущих значений (по одному из каждого файла) выбирается минимум, записывается в выходной файл, и из соответствующего файла читается следующее значение. Базовый шаг — слияние двух отсортированных последовательностей; при k > 2 используется min-heap.

## Когда использовать

Используйте слияние двух массивов, когда уже есть два (или k) отсортированных источника и нужно получить один отсортированный результат за линейное время. Типичные случаи: финальный шаг сортировки слиянием, объединение ответов из нескольких отсортированных источников, внешняя сортировка, слияние логов или событий по времени. Не используйте слияние для объединения неотсортированных данных — тогда либо сначала отсортируйте каждый источник и затем сливайте, либо выполните одну общую сортировку над объединённым набором.

## Заключение

Объединение двух отсортированных массивов — фундаментальная операция, лежащая в основе сортировки слиянием и многих сценариев объединения данных. Алгоритм с двумя указателями даёт линейную сложность `O(n + m)`, прост в реализации и стабилен. Для объединения k массивов эффективнее использовать min-heap с сложностью `O(n * log k)`. Понимание слияния необходимо для изучения `Merge Sort`, внешней сортировки и обработки потоков данных. В этом документе рассмотрены реализации на Java и Kotlin, варианты in-place и без дубликатов, сравнение сложности и практические рекомендации по проверке граничных случаев и использованию `System.arraycopy`.
