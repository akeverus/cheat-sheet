## Описание алгоритма

Задача о максимальном подмассиве — это задача найти ряд смежных элементов с максимальной суммой в любом заданном массиве.

Например, в массиве `[-2, 1, -3, 4, -1, 2, 1, -5, 4]` подмассив `[4, -1, 2, 1]` имеет максимальную сумму 6.

В этом уроке мы рассмотрим два решения для поиска максимального подмассива в массиве. Один из них мы разработаем с `O(n)` временной и пространственной сложностью.

## Реализация на Java

### Подход 1: Грубая сила (Brute Force) (Java)

Грубая сила — это итеративный подход к решению проблемы. В большинстве случаев для решения требуется несколько итераций по структуре данных. Вообще говоря, первое решение, которое приходит на ум, — вычислить сумму всех возможных подмассивов и вернуть тот, у которого сумма максимальна. Для начала мы вычислим сумму всех подмассивов, начинающихся с индекса `0`. И аналогичным образом мы найдём все подмассивы, начинающиеся с каждого индекса от `0` до `n — 1`, где `n` — длина массива. Итак, мы начнём с индекса `0` и добавим каждый элемент к текущей сумме в итерации. Мы также будем отслеживать максимальную сумму, увиденную до сих пор. Давайте теперь посмотрим, как мы можем реализовать это решение на `Java`:

```java
// Грубая сила: перебор всех подмассивов, сумма и максимум (O(n²))
public int maxSubArray(int[] nums) {
    int n = nums.length;
    int maximumSubArraySum = Integer.MIN_VALUE;
    int start = 0;
    int end = 0;

    for (int left = 0; left < n; left++) {
        int runningWindowSum = 0;

        for (int right = left; right < n; right++) {
            runningWindowSum += nums[right];

            if (runningWindowSum > maximumSubArraySum) {
                maximumSubArraySum = runningWindowSum;
                start = left;
                end = right;
            }
        }
    }

    logger.info("Found Maximum Subarray between {} and {}", start, end);
    return maximumSubArraySum;
}
```

Как и ожидалось, мы обновляем `maxSubArraySum`, если текущая сумма больше, чем предыдущая максимальная сумма. Примечательно, что затем мы также обновляем начало и конец, чтобы узнать расположение индексов этого подмассива.

### Сложность подхода грубой силы

Вообще говоря, решение грубой силы многократно перебирает массив, чтобы получить все возможные решения. Это означает, что время, затрачиваемое этим решением, растёт квадратично с количеством элементов в массиве. Это может не быть проблемой для массивов небольшого размера. Но по мере роста размера массива это решение становится неэффективным. Изучив код, мы также можем увидеть, что есть два вложенных цикла `for`. Следовательно, мы можем сделать вывод, что временная сложность этого алгоритма составляет `O(n²)`.

## Подход 2: Алгоритм Кадане (Kadane's Algorithm)

В последующих разделах мы решим эту задачу со сложностью `O(n)` с помощью динамического программирования. Динамическое программирование решает проблему, разделяя её на более мелкие подзадачи. Это очень похоже на метод решения алгоритма «разделяй и властвуй». Однако основное отличие состоит в том, что динамическое программирование решает подзадачу только один раз. Затем он сохраняет результат этой подзадачи и позже повторно использует этот результат для решения других связанных подзадач. Этот процесс известен как мемоизация. Алгоритм Кадане — популярное решение задачи о максимальном подмассиве, и это решение основано на динамическом программировании.

### Принцип работы

Наиболее важной задачей при решении задачи динамического программирования является поиск оптимальных подзадач. Давайте поймём эту проблему по‑другому. Мы предполагаем, что максимальный подмассив заканчивается в последнем местоположении индекса. Следовательно, максимальная сумма подмассива будет: `maximumSubArraySum = max_so_far + arr[n — 1]`. `max_so_far` — это максимальная сумма подмассива, который заканчивается на индексе `n — 2`. Теперь мы можем применить это предположение к любому индексу в массиве. Например, максимальная сумма подмассива, которая заканчивается на `n — 2`, может быть рассчитана как: `maximumSubArraySum[n — 2] = max_so_far[n — 3] + arr[n — 2]`. Таким образом, мы можем сделать вывод, что: `maximumSubArraySum[i] = maximumSubArraySum[i — 1] + arr[i]`. Теперь, поскольку каждый элемент в массиве является специальным подмассивом размера один, нам также нужно проверить, больше ли элемент, чем сама максимальная сумма: `maximumSubArraySum[i] = Max(arr[i], maximumSubArraySum[i — 1] + arr[i])`. Глядя на эти уравнения, мы видим, что нам нужно найти максимальную сумму подмассива по каждому индексу массива. Таким образом, мы разбили нашу задачу на `n` подзадач. Мы можем найти максимальную сумму по каждому индексу, перебирая массив только один раз.

#### Реализация алгоритма Кадане

Выделенный элемент показывает текущий элемент в итерации. Для каждого индекса мы будем применять уравнение, полученное ранее, для вычисления значения `max_ending_here`. Это помогает нам определить, должны ли мы включать текущий элемент в подмассив или начинать новый подмассив, начиная с этого индекса. Другая переменная, `max_so_far`, используется для хранения максимальной суммы подмассива, найденной во время итерации. Как только мы перейдём к последнему индексу, `max_so_far` сохранит сумму максимального подмассива. Опять же, давайте посмотрим, как теперь мы можем реализовать алгоритм Кадане в `Java`, следуя описанному выше подходу:

```java
// Алгоритм Кадане: один проход по массиву с накоплением текущей и глобальной максимальной суммы (O(n))
public int maxSubArraySum(int[] arr) {
    int size = arr.length;
    int start = 0;
    int end = 0;
    int maxSoFar = arr[0], maxEndingHere = arr[0];

    for (int i = 1; i < size; i++) {
        if (arr[i] > maxEndingHere + arr[i]) {
            start = i;
            maxEndingHere = arr[i];
        } else {
            maxEndingHere = maxEndingHere + arr[i];
        }

        if (maxSoFar < maxEndingHere) {
            maxSoFar = maxEndingHere;
            end = i;
        }
    }

    logger.info("Found Maximum Subarray between {} and {}", Math.min(start, end), end);
    return maxSoFar;
}
```

Здесь мы обновили начало и конец, чтобы найти максимальные индексы подмассива.

Обратите внимание, что мы берём `Math.min(start, end)` вместо `start` в качестве начального индекса максимального подмассива. Это связано с тем, что если массив содержит только отрицательные числа, максимальный подмассив будет самым большим элементом. В этом случае `if(arr[i] > maxEndingHere + arr[i])` всегда будет `true`. То есть значение `start` больше значения `end`.

### Упрощённая версия (только сумма)

Если нам не нужны индексы начала и конца:

```java
// Упрощённый вариант алгоритма Кадане: считаем только максимальную сумму без индексов подмассива
public int maxSubArraySumSimple(int[] arr) {
    int maxSoFar = arr[0];
    int maxEndingHere = arr[0];

    for (int i = 1; i < arr.length; i++) {
        maxEndingHere = Math.max(arr[i], maxEndingHere + arr[i]);
        maxSoFar = Math.max(maxSoFar, maxEndingHere);
    }

    return maxSoFar;
}
```

### Пример использования

```java
int[] arr = {-2, 1, -3, 4, -1, 2, 1, -5, 4};
int maxSum = maxSubArraySum(arr);
// maxSum = 6 (подмассив [4, -1, 2, 1])
```

## Реализация на Kotlin

В `Kotlin` алгоритм `Maximum Subarray` может быть реализован следующим образом:

### Подход 1: Грубая сила (Brute Force) (Kotlin)

```kotlin
// Грубая сила: перебираем все подмассивы и ищем максимальную сумму (O(n²))
fun maxSubArray(nums: IntArray): Int {
    val n = nums.size
    var maximumSubArraySum = Int.MIN_VALUE
    var start = 0
    var end = 0

    for (left in 0 until n) {
        var runningWindowSum = 0

        for (right in left until n) {
            runningWindowSum += nums[right]

            if (runningWindowSum > maximumSubArraySum) {
                maximumSubArraySum = runningWindowSum
                start = left
                end = right
            }
        }
    }

    println("Found Maximum Subarray between $start and $end")
    return maximumSubArraySum
}
```

### Подход 2: Алгоритм Кадане (Kadane's Algorithm)

```kotlin
// Алгоритм Кадане: однократный проход по массиву с отслеживанием текущей и глобальной максимальной суммы (O(n))
fun maxSubArraySum(arr: IntArray): Int {
    val size = arr.size
    var start = 0
    var end = 0
    var maxSoFar = arr[0]
    var maxEndingHere = arr[0]

    for (i in 1 until size) {
        if (arr[i] > maxEndingHere + arr[i]) {
            start = i
            maxEndingHere = arr[i]
        } else {
            maxEndingHere += arr[i]
        }

        if (maxSoFar < maxEndingHere) {
            maxSoFar = maxEndingHere
            end = i
        }
    }

    println("Found Maximum Subarray between ${minOf(start, end)} and $end")
    return maxSoFar
}
```

### Упрощённая версия (только сумма)

```kotlin
// Упрощённый вариант Кадане: возвращаем только максимальную сумму без индексов
fun maxSubArraySumSimple(arr: IntArray): Int {
    var maxSoFar = arr[0]
    var maxEndingHere = arr[0]

    for (i in 1 until arr.size) {
        maxEndingHere = maxOf(arr[i], maxEndingHere + arr[i])
        maxSoFar = maxOf(maxSoFar, maxEndingHere)
    }

    return maxSoFar
}
```

Использование:

```kotlin
fun main() {
    val arr = intArrayOf(-2, 1, -3, 4, -1, 2, 1, -5, 4)
    val maxSum = maxSubArraySumSimple(arr)
    println(maxSum) // 6 (подмассив [4, -1, 2, 1])
}
```

## Сравнение подходов

| Характеристика | Грубая сила | Алгоритм Кадане |
|----------------|-------------|-----------------|
| Временная сложность | `O(n²)` | `O(n)` |
| Пространственная сложность | `O(1)` | `O(1)` |
| Простота | Проще понять | Требует понимания `DP` |
| Применение | Малые массивы | Любые массивы |

## Сложность

### Подход 1: Грубая сила

Временная сложность подхода грубой силы составляет `O(n²)` из‑за двух вложенных циклов, которые перебирают все возможные подмассивы. Пространственная сложность составляет `O(1)`, так как алгоритм использует только константную память для хранения переменных, независимо от размера массива.

### Подход 2: Алгоритм Кадане

Временная сложность алгоритма Кадане составляет `O(n)`, так как требуется только один проход по массиву для вычисления максимальной суммы подмассива. Пространственная сложность также составляет `O(1)`, так как алгоритм использует только константную память для хранения переменных `maxSoFar` и `maxEndingHere`. Поскольку нам нужно выполнить итерацию массива только один раз, временная сложность этого алгоритма составляет `O(n)`. Итак, как мы видим, время, затрачиваемое этим решением, линейно растёт с количеством элементов в массиве. Следовательно, он более эффективен, чем метод грубой силы, который мы обсуждали в предыдущем разделе.

## Особенности

Алгоритм Кадане оптимален по времени, так как имеет линейную временную сложность `O(n)`, что является лучшим возможным результатом для этой задачи. Оба подхода используют `O(1)` дополнительной памяти, что делает их эффективными по использованию памяти. Алгоритм Кадане также гибок и позволяет найти как сумму максимального подмассива, так и индексы начала и конца этого подмассива, что может быть полезно для различных приложений.

## Применение

Задача о максимальном подмассиве используется в различных областях. В анализе финансовых данных алгоритм применяется для поиска периода с максимальной прибылью, что помогает инвесторам принимать обоснованные решения. В обработке сигналов алгоритм используется для поиска участков сигнала с максимальной амплитудой или энергией. В биоинформатике алгоритм применяется для анализа последовательностей ДНК и поиска участков с определёнными характеристиками. В компьютерном зрении алгоритм используется для поиска областей изображения с максимальной интенсивностью или другими характеристиками. В оптимизации портфеля алгоритм помогает найти оптимальное распределение активов для максимизации прибыли.

## Варианты задачи

Задача о максимальном подмассиве имеет несколько вариантов. Вариант 1 — найти максимальный подмассив длиной не более `k` элементов. Этот вариант требует модификации алгоритма Кадане для учёта ограничения на размер подмассива. Вариант 2 — расширение задачи на двумерные массивы (матрицы), где требуется найти подматрицу с максимальной суммой элементов. Этот вариант более сложен и требует применения алгоритма Кадане к каждому столбцу или строке матрицы. Вариант 3 — максимальный подмассив с отрицательными числами. Алгоритм Кадане работает и с отрицательными числами, находя максимальный элемент, если все числа отрицательны, или максимальную сумму подмассива, если есть положительные числа.

## Лучшие практики

Выбор подхода для продакшена должен основываться на требованиях к производительности. Для продакшена предпочтителен алгоритм Кадане с временной сложностью `O(n)`, так как он обеспечивает оптимальную производительность для больших массивов. Грубая сила с временной сложностью `O(n²)` допустима только для малых значений `n` или для отладки, когда нужно проверить корректность работы алгоритма.

Граничные случаи требуют особого внимания. Для пустого массива необходимо договориться о возвращаемом значении — это может быть `0`, `Integer.MIN_VALUE` или исключение, в зависимости от требований приложения. Для массива из одного элемента следует вернуть этот элемент. Если все числа отрицательны, максимум есть — это может быть наибольший элемент или пустой подмассив с суммой `0`, в зависимости от постановки задачи.

Индексы против суммы — это важное решение при реализации алгоритма. Если нужны индексы начала и конца подмассива, необходимо вести их в алгоритме Кадане при обновлении `max_so_far`. Упрощённая версия возвращает только сумму, что может быть достаточно для многих приложений, где не требуется знать точное расположение подмассива.

Память — оба подхода используют `O(1)` дополнительной памяти, что делает их эффективными по использованию памяти. Не следует создавать лишних массивов для хранения промежуточных сумм, так как это увеличит пространственную сложность без необходимости.

Тестирование должно включать проверку различных сценариев: один элемент, все отрицательные числа, все положительные числа, чередование положительных и отрицательных чисел, нули в массиве. Для версии с индексами необходимо проверить корректность `start` и `end`, чтобы убедиться, что они правильно указывают на начало и конец максимального подмассива.

| Симптом | Возможная причина | Решение |
|--------|-------------------|---------|
| Результат `0` вместо отрицательного числа | Начальное значение `maxSum = 0` вместо `Integer.MIN_VALUE` или первого элемента | Инициализировать `maxSum = arr[0]` и `currentSum = arr[0]`; начинать цикл с индекса 1 |
| Работает неверно на пустом массиве | Нет проверки на пустой/null массив | Добавить `if (arr == null ∣∣ arr.length == 0)` с выбросом исключения или возвратом 0 |
| Нужны индексы подмассива, а не только сумма | Стандартный Кадане возвращает только сумму | Добавить переменные `start`, `end`, `tempStart`; обновлять их при обновлении `maxSum` |

## Частые вопросы

**Почему алгоритм Кадане работает за `O(n)`?** Ключевая идея: если текущая сумма становится отрицательной, она не может улучшить будущий подмассив — начинаем заново. За один проход по массиву мы проверяем все возможные окончания подмассивов, поэтому решение линейное.

**Как обработать случай, когда все элементы отрицательные?** Если инициализировать `maxSum = arr[0]` и обновлять через `Math.max(arr[i], currentSum + arr[i])`, алгоритм корректно вернёт наибольший (наименее отрицательный) элемент.

**Можно ли найти минимальный подмассив?** Да, инвертируйте знаки всех элементов и запустите Кадане — результат (с обратным знаком) будет минимальной суммой. Или модифицируйте алгоритм: вместо `max` используйте `min`, сбрасывайте при положительной сумме.


## Заключение

В этом кратком руководстве мы описали два способа решения проблемы максимального подмассива. Во‑первых, мы исследовали подход грубой силы и увидели, что это итеративное решение приводит к квадратичному времени `O(n²)`. Позже мы обсудили алгоритм Кадане и использовали динамическое программирование для решения задачи за линейное время `O(n)`. Алгоритм Кадане является оптимальным решением для этой задачи и должен использоваться в продакшене для обеспечения наилучшей производительности.
