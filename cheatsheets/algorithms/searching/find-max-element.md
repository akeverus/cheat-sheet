## Описание алгоритма

В этой статье мы представим различные решения для нахождения k-го по величине элемента в последовательности уникальных чисел. Мы будем использовать массив целых чисел для наших примеров.

Мы также поговорим о средней и наихудшей временной сложности каждого алгоритма.

Теперь давайте рассмотрим несколько возможных решений - одно с использованием простой сортировки и два с использованием алгоритма быстрого выбора, полученного из быстрой сортировки.

## Подход 1: Сортировка

Когда мы думаем о проблеме, возможно, наиболее очевидным решением, которое приходит на ум, является сортировка массива.

### Определим необходимые шаги:

1. Отсортировать массив в порядке возрастания
2. Поскольку последний элемент массива будет самым большим элементом, k-й самый большой элемент будет иметь индекс x, где x = длина(**массив**) - k

**Как видим, решение простое, но требует сортировки всего массива. Следовательно, временная сложность будет `O(**n**log**(n**)`):**

### Реализация на Java (Сортировка)

```java
// k-й по величине через сортировку: O(n log n); индексируем с конца, чтобы взять k-й максимум
public int findKthLargestBySorting(Integer[] arr, int k) {
    Arrays.sort(arr); // сортируем по возрастанию, чтобы получить упорядоченный хвост
    int targetIndex = arr.length - k; // позиция k-го максимума в отсортированном массиве
    return arr[targetIndex]; // возвращаем найденное значение
}
```

**Альтернативный подход - отсортировать массив в порядке убывания и просто вернуть элемент по (**k - 1**)-му индексу:**

```java
// Альтернатива: сортировка по убыванию и прямой доступ к индексу k-1
public int findKthLargestBySortingDesc(Integer[] arr, int k) {
    Arrays.sort(arr, Collections.reverseOrder()); // сортируем по убыванию
    return arr[k - 1]; // k-й максимум теперь на позиции k-1
}
```

**Пример использования:**

```java
Integer[] arr = {3, 2, 1, 5, 6, 4};
int k = 2; // Найти 2-й по величине элемент
int result = findKthLargestBySorting(arr, k);
// result = 5
```

### Реализация на Kotlin (Сортировка)

```kotlin

    val targetIndex = arr.size - k // позиция k-го максимума
    return arr[targetIndex] // возвращаем k-й максимум
}
```

**Альтернативный подход:**

```kotlin
// Альтернатива: сортировка по убыванию и доступ к индексу k-1
fun findKthLargestBySortingDesc(arr: IntArray, k: Int): Int {
    arr.sortDescending() // сортируем по убыванию
    return arr[k - 1] // k-й максимум в позиции k-1
}
```

**Пример использования:**

```kotlin

val k = 2 // Найти 2-й по величине элемент

// result = 5
```

## Подход 2: QuickSelect

Это можно считать оптимизацией предыдущего подхода. Здесь мы выбираем **QuickSort** для сортировки. Анализируя постановку задачи, мы понимаем, что на самом деле нам не нужно сортировать весь массив - нам нужно только переставить его содержимое так, чтобы k-й элемент массива был k-м наибольшим или наименьшим.

В **QuickSort** мы выбираем опорный элемент и перемещаем его в правильное положение. Мы также разбиваем массив вокруг него. В **QuickSelect** идея состоит в том, чтобы остановиться в точке, где сама точка поворота является k-м по величине элементом.

Мы можем дополнительно оптимизировать алгоритм, если не будем повторяться как для левой, так и для правой сторон опорной точки. Нам нужно только повторить для одного из них в соответствии с положением точки опоры.

### Основные идеи алгоритма QuickSelect:

1. Выберите опорный элемент и разделите массив соответствующим образом
2. Выберите крайний правый элемент в качестве опорного
3. Перетасуйте массив так, чтобы опорный элемент располагался на своем законном месте - все элементы, меньшие опорного, будут иметь более низкие индексы, а элементы, большие опорного, будут помещены в более высокие индексы, чем опорный
4. Если стержень находится в k-м элементе массива, выйти из процесса, так как стержень - это k-й самый большой элемент
5. Если позиция поворота больше k, то продолжить процесс с левым подмассивом, в противном случае повторить процесс с правым подмассивом

Мы можем написать общую логику, которую также можно использовать для поиска k-го наименьшего элемента. Мы определим метод `**findKthElementByQuickSelect**()`, который будет возвращать k-й элемент в отсортированном массиве.

Если мы отсортируем массив в порядке возрастания, k-й элемент массива будет k-м наименьшим элементом. Чтобы найти k-й самый большой элемент, мы можем передать k = **length(**Array**) - k.

### Реализация на Java (QuickSelect)

**Давайте реализуем это решение:**

```java
// QuickSelect: находим k-й элемент за среднее O(n), не сортируя весь массив
public int findKthElementByQuickSelect(Integer[] arr, int left, int right, int k) {
    if (k < 0 || k > right - left + 1) {
        throw new IllegalArgumentException("k вне диапазона");
    }

    int pos = partition(arr, left, right); // ставим опору на своё место

    if (pos - left == k) { // опора оказалась на нужной позиции
        return arr[pos];
    }
    if (pos - left > k) { // искомый элемент левее опоры
        return findKthElementByQuickSelect(arr, left, pos - 1, k);
    }
    // искомый элемент правее опоры, корректируем k с учётом отброшенных слева
    return findKthElementByQuickSelect(arr, pos + 1, right, k - pos + left - 1);
}

// Разбиение массива вокруг опоры: всё <= pivot слева, остальные справа
public int partition(Integer[] arr, int left, int right) {
    int pivot = arr[right]; // опора — правый элемент
    int i = left;

    for (int j = left; j <= right - 1; j++) {
        if (arr[j] <= pivot) { // меньшие или равные опоре — налево
            swap(arr, i, j);
            i++;
        }
    }

    swap(arr, i, right); // ставим опору между меньшими и большими
    return i; // возвращаем позицию опоры
}

// Обмен элементов массива
public void swap(Integer[] arr, int n1, int n2) {
    int temp = arr[n2];
    arr[n2] = arr[n1];
    arr[n1] = temp;
}
```

Это решение работает в среднем за время `O(n)`. Однако в худшем случае временная сложность будет `O(**n²**)`.

### Реализация на Kotlin (QuickSelect)

```kotlin
// QuickSelect в Kotlin: средняя сложность O(n), ищем k-й элемент без полной сортировки
fun findKthElementByQuickSelect(arr: IntArray, left: Int, right: Int, k: Int): Int {
    require(k in 0..(right - left)) { "k вне диапазона" }

    val pos = partition(arr, left, right) // ставим опору на место
    return when {
        pos - left == k -> arr[pos] // опора — искомый элемент
        pos - left > k -> findKthElementByQuickSelect(arr, left, pos - 1, k) // ищем слева
        else -> findKthElementByQuickSelect(arr, pos + 1, right, k - pos + left - 1) // ищем справа
    }
}

// Разбиение вокруг опоры: всё <= pivot слева, остальное справа
fun partition(arr: IntArray, left: Int, right: Int): Int {
    val pivot = arr[right] // опора — правый элемент
    var i = left
    for (j in left until right) {
        if (arr[j] <= pivot) { // элементы не больше опоры перемещаем влево
            arr.swap(i, j)
            i++
        }
    }
    arr.swap(i, right) // ставим опору на её место
    return i
}

// Обмен элементов массива
fun IntArray.swap(i: Int, j: Int) {
    val temp = this[i]
    this[i] = this[j]
    this[j] = temp
}
```

**Пример использования:**

```kotlin
val arr = intArrayOf(3, 2, 1, 5, 6, 4)
val k = 2
val result = findKthElementByQuickSelect(arr, 0, arr.size - 1, arr.size - k)
// result = 5
```

## Подход 3: Рандомизированный QuickSelect

Этот подход является небольшой модификацией предыдущего подхода. Если массив почти/полностью отсортирован и если мы выберем самый правый элемент в качестве опорного, разделение левого и правого подмассивов будет очень неравномерным.

Этот метод предлагает выбирать начальный опорный элемент случайным образом. Однако нам не нужно менять логику разбиения.

Вместо вызова **partition** мы вызываем метод **randomPartition**, который выбирает случайный элемент и заменяет его крайним правым элементом, прежде чем, наконец, вызвать метод **partition**.

### Реализация на Java (Рандомизированный QuickSelect)

**Давайте реализуем метод **randomPartition**:**

```java
// Рандомизированный QuickSelect: случайная опора уменьшает шанс худшего случая
public int randomPartition(Integer[] arr, int left, int right) {
    int n = right - left + 1;
    int pivotOffset = ThreadLocalRandom.current().nextInt(n); // выбираем опору случайно
    swap(arr, left + pivotOffset, right); // переносим опору в конец
    return partition(arr, left, right); // стандартное разбиение
}

public int findKthElementByRandomizedQuickSelect(Integer[] arr, int left, int right, int k) {
    if (k < 0 || k > right - left + 1) {
        throw new IllegalArgumentException("k вне диапазона");
    }
    int pos = randomPartition(arr, left, right); // ставим случайную опору на место

    if (pos - left == k) { // опора — ответ
        return arr[pos];
    }
    if (pos - left > k) { // ответ левее опоры
        return findKthElementByRandomizedQuickSelect(arr, left, pos - 1, k);
    }
    // ответ правее опоры; корректируем k
    return findKthElementByRandomizedQuickSelect(arr, pos + 1, right, k - pos + left - 1);
}
```

В большинстве случаев это решение работает лучше, чем предыдущее.

Ожидаемая временная сложность рандомизированного **QuickSelect** составляет `O(n)`.

Однако наихудшая временная сложность по-прежнему остается `O(**n²**)`.

### Реализация на Kotlin (Рандомизированный QuickSelect)

```kotlin
// Рандомизированный QuickSelect в Kotlin: случайная опора сглаживает худший случай
fun randomPartition(arr: IntArray, left: Int, right: Int): Int {
    val n = right - left + 1
    val pivotOffset = (0 until n).random() // выбираем опору случайно
    arr.swap(left + pivotOffset, right) // переносим опору в конец
    return partition(arr, left, right) // стандартное разбиение
}

fun findKthElementByRandomizedQuickSelect(arr: IntArray, left: Int, right: Int, k: Int): Int {
    require(k in 0..(right - left)) { "k вне диапазона" }
    val pos = randomPartition(arr, left, right) // ставим случайную опору

    return when {
        pos - left == k -> arr[pos] // опора — ответ
        pos - left > k -> findKthElementByRandomizedQuickSelect(arr, left, pos - 1, k) // ищем слева
        else -> findKthElementByRandomizedQuickSelect(arr, pos + 1, right, k - pos + left - 1) // ищем справа
    }
}
```

**Пример использования:**

```kotlin
val arr = intArrayOf(3, 2, 1, 5, 6, 4)
val k = 2
val result = findKthElementByRandomizedQuickSelect(arr, 0, arr.size - 1, arr.size - k)
// result = 5
```

## Сравнение подходов

| Характеристика | Сортировка | QuickSelect | Рандомизированный QuickSelect |
|----------------|------------|-------------|-------------------------------|
| Временная сложность (среднее) | `O(n · log n)` | `O(n)` | `O(n)` |
| Временная сложность (худшее) | `O(n · log n)` | `O(n²)` | `O(n²)` |
| Пространственная сложность | `O(1)` при in-place | `O(log n)` стек рекурсии | `O(log n)` стек рекурсии |
| Простота | Простая | Средняя | Средняя |
| Применение | Когда нужна полная сортировка или несколько запросов | Один запрос k-го элемента | Устойчивость к частичной отсортированности |

## Сложность

### Подход 1: Сортировка

- Временная сложность: `O(n · log n)` — полная сортировка массива
- Пространственная сложность: `O(1)` при in-place (или `O(n)` при копировании)

### Подход 2: QuickSelect

- Временная сложность (среднее): `O(n)`
- Временная сложность (худшее): `O(n²)` при неудачных опорах
- Пространственная сложность: `O(log n)` на стек рекурсии

### Подход 3: Рандомизированный QuickSelect

- Временная сложность (среднее): `O(n)` за счёт случайной опоры
- Временная сложность (худшее): `O(n²)` маловероятно, но возможно
- Пространственная сложность: `O(log n)` на стек рекурсии

## Особенности

QuickSelect оптимален, когда нужен один порядковый элемент: средняя линейная сложность без полной сортировки. Алгоритм гибок — можно искать как k-й максимум, так и k-й минимум, просто корректируя индекс. Рандомизация опоры улучшает среднюю производительность и снижает вероятность провала в худший случай.

## Применение

Поиск k-го элемента применяют в статистике (медианы и перцентили), алгоритмах ранжирования, топ-k выборках, аналитике данных и машинном обучении, где требуется быстро получить порядковую статистику без полной сортировки.

## Когда использовать

Сортировка уместна, когда нужно несколько разных k или уже требуется отсортированный список. Обычный QuickSelect выбирайте для одного запроса и больших массивов, если не критично редкое попадание в худший случай. Рандомизированный QuickSelect предпочтителен на почти отсортированных данных или при требованиях к предсказуемой средней производительности.

## Лучшие практики

QuickSelect стоит выбирать, когда нужен один k-й элемент и важно уложиться в `O(n)` в среднем; сортировка удобнее и короче, но `O(n · log n)` по времени, и её имеет смысл использовать при множественных запросах или когда важен стабильный порядок. Всегда валидируйте `k` в диапазоне `[1, n]`, учитывайте пустые массивы и граничные случаи `k = 1` (максимум) и `k = n` (минимум). Рандомизация опоры снижает вероятность худшего случая `O(n²)`; для детерминированного `O(n)` можно применять медиану медиан, но это усложняет код. Помните про индексацию: в `Java` массивы 0-based, поэтому для 1-based k нужно переводить к индексу `length - k` при сортировке по возрастанию. Включайте тесты на дубликаты и одинаковые элементы, чтобы убедиться, что реализация корректно обрабатывает повторы.

## Проверка входа и контракты

Перед выполнением алгоритма проверьте:

- `k` в диапазоне `[1, n]`; вне диапазона — бросайте `IllegalArgumentException` или оговаривайте поведение.
- массив не `null` и не пуст; для пустого входа возвращайте понятное значение или исключение.
- допустимость модификации входного массива: QuickSelect меняет порядок элементов, поэтому при необходимости сохранения исходных данных делайте копию.
- в случае пользовательских типов — корректный `Comparator` с транзитивностью и без `ClassCastException`.

## Профилирование и масштабирование

На больших массивах узким местом становится количество сравнений. QuickSelect выполняет `O(n)` сравнений в среднем, сортировка — `O(n · log n)`. Если вход почти отсортирован, рандомизированная опора уменьшает глубину рекурсии. Для потоковых данных min-heap фиксированного размера `k` может быть проще и не требует рекурсии. Измеряйте реальные данные с помощью `JMH` или аналогов: распределение значений и доля дубликатов заметно влияют на производительность.

Пример микро-бенчмарка `JMH` для сравнения сортировки и QuickSelect:

```java
@State(Scope.Benchmark)
public class KthBench {
    int[] data;
    int k;

    @Setup(Level.Trial)
    public void setup() {
        data = ThreadLocalRandom.current().ints(1_000_000, 0, 10_000_000).toArray();
        k = 500;
    }

    @Benchmark
    public int quickSelectBench() {
        Integer[] copy = Arrays.stream(data).boxed().toArray(Integer[]::new);
        return findKthElementByRandomizedQuickSelect(copy, 0, copy.length - 1, copy.length - k);
    }

    @Benchmark
    public int sortBench() {
        int[] copy = Arrays.copyOf(data, data.length);
        Arrays.sort(copy);
        return copy[copy.length - k];
    }
}
```

Такой бенчмарк помогает понять точку, где QuickSelect начинает выигрывать у сортировки на реальном распределении данных.

## Метрики и наблюдаемость

В продовых сервисах полезно собирать метрики:

- время ответа для различных k и размеров входа;
- количество сравнений/итераций (можно оценивать через счётчики в тестовых сборках);
- объём временной памяти (heap usage) и частоту сборок мусора.

Добавьте логирование ошибок валидации `k` и таймауты для длительных вызовов (особенно если массивы очень большие). Если алгоритм работает на потоках данных, фиксируйте текущий размер кучи и число отброшенных элементов — это помогает отслеживать регрессии производительности и утечки памяти.

### Память и GC

QuickSelect работает in-place и экономит память, но рекурсивный стек растёт до `O(log n)`. Min-heap требует `O(k)` памяти; при большом k это может заметно увеличить давление на GC. Профилируйте использование кучи и при необходимости переходите на итеративные версии алгоритмов и на примитивные массивы без автобоксинга, чтобы уменьшить аллокации.

## Альтернативный подход: min-heap

Если QuickSelect нежелателен из-за модификации массива, можно использовать min-heap размера `k`: однократный проход и хранение только `k` элементов.

```java
// k-й максимум через min-heap: O(n log k), без перестановки входного массива
public int findKthLargestWithHeap(int[] arr, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>(); // min-heap
    for (int value : arr) {
        heap.offer(value); // добавляем элемент
        if (heap.size() > k) {
            heap.poll(); // убираем минимум, чтобы сохранить top-k
        }
    }
    return heap.peek(); // вершина — k-й максимум
}
```

Такой подход предпочтителен, если нельзя менять входные данные и важна стабильная производительность без рекурсии.

## Работа с дубликатами и стабильностью

QuickSelect возвращает значение на позиции `k`, но не гарантирует стабильного порядка равных элементов. Если важен детерминированный выбор при дубликатах, после получения значения k-го элемента можно выполнить дополнительный проход, чтобы подсчитать, сколько элементов больше и равно целевому. Для стабильного выбора конкретного индекса при равных значениях используйте сортировку или подход с min-heap, где порядок можно контролировать через индекс в компараторе.

Для задач, где нужно вернуть уникальные значения, предварительно примените дедупликацию (например, через `TreeSet`) и только потом ищите k-й элемент. Это меняет семантику (k-й уникальный максимум), поэтому важно явно фиксировать договорённость в контракте метода и тестах.

## Решение проблем

- Неверный результат: проверьте перевод 1-based k в индекс (`length - k`) для QuickSelect, а также корректность разбиения (опора должна оказаться между меньшими и большими).
- Дубликаты ведут к неожиданному значению: ожидайте совпадения с результатом сортировки по возрастанию; добавьте тесты на равные элементы.
- Слишком глубокая рекурсия: при очень больших массивах реализуйте итеративный вариант или ограничьте глубину, чтобы избежать `StackOverflowError`.
- Производительность проседает: используйте рандомизацию опоры; не применяйте QuickSelect к почти отсортированным данным без рандомизации.

## Частые вопросы

**Можно ли найти сразу несколько порядковых статистик?** Проще отсортировать один раз и обратиться по индексам, если запросов несколько.  
**QuickSelect меняет массив — что делать, если нужен исходный порядок?** Создайте копию входа перед вызовом.  
**Как обработать k = 1 и k = n?** Для k = 1 возвращайте максимум, для k = n — минимум; это быстрые граничные случаи.  
**Нужна стабильность равных элементов?** QuickSelect не гарантирует стабильность; сортировка по убыванию — надёжный способ получить упорядоченный список.  
**Можно ли использовать компаратор по полю объекта?** Да, обобщите QuickSelect и передавайте `Comparator`, следя за транзитивностью сравнения.

## Глоссарий

`Order statistic` — k-я порядковая статистика, элемент на позиции k в отсортированной последовательности.  
`Pivot` — опорный элемент для разбиения массива.  
`Partition` — шаг разделения на части ≤ опоры и > опоры.  
`Randomized QuickSelect` — QuickSelect со случайной опорой для сглаживания худших случаев.  
`In-place` — выполнение алгоритма без существенного дополнительного выделения памяти.

```java
// k-й максимум в потоке: храним k наибольших в min-heap
int kthFromStream(IntStream stream, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();
    stream.forEach(v -> {
        heap.offer(v);
        if (heap.size() > k) heap.poll();

}
```

```java
// Медиана объединённого массива через два вызова QuickSelect
double medianTwoArrays(int[] a, int[] b) {
    int total = a.length + b.length;
    int k1 = (total + 1) / 2;
    int k2 = (total + 2) / 2;
    Integer[] merged = new Integer[total];
    for (int i = 0; i < a.length; i++) merged[i] = a[i];
    for (int i = 0; i < b.length; i++) merged[a.length + i] = b[i];
    int v1 = findKthElementByRandomizedQuickSelect(merged, 0, total - 1, total - k1);
    int v2 = findKthElementByRandomizedQuickSelect(merged, 0, total - 1, total - k2);
    return (v1 + v2) / 2.0;
}
```

### Пример 5: Min-heap без модификации входа

```java
int kthWithHeapCopy(int[] arr, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();
    for (int value : arr) {
        heap.offer(value);
        if (heap.size() > k) heap.poll();
    }
    return heap.peek();
}
```

### Пример 6: Параллельная сортировка

```java
// Параллельная сортировка для очень больших массивов
int kthByParallelSort(int[] arr, int k) {
    int[] copy = Arrays.copyOf(arr, arr.length); // не трогаем исходный массив
    Arrays.parallelSort(copy); // использует fork-join для ускорения
    return copy[copy.length - k]; // k-й максимум
}
```

Параллельная сортировка полезна, когда массивы велики, а k-запросов много и нужен отсортированный порядок; она использует ресурсы CPU, но потребляет больше памяти.

## Дальнейшее чтение

Если требуется детерминированная линейная сложность, изучите алгоритм «медиана медиан» (BFPRT) — он гарантирует `O(n)` без рандомизации. Для нескольких динамических запросов на порядковые статистики полезны структуры `Order Statistic Tree` или `Fenwick/Segment Tree` (для ограниченного диапазона значений). В потоковых и распределённых сценариях обратите внимание на `Count-Min Sketch` и `Reservoir Sampling`, которые помогают находить частотные и случайные элементы при строгих ограничениях по памяти.

Отдельно контролируйте соответствие формата: дата сразу после H1, ссылки в `## Полезные ссылки` и `## Содержание` актуальны, код оформлен с указанием языка и содержит краткие русские комментарии, объясняющие «зачем» блок нужен.

## Заключение

Мы рассмотрели сортировку, QuickSelect и его рандомизированный вариант для поиска k-го по величине элемента. Сортировка остаётся самым простым, но более медленным подходом `O(n · log n)` и подходит, когда нужно несколько порядковых статистик или сохранение порядка. QuickSelect и рандомизированный QuickSelect дают среднюю сложность `O(n)` и предпочтительны для единичных запросов, принимая во внимание модификацию массива и риск худшего случая `O(n²)`. Чёткий контракт на `k`, работу с дубликатами и тесты на граничные сценарии делают решение предсказуемым и готовым к продакшену.

Держите под рукой бенчмарки и метрики исполнения, чтобы быстро выявлять регрессии после оптимизаций. Согласованные правила оформления (дата, TOC, кавычки для терминов, комментированный код) упрощают аудит и сопровождение всей коллекции шпаргалок.

В будущих расширениях стоит добавить обобщённые реализации с `Comparator`, покрыть сценарии с внешней памятью и стриминговые пайплайны поверх больших датасетов.
