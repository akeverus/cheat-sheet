## Описание алгоритма

Задача о рюкзаке — это задача комбинаторной оптимизации, имеющая множество приложений. В этом уроке мы решим эту проблему на **Java**.

Набор предметов с весами и стоимостями; ограничение по весу рюкзака. Нужно выбрать подмножество с максимальной суммой стоимостей, не превышающее лимит веса.

Пример: предметы (5 кг, $10), (6 кг, $30), (3 кг, $15), лимит 10 кг — оптимально взять первый и второй: $40.

## Формулировка задачи

Задача о рюкзаке имеет несколько вариантов. В этом уроке мы сосредоточимся на задаче о рюкзаке 0-1. В задаче о рюкзаке 0-1 каждый предмет нужно либо выбрать, либо оставить. Мы не можем взять часть суммы товара. Кроме того, мы не можем брать предмет несколько раз.

Формально: максимизировать Σ(vi×xi) при Σ(wi×xi) ≤ W, xi ∈ {0,1}. Здесь vi — стоимость, wi — вес i-го предмета, xi — взят (1) или нет (0), W — лимит веса. Задача NP-трудная; ДП даёт псевдополиномиальное время O(n×W).

## Реализация на Java

Рекуррентное соотношение: M(n,w) = max(M(n-1,w), M(n-1, w−wₙ)+vₙ) — либо не берём n-й предмет, либо берём (если wₙ ≤ w). База: n=0 0.

```java
// Рекурсивное решение 0-1 рюкзака: M(n,W) = max(M(n-1,W), M(n-1,W-w_n)+v_n) (O(2^n))
public class Knapsack {
    public static int knapsackRec(int[] w, int[] v, int n, int W) {
        if (n <= 0) {
            return 0;
        } else if (w[n - 1] > W) {
            return knapsackRec(w, v, n - 1, W);
        } else {
            return Math.max(
                knapsackRec(w, v, n - 1, W),
                v[n - 1] + knapsackRec(w, v, n - 1, W - w[n - 1])
            );
        }
    }
}
```

Время рекурсии без мемоизации O(2ⁿ).

### Пример использования

```java
int[] weights = {5, 6, 3};
int[] values = {10, 30, 15};
int capacity = 10;
int n = weights.length;

int maxValue = Knapsack.knapsackRec(weights, values, n, capacity);
System.out.println("Maximum value: " + maxValue); // Output: 40
```

## Решение с динамическим программированием

ДП: таблица m[i][j] — максимальная стоимость для первых i предметов и лимита j. Заполнение снизу вверх по i и j; переход тот же: не брать i-й или брать (если w[i-1] ≤ j).

```java
public static int knapsackDP(int[] w, int[] v, int n, int W) {
    if (n <= 0 || W <= 0) {
        return 0;
    }

    int[][] m = new int[n + 1][W + 1];

    // Инициализация: для 0 предметов стоимость всегда 0
    for (int j = 0; j <= W; j++) {
        m[0][j] = 0;
    }

    // Заполнение таблицы
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= W; j++) {
            if (w[i - 1] > j) {
                // Предмет слишком тяжелый, не берем его
                m[i][j] = m[i - 1][j];
            } else {
                // Выбираем максимум: не брать предмет или взять его
                m[i][j] = Math.max(
                    m[i - 1][j],
                    m[i - 1][j - w[i - 1]] + v[i - 1]
                );
            }
        }
    }

    return m[n][W];
}
```

Время O(n×W), память O(n×W); ниже — вариант с памятью O(W).

### Восстановление решения

Восстановление набора: идём от m[n][W] назад; если m[i][j] ≠ m[i-1][j], предмет i-1 взят.

```java
public static List<Integer> getSelectedItems(int[] w, int[] v, int n, int W, int[][] m) {
    List<Integer> selected = new ArrayList<>();
    int i = n;
    int j = W;

    while (i > 0 && j > 0) {
        if (m[i][j] != m[i - 1][j]) {
            // Предмет i был выбран
            selected.add(i - 1);
            j -= w[i - 1];
        }
        i--;
    }

    Collections.reverse(selected);
    return selected;
}
```

### Оптимизация памяти

Оптимизация памяти: один массив dp[0..W], обновление справа налево по j.

```java
public static int knapsackDPOptimized(int[] w, int[] v, int n, int W) {
    if (n <= 0 || W <= 0) {
        return 0;
    }

    int[] dp = new int[W + 1];

    for (int i = 0; i < n; i++) {
        // Идем справа налево, чтобы не использовать уже обновленные значения
        for (int j = W; j >= w[i]; j--) {
            dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i]);
        }
    }

    return dp[W];
}
```

## Сравнение подходов

| Подход | Время | Память | Когда использовать |
|--------|--------|--------|-------------------|
| Рекурсия | O(2ⁿ) | O(n) | Маленькие n, обучение |
| ДП 2D | O(n×W) | O(n×W) | Стандарт |
| ДП 1D | O(n×W) | O(W) | Экономия памяти |

## Сложность

Рекурсия: время O(2ⁿ), память O(n). ДП 2D: O(n×W) время и память. ДП 1D: O(n×W) время, O(W) память.

## Особенности

Задача NP-трудная; полиномиального алгоритма нет. ДП даёт псевдополиномиальное решение, приемлемое при умеренном W. Одномерный массив снижает потребление памяти.

## Применение

Распределение ресурсов, планирование инвестиций, криптография, бюджет, загрузка контейнеров.

## Варианты задачи

### Вариант 1: Неограниченный рюкзак

```java
public static int unboundedKnapsack(int[] w, int[] v, int n, int W) {
    int[] dp = new int[W + 1];

    for (int i = 0; i <= W; i++) {
        for (int j = 0; j < n; j++) {
            if (w[j] <= i) {
                dp[i] = Math.max(dp[i], dp[i - w[j]] + v[j]);
            }
        }
    }

    return dp[W];
}
```

### Вариант 2: Рюкзак с дробными предметами

```java
public static double fractionalKnapsack(int[] w, int[] v, int n, int W) {
    // Сортируем по соотношению стоимость/вес
    Item[] items = new Item[n];
    for (int i = 0; i < n; i++) {
        items[i] = new Item(w[i], v[i]);
    }
    Arrays.sort(items, (a, b) ->
        Double.compare(b.ratio, a.ratio)
    );

    double totalValue = 0;
    int remainingWeight = W;

    for (Item item : items) {
        if (remainingWeight >= item.weight) {
            totalValue += item.value;
            remainingWeight -= item.weight;
        } else {
            totalValue += item.value * ((double) remainingWeight / item.weight);
            break;
        }
    }

    return totalValue;
}
```

## Когда использовать

Рекурсия полезна для понимания и при малых n (например, n &lt; 20). Для продакшена и средних размеров — ДП (2D или 1D по весу/стоимости); при больших W — оптимизация по памяти или ветви и границы.

## Лучшие практики

Граничные случаи: n=0 или W=0 0; отрицательные веса/стоимости не допускаются. Восстановление набора — по таблице от m[n][W] назад по рекуррентному правилу. Дробные веса — жадный алгоритм (сортировка по удельной стоимости); целые — ДП или ветви и границы. Тесты: один предмет, все тяжелее W, пустой набор, сумма весов равна W.

## Решение проблем

| Симптом | Возможная причина | Решение |
|---------|-------------------|---------|
| StackOverflowError при рекурсии | Слишком большое n | Использовать ДП вместо чистой рекурсии |
| Неверный ответ при W больших | Переполнение или ошибка индекса | Проверить границы j в цикле (j ≥ w[i-1]) |
| Восстановление набора даёт не тот набор | Неверный порядок обхода таблицы | Идти от m[n][W], при m[i][j]≠m[i-1][j] считать предмет i-1 выбранным и переходить к m[i-1][j-w[i-1]] |

## Частые вопросы

**Почему ДП 1D обходится справа налево?** Чтобы не использовать уже обновлённые значения текущей итерации (один предмет не должен учитываться дважды в одной «строке»).

**Когда использовать рекурсию с мемоизацией?** Когда нужна читаемость рекуррентного соотношения без ручного заполнения таблицы; асимптотика та же, что у ДП, но стек вызовов ограничивает n.

**Чем 0-1 от неограниченного рюкзака?** В 0-1 каждый предмет один раз; в неограниченном один предмет можно брать многократно — в ДП переход тогда dp[j] = max(dp[j], dp[j-w[i]]+v[i]) с обходом j слева направо.

## Заключение

Задача 0-1 рюкзака формулируется как задача целочисленной оптимизации; рекурсия наглядна, ДП даёт практичное время O(n×W) и возможность восстановления набора предметов.
