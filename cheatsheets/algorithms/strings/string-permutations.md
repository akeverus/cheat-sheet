## Описание алгоритма

Перестановка — это перестановка элементов в множестве. Другими словами, это все возможные варианты порядка сбора.

В этом руководстве мы узнаем, как легко создавать перестановки в **Java** с использованием сторонних библиотек. В частности, мы будем работать с перестановкой в строке.

Иногда нам нужно проверить все возможные перестановки строкового значения. Часто для умопомрачительных онлайн-упражнений по кодированию и реже для повседневных рабочих задач. Например, строка «**abc**» будет иметь шесть различных способов расположения символов внутри: «**abc**», «**acb**», «**cab**», «**bac**», «**bca**», «**cba**».

Пара четко определенных алгоритмов может помочь нам создать все возможные перестановки для определенного значения **String**. Например, самым известным является алгоритм Хипа. Тем не менее, это довольно сложно и неинтуитивно. Кроме того, рекурсивный подход усугубляет ситуацию.

Реализация алгоритма генерации перестановок потребует написания пользовательской логики. Легко сделать ошибку в реализации и трудно проверить, правильно ли она работает с течением времени. Также нет смысла переписывать написанное ранее.

Кроме того, работая со строковыми значениями, можно переполнить пул строк, создав слишком много экземпляров, если делать это неаккуратно.

## Реализация на Java

### Apache Commons

Вот библиотеки, которые в настоящее время предоставляют такие функции для генерации перестановок в `Java`. Каждая библиотека имеет свои особенности и преимущества, и выбор конкретной библиотеки зависит от требований приложения.

#### Зависимость Maven

Во-первых, давайте добавим в проект общие коллекции зависимости `Maven`.

```xml
<dependency>
    <groupId>org.apache.commons</groupId>
    <artifactId>commons-collections4</artifactId>
    <version>4.4</version>
</dependency>
```

### Eager перестановки

**В целом **Apache** предоставляет простой **API**. **CollectionUtils** охотно создает перестановки, поэтому мы должны быть осторожны при работе с длинными строковыми значениями:**

```java
// Генерация всех перестановок символов строки (Apache Commons, eager)
public List<String> eagerPermutationWithRepetitions(final String string) {
    final List<Character> characters = Helper.toCharacterList(string);
    return CollectionUtils.permutations(characters)
        .stream()
        .map(Helper::toString)
        .collect(Collectors.toList());
}
```

### Lazy перестановки

В то же время, чтобы заставить его работать с ленивым подходом, мы должны использовать `PermutationIterator`. Это позволяет генерировать перестановки по требованию, что значительно экономит память при работе с большими строками.

```java
public List<String> lazyPermutationWithoutRepetitions(final String string) {
    final List<Character> characters = Helper.toCharacterList(string);
    final PermutationIterator<Character> permutationIterator = new PermutationIterator<>(characters);
    final List<String> result = new ArrayList<>();

    while (permutationIterator.hasNext()) {
        result.add(Helper.toString(permutationIterator.next()));
    }

    return result;
}
```

### Вспомогательные методы

Мы будем использовать метод `Helper.toCharacterList` в приведённых ниже примерах. Этот метод инкапсулирует сложность преобразования строки в список символов, что упрощает работу с различными библиотеками для генерации перестановок. Кроме того, мы будем использовать вспомогательный метод для преобразования списка символов в строку, что позволяет легко работать с результатами генерации перестановок.

```java
static String toString(Collection<Character> collection) {
    return collection.stream()
        .map(s -> s.toString())
        .collect(Collectors.joining());
}
```

### Особенности Apache Commons

Эта библиотека не обрабатывает дубликаты, поэтому строка «**aaaaaa**» будет производить `720` перестановок, что часто нежелательно. Кроме того, у **PermutationIterator** нет метода для получения количества перестановок. В этом случае мы должны рассчитать их отдельно в зависимости от размера ввода.

## Guava

Во-первых, давайте добавим в проект зависимость `Maven` для библиотеки `Guava`. Эта библиотека предоставляет мощные инструменты для работы с коллекциями и комбинаторикой.

```xml
<dependency>
    <groupId>com.google.guava</groupId>
    <artifactId>guava</artifactId>
    <version>31.0.1-jre</version>
</dependency>
```

### Перестановки с повторениями

`Guava` позволяет создавать перестановки с помощью `Collections2`. `API` прост в использовании и предоставляет удобные методы для работы с перестановками. Результатом `Collections2.permutations` является коллекция `PermutationCollection`, которая обеспечивает лёгкий доступ к перестановкам. Все перестановки создаются лениво, что делает работу с большими строками более эффективной.

### Перестановки без повторений

Кроме того, этот класс предоставляет `API` для создания перестановок без повторений. Это особенно полезно, когда нужно исключить дубликаты из результата генерации перестановок.

### Особенности Guava

Однако проблема с этими методами заключается в том, что они помечены аннотацией `@Beta`, что не гарантирует, что этот `API` не изменится в будущих выпусках. Это означает, что при обновлении библиотеки код может потребовать изменений, что следует учитывать при выборе библиотеки для долгосрочных проектов.

## CombinatoricsLib

**Чтобы использовать его в проекте, добавим **Maven**-зависимость **combinatoricslib3**:**

```xml
<dependency>
    <groupId>com.github.dpaukov</groupId>
    <artifactId>combinatoricslib3</artifactId>
    <version>3.3.3</version>
</dependency>
```

### Перестановки без повторений

Хотя это небольшая библиотека, она предоставляет множество инструментов комбинаторики, включая перестановки. Сам `API` очень интуитивно понятен и использует потоки `Java`. Давайте создадим перестановки из определённой строки или списка символов. Приведённый выше код создаёт генератор, который предоставит перестановки для `String`. Перестановка будет получена лениво. Таким образом, мы только создали генератор и подсчитали ожидаемое количество перестановок, что делает работу с большими строками более эффективной.

### Перестановки с повторениями

В то же время с помощью этой библиотеки мы можем определить стратегию для дубликатов. Если мы возьмём в качестве примера строку `aaaaaa`, мы получим только одну вместо `720` одинаковых перестановок. `TreatDuplicatesAs` позволяет нам определить, как мы хотели бы обрабатывать дубликаты, что делает библиотеку гибкой для различных сценариев использования.

### Другие опции

```java
// Перестановки с ограничением длины
public List<String> permutationWithLength(final String string, final int length) {
    List<Character> chars = Helper.toCharacterList(string);
    return Generator.permutation(chars)
        .simple(length)
        .stream()
        .map(Helper::toString)
        .collect(Collectors.toList());
}

// Перестановки с фильтром
public List<String> permutationWithFilter(final String string) {
    List<Character> chars = Helper.toCharacterList(string);
    return Generator.permutation(chars)
        .simple()
        .stream()
        .filter(perm -> perm.get(0) != 'a') // Фильтр: не начинается с 'a'
        .map(Helper::toString)
        .collect(Collectors.toList());
}
```

## Реализация на Kotlin

В `Kotlin` генерация перестановок может быть реализована различными способами, включая рекурсивный, итеративный и функциональный подходы. Каждый подход имеет свои преимущества и применяется в зависимости от требований приложения и стиля программирования.

### Рекурсивная реализация

```kotlin
fun generatePermutations(input: String): List<String> {
    if (input.length <= 1) {
        return listOf(input)
    }

    val result = mutableListOf<String>()
    for (i in input.indices) {
        val char = input[i]
        val remaining = input.substring(0, i) + input.substring(i + 1)
        val perms = generatePermutations(remaining)
        for (perm in perms) {
            result.add(char + perm)
        }
    }
    return result
}
```

### Итеративная реализация

```kotlin
fun generatePermutationsIterative(input: String): List<String> {
    val result = mutableListOf<String>()
    val queue = mutableListOf("")

    for (char in input) {
        val size = queue.size
        for (i in 0 until size) {
            val current = queue.removeAt(0)
            for (j in 0..current.length) {
                val newPerm = current.substring(0, j) + char + current.substring(j)
                queue.add(newPerm)
            }
        }
    }

    return queue
}
```

### Функциональный стиль

```kotlin
fun String.permutations(): List<String> {
    if (length <= 1) return listOf(this)

    return flatMapIndexed { index, char ->
        (substring(0, index) + substring(index + 1))
            .permutations()
            .map { char + it }
    }
}
```

Использование этих методов позволяет легко генерировать перестановки строк в `Kotlin`. Рекурсивный подход прост для понимания, итеративный подход более эффективен по памяти, а функциональный стиль использует возможности `Kotlin` для создания элегантного и читаемого кода.

### Использование библиотек

Для `Kotlin` можно использовать те же `Java` библиотеки или `Kotlin`-специфичные решения. Это позволяет использовать проверенные библиотеки из экосистемы `Java` в проектах на `Kotlin`, что упрощает интеграцию и обеспечивает совместимость с существующим кодом.

```kotlin
// Использование Java библиотек через Kotlin
import org.apache.commons.collections4.CollectionUtils
import org.paukov.combinatorics3.Generator

fun generatePermutationsWithCombinatoricsLib(input: String): List<String> {
    val chars = input.toList()
    return Generator.permutation(chars)
        .simple()
        .map { it.joinToString("") }
        .toList()
}
```

## Сравнение библиотек

Сравнение библиотек показывает различные подходы к генерации перестановок. `Apache Commons` поддерживает ленивую генерацию через `PermutationIterator`, но не обрабатывает дубликаты, что может быть проблематично для строк с повторяющимися символами. `Guava` также поддерживает ленивую генерацию и частично обрабатывает дубликаты, но методы помечены как `@Beta`, что означает возможные изменения в будущих версиях. `CombinatoricsLib` предоставляет полную поддержку ленивой генерации и обработки дубликатов с очень простым `API`, что делает её предпочтительным выбором для многих приложений.

## Сложность

### Временная сложность

- **Генерация всех перестановок:** `O(n! * n)`, где n — длина строки
- **Количество перестановок:** n! для строки без дубликатов
- **С дубликатами:** n! / (n1! * n2! ...  nk!), где ni — количество повторений i-го символа

### Пространственная сложность

- **Eager подход:** `O(n! * n)` - хранит все перестановки
- **Lazy подход:** `O(n)` - только текущая перестановка

## Особенности

- **Ленивая генерация:** Все библиотеки поддерживают ленивую генерацию
- **Обработка дубликатов: CombinatoricsLib** лучше всего обрабатывает дубликаты
- **Производительность: Lazy** подход более эффективен по памяти

## Ручная реализация

### Рекурсивный подход

Если нужно реализовать без библиотек, можно использовать рекурсивный подход, который прост для понимания и реализации. Этот подход основан на идее фиксирования одного символа и рекурсивной генерации перестановок для оставшихся символов.

```java
public List<String> generatePermutations(String str) {
    List<String> result = new ArrayList<>();
    generatePermutationsHelper("", str, result);
    return result;
}

private void generatePermutationsHelper(String prefix, String remaining, List<String> result) {
    int n = remaining.length();
    if (n == 0) {
        result.add(prefix);
    } else {
        for (int i = 0; i < n; i++) {
            generatePermutationsHelper(
                prefix + remaining.charAt(i),
                remaining.substring(0, i) + remaining.substring(i + 1, n),
                result
            );
        }
    }
}
```

### Итеративный подход (Heap's Algorithm)

Итеративный подход использует алгоритм Хипа (`Heap's Algorithm`), который генерирует перестановки без использования рекурсии. Этот подход более эффективен по памяти, так как не требует стека вызовов, и может быть предпочтительным для больших строк.

## Когда использовать

Используйте библиотеки, когда нужна надёжность и производительность, так как проверенные библиотеки обеспечивают оптимальную реализацию алгоритмов генерации перестановок. Библиотеки также полезны, когда не хотите писать свой код и нужна обработка дубликатов, что может быть сложно реализовать самостоятельно.

Используйте ручную реализацию, когда нужен полный контроль над процессом генерации перестановок, что позволяет настроить алгоритм под конкретные требования приложения. Ручная реализация также полезна при обучении алгоритмам, так как позволяет понять внутреннюю работу алгоритмов генерации перестановок. Кроме того, ручная реализация может быть предпочтительной, когда нет внешних зависимостей, что упрощает развёртывание и поддержку приложения.

## Лучшие практики

Объём перестановок критически важен при работе с большими строками. Число перестановок `n` символов без повторений равно `n!` — для `n > 10` предпочтите ленивую генерацию (итератор/стрим), чтобы не держать все варианты в памяти. Это предотвращает проблемы с памятью и обеспечивает эффективную работу приложения.

Дубликаты требуют особого внимания при генерации перестановок. При повторяющихся символах в строке используйте множество (`Set`) для результата или генерацию с учётом мультимножества, иначе будет дублирование перестановок. Это гарантирует корректность результатов и предотвращает создание идентичных перестановок.

Строки требуют эффективной обработки при генерации перестановок. Не конкатенируйте символы в цикле через `+`; используйте `StringBuilder` или коллекцию символов с последующим объединением. Это значительно улучшает производительность и предотвращает создание большого количества временных объектов.

Библиотеки имеют различные особенности, которые следует учитывать при выборе. `Apache Commons` `PermutationIterator` — ленивый; `Guava` и `CombinatoricsLib` дают готовые коллекции — выбирайте по зависимости от размера `n` и необходимости ленивости. Это позволяет выбрать оптимальную библиотеку для конкретных требований приложения.

Тестирование должно покрывать все граничные случаи. Проверьте строки `a`, `ab`, `abc`, `aab` (с повторением), пустую строку; сверьте количество результатов с `n!` для неповторяющихся символов. Это гарантирует корректную работу алгоритма во всех возможных ситуациях.

## Решение проблем

При работе с генерацией перестановок могут возникать различные проблемы. Если генерация перестановок занимает слишком много времени, убедитесь, что вы используете ленивую генерацию для больших строк. Если возникают проблемы с памятью, рассмотрите возможность использования итераторов или потоков вместо создания всех перестановок сразу. Если результаты содержат дубликаты, убедитесь, что вы правильно обрабатываете повторяющиеся символы в строке.

Проблемы с производительностью часто связаны с использованием eager подхода для больших строк. В таких случаях рекомендуется использовать lazy подход или итераторы, которые генерируют перестановки по требованию. Также важно избегать создания большого количества временных объектов при работе со строками.

Проблемы с корректностью результатов могут возникать при неправильной обработке дубликатов. Убедитесь, что вы используете правильную стратегию для обработки повторяющихся символов, что гарантирует корректность результатов генерации перестановок.

## Частые вопросы

**Какую библиотеку лучше использовать для генерации перестановок?** Выбор библиотеки зависит от конкретных требований. `CombinatoricsLib` предоставляет лучшую поддержку обработки дубликатов и простой `API`. `Apache Commons` подходит для базовых случаев с ленивой генерацией. `Guava` также хорош, но методы помечены как `@Beta`.

**Как обрабатывать очень длинные строки?** Для очень длинных строк рекомендуется использовать ленивую генерацию через итераторы или потоки, чтобы не создавать все перестановки сразу. Это предотвращает проблемы с памятью и обеспечивает эффективную работу приложения.

**Как обрабатывать дубликаты в строке?** Для обработки дубликатов используйте `CombinatoricsLib` с параметром `TreatDuplicatesAs.IDENTICAL` или используйте множество (`Set`) для хранения результатов. Это гарантирует, что дубликаты будут правильно обработаны и не будут создавать идентичные перестановки.

**Как улучшить производительность генерации перестановок?** Используйте ленивую генерацию для больших строк, избегайте создания большого количества временных объектов при работе со строками, используйте эффективные структуры данных для хранения результатов. Также рассмотрите возможность использования итераторов вместо создания всех перестановок сразу.

## Глоссарий терминов

**Перестановка** — упорядоченное расположение элементов множества. В контексте строк перестановка представляет собой все возможные способы расположения символов строки.

**Факториал** — произведение всех натуральных чисел от 1 до `n`, обозначаемое как `n!`. В контексте перестановок факториал определяет количество возможных перестановок `n` элементов.

**Ленивая генерация** — подход к генерации данных, при котором элементы создаются по требованию, а не все сразу. Это позволяет эффективно работать с большими объёмами данных без создания всех элементов в памяти.

**Eager генерация** — подход к генерации данных, при котором все элементы создаются сразу и сохраняются в памяти. Это может быть проблематично для больших объёмов данных, но обеспечивает быстрый доступ к элементам.

**Алгоритм Хипа** — алгоритм генерации перестановок без использования рекурсии. Алгоритм Хипа эффективен по памяти и может быть предпочтительным для больших строк.
