# Поиск строки в большом тексте (`Large Text String Search`)

Поиск подстроки в большом тексте — одна из фундаментальных задач в информатике, имеющая множество практических применений. В этом документе рассматриваются несколько классических алгоритмов поиска шаблона: наивный алгоритм, алгоритм Рабина-Карпа, алгоритм Кнута-Морриса-Пратта (`KMP`) и алгоритм Бойера-Мура-Хорспула. Каждый алгоритм имеет свои преимущества и области применения, и выбор конкретного алгоритма зависит от характеристик текста, шаблона и требований к производительности. Документ включает подробный анализ временной и пространственной сложности каждого алгоритма, а также практические рекомендации по их использованию.

## Описание алгоритма

Поиск подстроки в тексте представляет собой задачу нахождения всех вхождений заданного шаблона в тексте. Эта задача имеет множество практических применений, от простого поиска в текстовых редакторах до сложных систем полнотекстового поиска. В этом документе мы рассмотрим несколько классических алгоритмов поиска шаблона, каждый из которых имеет свои преимущества и области применения. Предоставленные алгоритмы представляют собой базовые подходы к поиску подстроки и не являются оптимальным решением для полнотекстового поиска в сложных приложениях. Для полноценного полнотекстового поиска с поддержкой морфологии, ранжирования результатов и работы с большими объёмами данных рекомендуется использовать специализированные решения, такие как `Solr` или `Elasticsearch`, которые построены на основе более сложных структур данных и алгоритмов.

## Реализация на Java

### Алгоритм 1: Наивный поиск (Java)

Название этого алгоритма описывает его лучше, чем любое другое объяснение. Это самое естественное решение задачи поиска подстроки, которое приходит в голову при первом знакомстве с задачей. Алгоритм работает путём последовательного сравнения шаблона с каждой возможной позицией в тексте.

```java
// Наивный поиск подстроки: сдвиг по одному символу, сравнение по буквам (O(n*m))
public static int simpleTextSearch(char[] pattern, char[] text) {
    int patternSize = pattern.length;
    int textSize = text.length;
    int i = 0;

    while ((i + patternSize) <= textSize) {
        int j = 0;
        while (text[i + j] == pattern[j]) {
            j += 1;
            if (j >= patternSize) {
                return i;
            }
        }
        i += 1;
    }

    return -1;
}
```

Идея этого алгоритма проста: перебрать текст и, если есть совпадение для первой буквы шаблона, проверить, все ли буквы шаблона совпадают с текстом.

Если `m` — количество букв в шаблоне, а `n` — количество букв в тексте, временная сложность этого алгоритма равна `O(m*(n-m+1))`. Наихудший сценарий возникает в случае, когда строка имеет много частичных вхождений шаблона:

```text
Text: baeldunbaeldunbaeldunbaeldun
Pattern: baeldung
```

Как упоминалось выше, алгоритм простого текстового поиска очень неэффективен при длинных шаблонах и при наличии большого количества повторяющихся элементов шаблона.

## Алгоритм 2: Рабина-Карпа

Идея алгоритма Рабина-Карпа состоит в том, чтобы использовать хеширование для поиска шаблона в тексте. В начале алгоритма нам нужно вычислить хэш шаблона, который позже используется в алгоритме. Этот процесс называется вычислением отпечатков пальцев и позволяет быстро сравнивать подстроки текста с шаблоном без посимвольного сравнения.

Важной особенностью этапа предварительной обработки является то, что его временная сложность составляет `O(m)`, а итерация по тексту займёт `O(n)`, что даёт временную сложность всего алгоритма `O(m+n)` в среднем случае. Однако при наличии коллизий хэша требуется дополнительное посимвольное сравнение, что может увеличить сложность до `O(m*n)` в худшем случае.

### Вспомогательные методы

Прежде чем мы начнём, давайте определим простые методы вычисления простых чисел, которые мы используем в алгоритме Рабина-Карпа. Эти методы необходимы для выбора подходящего модуля при вычислении хэша, что помогает избежать переполнения и обеспечивает равномерное распределение хэш-значений.

```java
public static long getBiggerPrime(int m) {
    BigInteger prime = BigInteger.probablePrime(getNumberOfBits(m) + 1, new Random());
    return prime.longValue();
}

private static int getNumberOfBits(int number) {
    return Integer.SIZE - Integer.numberOfLeadingZeros(number);
}
```

### Реализация

Реализация алгоритма Рабина-Карпа использует скользящее хэширование для эффективного вычисления хэша каждой подстроки текста. При обнаружении совпадения хэшей выполняется посимвольное сравнение для подтверждения вхождения шаблона.

```java
public static int RabinKarpMethod(char[] pattern, char[] text) {
    int patternSize = pattern.length;
    int textSize = text.length;
    long prime = getBiggerPrime(patternSize);
    long r = 1;

    for (int i = 0; i < patternSize - 1; i++) {
        r *= 2;
        r = r % prime;
    }

    long[] t = new long[textSize];
    t[0] = 0;
    long pfinger = 0;

    for (int j = 0; j < patternSize; j++) {
        t[0] = (2 * t[0] + text[j]) % prime;
        pfinger = (2 * pfinger + pattern[j]) % prime;
    }

    int i = 0;
    boolean passed = false;
    int diff = textSize - patternSize;

    for (i = 0; i <= diff; i++) {
        if (t[i] == pfinger) {
            passed = true;
            for (int k = 0; k < patternSize; k++) {
                if (text[i + k] != pattern[k]) {
                    passed = false;
                    break;
                }
            }
            if (passed) {
                return i;
            }
        }

        if (i < diff) {
            long value = 2 * (t[i] - r * text[i]) + text[i + patternSize];
            t[i + 1] = ((value % prime) + prime) % prime;
        }
    }

    return -1;
}
```

В худшем случае временная сложность этого алгоритма составляет `O(m*(n-m+1))`. Однако в среднем этот алгоритм имеет временную сложность `O(n+m)`, что делает его более эффективным, чем наивный алгоритм для большинства практических случаев.

Кроме того, существует версия этого алгоритма Монте-Карло, которая быстрее, но может привести к неправильным совпадениям, известным как ложные срабатывания. Эта версия пропускает посимвольное сравнение при совпадении хэшей, что ускоряет работу, но требует дополнительной проверки результатов в критических приложениях.

## Алгоритм 3: Кнута-Морриса-Пратта (KMP)

В алгоритме простого текстового поиска мы видели, как алгоритм может работать медленно, если есть много частей текста, соответствующих шаблону. Проблема заключается в том, что при несовпадении алгоритм возвращается назад и начинает сравнение заново, что приводит к повторным проверкам одних и тех же символов.

Идея алгоритма Кнута-Морриса-Пратта заключается в вычислении таблицы сдвигов, которая предоставляет нам информацию о том, где мы должны искать наши кандидаты в шаблоны. Эта таблица строится на основе анализа самого шаблона и позволяет избежать возврата назад по тексту, что обеспечивает линейную временную сложность.

Java-реализация алгоритма `KMP`:

```java
public static int KnuthMorrisPrattSearch(char[] pattern, char[] text) {
    int patternSize = pattern.length;
    int textSize = text.length;
    int i = 0, j = 0;
    int[] shift = KnuthMorrisPrattShift(pattern);

    while ((i + patternSize) <= textSize) {
        while (text[i + j] == pattern[j]) {
            j += 1;
            if (j >= patternSize) {
                return i;
            }
        }

        if (j > 0) {
            i += shift[j - 1];
            j = Math.max(j - shift[j - 1], 0);
        } else {
            i++;
            j = 0;
        }
    }

    return -1;
}
```

Таблица сдвигов вычисляется на основе анализа префиксов и суффиксов шаблона. Для каждой позиции в шаблоне мы определяем максимальную длину собственного суффикса, который совпадает с префиксом шаблона. Это позволяет эффективно сдвигать шаблон при несовпадении, не возвращаясь назад по тексту.

```java
public static int[] KnuthMorrisPrattShift(char[] pattern) {
    int patternSize = pattern.length;
    int[] shift = new int[patternSize];
    shift[0] = 1;
    int i = 1, j = 0;

    while ((i + j) < patternSize) {
        if (pattern[i + j] == pattern[j]) {
            shift[i + j] = i;
            j++;
        } else {
            if (j == 0) {
                shift[i] = i + 1;
            }
            if (j > 0) {
                i = i + shift[j - 1];
                j = Math.max(j - shift[j - 1], 0);
            } else {
                i = i + 1;
                j = 0;
            }
        }
    }

    return shift;
}
```

Временная сложность этого алгоритма также `O(m+n)`, что делает его одним из наиболее эффективных алгоритмов поиска подстроки. Алгоритм гарантирует линейную сложность даже в худшем случае, что является его главным преимуществом перед другими подходами.

## Алгоритм 4: Бойера-Мура-Хорспула

Двум учёным, Бойеру и Муру, пришла в голову другая идея. Почему бы не сравнить шаблон с текстом справа налево, а не слева направо, сохраняя при этом направление смещения? Такой подход позволяет пропускать большие участки текста при несовпадении, что значительно ускоряет поиск, особенно для длинных шаблонов и текстов с большим алфавитом.

```java
public static int BoyerMooreHorspoolSimpleSearch(char[] pattern, char[] text) {
    int patternSize = pattern.length;
    int textSize = text.length;
    int i = 0, j = 0;

    while ((i + patternSize) <= textSize) {
        j = patternSize - 1;
        while (text[i + j] == pattern[j]) {
            j--;
            if (j < 0) {
                return i;
            }
        }
        i++;
    }

    return -1;
}
```

Как и ожидалось, простая версия будет выполняться за время `O(m * n)`. Но этот алгоритм привёл к реализации эвристики вхождения и совпадения, что значительно ускорило алгоритм. Эвристика использует информацию о последнем символе текущей подстроки текста для определения оптимального сдвига.

Существует много вариантов эвристической реализации алгоритма Бойера-Мура, и самый простой из них — вариант Хорспула. Эта версия алгоритма называется Бойера-Мура-Хорспула, и эта вариация решает проблему отрицательных сдвигов, которая может возникать в полной версии алгоритма Бойера-Мура.

Как и в алгоритме Бойера-Мура, временная сложность сценария в наихудшем случае составляет `O(m * n)`, а средняя сложность — `O(n)`. Использование пространства не зависит от размера шаблона, а только от размера алфавита, который равен `256`, поскольку это максимальное значение символа `ASCII` в английском алфавите. Такая пространственная сложность делает алгоритм особенно эффективным для работы с ограниченными алфавитами.

```java
public static int BoyerMooreHorspoolSearch(char[] pattern, char[] text) {
    int shift[] = new int[256];

    for (int k = 0; k < 256; k++) {
        shift[k] = pattern.length;
    }

    for (int k = 0; k < pattern.length - 1; k++) {
        shift[pattern[k]] = pattern.length - 1 - k;
    }

    int i = 0, j = 0;

    while ((i + pattern.length) <= text.length) {
        j = pattern.length - 1;
        while (text[i + j] == pattern[j]) {
            j -= 1;
            if (j < 0) {
                return i;
            }
        }
        i = i + shift[text[i + pattern.length - 1]];
    }

    return -1;
}
```

### Алгоритм 2: Рабина-Карпа

```kotlin
fun getBiggerPrimeK(m: Int): Long {
    val bits = Integer.SIZE - Integer.numberOfLeadingZeros(m) + 1
    return BigInteger.probablePrime(bits, Random()).toLong()
}

fun rabinKarpMethodK(pattern: CharArray, text: CharArray): Int {
    val patternSize = pattern.size
    val textSize = text.size
    val prime = getBiggerPrimeK(patternSize)
    var r = 1L

    for (i in 0 until patternSize - 1) {
        r = (2 * r) % prime
    }

    var fp = 0L
    var ft = 0L

    for (i in 0 until patternSize) {
        fp = ((2 * fp) + pattern[i].toInt()) % prime
        ft = ((2 * ft) + text[i].toInt()) % prime
    }

    var j = 0

    while ((j + patternSize) <= textSize) {
        if (fp == ft) {
            var matches = true
            for (i in 0 until patternSize) {
                if (pattern[i] != text[j + i]) {
                    matches = false
                    break
                }
            }
            if (matches) {
                return j
            }
        }

        if (j + patternSize < textSize) {
            ft = (2 * (ft - text[j].toInt() * r) + text[j + patternSize].toInt()) % prime
            if (ft < 0) {
                ft += prime
            }
        }
        j++
    }

    return -1
}
```

### Алгоритм 3: Кнута-Морриса-Пратта (KMP)

fun knuthMorrisPrattShiftK(pattern: CharArray): IntArray {
    val patternSize = pattern.size
    val shift = IntArray(patternSize)
    shift[0] = 1
    var i = 1
    var j = 0

    while (i + j < patternSize) {
        if (pattern[i + j] == pattern[j]) {
            shift[i + j] = i
            j++
        } else {
            if (j == 0) {
                shift[i] = i + 1
            }
            if (j > 0) {
                i += shift[j - 1]
                j = maxOf(j - shift[j - 1], 0)
            } else {
                i++
                j = 0
            }
        }
    }

    return shift
}

### Алгоритм 4: Бойера-Мура-Хорспула

fun boyerMooreHorspoolSearchK(pattern: CharArray, text: CharArray): Int {
    val shift = IntArray(256) { pattern.size }

    for (k in 0 until pattern.size - 1) {
        shift[pattern[k].code] = pattern.size - 1 - k
    }

    var i = 0

    while (i + pattern.size <= text.size) {
        var j = pattern.size - 1
        while (text[i + j] == pattern[j]) {
            j--
            if (j < 0) {
                return i
            }
        }
        i += shift[text[i + pattern.size - 1].code]
    }

    return -1
}

fun boyerMooreHorspoolSimpleSearchK(pattern: CharArray, text: CharArray): Int {

    while (i + patternSize <= textSize) {
        var j = patternSize - 1
        while (text[i + j] == pattern[j]) {
            j--
            if (j < 0) {
                return i
            }
        }
        i++
    }

    return -1
}

| Наивный | `O(n)` | `O(**n**m**)` | `O(**n**m**)` | `O(1)` |
| Рабина-Карпа | `O(**n+m**)` | `O(**n+m**)` | `O(**n*m**)` | `O(1)` |
| `KMP` | `O(n+m)` | `O(n+m)` | `O(n+m)` | `O(m)` |
| Бойера-Мура-Хорспула | `O(n)` | `O(n)` | `O(**n*m**)` | `O(256)` |

## Сложность

### Временная сложность

Наивный алгоритм имеет временную сложность `O(n*m)`, так как для каждого символа текста мы проверяем весь шаблон. Это делает его неэффективным для длинных текстов и шаблонов. Алгоритм Рабина-Карпа имеет временную сложность `O(n+m)` в среднем случае, но может деградировать до `O(n*m)` в худшем случае при большом количестве коллизий хэша. Алгоритм `KMP` обеспечивает гарантированную линейную сложность `O(n+m)` во всех случаях, что делает его предпочтительным выбором для критических приложений. Алгоритм Бойера-Мура-Хорспула имеет временную сложность `O(n)` в среднем случае, что делает его одним из самых быстрых алгоритмов на практике, но в худшем случае сложность может достигать `O(n*m)`.

### Пространственная сложность

Наивный алгоритм требует только константную память `O(1)`, что делает его наиболее эффективным по памяти. Алгоритм Рабина-Карпа также требует только константную память `O(1)`, так как использует только несколько переменных для хранения хэш-значений. Алгоритм `KMP` требует `O(m)` памяти для хранения таблицы сдвигов, что является разумным компромиссом между памятью и производительностью. Алгоритм Бойера-Мура-Хорспула требует `O(256)` памяти для таблицы сдвигов, что не зависит от размера шаблона и делает его особенно эффективным для работы с ограниченными алфавитами.

## Особенности

Каждый алгоритм имеет свои особенности, которые определяют его применимость в различных ситуациях. Наивный алгоритм является самым простым для понимания и реализации, что делает его хорошим выбором для обучения и простых задач. Алгоритм `KMP` наиболее эффективен в худшем случае, гарантируя линейную сложность даже при неблагоприятных входных данных. Алгоритм Бойера-Мура-Хорспула часто быстрее на практике благодаря эффективной эвристике сдвигов, которая позволяет пропускать большие участки текста. Алгоритм Рабина-Карпа представляет собой хороший компромисс между простотой и эффективностью, особенно при работе с несколькими шаблонами одновременно.

## Применение

Алгоритмы поиска строк находят широкое применение в различных областях информатики и обработки данных. В текстовых редакторах они используются для реализации функции поиска и замены текста, что является одной из самых востребованных функций в таких приложениях. В поисковых системах алгоритмы поиска строк являются основой для индексации и поиска документов по ключевым словам. В компиляторах они применяются для анализа лексических токенов и поиска ключевых слов в исходном коде. В биоинформатике алгоритмы поиска строк используются для поиска последовательностей ДНК и анализа генетических данных. В обработке данных они применяются для фильтрации, поиска паттернов и анализа больших объёмов текстовой информации.

## Когда использовать

Выбор конкретного алгоритма зависит от характеристик задачи и требований к производительности. Наивный алгоритм следует использовать, когда тексты короткие, нужна простота реализации и производительность не является критическим фактором. Такой алгоритм подходит для учебных целей и простых приложений, где простота кода важнее оптимизации.

Алгоритм Рабина-Карпа следует использовать, когда нужна средняя производительность и вы работаете с несколькими шаблонами одновременно. Алгоритм особенно эффективен, когда хеширование подходит для вашей задачи и вы готовы мириться с возможными ложными срабатываниями в версии Монте-Карло.

Алгоритм `KMP` следует использовать, когда нужна гарантированная производительность и шаблоны имеют повторяющиеся паттерны. Алгоритм особенно эффективен, когда важна худшая производительность и вы не можете позволить себе деградацию производительности в неблагоприятных случаях.

Алгоритм Бойера-Мура-Хорспула следует использовать, когда нужна практическая производительность, шаблоны длинные и алфавит ограничен. Алгоритм часто показывает лучшие результаты на практике благодаря эффективной эвристике сдвигов, которая позволяет пропускать большие участки текста при несовпадении.

## Лучшие практики

При выборе алгоритма для коротких шаблонов и однократного поиска достаточно наивного алгоритма или встроенного метода `String.indexOf()`. Для многократного поиска по одному тексту рекомендуется использовать предобработку с алгоритмами `KMP` или Бойера-Мура, либо более сложные структуры данных, такие как суффиксное дерево. Для поиска множества ключевых слов одновременно следует использовать алгоритм Ахо-Корасик, который эффективно обрабатывает несколько шаблонов параллельно.

Важно правильно обрабатывать граничные случаи: пустой шаблон, пустой текст, шаблон длиннее текста и отсутствие вхождений. Для отсутствия вхождений следует использовать договорённое значение, например `-1`, которое явно указывает на то, что шаблон не найден в тексте.

При использовании алгоритма Рабина-Карпа важно правильно выбирать хеш-функцию. Используйте модульную арифметику и подходящее простое основание, чтобы избежать переполнения. При коллизиях хэша всегда проверяйте посимвольное совпадение для подтверждения вхождения шаблона.

В алгоритме `KMP` таблица длин префиксов-суффиксов строится за `O(m)` времени, что делает предобработку эффективной. Используйте эту таблицу для сдвига без возврата назад по тексту, что обеспечивает линейную сложность алгоритма.

Для полнотекстового поиска в приложениях с поддержкой морфологии, ранжирования результатов и работы с большими объёмами данных рекомендуется использовать готовые поисковые движки, такие как `Lucene` или `Elasticsearch`, а не ручную реализацию базовых алгоритмов. Эти движки предоставляют множество дополнительных возможностей, включая индексацию, ранжирование и поддержку различных языков.

## Решение проблем

При работе с алгоритмами поиска строк могут возникать различные проблемы. Если алгоритм работает слишком медленно, убедитесь, что вы используете подходящий алгоритм для вашей задачи. Для длинных текстов и шаблонов наивный алгоритм может быть неприемлемо медленным, в таких случаях следует использовать `KMP` или Бойера-Мура-Хорспула.

Если алгоритм Рабина-Карпа даёт неправильные результаты, проверьте обработку коллизий хэша. Убедитесь, что при совпадении хэшей выполняется посимвольное сравнение для подтверждения вхождения шаблона. Также проверьте правильность выбора простого числа для модульной арифметики.

При проблемах с памятью в алгоритме `KMP` убедитесь, что размер таблицы сдвигов соответствует размеру шаблона. Для очень длинных шаблонов может потребоваться оптимизация или использование альтернативных алгоритмов.

Если алгоритм Бойера-Мура-Хорспула работает медленно, проверьте размер алфавита. Алгоритм наиболее эффективен для ограниченных алфавитов, таких как `ASCII`. Для больших алфавитов может потребоваться оптимизация таблицы сдвигов.

## Частые вопросы

**Вопрос:** Какой алгоритм самый быстрый?

**Ответ:** На практике алгоритм Бойера-Мура-Хорспула часто показывает лучшие результаты благодаря эффективной эвристике сдвигов. Однако для гарантированной производительности в худшем случае лучше использовать алгоритм `KMP`.

**Вопрос:** Можно ли использовать `String.indexOf()` вместо этих алгоритмов?

**Ответ:** Для простых задач `String.indexOf()` может быть достаточным, так как он оптимизирован на уровне JVM. Однако для специфических задач, таких как поиск нескольких шаблонов или работа с большими текстами, специализированные алгоритмы могут быть более эффективными.

**Вопрос:** Как обрабатывать поиск с учётом регистра?

**Ответ:** Перед применением алгоритма приведите текст и шаблон к одному регистру, либо модифицируйте функцию сравнения символов в алгоритме для игнорирования регистра.

**Вопрос:** Можно ли использовать эти алгоритмы для поиска регулярных выражений?

**Ответ:** Нет, эти алгоритмы предназначены для поиска точных совпадений. Для поиска по регулярным выражениям используйте специализированные библиотеки, такие как `java.util.regex` в `Java` или `kotlin.text.Regex` в `Kotlin`.

**Вопрос:** Как найти все вхождения шаблона, а не только первое?

**Ответ:** Модифицируйте алгоритм так, чтобы после нахождения вхождения он продолжал поиск с позиции после найденного вхождения. Сохраняйте все найденные позиции в список или коллекцию.

## Глоссарий терминов

`Наивный алгоритм` — простейший алгоритм поиска подстроки, который последовательно проверяет каждую позицию в тексте как потенциальное начало вхождения шаблона.

`Хеширование` — процесс преобразования данных произвольного размера в значение фиксированного размера, используемое для быстрого сравнения подстрок.

`Отпечаток пальца (fingerprint)` — хэш-значение подстроки, используемое в алгоритме Рабина-Карпа для быстрого сравнения без посимвольного сравнения.

`Таблица сдвигов` — предвычисленная таблица, используемая в алгоритме `KMP` для определения оптимального сдвига шаблона при несовпадении.

`Префикс` — начальная часть строки заданной длины.

`Суффикс` — конечная часть строки заданной длины.

`Эвристика` — практический метод решения задачи, который не гарантирует оптимальное решение, но часто даёт хорошие результаты на практике.

`Коллизия хэша` — ситуация, когда разные строки имеют одинаковое хэш-значение, что требует дополнительной проверки для подтверждения совпадения.

`Скользящее хэширование` — техника вычисления хэша следующей подстроки на основе хэша предыдущей подстроки без полного пересчёта.

`Полнотекстовый поиск` — технология поиска по всему содержимому документов, включая поддержку морфологии, ранжирования и работы с большими объёмами данных.

## Дополнительные примеры использования

### Пример 1: Поиск всех вхождений шаблона

Модифицируем алгоритм `KMP` для поиска всех вхождений шаблона в тексте:

```java
public static List<Integer> findAllOccurrencesKMP(char[] pattern, char[] text) {
    List<Integer> occurrences = new ArrayList<>();
    int patternSize = pattern.length;
    int textSize = text.length;
    int i = 0, j = 0;
    int[] shift = KnuthMorrisPrattShift(pattern);

    while ((i + patternSize) <= textSize) {
        while (text[i + j] == pattern[j]) {
            j += 1;
            if (j >= patternSize) {
                occurrences.add(i);
                break;
            }
        }

        if (j > 0) {
            i += shift[j - 1];
            j = Math.max(j - shift[j - 1], 0);
        } else {
            i++;
            j = 0;
        }
    }

    return occurrences;
}
```

### Пример 3: Поиск нескольких шаблонов

Используем алгоритм Рабина-Карпа для поиска нескольких шаблонов одновременно:

```java
public static Map<String, List<Integer>> searchMultiplePatterns(
        List<char[]> patterns, char[] text) {
    Map<String, List<Integer>> results = new HashMap<>();

    for (char[] pattern : patterns) {
        List<Integer> positions = new ArrayList<>();
        int pos = RabinKarpMethod(pattern, text);
        while (pos != -1) {
            positions.add(pos);
            // Продолжаем поиск с следующей позиции
            char[] remainingText = Arrays.copyOfRange(text, pos + 1, text.length);
            int nextPos = RabinKarpMethod(pattern, remainingText);
            if (nextPos != -1) {
                pos = pos + 1 + nextPos;
            } else {
                break;
            }
        }
        results.put(new String(pattern), positions);
    }

    return results;
}
```

### Пример 4: Оптимизированный поиск для длинных текстов

Реализуем версию алгоритма с ранним прерыванием для больших текстов:

```java
public static int searchWithEarlyTermination(char[] pattern, char[] text, int maxPositions) {
    int count = 0;
    int pos = 0;

    while (count < maxPositions && pos < text.length - pattern.length) {
        int found = KnuthMorrisPrattSearch(pattern,
            Arrays.copyOfRange(text, pos, text.length));
        if (found == -1) {
            break;
        }
        count++;
        pos = found + pattern.length;
    }

    return count;
}
```
