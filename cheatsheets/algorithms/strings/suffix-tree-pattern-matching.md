# Поиск по суффиксному дереву (Suffix Tree Pattern Matching)

Быстрое сопоставление строк с образцом с использованием дерева суффиксов. Рассматривается реализация структуры данных дерева суффиксов для эффективного поиска паттернов в тексте за линейное время. Дерево суффиксов позволяет выполнять множественные поиски в одном тексте с высокой производительностью, что делает его особенно полезным для задач, требующих многократного поиска различных паттернов в статическом тексте.

## Описание алгоритма

В этом уроке мы рассмотрим концепцию сопоставления строк с образцом и то, как мы можем сделать это быстрее. Затем мы рассмотрим его реализацию на `Java`. В строках сопоставление с образцом — это процесс проверки заданной последовательности символов, называемой шаблоном, в последовательности символов, называемой текстом. Этот процесс является фундаментальным для многих задач обработки текста и поиска информации.

### Основные ожидания

Основные ожидания от сопоставления с шаблоном, когда шаблон не является регулярным выражением, включают два ключевых требования. Совпадение должно быть точным, а не частичным, что означает полное соответствие последовательности символов паттерна последовательности символов в тексте. Результат должен содержать все совпадения, а не только первое совпадение, что позволяет найти все вхождения паттерна в тексте, а не останавливаться после первого найденного совпадения.

### Пример

Давайте используем пример, чтобы понять простую задачу сопоставления с образцом. Предположим, у нас есть паттерн `NA` и текст `HAVANABANANA`. При поиске мы обнаруживаем, что паттерн встречается в тексте трижды: на позициях 3, 7 и 11. Чтобы получить этот результат, мы можем подумать о перемещении шаблона вниз по тексту по одному символу за раз и проверке совпадения. Однако это метод грубой силы с временной сложностью `O(p·t)`, где `p` — длина шаблона, а `t` — длина текста. Такой подход неэффективен для больших текстов и множественных поисков, поэтому нам нужны более эффективные структуры данных.

### Trie и Suffix Trie

Мы можем сократить время поиска, сохранив шаблоны в структуре данных `trie`, которая известна своим быстрым поиском элементов. Структура данных `trie` хранит символы строки в древовидной структуре. Для двух строк `NA` и `NAB` мы получим дерево с двумя путями. Создание дерева позволяет перемещать группу шаблонов вниз по тексту и проверять совпадения всего за одну итерацию, что значительно ускоряет процесс поиска по сравнению с методом грубой силы.

Обратите внимание, что мы используем символ `$` для обозначения конца строки. Это важно для правильного определения границ строк и предотвращения ложных совпадений.

Суффикс `trie`, с другой стороны, представляет собой структуру данных `trie`, построенную с использованием всех возможных суффиксов одной строки. Для предыдущего примера `HAVANABANANA` мы можем построить суффиксное дерево, которое содержит все суффиксы строки. Суффиксные `trie` создаются для текста и обычно выполняются как часть этапа предварительной обработки. После этого можно быстро выполнить поиск шаблонов, найдя путь, соответствующий последовательности шаблонов. Однако известно, что дерево суффиксов занимает много места, поскольку каждый символ строки хранится в ребре, что может быть проблематично для очень длинных текстов.

### Suffix Tree

Суффиксное дерево — это просто сжатое суффиксное дерево. Это означает, что, соединяя ребра, мы можем хранить группу символов и тем самым значительно уменьшать объем памяти.

Каждый путь, начинающийся от корня к листу, представляет собой суффикс строки.

Дерево суффиксов также хранит положение суффикса в листовом узле. Например, `BANANA$` — это суффикс, начинающийся с седьмой позиции. Следовательно, его значение будет равно шести с использованием нумерации, начинающейся с нуля.

Итак, посмотрев на вещи в перспективе, мы можем видеть, что совпадение с шаблоном происходит, когда мы можем получить путь, начинающийся от корневого узла с ребрами, полностью совпадающими с заданным шаблоном позиционно.

Если путь заканчивается на листовом узле, мы получаем совпадение суффикса. В противном случае мы получим просто совпадение подстроки. Например, шаблон `NA` является суффиксом **HAVANABANA**[`NA`] и подстрокой **HAVA**[`NA`]**BANANA**.

## Реализация на Java

### Структуры данных

Давайте создадим структуру данных дерева суффиксов. Нам понадобятся два класса домена.

### Класс Node (Java)

Во-первых, нам нужен класс для представления узла дерева. Он должен хранить ребра дерева и его дочерние узлы. Кроме того, когда это конечный узел, ему необходимо хранить позиционное значение суффикса.

Итак, давайте создадим наш класс `Node`.

```java
public class Node {
    private String text;
    private List<Node> children;
    private int position;

    public Node(String word, int position) {
        this.text = word;
        this.position = position;
        this.children = new ArrayList<>();
    }

    // Getters and setters
    public String getText() { return text; }
    public void setText(String text) { this.text = text; }
    public List<Node> getChildren() { return children; }
    public int getPosition() { return position; }
    public void setPosition(int position) { this.position = position; }
}
```

### Класс SuffixTree (Java)

Во-вторых, нам нужен класс для представления дерева и хранения корневого узла. Он также должен хранить полный текст, из которого генерируются суффиксы. Это необходимо для корректного построения дерева и выполнения поиска паттернов, так как нам нужно знать исходный текст для определения позиций найденных совпадений.

```java
public class SuffixTree {
    private static final String WORD_TERMINATION = "$";
    private static final int POSITION_UNDEFINED = -1;
    private Node root;
    private String fullText;

    public SuffixTree(String text) {
        root = new Node("", POSITION_UNDEFINED);
        fullText = text;

        for (int i = 0; i < text.length(); i++) {
            addSuffix(text.substring(i) + WORD_TERMINATION, i);
        }
    }
}
```

## Построение дерева суффиксов

Прежде чем мы напишем нашу основную логику для хранения данных, давайте добавим несколько вспомогательных методов.

### Вспомогательные методы

#### Добавление дочернего узла

```java
private void addChildNode(Node parentNode, String text, int index) {
    parentNode.getChildren().add(new Node(text, index));
}
```

#### Поиск общего префикса

```java
private String getLongestCommonPrefix(String str1, String str2) {
    int compareLength = Math.min(str1.length(), str2.length());
    for (int i = 0; i < compareLength; i++) {
        if (str1.charAt(i) != str2.charAt(i)) {
            return str1.substring(0, i);
        }
    }
    return str1.substring(0, compareLength);
}
```

#### Разделение узла

```java
private void splitNodeToParentAndChild(Node parentNode, String parentNewText, String childNewText) {
    Node childNode = new Node(childNewText, parentNode.getPosition());

    if (parentNode.getChildren().size() > 0) {
        while (parentNode.getChildren().size() > 0) {
            childNode.getChildren().add(parentNode.getChildren().remove(0));
        }
    }

    parentNode.getChildren().add(childNode);
    parentNode.setText(parentNewText);
    parentNode.setPosition(POSITION_UNDEFINED);
}
```

### Обход дерева

Теперь давайте напишем нашу логику для обхода дерева, если мы можем позиционно сопоставить заданный шаблон.

```java
private List<Node> getAllNodesInTraversePath(String pattern, Node startNode, boolean isAllowPartialMatch) {
    List<Node> nodes = new ArrayList<>();

    for (int i = 0; i < startNode.getChildren().size(); i++) {
        Node currentNode = startNode.getChildren().get(i);
        String nodeText = currentNode.getText();

        if (pattern.charAt(0) == nodeText.charAt(0)) {
            if (isAllowPartialMatch && pattern.length() <= nodeText.length()) {
                nodes.add(currentNode);
                return nodes;
            }

            int compareLength = Math.min(nodeText.length(), pattern.length());

            for (int j = 1; j < compareLength; j++) {
                if (pattern.charAt(j) != nodeText.charAt(j)) {
                    if (isAllowPartialMatch) {
                        nodes.add(currentNode);
                    }
                    return nodes;
                }
            }

            nodes.add(currentNode);

            if (pattern.length() > compareLength) {
                List<Node> nodes2 = getAllNodesInTraversePath(
                    pattern.substring(compareLength),
                    currentNode,
                    isAllowPartialMatch
                );

                if (nodes2.size() > 0) {
                    nodes.addAll(nodes2);
                } else if (!isAllowPartialMatch) {
                    nodes.add(null);
                }
            }

            return nodes;
        }
    }

    return nodes;
}
```

### Добавление суффикса

Теперь мы можем написать нашу логику для хранения данных. Начнём с определения нового метода `addSuffix`.

```java
private void addSuffix(String suffix, int position) {
    List<Node> nodes = getAllNodesInTraversePath(suffix, root, true);

    if (nodes.size() == 0) {
        addChildNode(root, suffix, position);
    } else {
        Node lastNode = nodes.remove(nodes.size() - 1);
        String newText = suffix;

        if (nodes.size() > 0) {
            String existingSuffixUptoLastNode = nodes.stream()
                .map(a -> a.getText())
                .reduce("", String::concat);
            newText = newText.substring(existingSuffixUptoLastNode.length());
        }

        extendNode(lastNode, newText, position);
    }
}
```

### Расширение узла

```java
private void extendNode(Node node, String newText, int position) {
    String currentText = node.getText();
    String commonPrefix = getLongestCommonPrefix(currentText, newText);

    if (commonPrefix != currentText) {
        String parentText = currentText.substring(0, commonPrefix.length());
        String childText = currentText.substring(commonPrefix.length());
        splitNodeToParentAndChild(node, parentText, childText);
    }

    String remainingText = newText.substring(commonPrefix.length());
    addChildNode(node, remainingText, position);
}
```

## Поиск паттернов

Определив нашу древовидную структуру суффиксов для хранения данных, теперь мы можем написать логику для выполнения нашего поиска.

### Получение позиций

```java
private List<Integer> getPositions(Node node) {
    List<Integer> positions = new ArrayList<>();

    if (node.getText().endsWith(WORD_TERMINATION)) {
        positions.add(node.getPosition());
    }

    for (int i = 0; i < node.getChildren().size(); i++) {
        positions.addAll(getPositions(node.getChildren().get(i)));
    }

    return positions;
}
```

### Поиск текста

```java
public List<String> searchText(String pattern) {
    List<String> result = new ArrayList<>();
    List<Node> nodes = getAllNodesInTraversePath(pattern, root, false);

    if (nodes.size() > 0) {
        Node lastNode = nodes.get(nodes.size() - 1);
        if (lastNode != null) {
            List<Integer> positions = getPositions(lastNode);
            positions = positions.stream()
                .sorted()
                .collect(Collectors.toList());

            positions.forEach(m -> result.add(markPatternInText(m, pattern)));
        }
    }

    return result;
}
```

### Отметка паттерна в тексте

```java
private String markPatternInText(Integer startPosition, String pattern) {
    String matchingTextLHS = fullText.substring(0, startPosition);
    String matchingText = fullText.substring(startPosition, startPosition + pattern.length());
    String matchingTextRHS = fullText.substring(startPosition + pattern.length());
    return matchingTextLHS + "[" + matchingText + "]" + matchingTextRHS;
}
```

## Реализация на Kotlin

### Класс Node (Kotlin)

```kotlin
class NodeK(
    var text: String = "",
    var children: MutableList<NodeK> = mutableListOf(),
    var position: Int = -1
)
```

### Класс SuffixTree (Kotlin)

```kotlin
class SuffixTreeK(private val fullText: String) {
    private val root = NodeK()

    init {
        buildTree()
    }

    private fun buildTree() {
        for (i in fullText.indices) {
            addSuffix(fullText.substring(i), i)
        }
    }

    private fun addSuffix(suffix: String, position: Int) {
        var node = root
        var i = 0

        while (i < suffix.length) {
            var child: NodeK? = null
            val ch = suffix[i]

            for (c in node.children) {
                if (c.text.startsWith(ch)) {
                    child = c
                    break
                }
            }

            if (child == null) {
                child = NodeK(suffix.substring(i), mutableListOf(), position)
                node.children.add(child)
                break
            } else {
                val j = getMatchingLength(child.text, suffix.substring(i))
                if (j < child.text.length) {
                    val parent = NodeK(
                        child.text.substring(0, j),
                        mutableListOf(),
                        child.position
                    )
                    child.text = child.text.substring(j)
                    parent.children.add(child)
                    node.children.remove(child)
                    node.children.add(parent)
                    node = parent
                } else {
                    node = child
                    i += j
                }
            }
        }
    }

    private fun getMatchingLength(str1: String, str2: String): Int {
        var count = 0
        val min = minOf(str1.length, str2.length)
        for (i in 0 until min) {
            if (str1[i] == str2[i]) {
                count++
            } else {
                break
            }
        }
        return count
    }

    private fun getAllNodesInTraversePath(
        pattern: String,
        startNode: NodeK,
        isAllowPartialMatch: Boolean
    ): List<NodeK> {
        val nodes = mutableListOf<NodeK>()
        for (i in 0 until startNode.children.size) {
            val currentNode = startNode.children[i]
            val nodeText = currentNode.text

            if (fullText.substring(fullText.length - nodeText.length) == nodeText &&
                pattern.length > nodeText.length &&
                pattern.substring(0, nodeText.length) == nodeText) {
                nodes.add(currentNode)
                nodes.addAll(getAllNodesInTraversePath(
                    pattern.substring(nodeText.length),
                    currentNode,
                    isAllowPartialMatch
                ))
            } else if (pattern == nodeText || (isAllowPartialMatch && pattern.startsWith(nodeText))) {
                nodes.add(currentNode)
            } else if (nodeText.startsWith(pattern)) {
                nodes.add(currentNode)
            }
        }
        return nodes
    }

    private fun getPositions(node: NodeK): List<Int> {
        val positions = mutableListOf<Int>()
        if (node.position != -1) {
            positions.add(node.position)
        }

        for (child in node.children) {
            positions.addAll(getPositions(child))
        }

        return positions
    }

    fun searchText(pattern: String): List<String> {
        val result = mutableListOf<String>()
        val nodes = getAllNodesInTraversePath(pattern, root, false)

        if (nodes.isNotEmpty()) {
            val lastNode = nodes.lastOrNull()
            if (lastNode != null) {
                val positions = getPositions(lastNode).sorted()
                positions.forEach { pos ->
                    result.add(markPatternInText(pos, pattern))
                }
            }
        }

        return result
    }

    private fun markPatternInText(startPosition: Int, pattern: String): String {
        val matchingTextLHS = fullText.substring(0, startPosition)
        val matchingText = fullText.substring(startPosition, startPosition + pattern.length)
        val matchingTextRHS = fullText.substring(startPosition + pattern.length)
        return matchingTextLHS + "[" + matchingText + "]" + matchingTextRHS
    }
}
```

## Сложность

### Временная сложность

Временная сложность суффиксного дерева зависит от операции, которую мы выполняем. Построение дерева имеет временную сложность `O(t)`, где `t` — длина текста. Это означает, что построение дерева выполняется за время, пропорциональное длине текста, что делает его эффективным для предварительной обработки. Поиск паттерна имеет временную сложность `O(p)`, где `p` — длина паттерна. Это означает, что поиск выполняется за время, пропорциональное длине паттерна, а не текста, что делает его очень эффективным для поиска коротких паттернов в длинных текстах. Общая сложность для одного паттерна составляет `O(t + p)`, что включает время на построение дерева и время на поиск паттерна.

### Пространственная сложность

Пространственная сложность суффиксного дерева составляет `O(t)` — линейная по длине текста. Это означает, что дерево требует памяти, пропорциональной длине текста, что делает его эффективным с точки зрения использования памяти. Однако на практике потребление памяти может быть выше из-за накладных расходов на хранение узлов и рёбер дерева, но в целом структура данных остаётся эффективной для большинства практических применений.

## Особенности

Суффиксное дерево имеет несколько ключевых особенностей, которые делают его эффективным инструментом для поиска паттернов. Эффективность поиска составляет линейное время, что означает, что поиск одного паттерна выполняется за время, пропорциональное длине паттерна, а не текста. Память также линейна по длине текста, что делает структуру данных эффективной с точки зрения использования памяти. Применение особенно эффективно для множественных поисков, когда нужно выполнить множество поисков различных паттернов в одном тексте.

## Применение

Дерево суффиксов используется в различных областях, где требуется эффективный поиск паттернов в тексте. В биоинформатике дерево суффиксов используется для поиска в ДНК, где нужно найти определённые последовательности нуклеотидов в геномных данных. Поисковые системы используют суффиксные деревья для индексации и быстрого поиска документов по ключевым словам. Сжатие данных также использует суффиксные деревья для эффективного представления повторяющихся паттернов в данных. Анализ текста и обработка строк также широко используют суффиксные деревья для различных задач поиска и анализа текстовых данных.

## Когда использовать

Используйте дерево суффиксов, когда выполняются множественные поиски в одном тексте, так как предварительная обработка текста позволяет выполнять последующие поиски очень быстро. Дерево суффиксов также подходит, когда нужна максимальная производительность поиска, так как оно обеспечивает оптимальную временную сложность для поиска паттернов. Текст должен быть статичным или редко меняться, так как построение дерева суффиксов требует времени и ресурсов, и перестроение дерева при каждом изменении текста может быть неэффективным.

### Альтернативы

Альтернативы дереву суффиксов включают различные структуры данных и алгоритмы в зависимости от конкретных требований задачи. `Trie` подходит для множества паттернов, когда нужно искать несколько различных паттернов в тексте. `KMP` (алгоритм Кнута-Морриса-Пратта) эффективен для одного паттерна, когда нужно найти все вхождения одного паттерна в тексте. `Boyer-Moore` подходит для практических применений, когда важна производительность в реальных сценариях использования.

## Лучшие практики

Когда использовать суффиксное дерево зависит от конкретных требований задачи. Суффиксное дерево оправдано при многократном поиске разных паттернов по одному и тому же тексту: построение `O(n)`, поиск одного паттерна `O(m)`. Для однократного поиска проще использовать `KMP` или алгоритм Бойера-Мура, которые не требуют предварительной обработки текста.

Память является важным фактором при работе с суффиксными деревьями. Суффиксное дерево потребляет значительный объём памяти — порядка десятков байт на символ текста. Для очень длинных текстов рассмотрите суффиксный массив или сжатые структуры данных, которые могут значительно уменьшить потребление памяти при сохранении приемлемой производительности поиска.

Терминатор играет важную роль в корректной работе суффиксного дерева. Добавляйте уникальный символ в конец строки (`$`), чтобы суффиксы не были префиксами друг друга и листья однозначно соответствовали суффиксам. Это гарантирует корректное построение дерева и правильный поиск паттернов.

Реализация построения суффиксного дерева за линейное время (алгоритм Укконена) сложна и требует глубокого понимания алгоритма. Для учебных целей допустимо квадратичное построение, которое проще реализовать и понять. Для продакшена рекомендуется использовать проверенные библиотеки, которые обеспечивают оптимальную производительность и надёжность.

Тестирование должно покрывать все граничные случаи. Проверьте поиск в пустой строке, паттерн длиннее текста, все вхождения паттерна, отсутствие паттерна в тексте, паттерн совпадает с целой строкой. Это гарантирует корректную работу алгоритма во всех возможных ситуациях.

## Решение проблем

При работе с суффиксными деревьями могут возникать различные проблемы. Если построение дерева занимает слишком много времени, убедитесь, что вы используете эффективный алгоритм построения. Для учебных целей допустимо квадратичное построение, но для продакшена рекомендуется использовать алгоритм Укконена или проверенные библиотеки. Если поиск паттернов даёт неверные результаты, проверьте корректность добавления терминатора (`$`) в конец строки и убедитесь, что все суффиксы правильно обрабатываются.

Проблемы с памятью часто связаны с большим размером текста. Если дерево суффиксов потребляет слишком много памяти, рассмотрите возможность использования суффиксного массива или сжатых структур данных. Также убедитесь, что вы правильно управляете памятью и освобождаете ресурсы после использования дерева.

Проблемы с производительностью могут возникать при неправильной реализации алгоритма. Убедитесь, что вы используете эффективные структуры данных для хранения узлов и рёбер дерева. Также проверьте, что поиск паттернов выполняется корректно и не создаёт лишних временных объектов.

## Глоссарий терминов

**Суффикс** — подстрока строки, начинающаяся с определённой позиции и продолжающаяся до конца строки. В контексте суффиксного дерева все суффиксы строки хранятся в структуре данных для эффективного поиска паттернов.

**Trie** — структура данных в виде дерева, используемая для хранения строк и быстрого поиска элементов. В контексте поиска паттернов `trie` позволяет эффективно хранить и искать множество паттернов.

**Суффиксное дерево** — сжатое суффиксное `trie`, которое хранит все суффиксы строки в компактной форме. Суффиксное дерево позволяет эффективно выполнять поиск паттернов за линейное время.

**Терминатор** — уникальный символ (обычно `$`), добавляемый в конец строки для предотвращения того, чтобы суффиксы были префиксами друг друга. Это гарантирует корректное построение дерева и правильный поиск паттернов.

**Алгоритм Укконена** — алгоритм построения суффиксного дерева за линейное время. Алгоритм Укконена является оптимальным алгоритмом построения суффиксного дерева, но его реализация сложна и требует глубокого понимания алгоритма.
