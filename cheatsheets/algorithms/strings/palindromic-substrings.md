# Палиндромные подстроки (Palindromic Substrings)

Поиск всех подстрок в заданной строке, которые являются палиндромами. Рассматриваются три подхода: грубая сила (`O(n³)`), расширение от центра (`O(n²)`), и алгоритм Манахера (`O(n)`). Каждый подход имеет свои преимущества и применяется в зависимости от размера входных данных, требований к производительности и сложности реализации.

## Описание алгоритма

В этом кратком руководстве мы рассмотрим различные подходы к поиску всех подстрок в заданной строке, которые являются палиндромами. Мы также отметим временную сложность каждого подхода, что поможет выбрать оптимальное решение для конкретной задачи.

### Примеры

Примеры показывают различные случаи поиска палиндромных подстрок. Для входа `"abc"` выход содержит все отдельные символы: `{"a", "b", "c"}`. Для входа `"aaa"` выход содержит все возможные палиндромные подстроки: `{"a", "aa", "aaa"}`. Для входа `"racecar"` выход содержит множество палиндромных подстрок, включая отдельные символы, пары символов и полный палиндром: `{"r", "a", "c", "e", "c", "a", "r", "ce", "ace", "racecar", ...}`.

## Реализация на Java

### Подход 1: Грубая сила (Java)

В этом подходе мы просто перебираем входную строку, чтобы найти все подстроки. Заодно проверим, является подстрока палиндромом или нет. В приведённом выше примере мы просто сравниваем подстроку с обратной, чтобы увидеть, является ли она палиндромом. Конечно, мы можем легко выбрать один из нескольких других подходов, которые будут более эффективными.

### Оптимизированная проверка палиндрома

Более эффективная проверка палиндрома использует два указателя, которые движутся навстречу друг другу от концов строки к центру. Это позволяет избежать создания обратной строки и значительно улучшает производительность.

```java
private boolean isPalindrome(String input) {
    int left = 0;
    int right = input.length() - 1;

    while (left < right) {
        if (input.charAt(left) != input.charAt(right)) {
            return false;
        }
        left++;
        right--;
    }

    return true;
}
```

Временная сложность этого подхода составляет `O(n³)`. Хотя это может быть приемлемо для небольших входных строк, нам понадобится более эффективный подход, если мы проверяем палиндромы в больших объёмах текста. Оптимизированная проверка палиндрома улучшает производительность, но общая сложность алгоритма остаётся высокой из-за необходимости проверки всех возможных подстрок.

## Подход 2: Расширение от центра

Идея подхода централизации состоит в том, чтобы рассматривать каждый символ как точку опоры и расширяться в обоих направлениях, чтобы найти палиндромы. Мы расширимся только в том случае, если символы слева и справа совпадают, что сделает строку палиндромом. В противном случае мы переходим к следующему символу.

Давайте посмотрим быструю демонстрацию, в которой мы будем рассматривать каждый символ как центр палиндрома. В приведённом выше цикле мы расширяемся в обоих направлениях, чтобы получить набор всех палиндромов с центром в каждой позиции. Мы найдём палиндромы как чётной, так и нечётной длины, дважды вызвав метод `findPalindromes` в цикле.

```java
private Set<String> findPalindromes(String input, int low, int high) {
    Set<String> result = new HashSet<>();

    while (low >= 0 && high < input.length() && input.charAt(low) == input.charAt(high)) {
        result.add(input.substring(low, high + 1));
        low--;
        high++;
    }

    return result;
}
```

### Визуализация

Для строки `"aba"` алгоритм работает следующим образом. Центр в позиции 1 (нечётная длина): расширяемся от `"b"` `"aba"`. Центр в позиции 0-1 (чётная длина): проверяем `"ab"` не палиндром. Центр в позиции 1-2 (чётная длина): проверяем `"ba"` не палиндром. Временная сложность этого подхода составляет `O(n²)`. Это улучшение по сравнению с нашим подходом грубой силы, но мы можем сделать ещё лучше, как мы увидим в следующем разделе.

## Подход 3: Алгоритм Манахера

Алгоритм Манахера находит самую длинную палиндромную подстроку за линейное время. Мы будем использовать этот алгоритм, чтобы найти все подстроки, являющиеся палиндромами.

### Инициализация

Прежде чем мы углубимся в алгоритм, мы инициализируем несколько переменных. Во-первых, мы защитим входную строку граничным символом в начале и в конце, прежде чем преобразовать результирующую строку в массив символов. Затем мы будем использовать двумерный массив `radius` с двумя строками — одна для хранения длин палиндромов нечётной длины, а другая — для хранения длин палиндромов чётной длины.

### Основной алгоритм

Затем мы пройдёмся по входному массиву, чтобы найти длину палиндрома с центром в позиции `i` и сохраним эту длину в `radius[][]`. Временная сложность этого подхода составляет `O(n)`. Наконец, мы пройдёмся по массиву `radius[][]` для вычисления палиндромных подстрок с центром в каждой позиции.

```java
for (int i = 1; i <= input.length(); i++) {
    for (int j = 0; j <= 1; j++) {
        for (max = radius[j][i]; max > 0; max--) {
            palindromes.add(input.substring(i - max - 1, max + j + i - 1));
        }
    }
}
```

### Особенности алгоритма Манахера

Хотя алгоритм Манахера имеет временную сложность `O(n)`, логика объединения всех палиндромов в множество будет работать за `O(n²)`. Это происходит потому, что метод подстроки каждый раз возвращает новую строку. Снижение производительности аналогично неэффективной конкатенации строк. Поэтому для задач, требующих только подсчёта палиндромных подстрок, рекомендуется использовать упрощённую версию алгоритма.

### Упрощенная версия алгоритма Манахера

Для поиска только количества палиндромных подстрок можно использовать упрощённую версию алгоритма, которая не сохраняет сами подстроки, а только подсчитывает их количество. Это значительно улучшает производительность и снижает использование памяти.

```java
public int countPalindromicSubstrings(String s) {
    int count = 0;

    for (int i = 0; i < s.length(); i++) {
        count += expandAroundCenter(s, i, i);     // Нечетная длина
        count += expandAroundCenter(s, i, i + 1); // Четная длина
    }

    return count;
}

private int expandAroundCenter(String s, int left, int right) {
    int count = 0;

    while (left >= 0 && right < s.length() && s.charAt(left) == s.charAt(right)) {
        count++;
        left--;
        right++;
    }

    return count;
}
```

## Реализация на Kotlin

### Подход 1: Грубая сила (Kotlin)

```kotlin
fun findAllPalindromesBruteForceK(input: String): Set<String> {
    val palindromes = mutableSetOf<String>()

    for (i in input.indices) {
        for (j in i + 1..input.length) {
            val substring = input.substring(i, j)
            if (isPalindromeK(substring)) {
                palindromes.add(substring)
            }
        }
    }

    return palindromes
}

private fun isPalindromeK(input: String): Boolean {
    var left = 0
    var right = input.length - 1

    while (left < right) {
        if (input[left] != input[right]) {
            return false
        }
        left++
        right--
    }

    return true
}
```

### Подход 2: Расширение от центра

```kotlin
fun findAllPalindromesCenterK(input: String): Set<String> {
    val palindromes = mutableSetOf<String>()

    for (i in input.indices) {
        // Нечетная длина
        expandAroundCenterK(input, i, i, palindromes)
        // Четная длина
        expandAroundCenterK(input, i, i + 1, palindromes)
    }

    return palindromes
}

private fun expandAroundCenterK(
    input: String,
    left: Int,
    right: Int,
    palindromes: MutableSet<String>
) {
    var l = left
    var r = right

    while (l >= 0 && r < input.length && input[l] == input[r]) {
        palindromes.add(input.substring(l, r + 1))
        l--
        r++
    }
}
```

### Подсчет палиндромных подстрок

```kotlin
fun countPalindromicSubstringsK(s: String): Int {
    var count = 0

    for (i in s.indices) {
        count += expandAroundCenterCountK(s, i, i)      // Нечетная длина
        count += expandAroundCenterCountK(s, i, i + 1)  // Четная длина
    }

    return count
}

private fun expandAroundCenterCountK(s: String, left: Int, right: Int): Int {
    var count = 0
    var l = left
    var r = right

    while (l >= 0 && r < s.length && s[l] == s[r]) {
        count++
        l--
        r++
    }

    return count
}
```

### Самая длинная палиндромная подстрока

```kotlin
fun longestPalindromeK(s: String): String {
    if (s.isEmpty()) {
        return ""
    }

    var start = 0
    var end = 0

    for (i in s.indices) {
        val len1 = expandAroundCenterLengthK(s, i, i)
        val len2 = expandAroundCenterLengthK(s, i, i + 1)
        val len = maxOf(len1, len2)

        if (len > end - start) {
            start = i - (len - 1) / 2
            end = i + len / 2
        }
    }

    return s.substring(start, end + 1)
}

private fun expandAroundCenterLengthK(s: String, left: Int, right: Int): Int {
    var l = left
    var r = right

    while (l >= 0 && r < s.length && s[l] == s[r]) {
        l--
        r++
    }

    return r - l - 1
}
```

### Функциональный стиль

```kotlin
fun findAllPalindromesFunctionalK(input: String): Set<String> {
    return input.indices.flatMap { i ->
        (i + 1..input.length).mapNotNull { j ->
            val substring = input.substring(i, j)
            if (isPalindromeK(substring)) substring else null
        }
    }.toSet()
}

fun countPalindromicSubstringsFunctionalK(s: String): Int {
    return s.indices.sumOf { i ->
        expandAroundCenterCountK(s, i, i) + expandAroundCenterCountK(s, i, i + 1)
    }
}
```

### Пример использования

```kotlin
fun main() {
    val input = "racecar"

    // Грубая сила
    val palindromes1 = findAllPalindromesBruteForceK(input)
    println(palindromes1) // {r, a, c, e, ace, cec, racecar, ...}

    // Расширение от центра

    println(palindromes2)

    // Подсчет
    println(countPalindromicSubstringsK("abc")) // 3
    println(countPalindromicSubstringsK("aaa")) // 6

}
```

## Сравнение подходов

Сравнение подходов показывает различные характеристики каждого метода. Грубая сила имеет временную сложность `O(n³)` и пространственную сложность `O(n²)`, что делает её подходящей только для малых строк. Расширение от центра имеет временную сложность `O(n²)` и пространственную сложность `O(n²)`, что делает её подходящей для средних строк. Алгоритм Манахера имеет временную сложность `O(n)` и пространственную сложность `O(n)`, что делает его подходящим для больших строк.

## Сложность

### Временная сложность

Временная сложность различных подходов значительно различается. Грубая сила имеет временную сложность `O(n³)` — для каждой подстроки проверяем палиндром, что делает этот подход неэффективным для больших строк. Расширение от центра имеет временную сложность `O(n²)` — для каждого центра расширяемся, что обеспечивает приемлемую производительность для средних строк. Алгоритм Манахера имеет временную сложность `O(n)` — один проход, но сбор результатов `O(n²)`, что делает его наиболее эффективным для больших строк.

### Пространственная сложность

Пространственная сложность также различается между подходами. Грубая сила требует `O(n²)` памяти для хранения всех подстрок, что может быть проблематично для больших строк. Расширение от центра также требует `O(n²)` памяти для хранения всех подстрок. Алгоритм Манахера требует `O(n)` памяти для массива `radius`, что делает его наиболее эффективным по памяти.

## Особенности

Алгоритм Манахера наиболее эффективен по времени выполнения, что делает его предпочтительным выбором для больших строк и задач, требующих высокой производительности. Расширение от центра проще понять и реализовать, что делает его подходящим для начинающих программистов и задач, где простота важнее максимальной производительности. Грубая сила требует больше памяти и времени, но является самым простым для понимания и реализации, что делает её подходящей только для очень малых строк.

## Применение

Поиск палиндромных подстрок используется в различных областях. В обработке текста поиск палиндромных подстрок используется для анализа текстовых данных и поиска интересных паттернов. В анализе ДНК палиндромные подстроки используются для идентификации важных последовательностей нуклеотидов. В криптографии палиндромные подстроки используются для создания и анализа шифров. В задачах на собеседованиях поиск палиндромных подстрок является популярной задачей для проверки навыков программирования. В поиске паттернов палиндромные подстроки используются для идентификации повторяющихся структур в данных.

## Варианты задачи

### Вариант 1: Самая длинная палиндромная подстрока

```java
public String longestPalindrome(String s) {
    if (s == null || s.length() < 1) {
        return "";
    }

    int start = 0, end = 0;

    for (int i = 0; i < s.length(); i++) {
        int len1 = expandAroundCenter(s, i, i);
        int len2 = expandAroundCenter(s, i, i + 1);
        int len = Math.max(len1, len2);

        if (len > end - start) {
            start = i - (len - 1) / 2;
            end = i + len / 2;
        }
    }

    return s.substring(start, end + 1);
}

private int expandAroundCenter(String s, int left, int right) {
    while (left >= 0 && right < s.length() && s.charAt(left) == s.charAt(right)) {
        left--;
        right++;
    }
    return right - left - 1;
}
```

### Вариант 2: Количество палиндромных подстрок

```java
public int countSubstrings(String s) {
    int count = 0;

    for (int i = 0; i < s.length(); i++) {
        count += countPalindromes(s, i, i);     // Нечетная длина
        count += countPalindromes(s, i, i + 1); // Четная длина
    }

    return count;
}

private int countPalindromes(String s, int left, int right) {
    int count = 0;

    while (left >= 0 && right < s.length() && s.charAt(left) == s.charAt(right)) {
        count++;
        left--;
        right++;
    }

    return count;
}
```

## Когда использовать

Используйте грубую силу, когда строки очень короткие и нужна простота реализации. Этот подход подходит, когда производительность не критична и важнее простота кода. Грубая сила также может быть полезна для обучения и понимания базовых концепций поиска палиндромных подстрок.

Используйте расширение от центра, когда работаете со средними строками и нужен баланс между простотой и эффективностью. Этот подход подходит, когда не нужна максимальная производительность, но важно иметь эффективное решение. Расширение от центра обеспечивает хороший компромисс между сложностью реализации и производительностью.

Используйте алгоритм Манахера, когда работаете с большими строками и нужна максимальная производительность. Этот подход подходит, когда важна временная сложность и требуется оптимальное решение. Алгоритм Манахера обеспечивает линейную временную сложность, что делает его предпочтительным выбором для больших объёмов данных.

## Лучшие практики

Выбор подхода зависит от конкретных требований задачи. Для подсчёта или перечисления всех палиндромных подстрок предпочтите «расширение от центра» (`O(n²)`) — проще, чем Манахер. Для одной самой длинной подстроки подойдёт и расширение от центра, и Манахер. Это позволяет выбрать оптимальное решение в зависимости от требований задачи.

Проверка палиндрома должна быть эффективной. В цикле используйте два указателя (`left`/`right`), сходящихся к центру. Не создавайте обратную строку через `StringBuilder.reverse()` в горячем цикле — это лишние аллокации, которые значительно снижают производительность.

Хранение результатов требует правильного выбора структуры данных. Используйте `Set<String>` для уникальных подстрок. Если нужен только счётчик, накапливайте счётчик в методе расширения, без сохранения подстрок. Это значительно улучшает производительность и снижает использование памяти.

Граничные случаи должны быть тщательно обработаны. Пустая строка — 0 подстрок. Один символ — одна подстрока-палиндром. Чётная и нечётная длина обрабатываются двумя вызовами расширения (центр `i,i` и `i,i+1`). Это гарантирует корректную работу алгоритма во всех возможных ситуациях.

Тестирование должно покрывать все граничные случаи. Проверьте строки `"a"`, `"aa"`, `"aba"`, `"abc"`, `"aaa"`, а также строки с одной самой длинной палиндромной подстрокой. Это гарантирует корректную работу алгоритма во всех возможных ситуациях.

## Решение проблем

При работе с поиском палиндромных подстрок могут возникать различные проблемы. Если алгоритм работает медленно, убедитесь, что вы используете правильный подход для размера входных данных. Для больших строк используйте алгоритм Манахера или расширение от центра вместо грубой силы. Если возникают проблемы с памятью, рассмотрите возможность использования упрощённой версии алгоритма, которая только подсчитывает палиндромные подстроки без их сохранения.

Проблемы с корректностью результатов могут возникать при неправильной обработке граничных случаев. Убедитесь, что вы правильно обрабатываете пустые строки, строки из одного символа и строки с чётной и нечётной длиной палиндромов. Также проверьте правильность обработки символов на границах строки.

Проблемы с производительностью часто связаны с созданием большого количества временных объектов. Избегайте создания обратных строк в циклах и используйте два указателя для проверки палиндромов. Также минимизируйте количество операций со строками, используя индексы вместо создания подстрок.

## Частые вопросы

**Какой подход лучше использовать для поиска палиндромных подстрок?** Выбор подхода зависит от размера входных данных и требований к производительности. Для малых строк используйте грубую силу. Для средних строк используйте расширение от центра. Для больших строк используйте алгоритм Манахера.

**Как оптимизировать производительность алгоритма?** Используйте два указателя для проверки палиндромов вместо создания обратных строк. Минимизируйте количество операций со строками. Если нужен только подсчёт, используйте упрощённую версию алгоритма без сохранения подстрок.

**Как обрабатывать различные длины палиндромов?** Используйте два вызова метода расширения для каждой позиции: один для палиндромов нечётной длины (центр `i,i`) и один для палиндромов чётной длины (центр `i,i+1`). Это гарантирует нахождение всех возможных палиндромных подстрок.

**Когда использовать алгоритм Манахера?** Используйте алгоритм Манахера для больших строк, когда важна максимальная производительность. Алгоритм обеспечивает линейную временную сложность, что делает его предпочтительным выбором для больших объёмов данных.

## Глоссарий терминов

**Палиндром** — строка, которая читается одинаково слева направо и справа налево. В контексте поиска палиндромных подстрок палиндромы могут иметь различную длину и начинаться с различных позиций в строке.

**Расширение от центра** — подход к поиску палиндромов, при котором каждый символ рассматривается как центр палиндрома, и алгоритм расширяется в обоих направлениях, пока символы совпадают.

**Алгоритм Манахера** — алгоритм для поиска самой длинной палиндромной подстроки за линейное время. Алгоритм использует информацию о ранее найденных палиндромах для оптимизации поиска.

**Грубая сила** — простой подход к решению задачи, при котором проверяются все возможные варианты. В контексте поиска палиндромных подстрок грубая сила проверяет все возможные подстроки на палиндромность.

**Подстрока** — последовательность символов, извлечённая из исходной строки. В контексте поиска палиндромных подстрок подстрока может начинаться с любой позиции и иметь различную длину.
