# Проверка панграммы (Pangram Check)

Панграмма — это любая строка, содержащая все буквы заданного набора алфавитов хотя бы один раз. Рассматриваются различные подходы для проверки панграмм: с использованием массива, `Stream API`, и проверка идеальных панграмм. Каждый подход имеет свои преимущества и применяется в зависимости от требований приложения, необходимости производительности и стиля программирования.

## Описание алгоритма

В этом уроке мы научимся проверять, является ли данная строка допустимой панграммой или нет, используя простую программу `Java`. Панграмма — это любая строка, содержащая все буквы заданного набора алфавитов хотя бы один раз. Панграммы применимы не только к английскому языку, но и к любому другому языку, имеющему фиксированный набор символов.

### Примеры

Например, общеизвестная английская панграмма звучит так: «Быстрая коричневая лиса перепрыгивает через ленивую собаку». Точно так же они доступны и на других языках. Примеры панграмм включают `"The quick brown fox jumps over the lazy dog"` и `"Two driven jocks help fax my big quiz"`, которые содержат все буквы английского алфавита. Примером строки, которая не является панграммой, является `"Hello world"`, так как в ней отсутствуют многие буквы алфавита.

## Реализация на Java

### Подход 1: Использование массива (Java)

Во-первых, давайте попробуем цикл **for**. Мы заполним логический массив маркерами для каждого символа алфавита.

**Код возвращает **true**, когда все значения в массиве маркеров установлены в **true**:**

```java
// Проверка панграммы: массив флагов для каждой буквы алфавита, один проход по строке.
private static final int ALPHABET_COUNT = 26;

public static boolean isPangram(String str) {
    if (str == null) {
        return false;
    }
    // Массив маркеров: true, если буква встретилась хотя бы раз
    Boolean[] alphabetMarker = new Boolean[ALPHABET_COUNT];
    Arrays.fill(alphabetMarker, false);

    int alphabetIndex = 0;
    str = str.toUpperCase();

    for (int i = 0; i < str.length(); i++) {
        // Учитываем только латинские буквы A–Z
        if ('A' <= str.charAt(i) && str.charAt(i) <= 'Z') {
            alphabetIndex = str.charAt(i) - 'A';
            alphabetMarker[alphabetIndex] = true;
        }
    }

    for (boolean index : alphabetMarker) {
        if (!index) {
            return false;
        }
    }

    return true;
}
```

### Проверка

Проверим нашу реализацию, чтобы убедиться в её корректности. Тестирование должно покрывать различные случаи, включая валидные панграммы, невалидные строки и граничные случаи.

### Альтернативная версия с Set

Альтернативная версия использует `Set` для хранения найденных букв. Этот подход более гибкий и читаемый, но может быть немного менее эффективным по памяти по сравнению с массивом.

```java
public static boolean isPangramWithSet(String str) {
    if (str == null) {
        return false;
    }

    Set<Character> alphabetSet = new HashSet<>();
    str = str.toUpperCase();

    for (char c : str.toCharArray()) {
        if (c >= 'A' && c <= 'Z') {
            alphabetSet.add(c);
        }
    }

    return alphabetSet.size() == ALPHABET_COUNT;
}
```

## Подход 2: Использование Stream API

Альтернативный подход предполагает использование `Java Streams API`. Мы можем создать отфильтрованный поток символов из данного входного текста и создать карту алфавита, используя этот поток. Код возвращает успех, если размер карты равен размеру алфавита. Для английского языка ожидаемый размер равен 26. И, конечно же, протестируем реализацию, чтобы убедиться в её корректности.

### Улучшенная версия с Stream

Улучшенная версия использует более эффективный подход с `Stream`, который использует `distinct()` для получения уникальных букв и `count()` для подсчёта их количества. Это делает код более читаемым и эффективным.

```java
public static boolean isPangramStreamImproved(String str) {
    if (str == null) {
        return false;
    }

    long distinctLetters = str.toUpperCase()
        .chars()
        .filter(c -> c >= 'A' && c <= 'Z')
        .distinct()
        .count();

    return distinctLetters == ALPHABET_COUNT;
}
```

## Идеальная панграмма

Идеальная панграмма немного отличается от обычной панграммы. Идеальная панграмма состоит из каждой буквы алфавита ровно один раз, в отличие от по крайней мере одного раза для панграммы. Код возвращает значение `true`, когда размер карты равен размеру алфавита, а частота каждого символа в алфавите равна единице. И давайте тестировать реализацию, чтобы убедиться в её корректности.

В идеальной панграмме каждый символ должен быть ровно один раз. Итак, наша предыдущая панграмма должна потерпеть неудачу, так как в приведённом выше коде заданная строка ввода имеет несколько дубликатов, например, два `o`. Следовательно, вывод является ложным.

### Альтернативная реализация идеальной панграммы

```java
public static boolean isPerfectPangramImproved(String str) {
    if (str == null) {
        return false;
    }

    Map<Character, Integer> frequency = new HashMap<>();
    str = str.toUpperCase();

    for (char c : str.toCharArray()) {
        if (c >= 'A' && c <= 'Z') {
            frequency.put(c, frequency.getOrDefault(c, 0) + 1);
        }
    }

    if (frequency.size() != ALPHABET_COUNT) {
        return false;
    }

    return frequency.values().stream().allMatch(count -> count == 1);
}
```

## Реализация на Kotlin

### Подход 1: Использование массива (Kotlin)

```kotlin
private const val ALPHABET_COUNT = 26

fun isPangramK(str: String?): Boolean {
    if (str == null) {
        return false
    }

    val alphabetMarker = BooleanArray(ALPHABET_COUNT) { false }
    val upperStr = str.uppercase()

    for (char in upperStr) {
        if (char in 'A'..'Z') {
            val alphabetIndex = char - 'A'
            alphabetMarker[alphabetIndex] = true
        }
    }

    return alphabetMarker.all { it }
}
```

### Подход 2: Использование Set

```kotlin
fun isPangramWithSetK(str: String?): Boolean {
```

### Функциональный стиль

```kotlin
fun isPangramFunctionalK(str: String?): Boolean {
    if (str == null) {
        return false
    }

    return str.uppercase()
        .filter { it in 'A'..'Z' }
        .toSet()
        .size == ALPHABET_COUNT
}
```

### Идеальная панграмма

```kotlin
fun isPerfectPangramK(str: String?): Boolean {
    if (str == null) {
        return false
    }

    val frequency = mutableMapOf<Char, Int>()
    val upperStr = str.uppercase()

    for (char in upperStr) {
        if (char in 'A'..'Z') {
            frequency[char] = frequency.getOrDefault(char, 0) + 1
        }
    }

    if (frequency.size != ALPHABET_COUNT) {
        return false
    }

    return frequency.values.all { it == 1 }
}
```

### Найти недостающие буквы

```kotlin
fun findMissingLettersK(str: String?): List<Char> {
    if (str == null) {
        return emptyList()
    }

    val foundLetters = str.uppercase()
        .filter { it in 'A'..'Z' }
        .toSet()

    return ('A'..'Z').filter { it !in foundLetters }
}
```

### Пример использования

```kotlin
fun main() {
    val pangram = "The quick brown fox jumps over the lazy dog"
    val notPangram = "Hello world"

    // Проверка панграммы
    println(isPangramK(pangram)) // true
    println(isPangramK(notPangram)) // false

    // Функциональный стиль
    println(isPangramFunctionalK(pangram)) // true

    // Идеальная панграмма
    println(isPerfectPangramK(pangram)) // false (есть дубликаты)

    // Найти недостающие буквы
    val missing = findMissingLettersK(notPangram)
    println(missing) // [A, B, C, D, E, F, G, H, I, J, K, L, M, N, P, Q, R, S, T, U, V, X, Y, Z]
}
```

## Сравнение подходов

Сравнение подходов показывает различные характеристики каждого метода. Массив имеет высокую простоту и производительность, но среднюю читаемость. `Set` имеет среднюю простоту, высокую производительность и высокую читаемость. `Stream API` имеет среднюю простоту и производительность, но высокую читаемость. Выбор конкретного подхода зависит от требований приложения и стиля программирования.

## Сложность

### Временная сложность

Временная сложность всех подходов составляет `O(n)`, где `n` — длина строки. Массив и `Set` требуют одного прохода по строке для проверки всех букв. `Stream API` также требует один проход по строке, что делает все подходы эффективными для большинства практических применений.

### Пространственная сложность

Пространственная сложность всех подходов составляет `O(1)` — константная память. Массив имеет фиксированный размер 26 элементов. `Set` требует максимум 26 элементов для хранения найденных букв. `Stream API` требует максимум 26 элементов для `Map`, что делает все подходы эффективными по памяти.

## Особенности

Все подходы эффективны и подходят для проверки панграмм. Массив подход самый простой для понимания и реализации, что делает его подходящим для начинающих программистов. `Stream API` наиболее гибкий и позволяет легко адаптировать алгоритм для различных требований, что делает его предпочтительным для функционального стиля программирования.

## Применение

Проверка панграмм используется в различных областях. В обработке текста проверка панграмм используется для анализа текстовых данных и определения полноты использования алфавита. В валидации данных проверка панграмм используется для проверки корректности входных данных и обеспечения полноты информации. В играх и головоломках панграммы используются для создания интересных заданий и проверки знаний алфавита. В тестировании клавиатур проверка панграмм используется для проверки работоспособности всех клавиш клавиатуры. В лингвистических исследованиях панграммы используются для изучения особенностей различных языков и алфавитов.

## Варианты задачи

### Вариант 1: Панграмма с учетом регистра

```java
public static boolean isPangramCaseSensitive(String str) {
    if (str == null) {
        return false;
    }

    Set<Character> upperCase = new HashSet<>();
    Set<Character> lowerCase = new HashSet<>();

    for (char c : str.toCharArray()) {
        if (c >= 'A' && c <= 'Z') {
            upperCase.add(c);
        } else if (c >= 'a' && c <= 'z') {
            lowerCase.add((char) (c - 'a' + 'A'));
        }
    }

    return upperCase.size() == ALPHABET_COUNT ||
           lowerCase.size() == ALPHABET_COUNT;
}
```

### Вариант 2: Панграмма для другого алфавита

```java
public static boolean isPangramForAlphabet(String str, String alphabet) {
    if (str == null || alphabet == null) {
        return false;
    }

    Set<Character> alphabetSet = new HashSet<>();
    for (char c : alphabet.toCharArray()) {
        alphabetSet.add(Character.toUpperCase(c));
    }

    Set<Character> foundLetters = new HashSet<>();
    str = str.toUpperCase();

    for (char c : str.toCharArray()) {
        if (alphabetSet.contains(c)) {
            foundLetters.add(c);
        }
    }

    return foundLetters.size() == alphabetSet.size();
}
```

### Вариант 3: Найти недостающие буквы

```java
public static List<Character> findMissingLetters(String str) {
    if (str == null) {
        return Collections.emptyList();
    }

    Set<Character> foundLetters = new HashSet<>();
    str = str.toUpperCase();

    for (char c : str.toCharArray()) {
        if (c >= 'A' && c <= 'Z') {
            foundLetters.add(c);
        }
    }

    List<Character> missing = new ArrayList<>();
    for (char c = 'A'; c <= 'Z'; c++) {
        if (!foundLetters.contains(c)) {
            missing.add(c);
        }
    }

    return missing;
}
```

## Когда использовать

Используйте массив, когда нужна максимальная производительность и простота важна. Массив особенно подходит, когда работаете с английским алфавитом, так как размер алфавита фиксирован и известен заранее. Этот подход обеспечивает оптимальную производительность и минимальное использование памяти.

Используйте `Set`, когда нужна гибкость и важна читаемость кода. `Set` особенно подходит, когда работаете с разными алфавитами, так как позволяет легко адаптировать алгоритм для различных наборов символов. Этот подход обеспечивает хороший баланс между производительностью и гибкостью.

Используйте `Stream API`, когда нужна функциональная парадигма и работаете с `Java` 8+. `Stream API` особенно подходит, когда нужна цепочка операций, что позволяет создавать более выразительный и читаемый код. Этот подход обеспечивает высокую гибкость и поддерживает функциональный стиль программирования.

## Лучшие практики

Выбор подхода зависит от конкретных требований. Массив маркеров имеет временную сложность `O(n)` и пространственную сложность `O(1)` по дополнительной памяти (26 булевых значений). `Stream API` читаемо, но создаёт объекты, что может быть проблематично для больших объёмов данных. Для латинского алфавита достаточно 26 символов, что делает массив эффективным выбором.

Null и пустая строка требуют явной обработки. Явно обрабатывайте `null` (возвращать `false` или по контракту). Пустая строка — не панграмма (нет ни одной буквы). Это гарантирует корректное поведение алгоритма во всех возможных случаях.

Регистр символов требует нормализации перед проверкой. Приводите к одному регистру (`toUpperCase`/`toLowerCase`) перед проверкой, чтобы `A` и `a` считались одной буквой. Это гарантирует корректную работу алгоритма независимо от регистра входных данных.

Алфавит может различаться в зависимости от языка. Для латиницы — 26 букв. Для других алфавитов задайте размер и диапазон символов. При необходимости поддерживайте юникод (кодовые точки), что позволяет работать с различными языками и системами письменности.

Тестирование должно покрывать все граничные случаи. Проверяйте граничные случаи (одна буква 26 раз, идеальная панграмма, строка с пробелами и знаками препинания). Это гарантирует корректную работу алгоритма во всех возможных ситуациях.

## Решение проблем

При работе с проверкой панграмм могут возникать различные проблемы. Если алгоритм не находит панграмму в валидной строке, убедитесь, что вы правильно обрабатываете регистр символов и фильтруете только буквы алфавита. Если возникают проблемы с производительностью, рассмотрите возможность использования массива вместо `Set` или `Stream API`, так как массив обеспечивает оптимальную производительность.

Проблемы с обработкой различных алфавитов могут возникать при использовании массива, так как размер массива фиксирован. В таких случаях рекомендуется использовать `Set` или `Stream API`, которые позволяют работать с алфавитами различного размера. Также убедитесь, что вы правильно определяете диапазон символов для конкретного алфавита.

Проблемы с идеальными панграммами могут возникать при неправильной проверке частоты символов. Убедитесь, что вы проверяете не только наличие всех букв алфавита, но и то, что каждая буква встречается ровно один раз. Это критически важно для корректной работы алгоритма проверки идеальных панграмм.

## Частые вопросы

**Какой подход лучше использовать для проверки панграмм?** Выбор подхода зависит от конкретных требований. Массив обеспечивает максимальную производительность и подходит для английского алфавита. `Set` обеспечивает хороший баланс между производительностью и гибкостью. `Stream API` подходит для функционального стиля программирования.

**Как обрабатывать различные алфавиты?** Для различных алфавитов используйте `Set` или `Stream API`, которые позволяют работать с алфавитами различного размера. Определите диапазон символов для конкретного алфавита и адаптируйте алгоритм соответственно.

**Как проверить идеальную панграмму?** Идеальная панграмма требует проверки не только наличия всех букв алфавита, но и того, что каждая буква встречается ровно один раз. Используйте `Map` для подсчёта частоты каждого символа и проверьте, что все частоты равны единице.

**Как обрабатывать регистр символов?** Приводите все символы к одному регистру перед проверкой, используя `toUpperCase()` или `toLowerCase()`. Это гарантирует, что `A` и `a` считаются одной буквой.

## Глоссарий терминов

**Панграмма** — строка, содержащая все буквы заданного алфавита хотя бы один раз. Панграммы используются в различных областях, включая обработку текста, валидацию данных и лингвистические исследования.

**Идеальная панграмма** — панграмма, в которой каждая буква алфавита встречается ровно один раз. Идеальные панграммы более редки, чем обычные панграммы, и требуют более строгой проверки.

**Алфавит** — набор символов, используемых в системе письменности. В контексте проверки панграмм алфавит определяет набор букв, которые должны присутствовать в строке.

**Массив маркеров** — массив булевых значений, используемый для отслеживания найденных букв алфавита. Каждый элемент массива соответствует одной букве алфавита и указывает, была ли эта буква найдена в строке.

**Set** — структура данных, которая хранит уникальные элементы. В контексте проверки панграмм `Set` используется для хранения найденных букв алфавита без дубликатов.

В системах валидации данных проверка панграмм используется для проверки корректности входных данных и обеспечения полноты информации, что критически важно для надёжности приложений.
