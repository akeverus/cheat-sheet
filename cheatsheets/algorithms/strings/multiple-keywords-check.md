Каждый подход имеет свои преимущества и применяется в зависимости от количества ключевых слов, размера текста и требований к производительности.

## Описание алгоритма

В этом кратком руководстве мы узнаем, как обнаружить несколько слов внутри строки. Предположим, у нас есть строка `"hello there, Baeldung"`. Наша задача — найти, содержит ли `inputString` слова `"hello"` и `"Baeldung"`. Итак, давайте поместим наши ключевые слова в массив. Кроме того, порядок слов не важен, и совпадения должны быть чувствительны к регистру, что означает, что `"Hello"` и `"hello"` считаются разными словами.

## Реализация на Java

### Подход 1: String.contains() (Java)

Для начала мы покажем, как использовать метод `String.contains()` для достижения нашей цели. Давайте перейдём к массиву ключевых слов и проверим наличие каждого элемента внутри `inputString`. Метод `contains()` вернёт `true`, если `inputString` содержит данный элемент. Когда у нас нет ни одного из ключевых слов внутри нашей строки, мы можем прекратить движение вперёд и немедленно вернуть `false`. Несмотря на то, что нам нужно написать больше кода, это решение работает быстро для простых случаев использования.

### Улучшенная версия

```java
public static boolean containsWordsImproved(String inputString, String[] items) {
    for (String item : items) {
        if (!inputString.contains(item)) {
            return false;
        }
    }
    return true;
}
```

## Подход 2: String.indexOf()

Подобно решению, использующему метод `String.contains()`, мы можем проверить индексы ключевых слов с помощью метода `String.indexOf()`. Для этого нам нужен метод, принимающий `inputString` и список ключевых слов. Метод `indexOf()` возвращает индекс слова внутри `inputString`. Когда у нас нет слова в тексте, индекс будет равен -1, что позволяет легко определить отсутствие ключевого слова в строке.

### Альтернативная версия

```java
public static boolean containsWordsIndexOfImproved(String inputString, String[] words) {
    for (String word : words) {
        if (inputString.indexOf(word) == -1) {
            return false;
        }
    }
    return true;
}
```

## Подход 3: Регулярные выражения

Теперь давайте используем регулярное выражение для сопоставления наших слов. Для этого мы будем использовать класс `Pattern`. Во-первых, давайте определим строковое выражение. Поскольку нам нужно сопоставить два ключевых слова, мы построим наше правило регулярного выражения с двумя прогнозами. После этого мы будем использовать метод `matcher()` для поиска вхождений. Но у регулярных выражений есть издержки производительности. Если у нас есть несколько слов для поиска, производительность этого решения может быть не оптимальной, так как регулярные выражения требуют компиляции и могут быть медленнее простых методов поиска.

### Экранирование специальных символов

```java
public static boolean containsWordsPatternMatchEscaped(String inputString, String[] words) {
    StringBuilder regexp = new StringBuilder();

    for (String word : words) {
        regexp.append("(?=.*").append(Pattern.quote(word)).append(")");
    }

    Pattern pattern = Pattern.compile(regexp.toString());
    return pattern.matcher(inputString).find();
}
```

## Подход 4: Stream API

И, наконец, мы можем использовать `Stream API Java` 8. Но сначала давайте сделаем небольшие преобразования с нашими исходными данными. Теперь пришло время использовать `Stream API`. Приведённый выше конвейер операций вернёт `true`, если входная строка содержит все наши ключевые слова.

В качестве альтернативы мы можем просто использовать метод `containsAll()` фреймворка `Collections` для достижения желаемого результата. Однако этот метод работает только для целых слов. Таким образом, он найдёт наши ключевые слова, только если они разделены пробелом в тексте, что ограничивает его применение.

### Улучшенная версия Stream API

Улучшенная версия `Stream API` использует прямой вызов `contains()` для каждого ключевого слова, что делает код более читаемым и эффективным. Этот подход не требует предварительного разбиения строки на слова и работает с подстроками, что делает его более универсальным.

```java
public static boolean containsWordsStreamImproved(String inputString, String[] words) {
    return Arrays.stream(words)
        .allMatch(inputString::contains);
}
```

## Подход 5: Алгоритм Ахо-Корасика

Проще говоря, алгоритм Ахо-Корасика предназначен для поиска текста по нескольким ключевым словам. Он имеет временную сложность `O(n)` независимо от того, сколько ключевых слов мы ищем или какова длина текста. Давайте включим зависимость алгоритма Ахо-Корасика в наш `pom.xml`.

Во-первых, давайте создадим конвейер `trie` с массивом ключевых слов `words`. Для этого мы будем использовать структуру данных `Trie`. После этого вызовем метод парсера с текстом `inputString`, в котором мы хотели бы найти ключевые слова, и сохраним результаты в коллекции `emits`. И, наконец, если мы напечатаем наши результаты, для каждого ключевого слова мы увидим начальную позицию ключевого слова в тексте, конечную позицию и само ключевое слово.

Наконец, давайте посмотрим на полную реализацию. В этом примере мы ищем только целые слова. Итак, если мы хотим сопоставить не только `inputString`, но и `"helloBaeldung"`, мы должны просто удалить атрибут `onlyWholeWords()` из конвейера построителя `Trie`. Кроме того, имейте в виду, что мы также удаляем повторяющиеся элементы из коллекции `emits`, поскольку для одного и того же ключевого слова может быть несколько совпадений.

### Улучшенная версия

```java
public static boolean containsWordsAhoCorasickImproved(String inputString, String[] words) {
    Trie trie = Trie.builder().addKeywords(words).build();
    Collection<Emit> emits = trie.parseText(inputString);

    Set<String> foundWords = emits.stream()
        .map(Emit::getKeyword)
        .collect(Collectors.toSet());

    return foundWords.size() == words.length;
}
```

```kotlin
fun containsWordsRegexK(inputString: String, words: Array<String>): Boolean {

    return pattern.toRegex().containsMatchIn(inputString)
```

```kotlin
fun containsWordsFunctionalK(inputString: String, words: Array<String>): Boolean {

}

// С учетом регистра
fun containsWordsCaseInsensitiveK(inputString: String, words: Array<String>): Boolean {
    val lowerInput = inputString.lowercase()
```

### Подсчет вхождений

```kotlin
fun countWordOccurrencesK(inputString: String, words: Array<String>): Map<String, Int> {
    return words.associateWith { word ->
        var count = 0
        var index = 0
        while (true) {
            index = inputString.indexOf(word, index)
            if (index == -1) break
            count++
            index += word.length
        }
        count
    }
}
```

### Поиск позиций

```kotlin
fun findWordPositionsK(inputString: String, words: Array<String>): Map<String, List<Int>> {
    return words.associateWith { word ->
        val positions = mutableListOf<Int>()
        var index = 0
        while (true) {
            index = inputString.indexOf(word, index)
            if (index == -1) break
            positions.add(index)
            index += word.length
        }
        positions
    }
}
```

## Сравнение подходов

Сравнение подходов показывает различные характеристики каждого метода. `String.contains()` имеет временную сложность `O(n*m)` и пространственную сложность `O(1)`, что делает его подходящим для небольшого количества слов. `String.indexOf()` имеет аналогичные характеристики и также подходит для небольшого количества слов. Регулярные выражения имеют временную сложность `O(n*m)` и пространственную сложность `O(m)`, что делает их подходящими для сложных паттернов. `Stream API` имеет временную сложность `O(n*m)` и пространственную сложность `O(k)`, что делает его подходящим для функционального стиля. Ахо-Корасик имеет временную сложность `O(n)` и пространственную сложность `O(m)`, что делает его подходящим для множества ключевых слов. Где `n` — длина текста, `m` — длина ключевого слова, `k` — количество ключевых слов.

## Сложность

### Временная сложность

Временная сложность различных подходов зависит от количества ключевых слов и размера текста. `String.contains()`/`indexOf()` имеют временную сложность `O(n*m*k)`, где `n` — длина текста, `m` — средняя длина слова, `k` — количество слов. Регулярные выражения имеют временную сложность `O(n*m*k)` — может быть медленнее из-за накладных расходов на компиляцию и выполнение регулярных выражений. `Stream API` имеет временную сложность `O(n*m*k)` — аналогично `contains()`. Ахо-Корасик имеет временную сложность `O(n + m*k)` — эффективен для множества ключевых слов, так как строит структуру данных один раз и затем выполняет поиск за линейное время.

### Пространственная сложность

Пространственная сложность также различается между подходами. `String.contains()`/`indexOf()` требуют только константной памяти `O(1)`, что делает их наиболее эффективными по памяти. Регулярные выражения требуют `O(m)` памяти для хранения паттерна. `Stream API` требует `O(k)` памяти для списка слов. Ахо-Корасик требует `O(m*k)` памяти для построения `trie`, что может быть значительным для большого количества ключевых слов.

## Особенности

`String.contains()` самый простой для понимания и реализации, что делает его подходящим для начинающих программистов и простых случаев использования. Ахо-Корасик наиболее эффективен для множества слов, так как обеспечивает линейную временную сложность независимо от количества ключевых слов. Регулярные выражения наиболее гибкие и позволяют создавать сложные паттерны для поиска, что делает их подходящими для задач, требующих сложной логики поиска.

## Применение

Проверка нескольких ключевых слов используется в различных областях. В поиске в тексте проверка нескольких ключевых слов используется для нахождения документов, содержащих определённые термины. В фильтрации контента проверка ключевых слов используется для автоматической модерации и фильтрации нежелательного контента. В анализе документов проверка ключевых слов используется для категоризации и индексации документов. В мониторинге проверка ключевых слов используется для отслеживания определённых событий и паттернов в логах и данных. В `NLP` (обработка естественного языка) проверка ключевых слов используется для анализа текста и извлечения информации.

## Варианты задачи

### Вариант 1: Проверка с учетом регистра

```java
public static boolean containsWordsCaseInsensitive(String inputString, String[] words) {
    String lowerInput = inputString.toLowerCase();
    return Arrays.stream(words)
        .map(String::toLowerCase)
        .allMatch(lowerInput::contains);
}
```

### Вариант 2: Подсчет вхождений

```java
public static Map<String, Integer> countWordOccurrences(String inputString, String[] words) {
    Map<String, Integer> counts = new HashMap<>();

    for (String word : words) {
        int count = 0;
        int index = 0;
        while ((index = inputString.indexOf(word, index)) != -1) {
            count++;
            index += word.length();
        }
        counts.put(word, count);
    }

    return counts;
}
```

### Вариант 3: Поиск позиций

```java
public static Map<String, List<Integer>> findWordPositions(String inputString, String[] words) {
    Map<String, List<Integer>> positions = new HashMap<>();

    for (String word : words) {
        List<Integer> wordPositions = new ArrayList<>();
        int index = 0;
        while ((index = inputString.indexOf(word, index)) != -1) {
            wordPositions.add(index);
            index += word.length();
        }
        positions.put(word, wordPositions);
    }

    return positions;
}
```

## Когда использовать

Используйте `String.contains()`, когда работаете с небольшим количеством ключевых слов и нужна простота реализации. Этот подход подходит, когда производительность не критична и важнее читаемость кода. `String.contains()` обеспечивает простой и понятный способ проверки наличия ключевых слов в строке.

Используйте регулярные выражения, когда нужны сложные паттерны и гибкость в поиске. Этот подход подходит, когда работаете с паттернами и требуется сложная логика поиска. Регулярные выражения позволяют создавать мощные паттерны для поиска, но могут быть медленнее простых методов.

Используйте Ахо-Корасик, когда работаете с множеством ключевых слов и нужна максимальная производительность. Этот подход подходит, когда выполняются частые поиски и важно обеспечить оптимальную производительность. Алгоритм Ахо-Корасика обеспечивает линейную временную сложность независимо от количества ключевых слов.

## Лучшие практики

Граничные случаи требуют тщательной обработки. Проверяйте `null` для строки и массива слов; пустой массив слов трактуйте как «все найдены» или явно оговорите контракт (например, возвращать `false`). Это гарантирует корректное поведение алгоритма во всех возможных случаях.

Регистр символов требует нормализации при необходимости нечувствительного поиска. Приводите строку и ключевые слова к одному регистру (`toLowerCase`/`toUpperCase`) до сравнения или используйте `Pattern.CASE_INSENSITIVE`. Это гарантирует корректную работу алгоритма независимо от регистра входных данных.

Экранирование в `regex` критически важно при работе с пользовательским вводом. При сборке регулярного выражения из пользовательских слов используйте `Pattern.quote(word)`, чтобы спецсимволы (`.`, `*`, `[`, `]`) не ломали паттерн. Это предотвращает ошибки при работе с пользовательским вводом, содержащим специальные символы регулярных выражений.

Производительность зависит от количества ключевых слов. Для 1–3 слов достаточно цикла с `String.contains()` или `indexOf`; при десятках/сотнях ключевых слов и большом тексте предпочтите алгоритм Ахо-Корасика (`O(n+m+k)`). Это позволяет выбрать оптимальное решение в зависимости от конкретных требований задачи.

Целые слова требуют особого внимания при использовании Ахо-Корасика. При использовании Ахо-Корасика `onlyWholeWords()` исключает вхождения внутри других слов; для подстрок уберите этот вызов. Это позволяет контролировать, должны ли ключевые слова быть целыми словами или могут быть подстроками.

## Решение проблем

При работе с проверкой нескольких ключевых слов могут возникать различные проблемы. Если алгоритм не находит ключевые слова в валидной строке, убедитесь, что вы правильно обрабатываете регистр символов и экранируете специальные символы в регулярных выражениях. ## Частые вопросы

**Какой подход лучше использовать для проверки нескольких ключевых слов?** Выбор подхода зависит от количества ключевых слов и требований к производительности. Для небольшого количества слов (1–3) используйте `String.contains()` или `indexOf()`. Для большого количества слов используйте алгоритм Ахо-Корасика.

**Как обрабатывать регистр символов?** Приводите строку и ключевые слова к одному регистру перед сравнением, используя `toLowerCase()` или `toUpperCase()`. Альтернативно используйте `Pattern.CASE_INSENSITIVE` для регулярных выражений.

**Как оптимизировать производительность?** Для большого количества ключевых слов используйте алгоритм Ахо-Корасика, который обеспечивает линейную временную сложность. Для небольшого количества слов используйте простые методы `contains()` или `indexOf()`.

**Как обрабатывать специальные символы в регулярных выражениях?** Используйте `Pattern.quote()` для экранирования специальных символов в пользовательском вводе. Это предотвращает ошибки при работе с пользовательским вводом, содержащим специальные символы регулярных выражений.
