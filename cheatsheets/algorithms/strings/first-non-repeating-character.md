# Первый неповторяющийся символ (`First Non-Repeating Character`)
Поиск первого неповторяющегося символа в строке — классическая задача обработки строк, которая имеет множество практических применений. В этом документе рассматриваются различные подходы к решению этой задачи: наивный алгоритм с двойным циклом, использование `HashMap` для подсчёта частот символов, и оптимизация с массивом фиксированного размера для ограниченных алфавитов. Каждый подход имеет свои преимущества и области применения, и выбор конкретного подхода зависит от характеристик входных данных и требований к производительности. Документ включает подробный анализ временной и пространственной сложности каждого подхода, а также практические рекомендации по их использованию.

## Описание алгоритма

В этом документе мы рассмотрим различные способы поиска первого неповторяющегося символа в строке в `Java` и `Kotlin`. Задача заключается в том, чтобы найти первый символ в строке, который встречается ровно один раз. Мы также проанализируем сложность решения во время выполнения и сравним различные подходы.

### Требования

При решении этой задачи необходимо учитывать несколько важных моментов. Во-первых, входная строка может быть любой длины и может содержать сочетание символов верхнего и нижнего регистра, что требует правильной обработки регистра в зависимости от требований задачи. Во-вторых, наше решение должно корректно обрабатывать пустой или `null` ввод, возвращая соответствующее значение. В-третьих, во входной строке может не быть неповторяющихся символов, то есть все символы могут повторяться хотя бы один раз, и в этом случае вывод должен быть `null` или другим договорённым значением, указывающим на отсутствие результата.

### Примеры

Рассмотрим несколько примеров для лучшего понимания задачи. Для входной строки `"leetcode"` выходным значением будет символ `'l'`, так как это первый символ, который встречается только один раз. Для входной строки `"loveleetcode"` выходным значением будет символ `'v'`, так как символы `'l'`, `'o'`, `'v'`, `'e'` встречаются несколько раз, а `'v'` является первым неповторяющимся символом. Для входной строки `"aabb"` выходным значением будет `null`, так как все символы повторяются, и неповторяющихся символов нет.

## Реализация на Java

### Подход 1: Грубая сила (Java)

С этим пониманием попробуем подойти к проблеме.

Во-первых, мы пытаемся разработать метод грубой силы для поиска первого неповторяющегося символа в строке. Мы начинаем с начала строки и берем по одному символу за раз и сравниваем символ с каждым другим символом строки. Если мы находим совпадение, это означает, что этот символ повторяется в другом месте строки, поэтому мы переходим к следующему символу. Если нет совпадения для символа, мы нашли решение и выходим из программы с символом.

### Реализация 1: Двойной цикл

Код выглядит следующим образом:

```java
// Поиск первого символа, встречающегося ровно один раз (двойной цикл)
public Character firstNonRepeatingCharBruteForceNaive(String inputString) {
    if (null == inputString || inputString.isEmpty()) {
        return null;
    }

    for (int outer = 0; outer < inputString.length(); outer++) {
        boolean repeat = false;

        for (int inner = 0; inner < inputString.length(); inner++) {
            if (inner != outer && inputString.charAt(outer) == inputString.charAt(inner)) {
                repeat = true;
                break;
            }
        }

        if (!repeat) {
            return inputString.charAt(outer);
        }
    }

    return null;
}
```

Временная сложность приведённого выше решения составляет `O(n²)` из-за двух вложенных циклов. Для каждого символа, который мы посещаем, мы посещаем все символы входной строки, что приводит к квадратичной сложности. Такой подход прост для понимания, но неэффективен для длинных строк.

### Реализация 2: Использование indexOf и lastIndexOf

Ниже представлено более компактное решение того же алгоритма, в котором используются методы `indexOf()` и `lastIndexOf()` класса `String`. Когда мы находим символ, чей первый индекс в строке также является последним индексом, это означает, что символ существует только по этому индексу в строке и, следовательно, становится первым неповторяющимся символом.

Временная сложность этого решения также `O(n²)`. Следует отметить, что методы `indexOf()` и `lastIndexOf()` выполняются за время `O(n)` каждый, и они вызываются для каждого символа во внешнем цикле, что делает это решение `O(n²)`, аналогичное предыдущему. Несмотря на более компактный код, производительность остаётся такой же.

```java
public Character firstNonRepeatingCharBruteForce(String inputString) {
    if (null == inputString || inputString.isEmpty()) {
        return null;
    }

    for (Character c : inputString.toCharArray()) {
        int indexOfC = inputString.indexOf(c);
        if (indexOfC == inputString.lastIndexOf(c)) {
            return c;
        }
    }

    return null;
}
```

## Подход 2: Использование HashMap

Посмотрим, сможем ли мы сделать лучше. Узким местом подходов, которые мы обсуждали, является то, что мы сравниваем каждый символ с каждым другим символом, который появляется в строке, и мы продолжаем это, пока не достигнем конца строки или не найдём ответ. Вместо этого, если мы сможем запомнить, сколько раз появляется каждый символ, нам не нужно будет сравнивать каждый раз, а вместо этого просто искать частоту появления символа. Для этой цели мы можем использовать `Map`, точнее, `HashMap`, который обеспечивает эффективный доступ к данным по ключу.

### Алгоритм

Карта будет хранить символ в качестве ключа и его частоту в качестве значения. Когда мы посещаем каждого персонажа, у нас есть два варианта. Если персонаж уже есть на карте, мы увеличиваем его значение, что означает, что мы встретили этот символ ещё раз. Если персонаж не появляется на построенной карте до сих пор, это новый персонаж, и мы устанавливаем его частоту в `1`, что означает, что мы встретили этот символ впервые.

После того, как мы завершим вычисления для всей строки, у нас будет карта, которая сообщает нам количество каждого символа в строке. Всё, что нам осталось сделать, это ещё раз перебрать строку, и первый символ, чьё значение на карте равно единице, является нашим ответом. Такой подход позволяет нам найти первый неповторяющийся символ за два прохода по строке, что значительно эффективнее наивного подхода.

### Реализация

Реализация алгоритма с использованием `HashMap` состоит из двух этапов. На первом этапе мы проходим по строке и подсчитываем частоту каждого символа, сохраняя результаты в карте. На втором этапе мы снова проходим по строке и ищем первый символ с частотой, равной единице.

```java
public Character firstNonRepeatingCharWithMap(String inputString) {
    if (null == inputString || inputString.isEmpty()) {
        return null;
    }

    Map<Character, Integer> frequency = new HashMap<>();

    for (int outer = 0; outer < inputString.length(); outer++) {
        char character = inputString.charAt(outer);
        frequency.put(character, frequency.getOrDefault(character, 0) + 1);
    }

    for (Character c : inputString.toCharArray()) {
        if (frequency.get(c) == 1) {
            return c;
        }
    }

    return null;
}
```

Приведённое выше решение намного быстрее, учитывая, что поиск на карте — это операция с постоянным временем, или `O(1)`. Это означает, что время получения результата не будет увеличиваться с увеличением размера входной строки. Общая временная сложность составляет `O(n)`, что является значительным улучшением по сравнению с квадратичной сложностью наивного подхода.

### Альтернативная реализация с LinkedHashMap

Для сохранения порядка вставки можно использовать `LinkedHashMap`, который сохраняет порядок, в котором элементы были добавлены в карту. Это позволяет нам найти первый неповторяющийся символ, не проходя по строке второй раз, а просто перебирая записи карты в порядке их вставки.

```java
public Character firstNonRepeatingCharWithLinkedHashMap(String inputString) {
    if (null == inputString || inputString.isEmpty()) {
        return null;
    }

    Map<Character, Integer> frequency = new LinkedHashMap<>();

    for (char c : inputString.toCharArray()) {
        frequency.put(c, frequency.getOrDefault(c, 0) + 1);
    }

    return frequency.entrySet().stream()
        .filter(entry -> entry.getValue() == 1)
        .map(Map.Entry::getKey)
        .findFirst()
        .orElse(null);
}
```

## Подход 3: Оптимизация с массивом

Мы должны обсудить некоторые предостережения относительно оптимизированного решения, которое мы обсуждали ранее. Исходный вопрос утверждает, что ввод может быть любой длины и может содержать любой символ. Это делает выбор карты для поиска более эффективным и универсальным решением.

Однако, если бы мы могли ограничить набор входных символов только символами нижнего регистра, символами верхнего регистра, символами английского алфавита или `ASCII` символами, было бы лучше использовать массив фиксированного размера вместо карты. Такой подход позволяет достичь постоянной пространственной сложности `O(1)` вместо `O(k)`, где `k` — количество уникальных символов.

### Реализация для строчных букв

Например, если бы ввод был ограничен только строчными буквами латинского алфавита, мы могли бы использовать массив размером `26`, где каждый индекс в массиве относится к соответствующей букве алфавита (`'a'` соответствует индексу `0`, `'b'` — индексу `1`, и так далее), а значение обозначает частоту символа в строке. Наконец, первый символ в строке, значение которого в массиве равно `1`, является ответом. Такой подход эффективен по памяти и обеспечивает быстрый доступ к частотам символов.

```java
public Character firstNonRepeatingCharWithArray(String inputString) {
    if (null == inputString || inputString.isEmpty()) {
        return null;
    }

    int[] frequency = new int[26];

    for (int outer = 0; outer < inputString.length(); outer++) {
        char character = inputString.charAt(outer);
        frequency[character - 'a']++;
    }

    for (Character c : inputString.toCharArray()) {
        if (frequency[c - 'a'] == 1) {
            return c;
        }
    }

    return null;
}
```

Обратите внимание, что временная сложность по-прежнему `O(n)`, но мы улучшили нашу пространственную сложность до постоянного пространства `O(1)`. Это связано с тем, что независимо от длины строки размер вспомогательного пространства, то есть массива, которое мы используем для хранения частоты, будет постоянным и равным `26` для строчных букв латинского алфавита.

### Реализация для ASCII символов

Для всех `ASCII` символов, которых насчитывается `256`, мы можем использовать массив размером `256`, где каждый индекс соответствует коду `ASCII` символа. Такой подход позволяет обрабатывать все стандартные `ASCII` символы, включая буквы, цифры, знаки препинания и управляющие символы.

```java
public Character firstNonRepeatingCharWithASCIIArray(String inputString) {
    if (null == inputString || inputString.isEmpty()) {
        return null;
    }

    int[] frequency = new int[256];

    for (int i = 0; i < inputString.length(); i++) {
        frequency[inputString.charAt(i)]++;
    }

    for (int i = 0; i < inputString.length(); i++) {
        if (frequency[inputString.charAt(i)] == 1) {
            return inputString.charAt(i);
        }
    }

    return null;
}
```

## Сравнение подходов

| Подход | Временная сложность | Пространственная сложность | Когда использовать |
|--------|---------------------|----------------------------|-------------------|
| Грубая сила | `O(n²)` | `O(1)` | Малые строки |
| `HashMap` | `O(n)` | `O(k)`, k — уникальные символы | Общий случай |
| `LinkedHashMap` | `O(n)` | `O(k)` | Нужен порядок |
| Массив (26) | `O(n)` | `O(1)` | Только строчные буквы |
| Массив (256) | `O(n)` | `O(1)` | Только `ASCII` |

## Сложность

### Временная сложность

Подход грубой силы имеет временную сложность `O(n²)`, потому что для каждого символа выполняется внутренний проход по всей строке. Подход с `HashMap` или `LinkedHashMap` обеспечивает линейную сложность `O(n)`, так как достаточно двух проходов: подсчёт частот и поиск первого символа с частотой `1`. Решения на массивах также работают за `O(n)`, выполняя два линейных прохода по строке.

### Пространственная сложность

Подход грубой силы использует константную память `O(1)`. Решение на `HashMap` или `LinkedHashMap` требует `O(k)`, где `k` — число уникальных символов. Массив фиксированного размера для 26 строчных букв даёт постоянную сложность `O(1)`, как и массив из `256` элементов для полного набора `ASCII`.

## Особенности

Каждый подход имеет свои особенности, которые определяют его применимость в различных ситуациях. Подход с использованием `HashMap` оптимален для общего случая, когда входная строка может содержать любые символы, включая символы `Unicode`. Подход с массивом эффективнее по памяти для ограниченного набора символов, таких как только строчные буквы латинского алфавита или `ASCII` символы. Грубая сила проще всего понять и реализовать, что делает её хорошим выбором для обучения и простых задач, но она неэффективна для длинных строк.

## Применение

Поиск первого неповторяющегося символа находит широкое применение в различных областях программирования. В обработке текста этот алгоритм используется для анализа структуры строк и поиска уникальных элементов. В парсинге он помогает идентифицировать разделители и специальные символы, которые встречаются только один раз. В валидации данных алгоритм используется для проверки корректности входных данных и обнаружения ошибок. В задачах на собеседованиях это классическая задача, которая проверяет понимание алгоритмов и структур данных. В анализе строк алгоритм помогает находить паттерны и особенности в текстовых данных.

## Варианты задачи

### Вариант 1: Все неповторяющиеся символы

```java
public List<Character> allNonRepeatingChars(String inputString) {
    if (null == inputString || inputString.isEmpty()) {
        return Collections.emptyList();
    }

    Map<Character, Integer> frequency = new LinkedHashMap<>();

    for (char c : inputString.toCharArray()) {
        frequency.put(c, frequency.getOrDefault(c, 0) + 1);
    }
```

## Лучшие практики

При реализации алгоритма поиска первого неповторяющегося символа важно правильно обрабатывать граничные случаи. Всегда проверяйте `null` и пустую строку в начале функции, возвращая соответствующее значение. При отсутствии неповторяющихся символов возвращайте `null` для символа или договорённое значение, например `-1` для индекса, которое явно указывает на отсутствие результата.

Выбор структуры данных зависит от характеристик входных данных. Для общего случая, когда входная строка может содержать любые символы `Unicode`, используйте `HashMap` или `LinkedHashMap`, если важен порядок первого появления символов. Для ограниченного алфавита, такого как только строчные латинские буквы или `ASCII` символы, используйте массив частот, чтобы сэкономить память и улучшить производительность.

При использовании `Map` для сохранения первого неповторяющегося символа важно обходить строку слева направо и проверять частоту в том же порядке. `LinkedHashMap` сохраняет порядок вставки, что позволяет найти первый неповторяющийся символ без второго прохода по строке.

Для достижения оптимальной производительности используйте два прохода по строке: один для подсчёта частот и один для поиска первого символа с частотой `1`. Это даёт временную сложность `O(n)`. Избегайте вызовов `indexOf()` и `lastIndexOf()` в цикле, так как они дают временную сложность `O(n²)`.

При тестировании важно покрыть все граничные случаи: пустая строка, один символ, все символы повторяются, несколько неповторяющихся символов (должен вернуться первый), и различные варианты регистра, если требуется чувствительность к регистру.

## Когда использовать

Выбор конкретного подхода зависит от характеристик задачи и требований к производительности. Грубую силу следует использовать, когда строки очень короткие, нужна простота реализации и производительность не является критическим фактором. Такой подход подходит для учебных целей и простых приложений, где простота кода важнее оптимизации.

Подход с использованием `HashMap` следует использовать в общем случае, когда нужна максимальная производительность и набор символов не ограничен. Этот подход эффективен для строк любой длины и с любыми символами, включая символы `Unicode`.

Подход с массивом следует использовать, когда набор символов ограничен, например только `ASCII` символы или только строчные буквы латинского алфавита. Этот подход особенно эффективен, когда важна экономия памяти и нужна максимальная производительность благодаря прямому доступу к элементам массива.

## Решение проблем

При работе с алгоритмом поиска первого неповторяющегося символа могут возникать различные проблемы. Если алгоритм возвращает неправильный результат, убедитесь, что вы правильно обрабатываете регистр символов. Если требуется чувствительность к регистру, символы `'A'` и `'a'` считаются разными, в противном случае их нужно нормализовать перед обработкой.

Если алгоритм работает слишком медленно, проверьте, не используете ли вы методы `indexOf()` или `lastIndexOf()` в цикле, что приводит к квадратичной сложности. Используйте подход с `HashMap` или массивом для достижения линейной сложности.

При проблемах с памятью убедитесь, что вы используете подходящую структуру данных. Для ограниченного набора символов используйте массив вместо `HashMap`, что значительно снижает потребление памяти.

Если алгоритм не обрабатывает граничные случаи, проверьте обработку `null`, пустой строки и случая, когда все символы повторяются. Убедитесь, что функция возвращает корректное значение во всех этих случаях.

## Частые вопросы

Вопрос: Как обрабатывать регистр символов? Ответ: Если требуется чувствительность к регистру, символы `'A'` и `'a'` считаются разными. Если регистр не важен, приведите строку к одному регистру перед обработкой, используя методы `toLowerCase()` или `toUpperCase()`.

Вопрос: Какой подход самый быстрый? Ответ: Для ограниченного набора символов подход с массивом обычно самый быстрый благодаря прямому доступу к элементам. Для общего случая подход с `HashMap` обеспечивает хорошую производительность с линейной сложностью.

Вопрос: Можно ли найти все неповторяющиеся символы за один проход? Ответ: Да, используя `LinkedHashMap`, можно найти все неповторяющиеся символы за один проход, поскольку она сохраняет порядок вставки. Для поиска только первого неповторяющегося символа достаточно двух проходов.

Вопрос: Как обрабатывать символы `Unicode`? Ответ: Для символов `Unicode` используйте `HashMap` или `LinkedHashMap`, так как они могут хранить любые символы. Массив фиксированного размера подходит только для ограниченных наборов символов, таких как `ASCII`.

Вопрос: Что возвращать, если все символы повторяются? Ответ: В этом случае следует возвращать `null` для символа или договорённое значение, например `-1` для индекса, чтобы явно указать на отсутствие результата.

## Глоссарий терминов

`Неповторяющийся символ` — символ, который встречается в строке ровно один раз.

`Частота символа` — количество раз, которое символ встречается в строке.

`HashMap` — структура данных, которая хранит пары ключ-значение и обеспечивает эффективный доступ к данным по ключу.

`LinkedHashMap` — вариант `HashMap`, который сохраняет порядок вставки элементов.

`Пространственная сложность` — количество дополнительной памяти, необходимое алгоритму для работы.

`Временная сложность` — количество операций, которое выполняет алгоритм в зависимости от размера входных данных.

`Грубая сила (brute force)` — простейший подход к решению задачи, который проверяет все возможные варианты.

`Оптимизация` — улучшение алгоритма для достижения лучшей производительности или использования памяти.

```java
        } else if (c >= 'A' && c <= 'Z') {
            frequency[26 + c - 'A']++;

        } else if (c >= 'A' && c <= 'Z') {

        } else {

        }

        if (frequency[index] == 1) {

        }
    }
```
