## Описание алгоритма

Палиндром — это слово, фраза, число или другие последовательности символов, которые читаются так же, как в прямом, так и в обратном порядке, например, «мадам» или «гоночная машина». В следующих разделах мы рассмотрим различные способы проверки того, является ли данная строка палиндромом или нет.

### Примеры палиндромов

Примеры палиндромов показывают различные случаи проверки. Строка `"madam"` является палиндромом, так как читается одинаково в обоих направлениях. Строка `"racecar"` также является палиндромом. Строка `"level"` является палиндромом. Строка `"hello"` не является палиндромом, так как не читается одинаково в обратном направлении. Строка `"A man a plan a canal Panama"` является палиндромом с игнорированием пробелов, что демонстрирует важность нормализации входных данных перед проверкой.

## Реализация на Java

### Подход 1: Два указателя (Java)

Мы можем одновременно начать итерацию заданной строки вперёд и назад, по одному символу за раз. Если есть совпадение, цикл продолжается; в противном случае цикл завершается. Этот подход эффективен по памяти (`O(1)` дополнительной памяти), проходит только половину строки и игнорирует пробелы и регистр, что делает его предпочтительным выбором для большинства практических применений.

### Подход 2: Реверс строки (Java)

Есть несколько различных реализаций, которые подходят для этого варианта использования: мы можем использовать методы `API` из классов `StringBuilder` и `StringBuffer` при проверке палиндромов или мы можем обратить `String` без этих классов.

#### Реализация без API

Давайте сначала посмотрим на реализации кода без вспомогательных `API`. В приведённом выше фрагменте мы просто повторяем заданную строку от последнего символа и добавляем каждый символ к следующему символу, вплоть до первого символа, тем самым изменяя заданную строку. Наконец, мы проверяем равенство между заданной строкой и перевёрнутой строкой.

#### Использование StringBuilder API

Такого же поведения можно добиться с помощью методов `API`. Давайте посмотрим быструю демонстрацию. Во фрагменте кода мы вызываем метод `reverse()` из `API StringBuilder` и `StringBuffer`, чтобы перевернуть заданную строку и проверить её на равенство.

### Подход 3: Рекурсивный (Java)

Рекурсия — очень популярный метод решения подобных задач. В продемонстрированном примере мы рекурсивно перебираем заданную строку и проверяем, является ли она палиндромом или нет. Рекурсивный подход имеет несколько особенностей. Это элегантное решение, которое использует стек вызовов (`O(n)` памяти) и может быть медленнее из-за накладных расходов на рекурсию. Однако рекурсивный подход демонстрирует красоту рекурсивного мышления и может быть полезен для обучения.

### Подход 4: Stream API

Мы также можем использовать `IntStream` для предоставления решения. В приведённом выше фрагменте мы проверяем, что ни одна из пар символов с каждого конца строки не соответствует условию `Predicate`. Это позволяет использовать функциональный стиль программирования и создавать более выразительный код.

### Альтернативная версия с Stream

Альтернативная версия использует `allMatch` вместо `noneMatch`, что делает код более читаемым и понятным. Оба подхода эквивалентны по функциональности, но могут различаться по читаемости в зависимости от контекста использования.

## Реализация на Kotlin

В `Kotlin` проверка палиндрома может быть реализована различными способами, включая императивный, функциональный и рекурсивный подходы. Каждый подход имеет свои преимущества и применяется в зависимости от стиля программирования и требований приложения.

### Подход 1: Два указателя (Kotlin)

```kotlin
fun isPalindrome(text: String): Boolean {
    val clean = text.replace("\\s+".toRegex(), "").lowercase()
    var forward = 0
    var backward = clean.length - 1

    while (backward > forward) {
        if (clean[forward++] != clean[backward--]) {
            return false
        }
    }

    return true
}
```

### Подход 2: Реверс строки (Kotlin)

Реверс строки в `Kotlin` может быть реализован с использованием встроенной функции `reversed()` или с использованием `StringBuilder`. Оба подхода эквивалентны по функциональности, но использование `reversed()` более идиоматично для `Kotlin`.

### Подход 3: Рекурсивный (Kotlin)

```kotlin
fun isPalindromeRecursive(text: String): Boolean {
    val clean = text.replace("\\s+".toRegex(), "").lowercase()
    return recursivePalindrome(clean, 0, clean.length - 1)
}

private fun recursivePalindrome(text: String, forward: Int, backward: Int): Boolean {
    if (forward == backward) return true
    if (text[forward] != text[backward]) return false
    if (forward < backward + 1) {
        return recursivePalindrome(text, forward + 1, backward - 1)
    }
    return true
}
```

### Подход 4: Функциональный стиль

Функциональный стиль в `Kotlin` позволяет создавать элегантный и выразительный код. Более компактная версия использует прямое сравнение строки с её обращённой версией, что делает код максимально простым и читаемым. Использование этих методов позволяет легко проверять палиндромы в различных контекстах.

## Сравнение подходов

Сравнение подходов показывает различные характеристики каждого метода. Два указателя имеют временную сложность `O(n)` и пространственную сложность `O(1)`, что делает их наиболее эффективными. Реверс строки имеет временную сложность `O(n)` и пространственную сложность `O(n)`, но проще для понимания. Рекурсивный подход имеет временную сложность `O(n)` и пространственную сложность `O(n)`, но более элегантен. `Stream API` имеет временную сложность `O(n)` и пространственную сложность `O(1)`, что делает его эффективным и выразительным.

## Сложность

### Временная сложность

Все подходы имеют временную сложность `O(n)`, где `n` — длина строки. Каждый символ проверяется один раз, что делает все подходы эффективными по времени выполнения. Различия в производительности между подходами связаны с накладными расходами на создание объектов и вызовы методов, а не с временной сложностью алгоритма.

### Пространственная сложность

Пространственная сложность различается между подходами. Два указателя требуют только константной памяти `O(1)`, что делает их наиболее эффективными по памяти. Реверс строки требует `O(n)` памяти для хранения перевёрнутой строки. Рекурсивный подход требует `O(n)` памяти для стека вызовов. `Stream API` требует только константной памяти `O(1)`, что делает его эффективным по памяти.

## Особенности

Большинство реализаций игнорируют пробелы и регистр символов, что делает проверку палиндромов более гибкой и практичной. Игнорирование пробелов позволяет проверять фразы, такие как `"A man a plan a canal Panama"`, как палиндромы. Игнорирование регистра гарантирует, что `"Madam"` и `"madam"` считаются одинаковыми. Два указателя — самый эффективный подход по памяти и времени, что делает его предпочтительным выбором для большинства практических применений.

Проверка палиндромов используется в различных областях. В обработке текста проверка палиндромов используется для анализа текстовых данных и поиска интересных паттернов. В валидации данных проверка палиндромов используется для проверки корректности входных данных, таких как номера телефонов или идентификаторы. В алгоритмах сжатия палиндромы используются для оптимизации сжатия данных. В задачах на собеседованиях проверка палиндромов является популярной задачей для проверки навыков программирования. В анализе ДНК палиндромы используются для идентификации важных последовательностей нуклеотидов.

## Варианты задачи

### Вариант 1: Палиндром с учетом регистра

```java
public boolean isPalindromeCaseSensitive(String text) {
    String clean = text.replaceAll("\\s+", "");
    int length = clean.length();
    int forward = 0;
    int backward = length - 1;

    while (backward > forward) {
        if (clean.charAt(forward++) != clean.charAt(backward--)) {
            return false;
        }
    }

    return true;
}
```

### Вариант 2: Палиндром с учетом пробелов

```java
public boolean isPalindromeWithSpaces(String text) {
    int forward = 0;
    int backward = text.length() - 1;

    while (backward > forward) {
        char forwardChar = text.charAt(forward);
        char backwardChar = text.charAt(backward);

        if (!Character.isLetterOrDigit(forwardChar)) {
            forward++;
            continue;
        }

        if (!Character.isLetterOrDigit(backwardChar)) {
            backward--;
            continue;
        }

        if (Character.toLowerCase(forwardChar) != Character.toLowerCase(backwardChar)) {
            return false;
        }

        forward++;
        backward--;
    }

    return true;
}
```

### Вариант 3: Числовой палиндром

```java
public boolean isNumericPalindrome(int number) {
    int original = number;
    int reversed = 0;

    while (number > 0) {
        reversed = reversed * 10 + number % 10;
        number /= 10;
    }

    return original == reversed;
}
```

## Когда использовать

Используйте два указателя, когда нужна максимальная эффективность и важна экономия памяти. Этот подход подходит, когда простая реализация достаточна и не требуется сложная логика. Два указателя обеспечивают оптимальную производительность и минимальное использование памяти, что делает их предпочтительным выбором для большинства практических применений.

Используйте реверс строки, когда нужна простота понимания и память не является ограничением. Этот подход подходит, когда работаете с небольшими строками и важнее читаемость кода, чем максимальная производительность. Реверс строки проще для понимания и может быть полезен для обучения и демонстрации концепций.

Используйте рекурсивный подход, когда нужна элегантность кода и обучаете рекурсию. Этот подход подходит, когда стек вызовов не является проблемой и важнее демонстрация рекурсивного мышления, чем максимальная производительность. Рекурсивный подход демонстрирует красоту рекурсии и может быть полезен для образовательных целей.

## Лучшие практики

Выбор подхода зависит от конкретных требований. Для продакшена предпочтителен подход с двумя указателями: `O(n)` по времени, `O(1)` по дополнительной памяти; один проход по половине строки. Это обеспечивает оптимальную производительность и минимальное использование памяти.

Нормализация критически важна для корректной работы алгоритма. При необходимости игнорировать пробелы, пунктуацию и регистр — нормализуйте строку до сравнения (например, `replaceAll("\\s+", "").toLowerCase()` или удаление не-букв). Это гарантирует корректную работу алгоритма независимо от формата входных данных.

Null и пустая строка требуют явной обработки. Обрабатывайте `null` и пустую строку явно (пустая строка обычно считается палиндромом). Это гарантирует корректное поведение алгоритма во всех возможных случаях и предотвращает ошибки при работе с неинициализированными или пустыми строками.

Юникод требует особого внимания при работе со сложными символами. Для строк с символами вне `BMP` (суррогатные пары) используйте `Character.codePointAt` и итерацию по кодовым точкам, чтобы не разбивать пары. Это гарантирует корректную работу алгоритма с различными языками и системами письменности.

Производительность может быть улучшена путём минимизации создания временных объектов. Избегайте создания лишних строк (реверс через `StringBuilder` создаёт копию); два указателя не создают промежуточных объектов. Это значительно улучшает производительность и снижает использование памяти.

## Решение проблем

При работе с проверкой палиндромов могут возникать различные проблемы. Если алгоритм не распознаёт валидные палиндромы, убедитесь, что вы правильно нормализуете входные данные, удаляя пробелы и приводя к одному регистру. Если возникают проблемы с производительностью, рассмотрите возможность использования подхода с двумя указателями вместо реверса строки, так как он не создаёт временных объектов.

Проблемы с памятью могут возникать при использовании рекурсивного подхода для длинных строк. В таких случаях рекомендуется использовать итеративный подход с двумя указателями или `Stream API`, которые не требуют стека вызовов. Также убедитесь, что вы правильно обрабатываете граничные случаи, такие как пустые строки и строки из одного символа.

Проблемы с юникодом могут возникать при работе со сложными символами. Убедитесь, что вы используете правильные методы для работы с кодовыми точками, а не с отдельными символами, что гарантирует корректную работу алгоритма с различными языками.

## Частые вопросы

**Какой подход лучше использовать для проверки палиндромов?** Для продакшена рекомендуется использовать подход с двумя указателями, так как он обеспечивает оптимальную производительность и минимальное использование памяти. Для обучения и демонстрации концепций можно использовать рекурсивный подход или реверс строки.

**Как обрабатывать пробелы и регистр?** Нормализуйте строку перед проверкой, используя `replaceAll("\\s+", "")` для удаления пробелов и `toLowerCase()` для приведения к нижнему регистру. Это гарантирует корректную работу алгоритма независимо от формата входных данных.

**Как обрабатывать пустые строки и null?** Явно обрабатывайте `null` и пустые строки. Пустая строка обычно считается палиндромом, так как она читается одинаково в обоих направлениях. Это гарантирует корректное поведение алгоритма во всех возможных случаях.

**Как улучшить производительность?** Используйте подход с двумя указателями, который не создаёт временных объектов. Избегайте создания обратных строк в циклах и минимизируйте количество операций со строками. Это значительно улучшает производительность и снижает использование памяти.

## Глоссарий терминов

**Палиндром** — последовательность символов, которая читается одинаково в прямом и обратном порядке. Палиндромы могут быть словами, фразами, числами или другими последовательностями символов.

**Два указателя** — подход к решению задач, при котором используются два индекса, движущихся навстречу друг другу. В контексте проверки палиндромов два указателя сравнивают симметричные символы строки.

**Реверс строки** — создание обратной версии строки, при которой порядок символов меняется на противоположный. В контексте проверки палиндромов реверс используется для сравнения исходной строки с её обращённой версией.

**Нормализация** — процесс приведения данных к единому формату. В контексте проверки палиндромов нормализация включает удаление пробелов и приведение к одному регистру.

**Кодовая точка** — числовое значение символа в системе Unicode. В контексте проверки палиндромов кодовые точки используются для корректной обработки сложных символов, таких как суррогатные пары.
