# Баланс скобок (Balanced Parentheses)

Задача проверки сбалансированности скобок — классическая задача программирования, которая заключается в проверке правильности расстановки скобок в строке. Скобки считаются сбалансированными, если каждая открывающая скобка имеет соответствующую закрывающую скобку в правильном порядке и типе. Эта задача имеет множество практических применений, от парсинга выражений до валидации структурированных данных. В этом документе рассматриваются различные подходы к решению задачи: использование методов `String` для удаления пар скобок и использование структуры данных `Stack` или `Deque` для отслеживания открывающих скобок. Документ включает реализации на `Java` и `Kotlin`, анализ сложности алгоритмов и практические рекомендации по выбору подхода в зависимости от требований приложения.

## Описание алгоритма

Задача сбалансированных скобок являются распространенной проблемой программирования.

В этом уроке мы проверим, сбалансированы ли скобки в данной строке или нет.

Этот тип строк является частью того, что известно как язык Дайка.

Скобкой считается любой из следующих символов — «(», «)», «[», «]», «{», «}».

Набор скобок считается совпадающей парой, если открывающая скобка «(», «[» и «{» стоит слева от соответствующей закрывающей скобки «)», «]» и «}», соответственно.

Однако строка, содержащая пары квадратных скобок, не сбалансирована, если набор заключенных в нее скобок не совпадает.

Точно так же строка, содержащая символы без квадратных скобок, такие как **a-z**, **A-Z**, 0-9 или другие специальные символы, такие как #, $, @, также считается несбалансированной.

### Примеры

Например, если ввод `"{[(])}"`, пара квадратных скобок `"[]"` заключает в себя одну несбалансированную открывающую круглую скобку `'('`. Аналогично, пара круглых скобок `"()"` заключает в себя одну несбалансированную закрывающую квадратную скобку `']'`. Таким образом, входная строка `"{[(])}"` несбалансированная, так как порядок закрывающих скобок не соответствует порядку открывающих скобок.

## Определение сбалансированности

Таким образом, строка, содержащая символы скобок, называется сбалансированной, если выполняются следующие условия. Во-первых, соответствующая открывающая скобка находится слева от каждой соответствующей закрывающей скобки, что означает правильный порядок пар скобок. Во-вторых, скобки, заключённые в сбалансированные скобки, также являются сбалансированными, что обеспечивает правильную вложенность скобок. В-третьих, строка не содержит символов, не являющихся скобками, если по условию задачи допускаются только скобки. В-четвёртых, следует помнить о нескольких особых случаях: значение `null` считается несбалансированным, а пустая строка обычно считается сбалансированной, так как в ней нет несбалансированных скобок.

### Примеры сбалансированных скобок

```text
()
[()]
{[()]}
([{{[(())]}}])
```

### Примеры несбалансированных скобок

```text
abc[](){}  // содержит не-скобки
{{[]()}}}  // непарные скобки
{[(])}     // неправильный порядок
```

## Реализация на Java

### Подход 1: Использование String методов (Java)

Теперь, когда мы лучше понимаем нашу проблему, давайте посмотрим, как её решить. Существуют разные способы решения этой проблемы. В этом документе мы рассмотрим два основных подхода, каждый из которых имеет свои преимущества и области применения.

Давайте сначала создадим метод, который будет возвращать `true`, если вход сбалансирован, и `false`, если вход несбалансирован. Этот метод будет основой для всех наших реализаций и позволит нам проверить различные подходы к решению задачи.

```java
public boolean isBalanced(String str)
```

### Проверки входной строки

Рассмотрим основные проверки входной строки, которые позволяют нам быстро определить, может ли строка быть сбалансированной. Во-первых, если передаётся нулевой вход (`null`), то он не сбалансирован, так как не содержит скобок для проверки. Во-вторых, чтобы строка была сбалансированной, пары открывающих и закрывающих скобок должны совпадать. Следовательно, можно с уверенностью сказать, что входная строка нечётной длины не будет сбалансирована, поскольку она будет содержать по крайней мере одну несовпадающую скобку. В-третьих, согласно постановке задачи, сбалансированное поведение должно быть проверено только в скобках. Следовательно, любая входная строка, содержащая символы без скобок, является несбалансированной строкой, если по условию задачи допускаются только скобки.

Учитывая эти правила, мы можем реализовать проверки, которые позволят нам быстро отсеять заведомо несбалансированные строки без выполнения полного алгоритма проверки.

```java
// Быстрые проверки: null и нечётная длина (пара скобок не может быть нечётной)
if (null == str || ((str.length() % 2) != 0)) {
    return false;
} else {
    char[] ch = str.toCharArray();
    for (char c : ch) {
        // Допускаем только скобки; иначе строка несбалансирована по условию
        if (!(c == '{' || c == '[' || c == '(' || c == '}' || c == ']' || c == ')')) {
            return false;
        }
    }
}
```

### Реализация с replaceAll

В этом подходе мы будем перебирать входную строку, удаляя вхождения `"()"`, `"[]"` и `"{}"` из строки, используя метод `String.replaceAll()`. Мы продолжаем этот процесс до тех пор, пока во входной строке не будет найдено больше вхождений пар скобок. Идея заключается в том, что если все скобки сбалансированы, мы сможем удалить все пары, оставив пустую строку.

После завершения процесса, если длина нашей строки равна нулю, все совпадающие пары скобок удалены, и входная строка сбалансирована. Если же длина не равна нулю, то в строке всё ещё присутствуют непарные открывающие или закрывающие скобки. Следовательно, входная строка несбалансирована. Этот подход прост для понимания, но может быть неэффективным для длинных строк из-за многократных проходов по строке.

```java
public boolean isBalanced(String str) {
    if (null == str || ((str.length() % 2) != 0)) {
        return false;
    } else {
        char[] ch = str.toCharArray();
        for (char c : ch) {
            if (!(c == '{' || c == '[' || c == '(' || c == '}' || c == ']' || c == ')')) {
                return false;
            }
        }
    }

    while (str.contains("()") || str.contains("[]") || str.contains("{}")) {
        str = str.replaceAll("\\(\\)", "")
            .replaceAll("\\[\\]", "")
            .replaceAll("\\{\\}", "");
    }

    return (str.length() == 0);
}
```

### Особенности

Подход с использованием `String.replaceAll()` имеет несколько важных особенностей. Во-первых, он имеет простую реализацию, которая легко понимается и может быть быстро написана. Во-вторых, он может быть медленным для длинных строк, так как требует многократных проходов по строке для удаления всех пар скобок. В-третьих, каждый вызов `replaceAll()` создаёт новую строку, что увеличивает потребление памяти и снижает производительность. Эти особенности делают этот подход подходящим для коротких строк или учебных целей, но не рекомендуемым для продакшена с большими объёмами данных.

## Подход 2: Использование Deque/Stack

`Deque` — это форма очереди, которая обеспечивает операции добавления, извлечения и просмотра на обоих концах очереди. Мы будем использовать функцию «последним пришёл — первым вышел» (`LIFO`) этой структуры данных, чтобы проверить баланс во входной строке. Такой подход позволяет нам эффективно отслеживать открывающие скобки и проверять их соответствие закрывающим скобкам по мере прохождения по строке.

### Реализация с Deque

Во-первых, давайте создадим нашу `Deque` для хранения открывающих скобок. Обратите внимание, что здесь мы использовали `LinkedList`, потому что он обеспечивает реализацию интерфейса `Deque` и позволяет эффективно добавлять и удалять элементы с обоих концов.

Теперь, когда наша двухсторонняя очередь построена, мы будем перебирать каждый символ входной строки один за другим. Если символ является открывающей скобкой, то мы добавим его первым элементом в `Deque`, используя метод `addFirst()`. Это позволяет нам отслеживать порядок открывающих скобок и проверять их соответствие закрывающим скобкам.

```java
if (ch == '{' || ch == '[' || ch == '(') {
    deque.addFirst(ch);
}
```

Но, если символ является закрывающей скобкой, то мы выполним некоторые проверки `Deque`. Во-первых, мы проверяем, является ли `Deque` пустым или нет. Пустой список означает, что закрывающая скобка не имеет соответствующей открывающей скобки. Следовательно, входная строка несбалансирована, и мы возвращаем `false`.

Однако, если `Deque` не пуст, мы просматриваем его первый символ, используя метод `peekFirst()`. Если его можно поставить в пару с закрывающей скобкой, то удаляем этот самый верхний символ из списка с помощью метода `removeFirst()` и переходим к следующей итерации цикла. Если же типы скобок не совпадают, это означает, что порядок скобок неправильный, и мы возвращаем `false`.

К концу цикла все символы проверяются на баланс. Если `Deque` пуст, это означает, что все открывающие скобки были успешно сопоставлены с закрывающими скобками, и мы можем вернуть `true`. Ниже приведена полная реализация подхода на основе `Deque`:

```java
public boolean isBalanced(String str) {
    if (null == str || ((str.length() % 2) != 0)) {
        return false;
    } else {
        char[] ch = str.toCharArray();
        for (char c : ch) {
            if (!(c == '{' || c == '[' || c == '(' || c == '}' || c == ']' || c == ')')) {
                return false;
            }
        }
    }

    Deque<Character> deque = new LinkedList<>();

    for (char ch : str.toCharArray()) {
        if (ch == '{' || ch == '[' || ch == '(') {
            deque.addFirst(ch);
        } else {
            if (!deque.isEmpty()
                && ((deque.peekFirst() == '{' && ch == '}')
                || (deque.peekFirst() == '[' && ch == ']')
                || (deque.peekFirst() == '(' && ch == ')'))) {
                deque.removeFirst();
            } else {
                return false;
            }
        }
    }

    return deque.isEmpty();
}
```

### Реализация с Stack

Альтернативная реализация с использованием `Stack` предоставляет более традиционный подход к решению задачи. `Stack` является устаревшим классом в `Java`, и рекомендуется использовать `Deque` вместо него, но для понимания концепции стека эта реализация полезна.

```java
public boolean isBalancedWithStack(String str) {
    if (str == null || str.length() % 2 != 0) {
        return false;
    }

    Stack<Character> stack = new Stack<>();

    for (char ch : str.toCharArray()) {
        if (ch == '{' || ch == '[' || ch == '(') {
            stack.push(ch);
        } else if (ch == '}' || ch == ']' || ch == ')') {
            if (stack.isEmpty()) {
                return false;
            }

            char top = stack.pop();
            if ((ch == '}' && top != '{')
                || (ch == ']' && top != '[')
                || (ch == ')' && top != '(')) {
                return false;
            }
        } else {
            return false; // Не-скобки
        }
    }

    return stack.isEmpty();
}
```

### Улучшенная версия с Map

**Для более чистого кода можно использовать **Map** для хранения соответствий скобок:**

```java
public boolean isBalancedWithMap(String str) {
    if (str == null || str.length() % 2 != 0) {
        return false;
    }

    Map<Character, Character> brackets = new HashMap<>();
    brackets.put(')', '(');
    brackets.put(']', '[');
    brackets.put('}', '{');

    Stack<Character> stack = new Stack<>();

    for (char ch : str.toCharArray()) {
        if (brackets.containsValue(ch)) {
            stack.push(ch);
        } else if (brackets.containsKey(ch)) {
            if (stack.isEmpty() || stack.pop() != brackets.get(ch)) {
                return false;
            }
        } else {
            return false;
        }
    }

    return stack.isEmpty();
}
```

## Реализация на Kotlin

### Подход 1: Использование String методов (Kotlin)

```kotlin
fun isBalancedStringK(str: String?): Boolean {
    if (str == null || str.length % 2 != 0) {
        return false
    }

    var modified = str
    while (modified.contains("()") || modified.contains("[]") || modified.contains("{}")) {
        modified = modified.replace("()", "")
            .replace("[]", "")
            .replace("{}", "")
    }

    return modified.isEmpty()
}
```

### Подход 2: Использование Stack/Deque

```kotlin
fun isBalancedStackK(str: String?): Boolean {
    if (str == null || str.length % 2 != 0) {
        return false
    }

    val stack = ArrayDeque<Char>()

    for (ch in str) {
        if (ch == '{' || ch == '[' || ch == '(') {
            stack.addFirst(ch)
        } else {
            if (stack.isNotEmpty() &&
                ((stack.first() == '{' && ch == '}') ||
                 (stack.first() == '[' && ch == ']') ||
                 (stack.first() == '(' && ch == ')'))) {
                stack.removeFirst()
            } else {
                return false
            }
        }
    }

    return stack.isEmpty()
}
```

### Улучшенная версия с Map

```kotlin
fun isBalancedMapK(str: String?): Boolean {
    if (str == null || str.length % 2 != 0) {
        return false
    }

    val brackets = mapOf(')' to '(', ']' to '[', '}' to '{')
    val stack = ArrayDeque<Char>()

    for (ch in str) {
        when {
            brackets.values.contains(ch) -> stack.addFirst(ch)
            brackets.containsKey(ch) -> {
                if (stack.isEmpty() || stack.removeFirst() != brackets[ch]) {
                    return false
                }
            }
            else -> return false
        }
    }

    return stack.isEmpty()
}
```

### Только круглые скобки

```kotlin
fun isBalancedParenthesesK(str: String): Boolean {
    var count = 0
    for (ch in str) {
        when (ch) {
            '(' -> count++
            ')' -> {
                count--
                if (count < 0) return false
            }
        }
    }
    return count == 0
}
```

### Функциональный стиль

```kotlin
fun isBalancedFunctionalK(str: String?): Boolean {
    if (str == null || str.length % 2 != 0) return false

    val brackets = mapOf(')' to '(', ']' to '[', '}' to '{')

    return str.fold(ArrayDeque<Char>()) { stack, ch ->
        when {
            brackets.values.contains(ch) -> stack.apply { addFirst(ch) }
            brackets.containsKey(ch) -> {
                if (stack.isEmpty() || stack.removeFirst() != brackets[ch]) {
                    return false
                }
                stack
            }
            else -> return false
        }
    }.isEmpty()
}
```

### Пример использования

```kotlin

## Сравнение подходов

Сравнение различных подходов к решению задачи показывает их преимущества и недостатки. Подход с использованием `String.replaceAll()` имеет временную сложность `O(n²)` в худшем случае из-за многократных проходов по строке, пространственную сложность `O(n)` для хранения строки и простую реализацию, что делает его подходящим для коротких строк или учебных целей. Подход с использованием `Deque` или `Stack` имеет временную сложность `O(n)` благодаря одному проходу по строке, пространственную сложность `O(n)` для стека в худшем случае и среднюю сложность реализации, что делает его предпочтительным для продакшена. Подход с использованием `Stack` и `Map` также имеет временную сложность `O(n)` и пространственную сложность `O(n)`, но обеспечивает более чистый и расширяемый код благодаря использованию карты для хранения соответствий скобок.

## Сложность

### Подход 1: String replaceAll

Подход с использованием `String.replaceAll()` имеет временную сложность `O(n²)` в худшем случае, так как может потребоваться `n` проходов по строке для удаления всех пар скобок. Каждый вызов `replaceAll()` создаёт новую строку и выполняет поиск по всей строке, что увеличивает время выполнения. Пространственная сложность составляет `O(n)` для хранения строки и промежуточных результатов.

### Подход 2: Deque/Stack

Подход с использованием `Deque` или `Stack` имеет временную сложность `O(n)`, так как требует только одного прохода по строке. Каждый символ обрабатывается один раз, что делает этот подход значительно более эффективным для длинных строк. Пространственная сложность составляет `O(n)` для стека в худшем случае, когда все символы являются открывающими скобками. В среднем случае пространственная сложность может быть меньше, если скобки сбалансированы и удаляются из стека по мере обработки.

## Особенности

Каждый подход имеет свои особенности, которые определяют его применимость в различных ситуациях. Подход с использованием `Stack` или `Deque` более эффективен по времени выполнения, обеспечивая линейную сложность и подходя для обработки больших объёмов данных. Подход с использованием `String.replaceAll()` проще понять и реализовать, что делает его хорошим выбором для обучения и простых задач. Оба подхода легко расширить для поддержки других типов скобок или дополнительных правил проверки, что обеспечивает гибкость при адаптации алгоритма под конкретные требования приложения.

## Варианты задачи

### Вариант 1: Только круглые скобки

public boolean isBalancedParentheses(String str) {
    int count = 0;
    for (char ch : str.toCharArray()) {
        if (ch == '(') {
            count++;
        } else if (ch == ')') {
            count--;
            if (count < 0) {
                return false;
            }
        }
    }
    return count == 0;
}
```

## Когда использовать

Выбор конкретного подхода зависит от характеристик задачи и требований к производительности. Используйте `String.replaceAll()`, когда строки короткие, нужна простота реализации и производительность не является критическим фактором. Такой подход подходит для учебных целей и простых приложений, где простота кода важнее оптимизации.

Используйте `Stack` или `Deque`, когда строки длинные, нужна максимальная производительность и важна эффективность. Этот подход обеспечивает линейную временную сложность и является предпочтительным выбором для продакшена, особенно при обработке больших объёмов данных или в системах с высокими требованиями к производительности.

## Лучшие практики

При реализации алгоритма проверки сбалансированности скобок важно следовать нескольким лучшим практикам. Для продакшена предпочтителен подход с использованием стека (`Deque`), который обеспечивает временную сложность `O(n)` и пространственную сложность `O(n)` при одном проходе по строке. Подход с `replaceAll()` имеет временную сложность `O(n²)` в худшем случае из-за многократного прохода по строке, что делает его неподходящим для больших объёмов данных.

Обработка `null` и пустой строки должна быть явной. Значение `null` обычно считается несбалансированным или должно вызывать исключение по контракту метода. Пустая строка обычно считается сбалансированной, так как в ней нет несбалансированных скобок. Важно зафиксировать это поведение в документации метода.

При работе с набором скобок важно правильно определить правила проверки. Если допустимы только круглые скобки, можно упростить проверку, используя простой счётчик вместо стека. При смешанных типах скобок обязательно проверять соответствие типа открывающей и закрывающей скобки через стек, чтобы избежать ошибок типа `([)]`.

Обработка символов вне скобок зависит от требований задачи. По условию задачи можно либо игнорировать не-скобки, либо считать строку несбалансированной. Важно зафиксировать это поведение в контракте метода и документации, чтобы пользователи знали, как алгоритм обрабатывает такие случаи.

При тестировании важно проверять граничные случаи: пустая строка, одна пара скобок, вложенные пары скобок, несбалансированные типы скобок типа `([)]`, строки только с открывающими скобками, строки только с закрывающими скобками, и строки с различными комбинациями типов скобок. Это поможет выявить потенциальные проблемы и обеспечить корректную работу алгоритма во всех ситуациях.

## Решение проблем

При работе с алгоритмом проверки сбалансированности скобок могут возникать различные проблемы. Если алгоритм возвращает неправильный результат, проверьте обработку граничных случаев: `null`, пустая строка, строки нечётной длины. Убедитесь, что вы правильно обрабатываете различные типы скобок и проверяете соответствие типов открывающих и закрывающих скобок.

Если алгоритм работает слишком медленно, убедитесь, что вы используете подход с `Stack` или `Deque` вместо `String.replaceAll()` для длинных строк. Подход с `replaceAll()` может быть очень медленным для больших объёмов данных из-за квадратичной сложности.

При проблемах с памятью проверьте размер стека. В худшем случае, когда все символы являются открывающими скобками, стек может содержать все символы строки. Для очень длинных строк это может привести к проблемам с памятью.

Если алгоритм не обрабатывает не-скобочные символы правильно, определите правила их обработки в соответствии с требованиями задачи. Убедитесь, что поведение зафиксировано в документации и тестах.

## Частые вопросы

**Вопрос:** Какой подход самый быстрый?

**Ответ:** Подход с использованием `Stack` или `Deque` является самым быстрым, обеспечивая линейную временную сложность `O(n)`. Подход с `String.replaceAll()` имеет квадратичную сложность `O(n²)` и может быть медленным для длинных строк.

**Вопрос:** Можно ли использовать простой счётчик вместо стека для круглых скобок?

**Ответ:** Да, для случая только круглых скобок можно использовать простой счётчик вместо стека, что упрощает реализацию и снижает потребление памяти. Однако для смешанных типов скобок необходим стек для проверки соответствия типов.

**Вопрос:** Как обрабатывать строки с другими символами, не являющимися скобками?

**Ответ:** Обработка зависит от требований задачи. Вы можете либо игнорировать такие символы, либо считать строку несбалансированной. Важно зафиксировать это поведение в документации метода.

**Вопрос:** Что возвращать для пустой строки?

**Ответ:** Пустая строка обычно считается сбалансированной, так как в ней нет несбалансированных скобок. Однако это зависит от конкретных требований задачи и должно быть зафиксировано в документации.

**Вопрос:** Можно ли использовать `Stack` вместо `Deque`?

**Ответ:** Технически да, но `Stack` является устаревшим классом в `Java`, и рекомендуется использовать `Deque` вместо него. `Deque` предоставляет более современный и гибкий интерфейс для работы со стеком.

## Глоссарий терминов

`Сбалансированные скобки` — скобки, которые правильно расставлены в строке, где каждая открывающая скобка имеет соответствующую закрывающую скобку в правильном порядке и типе.

`Стек (Stack)` — структура данных, которая следует принципу «последним пришёл — первым вышел» (`LIFO`), используемая для отслеживания открывающих скобок.

`Deque` — двухсторонняя очередь, которая позволяет добавлять и удалять элементы с обоих концов, часто используемая как стек или очередь.

`Язык Дайка` — формальный язык, который описывает правильно сбалансированные скобки.

`Вложенность скобок` — свойство скобок, когда одни скобки находятся внутри других, и все они правильно сбалансированы.

`Открывающая скобка` — символ, который начинает пару скобок: `(`, `[`, `{`.

`Закрывающая скобка` — символ, который завершает пару скобок: `)`, `]`, `}`.

`Парность скобок` — свойство скобок, когда каждая открывающая скобка имеет соответствующую закрывающую скобку того же типа.

`LIFO` — принцип «последним пришёл — первым вышел», используемый в структуре данных стек.

`Временная сложность` — количество операций, которое выполняет алгоритм в зависимости от размера входных данных.

### Пример 1: Проверка с подсчётом позиций ошибок

public int findFirstUnbalancedPosition(String str) {
    if (str == null) {
        return -1;
    }

    Deque<Character> stack = new LinkedList<>();
    Map<Character, Character> brackets = new HashMap<>();
    brackets.put(')', '(');
    brackets.put(']', '[');
    brackets.put('}', '{');

    for (int i = 0; i < str.length(); i++) {
        char ch = str.charAt(i);
        if (brackets.containsValue(ch)) {
            stack.push(ch);
        } else if (brackets.containsKey(ch)) {
            if (stack.isEmpty() || stack.pop() != brackets.get(ch)) {
                return i; // Позиция несбалансированной скобки
            }
        }
    }

    return stack.isEmpty() ? -1 : str.length(); // -1 если сбалансировано

    }
