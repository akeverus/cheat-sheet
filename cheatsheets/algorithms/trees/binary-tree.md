# Бинарное дерево (`Binary Tree`)

**Дата последнего обновления:** 2026-02-06

Бинарное дерево — это рекурсивная структура данных, в которой каждый узел может иметь не более двух дочерних элементов. Эта структура данных является основой для многих алгоритмов и используется в различных областях информатики. В этом документе рассматриваются основные операции работы с бинарным деревом: вставка, поиск, удаление и различные способы обхода дерева.

## Описание структуры данных

В этом руководстве мы рассмотрим реализацию двоичного дерева в `Java`. Для этого руководства мы будем использовать отсортированное двоичное дерево, содержащее значения `int`. Бинарное дерево — это рекурсивная структура данных, в которой каждый узел может иметь не более двух дочерних элементов. Распространённым типом бинарного дерева является бинарное дерево поиска (`BST`), в котором каждый узел имеет значение, которое больше или равно значениям узлов в левом поддереве и меньше или равно значениям узлов в правом поддереве. Такая структура обеспечивает эффективность операций поиска, вставки и удаления элементов.

### Визуализация

```text
        6
      /   \
     4     8
    / \   / \
   3   5 7   9
```

## Реализация на Java

### Реализация узла

Для реализации мы будем использовать вспомогательный класс `Node`, который будет хранить значения `int` и сохранять ссылку на каждого дочернего элемента. Затем мы добавим начальный узел нашего дерева, обычно называемый корнем (`root`). Корень является точкой входа в дерево и используется для доступа ко всем остальным узлам.

```java
// Узел бинарного дерева: значение и ссылки на левого/правого потомка
class Node {
    int value;
    Node left;
    Node right;
    
    Node(int value) {
        this.value = value;
        right = null;
        left = null;
    }
}
```

```java
public class BinaryTree {
    Node root;
}
```

## Операции с деревом

Теперь давайте посмотрим на наиболее распространенные операции, которые мы можем выполнять с бинарным деревом.

### Вставка узлов

Первая операция, которую мы рассмотрим, - это вставка новых узлов.

Во‑первых, мы должны найти место, где мы хотим добавить новый узел, чтобы сохранить сортировку дерева. Мы будем следовать этим правилам, начиная с корневого узла: если значение нового узла ниже, чем значение текущего узла, мы переходим к левому дочернему элементу; если значение нового узла больше, чем значение текущего узла, мы переходим к правому дочернему элементу; когда текущий узел равен `null`, мы достигли конечного узла и можем вставить новый узел в эту позицию. Затем мы создадим рекурсивный метод для вставки:

```java
private Node addRecursive(Node current, int value) {
    if (current == null) {
        return new Node(value);
    }
    
    if (value < current.value) {
        current.left = addRecursive(current.left, value);
    } else if (value > current.value) {
        current.right = addRecursive(current.right, value);
    } else {
        return current;
    }
    
    return current;
}
```

**Далее мы создадим общедоступный метод, который запускает рекурсию с корневого узла:**

```java
public void add(int value) {
    root = addRecursive(root, value);
}
```

**Давайте посмотрим, как мы можем использовать этот метод для создания дерева из нашего примера:**

```java
private BinaryTree createBinaryTree() {
    BinaryTree bt = new BinaryTree();
    
    bt.add(6);
    bt.add(4);
    bt.add(8);
    bt.add(3);
    bt.add(5);
    bt.add(7);
    bt.add(9);
    
    return bt;
}
```

### Поиск узла

Теперь добавим метод для проверки наличия в дереве определенного значения.

**Как и раньше, мы сначала создадим рекурсивный метод, который проходит по дереву:**

```java
private boolean containsNodeRecursive(Node current, int value) {
    if (current == null) {
        return false;
    }
    
    if (value == current.value) {
        return true;
    }
    
    return value < current.value
        ? containsNodeRecursive(current.left, value)
        : containsNodeRecursive(current.right, value);
}
```

Здесь мы ищем значение, сравнивая его со значением в текущем узле; затем мы продолжим в левом или правом дочернем элементе в зависимости от результата.

**Далее мы создадим общедоступный метод, который начинается с корня:**

```java
public boolean containsNode(int value) {
    return containsNodeRecursive(root, value);
}
```

**Затем мы создадим простой тест, чтобы убедиться, что дерево действительно содержит вставленные элементы:**

```java
@Test
public void givenABinaryTree_WhenAddingElements_ThenTreeContainsThoseElements() {
    BinaryTree bt = createBinaryTree();
    
    assertTrue(bt.containsNode(6));
    assertTrue(bt.containsNode(4));
    assertFalse(bt.containsNode(1));
}
```

Все добавленные узлы должны содержаться в дереве.

### Удаление узла

Другой распространенной операцией является удаление узла из дерева.

**Во-первых, мы должны найти удаляемый узел так же, как и раньше:**

```java
private Node deleteRecursive(Node current, int value) {
    if (current == null) {
        return null;
    }
    
    if (value == current.value) {
        // Узел для удаления найден
    }
    
    if (value < current.value) {
        current.left = deleteRecursive(current.left, value);
        return current;
    }
    
    current.right = deleteRecursive(current.right, value);
    return current;
}
```

**Как только мы находим узел для удаления, есть 3 основных разных случая:**

1. **узел не имеет потомков** - это самый простой случай; нам просто нужно заменить этот узел на **null** в его родительском узле
2. **у узла есть ровно один дочерний элемент** - в родительском узле мы заменяем этот узел его единственным дочерним элементом
3. **узел имеет двух детей** - это самый сложный случай, потому что он требует реорганизации дерева

**Давайте посмотрим, как бы мы реализовали первый случай, когда узел является листовым узлом:**

```java
if (current.left == null && current.right == null) {
    return null;
}
```

**Теперь продолжим со случаем, когда у узла есть один дочерний элемент:**

```java
if (current.right == null) {
    return current.left;
}

if (current.left == null) {
    return current.right;
}
```

Здесь мы возвращаем ненулевой дочерний элемент, чтобы его можно было назначить родительскому узлу.

Наконец, нам нужно обработать случай, когда у узла есть два потомка.

**Во-первых, нам нужно найти узел, который заменит удаленный узел. Мы будем использовать наименьший узел правого поддерева узла, который скоро будет удален:**

```java
private int findSmallestValue(Node root) {
    return root.left == null ? root.value : findSmallestValue(root.left);
}
```

**Затем мы присваиваем наименьшее значение удаляемому узлу, после чего удаляем его из правого поддерева:**

```java
int smallestValue = findSmallestValue(current.right);
current.value = smallestValue;
current.right = deleteRecursive(current.right, smallestValue);
return current;
```

**Наконец, мы создадим общедоступный метод, который запускает удаление из корня:**

```java
public void delete(int value) {
    root = deleteRecursive(root, value);
}
```

**Теперь давайте проверим, что удаление сработало как положено:**

```java
@Test
public void givenABinaryTree_WhenDeletingElements_ThenTreeDoesNotContainThoseElements() {
    BinaryTree bt = createBinaryTree();
    
    assertTrue(bt.containsNode(9));
    bt.delete(9);
    assertFalse(bt.containsNode(9));
}
```

## Реализация на Kotlin

В `Kotlin` бинарное дерево может быть реализовано следующим образом. Использование `data class` для узла упрощает создание и работу с узлами дерева, а использование nullable типов позволяет корректно обрабатывать отсутствие дочерних элементов.

```kotlin
data class Node(
    var value: Int,
    var left: Node? = null,
    var right: Node? = null
)

class BinaryTree {
    var root: Node? = null

    fun add(value: Int) {
        root = addRecursive(root, value)
    }

    private fun addRecursive(current: Node?, value: Int): Node {
        if (current == null) {
            return Node(value)
        }

        when {
            value < current.value -> current.left = addRecursive(current.left, value)
            value > current.value -> current.right = addRecursive(current.right, value)
        }

        return current
    }

    fun containsNode(value: Int): Boolean {
        return containsNodeRecursive(root, value)
    }

    private fun containsNodeRecursive(current: Node?, value: Int): Boolean {
        if (current == null) {
            return false
        }

        return when {
            value == current.value -> true
            value < current.value -> containsNodeRecursive(current.left, value)
            else -> containsNodeRecursive(current.right, value)
        }
    }

    fun delete(value: Int) {
        root = deleteRecursive(root, value)
    }

    private fun deleteRecursive(current: Node?, value: Int): Node? {
        if (current == null) {
            return null
        }

        when {
            value == current.value -> {
                when {
                    current.left == null && current.right == null -> return null
                    current.right == null -> return current.left
                    current.left == null -> return current.right
                    else -> {
                        val smallestValue = findSmallestValue(current.right!!)
                        current.value = smallestValue
                        current.right = deleteRecursive(current.right, smallestValue)
                        return current
                    }
                }
            }
            value < current.value -> {
                current.left = deleteRecursive(current.left, value)
                return current
            }
            else -> {
                current.right = deleteRecursive(current.right, value)
                return current
            }
        }
    }

    private fun findSmallestValue(root: Node): Int {
        return root.left?.let { findSmallestValue(it) } ?: root.value
    }
}
```

**Использование:**

```kotlin
fun main() {
    val bt = BinaryTree()
    bt.add(6)
    bt.add(4)
    bt.add(8)
    bt.add(3)
    bt.add(5)
    bt.add(7)
    bt.add(9)

    println(bt.containsNode(5)) // true
    bt.delete(5)
    println(bt.containsNode(5)) // false
}
```

## Обход дерева

В этом разделе мы рассмотрим различные способы обхода дерева, подробно рассмотрев поиск в глубину (`DFS`) и в ширину (`BFS`). Каждый тип обхода имеет свои особенности и применяется в различных ситуациях в зависимости от требований алгоритма.

### Inorder (Центрированный обход)

`Inorder` обход: левое поддерево → корень → правое поддерево. Этот тип обхода особенно полезен для бинарных деревьев поиска, так как он посещает узлы в отсортированном порядке. Это делает `inorder` обход идеальным для операций, требующих обработки элементов в порядке сортировки.

```java
public void traverseInOrder(Node node) {
    if (node != null) {
        traverseInOrder(node.left);
        System.out.print(" " + node.value);
        traverseInOrder(node.right);
    }
}
```

### Preorder (Прямой обход)

`Preorder` обход: корень → левое поддерево → правое поддерево. Этот тип обхода полезен для копирования структуры дерева или создания префиксного представления выражения. Корень обрабатывается первым, что позволяет сохранить структуру дерева при копировании.

```java
public void traversePreOrder(Node node) {
    if (node != null) {
        System.out.print(" " + node.value);
        traversePreOrder(node.left);
        traversePreOrder(node.right);
    }
}
```

### Postorder (Обратный обход)

`Postorder` обход: левое поддерево → правое поддерево → корень. Этот тип обхода полезен для удаления дерева или вычисления выражений в постфиксной нотации. Корень обрабатывается последним, что позволяет сначала обработать все дочерние элементы перед обработкой родительского узла.

```java
public void traversePostOrder(Node node) {
    if (node != null) {
        traversePostOrder(node.left);
        traversePostOrder(node.right);
        System.out.print(" " + node.value);
    }
}
```

### Level Order (Обход по уровням)

Обход по уровням использует очередь и является примером поиска в ширину (`BFS`). Этот тип обхода посещает все узлы на каждом уровне дерева перед переходом на следующий уровень, что полезно для операций, требующих обработки узлов по уровням, таких как печать дерева или поиск кратчайшего пути.

```java
public void traverseLevelOrder() {
    if (root == null) {
        return;
    }
    
    Queue<Node> nodes = new LinkedList<>();
    nodes.add(root);
    
    while (!nodes.isEmpty()) {
        Node node = nodes.remove();
        System.out.print(" " + node.value);
        
        if (node.left != null) {
            nodes.add(node.left);
        }
        
        if (node.right != null) {
            nodes.add(node.right);
        }
    }
}
```

## Сложность

### Временная сложность

| Операция | Средний случай | Худший случай |
|----------|----------------|---------------|
| Поиск | `O(log n)` | `O(n)` |
| Вставка | `O(log n)` | `O(n)` |
| Удаление | `O(log n)` | `O(n)` |
| Обход | `O(n)` | `O(n)` |

### Пространственная сложность

Пространственная сложность операций с бинарным деревом составляет `O(h)`, где `h` — высота дерева. Это связано с тем, что рекурсивные операции требуют памяти для стека вызовов, глубина которого равна высоте дерева. В худшем случае для вырожденного дерева (список) пространственная сложность составляет `O(n)`, так как высота дерева равна количеству узлов. В лучшем случае для сбалансированного дерева пространственная сложность составляет `O(log n)`, что делает операции эффективными для таких структур.

## Особенности

Бинарное дерево имеет несколько важных особенностей. Рекурсивная структура означает, что каждое поддерево само является бинарным деревом, что делает рекурсивные алгоритмы естественным выбором для работы с деревом. Сортировка в бинарном дереве поиска автоматически поддерживается благодаря правилам вставки элементов, что обеспечивает эффективность операций поиска. Гибкость структуры позволяет легко расширять её для различных операций, таких как обходы, поиск минимального и максимального элементов, и других специализированных операций.

## Применение

Бинарные деревья используются в различных областях. В базах данных бинарные деревья применяются для создания индексов, которые обеспечивают быстрый поиск записей по ключам. В файловых системах бинарные деревья используются для организации структуры каталогов и быстрого доступа к файлам. В компиляторах бинарные деревья применяются для представления синтаксических деревьев, которые используются для анализа и преобразования исходного кода. В выражениях бинарные деревья используются для представления деревьев выражений, что позволяет эффективно вычислять и оптимизировать выражения. В алгоритмах сжатия бинарные деревья используются для создания деревьев Хаффмана, которые обеспечивают эффективное сжатие данных.

## Когда использовать

Выбор между бинарным деревом и другими структурами данных зависит от конкретных требований приложения. Используйте бинарное дерево, когда нужна быстрая вставка и поиск, данные должны быть отсортированы, нужна гибкая структура данных, и важна производительность поиска. Бинарное дерево особенно эффективно, когда операции поиска выполняются чаще, чем операции вставки и удаления, и когда требуется поддержание отсортированного порядка элементов.

Альтернативы включают `HashSet`/`HashMap` для `O(1)` поиска без сортировки, что делает их подходящими для случаев, когда порядок элементов не важен. `SortedSet`/`SortedMap` обеспечивают автоматическую сортировку с балансировкой, что делает их более эффективными для часто изменяющихся данных. Массивы подходят для простых случаев с фиксированным размером, где не требуется динамическое изменение структуры данных.

## Лучшие практики

Балансировка критически важна для эффективности бинарного дерева. Несбалансированное `BST` вырождается в список при упорядоченной вставке — `O(n)` высота; для гарантированного `O(log n)` используйте `AVL`, красно‑чёрное дерево или `TreeMap`. Это особенно важно для приложений, где порядок вставки элементов может быть предсказуемым или контролируемым.

Дубликаты требуют явного решения при проектировании структуры данных. Решите, разрешены ли дубликаты; при запрете используйте `<=` или `>=` при вставке для однозначного размещения; при разрешении — храните счётчик в узле или поддерево «равных» справа/слева. Это решение влияет на поведение операций поиска и удаления, поэтому важно документировать выбранный подход.

Рекурсия против итерации — важное решение при реализации операций с деревом. Рекурсивные вставка/поиск/удаление читаемы, но при большой высоте возможен переполнение стека; для продакшена рассмотрите итеративную реализацию. Итеративный подход особенно важен для приложений, работающих с большими деревьями или в средах с ограниченным размером стека.

Удаление требует особого внимания при работе с узлами, имеющими двух детей. При удалении узла с двумя детьми подставляйте минимум правого поддерева (или максимум левого) и рекурсивно удаляйте подставленный узел; обрабатывайте случай одного/нуля детей. Это гарантирует сохранение свойств бинарного дерева поиска после операции удаления.

Тестирование должно покрывать все возможные сценарии работы с деревом. Проверьте пустое дерево, один узел, вставку в возрастающем/убывающем порядке, поиск отсутствующего элемента, удаление листа/узла с одним ребёнком/с двумя детьми. Это гарантирует корректность работы алгоритма во всех возможных ситуациях и помогает выявить потенциальные проблемы на раннем этапе разработки.


## Решение проблем

| Симптом | Возможная причина | Решение |
|--------|-------------------|---------|
| `NullPointerException` при обходе | Не проверяется `null` для потомков | Всегда проверяйте `node != null` перед обращением к `left`/`right` |
| `StackOverflowError` при глубоком дереве | Рекурсивный обход на несбалансированном дереве (глубина ~10000+) | Заменить рекурсию на итеративный обход со стеком; увеличить `-Xss` |
| BFS возвращает неверный порядок | Используется `Stack` вместо `Queue` | Для обхода в ширину использовать `LinkedList` или `ArrayDeque` как `Queue` |

## Частые вопросы

**Чем бинарное дерево отличается от бинарного дерева поиска?** В бинарном дереве нет ограничений на значения узлов — любой узел может содержать любое значение. В BST левое поддерево содержит значения меньше корня, правое — больше. BST позволяет искать за `O(log n)`, обычное бинарное дерево — за `O(n)`.

**Когда использовать дерево вместо массива?** Дерево подходит для иерархических данных (файловая система, DOM, AST), а также когда нужны частые вставки/удаления в середину. Массив лучше для последовательного доступа и когда важна локальность кэша.

**Как выбрать между DFS и BFS для обхода?** DFS (глубина) подходит для поиска пути, проверки свойств поддеревьев, экономит память при широком дереве. BFS (ширина) подходит для поиска ближайшего элемента, обхода по уровням, работы с неглубокими деревьями.
