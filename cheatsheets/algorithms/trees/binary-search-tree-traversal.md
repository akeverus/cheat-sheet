# Обход бинарного дерева поиска (Binary Search Tree Traversal)

Обход бинарного дерева поиска может выполняться тремя основными способами: `Inorder` (слева-корень-справа), `Preorder` (корень-слева-справа), и `Postorder` (слева-справа-корень). Каждый тип обхода имеет свои особенности и применяется в различных ситуациях в зависимости от требований алгоритма. Понимание различных способов обхода дерева критически важно для эффективной работы с бинарными деревьями поиска и реализации различных алгоритмов.

## Описание бинарного дерева поиска

В этом руководстве вы узнаете, что такое бинарное дерево поиска, из каких частей состоит дерево, а также некоторые общие термины, которые мы используем при описании частей дерева. Мы также увидим, как пройти по дереву, используя некоторые распространённые алгоритмы — все проиллюстрировано наглядными примерами.

### Что такое бинарное дерево поиска?

Бинарное дерево поиска (`BST`) — это бинарное дерево, состоящее из узлов. Каждый узел имеет ключ, обозначающий его значение. Значение узлов в левом поддереве меньше значения корневого узла. И значение узлов в правом поддереве больше, чем значение корневого узла. Корневой узел является родительским узлом обоих поддеревьев. Такая структура обеспечивает эффективность операций поиска, вставки и удаления элементов.

### Визуализация

```text
         A
      /     \
     B       C
    / \     / \
   D   E   F   G
  / \
 H   I
```

## Терминология

Давайте посмотрим на отношения между узлами в примере выше. Узел `A` является корневым узлом. Левое поддерево начинается с `B`, а правое поддерево начинается с `C`. У узла `A` есть два дочерних узла — `B` и `C`. Узел `C` является родительским узлом для `F` и `G`. `F` и `G` являются братьями и сёстрами. Узлы `F` и `G` называются конечными узлами (листьями), потому что у них нет потомков. Узел `B` является родительским узлом для `D` и `E`. Узел `D` является родительским узлом для `H` и `I`. `D` и `E` являются братьями и сёстрами, а также `H` и `I`. Узел `E` является листовым узлом.

Итак, вот несколько важных терминов, которые мы только что использовали для описания дерева выше. Корень — это самый верхний узел в дереве, который является точкой входа для доступа ко всем остальным узлам. Родитель — это узел с дочерним элементом или дочерними элементами, который связан с другими узлами через отношения родитель-потомок. Дочерний — это узел, расширенный из другого узла (родительского узла), который находится на уровень ниже родителя. Лист — это узел без дочернего элемента, который является конечной точкой в структуре дерева. Братья и сёстры — это узлы с общим родителем, которые находятся на одном уровне в иерархии дерева.

## Для чего используется бинарное дерево поиска?

Деревья бинарного поиска помогают нам ускорить наш бинарный поиск, поскольку мы можем быстрее находить элементы. Мы можем использовать бинарное дерево поиска для добавления и удаления элементов в дереве. Мы также можем представить данные в ранжированном порядке, используя двоичное дерево. А в некоторых случаях его можно использовать как диаграмму для представления набора информации. Структура `BST` обеспечивает эффективность операций поиска, вставки и удаления, что делает её полезной для различных приложений, требующих быстрого доступа к данным.

## Типы обходов

Далее мы рассмотрим некоторые приемы, используемые при обходе бинарного дерева.

### Что такое обход дерева?

Обход дерева означает посещение и вывод значения каждого узла в определённом порядке. В этом уроке мы будем использовать методы обхода дерева `Inorder`, `Preorder` и `Postorder`. Основное значение обхода дерева заключается в том, что существует несколько способов выполнения операций обхода, в отличие от линейных структур данных, таких как массивы, растровые изображения, матрицы, где обход выполняется в линейном порядке.

Каждый из этих методов обхода дерева имеет определённый порядок. `Inorder` — вы переходите от левого поддерева к корню, а затем к правому поддереву. `Preorder` — вы переходите от корня к левому поддереву, а затем к правому поддереву. `Postorder` — вы переходите от левого поддерева к правому поддереву, а затем к корню. Вот ещё один способ представления приведённой выше информации: `Inorder` => Слева, Корень, Справа; `Preorder` => Корень, Левый, Правый; `Postorder` => Влево, Вправо, Корень. Каждый тип обхода имеет свои особенности и применяется в различных ситуациях в зависимости от требований алгоритма.

## Реализация на Java

### Структура узла (Java)

```java
// Узел бинарного дерева поиска: ключ и ссылки на левое/правое поддерево
class Node {
    int key;
    Node left;
    Node right;

    Node(int key) {
        this.key = key;
        left = right = null;
    }
}
```

### Inorder обход (Центрированный)

Мы собираемся создать дерево, похожее на то, что было в предыдущем разделе, но на этот раз ключами узлов будут числа, а не буквы.

Помните, что значения узлов левого поддерева всегда меньше значения корневого узла. Кроме того, значения узлов в правом поддереве больше, чем значение корневого узла.

Напомним, что порядок неупорядоченного обхода: влево, корень, вправо.

Вот результат, который мы получаем после использования неупорядоченного обхода: `D, B, E, A, F, C, G`.

```java
void inorderTraversal(Node node) {
    if (node != null) {
        inorderTraversal(node.left);
        System.out.print(node.key + " ");
        inorderTraversal(node.right);
    }
}
```

Особенность: `Inorder` обход бинарного дерева поиска даёт элементы в отсортированном порядке, что делает его особенно полезным для операций, требующих обработки элементов в порядке возрастания.

### Preorder обход (Прямой)

Порядок здесь: корень, левый, правый.

**Используя ту же диаграмму выше, мы имеем:**

**A, B, D, E, C, F, G**

```java
void preorderTraversal(Node node) {
    if (node != null) {
        System.out.print(node.key + " ");
        preorderTraversal(node.left);
        preorderTraversal(node.right);
    }
}
```

Особенность: `Preorder` обход используется для копирования дерева или создания префиксного выражения. Корень обрабатывается первым, что позволяет сохранить структуру дерева при копировании и создании новых экземпляров дерева.

### Postorder обход (Обратный)

Порядок обхода почтового заказа: левый, правый, корень.

**Вот результат:**

**D, E, B, F, G, C, A**

```java
void postorderTraversal(Node node) {
    if (node != null) {
        postorderTraversal(node.left);
        postorderTraversal(node.right);
        System.out.print(node.key + " ");
    }
}
```

Особенность: `Postorder` обход используется для удаления дерева или создания постфиксного выражения. Корень обрабатывается последним, что позволяет сначала обработать все дочерние элементы перед обработкой родительского узла, что критически важно для корректного удаления дерева.

### Полная реализация

```java
public class BinaryTreeTraversal {
    Node root;

    BinaryTreeTraversal() {
        root = null;
    }

    void inorderTraversal(Node node) {
        if (node != null) {
            inorderTraversal(node.left);
            System.out.print(node.key + " ");
            inorderTraversal(node.right);
        }
    }

    void preorderTraversal(Node node) {
        if (node != null) {
            System.out.print(node.key + " ");
            preorderTraversal(node.left);
            preorderTraversal(node.right);
        }
    }

    void postorderTraversal(Node node) {
        if (node != null) {
            postorderTraversal(node.left);
            postorderTraversal(node.right);
            System.out.print(node.key + " ");
        }
    }

    // Обертки для вызова с корня
    void printInorder() {
        inorderTraversal(root);
    }

    void printPreorder() {
        preorderTraversal(root);
    }

    void printPostorder() {
        postorderTraversal(root);
    }
}
```

### Пример использования (Java)

```java
BinaryTreeTraversal tree = new BinaryTreeTraversal();
tree.root = new Node(1);
tree.root.left = new Node(2);
tree.root.right = new Node(3);
tree.root.left.left = new Node(4);
tree.root.left.right = new Node(5);

System.out.println("Inorder traversal:");
tree.printInorder();  // 4 2 5 1 3

System.out.println("\nPreorder traversal:");
tree.printPreorder();  // 1 2 4 5 3

System.out.println("\nPostorder traversal:");
tree.printPostorder();  // 4 5 2 3 1
```

### Итеративные версии (Java)

Итеративные версии обходов используют явный стек вместо рекурсии, что позволяет избежать переполнения стека вызовов для очень глубоких деревьев. Это особенно важно для вырожденных деревьев, где глубина может быть равна количеству узлов.

#### Inorder (с использованием стека)

```java
void inorderIterative(Node root) {
    Stack<Node> stack = new Stack<>();
    Node current = root;

    while (current != null || !stack.isEmpty()) {
        while (current != null) {
            stack.push(current);
            current = current.left;
        }
        current = stack.pop();
        System.out.print(current.key + " ");
        current = current.right;
    }
}
```

#### Preorder (с использованием стека)

```java
void preorderIterative(Node root) {
    if (root == null) return;

    Stack<Node> stack = new Stack<>();
    stack.push(root);

    while (!stack.isEmpty()) {
        Node node = stack.pop();
        System.out.print(node.key + " ");

        if (node.right != null) {
            stack.push(node.right);
        }
        if (node.left != null) {
            stack.push(node.left);
        }
    }
}
```

#### Postorder (с использованием двух стеков)

```java
void postorderIterative(Node root) {
    if (root == null) return;

    Stack<Node> stack1 = new Stack<>();
    Stack<Node> stack2 = new Stack<>();
    stack1.push(root);

    while (!stack1.isEmpty()) {
        Node node = stack1.pop();
        stack2.push(node);

        if (node.left != null) {
            stack1.push(node.left);
        }
        if (node.right != null) {
            stack1.push(node.right);
        }
    }

    while (!stack2.isEmpty()) {
        System.out.print(stack2.pop().key + " ");
    }
}
```

class BinaryTreeTraversalK {

    fun printPreorderK() = preorderTraversalK(root)

### Итеративные версии (Kotlin)

```kotlin
fun inorderIterativeK(root: NodeK?) {
    val stack = mutableListOf<NodeK>()
    var current = root

    while (current != null || stack.isNotEmpty()) {
        while (current != null) {
            stack.add(current)
            current = current.left
        }
        current = stack.removeAt(stack.size - 1)
        print("${current.key} ")
        current = current.right
    }
}

fun preorderIterativeK(root: NodeK?) {
    if (root == null) return

    val stack = mutableListOf(root)

    while (stack.isNotEmpty()) {
        val node = stack.removeAt(stack.size - 1)
        print("${node.key} ")

        node.right?.let { stack.add(it) }
        node.left?.let { stack.add(it) }
    }
}

fun postorderIterativeK(root: NodeK?) {
    if (root == null) return

    val stack1 = mutableListOf(root)
    val stack2 = mutableListOf<NodeK>()

    while (stack1.isNotEmpty()) {
        val node = stack1.removeAt(stack1.size - 1)
        stack2.add(node)

        node.left?.let { stack1.add(it) }
        node.right?.let { stack1.add(it) }
    }

    while (stack2.isNotEmpty()) {
        print("${stack2.removeAt(stack2.size - 1).key} ")
    }
}
```

## Сложность

### Временная сложность

Временная сложность всех типов обхода составляет `O(n)`, где `n` — количество узлов в дереве. Каждый узел посещается ровно один раз, что делает обход эффективным независимо от структуры дерева. Это означает, что независимо от того, является ли дерево сбалансированным или вырожденным, время обхода будет линейным по количеству узлов.

### Пространственная сложность

Пространственная сложность зависит от используемого подхода. Рекурсивные версии требуют `O(h)` памяти для стека вызовов, где `h` — высота дерева. Итеративные версии также требуют `O(h)` памяти для стека. В худшем случае для вырожденного дерева пространственная сложность составляет `O(n)`, так как глубина рекурсии или размер стека равен количеству узлов. В лучшем случае для сбалансированного дерева пространственная сложность составляет `O(log n)`, что делает обход эффективным для таких структур.

## Сравнение обходов

| Обход | Порядок | Применение |
|-------|---------|------------|
| `Inorder` | Лево Корень Право | Сортировка, получение элементов в порядке |
| `Preorder` | Корень Лево Право | Копирование дерева, префиксные выражения |
| `Postorder` | Лево Право Корень | Удаление дерева, постфиксные выражения |

Каждый тип обхода имеет свои особенности и применяется в различных ситуациях. `Inorder` обход особенно полезен для бинарных деревьев поиска, так как он посещает узлы в отсортированном порядке. `Preorder` обход полезен для копирования структуры дерева, так как корень обрабатывается первым. `Postorder` обход необходим для корректного удаления дерева, так как дочерние элементы обрабатываются перед родительским узлом.

## Особенности

Обходы дерева имеют несколько важных особенностей. `Inorder` обход для `BST` даёт элементы в отсортированном порядке, что делает его особенно полезным для операций, требующих обработки элементов в порядке возрастания. `Preorder` обход всегда начинается с корня, что делает первый элемент всегда корневым узлом. `Postorder` обход всегда заканчивается корнем, что делает последний элемент всегда корневым узлом. Универсальность всех трёх обходов заключается в том, что они работают с любым бинарным деревом, независимо от его структуры и баланса.

## Применение

Обходы дерева используются в различных областях. В вычислении выражений обходы используются для обработки префиксных, инфиксных и постфиксных выражений, что позволяет эффективно вычислять математические выражения, представленные в виде дерева. В копировании и сериализации деревьев обходы позволяют создать точную копию структуры дерева или преобразовать дерево в последовательный формат для хранения или передачи. В удалении деревьев обходы обеспечивают корректное освобождение памяти, обрабатывая дочерние элементы перед родительскими узлами. В поиске элементов обходы позволяют найти элементы, удовлетворяющие определённым условиям. В валидации структуры дерева обходы используются для проверки корректности структуры и свойств дерева.

## Когда использовать

Выбор типа обхода зависит от конкретных требований алгоритма и структуры данных. Используйте `Inorder`, когда нужны элементы в отсортированном порядке (для `BST`), вычисляете инфиксные выражения, и нужна валидация `BST`. Этот тип обхода особенно эффективен для бинарных деревьев поиска, так как он естественным образом посещает узлы в порядке сортировки.

Используйте `Preorder`, когда копируете дерево, создаёте префиксные выражения, и нужно быстро получить структуру дерева. Корень обрабатывается первым, что позволяет сохранить структуру дерева при копировании и создании новых экземпляров.

Используйте `Postorder`, когда удаляете дерево, вычисляете постфиксные выражения, и нужно обработать дочерние узлы перед родительским. Корень обрабатывается последним, что критически важно для корректного удаления дерева и освобождения памяти.

## Лучшие практики

`Inorder` для `BST` — это важное правило при работе с бинарными деревьями поиска. `Inorder` обход `BST` даёт элементы в отсортированном порядке; используйте его для валидации `BST` или вывода в порядке возрастания. Это свойство делает `inorder` обход особенно полезным для операций, требующих обработки элементов в отсортированном порядке.

Рекурсия против стека — важное решение при реализации обходов. Рекурсивные реализации компактны и легко читаются; для очень глубоких деревьев предпочитайте итеративный обход со стеком, чтобы избежать переполнения стека. Это особенно важно для вырожденных деревьев, где глубина может быть равна количеству узлов.

Один проход может быть эффективнее, чем несколько отдельных обходов. При необходимости нескольких обходов (например, `inorder` и `preorder`) можно совместить в одном проходе, передавая список для накопления результатов. Это позволяет уменьшить количество проходов по дереву и улучшить производительность алгоритма.

Null-безопасность критически важна для корректной работы алгоритма. Явно проверяйте узел на `null` перед обращением к полям; в `Kotlin` используйте nullable-типы и безопасные вызовы. Это позволяет избежать ошибок при работе с пустыми поддеревьями и обеспечивает корректность алгоритма во всех случаях.

Тестирование должно покрывать все возможные сценарии работы с деревом. Покройте случаи: пустое дерево, один узел, только левая/правая ветвь, полное дерево. Это гарантирует, что алгоритм работает корректно во всех возможных ситуациях и позволяет выявить потенциальные проблемы на раннем этапе разработки.


## Решение проблем

| Симптом | Возможная причина | Решение |
|--------|-------------------|---------|
| In-order обход возвращает неотсортированный результат | Дерево не является BST или нарушена структура | Проверить, что все вставки корректно размещают узлы (left < root < right) |
| `StackOverflowError` при обходе | Дерево вырожденное (все элементы в одну сторону) | Использовать итеративный обход с явным стеком (`Deque<Node>`) |
| Итератор пропускает элементы | Модификация дерева во время обхода | Не вставлять/удалять узлы во время итерации; при необходимости — собрать результат в список |

## Частые вопросы

**В чём разница между in-order, pre-order и post-order?** In-order (лево-корень-право) возвращает отсортированную последовательность в BST. Pre-order (корень-лево-право) удобен для копирования дерева. Post-order (лево-право-корень) — для удаления дерева и вычислений, зависящих от потомков.

**Как итеративно реализовать in-order обход?** Используйте стек: идите влево до конца, кладя узлы в стек. Когда дошли до `null` — извлеките узел, обработайте его, перейдите в правое поддерево. Это `O(n)` по времени и `O(h)` по памяти, где `h` — высота дерева.

**Когда нужен обход Morris (без стека)?** Когда критична память и нельзя использовать `O(h)` дополнительной памяти. Morris traversal модифицирует дерево временно (threaded tree), давая `O(1)` по памяти, но сложнее в реализации.


## Заключение

В этом руководстве мы рассмотрели три основных способа обхода бинарного дерева поиска: `Inorder`, `Preorder` и `Postorder`. Каждый обход имеет свои особенности и применения. Понимание этих обходов важно для работы с деревьями и реализации различных алгоритмов. Выбор конкретного типа обхода зависит от требований алгоритма и структуры данных, поэтому важно понимать особенности каждого типа обхода и их применение в различных ситуациях.
