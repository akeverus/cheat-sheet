# Алгоритм Борувки (`Borůvka's Algorithm`)

Алгоритм Борувки — это алгоритм для нахождения минимального остовного дерева (`MST`) графа, взвешенного по рёбрам. Предшествует алгоритмам Прима и Крускала. Временная сложность `O(E log V)`.

## История алгоритма

В этом уроке мы рассмотрим `Java`‑реализацию алгоритма Борувки для нахождения минимального остовного дерева (`MST`) графа, взвешенного по рёбрам. Он предшествует алгоритмам Прима и Крускала, но всё же может считаться чем‑то средним между ними. Способ нахождения `MST` данного графа был впервые сформулирован Отакаром Борувкой в `1926` году. Это было задолго до того, как появились компьютеры, и фактически он был смоделирован для разработки эффективной системы распределения электроэнергии. Жорж Соллен заново открыл его в `1965` году и использовал в параллельных вычислениях.

## Описание алгоритма

Основная идея алгоритма состоит в том, чтобы начать с набора деревьев, каждая вершина которого представляет собой изолированное дерево. Затем нам нужно продолжать добавлять ребра, чтобы уменьшить количество изолированных деревьев, пока у нас не получится одно связанное дерево.

## Принцип работы

Давайте рассмотрим это по шагам на примере графа. На шаге `0` создаётся граф. На шаге `1` начинаем с набора несвязанных деревьев, где количество деревьев равно количеству вершин. На шаге `2`, пока есть несвязанные деревья, для каждого несвязанного дерева находим его ребро с меньшим весом и добавляем это ребро, чтобы соединить другое дерево. Этот процесс повторяется до тех пор, пока не останется одно связанное дерево, которое и будет минимальным остовным деревом.

### Пример работы

```text
Исходный граф:
    0---8---1
   /|      /|
  5 |     9 |
 /  |    /  |
2   |   3   |
 \  |    \  |
  15|    11 |
   \|      \|
    3---7---4
```

На каждой итерации каждое дерево находит своё минимальное ребро, которое соединяет его с другим деревом. Найденные рёбра добавляются в `MST`, и деревья объединяются в более крупные компоненты. Процесс повторяется до получения одного дерева, которое покрывает все вершины графа и имеет минимальный общий вес.

## Реализация на Java

### Реализация

Теперь давайте посмотрим, как мы можем реализовать это на `Java`.

### Класс UnionFind (Java)

Для начала нам нужна структура данных для хранения родителей и рангов наших вершин. Для этой цели определим класс `UnionFind` с двумя методами: `union` и `find`:

```java
// Непересекающиеся множества с рангами для объединения компонент в алгоритме Борувки
public class UnionFind {
    private int[] parents;
    private int[] ranks;
    
    public UnionFind(int n) {
        parents = new int[n];
        ranks = new int[n];
        for (int i = 0; i < n; i++) {
            parents[i] = i;
            ranks[i] = 0;
        }
    }
    
    public int find(int u) {
        while (u != parents[u]) {
            u = parents[u];
        }
        return u;
    }
    
    public void union(int u, int v) {
        int uParent = find(u);
        int vParent = find(v);
        
        if (uParent == vParent) {
            return;
        }
        
        if (ranks[uParent] < ranks[vParent]) {
            parents[uParent] = vParent;
        } else if (ranks[uParent] > ranks[vParent]) {
            parents[vParent] = uParent;
        } else {
            parents[vParent] = uParent;
            ranks[uParent]++;
        }
    }
}
```

Мы можем думать об этом классе как о вспомогательной структуре для поддержания отношений между нашими вершинами и постепенного построения нашего `MST`. Чтобы узнать, принадлежат ли две вершины `u` и `v` одному и тому же дереву, мы смотрим, возвращает ли `find(u)` того же родителя, что и `find(v)`. Метод объединения используется для объединения деревьев, что позволяет постепенно строить минимальное остовное дерево.

### Инициализация графа

Теперь нам нужен способ получить вершины и ребра графа от пользователя и сопоставить их с объектами, которые мы можем использовать в нашем алгоритме во время выполнения.

Так как мы будем использовать `JUnit` для проверки нашего алгоритма, эта часть выполняется в методе `@Before`:

```java
@BeforeEach
public void setup() {

    graph.putEdgeValue(0, 1, 8);
    graph.putEdgeValue(0, 2, 5);
    graph.putEdgeValue(1, 2, 9);
    graph.putEdgeValue(1, 3, 11);
    graph.putEdgeValue(2, 3, 15);
    graph.putEdgeValue(2, 4, 10);
    graph.putEdgeValue(3, 4, 7);

```

Здесь мы использовали `MutableValueGraph<Integer, Integer>` от `Guava` для хранения нашего графа. Затем мы использовали `ValueGraphBuilder` для построения неориентированного взвешенного графа. Метод `putEdgeValue` принимает три аргумента: два `Integer` для вершин и третий `Integer` для веса, как указано в объявлении универсального типа `MutableValueGraph`.

### Класс BoruvkaMST

Наконец, мы подошли к сути дела, реализации алгоритма. Мы сделаем это в классе, который назовём `BoruvkaMST`. Во‑первых, давайте объявим пару переменных экземпляра:

```java
public class BoruvkaMST {
    private static MutableValueGraph<Integer, Integer> mst = ValueGraphBuilder.undirected().build();
    private static int totalWeight;
    
    public MutableValueGraph<Integer, Integer> getMST() {
        return mst;
    }
    
    public int getTotalWeight() {
        return totalWeight;
    }
}
```

Как мы видим, здесь мы используем `MutableValueGraph<Integer, Integer>` для представления `MST`.

### Конструктор с алгоритмом

Во‑вторых, мы определим конструктор, в котором происходит вся магия. Он принимает один аргумент — граф, который мы построили ранее. Первое, что он делает, это инициализирует `UnionFind` вершин входного графа. Изначально все вершины являются своими родителями, ранг каждой равен `0`:

```java
public BoruvkaMST(MutableValueGraph<Integer, Integer> graph) {
    int size = graph.nodes().size();
    UnionFind uf = new UnionFind(size);
    totalWeight = 0;
    
    // Основной цикл алгоритма
    for (int t = 1; t < size && mst.edges().size() < size - 1; t = t + t) {
        EndpointPair<Integer>[] closestEdgeArray = new EndpointPair[size];
        
        // Находим минимальное ребро для каждого дерева
        for (EndpointPair<Integer> edge : graph.edges()) {
            int u = edge.nodeU();
            int v = edge.nodeV();
            int uParent = uf.find(u);
            int vParent = uf.find(v);
            
            if (uParent == vParent) {
                continue;
            }
            
            int weight = graph.edgeValueOrDefault(u, v, 0);
            
            if (closestEdgeArray[uParent] == null) {
                closestEdgeArray[uParent] = edge;
            }
            
            if (closestEdgeArray[vParent] == null) {
                closestEdgeArray[vParent] = edge;
            }
            
            int uParentWeight = graph.edgeValueOrDefault(
                closestEdgeArray[uParent].nodeU(),
                closestEdgeArray[uParent].nodeV(), 0);
            
            int vParentWeight = graph.edgeValueOrDefault(
                closestEdgeArray[vParent].nodeU(),
                closestEdgeArray[vParent].nodeV(), 0);
            
            if (weight < uParentWeight) {
                closestEdgeArray[uParent] = edge;
            }
            
            if (weight < vParentWeight) {
                closestEdgeArray[vParent] = edge;
            }
        }
        
        // Добавляем найденные ребра в MST
        for (int i = 0; i < size; i++) {
            EndpointPair<Integer> edge = closestEdgeArray[i];
            if (edge != null) {
                int u = edge.nodeU();
                int v = edge.nodeV();
                int weight = graph.edgeValueOrDefault(u, v, 0);
                
                if (uf.find(u) != uf.find(v)) {
                    mst.putEdgeValue(u, v, weight);
                    totalWeight += weight;
                    uf.union(u, v);
                }
            }
        }
    }
}
```

Далее мы создаём цикл, определяющий количество итераций, необходимых для создания `MST` — не более `log V` раз или до тех пор, пока у нас не будет рёбер `V - 1`, где `V` — количество вершин. Здесь мы также инициализируем массив рёбер, `closestEdgeArray` — для хранения ближайших рёбер с меньшим весом. После этого мы определим внутренний цикл `for` для перебора всех рёбер графа, чтобы заполнить наш ближайший `EdgeArray`. Если родители двух вершин одинаковы, это одно и то же дерево, и мы не добавляем его в массив. В противном случае мы сравниваем вес текущего ребра с весом рёбер его родительских вершин. Если меньше, то добавляем в ближайший `EdgeArray`. Затем мы определим второй внутренний цикл для создания дерева. Мы добавим к этому дереву рёбра из предыдущего шага, не добавляя одно и то же ребро дважды. Кроме того, мы выполним объединение нашего `UnionFind`, чтобы получить и сохранить родителей и ранги вершин вновь созданных деревьев. После повторения этих шагов не более `log V` раз или до тех пор, пока у нас не будет рёбер `V - 1`, результирующее дерево будет нашим `MST`.

## Реализация на Kotlin

### Класс UnionFind (Kotlin)

```kotlin
class UnionFindK(private val n: Int) {
    private val parents = IntArray(n) { it }
    private val ranks = IntArray(n) { 0 }
    
    fun find(u: Int): Int {
        var current = u
        while (current != parents[current]) {
            current = parents[current]
        }
        return current
    }
    
    fun union(u: Int, v: Int) {
        val uParent = find(u)
        val vParent = find(v)
        
        if (uParent == vParent) return
        
        when {
            ranks[uParent] < ranks[vParent] -> parents[uParent] = vParent
            ranks[uParent] > ranks[vParent] -> parents[vParent] = uParent
            else -> {
                parents[vParent] = uParent
                ranks[uParent]++
            }
        }
    }
}
```

### Алгоритм Борувки

```kotlin
data class EdgeK(val u: Int, val v: Int, val weight: Int)

class BoruvkaMSTK {
    private val mst = mutableListOf<EdgeK>()
    private var totalWeight = 0
    
    fun getMST(graph: Map<Int, List<Pair<Int, Int>>>, vertexCount: Int): List<EdgeK> {
        val unionFind = UnionFindK(vertexCount)
        var treeCount = vertexCount
        
        while (treeCount > 1) {
            val cheapest = IntArray(vertexCount) { -1 }
            
            for ((u, neighbors) in graph) {
                val uRoot = unionFind.find(u)
                
                for ((v, weight) in neighbors) {
                    val vRoot = unionFind.find(v)
                    
                    if (uRoot != vRoot) {
                        if (cheapest[uRoot] == -1 || 
                            weight < graph[u]!![cheapest[uRoot]].second) {
                            cheapest[uRoot] = neighbors.indexOfFirst { it.first == v }
                        }
                    }
                }
            }
            
            for (u in 0 until vertexCount) {
                if (cheapest[u] != -1) {
                    val (v, weight) = graph[u]!![cheapest[u]]
                    val uRoot = unionFind.find(u)
                    val vRoot = unionFind.find(v)
                    
                    if (uRoot != vRoot) {
                        mst.add(EdgeK(u, v, weight))
                        totalWeight += weight
                        unionFind.union(uRoot, vRoot)
                        treeCount--
                    }
                }
            }
        }
        
        return mst
    }
    
    fun getTotalWeight(): Int = totalWeight
}
```

### Пример использования

```kotlin
fun main() {

```

## Сложность

### Временная сложность

Временная сложность алгоритма Борувки во всех случаях составляет `O(E log V)`, где `E` — количество рёбер, а `V` — количество вершин. Алгоритм выполняет не более `log(V)` итераций, и на каждой итерации обрабатывает все `E` рёбер. Это делает алгоритм эффективным для графов с большим количеством вершин и рёбер.

### Пространственная сложность

Пространственная сложность алгоритма во всех случаях составляет `O(V + E)` — для хранения графа, `MST` и `Union-Find` структуры. Это означает, что алгоритм требует линейное количество памяти относительно размера графа, что делает его эффективным по использованию памяти.

## Особенности

Алгоритм Борувки имеет несколько важных особенностей. Алгоритм хорошо поддаётся параллелизации, что делает его особенно эффективным для больших графов в распределённых системах. Алгоритм использует жадный подход, на каждой итерации выбирая минимальные рёбра для каждого дерева, что гарантирует построение минимального остовного дерева. Алгоритм работает за `O(E log V)` время, что делает его эффективным для графов различных размеров.

## Применение

Алгоритм Борувки используется в различных областях. В параллельных вычислениях алгоритм применяется для эффективного построения минимальных остовных деревьев в распределённых системах, где различные компоненты могут обрабатываться параллельно. В распределённых системах алгоритм используется для построения эффективных сетевых топологий, которые минимизируют общую стоимость соединений. В проектировании сетей алгоритм применяется для создания оптимальных сетевых конфигураций с минимальными затратами на прокладку кабелей или установку соединений. В кластеризации данных алгоритм используется для группировки похожих объектов в кластеры на основе их взаимосвязей.

## Сравнение с другими алгоритмами MST

| Алгоритм | Временная сложность | Параллелизация | Применение |

| Крускала | `O(E log E)` | Хорошо | Разреженные графы |

## Когда использовать

Выбор между алгоритмом Борувки и другими алгоритмами `MST` зависит от конкретных требований задачи. Алгоритм Борувки следует использовать, когда нужна параллельная реализация, граф большой и распределён, и важна эффективность на параллельных системах. Алгоритм особенно эффективен в распределённых системах, где различные компоненты могут обрабатываться параллельно, что значительно ускоряет построение минимального остовного дерева.

Альтернативы включают алгоритм Прима для последовательных вычислений на плотных графах, где он может быть более эффективным благодаря своей структуре данных. Алгоритм Крускала подходит для последовательных вычислений на разреженных графах, где он может быть проще в реализации и эффективнее по использованию памяти.

## Преимущества и недостатки

Алгоритм Борувки имеет несколько преимуществ и недостатков. Преимущества включают хорошую параллелизацию, что делает алгоритм особенно эффективным в распределённых системах. Простая логика на каждой итерации упрощает реализацию и отладку алгоритма. Алгоритм эффективен для больших графов, где параллельная обработка может значительно ускорить построение минимального остовного дерева.

Недостатки включают то, что алгоритм может быть медленнее, чем Прима или Крускала на последовательных системах, где параллелизация не используется. Алгоритм также требует больше памяти для хранения промежуточных результатов, что может быть проблемой для очень больших графов с ограниченной памятью.

## Лучшие практики

Параллелизация является ключевым преимуществом алгоритма Борувки. Алгоритм естественно распараллеливается по компонентам на каждой итерации, что делает его особенно эффективным в распределённых или многопоточных средах. Использование параллельной обработки может значительно ускорить построение минимального остовного дерева для больших графов.

`Union-Find` структура данных критически важна для эффективной работы алгоритма. Применяйте `Union-Find` с рангами и сжатием пути для объединения компонент, что обеспечивает практически `O(1)` на операцию и значительно улучшает производительность алгоритма.

Минимальное ребро на компоненту должно находиться на каждой итерации для каждой компоненты. Найдите ребро минимального веса, ведущее наружу компоненты, и избегайте дублирования рёбер при объединении компонент, что гарантирует корректность построения минимального остовного дерева.

Критерий остановки должен проверяться на каждой итерации. Останавливайтесь, когда осталась одна компонента (одно дерево) или когда добавлено `V - 1` рёбер, что гарантирует, что построенное дерево действительно является минимальным остовным деревом.

Большие графы хорошо обрабатываются алгоритмом при параллельном выполнении. Алгоритм хорошо масштабируется на больших графах благодаря своей параллельной природе. Для малых графов алгоритмы Прима или Крускала могут быть проще в реализации и эффективнее по использованию памяти.


## Решение проблем

| Симптом | Возможная причина | Решение |
|--------|-------------------|---------|
| Алгоритм зацикливается | Не обновляются компоненты после объединения | Убедиться, что `Union-Find` корректно обновляет parent/rank после `union()` |
| MST содержит больше `V-1` рёбер | Добавляется ребро между вершинами одной компоненты | Проверять `find(u) != find(v)` перед добавлением ребра |
| Некорректный результат на графе с одинаковыми весами | Параллельное добавление рёбер с одинаковым весом может создать цикл | Использовать уникальный порядок рёбер (например, по индексу) для разрешения конфликтов |

## Частые вопросы

**Чем Борувка отличается от Прима и Краскала?** Борувка на каждом шаге находит минимальное ребро для КАЖДОЙ компоненты одновременно и объединяет их. Это делает алгоритм хорошо параллелизуемым. Prim растёт из одной вершины, Kruskal сортирует все рёбра глобально.

**Когда использовать Борувку?** Когда граф можно обрабатывать параллельно (каждая компонента ищет минимальное ребро независимо), или когда рёбра хранятся в формате, где сортировка дорога, но нахождение минимума по компоненте дёшево.

**Какова сложность Борувки?** `O(E log V)` — на каждой итерации число компонент уменьшается минимум вдвое (каждая находит минимальное ребро и объединяется). Максимум `O(log V)` итераций, на каждой `O(E)` работы.


## Заключение

В этом уроке мы увидели реализацию алгоритма Борувки на `Java`. Его временная сложность равна `O(E log V)`, где `E` — количество рёбер, а `V` — количество вершин. Алгоритм особенно полезен для параллельных вычислений и больших распределённых графов, где его способность к параллелизации может значительно ускорить построение минимального остовного дерева.
