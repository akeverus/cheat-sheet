# AWS Basics

**Amazon Web Services** (AWS) — облачная платформа от **Amazon**, предоставляющая вычислительные ресурсы, хранение данных и множество сервисов. Краткий обзор; детали — в [AWS Services](aws-services.md).

## Введение

**AWS** — лидер рынка облачной инфраструктуры; предоставляет сервисы по подписке (pay-as-you-go). Типичные сценарии: хостинг приложений (EC2, Lambda), хранение и **CDN** (S3, CloudFront), базы данных (RDS, DynamoDB), очереди и потоковая обработка (SQS, SNS, Kinesis). Управление доступом централизовано в **IAM**.

## Основы AWS

**AWS** предлагает сервисы по модели **IaaS**, **PaaS** и **SaaS**. Основные категории: **Compute** (EC2, Lambda), **Storage** (S3, EBS), **Database** (RDS, DynamoDB), **Networking** (VPC, CloudFront).

## Ключевые сервисы

| Категория | Сервис | Назначение |
|-----------|--------|------------|
| Compute | **EC2** | Виртуальные серверы |
| Compute | **Lambda** | Серверные функции без управления серверами |
| Storage | **S3** | Объектное хранилище |
| Storage | **EBS** | Диски для **EC2** |
| Database | **RDS** | Управляемые реляционные БД |
| Database | **DynamoDB** | Управляемая **NoSQL** БД |
| Networking | **VPC** | Изолированная сеть |
| Networking | **CloudFront** | **CDN** |

## Регионы и зоны доступности

Регион (Region) — географическая зона; внутри региона — зоны доступности (Availability Zones, AZ) для отказоустойчивости. Ресурсы привязываются к региону; межрегиональная репликация настраивается отдельно (например, S3 Cross-Region Replication).

## IAM и безопасность

См. [AWS IAM](aws-iam.md) для управления доступом и идентификацией. **IAM** управляет пользователями, группами, ролями и политиками; для приложений предпочтительны **IAM Roles** (временные учётные данные), а не долгоживущие ключи.

## Консоль и CLI

- **AWS Management Console** — веб-интерфейс по адресу [console.aws.amazon.com](https://console.aws.amazon.com/).
- **AWS CLI** — установка и настройка: `aws configure` (ввод Access Key, Secret Key, региона). Пример: `aws s3 ls`, `aws ec2 describe-instances`.

## Лучшие практики

- **Выбор региона:** выбирайте регион ближе к пользователям для снижения задержки; учитывайте соответствие требованиям по резидентности данных (GDPR и т.д.).
- **IAM:** используйте принцип наименьших привилегий; включайте **MFA** для корневого и привилегированных пользователей; предпочитайте **IAM**-роли временным ключам для приложений.
- **Биллинг и теги:** включите **Cost Explorer** и бюджеты; применяйте теги для учёта затрат по проектам и окружениям.
- **Резервирование:** для **production** используйте несколько зон доступности (AZ) и настройте резервное копирование и мониторинг.
