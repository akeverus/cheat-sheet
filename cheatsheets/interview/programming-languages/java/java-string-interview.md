## Q1. Что такое `String`?

В `Java` строка представлена внутри массивом байтовых значений (или значений `char` до `JDK` 9).

В версиях до `Java` 8 включительно строка состояла из неизменного массива символов `Unicode`. Однако для представления большинства символов требуется всего 8 бит (1 байт) вместо 16 бит (размер `char`).

Чтобы улучшить потребление памяти и производительность, в `Java` 9 появились компактные строки. Это означает, что если строка содержит только 1-байтовые символы, она будет представлена с использованием кодировки `Latin-1`. Если строка содержит хотя бы 1 многобайтовый символ, она будет представлена как 2 байта на символ с использованием кодировки `UTF-16`.

В C и C++ `String` также является массивом символов, но в `Java` это отдельный объект с собственным `API`.

## Q2. Как создать `String`?

`java.lang.String` определяет 13 различных способов создания `String`. Однако, как правило, их два.

Через строковый литерал:

```java
String s = "abc";
```

Через ключевое слово `new`:

```java
String s = new String("abc");
```

Все строковые литералы в `Java` являются экземплярами класса `String`.

## Q3. Наследуется ли `String` от `Object`?

`String` является производным типом, поскольку у него есть состояние и поведение. Например, у него есть такие методы, как `substring()`, `indexOf()` и `equals()`, которых не может быть у примитивов.

Но поскольку мы все так часто его используем, у него есть некоторые особенности, из-за которых он кажется примитивным:

1. Хотя строки не хранятся в стеке вызовов, как примитивы, они хранятся в специальной области памяти, называемой пулом строк.
2. Как и в примитивах, мы можем использовать оператор + для строк.
3. И снова, как и в случае с примитивами, мы можем создать экземпляр `String` без ключевого слова `new`.

## Q4. (!) Каковы преимущества иммутабельности `String`?

Согласно интервью Джеймса Гослинга, строки неизменяемы для повышения производительности и безопасности.

И на самом деле мы видим несколько преимуществ неизменяемых строк:

1. Пул строк возможен только в том случае, если строки, однажды созданные, никогда не изменяются, так как предполагается их повторное использование.
2. Код может безопасно передать строку другому методу, зная, что этот метод не может ее изменить.
3. `Immutable` автоматически делает этот класс потокобезопасным.
4. Поскольку этот класс потокобезопасен, нет необходимости синхронизировать общие данные, что, в свою очередь, повышает производительность.
5. Поскольку они гарантированно не изменятся, их хэш-код можно легко кэшировать.

## Q5. (!) Как `String` хранится в памяти?

В `Java` класс `String` является неизменяемым (immutable). Когда создается экземпляр `String`, он хранится в памяти (`Java Heap`). Каждый раз, когда происходит операция конкатенации (+), создается новый экземпляр `String`.

При создании строки с помощью двойных кавычек, например: `String str = "Hello";`, `Java` использует механизм пула строк (`String Pool`). Значение строки помещается в пул, и при создании новой строки с тем же значением `Java` сначала ищет его в пуле. Если строка уже находится в пуле, тогда `Java` будет использовать ссылку на уже существующий экземпляр строки, вместо создания нового.

Например, если мы создадим две строки с одинаковым значением:

`String` str1 = "Hello";

`String` str2 = "Hello";

`Java` будет использовать одну и ту же ссылку на строку `"Hello"` для обоих переменных str1 и str2. Это делается для экономии памяти и повышения производительности.

Однако, если используется оператор `new`:

```java
String str3 = new String("Hello");
```

Тогда `Java` создаст новый объект строки независимо от пула строк. В этом случае создается два объекта: один в пуле строк и один в обычной области памяти (`Java Heap`).

Таким образом, строки `String` в `Java` хранятся в памяти с использованием пула строк (`String Pool`), который экономит память и повышает производительность.

## Q6. (!) Подходят ли интернированные `String` для сборки мусора?

Интернированные строки (interned strings) в `Java` являются особым видом строк, которые хранятся в специальном пуле строк (`String Pool`). Когда строка интернируется с помощью метода intern(), `Java` проверяет, есть ли в пуле строк другая строка с тем же значением. Если уже есть, то возвращается ссылка на уже существующий объект строки. Если же нет, то создается новый объект строки и помещается в пул строк.

Интернированные строки имеют важную особенность, связанную с сборкой мусора. По умолчанию, интернированные строки не подвержены сборке мусора, поскольку они сохраняются в пуле строк, доступном всему приложению.

Основной механизм сборки мусора в `Java` основан на принципе достижимости объектов. Если объект не имеет ссылок на него, он считается недостижимым и может быть удален во время сборки мусора.

Однако интернированные строки являются исключением. Поскольку они сохраняются в пуле строк и доступны всему приложению, на них всегда есть как минимум одна ссылка, что предотвращает их удаление во время сборки мусора. Другими словами, интернированные строки не будут удалены, пока приложение работает.

Из-за этого особого поведения интернированных строк не рекомендуется применять интернирование в больших масштабах или без необходимости. Большое количество интернированных строк может существенно увеличить потребление памяти в приложении и снизить производительность.

В целом, использование интернированных строк должно быть ограничено только в случаях, когда это необходимо, например, для сравнения строк, чтобы гарантировать существование только одного экземпляра строки с определенным значением.

## Q7. (!) Что такое `String Pool`?

`String Pool` (пул строк) — это специальная область памяти в `Java`, где хранятся интернированные строки. Пул строк представляет собой механизм, который позволяет сократить использование памяти и повысить производительность при работе со строками.

Когда создается строка с помощью двойных кавычек, например: `String str = "Hello";`, `Java` автоматически помещает эту строку в пул строк. Если уже имеется строка с тем же значением в пуле строк, `Java` будет использовать ссылку на уже существующий экземпляр строки вместо создания нового.

Это делается для экономии памяти и повышения производительности, поскольку многие строки в программе могут иметь одинаковые значения. Вместо создания отдельной копии каждой строки с одинаковым значением, пул строк позволяет использовать одну и ту же строку.

Интернированные строки (interned strings) — это строки, которые находятся в пуле строк. Это означает, что они имеют ссылку на уже существующий экземпляр строки с тем же значением. При необходимости интернирования строки можно использовать метод `intern()`. Например: `String str = "Hello".intern();`.

Важно помнить, что пул строк доступен всему приложению и сохраняет строки до тех пор, пока приложение работает. Это означает, что строки в пуле недоступны для сборки мусора и могут занимать память даже после того, как на них больше нет ссылок. Поэтому следует использовать интернирование строк с умом и ограниченным объемом, чтобы не занимать слишком много памяти.

## Q8. (!) Является ли `String` потокобезопасным?

Класс `String` в `Java` является неизменяемым (immutable). Это означает, что после создания объекта `String` его содержимое не может быть изменено.

В контексте потокобезопасности неизменяемые объекты, такие как `String`, обычно считаются потокобезопасными. Потокобезопасность подразумевает, что объект может быть использован совместно несколькими потоками без неожиданных результатов или повреждения данных.

Поскольку строки неизменяемы, каждый поток может считывать строки, вызывать методы доступа к данным строки (например, `length()`, `charAt()`, `substring()`) и выполнять другие операции безопасно. Это происходит потому, что методы класса `String` являются потокобезопасными и многопоточное чтение над безизменными данными не вызывает проблем.

Однако, если один поток изменяет или модифицирует строку, пока другой поток считывает ее, могут возникнуть проблемы согласованности данных. В таких случаях потокобезопасность не гарантируется.

Также следует обратить внимание на операции конкатенации или изменения строк. Хотя строки неизменяемы, при выполнении операций конкатенации (+) или изменения с использованием методов типа `StringBuilder`, которые создают новую строку, могут возникать проблемы при многопоточном доступе.

В общем, класс `String` можно считать потокобезопасным для операций чтения и доступа к данным. Однако, для операций изменения или конкатенации строк рекомендуется использовать синхронизацию или другие механизмы потокобезопасности по необходимости.

## Q9. Что такое `Locale`?

Указание `Locale` важно для строковых операций, которые зависят от локали (региональных настроек). Локаль определяет язык, страну и другие культурные параметры, которые могут влиять на правильную интерпретацию и отображение строковых значений.

Некоторые примеры строковых операций, для которых важно указывать `Locale`:

1. Преобразование чисел и дат: методы, такие как `String.format()`, `NumberFormat.format()` и `DateFormat.format()`, используют `Locale` для правильного форматирования чисел и дат в соответствии с предпочтениями локали. Например, разделители между группами цифр и формат даты могут отличаться для разных регионов.
2. Сравнение строк: методы сравнения строк, такие как `String.compareTo()`, могут давать различные результаты в зависимости от настроек локали. Например, в случае сравнения буквы "a" и "A" в некоторых локалях они могут считаться одинаковыми, а в других разными.
3. Преобразование регистра: методы преобразования регистра, такие как `String.toLowerCase()` и `String.toUpperCase()`, могут иметь различное поведение для разных локалей. Некоторые языки имеют свои особенности в отношении правил преобразования регистра.
4. Сопоставление строк: некоторые методы, такие как `String.equalsIgnoreCase()` и `String.compareToIgnoreCase()`, игнорируют регистр символов при сопоставлении строк. Однако это поведение может отличаться для разных локалей, так как некоторые языки могут иметь разные правила для сравнения регистра символов.

Указание правильной локали позволяет гарантировать, что строки правильно интерпретируются и обрабатываются с учетом предпочтений и культурных особенностей конкретного региона.

## Q10. Какая базовая кодировка для `String`?

Согласно `String Javadocs` для версий до `Java` 8 включительно строки хранятся внутри в формате `UTF-16`.

Тип данных char и объекты `java.lang.Character` также основаны на исходной спецификации `Unicode`, которая определяет символы как 16-разрядные объекты фиксированной ширины.

Начиная с `JDK` 9, строки, содержащие только 1-байтовые символы, используют кодировку `Latin-1`, а строки, содержащие как минимум 1 многобайтовый символ, используют кодировку `UTF-16`.

## Q11. Как мы можем сравнить две строки? В чем разница между str1 == str2 и `str1.equals(str2)`?

Мы можем сравнивать строки двумя разными способами: используя оператор равенства (==) и используя метод equals().

Оба сильно отличаются друг от друга:

1. Оператор (str1 == str2) проверяет ссылочное равенство.
2. Метод `str1.equals(str2)` проверяет лексическое равенство.
3. Хотя верно, что если две строки лексически равны, то `str1.intern() == str2.intern()` также верно.

Как правило, для сравнения двух строк на предмет их содержимого мы всегда должны использовать `String.equals()`.

## Q12. Как разделить `String`?

Сам класс `String` предоставляет нам метод `split`, который принимает разделитель регулярного выражения. Он возвращает нам массив `String`\[\]:

```java
String[] parts = "john,peter,mary".split(",");

assertEquals(new String[]{"john", "peter", "mary"}, parts);
```

Одна хитрость в разделении заключается в том, что при разделении пустой строки мы можем получить непустой массив:

```java
assertEquals(new String[]{""}, "".split(","));
```

Конечно, разделение это лишь один из многих способов разделения `Java String`.

## Q13. Что такое `StringJoiner`?

`StringJoiner` — это класс, представленный в `Java` 8 для объединения отдельных строк в одну, например, для получения списка цветов и возврата их в виде строки с разделителями-запятыми. Мы можем указать разделитель, а также префикс и суффикс:

```java
StringJoiner joiner = new StringJoiner(",", "[", "]");

joiner.add("Red").add("Green").add("Blue");

assertEquals("[Red,Green,Blue]", joiner.toString());
```

## Q14. Разница между `String`, `StringBuffer` и `StringBuilder`?

Строки неизменяемы. Это означает, что если мы попытаемся изменить или модифицировать его значение, то `Java` создаст абсолютно новую строку.

Например, если мы добавим к строке str1 после ее создания:

```java
String str1 = "abc";
str1 = str1 + "def";
```

Затем `JVM` вместо модификации str1 создает совершенно новую строку `String`.

Однако в большинстве простых случаев компилятор внутри использует `StringBuilder` и оптимизирует приведённый выше код.

Но для более сложного кода, такого как циклы, будет создана совершенно новая строка, что ухудшит производительность. Вот где полезны `StringBuilder` и `StringBuffer`.

И `StringBuilder`, и `StringBuffer` в `Java` создают объекты, содержащие изменяемую последовательность символов. `StringBuffer` синхронизирован и, следовательно, потокобезопасен, а `StringBuilder` нет.

Поскольку дополнительная синхронизация в `StringBuffer` обычно не требуется, мы часто можем получить прирост производительности, выбрав `StringBuilder`.

## Q15. Почему безопаснее хранить пароли в массиве `Char`\[\], а не в `String`?

Поскольку строки неизменяемы, они не допускают модификации. Такое поведение не позволяет нам перезаписывать, изменять или обнулять его содержимое, что делает строки непригодными для хранения конфиденциальной информации.

Мы должны полагаться на `Garbage Collector`, чтобы удалить содержимое строки. Более того, в версии `Java` 6 и ниже строки хранились в `PermGen`, а это означает, что после создания строки она никогда не подвергалась сборке мусора.

Используя массив char\[\], мы имеем полный контроль над этой информацией. Мы можем изменить его или полностью стереть, даже не полагаясь на `Garbage Collector`.

Использование char\[\] вместо `String` не обеспечивает полной защиты информации; это просто дополнительная мера, уменьшающая возможность злоумышленника получить доступ к конфиденциальной информации.

## Q16. Что делает метод `String.intern()`?

Метод intern() создаёт точную копию объекта `String` в куче и сохраняет её в пуле констант `String`, который поддерживает `JVM`. `Java` автоматически интернирует все строки, созданные с помощью строковых литералов, но если мы создадим `String` с помощью оператора new, например, `String str = new String("abc")`, то `Java` добавит его в кучу, как и любой другой объект.

Мы можем вызвать метод intern(), чтобы указать `JVM` добавить его в пул строк, если он там ещё не существует, и вернуть ссылку на эту интернированную строку:

```java
String s1 = "Baeldung";
String s2 = new String("Baeldung");
String s3 = new String("Baeldung").intern();

assertThat(s1 == s2).isFalse();
assertThat(s1 == s3).isTrue();
```

## Q18. Что такое `String.format()`?

## Q31. Как работать с регулярными выражениями (`Pattern`, `Matcher`)?
