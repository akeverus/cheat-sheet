## Q1. Какие новые функции были добавлены в `Java` 8?

`Java` 8 поставляется с несколькими новыми функциями, наиболее важными из которых являются следующие:

1. `Lambda Functions` — новая функция языка, позволяющая нам рассматривать действия как объекты.
2. **Method References** (ссылки на методы) позволяют определять лямбда-выражения, ссылаясь на методы напрямую по имени.
3. `Optional` — специальный класс-оболочка, используемый для выражения необязательности.
4. **Functional Interface** — интерфейс с максимум одним абстрактным методом; реализация может быть предоставлена с использованием лямбда-выражения.
5. `Default Methods` — дают нам возможность добавлять полные реализации в интерфейсы помимо абстрактных методов.
6. `Nashorn`, `JavaScript Engine` — движок на основе `Java` для выполнения и оценки кода `JavaScript`.
7. `Stream API` — специальный класс итератора, который позволяет нам функционально обрабатывать коллекции объектов.
8. `Date API` — улучшенный, неизменяемый `API Date`, вдохновленный `JodaTime`.

Наряду с этими новыми функциями, множество внутренних улучшений реализовано как на уровне компилятора, так и на уровне `JVM`.

## Q2. Какие важные методы коллекций и `API` добавлены в `Java` 9–21?

Java 9: неизменяемые фабрики коллекций — `List.of()`, `Set.of()`, `Map.of()`, `Map.ofEntries()`; `Optional.or()`, `Stream.takeWhile()`, `dropWhile()`, `iterate` с предикатом. Java 10: `var` для локальных переменных. Java 11: `String.isBlank()`, `strip()`, `lines()`; `Optional.isEmpty()`; `HttpClient`. Java 12–17: `switch`-выражение, `instanceof` pattern matching, текстовые блоки, `record`, `sealed` классы. Коллекции: `List.copyOf()`, `Set.copyOf()` (неизменяемые копии). На собеседовании достаточно назвать фабрики `of()`, методы `Stream` и ключевые фичи по версиям.

## Q3. (!) Что такое функциональный интерфейс?

Функциональный интерфейс — это интерфейс с одним-единственным абстрактным методом (методы по умолчанию не в счёт), ни больше, ни меньше.

Если требуется экземпляр такого интерфейса, вместо него можно использовать лямбда-выражение. Говоря более формально: функциональные интерфейсы предоставляют целевые типы для лямбда-выражений и ссылок на методы. Аргументы и тип возвращаемого значения такого выражения полностью совпадают с таковыми у единственного абстрактного метода.

Например, интерфейс `Runnable` это функциональный интерфейс, поэтому вместо:

```java
Thread thread = new Thread(new Runnable() {
    @Override
    public void run() {
        System.out.println("Hello World!");
    }
});
```

Мы могли бы просто сделать:

```java
Thread thread = new Thread(() -> System.out.println("Hello World!"));
```

Функциональные интерфейсы обычно снабжаются аннотацией `@FunctionalInterface`, которая является информативной и не влияет на семантику.

## Q4. (!) Какие есть функциональные интерфейсы в стандартной библиотеке?

В стандартной библиотеке `Java` имеется набор предопределённых функциональных интерфейсов, которые были введены в `JDK` 8 и дополнительные функциональные интерфейсы, добавленные в последующих версиях `JDK`. Некоторые из них включают:

1. `Predicate<T>` — принимает один аргумент и возвращает логическое значение `true` или `false`. Используется для фильтрации элементов коллекций или проверки условий.
2. `Function<T, R>` — принимает один аргумент типа T и возвращает значение типа R. Используется для преобразования объектов одного типа в другой.
3. `Consumer<T>` — принимает один аргумент типа T и не возвращает результат. Используется для выполнения операций над объектом типа T.
4. `Supplier<T>` — не принимает аргументов и возвращает объект типа T. Используется для поставки (получения) значения.
5. `BiPredicate<T, U>` — принимает два аргумента типа T и U и возвращает логическое значение `true` или `false`.
6. `BiFunction<T, U, R>` — принимает два аргумента типа T и U и возвращает значение типа R.
7. `BiConsumer<T, U>` — принимает два аргумента типа T и U и не возвращает результат.

Это только несколько примеров функциональных интерфейсов из стандартной библиотеки `Java`. В `JDK` также имеются другие функциональные интерфейсы и возможность создания пользовательских. Функциональные интерфейсы в `Java` позволяют использовать функциональное программирование и лямбда-выражения.

## Q5. Что такое лямбда-выражение?

Лямбда-выражение — это компактный способ представления анонимной функции, которую можно передать как аргумент или присвоить переменной. Оно позволяет создавать небольшие, одноразовые функции «на лету» без необходимости явного объявления метода.

В `Java` лямбда-выражения были представлены в `JDK` 8 вместе с функциональными интерфейсами. Они представляют удобный и мощный инструмент для функционального программирования.

Синтаксис лямбда-выражения в `Java` имеет следующую структуру:

```java
(parameter1, parameter2, ...) -> expression
```

Лямбда-выражение состоит из следующих элементов:

1. Параметры: список параметров, которые принимает функция.
2. Стрелка: стрелка (`->`) разделяет параметры и тело выражения.
3. Тело выражения: выражение или блок кода, который выполняется внутри лямбда-функции.

Лямбда-выражения используются в `Java` для работы с функциональными интерфейсами, чтобы предоставить компактный и элегантный способ реализовать методы функциональных интерфейсов. Они позволяют писать более читаемый и гибкий код, упрощают обработку коллекций данных, асинхронную обработку событий, обработку запросов и многое другое. Лямбда-выражения также позволяют сократить объём кода и избежать необходимости объявления и реализации отдельного метода для каждой операции или обработки данных.

## Q8. Что такое ссылка на метод?

Ссылка на метод — это специальный тип данных в `Java`, который позволяет передавать методы как аргументы или возвращать их из других методов. Вместо вызова метода напрямую можно создать ссылку на него и использовать эту ссылку для вызова.

Ссылка на метод может быть создана в двух формах: ссылка на статический метод или ссылка на метод экземпляра. Ссылка на статический метод используется для ссылки на метод, объявленный как статический. Формат: `ClassName::methodName`. Например, `Math::max`. Ссылка на метод экземпляра используется для ссылки на метод, объявленный в классе экземпляра. Формат: `objectReference::methodName`. Например, `String::length`.

Ссылки на методы могут быть переданы в методы высшего порядка, такие как `Stream API`, для обработки коллекций данных или для создания функциональных интерфейсов с одним абстрактным методом. Ссылки на методы позволяют улучшить читаемость кода и сделать его более компактным и выразительным. Они являются частью функционального программирования в `Java` и мощным инструментом, упрощающим работу с методами как с данными.

## Q11. Будет ли компилироваться следующий код?

## Q12. Что такое `Optional`? Как его можно использовать?

`Optional` — это новый класс в `Java` 8, который инкапсулирует необязательное значение, то есть значение, которое либо есть, либо нет. Это оболочка вокруг объекта, и мы можем думать о ней как о контейнере из нуля или одного элемента. `Optional` имеет специальное значение `Optional.empty()` вместо обёрнутого `null`. Таким образом, во многих случаях его можно использовать вместо значений, допускающих `null`, чтобы избавиться от `NullPointerException`.

Основная цель `Optional`, задуманная его создателями, состоит в том, чтобы быть возвращаемым типом методов, которые ранее возвращали бы `null`. Такие методы потребовали бы написания шаблонного кода для проверки возвращаемого значения, и иногда можно было бы забыть сделать защитную проверку. В `Java` 8 `Optional` как возвращаемый тип явно требует по-разному обрабатывать обёрнутые значения `null` или non-null.

Например, метод `Stream.min()` вычисляет минимальное значение в потоке значений. Но что, если поток пуст? Если бы не **Optional**, метод вернул бы `null` или выдал бы исключение.

Однако он возвращает `Optional`, которое может быть `Optional.empty()` (второй случай). Это позволяет легко обрабатывать такие случаи:

```java
int min1 = Arrays.stream(new int[]{1, 2, 3, 4, 5}).min().orElse(0);
assertEquals(1, min1);

int min2 = Arrays.stream(new int[]{}).min().orElse(0);
assertEquals(0, min2);
```

Стоит отметить, что `Optional` не является классом общего назначения, как `Option` в `Scala`. Не рекомендуется использовать его в качестве значения поля в классах сущностей, на что явно указывает то, что он не реализует интерфейс **Serializable**.

## Q13. Как использовать `Optional.orElse` vs `orElseGet`?

`orElse(value)` — возвращает значение, если `Optional` пуст; аргумент вычисляется всегда. `orElseGet(Supplier)` — вызывает `Supplier` только при пустом `Optional`. Если получение значения дорогое (вызов метода, создание объекта) — предпочтительнее `orElseGet`; иначе `orElse`. `orElseThrow()` — бросать исключение при пустом значении.

## Q17. Что такое `Stream`?

`Stream` — это новый функциональный `API`, введённый в `JDK` 8, который позволяет эффективно и удобно выполнять операции с коллекциями и другими данными. Он предоставляет возможности для функционального программирования, обработки данных параллельно и лениво (отложенно).

Основные отличия между `Stream` и `Collection`:

1. Спецификация данных: коллекция — это структура данных, которая хранит и управляет набором элементов в определённом порядке. `Stream` представляет логическую последовательность элементов, скомбинированную с набором операций, которые можно применять к этой последовательности.
2. Цель использования: коллекции предназначены для хранения и доступа к набору элементов. `Stream` используется для выполнения и трансформации операций над элементами в коллекции или других источниках данных, без изменения исходных данных.
3. Доступ к данным: коллекции обеспечивают прямой доступ к элементам по индексу и позволяют выполнять операции вставки, удаления и обновления. `Stream` не имеет прямого доступа к элементам и не позволяет изменять исходные данные; он выполняет операции над элементами и возвращает новый поток с результатами.
4. Обработка операций: коллекции выполняют операции над элементами непосредственно в памяти, что требует модификации коллекции. `Stream` выполняет операции «на лету» (лениво), по требованию, без изменения исходных данных, используя конвейерную обработку, где каждая операция выполняется только при необходимости.
5. Параллельная обработка: `Stream` обеспечивает лёгкую параллельную обработку данных с помощью методов `parallel()` и `parallelStream()`. Коллекции не имеют встроенной поддержки параллельной обработки.

`Stream` предоставляет богатый набор операций для фильтрации, преобразования, сортировки, ограничения, сведения, агрегации и других операций над данными. Он предоставляет элегантный и функциональный подход к работе с данными, что делает его мощным инструментом в функциональном программировании и обработке коллекций в `Java`.

## Q18. (!) В чем разница между промежуточными и терминальными операциями?

Различие между промежуточными и терминальными операциями в `Stream` заключается в их целях и результате выполнения.

Промежуточные операции — это операции, которые применяются к элементам потока и возвращают новый поток. Они не выполняются немедленно при вызове, а откладываются и выполняются только при наличии терминальной операции. Примеры: `filter()`, `map()`, `sorted()`, `distinct()`.

Терминальные операции — это операции, которые приводят к окончательному результату и завершают выполнение потока. После выполнения терминальной операции нельзя использовать поток ещё раз. Примеры: `forEach()`, `count()`, `collect()`, `reduce()`, `anyMatch()`, `allMatch()`, `noneMatch()`.

Главная разница: промежуточные операции выполняются лениво и работают с элементами потока, создавая новый поток; терминальные операции вызываются немедленно и приводят к фактическому выполнению и получению конечного результата. Терминальная операция обязательна для выполнения потока; без неё промежуточные операции не будут выполнены и результат не будет получен.

## Q19. Что такое `Stream Pipelining`?

`Stream Pipelining` (конвейеризация потоков) — это процесс последовательного применения нескольких операций к элементам потока данных в `Java` 8 `Stream API`. Конвейер состоит из промежуточных и терминальных операций, которые работают вместе для преобразования и обработки данных.

При использовании `Stream Pipelining` каждая операция применяется к элементам потока и передаёт результат следующей операции. Это позволяет создавать цепочки операций, выполняющих различные преобразования и фильтрации данных.

Пример использования `Stream Pipelining`:

```java
List<String> names = List.of("John", "Jane", "Jack", "Jill", "James");
List<String> result = names.stream()
        .filter(name -> name.length() > 3)
        .map(String::toUpperCase)
        .sorted()
        .collect(Collectors.toList());
```

В этом примере создаётся поток из списка имён, фильтруются имена длиннее 3 символов, затем они преобразуются в верхний регистр, сортируются и собираются в новый список. Каждая операция в конвейере применяется последовательно, используя результат предыдущей. `Stream Pipelining` позволяет использовать лаконичный и выразительный код для обработки и преобразования данных и способствует ленивому выполнению операций, что может повысить эффективность при больших объёмах данных.

## Q20. В чем разница между `map()` и `flatMap()`?

Разница между операциями `map()` и `flatMap()` в `Stream` состоит в том, как они обрабатывают и представляют элементы в потоке.

Метод `map()` применяет функцию к каждому элементу потока и возвращает новый поток, содержащий результаты преобразования. Каждый элемент входного потока преобразуется в один элемент выходного потока. Результатом работы `map()` является поток элементов того же типа.

Пример использования `map()`:

```java
List<String> names = List.of("John", "Jane", "Jack");
List<String> upperCaseNames = names.stream().map(String::toUpperCase).collect(Collectors.toList());
```

В этом примере `map()` применяет функцию `toUpperCase()` к каждому элементу списка и возвращает поток с преобразованными значениями «JOHN», «JANE», «JACK», который затем собирается в список.

Метод `flatMap()` получает в качестве аргумента функцию, которая возвращает поток элементов. `flatMap()` «разворачивает» каждый полученный поток в один плоский поток и объединяет все потоки в один выходной. Результатом работы `flatMap()` является поток элементов нового типа.

Пример использования `flatMap()`:

```java
List<List<Integer>> numbers = List.of(List.of(1, 2), List.of(3, 4), List.of(5, 6));
List<Integer> flattenedNumbers = numbers.stream().flatMap(List::stream).collect(Collectors.toList());
```

В этом примере `flatMap()` применяет метод `stream()` к каждому элементу списка и разворачивает каждый поток в один плоский поток чисел. Результат — список `flattenedNumbers` [1, 2, 3, 4, 5, 6].

Таким образом, `map()` возвращает поток элементов того же типа, а `flatMap()` возвращает развёрнутый поток элементов из вложенных потоков. В зависимости от требуемого результата и типов данных выбирают `map()` или `flatMap()`.

## Q29. Опишите новый `Date API`

В `Java` 8 был представлен новый `API` для работы с датами и временем — `java.time`. Этот `API` предоставляет более удобные и гибкие средства для работы с датами, временем, промежутками времени и временными зонами.

9. `DateTimeFormatter` — формат даты и времени для преобразования строк в объекты даты и времени и обратно.
10. `ZoneId` — временная зона, например `Europe/Paris`.
11. `ZoneOffset` — смещение относительно `UTC`, например +02:00.

`Java` 8 Date API улучшает производительность, упрощает работу со сменой даты и времени и имеет более интуитивный и гибкий интерфейс. Также `API` предлагает множество методов для операций над датами и временем: получение следующего рабочего дня, сравнение дат, добавление промежутков времени и т.д.

```java
System.out.println("Текущее время: " + currentTime);
System.out.println("Комбинированная дата и время: " + dateTime);
System.out.println("Дата, время и временная зона: " + zonedDateTime);
System.out.println("Результат после добавления промежутка времени: " + resultDateTime);
```

Это лишь небольшой пример использования нового `API` даты и времени. Он предлагает мощные и удобные инструменты для работы с датами и временем в `Java` 8.

Связь с `Java` 8: лямбды и method references в колбэках; `CompletableFuture.supplyAsync(Supplier)`. Упрощает асинхронный код без callback hell. Практический акцент в таких вопросах — показать не только синтаксис, но и эксплуатационные последствия: читаемость, совместимость и профиль производительности. На интервью это обычно усиливают примером типичной ошибки и способом её предотвращения в код-ревью или тестах.

## Q31. Как обработать исключения в лямбдах и `Stream`?

Лямбды не объявляют checked exceptions; обёрнуть в `try-catch` внутри лямбды или вынести в метод. В `Stream`: обернуть вызов в метод, возвращающий `Optional` или бросающий unchecked; использовать `Optional` вместо исключений для случая «нет результата». Кастомный `Consumer`/`Function` с `throws` и обёртка `try-catch` при вызове. Библиотеки (например, `Vavr`) предоставляют **Try** для обработки исключений в функциональном стиле.
