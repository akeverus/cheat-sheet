## Q1. Опишите место класса `Object` в иерархии типов. Какие типы наследуются от `Object`, а какие нет? Наследуются ли массивы от объекта? Можно ли присвоить лямбда-выражение объектной переменной?

`java.lang.Object` находится на вершине иерархии классов в `Java`. Все классы наследуются от него либо явно, либо неявно (когда в определении класса опущено ключевое слово extends), либо транзитивно через цепочку наследования.

Однако есть восемь примитивных типов, которые не наследуются от `Object`, а именно: boolean, byte, short, char, int, float, long и double.

Согласно Спецификации языка `Java`, массивы также являются объектами. Они могут быть назначены ссылке на объект, и для них могут быть вызваны все методы объекта.

Лямбда-выражения нельзя назначать непосредственно переменной объекта, поскольку объект не является функциональным интерфейсом. Но вы можете назначить лямбду переменной функционального интерфейса, а затем назначить ее переменной объекта (или просто назначить ее переменной объекта, одновременно приведя ее к функциональному интерфейсу).

## Q2. В чём разница между примитивными и ссылочными типами?

Ссылочные типы наследуются от верхнего класса `java.lang.Object` и сами являются наследуемыми (за исключением конечных классов). Примитивные типы не наследуются и не могут быть подклассами.

Значения аргументов с примитивным типом всегда передаются через стек, что означает, что они передаются по значению, а не по ссылке. Это имеет следующий смысл: изменения, внесенные в значение примитивного аргумента внутри метода, не распространяются на фактическое значение аргумента.

Примитивные типы обычно хранятся с использованием базовых аппаратных типов значений.

Например, для хранения значения `int` может использоваться 32-битная ячейка памяти. Ссылочные типы вводят накладные расходы на заголовок объекта, который присутствует в каждом экземпляре ссылочного типа.

Размер заголовка объекта может быть весьма значительным по сравнению с размером простого числового значения. Вот почему в первую очередь были введены примитивные типы для экономии места на служебных объектах. Недостатком является то, что не все в `Java` технически является объектом — примитивные значения не наследуются от класса `Object`.

```java
int value = list.get(0);
```

## Q3. В чём разница между `equals()` и ==?

Оператор `==` позволяет сравнивать два объекта на предмет "одинаковости" (т. е. того, что обе переменные ссылаются на один и тот же объект в памяти). Важно помнить, что ключевое слово `new` всегда создает новый объект, который не будет передавать равенство `==` с любым другим объектом, даже если они имеют одинаковое значение:

```java
String string1 = new String("Hello");
String string2 = new String("Hello");

assertFalse(string1 == string2);
```

Также оператор `==` позволяет сравнивать примитивные значения:

```java
int i1 = 5;
int i2 = 5;

assertTrue(i1 == i2);
```

Метод `equals()` определён в классе `java.lang.Object` и поэтому доступен для любого ссылочного типа. По умолчанию он просто проверяет, что объект тот же, с помощью оператора `==`. Но обычно это переопределяется в подклассах, чтобы обеспечить конкретную семантику сравнения для класса.

Например, для класса `String` этот метод проверяет, содержат ли строки одинаковые символы:

```java
String string1 = new String("Hello");
String string2 = new String("Hello");

assertTrue(string1.equals(string2));
```

## Q4. Какие есть типы примитивов?

`Java` имеет 8 примитивных типов:

1. `boolean` — логическое значение true/false. Размер логического значения не определяется спецификацией `JVM` и может различаться в разных реализациях.
2. `byte` — 8-битное значение со знаком.
3. `short` — 16-битное значение со знаком.
4. `char` — беззнаковое 16-битное значение.
5. `int` — 32-битное значение со знаком.
6. `long` — 64-битное значение со знаком.
7. `float` — 32-битное значение с плавающей запятой одинарной точности, соответствующее стандарту `IEEE 754`.
8. `double` — 64-битное значение с плавающей запятой двойной точности, соответствующее стандарту `IEEE 754`.

## Q5. (!) В чем разница между `Abstract Class` и `Interface`?

Разница между абстрактным классом (`Abstract Class`) и интерфейсом (`Interface`) состоит в следующем:

1. Определение методов:
    - Абстрактный класс может содержать конкретные методы, абстрактные методы и переменные экземпляра.
    - Интерфейс может содержать только абстрактные методы и статические константы.
2. Наследование:
    - Класс может наследовать только один абстрактный класс, но может реализовывать несколько интерфейсов.
    - Класс, наследующий абстрактный класс, расширяет его функциональность.
    - Класс, реализующий интерфейс, обеспечивает реализацию указанных методов.
3. Поля:
    - Абстрактный класс может иметь переменные экземпляра, которые могут быть изменены и наследованы классами-потомками.
    - Интерфейс не может иметь переменных экземпляра, только статические константы.
4. Использование:
    - Абстрактные классы могут использоваться в случаях, когда существует общая функциональность между классами-потомками и необходимо обеспечить базовую реализацию.
    - Интерфейсы часто используются, когда необходимо определить контракт, который классы должны реализовать. Они позволяют сделать код более гибким и поддерживаемым, позволяя классам реализовывать несколько интерфейсов.

Использование абстрактных классов и интерфейсов зависит от особенностей проекта и его требований. Если вам нужна базовая реализация и несколько классов с общей функциональностью, то использование абстрактного класса имеет смысл. Если вам нужно определить контракт, который классы должны реализовать, или если вам нужно множественное наследование, то интерфейсы будут более подходящим выбором.

## Q6. Каковы ограничения для членов (полей и методов) типа `Interface`?

Интерфейс может объявлять поля, но они неявно объявляются как `public`, `static` и `final`, даже если вы не указываете эти модификаторы. Следовательно, вы не можете явно определить поле интерфейса как `private`. По сути, интерфейс может иметь только поля-константы, а не поля-экземпляры.

Все методы интерфейса также неявно являются общедоступными. Они также могут быть (неявно) abstract или default.

## Q7. (!) В чем разница между `Inner Class` и `Static Nested Class`?

Разница между внутренним классом (`Inner Class`) и статическим вложенным классом (`Static Nested Class`) заключается в следующем:

1. Область видимости:
    - Внутренний класс имеет доступ ко всем членам и методам внешнего класса, включая закрытые (`private`) элементы. Он связан с экземпляром внешнего класса и не может существовать без него.
    - Статический вложенный класс является независимым от экземпляра внешнего класса и не имеет доступа к нестатическим методам или переменным внешнего класса.
2. Создание экземпляров:
    - Внутренний класс может быть создан только в контексте экземпляра внешнего класса. Для создания экземпляра внутреннего класса сначала нужно создать экземпляр внешнего класса.
    - Статический вложенный класс может быть создан независимо от экземпляров внешнего класса. Нет необходимости создавать экземпляр внешнего класса для создания экземпляра статического вложенного класса.
3. Связь с внешним классом:
    - Внутренний класс имеет доступ к полям и методам внешнего класса, включая закрытые (`private`) элементы, потому что он связан с экземпляром внешнего класса.
    - Статический вложенный класс не имеет прямого доступа к членам внешнего класса. Он может использовать только статические элементы и методы внешнего класса.
4. Использование:
    - Внутренние классы полезны, когда внутренний класс обеспечивает определённое функциональное поведение, которое тесно связано с внешним классом и требует доступа к его членам.
    - Статические вложенные классы используются, когда требуется связанный класс, который не нуждается в доступе к инстансам внешнего класса. Они обеспечивают логическую группировку классов внутри внешнего класса.

Выбор между внутренним классом и статическим вложенным классом зависит от требований вашего проекта и логики использования классов.

## Q8. Есть ли множественное наследование?

Нет, в `Java` нет прямой поддержки множественного наследования классов. В языке `Java` можно наследоваться только от одного класса, но можно реализовать несколько интерфейсов одновременно. Это сделано для избежания проблем, связанных с неоднозначностью и сложностью, которые могут возникнуть при множественном наследовании классов.

Однако `Java` поддерживает концепцию интерфейсов, которые позволяют классу имплементировать (реализовывать) несколько интерфейсов. В интерфейсах определяются только методы и константы, но не реализуется их функциональность. Это обеспечивает гибкость и позволяет классу реализовывать поведение, определенное в нескольких интерфейсах.

Таким образом, хотя множественное наследование классов запрещено в `Java`, можно достичь аналогичной функциональности, используя интерфейсы.

## Q9. (!) Что такое классы-оболочки? Что такое `Autoboxing` и `Unboxing`?

Классы-оболочки являются классами, представляющими примитивные типы данных в `Java` в виде объектов. Они предоставляют дополнительные функциональности для работы с примитивными типами, такие как методы для преобразования значений, выполнения математических операций и сравнения.

Преобразование примитивных типов в их соответствующие классы-оболочки называется автобоксингом (autoboxing). Это процесс, при котором значения примитивных типов автоматически упаковываются в соответствующие классы-оболочки. Например, число типа `int` может быть автоматически упаковано в объект типа `Integer`.

Автобоксинг позволяет нам использовать примитивные типы и классы-оболочки взаимозаменяемо во многих ситуациях. Например, при работе с коллекциями, которые требуют объектов, мы можем использовать классы-оболочки для представления примитивных типов данных.

Обратным процессом автобоксинга является автораспаковка (unboxing), при которой значения объектов классов-оболочек автоматически распаковываются в соответствующие примитивные типы.

## Q10. Предположим, у вас есть переменная, которая ссылается на экземпляр типа класса. Как проверить, что объект является экземпляром этого класса?

Вы не можете использовать ключевое слово `instanceof` в этом случае, потому что оно работает только в том случае, если вы предоставляете фактическое имя класса как литерал.

К счастью, в классе `Class` есть метод `isInstance()`, который позволяет проверить, является ли объект экземпляром этого класса:

```java
Class<?> integerClass = new Integer(5).getClass();
assertTrue(integerClass.isInstance(new Integer(4)));
```

## Q11. (!) Что такое анонимный класс?

Анонимный класс в `Java` представляет собой специальный вид класса, который не имеет имени. Он создается именно в момент использования и используется для расширения или реализации интерфейсов одновременно.

Анонимные классы часто используются в следующем контексте:

1. Расширение класса: Мы можем создать анонимный класс, который расширяет уже имеющийся класс или производный от него подкласс, чтобы переопределить его методы или добавить новые.
2. Реализация интерфейса: Анонимные классы часто используются для реализации интерфейсов, не требуя наличия отдельного класса реализации. Они предоставляют возможность определить и реализовать методы интерфейса непосредственно в месте использования.

Пример использования анонимного класса:
```java
interface Greeting {
    void greet();
}

public class Main {
    public static void main(String[] args) {
        Greeting greeting = new Greeting() {
            @Override
            public void greet() {
                System.out.println("Привет, мир!");
            }
        };

        greeting.greet();
    }
}
```

В данном примере мы создаем анонимный класс, реализующий интерфейс `Greeting`, и переопределяющий его метод greet(). Затем мы создаем объект этого анонимного класса и вызываем его метод greet(). Результат работы программы будет вывод строки "Привет, мир!".

## Q12. Что такое `record` (`Java 14+`) и чем он отличается от обычного класса?

`Record` — компактный тип для хранения неизменяемых данных; объявляет компоненты (поля) в заголовке; компилятор генерирует конструктор, геттеры, `equals`, `hashCode`, `toString`. Отличие от обычного класса: все поля final; нет сеттеров; наследование только от интерфейсов; подходит для `DTO`, ключей, значений.

```java
// Обычный класс для сравнения — нужны поля, конструктор, геттеры, equals, hashCode вручную

    private final int x;
    private final int y;
    public PointClass(int x, int y) { this.x = x; this.y = y; }
    public int x() { return x; }
    public int y() { return y; }
    // equals, hashCode, toString — писать вручную
}

// Record — то же самое в одной строке; компилятор генерирует всё остальное
public record Point(int x, int y) {}
```

## Q13. Что такое `sealed class` (`Java 17`) и зачем он нужен?

`Sealed` class (sealed interface) — класс или интерфейс, разрешающий наследование/реализацию только перечисленным типам (permits). Ограничивает иерархию типов; компилятор знает все подтипы — удобно для pattern matching и exhaustive switch. Используют для моделирования закрытых иерархий (результат операции, состояние).

```java
// Только Success и Failure могут реализовывать Result; компилятор проверяет полноту switch
public sealed interface Result<T> permits Success, Failure {}
record Success<T>(T value) implements Result<T> {}
record Failure<T>(Throwable error) implements Result<T> {}

Result<String> r = getResult();
String s = switch (r) {
    case Success<String>(var v) -> v;
    case Failure<String>(var e) -> "error: " + e.getMessage();
};  // exhaustive — все варианты покрыты
```

## Q18. Что такое `type erasure` в `generics`?

`type erasure` — стирание информации о generic-параметрах во время компиляции; в байт-коде `List<String>` становится `List`, а параметры заменяются на `Object` (или границу типа).
```java
// После компиляции оба метода имеют одинаковую сигнатуру (raw List) — перегрузка по T невозможна
// public void process(List<String> list) { }
// public void process(List<Integer> list) { }  // ошибка компиляции: дублирование после erasure

// Обход: передать Class<T> для создания массивов/рефлексии
public <T> T[] toArray(List<T> list, Class<T> clazz) {
    @SuppressWarnings("unchecked")
    T[] arr = (T[]) java.lang.reflect.Array.newInstance(clazz, list.size());
    return list.toArray(arr);
}
```

Наследование: если родитель не `Serializable`, у потомка сериализуются только поля потомка; при десериализации родитель инициализируется конструктором по умолчанию. `serialVersionUID` фиксирует версию класса для совместимости. Типы влияют на то, какие поля попадают в поток и как восстанавливается граф объектов.

Практическая ценность ответа обычно повышается, если дополнить определение операционным контекстом: как решение ведёт себя под нагрузкой, при сбоях и в процессе сопровождения. На интервью ожидают, что вы назовёте критерии выбора и способ валидации решения через метрики и проверяемый сценарий.
