## Q1. (!) Что такое coroutines?

`Coroutines` (или корутины) — это понятие, используемое в программировании, чтобы описать легковесные "потоки выполнения", которые позволяют писать асинхронный код более последовательно и понятно. Они представляют собой концепцию для управления асинхронными операциями и потоками выполнения в языке программирования. `Coroutines` позволяют разрабатывать код, который может быть приостановлен и возобновлен в любой момент времени, не блокируя основной поток выполнения. Вместо того, чтобы создавать новые потоки для каждой асинхронной задачи, корутины позволяют работать существующими потоками более эффективно.

В реальном проекте здесь важно показать контракт API и предсказуемость поведения: `null-safety`, читаемость и совместимость с Java/корутинами. На интервью обычно ценят, когда кандидат называет типичные ошибки команды и конкретные практики предотвращения через тесты, review и статический анализ.

## Q2. (!) Что такое `Dispatchers` и `Context`?

Для указания потока, в котором должна выполняться корутина, в `Kotlin` используются различные диспетчеры и контексты. Вот несколько примеров:

1. `Dispatchers`:
   - `Dispatchers.Default`: это диспетчер по умолчанию, который используется для `CPU`-интенсивных операций. Он использует общий пул потоков.
   - `Dispatchers.IO`: этот диспетчер предназначен для ввода-вывода или сетевых операций, которые блокируют потоки. Он использует пул потоков, оптимизированный для ввода-вывода.
   - `Dispatchers.Main`: это диспетчер, который используется для выполнения корутин на главном потоке `Android`. Он доступен только при использовании `Kotlin Coroutines` для `Android`.
   - `Dispatchers.Unconfined`: этот диспетчер не привязан к конкретному потоку. Он делает передачу выполнения в произвольный поток и сохраняет основной или текущий поток выполнения.

2. `Context`:
   - `CoroutineScope`: вы можете создать свою собственную область видимости (`CoroutineScope`) и указать желаемый диспетчер при создании корутины.

```kotlin
val myCoroutineScope = CoroutineScope(Dispatchers.Default)

myCoroutineScope.launch {
}
```

   - `withContext()`: вы можете использовать функцию `withContext()`, чтобы временно изменить контекст выполнения корутины.

```kotlin
coroutineScope.launch {
    val result = withContext(Dispatchers.IO) {
    }
}
```

Использование различных диспетчеров и контекстов позволяет точно управлять выполнением корутин и выбирать подходящие потоки для разных типов операций. Необходимо учитывать, что корутины, выполняемые на главном потоке `Android` (`Dispatchers.Main`), должны удерживать возможность завершиться, чтобы избежать блокировки интерфейса пользователя.

## Q3. Как определить и запустить coroutines?

Для определения и запуска корутин (coroutines) в `Kotlin` необходимо использовать библиотеку `Kotlin Coroutines`. Вот как это можно сделать:

1. Добавьте зависимость на библиотеку `Kotlin Coroutines` в файле `build.gradle`:

```kotlin
dependencies {
    implementation 'org.jetbrains.kotlinx:kotlinx-coroutines-core:1.5.0'
}
```

2. Импортируйте функции и классы, связанные с корутинами:

```kotlin
import kotlinx.coroutines.*
```

3. Определите функцию, которую вы хотите запустить как корутин:

```kotlin
fun myCoroutineFunction() {
}
```

4. Запустите корутин с помощью функции launch():

```kotlin
fun main() {
    val myCoroutine = GlobalScope.launch {
        myCoroutineFunction()
    }

    runBlocking {
        myCoroutine.join()
    }
}
```

Обратите внимание, что `GlobalScope` используется для создания корутины в примере выше. Вместо этого можно создать свою собственную область видимости (`CoroutineScope`) для управления жизненным циклом корутин.

Также, в коде корутины можно использовать различные сопрограммные строители, такие как async(), `withContext()`, delay() и другие, для реализации асинхронных операций, ожиданий и обработки результатов.

Важно отметить, что корутины используются для выполняемых асинхронно задач без выполнения блокировки потока, что позволяет более эффективно использовать ресурсы и писать асинхронный код как синхронный.

## Q4. (!) Разница между `Threads` и `Coroutines`?

Давайте разберёмся в разнице между потоками и корутинами более подробно:

1. Потоки (`Threads`):
   - Потоки это низкоуровневая абстракция операционной системы, представляющая параллельную работу.
   - Каждый поток имеет свою собственную стековую память и может выполнять инструкции независимо от других потоков.
   - Потоки позволяют выполнять несколько задач одновременно, в разных потоках.
   - Операционная система управляет планированием потоков и распределяет процессорное время между ними.

2. Корутины (`Coroutines`):
   - Корутины это более высокоуровневая абстракция, предоставляемая языком программирования или библиотекой.
   - Корутины позволяют разрабатывать асинхронный код, который выглядит последовательным и естественным.
   - Корутины не являются независимыми сущностями, а представляют собой обусловленный пользователем способ приостанавливать и возобновлять выполнение кода.
   - В отличие от потоков, корутины выполняются на основе потоков или пула потоков, что позволяет эффективно использовать ресурсы и избегать проблем с многопоточностью.
   - Управление корутинами происходит внутри программы, а не операционной системой, что делает их более гибкими и производительными.

В общем, потоки предоставляют параллельную работу за счёт использования отдельных потоков, в то время как корутины позволяют разрабатывать асинхронный код последовательно и эффективно использовать ресурсы путём переиспользования тех же потоков. Выбор между потоками и корутинами зависит от требований и характера вашего проекта.

С точки зрения производительности потоки и корутины (корутины) имеют некоторые различия и особенности:

1. Создание и уничтожение:
   - Создание и уничтожение потоков требует значительных накладных расходов, так как требуется выделить и освободить память, скопировать данные, настроить межпоточную синхронизацию и т.д.
   - В то же время, создание и уничтожение сопрограмм имеет намного меньшие затраты, так как это легковесные задачи, не требующие отдельного выделения памяти.

2. Переключение контекста:
   - Переключение контекста между потоками осуществляется операционной системой. Это занимает время и может потребовать синхронизации данных.
   - Переключение контекста между корутинами происходит внутри программы и требует намного меньше времени, так как оно не зависит от операционной системы. Также корутины могут выполняться на одном потоке, что устраняет накладные расходы на переключение.

3. Ресурсы:
   - Каждый поток требует выделения собственной стековой памяти, что может быть затратным при большом количестве потоков.
   - Корутины могут запускаться в рамках одного или нескольких потоков и могут переиспользовать уже выделенные ресурсы. Это позволяет снизить накладные расходы на управление памятью.

Итак, корутины обычно более производительны и эффективны, чем потоки, благодаря своей легковесной природе. Они позволяют эффективнее использовать ресурсы и управлять асинхронным кодом, не прибегая к созданию и уничтожению большого количества потоков. Однако выбор между ними должен основываться на требованиях и характеристиках вашего конкретного проекта.

## Q5. (!) Что такое `Suspend` функция?

Функции приостановки (suspend functions) являются основным строительным блоком в `Kotlin Coroutines`. Они позволяют создавать асинхронные и неблокирующие операции без необходимости использования явных колбэков или конструкций с "`callback` hell".

Основная идея функций приостановки заключается в том, что они могут быть приостановлены на время выполнения асинхронной операции без блокирования потока исполнения. Приостановка функции возможна только внутри корутины и осуществляется с помощью ключевого слова suspend.

Когда функция приостанавливается, управление передается обратно в вызывающую функцию или корутину, которая может продолжить выполнение другой задачи. Когда асинхронная операция завершается, выполнение функции приостанавливается, а результат возвращается в место вызова. Пример функции приостановки:

```kotlin
suspend fun fetchData(): String {
    delay(1000)
    return "Данные получены"
}
```

В этом примере функция `fetchData` объявлена с ключевым словом suspend, что позволяет использовать её внутри корутин. Она имитирует асинхронную операцию с помощью функции delay, которая приостанавливает выполнение корутины на заданное количество времени.

В результате использования функций приостановки, асинхронный код становится более лаконичным и понятным. Это позволяет упростить работу с асинхронными операциями, такими как сетевые запросы, чтение/запись в файлы, работа с базами данных и другие асинхронные операции.

## Q6. (!) Асинхронность и параллелизм

`Kotlin Coroutines API` предоставляет мощные возможности для выполнения асинхронного программирования и управления параллелизмом. Вот некоторые способы использования `Kotlin Coroutines API` в коде:

1. Асинхронные операции:
   - Использование функции launch(): Вы можете запустить асинхронную операцию в корутине с помощью функции launch(). Это позволяет выполнять операцию асинхронно без блокировки основного потока.

```kotlin
GlobalScope.launch {
}
```

   - Использование функции async() и ожидание результата: Вы можете использовать функцию async(), чтобы выполнить асинхронную операцию и получить результат типа `Deferred`, который можно использовать позже для получения финального результата. Функция await() ожидает завершения операции и возвращает результат.

```kotlin
val result: Deferred<Int> = GlobalScope.async {
    return@async 42
}

val finalResult = runBlocking {
    val asyncResult = result.await()
}
```

   - Использование `withContext()`: Вы можете использовать функцию `withContext()`, чтобы выполнить асинхронную операцию на различных диспетчерах и вернуть результат операции.

```kotlin
val result = withContext(Dispatchers.IO) {
    return@withContext 42
}
```

2. Параллельность:
   - Использование функции async() и `awaitAll()`: Если у вас есть несколько асинхронных операций, которые можно выполнять параллельно, вы можете использовать функцию async() для запуска каждой операции и функцию `awaitAll()` для ожидания завершения всех операций.

```kotlin
val result1: Deferred<Int> = GlobalScope.async {
    return@async 42
}

val result2: Deferred<String> = GlobalScope.async {
    return@async "Hello"
}

val finalResult = runBlocking {
    val results = awaitAll(result1, result2)
}
```

   - Использование функции `concurrentMap()`: Вы можете использовать функцию `concurrentMap()` из библиотеки `kotlinx.coroutines`, чтобы параллельно обрабатывать элементы коллекции.

```kotlin
val list = listOf(1, 2, 3, 4, 5)

val results = runBlocking {
    list.concurrentMap {
        return@concurrentMap it * 2
    }
}
```

Кроме того, `Kotlin Coroutines API` предоставляет и другие функции и возможности для управления асинхронным кодом, такие как отмена корутин, обработка исключений и управление временем ожидания. Он также интегрируется с различными библиотеками и фреймворками, такими как `Retrofit`, `Room`, `Android Jetpack` и другими, что делает работу с асинхронным кодом еще более удобной и мощной.

## Q7. (!) В чем разница между асинхронным кодом и параллельным кодом?

Разница между асинхронным кодом и параллельным кодом в `Kotlin` заключается в способе управления выполнением задач и использовании системных ресурсов.

Асинхронный код относится к ситуации, когда задачи выполняются независимо друг от друга, без явного использования параллелизма или многопоточности. В асинхронном коде задачи могут выполняться последовательно, но с возможностью приостановки и продолжения других задач во время блокирующих операций, таких как сетевые запросы или операции ввода-вывода. Это может быть достигнуто с использованием конструкций асинхронного программирования, таких как колбэки, промисы, фьючеры или корутины.

Параллельный код, с другой стороны, относится к ситуации, когда задачи выполняются одновременно на нескольких процессорах, ядрах или потоках. Параллельное исполнение задач позволяет использовать вычислительные ресурсы более эффективно и ускоряет выполнение программы. В `Kotlin` для реализации параллельного кода можно использовать средства многопоточности, такие как классы `Thread`, `ExecutorService` или корутины с использованием диспетчера `Dispatchers.Default`.

Таким образом, основная разница между асинхронным кодом и параллельным кодом состоит в том, что асинхронный код позволяет эффективно управлять блокирующими операциями, не блокируя исполнение программы, в то время как параллельный код использует несколько потоков или ядер для выполнения задач одновременно и повышения общей производительности программы.

## Q8. (!) В чем разница между launch() и async()?

launch() и async() являются функциями из пакета `kotlinx.coroutines` и используются для создания сопрограмм. Они имеют некоторые различия в поведении и возвращаемых значениях.

1. launch():
   - Не возвращает никакого значения.
   - Запускает новую корутину параллельно с вызывающей сопрограммой.
   - Не ожидает завершения запущенной корутины и продолжает выполнение без блокировки. Пример использования launch():

```kotlin
GlobalScope.launch {
}
```

2. async():
   - Возвращает отложенное значение, представленное типом `Deferred`.
   - Запускает новую корутину параллельно с вызывающей сопрограммой.
   - Ожидает завершения запущенной корутины при вызове функции await() для получения результата. Пример использования async():

```kotlin
val deferredResult = GlobalScope.async {
}

val result = deferredResult.await()
```

Когда следует использовать каждую из функций зависит от конкретной ситуации:

1. Используйте launch(), если вам не важно получить результат выполняемой корутины, и вы хотите, чтобы она выполнялась независимо в фоне. Например, это может быть полезно, когда вам нужно выполнить асинхронную задачу, которая не требует возвращения результата, или когда вам нужно параллельно запустить несколько независимых задач.
2. Используйте async(), если вам нужно получить результат выполнения корутины. Например, когда вам нужно выполнить несколько параллельных вычислительных задач и получить результаты каждой из них для последующей обработки или агрегации.

Если вам нужно запустить корутины параллельно, но вам не важны их результаты, вы можете использовать launch(). Если вам важны результаты и вы хотите получить их в дальнейшем, то async() предоставляет доступ к отложенному значению, которое можно ожидать и получить позднее с помощью await().

## Q9. (!) Что произойдет, если мы вызовем `Suspend` функцию из другой `Suspend` функции?

Если вы вызываете функцию приостановки из другой функции приостановки, то выполнение первой функции будет приостановлено до завершения второй функции.

При вызове функции приостановки suspend, управление передается обратно в вызывающую функцию или корутину, которая может решить, что делать дальше. Если вызывающая функция или корутина также является функцией приостановки, то ее выполнение также будет приостановлено до завершения следующей функции приостановки в цепочке вызовов. Пример:

```kotlin
suspend fun suspendFunction1() {
    println("Приостановка функции 1")
    suspendFunction2()
    println("Возобновление функции 1")
}

suspend fun suspendFunction2() {
    println("Приостановка функции 2")
    delay(1000)
    println("Возобновление функции 2")
}
```

При вызове функции `suspendFunction1` сначала будет выведено сообщение "Приостановка функции 1". Затем будет вызвана функция `suspendFunction2`, которая также приостановит выполнение до завершения задержки. По истечении 1 секунды будет выведено сообщение "Возобновление функции 2", а затем контроль вернется к `suspendFunction1`, которая продолжит выполнение и выведет сообщение "Возобновление функции 1".

Таким образом, вызов функции приостановки из другой функции приостановки приводит к последовательному выполнению кода и ожиданию завершения каждой вызванной функции, пока не будет возобновлено выполнение предыдущей функции в цепочке вызовов.

## Q10. (!) Что произойдет, если внутри `Coroutines` возникнет `Exception`?

Если внутри корутины возникнет исключение, по умолчанию оно будет исключено исключением вверх по стеку вызовов и может вызвать отмену задания.

Вот что происходит, когда исключение возникает внутри корутины:

1. Исключение внутри корутины:
   - Если внутри корутины возникает исключение, оно будет подавлено внутри корутины на месте, где оно было вызвано.
   - Исключение не прекратит выполнение кода в других корутинах или в вызывающем коде за пределами корутины.

2. Отмена задания:
   - Исключение в сопрограмме может вызвать отмену задания, если код корутины явно проверяет флаг отмены с помощью `isActive` или использует приостановку с помощью функции yield() или delay().
   - При вызове cancel() на объекте Job или при отмене родительского задания, любая текущая выполняемая корутина, а также все простаивающие корутины будут отменены.
   - Отмена задания осуществляется путем установки флага `isActive` в `false`, что позволяет коду в сопрограмме проверить этот флаг и завершить выполнение.

3. Обработка исключений:
   - Вы можете использовать конструкцию try-сatch внутри корутины для обработки исключений и принятия соответствующих мер.
   - Если исключение не обрабатывается внутри корутины, оно может быть исключено на уровне вызывающего кода или поймано вышестоящим обработчиком исключений.

Важно отметить, что обработка исключений может быть произвольной и зависит от конкретной реализации кода корутины и вызывающего кода. Желательно обрабатывать исключения внутри корутины с помощью конструкции try-сatch и использовать функционал отмены задания для более плавного завершения и управления выполнением корутины.

## Q11. Пример одновременно запуска двух задач

Конечно! Вот пример, когда две задачи необходимо запустить одновременно, а не последовательно:

```kotlin
import kotlinx.coroutines.GlobalScope
import kotlinx.coroutines.delay
import kotlinx.coroutines.launch
import kotlinx.coroutines.runBlocking

fun main() = runBlocking {
    println("Start")

    GlobalScope.launch {
        println("Задача 1 запущена")
        delay(1000)
        println("Задача 1 завершена")
    }

    GlobalScope.launch {
        println("Задача 2 запущена")
        delay(1000)
        println("Задача 2 завершена")
    }

    println("End")
}
```

В данном примере используются корутины из пакета `kotlinx.coroutines`. Функция launch вызывается два раза для запуска двух задач. Каждая задача имитирует выполнение с помощью операции задержки delay на 1 секунду. При запуске двух задач с использованием launch, они будут выполняться параллельно, без ожидания завершения предыдущей задачи.

Результат выполнения программы может быть следующим:

```text
Start
Задача 1 запущена
Задача 2 запущена
End
Задача 1 завершена
Задача 2 завершена
```

Как видно из вывода, задачи 1 и 2 запускаются одновременно и выполняются параллельно, а вывод "End" отображается до их завершения. Это позволяет ускорить выполнение программы и использовать вычислительные ресурсы более эффективно.

## Q12. (!) Что такое Job? В чём разница Job и `CoroutineScope`?

В пакете `kotlinx.coroutines` в `Kotlin` объект Job является управляющей структурой для работы с корутинами. Он представляет собой уникальный идентификатор задания с возможностью управления его состоянием, отмены и ожидания завершения.

Вот некоторые основные аспекты объекта Job:

1. Управление состоянием:
   - Job предоставляет методы для управления состоянием задания, такие как start(), cancel(), `isCompleted`, `isActive`, `isCancelled` и другие.
   - Вы можете использовать методы `isCompleted`, `isActive` и `isCancelled`, чтобы проверить состояние задания и принять соответствующие меры.

2. Отмена задания:
   - Вы можете использовать метод cancel() для отмены задания.
   - После вызова cancel() флаг `isCancelled` задания становится `true`.
   - Задание может быть отменено, а может и не быть, в зависимости от реализации кода корутины. Отмена является кооперативной, и код корутины должен периодически проверять флаг отмены и завершаться при необходимости.

3. Ожидание завершения:
   - Вы можете использовать метод join() для ожидания завершения задания.
   - Метод join() блокирует текущий поток выполнения до тех пор, пока задание не завершится.

Объект `CoroutineScope`, с другой стороны, является контекстом выполнения для корутины. Он связывает корутину с жизненным циклом или областью, в которой она выполняется. Он предоставляет методы для запуска сопрограмм и управления ими. Основные аспекты объекта `CoroutineScope`:

1. Управление корутинами:
   - `CoroutineScope` предоставляет методы для запуска сопрограмм, такие как launch и async.
   - Методы launch и async возвращают объект Job, который представляет запущенную корутину, и вы можете использовать его для управления заданием.

2. Жизненный цикл:
   - `CoroutineScope` связывает корутины с жизненным циклом или областью, в которой они выполняются.
   - Когда ваша область или жизненный цикл заканчивается, все корутины, запущенные в этой области, автоматически отменяются.

Коротко говоря, объект Job представляет собой управляющую структуру для отдельного задания с возможностью управления его состоянием и отмены, тогда как `CoroutineScope` представляет собой контекст выполнения для корутины и предоставляет методы для запуска и управления корутинами.

## Q13. Как отменить запущенный Job?

В `Kotlin` с использованием пакета `kotlinx.coroutines` можно отменить запущенные задания с помощью функции cancel() на объекте Job, возвращаемом при запуске корутины. Вот несколько способов отменить задание:

1. Отменить задание по условию:

```kotlin
val job = GlobalScope.launch {
}

if (условие) {
    job.cancel()
}
```

2. Отменить задание после определенного времени:

```kotlin
val job = GlobalScope.launch {
}

delay(5000)
job.cancel()
```

3. Отменить несколько заданий:

```kotlin
val job1 = GlobalScope.launch {
}

val job2 = GlobalScope.launch {
}

job1.cancel()
job2.cancel()
```

4. Использовать yield() для проверки флага отмены:

```kotlin
val job = GlobalScope.launch {
    while (isActive) {
        yield()
    }
}
```

`isActive` является свойством, которое возвращает `true`, если задание не было отменено, и `false`, если задание было отменено.

Важно отметить, что отмена задания является кооперативной. То есть, само по себе вызов метода cancel() не останавливает выполнение корутины, он только устанавливает флаг отмены. Код корутины должен периодически проверять этот флаг и завершаться, если задание отменено. Это может быть осуществлено с помощью вызова функций yield() или проверки значения свойства `isActive`.

## Q14. (!) Распространенные ошибки при работе с `Coroutines`

При работе с корутинами в `Kotlin` могут возникать различные ошибки или проблемы. Ниже представлен список распространенных ошибок, которые могут возникнуть при использовании сопрограмм:

1. Забывание вызвать start() или launch(): Важно вызывать метод start() или launch() для запуска корутины. Если этот шаг был пропущен, корутина не будет выполнена.
2. Неправильный диспетчер: Выбор правильного диспетчера важен для эффективной работы с корутинами. Использование неправильного диспетчера (например, `Dispatchers.Main` в неподходящем контексте) может привести к блокированию главного потока или ошибкам в работе приложения.
3. Утечка памяти: Если корутина не корректно завершается или отменяется, это может привести к утечке памяти. Убедитесь, что ваш код корректно обрабатывает завершение и отмену сопрограмм и освобождает все ресурсы.
4. Взаимное блокирование: Использование сопрограмм внутри других сопрограмм может привести к взаимному блокированию (`deadlock`), если одна корутина ожидает завершения другой, которая в свою очередь ожидает завершения первой. Избегайте блокировки, используя правильные конструкции, такие как async и await.
5. Исключения и обработка ошибок: Необходимо корректно обрабатывать исключения, возникающие внутри сопрограмм. Незахваченное исключение может привести к аварийному завершению приложения или неожиданному поведению. Используйте конструкцию try-сatch или функцию `CoroutineExceptionHandler` для обработки ошибок.
6. Неправильная последовательность выполнения: Использование асинхронных операций может изменить порядок выполнения кода. Неправильная последовательность выполнения может привести к непредсказуемым результатам или ошибкам. Убедитесь, что ваш код правильно управляет последовательностью выполнения и использует нужные операторы, такие как async и await.

Важно следить за этими распространенными ошибками и правильно обрабатывать ситуации, когда они возникают, чтобы обеспечить стабильную и эффективную работу с корутинами в `Kotlin`.

## Q15. (!) Рекомендации при работе с `Coroutines`

При использовании сопрограмм в `Kotlin` следует соблюдать следующие рекомендации:

1. Используйте `CoroutineScope`: Создавайте области корутин с помощью `CoroutineScope`, чтобы контролировать жизненный цикл ваших сопрограмм. Не забывайте отменять корутины, когда они больше не нужны, чтобы избежать утечек памяти.
2. Выберите подходящий диспетчер: Выберите диспетчер, который наилучшим образом соответствует потребностям вашего кода. Если вам нужен доступ к основному потоку `UI`, используйте `Dispatchers.Main`, если требуется выполнение в фоновом режиме, используйте `Dispatchers.Default`, а для ввода-вывода и блокирующих операций используйте `Dispatchers.IO`.
3. Обрабатывайте ошибки: Обрабатывайте исключения, которые возникнут внутри корутины, с помощью конструкции try-сatch или функции `CoroutineExceptionHandler`. Это поможет предотвратить аварийное завершение приложения и предоставит возможность корректно обработать ошибку.
4. Не блокируйте потоки: Избегайте блокировки основного потока или других потоков при помощи долгих операций в корутинах. Вместо этого используйте неблокирующие операции или асинхронные вызовы, чтобы не блокировать выполнение других операций и держать приложение отзывчивым.
5. Используйте async и await для параллельных операций: Для выполнения параллельных операций используйте async и await. async создаёт отложенное значение, которое может быть использовано позже, а await ожидает завершения всех отложенных значений.
6. Управляйте задержкой и таймаутами: Используйте функции delay и `withTimeout` для управления задержкой и настройки таймаутов операций в корутинах. Это позволит избежать блокировки и предотвратить зависание приложения.
7. Избегайте вложенных сопрограмм: Полностью избегайте вложенных сопрограмм, которые могут привести к взаимной блокировке. Вместо этого, используйте конструкцию async и await, чтобы управлять выполнением нескольких сопрограмм.
8. Тестируйте корутины: При написании кода с использованием сопрограмм, убедитесь, что вы также покрываете тестами логику вашего кода, включая корутины. Используйте инструменты, такие как `TestCoroutineDispatcher`, `TestCoroutineScope` или `runBlockingTest`, чтобы упростить тестирование ваших сопрограмм.

Следование этим рекомендациям поможет вам правильно использовать корутины в `Kotlin` и достичь эффективной и безопасной асинхронной обработки в вашем коде.

## Q17. Что такое `runBlocking` и когда его использовать?

`runBlocking` — блокирующий строитель корутин: он блокирует текущий поток до полного завершения переданного блока. Внутри блока можно вызывать suspend-функции. Используется в основном в main, в тестах или в скриптах, где нужно дождаться завершения корутин перед выходом. В production-коде (серверы, `Android`) `runBlocking` использовать не следует: он блокирует поток и может привести к `deadlock` при вызове из корутины или из диспетчера с ограниченным пулом.

В реальном проекте здесь важно показать контракт API и предсказуемость поведения: `null-safety`, читаемость и совместимость с Java/корутинами. На интервью обычно ценят, когда кандидат называет типичные ошибки команды и конкретные практики предотвращения через тесты, review и статический анализ.

## Q19. Как работает отмена родительской корутины (родитель отменяет детей)?

При отмене Job родительской корутины (или `CoroutineScope`) отменяются все дочерние Job. Отмена распространяется вниз по иерархии. Дочерние корутины получают отмену через `isActive` и `CancellationException`; они должны завершаться кооперативно (проверять отмену, не блокировать поток). Родитель не завершится, пока не завершатся все дети (если использовался launch/ async без Job с особым поведением). Это ключевой механизм structured concurrency.

## Q22. Что такое `Channel` и чем отличается от `Flow`?

`Channel` — горячий поток данных между корутинами: отправитель (send) и получатель (receive) работают с одним и тем же каналом; данные доставляются одному потребителю. Подходит для передачи событий, очередей «производитель–потребитель». `Flow` — холодный поток: каждый коллектор запускает свой экземпляр эмиссии; данные вычисляются по запросу. `Flow` не передаёт данные между корутинами «по трубе», а описывает последовательность значений. `Channel` — для коммуникации; `Flow` — для описания потока данных и отложенных вычислений.

## Q23. Что такое `Flow` и cold vs hot `stream`?

`Flow` — тип холодного потока в `Kotlin`: коллектор вызывает collect, и только тогда начинается выполнение блока flow { ... }; эмиссии происходят по запросу. Один и тот же `Flow` при нескольких вызовах collect запускается заново для каждого коллектора (cold). Горячий поток — когда эмиссия идёт независимо от подписчиков; несколько подписчиков могут получать одни и те же данные (например, `SharedFlow`, `StateFlow`, или обёртка `Channel`). `Flow` по умолчанию cold; для hot используют `SharedFlow / StateFlow` или `channelFlow` с осторожностью.

## Q24. Как обеспечить отмену при таймауте (`withTimeout`, `withTimeoutOrNull`)?

`withTimeout`(millis) { ... } выполняет блок и отменяет его с `TimeoutCancellationException`, если выполнение превысило заданное время. `withTimeoutOrNull`(millis) { ... } делает то же, но при таймауте возвращает `null` вместо исключения. Оба отменяют корутину кооперативно: внутри блока должны выполняться проверки отмены (`isActive`, yield), иначе отмена сработает только в следующей точке приостановки.

## Q26. В чём разница между `GlobalScope` и scope с жизненным циклом?

`GlobalScope` — scope с жизненным циклом приложения: корутины в нём не отменяются при уничтожении экрана или компонента, что легко приводит к утечкам памяти и работе после уничтожения `Activity / ViewModel`. `Scope` с жизненным циклом (`lifecycleScope`, `viewModelScope`) привязан к компоненту: при его уничтожении scope отменяется и все корутины завершаются. Для приложений с `UI` или сервисами всегда предпочтительны scope с жизненным циклом; `GlobalScope` — только для операций, которые должны жить всё время работы приложения и явно управляются.

## Q27. Что такое structured concurrency в корутинах?

`Structured` concurrency — подход, при котором корутины запускаются только внутри `CoroutineScope`; у каждой корутины есть родитель; отмена родителя отменяет детей; родитель приостанавливается до завершения детей. Это даёт предсказуемую отмену, отсутствие «потерянных» корутин и единую точку обработки ошибок (scope). Противоположность — «огнестрельные» корутины в `GlobalScope` без привязки к scope, что усложняет отмену и контроль.

## Q29. Что такое `yield` и `ensureActive`, зачем они нужны?

yield() — приостанавливает текущую корутину и отдаёт выполнение другим корутинам в том же диспетчере; при возобновлении проверяется отмена. Используется в длинных циклах без точек приостановки, чтобы дать возможность отмене сработать и не «монополизировать» поток. `ensureActive()` — проверяет Job.`isActive` и сразу бросает `CancellationException`, если job отменён. Нужен для явной проверки отмены в местах, где нет естественных приостановок (тяжёлые циклы, нативные вызовы).
