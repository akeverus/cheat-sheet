## Q1. Что такое `SQL`?

`SQL` (`Structured Query Language`) — это стандартный язык программирования, используемый для работы с реляционными базами данных. `SQL` позволяет выполнять различные операции над данными, такие как создание таблиц, вставка, обновление и удаление записей, а также запросы для извлечения информации из базы данных. Он широко используется в различных областях разработки программного обеспечения, включая веб-разработку, анализ данных и управление базами данных. `SQL` предоставляет мощные инструменты для управления и манипулирования данными.

На практике этот выбор почти всегда подтверждают измерениями: планом выполнения запросов, профилем нагрузки и latency по p95/p99. В интервью полезно коротко обозначить, как именно вы проверяете гипотезу и какие метрики будут критерием успешности.

## Q2. (!) В чём разница `PRIMARY KEY` и `UNIQUE`?

Ограничения `PRIMARY KEY` и `UNIQUE` имеют сходства, поскольку оба обеспечивают уникальность значений в столбце или наборе столбцов в таблице. Однако есть несколько отличий между ними:

1. Количество столбцов: Ограничение `PRIMARY KEY` может быть применено только к одному или нескольким столбцам, которые уникально идентифицируют каждую запись в таблице. В то время как ограничение `UNIQUE` может быть применено к одному или нескольким столбцам, но не является необходимым для идентификации каждой записи уникальным.
2. `NULL` значения: Ограничение `PRIMARY KEY` не разрешает значения `NULL` в столбце или наборе столбцов, тогда как ограничение `UNIQUE` разрешает одно `NULL` значение (если не указано иное).
3. Связь с внешними ключами: Ограничение `PRIMARY KEY` может быть ссылкой для внешнего ключа в другой таблице, тогда как ограничение `UNIQUE` не может быть ссылкой для внешнего ключа.
4. Количество ограничений: В одной таблице может быть только одно ограничение `PRIMARY KEY`, которое определяет идентификатор для каждой записи. В то время как ограничение `UNIQUE` может быть применено к нескольким столбцам и/или комбинации столбцов с целью обеспечения уникальности значений в этих столбцах или комбинациях.

В целом, ограничение `PRIMARY KEY` используется для идентификации уникальных записей в таблице, в то время как ограничение `UNIQUE` ограничивает значения в столбце или наборе столбцов от дублирования. Оба ограничения полезны в зависимости от требований базы данных и структуры данных.

## Q3. (!) Какие ограничения на целостность данных существуют в `SQL`?

В `SQL` существуют несколько ограничений на целостность данных, которые гарантируют правильность и согласованность данных в базе данных. Вот некоторые из них:

1. Ограничения `PRIMARY KEY` (первичный ключ): Первичный ключ уникально идентифицирует каждую запись в таблице и не может содержать дубликатов или `NULL` значений.
2. Ограничения `FOREIGN KEY` (внешний ключ): Внешний ключ связывает две таблицы на основе значений столбца, соответствующего первичному ключу другой таблицы. Он обеспечивает целостность ссылочных данных, контролируя ссылки на другой таблице.
3. Ограничения `UNIQUE` (уникальное): Ограничение `UNIQUE` обеспечивает уникальность значений в столбце или наборе столбцов. Оно не позволяет повторяющимся значениям в указанном столбце или столбцах.
4. Ограничения `NOT NULL` (не пустое): Ограничение `NOT NULL` не позволяет значениям `NULL` в указанном столбце. Таким образом, этот столбец должен иметь непустые значения.
5. Ограничения `CHECK` (проверочное): Ограничение `CHECK` позволяет определить условие, которому должны соответствовать значения в столбце для выполнения операции `INSERT` или `UPDATE`. Например, ограничение `CHECK` может проверять, чтобы значение в столбце было положительным или находилось в определенном диапазоне.
6. Ограничения `DEFAULT` (по умолчанию): Ограничение `DEFAULT` позволяет установить значение по умолчанию для столбца. Если для столбца не указано значения в операции `INSERT`, будет использовано значение по умолчанию.

Эти ограничения на целостность данных играют важную роль в поддержании правильности и последовательности данных в базе данных, предотвращая нежелательные изменения или некорректные данные.

## Q4. В чём разница между `DATETIME` и `TIMESTAMP`?

Типы данных `DATETIME` и `TIMESTAMP` используются в базах данных для хранения и обработки даты и времени. Вот основные отличия между ними:

1. Диапазон значений: Тип данных `DATETIME` поддерживает диапазон значений от '1000-01-01 00:00:00' до '9999-12-31 23:59:59'. Тип данных `TIMESTAMP` ограничен диапазоном значений от '1970-01-01 00:00:01' `UTC` до '2038-01-19 03:14:07' `UTC`.
2. Хранение данных: В `MySQL` и `MariaDB` тип данных `DATETIME` хранит значения в формате `YYYY-MM-DD HH:MM:SS`. Тип данных `TIMESTAMP` также хранит значения в формате `YYYY-MM-DD HH:MM:SS`, но с учётом временной зоны `UTC`.
3. Временная зона: В отличие от типа данных `DATETIME`, тип данных `TIMESTAMP` автоматически преобразует значения в `UTC` для хранения и обратно в местное время при извлечении. Это обеспечивает автоматический учет временных зон при работе с данными.
4. Автоматическое обновление: В некоторых СУБД, таких как `MySQL`, тип данных `TIMESTAMP` может быть настроен на автоматическое обновление при каждом изменении строки. В то же время тип данных `DATETIME` не имеет такой функциональности.
5. Размер хранилища: В некоторых СУБД размер хранилища для типа данных `TIMESTAMP` меньше, чем для типа данных `DATETIME`. Например, в `MySQL` тип данных `TIMESTAMP` требует 4 байта, а тип данных `DATETIME` — 8 байт.

Использование типов данных `DATETIME` и `TIMESTAMP` зависит от конкретных требований проекта. Если вам нужны даты и время в определенном диапазоне, и вам не нужно учитывать временные зоны, то `DATETIME` может быть предпочтительным выбором. Если вам важна учет временных зон и вы работаете с базой данных, которая поддерживает автоматическое обновление `TIMESTAMP`, то `TIMESTAMP` может быть более удобным и гибким вариантом.

## Q5. (!) Может ли `FOREIGN KEY` равняться `NULL`?

Да, значение в столбце, на который наложено ограничение `FOREIGN KEY`, может равняться `NULL`. Ограничение `FOREIGN KEY` указывает связь между значениями в столбце, который является внешним ключом, и значениями в столбце, который является первичным ключом в другой таблице.

Когда значение в столбце, на который наложено ограничение `FOREIGN KEY`, равно `NULL`, это означает, что нет соответствующей записи в таблице, связанной с данным внешним ключом. Такое значение `NULL` может быть разрешено или запрещено, в зависимости от настроек ограничения `FOREIGN KEY`.

Некоторые базы данных позволяют столбцу, на который наложено ограничение `FOREIGN KEY`, принимать значения `NULL`, что означает, что запись может быть несвязанной или не иметь ссылки на запись в другой таблице. В таких случаях, такая связь будет считаться "незавершенной" или "нулевой".

Однако есть базы данных, в которых значения `NULL` в столбце, на который наложено ограничение `FOREIGN KEY`, запрещены. Это означает, что каждое значение в этом столбце должно ссылаться на существующую запись в другой таблице.

Поэтому, возможность использования значений `NULL` в столбце с ограничением `FOREIGN KEY` зависит от конкретных настроек и требований базы данных.

## Q6. Какие существуют операторы `SQL`?

В `SQL` существует широкий набор операторов, которые позволяют выполнить различные действия с данными. Вот некоторые из наиболее часто используемых операторов `SQL`:

1. `SELECT`: Используется для выборки данных из базы данных.
2. `INSERT`: Используется для вставки новых записей в таблицу.
3. `UPDATE`: Используется для обновления существующих записей в таблице.
4. `DELETE`: Используется для удаления записей из таблицы.
5. `JOIN`: Используется для объединения данных из разных таблиц.
6. `WHERE`: Используется для задания условий выборки данных.
7. `GROUP BY`: Используется для группировки данных по определенным столбцам.
8. `ORDER BY`: Используется для сортировки данных по определенным столбцам.
9. `HAVING`: Используется для задания условий выборки после выполнения группировки данных.
10. `UNION`: Используется для объединения результатов двух или более запросов.

Это лишь некоторые из операторов `SQL`, и существует еще множество других операторов, позволяющих выполнять более сложные действия с данными.

## Q7. Что означает `NULL` в `SQL`?

В `SQL`, `NULL` обозначает отсутствие значения или неопределенное значение. `NULL` является особым значением, которое может быть использовано в столбцах таблицы. Если столбец имеет значение `NULL`, это означает, что для данной ячейки нет конкретного значения или значение неизвестно. `NULL` отличается от пустого значения или нуля. Пустое значение означает, что ячейка содержит некоторое значение, но оно отсутствует или не определено, а нуль обозначает конкретное значение, равное нулю.

Когда работаем с данными в `SQL`, важно правильно обрабатывать значения `NULL`, чтобы избежать ошибок и получить корректные результаты.

## Q8. Что такое `Temporary` table?

Временная таблица в `SQL` это таблица, которая существует только в пределах текущего сеанса или соединения с базой данных. Она создается и используется временно для выполнения определенных операций или сохранения временных результатов.

Временная таблица может быть создана с помощью ключевого слова `CREATE TEMPORARY TABLE` или `CREATE TABLE` с префиксом `#` или `##` перед именем таблицы. Она может иметь структуру и столбцы, а также может быть заполнена данными, аналогично постоянной таблице.

Временная таблица обычно используется в следующих случаях:

1. Хранение временных или промежуточных результатов запроса. Временная таблица может быть использована для сохранения промежуточных данных при выполнении сложных операций или обработке больших объёмов данных.
2. Разделение данных для разных пользователей или сеансов. Каждый сеанс или пользователь может иметь свою собственную временную таблицу для выполнения операций без вмешательства других пользователей.
3. Работа с различными пакетами программного обеспечения или процессами. Временные таблицы могут быть использованы для обмена данными между различными компонентами или процессами.

Обычно временные таблицы автоматически удаляются после завершения сеанса или закрытия соединения с базой данных, хотя некоторые СУБД предоставляют возможность явного удаления временных таблиц.

## Q9. Что такое `View`?

Представление (view) в `SQL` представляет собой виртуальную таблицу, которая основана на результатах выполнения запроса к одной или нескольким реальным таблицам в базе данных. Представление не содержит фактических данных, а предоставляет собой логическую оболочку для доступа и работы с данными.

Представление создается с использованием ключевого слова `CREATE VIEW` и может быть использовано вместо основных таблиц при выполнении запросов. Оно может содержать только выбранные столбцы и строки из исходных таблиц или комбинировать данные из нескольких таблиц, скрывая сложность составления запроса от конечного пользователя.

Представления используются для следующих целей:

1. Упрощение доступа к данным: Представление может скрыть сложные или длинные запросы за простым именем представления, облегчая доступ и повышая удобство использования данных.
2. Ограничение доступа: Представления могут быть использованы для ограничения доступа пользователей к определенным столбцам или строкам данных, скрывая конфиденциальные сведения и обеспечивая безопасность.
3. Улучшение производительности: Представления могут использоваться для кэширования результатов запросов, что может улучшить общую производительность системы путем избегания повторного выполнения сложного запроса.
4. Объединение данных из разных таблиц: Используя представления, можно объединить данные из нескольких таблиц или выполнить сложные операции над данными без необходимости изменения фактической структуры базы данных.

Представления являются мощным инструментом в `SQL`, позволяющим эффективно работать с данными и упростить сложности запросов.

## Q10. Что такое `Stored Procedure`?

Хранимая процедура (`Stored Procedure`) это набор предварительно скомпилированных `SQL`-инструкций, которые сохранены на сервере базы данных и могут быть вызваны и выполнены многократно.

Хранимая процедура выполняет определенные задачи в базе данных. Она может принимать параметры, выполнять манипуляции с данными, включать логику связанных операций и возвращать результаты. Хранимые процедуры могут содержать условные операторы, циклы, вызовы других хранимых процедур или функций.Основные преимущества хранимых процедур:

1. Повторное использование логики: Хранимые процедуры могут быть вызваны из различных приложений и запросов, что позволяет избежать дублирования кода и обеспечить единое поведение в разных сценариях.
2. Увеличение производительности: Поскольку хранимые процедуры уже скомпилированы и хранятся на сервере базы данных, они могут выполняться более эффективно, чем динамические `SQL`-запросы.
3. Улучшенная безопасность: Хранимые процедуры могут быть предоставлены различным пользователям или ролям с различными правами доступа, что усиливает контроль над данными и обеспечивает безопасность.
4. Легкая поддержка и обслуживание: Хранимые процедуры могут быть изменены или обновлены независимо от приложений, которые их используют. Это делает сопровождение и обновление системы более гибкими.

Хранимые процедуры поддерживаются в большинстве серверов баз данных, таких как `MySQL`, `Oracle`, `SQL Server` и другие, и являются мощным инструментом для управления данными и логикой в базе данных.

## Q11. Что такое `Trigger`?

Триггер (`Trigger`) это объект базы данных, который автоматически выполняет определенные действия при возникновении определенного события или условия в базе данных. Он может быть привязан к таблице или представлению и реагировать на операции вставки (`INSERT`), обновления (`UPDATE`) или удаления (`DELETE`) данных.

Триггеры позволяют автоматизировать выполнение определенных действий, таких как поддержка целостности данных, аудит операций, валидация данных и других бизнес-правил.

Основные компоненты триггера:

1. Триггерное событие: Определяет, при каком событии должен быть запущен триггер. Например, это может быть выполнение операции `INSERT`, `UPDATE` или `DELETE` на определенной таблице.
2. Триггерное действие: Определяет, какие действия должны быть выполнены при возникновении триггерного события. Например, это может быть выполнение `SQL`-запросов, вызов хранимых процедур или отправка уведомлений.Пример использования триггера:

Предположим, у нас есть таблица "orders" с колонкой "`total_price`". Мы можем создать триггер, который будет автоматически обновлять столбец "`total_price`" при каждом изменении цены товара в таблице "products". Вот пример такого триггера на языке `SQL`:

```sql
CREATE TRIGGER update_total_price
AFTER UPDATE ON products
FOR EACH ROW
BEGIN
    UPDATE orders
    SET total_price = (SELECT SUM(price * quantity) FROM products WHERE order_id = NEW.order_id)
    WHERE order_id = NEW.order_id;
END;
```

В этом примере триггер "`update_total_price`" выполняется после операции `UPDATE` на таблице "products". Каждый раз, когда цена товара изменяется, триггер автоматически обновляет столбец "`total_price`" в таблице "orders" путем вычисления суммы цены умноженной на количество товаров для каждого заказа.

Триггеры предоставляют мощный механизм для автоматизации действий в базе данных и часто используются для поддержки бизнес-правил и обеспечения целостности данных.

## Q12. Что такое `Cursor`?

Курсор (`Cursor`) это объект, который позволяет последовательно перебирать результирующий набор строк из запроса в базе данных. Курсоры обеспечивают доступ к результатам запроса в приложении по одной строке за один раз, что позволяет обработать данные по мере необходимости и управлять навигацией по результатам запроса.Основные операции с курсорами:

1. Открытие курсора: Курсор открывается для определенного запроса и создает буферную область памяти, в которую загружаются строки из результирующего набора.
2. Перемещение по курсору: Команды позволяют перемещаться по результирующему набору вперед (`NEXT`), назад (`PRIOR`), в начало (`FIRST`) или в конец (`LAST`), а также выполнять относительное перемещение (`ABSOLUTE`, `RELATIVE`).
3. Извлечение данных из курсора: Курсор позволяет получить значения определенных столбцов текущей строки результирующего набора.
4. Обновление данных: Курсор может быть использован для обновления данных в базе данных, например, с помощью команды `UPDATE`.
5. Закрытие курсора: Курсор должен быть закрыт после завершения работы с ним, освобождая ресурсы и память.

Пример использования курсора:

```sql
DECLARE @name VARCHAR(50)
DECLARE cursor_name CURSOR FOR SELECT name FROM users

OPEN cursor_name
FETCH NEXT FROM cursor_name INTO @name

WHILE @@FETCH_STATUS = 0
BEGIN
    PRINT @name
    FETCH NEXT FROM cursor_name INTO @name
END

CLOSE cursor_name
DEALLOCATE cursor_name
```

В этом примере мы объявляем курсор "`cursor_name`" для запроса, выбирающего столбец "name" из таблицы "users". Затем мы открываем курсор, выполняем цикл, который последовательно извлекает значения столбца "name" из курсора, выводит их и перемещается к следующей строке, пока не достигнет конца результирующего набора. Затем мы закрываем и освобождаем курсор.

Курсоры предоставляют гибкий способ работы с результатами запроса в базе данных, но следует быть осторожным при использовании их из-за потенциальных проблем с производительностью и использованием памяти.

## Q13. Что такое `Index`?

Для создания индекса вам понадобится использовать оператор `CREATE INDEX`. Вот пример `SQL`-запроса для создания индекса:

```sql
CREATE INDEX index_name ON table_name (column1, column2,...);
```

где:

1. `index_name` имя, которое вы выбираете для индекса.
2. `table_name` имя таблицы, в которой вы хотите создать индекс.
3. column1, column2 и т. д. столбцы, для которых нужно создать индекс.

Пример использования:

```sql
CREATE INDEX idx_customer_name ON customers (customer_name);
```

Этот запрос создаст индекс с именем "`idx_customer_name`" для столбца "`customer_name`" в таблице "customers". Теперь запросы, которые используют условие `WHERE` с помощью столбца "`customer_name`", будут выполняться более эффективно с использованием этого индекса.

Обратите внимание, что создание индекса может занять некоторое время, особенно для больших таблиц. Кроме того, имейте в виду, что создание индекса может повлиять на производительность при вставке, обновлении и удалении данных, так как индекс должен поддерживаться и обновляться с каждым изменением данных. Поэтому следует тщательно оценить необходимость создания индекса и его влияние на производительность перед его созданием.

## Q14. Что такое `SELECT`?

Оператор `SELECT` в `SQL` используется для извлечения данных из таблицы или представления. Общий синтаксис оператора `SELECT` выглядит следующим образом:

```sql
SELECT column1, column2,..., columnN
FROM table_name
WHERE condition
GROUP BY column1, column2,..., columnN
HAVING condition
ORDER BY column1, column2,..., columnN;
```

1. column1, column2,..., `columnN`: список столбцов, которые нужно выбрать. Можно указать "\" для выбора всех столбцов.
2. `table_name`: имя таблицы или представления, из которого нужно извлечь данные.
3. `WHERE` condition: условие, которое нужно выполнить для выбора определенных строк.
4. `GROUP BY` column1, column2,..., `columnN`: используется для группировки строк по указанным столбцам.
5. `HAVING` condition: условие, которое нужно выполнить для отфильтрованных групп после применения операции `GROUP BY`.
6. `ORDER BY` column1, column2,..., `columnN`: указывает порядок сортировки выбранных строк по указанным столбцам.

Оператор `SELECT` может быть использован с различными комбинациями этих элементов. Например, можно пропустить некоторые части, такие как `WHERE` или `ORDER BY`, если они не требуются в запросе.

Также после ключевого слова `SELECT` можно использовать различные функции, агрегатные функции (например, `COUNT`, `SUM`, `AVG`) и операторы (например, `DISTINCT`) для дальнейшей обработки данных.

## Q15. Что такое `ORDER BY`?

Оператор `ORDER BY` используется в языке `SQL` для сортировки результатов запроса по одному или нескольким столбцам.

Оператор `ORDER BY` позволяет указывать порядок сортировки - по возрастанию (`ASC`) или по убыванию (`DESC`) - для каждого столбца, по которому происходит сортировка. По умолчанию, если не указано направление сортировки, используется сортировка по возрастанию.

Пример использования `ORDER BY`:

```sql
SELECT name, age, salary
FROM employees
ORDER BY salary DESC, age ASC;
```

В данном запросе мы выбираем столбцы name, age и salary из таблицы employees и сортируем результаты сначала по столбцу salary по убыванию, а затем по столбцу age по возрастанию.

Оператор `ORDER BY` может использоваться совместно с оператором `SELECT`, чтобы отсортировать строки перед их выводом, или с оператором `GROUP BY`, чтобы отсортировать результаты группировки по заданным условиям.

Основное назначение оператора `ORDER BY` заключается в упорядочивании результатов запроса для лучшего представления данных или для более удобного анализа. Это позволяет получить данные в нужном порядке и сделать выводы на основе отсортированных данных.

## Q16. Что такое `EXISTS`?

Оператор `EXISTS` используется в `SQL` для проверки наличия хотя бы одной записи в результирующем наборе данных, который возвращается подзапросом. Он возвращает значение `TRUE`, если подзапрос возвращает хотя бы одну строку, и `FALSE`, если подзапрос не возвращает ни одной строки.

Оператор `EXISTS` обычно используется в предложениях `WHERE` или `HAVING` для фильтрации данных, основываясь на результате подзапроса. Он полезен, когда необходимо проверить наличие связанных данных в других таблицах перед выполнением операции.

Пример использования оператора `EXISTS`:

```sql
SELECT column1, column2
FROM table1
WHERE EXISTS (SELECT column3 FROM table2 WHERE condition);
```

В этом примере оператор `EXISTS` проверяет наличие хотя бы одной строки в результирующем наборе подзапроса (`SELECT` column3 `FROM` table2 `WHERE` condition). Если подзапрос возвращает хотя бы одну строку, то возвращается `TRUE` и соответствующие строки из table1 будут включены в результирующий набор.

Оператор `EXISTS` очень полезен для условного выполнения операций, основанных на наличии или отсутствии данных в других таблицах. Он помогает оптимизировать запросы, так как может прекратить выполнение подзапроса сразу после нахождения первого совпадения.

## Q17. (!) Что такое `MERGE`?

Оператор `MERGE` используется в `SQL` для объединения операций `INSERT`, `UPDATE` и `DELETE` в одном запросе. Он позволяет обновлять или вставлять данные в таблицу в зависимости от условия.

Пример синтаксиса оператора `MERGE`:

```sql
MERGE INTO target_table
USING source_table ON (condition)
WHEN MATCHED THEN
    UPDATE SET column1 = value1, column2 = value2,...
WHEN NOT MATCHED THEN
    INSERT (column1, column2,...)
    VALUES (value1, value2,...)
WHEN NOT MATCHED BY SOURCE THEN
    DELETE;
```

Оператор `MERGE` выполняет следующие шаги:

1. Определяется целевая таблица (`target_table`) и таблица источник данных (`source_table`).
2. Условие `ON` определяет, на основе какого сравнения будет выполняться слияние данных.
3. Когда совпадение найдено (`WHEN MATCHED`), проводится операция `UPDATE`, которая обновляет столбцы в целевой таблице, основываясь на значениях из источника.
4. Когда совпадения не найдены (`WHEN NOT MATCHED`), происходит операция `INSERT`, которая вставляет новые строки в целевую таблицу на основе данных из источника.
5. Когда источник данных не содержит совпадений (`WHEN NOT MATCHED BY SOURCE`), выполняется операция удаления (`DELETE`), которая удаляет строки из целевой таблицы.

Оператор `MERGE` позволяет эффективно обновлять и вставлять данные в таблицу, особенно если у вас есть большой набор данных и вы хотите минимизировать количество операций.

## Q18. (!) Что такое `EXPLAIN`?

Оператор `EXPLAIN` в `SQL` используется для анализа и понимания плана выполнения запроса. Он позволяет получить информацию о том, как оптимизатор запросов в базе данных будет выполнять запрос, какие индексы и операции будут использованы, и какие статистические данные используются для принятия решений.

При использовании оператора `EXPLAIN` перед вашим запросом, база данных возвращает информацию (план выполнения), которая может включать следующие сведения:

1. Тип доступа к данным: Оператор `EXPLAIN` показывает, как выбираются данные из таблицы, например, полные таблицы, индексные сканирования или объединения.
2. Порядок выполнения операций: Оператор `EXPLAIN` показывает последовательность операций, которые база данных выполняет для получения результата.
3. Использование индексов: Оператор `EXPLAIN` показывает, какие индексы (если есть) используются для ускорения запроса.
4. Оценка стоимости: Оператор `EXPLAIN` предоставляет статистическую оценку стоимости каждой операции, что помогает оценить эффективность выполнения запроса.
5. Объединение и сортировка данных: Оператор `EXPLAIN` показывает, как происходит объединение или сортировка данных при выполнении запроса.

Анализ плана выполнения с помощью оператора `EXPLAIN` может помочь в оптимизации запросов и повысить производительность базы данных. Он дает возможность идентифицировать проблемные части запроса, улучшить структуру таблицы или добавить индексы для ускорения запросов.

## Q19. (!) Что такое `RETURNING`?

`RETURNING` — это ключевое слово, используемое в языке `SQL` для получения значений, возвращаемых после выполнения операции `INSERT`, `UPDATE` или `DELETE`.

Когда в `SQL` выполняется операция `INSERT`, `UPDATE` или `DELETE`, `RETURNING` позволяет получить значения конкретных столбцов, заданных в операторе `RETURNING`. Полученные значения могут быть сохранены в переменных или использованы для дальнейшего анализа или обработки.

Например, при выполнении операции `INSERT` с `RETURNING` можно получить значения сгенерированных автоматически идентификаторов или других столбцов, которые добавлены в таблицу.

Пример использования `RETURNING`:

```sql
INSERT INTO users (name, email)
VALUES ('John Doe', 'john.doe@example.com')
RETURNING id, name;
```

В этом примере после выполнения операции `INSERT` в таблицу "users" будут добавлены новые данные, и с помощью `RETURNING` мы можем получить значения столбцов "id" и "name" для использования или отображения.

Использование `RETURNING` упрощает обработку результатов операций `INSERT`, `UPDATE` или `DELETE` в одном запросе, что может быть полезным при создании аудита операций или при выполнении дополнительных действий на основе возвращаемых значений.

## Q20. В чём разница между `IN`, `BETWEEN`, `LIKE`?

Операторы `IN`, `BETWEEN` и `LIKE` используются в `SQL` для различных типов сравнений и фильтрации данных:

1. Оператор `IN` используется для сравнения значения столбца со списком значений. Он позволяет выбрать строки, у которых значение столбца соответствует хотя бы одному значению из списка. Пример:

```sql
SELECT column1, column2
FROM table
WHERE column1 IN (value1, value2, value3);
```

В этом примере оператор `IN` выбирает строки, у которых значение столбца column1 равно value1, value2 или value3.

2. Оператор `BETWEEN` используется для выбора строк, у которых значение столбца находится в заданном диапазоне. Он позволяет выбрать строки, у которых значение столбца больше или равно нижнему пределу и меньше или равно верхнему пределу. Пример:

```sql
SELECT column1, column2
FROM table
WHERE column1 BETWEEN lower_limit AND upper_limit;
```

В этом примере оператор `BETWEEN` выбирает строки, у которых значение столбца column1 находится в диапазоне между `lower_limit` и `upper_limit`.

3. Оператор `LIKE` используется для сравнения значения столбца с шаблоном, указанным с помощью символов-шаблонов. Он позволяет выбирать строки, у которых значение столбца соответствует заданному шаблону. Пример:

```sql
SELECT column1, column2
FROM table
WHERE column1 LIKE 'pattern';
```

В этом примере оператор `LIKE` выбирает строки, у которых значение столбца column1 соответствует указанному шаблону. Шаблон может содержать специальные символы, такие как % (любое количество символов) или _ (любой одиночный символ).

Операторы `IN`, `BETWEEN` и `LIKE` являются мощными инструментами фильтрации данных и помогают выбрать только те строки, которые соответствуют определенным критериям или условиям.

## Q21. (!) В чем разница между `DELETE` и `TRUNCATE`?

Операторы `DELETE` и `TRUNCATE` используются для удаления данных из таблицы в `SQL`, но у них есть некоторые ключевые различия.

1. `DELETE`:
 1. `DELETE` применяется с `WHERE`-условием или без него для удаления определенных строк из таблицы.
 2. `DELETE` выполняется построчно и каждая удаленная строка записывается в журнал транзакций, что позволяет откатить или восстановить удаленные данные.
 3. `DELETE` применяется к выборке строк, а не к самой таблице.
 4. После операции `DELETE` можно использовать команду `ROLLBACK` для отмены изменений.
 5. `DELETE` не сбрасывает счетчик автоинкремента и не освобождает пространство, занимаемое записями.
2. `TRUNCATE`:
 1. `TRUNCATE` удаляет все строки из таблицы без использования `WHERE`-условия.
 2. `TRUNCATE` выполняется путем удаления данных сразу из файла таблицы, что делает его более быстрым, чем `DELETE`.
 3. `TRUNCATE` не записывает удаленные данные в журнал транзакций, поэтому его нельзя откатить и восстановить.
 4. `TRUNCATE` применяется к таблице в целом, а не к выборке строк.
 5. После операции `TRUNCATE` нельзя использовать команду `ROLLBACK` для отмены изменений.
 6. `TRUNCATE` сбрасывает счетчик автоинкремента и освобождает пространство, занимаемое записями.

В общем, использование `DELETE` или `TRUNCATE` в `SQL` зависит от ваших потребностей. Если вам нужно удалить выбранные строки или нужна возможность отмены удаления, используйте `DELETE`. Если же вам необходимо быстро удалить все строки без возможности восстановления, `TRUNCATE` может быть предпочтительным выбором.

## Q22. Что такое `UNION`?

Ключевое слово `UNION` в `SQL` используется для объединения результатов двух или более `SELECT` запросов в один результирующий набор. Оно позволяет объединять строки из разных таблиц или запросов с одинаковой структурой.

Основное назначение ключевого слова `UNION` состоит в том, чтобы объединить результирующие наборы запросов, которые имеют одинаковое количество столбцов и совместимые (по типу данных) столбцы.

Пример использования ключевого слова `UNION`:

```sql
SELECT column1, column2
FROM table1
UNION
SELECT column1, column2
FROM table2;
```

В этом примере мы объединяем результирующий набор двух запросов (`SELECT` column1, column2 `FROM` table1 и `SELECT` column1, column2 `FROM` table2) с помощью `UNION`. Результирующий набор будет содержать уникальные (без дубликатов) строки, которые соответствуют структуре и типам данных столбцов.

Ключевое слово `UNION ALL` также используется для объединения результирующих наборов, но в отличие от `UNION` оно не удаляет дубликаты строк. Если вам необходимо сохранить все строки из объединяемых запросов, включая повторяющиеся, вы можете использовать `UNION ALL`.

В целом ключевое слово `UNION` очень полезно и позволяет эффективно объединять данные из разных источников или запросов в один результирующий набор, что упрощает анализ и обработку данных.

## Q23. Что такое `JOIN`?

`JOIN` в `SQL` — это операция объединения данных из двух или более таблиц на основе общего столбца между ними. Она позволяет комбинировать данные из разных таблиц для создания новой таблицы, которая будет содержать столбцы и строки из обоих исходных таблиц. `JOIN` используется для связывания данных из разных таблиц на основе их отношений.

Общий синтаксис оператора `JOIN`:

```sql
SELECT column1, column2,..., columnN
FROM table1
JOIN table2 ON table1.column = table2.column;
```

1. column1, column2,..., `columnN`: список столбцов, которые нужно выбрать.
2. table1 и table2: имена таблиц, которые нужно объединить.
3. `ON table1.column` = `table2.column`: условие объединения, где указывается общий столбец или выражение, на основе которого должно произойти объединение данных.

`JOIN` может быть использован с различными типами `JOIN`:

1. `INNER JOIN`: возвращает только совпадающие строки из обеих таблиц.
2. `LEFT JOIN`: возвращает все строки из левой таблицы и совпадающие строки из правой таблицы. Если совпадающих строк нет, то возвращается `NULL` для столбцов из правой таблицы.
3. `RIGHT JOIN`: возвращает все строки из правой таблицы и совпадающие строки из левой таблицы. Если совпадающих строк нет, то возвращается `NULL` для столбцов из левой таблицы.
4. `FULL JOIN`: возвращает все строки из обеих таблиц. Если совпадающих строк нет, то возвращаются `NULL` для соответствующих столбцов.

`JOIN` — очень мощный инструмент, который позволяет объединять данные из разных таблиц и извлекать информацию на основе их отношений.

## Q24. Какие существуют типы `JOIN`?

В `SQL` существуют несколько типов операций `JOIN`, которые позволяют объединять данные из разных таблиц. Основные типы `JOIN` включают:

1. `INNER JOIN`: Возвращает только совпадающие строки из обеих таблиц, основываясь на условии объединения. Возвращаются только те строки, для которых есть соответствующая запись в каждой таблице.
2. `LEFT JOIN` (или `LEFT OUTER JOIN`): Возвращает все строки из левой (первой) таблицы и совпадающие строки из правой (второй) таблицы. Если в правой таблице нет совпадающих строк, то возвращается `NULL` для столбцов из правой таблицы.
3. `RIGHT JOIN` (или `RIGHT OUTER JOIN`): Возвращает все строки из правой (второй) таблицы и совпадающие строки из левой (первой) таблицы. Если в левой таблице нет совпадающих строк, то возвращается `NULL` для столбцов из левой таблицы.
4. `FULL JOIN` (или `FULL OUTER JOIN`): Возвращает все строки из обеих таблиц. Если совпадающих строк нет, то возвращаются `NULL` для соответствующих столбцов.
5. `CROSS JOIN`: Производит декартово произведение двух таблиц, т.е. комбинирует каждую строку из первой таблицы с каждой строкой из второй таблицы. Результатом будет таблица с числом строк, равным произведению количества строк в каждой из таблиц.

Каждый тип `JOIN` имеет свое применение в зависимости от требуемых результатов запроса и структуры данных. Выбор правильного типа `JOIN` важен для получения нужной информации из объединенных таблиц.

## Q25. (!) Что лучше использовать `JOIN` или подзапросы?

Вопрос о том, что лучше использовать `JOIN` или подзапросы, зависит от конкретной задачи и структуры данных.

1. `JOIN` предоставляет более явный и декларативный способ объединения данных из нескольких таблиц. Он позволяет объединять данные на основе общего столбца и возвращать результат в виде новой таблицы. `JOIN` более эффективен в случаях, когда требуется выполнить сложное объединение с использованием различных типов `JOIN`, фильтрации и группировки данных.
2. Подзапросы позволяют использовать результат одного запроса (подзапроса) в качестве входных данных для другого запроса. Они могут быть полезны в ситуациях, когда требуется выполнить операции с данными из одной таблицы, основываясь на результатах другого запроса. Подзапросы могут быть удобны, когда требуется выполнить несколько последовательных операций или когда нет возможности использовать `JOIN` (например, когда требуется выполнить операцию сравнения с несколькими столбцами).

Оба подхода имеют свои преимущества и недостатки, и выбор между ними зависит от конкретных требований и контекста задачи. Рекомендуется выбирать тот вариант, который обеспечивает более простое и понятное написание запроса, а также оптимальную производительность в конкретном случае.

## Q26. В чем разница между `COUNT(*)` и `COUNT(column)`?

Разница в том, **что именно считается**.

- `COUNT(*)` считает **все строки** в наборе результата (или в группе), включая строки, где конкретный столбец имеет значение `NULL`.
- `COUNT(column)` считает только **ненулевые значения** указанного столбца, строки с `NULL` в этом столбце **не попадают** в подсчёт.

Пример:

```sql
SELECT
  COUNT(*)     AS total_rows,
  COUNT(price) AS non_null_prices
FROM orders;
```

Если часть строк имеет `price = NULL`, то `total_rows` будет больше, чем `non_null_prices`.
Отдельно существует `COUNT(DISTINCT column)`, который считает количество **уникальных ненулевых** значений в столбце.

## Q27. Для каких числовых типов недопустимо использовать операции сложения/вычитания?

Операции сложения и вычитания недопустимы для данных типов, не являющихся числами или несовместимыми с числовыми вычислениями. Вот несколько таких типов:

1. Строки (тип данных `VARCHAR`, `TEXT` и т.д.): Сложение и вычитание не определены для строк. Вместо этого операции сложения (+) и вычитания (-) могут использоваться для конкатенации строк (объединения) и удаления подстрок.
2. Даты и времени (типы данных `DATE`, `TIME`, `DATETIME` и т.д.): Сложение и вычитание не имеют смысла для дат и времени. Однако можно выполнять операции сравнения и вычисления разницы между датами и временем.
3. Логические значения (тип данных `BOOLEAN`): Логические значения (`true / false`) не могут быть складываемыми или вычитаемыми, так как это не имеет смысла с точки зрения логики.
4. `NULL` значения: `NULL` представляет отсутствие значения и не имеет определенного числового значения. Поэтому операции сложения и вычитания с `NULL` значениями будут возвращать `NULL`.
5. Бинарные данные: Бинарные данные (типы данных `BLOB`, `VARBINARY` и т.д.) не могут быть математически складываемыми или вычитаемыми. Однако можно выполнять операции сравнения или конкатенации бинарных данных.
6. Списки, массивы, словари: Операции сложения и вычитания обычно не определены для таких структур данных. Вместо этого они могут иметь свои специфические операторы для работы с элементами внутри них.

Важно применять правильные операции для соответствующих типов данных, чтобы избежать ошибок и нежелательных результатов. В `SQL`, например, можно использовать различные функции и операторы для выполнения разных операций со строками, датами, числами и другими типами данных.

## Q28. Что такое `GROUP BY`?

Оператор `GROUP BY` используется в языке `SQL` для группировки набора данных по одному или нескольким столбцам.

Оператор `GROUP BY` создает группы из одинаковых значений в указанных столбцах и позволяет применять агрегатные функции к этим группам. Например, с помощью оператора `GROUP BY` можно вычислить сумму, среднее значение, минимальное или максимальное значение и т.д. для каждой группы.

Пример использования `GROUP BY`:

```sql
SELECT department, COUNT(*) as num_employees
FROM employees
GROUP BY department;
```

В данном запросе мы создаем группы по столбцу department в таблице employees и вычисляем количество сотрудников в каждом отделе с помощью функции `COUNT(*)`. Результаты будут группированы по отделам.

Оператор `GROUP BY` часто используется совместно с операторами `SELECT` и агрегатными функциями, такими как `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` и т.д. Он позволяет анализировать данные по группам, вычислять агрегатные значения для каждой группы и получать сводные результаты.

Основное назначение оператора `GROUP BY` заключается в группировке и агрегации данных для получения сводной информации или проведения анализа по определенным категориям или группам значений. Это позволяет сгруппировать данные, выделить общие характеристики и сделать выводы на основе группированных результатов.

## Q29. Как `GROUP BY` обрабатывает значения `NULL`?

Оператор `GROUP BY` в `SQL` обрабатывает значения `NULL` особым образом. При выполнении группировки все строки с `NULL`-значениями в столбцах, указанных в операторе `GROUP BY`, объединяются в одну группу. Это означает, что все `NULL`-значения считаются одним значением при группировке.

Например, рассмотрим следующий запрос:

```sql
SELECT department, COUNT(*)
FROM employees
GROUP BY department;
```

Если в столбце department есть значения `NULL`, то все строки с `NULL`-значениями будут объединены в одну группу. Результат запроса будет включать группу с `NULL`-значениями в столбце department и число строк в этой группе.

Оператор `GROUP BY` также позволяет использовать функции агрегации, такие как `SUM`, `AVG`, `MIN`, `MAX` и др., для обработки `NULL`-значений. Например, если вы хотите вычислить сумму зарплаты (salary) для каждого отдела (department) и у вас есть `NULL`-значения в столбце зарплаты, функция `SUM` будет игнорировать `NULL`-значения и вычислять сумму только для ненулевых значений.

Важно учитывать, что значения `NULL` не рассматриваются как равные или эквивалентные значения в операторе `GROUP BY`. Они объединяются в одну группу, но не рассматриваются как одинаковые значения при сравнении или сортировке.

## Q30. В чем разница между `GROUP BY` и `DISTINCT`?

Операторы `GROUP BY` и `DISTINCT` в `SQL` используются для удаления дубликатов из набора данных, но есть некоторые различия в их функциональности:

1. `DISTINCT`: Оператор `DISTINCT` используется для выбора уникальных значений из одного столбца или нескольких столбцов. Он удаляет повторяющиеся строки из результирующего набора данных. Пример использования:

```sql
SELECT DISTINCT department
FROM employees;
```

В данном запросе будут выбраны уникальные значения из столбца department в таблице employees.

Оператор `DISTINCT` работает на уровне всей строки, поэтому если есть строки, в которых все столбцы имеют одинаковые значения, то только одна из таких строк будет включена в результат.

2. `GROUP BY`: Оператор `GROUP BY` используется для группировки данных по одному или нескольким столбцам и применения агрегатных функций к каждой группе. Он позволяет вычислять суммы, средние значения, минимальные или максимальные значения и т.д. для каждой группы. Пример использования:

```sql
SELECT department, COUNT(*) as num_employees
FROM employees
GROUP BY department;
```

В данном запросе мы группируем данные по столбцу department и вычисляем количество сотрудников (с использованием функции `COUNT`) в каждом отделе.

Оператор `GROUP BY` работает на уровне групп, поэтому он объединяет строки с одинаковыми значениями в указанных столбцах в одну группу. Результат будет включать отдельную строку для каждой группы с агрегатными значениями.

Таким образом, основное отличие между операторами `GROUP BY` и `DISTINCT` заключается в том, что `GROUP BY` позволяет группировать данные по одному или нескольким столбцам и выполнять агрегатные функции для каждой группы, в то время как `DISTINCT` используется для выбора уникальных значений из одного или нескольких столбцов без группировки и агрегации.

## Q31. Что такое `HAVING`?

Оператор `HAVING` используется в языке `SQL` после оператора `GROUP BY` для фильтрации группированных данных на основе агрегатных функций. Он позволяет применять условия к результатам агрегатных функций и возвращать только те группы, которые соответствуют заданному условию.

В отличие от оператора `WHERE`, который применяется к каждой отдельной строке перед группировкой, оператор `HAVING` применяется после группировки и работает с агрегатными функциями, такими как `COUNT`, `SUM`, `AVG` и т.д. Он позволяет фильтровать результаты группировки на основе вычисленных значений этих функций.

Пример использования оператора `HAVING`:

```sql
SELECT department, AVG(salary) as average_salary
FROM employees
GROUP BY department
HAVING AVG(salary) > 5000;
```

В данном запросе мы вычисляем среднюю зарплату для каждого отдела и затем фильтруем результаты, оставляя только те отделы, у которых средняя зарплата превышает `5000`. Оператор `HAVING` позволяет нам применить условие к результатам агрегатной функции `AVG(salary)`.

Таким образом, оператор `HAVING` позволяет фильтровать группированные данные на основе агрегатных функций и использовать условия для выбора нужных результатов.

## Q32. В чем различие между `HAVING` и `WHERE`?

Операторы `HAVING` и `WHERE` являются частями языка `SQL` и используются для фильтрации данных, однако они применяются в разных этапах обработки данных.

1. `WHERE`: Оператор `WHERE` применяется в операторе `SELECT`, чтобы установить условие для отбора строк до их группировки и агрегации. Он фильтрует строки на основе условий, примененных к отдельным значениям столбцов, до выполнения группировки или применения агрегатных функций. `WHERE` используется для определения критериев отбора строк и работает с данными на уровне записей.

Пример использования `WHERE`:

```sql
SELECT * FROM employees WHERE salary > 5000;
```

В данном запросе мы выбираем все строки из таблицы employees, где значение столбца salary больше `5000`.

2. `HAVING`: Оператор `HAVING` используется после оператора `GROUP BY` в операторе `SELECT` для фильтрации группированных данных на основе агрегатных функций. Он фильтрует группы, сгруппированные с помощью оператора `GROUP BY`, на основе заданных условий, применяемых к агрегатным функциям. `HAVING` используется для определения условий, которые должны быть истинными для групп, а не отдельных записей.

Пример использования `HAVING`:

```sql
SELECT department, AVG(salary) as average_salary
FROM employees
GROUP BY department
HAVING AVG(salary) > 5000;
```

В данном запросе мы вычисляем среднюю зарплату для каждого отдела и фильтруем результаты, оставляя только те отделы, у которых средняя зарплата превышает `5000`.

Таким образом, основное различие между операторами `HAVING` и `WHERE` заключается в том, что `WHERE` применяется к отдельным записям перед группировкой, а `HAVING` применяется к группам после группировки. `WHERE` работает с данными на уровне записей, а `HAVING` работает с агрегатными функциями на уровне групп.

## Q33. Какие есть основные агрегатные функции?

**Краткий ответ:** основные агрегатные функции в `SQL`: **COUNT**, **SUM**, **AVG**, **MIN**, **MAX**; **GROUP_CONCAT** (в `MySQL`), **STRING_AGG** (в `PostgreSQL`).

### Введение

Агрегатные функции в `SQL` используются для выполнения вычислений над набором строк и возврата одного результата. Они часто используются вместе с `GROUP BY` для группировки данных.

### Основные агрегатные функции

1. `COUNT()` — подсчет количества строк
2. `SUM()` — сумма значений
3. `AVG()` — среднее значение
4. `MIN()` — минимальное значение
5. `MAX()` — максимальное значение
