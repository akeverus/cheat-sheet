## Q1. (!) Что такое `Elasticsearch`?

`Elasticsearch` — это распределённая система поиска и аналитики с открытым исходным кодом, основанная на `Apache Lucene`. Она используется для хранения, поиска и анализа данных в режиме реального времени. `Elasticsearch` широко применяется для следующих задач:

1. Полнотекстовый поиск: `Elasticsearch` предоставляет мощные возможности полнотекстового поиска, позволяя выполнять поиск по большим объемам структурированных, неструктурированных и полуструктурированных данных. Он обладает мощными функциями, такими как поиск по словам, фразам, префиксам, синонимам, а также полнотекстовый поиск в разных языках с поддержкой стемминга.
2. Анализ и агрегация данных: `Elasticsearch` предоставляет возможность визуализации и агрегации данных реального времени, что полезно при анализе больших объёмов данных. Он позволяет выполнять сложные агрегационные запросы, группировку данных, расчет статистики и генерацию отчетов.
3. Масштабируемость и отказоустойчивость: `Elasticsearch` обеспечивает горизонтальное масштабирование для обработки больших объёмов данных и поддерживает репликацию данных для обеспечения высокой доступности. Вы можете создавать кластеры `Elasticsearch` с несколькими узлами, чтобы распределить данные и запросы между ними.
4. Лог-анализ: `Elasticsearch` широко используется для индексации и анализа журналов или лог-файлов. Он позволяет хранить, искать и анализировать огромные объёмы лог-данных, что помогает в оперативном обнаружении проблем, мониторинге и отладке приложений.
5. Полнотекстовый поиск и анализ структурированных данных: `Elasticsearch` позволяет индексировать и анализировать структурированные данные, такие как `JSON`, и выполнять поиск по ним с использованием различных фильтров, сортировок и запросов. `Elasticsearch` имеет обширное экосистемное окружение и широкий спектр инструментов для визуализации данных, построения дашбордов, мониторинга и управления кластерами. Он известен своей простой интеграцией с другими компонентами стека `ELK` (`Elasticsearch`, `Logstash`, `Kibana`), который обеспечивает полный цикл сбора, обработки, визуализации и анализа данных.

## Q2. (!) Какие основные компоненты `Elasticsearch`?

`Elasticsearch` состоит из следующих основных компонентов:

1. Узел (`Node`): Узел представляет собой инсталляцию `Elasticsearch` на одной машине. Каждый узел является автономным, самоуправляемым и может выполнять операции поиска и индексации данных.
2. Кластер (`Cluster`): Кластер представляет собой группу связанных узлов. Каждый кластер имеет уникальное имя и использует механизм обмена сообщениями для обеспечения согласованности и сетевой связи между узлами.
3. Индекс (`Index`): Индекс представляет собой коллекцию документов, сгруппированных логически похожими характеристиками. Каждый документ в индексе имеет уникальный идентификатор и структурирован в виде `JSON`-объекта.
4. Тип (`Type`): Тип представляет собой категорию документов внутри индекса. Каждый тип определяет набор полей и типов данных, которые могут быть содержаны в документах.
5. Документ (`Document`): Документ представляет собой базовую единицу информации в `Elasticsearch`. Он представляет собой `JSON`-объект, который хранится и индексируется внутри индекса.
6. Маппинг (`Mapping`): Маппинг представляет собой описание схемы индекса, определяющее структуру документов и типы данных полей. Он определяет, какие поля индексируются, как хранятся и как производится поиск по ним.
7. Шард (`Shard`): Шард представляет собой фрагмент индекса, в котором хранятся данные. Индекс может быть разделен на несколько шардов для обеспечения масштабируемости и параллельной обработки запросов.
8. Реплика (`Replica`): Реплика представляет собой точную копию шарда, хранящуюся на других узлах. Реплики служат для обеспечения отказоустойчивости и повышения производительности при параллельном исполнении запросов.

Эти компоненты взаимодействуют между собой, чтобы обеспечить хранение, поиск и анализ данных в `Elasticsearch`.

## Q3. Какие типы данных поддерживает `Elasticsearch`?

`Elasticsearch` поддерживает несколько типов данных для индексирования и хранения информации в документах. Некоторые из основных типов данных в `Elasticsearch` включают:

1. `Text` (Текст): Этот тип данных используется для индексации и хранения текстовых значений. Он поддерживает поиск по подстрокам, а также различные анализаторы для обработки и нормализации текста.
2. `Keyword` (Ключевое слово): Этот тип данных используется для индексации и хранения непроанализированных значений, таких как идентификаторы или метки. Он может использоваться для точного сопоставления или фильтрации данных.
3. `Numeric` (Числовой): `Elasticsearch` поддерживает различные типы числовых данных, такие как целочисленные (integer), числа с плавающей точкой (float), двоичные числа (byte) и другие. Они позволяют выполнять числовые операции, такие как сортировка, агрегации и диапазонные запросы.
4. `Date` (Дата): Данный тип данных используется для индексации и хранения дат и времени. Он поддерживает различные форматы даты и время, а также операции с датами, включая диапазонные запросы и агрегации.
5. `Boolean` (Булево): Этот тип данных используется для индексации и хранения логических значений, таких как `true / false` или да/нет. Он позволяет выполнять фильтрацию и поиск на основе булевых условий.

Это лишь некоторые основные типы данных, поддерживаемые `Elasticsearch`. Он также поддерживает географические данные, бинарные данные, массивы и другие типы данных для обработки и анализа различных видов информации.

## Q4. Какой язык запросов используется в `Elasticsearch`?

В `Elasticsearch` для выполнения поисковых запросов используется свой собственный язык запросов, который называется `Query DSL` (`Domain Specific Language`). `Query DSL` представляет собой `JSON`-подобную структуру, в которой определяются различные параметры и условия для поиска и фильтрации данных. `Query DSL` в `Elasticsearch` предоставляет богатый набор операций и функций для формирования сложных запросов. Он позволяет задать условия поиска, определить сортировку результатов, управлять ограничениями по количеству возвращаемых документов и многое другое.

Пример простого запроса `Query DSL` в `Elasticsearch`:

```json
{
    "query": {
        "match": {
            "title": "эластиксерч"
        }
    }
}
```

В этом примере мы ищем документы, в которых поле `title` содержит слово "эластиксерч". Запрос передаётся в `Elasticsearch` в виде `JSON`-объекта, который содержит ключевое слово `query` с заданными условиями поиска. `Query DSL` предоставляет множество других возможностей, таких как фильтрация результатов по определённым критериям, агрегация данных, поиск по фразам и т.д. Он является мощным инструментом для формирования точных и гибких запросов в `Elasticsearch`.

## Q5. (!) Какие преимущества есть у `Elasticsearch`?

`Elasticsearch` предоставляет несколько преимуществ по сравнению с другими поисковыми решениями:

1. Масштабируемость: `Elasticsearch` является распределённой системой, которая позволяет масштабировать горизонтально, добавляя новые узлы в кластер без прерывания работы системы. Это обеспечивает возможность обработки больших объёмов данных и увеличение производительности.
2. Высокая скорость поиска: `Elasticsearch` использует инвертированный индекс для быстрого поиска и фильтрации данных. Он также предоставляет кэширование запросов и операций, что позволяет достичь высоких скоростей поиска и отклика.
3. Полнотекстовый поиск: `Elasticsearch` обладает мощными функциями полнотекстового поиска, такими как автоматическая лемматизация, поиск по синонимам, фонетический поиск и многое другое. Это дает возможность точного и гибкого поиска по текстовым данным.
4. Расширенные возможности анализа: `Elasticsearch` предоставляет широкий спектр функций для анализа данных, включая агрегации, группировку, фасетное и временное анализы. Это помогает использовать данные более эффективно и извлекать важную информацию.
5. Удобство использования: `Elasticsearch` имеет простой и интуитивно понятный `API`, который позволяет легко интегрировать его с другими приложениями и инструментами. Он также поддерживает различные языки запросов, такие как `JSON`, что делает его простым в использовании и настройке.
6. Открытый и экосистема: `Elasticsearch` является открытым и бесплатным ПО с открытым исходным кодом. Он имеет активное сообщество разработчиков и широкий набор инструментов, таких как `Kibana`, `Logstash` и `Beats`, которые могут быть использованы вместе с `Elasticsearch` для обработки и визуализации данных.

В целом, `Elasticsearch` предлагает мощные функции, высокую скорость и масштабируемость, что делает его привлекательным решением для поиска и анализа данных в различных сценариях, от веб-поиска и мониторинга логов до аналитики данных и бизнес-интеллекта.

## Q6. (!) Какие ограничения есть у `Elasticsearch`?

В `Elasticsearch` есть несколько ограничений, которые стоит учитывать:

1. Ограничение по объему данных: `Elasticsearch` имеет ограничение по максимальному объему данных, который может быть хранен и обработан на одном узле или кластере. Это ограничение определяется доступными ресурсами (памятью, диском и процессором) на узлах в вашей системе.
2. Ограничение по количеству индексов и типов: `Elasticsearch` имеет ограничение на количество индексов и типов, которые можно создать в одном кластере. Это ограничение определяется максимальным количеством открытых файлов в системе и может быть изменено в настройках операционной системы.
3. Ограничение размера документа: `Elasticsearch` ограничивает максимальный размер документа в индексе. По умолчанию это ограничение составляет `100` МБ. Однако, ограничение может быть изменено путем настройки параметра http.`max_content_length` в файле конфигурации `Elasticsearch`.
4. Ограничение по количеству результатов поиска: По умолчанию `Elasticsearch` ограничивает количество возвращаемых результатов поиска до 10 вариантов. Это ограничение может быть изменено с использованием параметров size и from в запросе поиска.
5. Ограничение скорости запросов: `Elasticsearch` имеет ограничение скорости запросов по умолчанию, чтобы предотвратить перегрузку системы. Это ограничение может быть настроено с помощью параметра `indices.requests.limit`.
6. Ограничение по производительности: В зависимости от конфигурации и настроек, `Elasticsearch` может столкнуться с ограничениями производительности при обработке больших объёмов данных. В таких случаях, может потребоваться производственное масштабирование, а также оптимизация индекса и запросов.

Важно учитывать эти ограничения при проектировании и развертывании системы `Elasticsearch`, а также при разработке и настройке запросов и индексов. Это поможет избежать проблем и обеспечить эффективное использование `Elasticsearch` в вашем приложении или проекте.

## Q7. В чём разница между `Elasticsearch` и `Lucene`?

**Lucene** — библиотека полнотекстового поиска и индексации на `Java`; один инстанс, без распределённости. **Elasticsearch** — распределённая система поверх `Lucene`: шардирование, репликация, `REST API`, агрегации, мониторинг.

`Lucene` даёт инвертированный индекс, анализаторы, запросы (`TermQuery`, `BooleanQuery`). `Elasticsearch` добавляет координацию, кластеризацию и высокоуровневые функции (mapping, анализ, `DSL` запросов, `Kibana`). Каждый шард `Elasticsearch` — инстанс индекса `Lucene`. `Elasticsearch` добавляет координацию, кластеризацию и высокоуровневые функции (mapping, анализ, запросы).

`Lucene` даёт инвертированный индекс, анализаторы, запросы (`TermQuery`, `BooleanQuery` и т.д.). `Elasticsearch` поверх этого: распределение по шардам, репликация, `REST API`, `DSL` запросов (match, bool, agg), `Kibana`, мониторинг. При разработке кастомного поиска можно использовать `Lucene` напрямую; для распределённого поиска и аналитики обычно выбирают `Elasticsearch` (или `OpenSearch`).

**Практика:** для встраиваемого поиска в одном `JVM` (например, десктоп-приложение) — `Lucene` напрямую. Для облачного или распределённого поиска, логов, метрик — `Elasticsearch / OpenSearch`: `REST API`, горизонтальное масштабирование, `Kibana / Lucene` на `Elasticsearch`: переиндексация данных в `ES`; запросы переписать с `Lucene Query` на `Elasticsearch Query DSL` (match, term, bool).

## Q8. (!) Какие операции доступны для работы с данными?

В `Elasticsearch` доступны различные операции для работы с данными, включая:

1. `Indexing` (Индексация): Операция индексации используется для добавления новых документов в индекс `Elasticsearch`. Индексация включает создание нового документа или обновление существующего по его уникальному идентификатору.
2. `Searching` (Поиск): `Elasticsearch` позволяет выполнять поисковые запросы для поиска документов по определённым критериям. Запросы могут быть простыми — с использованием ключевых слов или строк, или более сложными — с использованием `Query DSL` для формирования точных и гибких запросов.
3. `Updating` (Обновление): Обновление документов в `Elasticsearch` осуществляется путем выполнения операции индексации с указанием существующего идентификатора документа. При обновлении `Elasticsearch` обновляет только измененные поля документа, не затрагивая остальные данные.
4. `Deleting` (Удаление): Удаление документов из индекса может быть выполнено путем указания их уникального идентификатора в операции удаления. `Elasticsearch` также поддерживает удаление документов по запросу, позволяя удалить все документы, удовлетворяющие определённым критериям.
5. `Bulk Operations` (Групповые операции): `Elasticsearch` предоставляет возможность выполнения групповых операций, таких как индексация, обновление и удаление, для нескольких документов одним запросом. Это позволяет оптимизировать производительность и экономить ресурсы на общение с `Elasticsearch`.

Это лишь несколько примеров операций, доступных в `Elasticsearch`. Есть и другие операции, такие как агрегации, сортировка, фильтрация и т.д., которые позволяют использовать `Elasticsearch` в качестве мощного инструмента для работы с данными.

## Q9. (!) Что такое `Index`?

В `Elasticsearch` индекс является основной единицей организации и хранения данных. Индекс содержит набор документов, которые могут быть проиндексированы, поиск которых может быть выполнен и анализ которых может быть проведен.

Основное отличие индекса в `Elasticsearch` от таблицы в реляционных базах данных заключается в способе хранения и поиска данных. В реляционной базе данных данные хранятся в структурированном формате, в таблицах, где каждая таблица имеет определённую схему с набором столбцов и типов данных. Каждая строка таблицы представляет отдельную запись.

В `Elasticsearch` индексы хранят данные в документах, которые, в свою очередь, представляют собой `JSON`-подобные объекты. Каждый документ может иметь различные поля и структуру данных, и не требуется задавать строго определённую схему заранее. Индексы могут содержать несколько типов документов.

В реляционных базах данных таблицы часто используются для связи и организации данных, обеспечивая консистентность и предотвращая дублирование данных. В `Elasticsearch` индексы используются для эффективного поиска и анализа данных. Они предоставляют возможность выполнения сложных операций поиска, фильтрации, агрегации и других операций над документами, что делает их мощным инструментом для обработки и анализа данных.

## Q10. (!) Какие типы `Index` существуют?

В `Elasticsearch` доступны два основных типа индексирования:

1. `Inverted Index` (Инвертированный индекс): Это наиболее распространённый тип индексации в `Elasticsearch`. В инвертированном индексе каждое уникальное слово в текстовом поле ассоциируется с набором документов, где это слово встречается. Этот тип индексирования позволяет эффективно искать и анализировать текстовые данные, поддерживая операции поиска, фильтрации и агрегации.
2. `Columnar Index` (Столбцовый индекс): Этот тип индексирования применяется для числовых и датовых полей. Данные в столбцовом индексе организованы по столбцам, что позволяет эффективно выполнять операции сортировки и агрегации. Столбцовый индекс особенно полезен для обработки больших объёмов числовых данных.

При выборе типа индексирования следует учитывать характеристики данных и ожидаемые операции над ними. Если большая часть данных представляет собой текстовые значения и требуется мощный поиск и анализ, инвертированный индекс является наиболее подходящим выбором. Если данные в основном числовые или датовые и важны операции сортировки или агрегации, столбцовый индекс может быть более эффективным.

Однако в большинстве случаев `Elasticsearch` автоматически выбирает наиболее подходящий тип индексирования, основываясь на анализе данных и запросах, поступающих в индекс. Это позволяет достичь хорошей производительности без необходимости вручную указывать тип индексирования.

## Q11. (!) Как работает механизм `Index`?

Механизм индексов в `Elasticsearch` является ключевой особенностью, которая повышает производительность и эффективность поиска данных.

В `Elasticsearch` данные хранятся и организуются в индексах. Индекс представляет собой коллекцию документов с одинаковой структурой, которые могут быть индексированы, храниться и поиск по ним выполняется очень быстро. Каждый индекс состоит из одного или нескольких фрагментов, называемых "`Shard`", которые распределяются по узлам кластера.

Механизм индексов в `Elasticsearch` повышает производительность по нескольким причинам:

1. Распределение нагрузки: `Shard` индексов могут быть разделены и распределены по всем узлам кластера, которые могут работать параллельно. Таким образом, запросы разделяются между узлами, что позволяет балансировать нагрузку и повышает общую производительность.
2. Параллельный поиск: При поиске данных `Elasticsearch` может параллельно выполнять запросы к разным `Shard`, что ускоряет обработку запросов и улучшает производительность.
3. Репликация: `Elasticsearch` позволяет создавать реплики `Shard`, которые содержат точные копии данных. Репликация улучшает отказоустойчивость кластера и позволяет распределить чтение запросов между репликами, что увеличивает производительность чтения.
4. Обратный индекс: `Elasticsearch` использует обратный индекс, который значительно ускоряет процесс поиска. Обратный индекс содержит индексы терминов, каждый из которых указывает на документы, содержащие эти термины. Благодаря обратному индексу поиск становится очень быстрым и эффективным.
5. Кеширование: `Elasticsearch` имеет механизм кеширования, который позволяет сохранять результаты выполненных запросов и эффективно использовать их при повторных запросах. Кеширование уменьшает нагрузку на систему и сокращает время выполнения запросов.

В целом, механизм индексов в `Elasticsearch` является мощным инструментом для ускорения поиска и обработки данных. Он позволяет эффективно организовать и хранить информацию, равномерно распределить нагрузку и обеспечить быстрый доступ к данным.

## Q12. (!) Что такое `Real-Time Indexing`?

Индексирование в реальном времени (`Real-Time Indexing`) в `Elasticsearch` означает возможность мгновенного добавления и обновления данных в индексе `Elasticsearch` без задержек. Этот подход позволяет мгновенно отображать изменения данных в поисковых результатах или аналитических отчетах.

Для использования индексирования в реальном времени в `Elasticsearch` необходимо выполнить следующие шаги:

1. Настройка индекса: Создайте индекс и определите его структуру и настройки с помощью маппинга. Маппинг определяет, как данные будут храниться, индексироваться и анализироваться в `Elasticsearch`.
2. Индексация данных: используйте REST API (`PUT /index/_doc/id` или `POST /index/_doc`) для добавления новых документов в индекс или для обновления существующих. Вы можете указать уникальный идентификатор для каждого документа.
3. Поиск данных: используйте API (`GET /index/_search`) для выполнения поисковых запросов и получения результатов.
4. Обновление данных: при изменении данных используйте API (`POST /index/_update/id`) для обновления существующих документов в индексе.
5. Удаление данных: для удаления документов из индекса используйте API (`DELETE /index/_doc/id`).

Таким образом, с использованием индексирования в реальном времени в `Elasticsearch` вы можете добавлять, обновлять и удалять данные на лету, а поисковые результаты будут отражать эти изменения немедленно. Это особенно полезно в приложениях, где требуется оперативный доступ к актуальным данным, таким как мониторинг, логирование, аналитика и другие.

## Q13. (!) Что такое `Document`?

В `Elasticsearch` документ представляет собой базовую единицу информации, которая хранится и индексируется внутри индекса. Каждый документ в `Elasticsearch` представлен в виде `JSON`-объекта.

Основное отличие документа в `Elasticsearch` от записи в реляционных базах данных заключается в том, что документы не требуют определённой структуры и схемы. Это означает, что каждый документ может содержать различные поля и структуры данных. Каждый документ может иметь свой уникальный идентификатор, который позволяет легко обращаться к нему.

В реляционной базе данных записи организованы в таблицы с определёнными столбцами и типами данных. Каждая запись в таблице имеет свой уникальный идентификатор (обычно первичный ключ), а поля и их типы должны соответствовать предопределённой схеме базы данных.

Документы в `Elasticsearch` могут быть более гибкими и масштабируемыми, так как каждый документ может иметь свой набор полей и структуру данных. Это позволяет хранить и анализировать различные типы данных в одном индексе. В реляционных базах данных же требуется определение схемы заранее, что делает их менее гибкими для работы с разнообразными типами данных.

## Q14. (!) Что такое `Mapping`?

`Mapping` в `Elasticsearch` — это процесс определения схемы индекса, который определяет, как данные будут храниться и интерпретироваться внутри индекса. Он определяет типы полей, анализаторы, форматы и другие параметры, которые связаны с обработкой и поиском данных.

Для настройки маппинга в `Elasticsearch` можно использовать следующие подходы:

1. Явное определение маппинга: Вы можете явно указать маппинг при создании индекса. Это позволяет вам точно определить типы полей, настройки анализаторов и другие параметры. Например, вы можете указать, что поле является текстовым или числовым, настроить его анализатор и т.д. Явное определение маппинга может быть полезно, когда нужно точно управлять обработкой и поиском данных.
2. `Dynamic Mapping` (Динамическое создание маппинга): `Elasticsearch` также предоставляет возможность автоматического определения маппинга на основе структуры загружаемых документов. Это значит, что `Elasticsearch` автоматически создаёт маппинг для вас, исходя из структуры данных в индексе. Он пытается угадать типы полей и настроить анализаторы на основе данных. Динамическое создание маппинга удобно, когда необходимо быстро загрузить данные без явного определения маппинга.

Чтобы достичь оптимального хранения данных в `Elasticsearch`, рекомендуется применять следующие рекомендации при настройке маппинга:

1. Типы полей: Используйте подходящий тип поля для каждого атрибута данных. Например, числовые атрибуты могут быть указаны как числовые, даты — как даты, а текстовые — как текстовые.
2. Анализаторы: Настройте анализаторы для текстовых полей. Анализаторы определяют, как текст будет разделен на токены для поиска. Выберите подходящий анализатор для вашего случая использования.
3. Индексирование и хранение: Определите, какие поля будут проиндексированы (доступны для поиска) и какие будут храниться (доступны для извлечения). Некоторые поля могут быть полезны только для агрегаций и не требуют индексирования или хранения.
4. Маппинг сопоставления: При необходимости создайте маппинг сопоставления для специфического поиска. Маппинг сопоставления позволяет задать дополнительные правила для сопоставления текстовых запросов, таких как сопоставление слова синонимов или возможность игнорировать регистр при поиске.

Правильная настройка маппинга позволяет оптимизировать процессы индексации, поиска и агрегации данных в `Elasticsearch`, что обеспечивает более эффективное использование системы.

## Q15. Что такое refresh и flush в контексте индексации?

**Refresh** — делает недавно проиндексированные документы видимыми для поиска; по умолчанию раз в 1 с. Данные из буфера индексатора переносятся в новый сегмент `Lucene` (поиск читает сегменты). **Flush** — запись сегментов из памяти на диск (fsync); происходит по расписанию или при нехватке памяти.

`Refresh` не гарантирует персистентность на диск; flush — да. При сбое между refresh и flush возможна потеря данных за последние секунды. Настройка: `index.refresh_interval` (1s по умолчанию) можно увеличить для массовой индексации; после загрузки вернуть значение.

**Настройка:** `index.refresh_interval` (по умолчанию 1s); принудительный refresh — `POST /index/_refresh`. **Flush** вызывается автоматически по таймеру или при нехватке памяти; принудительный — `POST /index/_flush`. Для логов часто используют `refresh_interval` 5–10s; для поиска в реальном времени — 1s или явный refresh после критичных записей.

## Q16. (!) Что такое `Replication`?

`Replication` в `Elasticsearch` — это процесс создания дополнительных копий индекса для обеспечения высокой доступности данных и улучшения производительности запросов. Когда вы создаёте реплику, `Elasticsearch` автоматически создаёт дополнительное количество копий индекса и распределяет их по узлам кластера.

Для настройки и использования репликации в `Elasticsearch` вам потребуется выполнить следующие шаги:

1. Конфигурация реплик: В файле конфигурации `Elasticsearch` (`elasticsearch.yml`) определите желаемое количество реплик для индексов. Например, если вы хотите, чтобы каждый индекс имел две реплики, установите `index.`number_of_replicas`: 2`.
2. Создание индекса: При создании нового индекса определите количество реплик, используя параметр `number_of_replicas`. Например, при создании индекса через `API Elasticsearch` можно передать параметр `"`number_of_replicas`": 2`.
3. Модификация настроек индекса: Если индекс уже создан и вы хотите изменить количество реплик, вы можете выполнить запрос на изменение настроек индекса, используя `API Elasticsearch`. Например, вы можете использовать запрос `PUT /index/_settings` с телом `{"number_of_replicas": 2}` для изменения `number_of_replicas`.
4. Мониторинг и управление репликами: Вы можете использовать `API Elasticsearch` или инструменты мониторинга, такие как `Kibana`, для отслеживания состояния реплик и выполнения операций по управлению репликами, таких как добавление или удаление реплик.

Преимущества использования репликации в `Elasticsearch`:

1. Высокая доступность: Репликация обеспечивает отказоустойчивость, поскольку если один узел выходит из строя, копии данных на других узлах остаются доступными для запросов.
2. Улучшенная производительность: Репликация позволяет параллельно обрабатывать запросы на различных узлах, распределяя нагрузку и улучшая время отклика.

Важно отметить, что репликация требует дополнительных ресурсов, таких как дисковое пространство и процессорное время, поэтому настройка репликации должна быть основана на ресурсах и требованиях вашего кластера `Elasticsearch`.

## Q17. (!) Как масштабировать данные с помощью `Sharding`?

Масштабирование данных в `Elasticsearch` может быть достигнуто с помощью `Sharding`. `Sharding` — это процесс разделения индекса на несколько независимых фрагментов данных, называемых `Shard`, и их распределение по узлам кластера `Elasticsearch`. Вот некоторые шаги для масштабирования данных с помощью `Sharding`:

1. Разработка стратегии `Sharding`: Определите необходимую стратегию `Sharding` для вашего индекса. Учетом следующих факторов поможет принять решение:
 1. Размер данных: Если у вас большие объемы данных, вам может потребоваться больше `Shard` для обеспечения равномерного распределения нагрузки.
 2. Производительность запросов: Если вы ожидаете высокую нагрузку на чтение/запись данных, увеличение количества `Shard` может улучшить производительность запросов.
 3. Стабильность кластера: Большее количество `Shard` может повлечь за собой увеличение нагрузки на кластер `Elasticsearch`, поэтому убедитесь, что ваш кластер способен обрабатывать такую нагрузку.
2. Создание индекса с нужным количеством `Shard`: При создании нового индекса определите количество `Shard` с помощью параметра `number_of_shards`. Например, при создании индекса через `API Elasticsearch` можно передать параметр `"`number_of_shards`":`.
3. Перераспределение `Shard`: Если у вас уже есть существующий индекс, и вы хотите изменить количество `Shard`, вам необходимо выполнить перераспределение данных. Это можно сделать с помощью инструментов управления кластером `Elasticsearch`, таких как `API Elasticsearch` или `Kibana`. Например, вы можете использовать Reindex API (`POST _reindex`) или `_shrink`/`_split` для перераспределения шардов (для существующего индекса число primary shards не меняется — создают новый индекс и переиндексируют).
4. Мониторинг и управление `Shard`: Вы можете использовать `API Elasticsearch` или инструменты мониторинга, чтобы отслеживать состояние `Shard` и выполнить операции по управлению `Shard`, такие как добавление или удаление `Shard`.

Преимущества масштабирования данных с помощью `Sharding` в `Elasticsearch`:

1. Распараллеливание запросов: `Sharding` позволяет распараллелить обработку запросов на разных узлах кластера, улучшая производительность при работе с большими объемами данных.
2. Распределение нагрузки: `Sharding` позволяет равномерно распределить данные и запросы между узлами кластера, обеспечивая балансировку нагрузки.

Однако важно отметить, что разработка эффективной стратегии шардирования и масштабирования зависит от ресурсов, требований и характера данных вашего кластера `Elasticsearch`.

## Q18. (!) Что обеспечивает отказоустойчивость данных?

`Elasticsearch` предлагает несколько механизмов для обеспечения отказоустойчивости данных. Вот некоторые из них:

1. Репликация данных: `Elasticsearch` автоматически создаёт реплики `Shard`, чтобы обеспечить отказоустойчивость данных. Реплики — это точные копии данных, хранящиеся на разных узлах кластера. Если узел или шард становятся недоступными, `Elasticsearch` может восстановить данные из реплик и продолжить работу без потери данных.
2. Репликационная стратегия: `Elasticsearch` предлагает различные стратегии репликации, чтобы обеспечить надежность и отказоустойчивость данных. Например, вы можете настроить `Elasticsearch` на создание нескольких реплик для каждого шарда, чтобы иметь дополнительные копии данных.
3. `Kafka` и `RabbitMQ`: `Elasticsearch` интегрируется с `Kafka` и `RabbitMQ`, популярными системами обмена сообщениями. Использование этих систем позволяет выполнять асинхронную репликацию данных между различными кластерами `Elasticsearch`, обеспечивая дополнительную отказоустойчивость.
4. Мониторинг состояния кластера: `Elasticsearch` предоставляет `API` и инструменты мониторинга, которые позволяют отслеживать состояние кластера и обнаруживать проблемы, связанные с доступностью данных. Можно настроить системы мониторинга, такие как `Prometheus` или `Nagios`, чтобы получать предупреждения о недоступности данных или низкой производительности.
5. Распределение данных по узлам: `Elasticsearch` автоматически распределяет шарды и их реплики по узлам кластера, чтобы обеспечить равномерное распределение нагрузки и предотвратить единую точку отказа. Это помогает увеличить доступность данных и устранить возможность потери данных из-за отказа одного узла.
6. Транзакционная и `ACID`-совместимая индексация: `Elasticsearch 7.0` и выше поддерживает транзакционную и `ACID`-совместимую индексацию. Это позволяет гарантировать консистентность данных и обеспечить отказоустойчивость в случае сбоев при записи данных.

Все эти механизмы вместе обеспечивают отказоустойчивость данных в `Elasticsearch` и помогают сохранить целостность и доступность данных в случае сбоев или недоступности узлов.

## Q19. Как масштабировать кластер `Elasticsearch`?

Добавление узлов: новый узел присоединяется к кластеру; шарды автоматически перераспределяются (**rebalancing**). Число **primary shards** задаётся при создании индекса и не меняется для существующего индекса; число реплик можно менять динамически.

Для масштабирования записи — больше primary shards при создании индекса; для чтения — больше реплик. Для временных индексов (логи) используют rollover: новый индекс при достижении размера/возраста, алиас переключается. Мониторинг: баланс шардов по узлам, горячие узлы; при необходимости — индексные алиасы и rollover для временных данных.

**Практика:** число primary shards выбирают при создании индекса (например, по числу узлов или ожидаемому объёму); для временных индексов (логи) используют rollover — новый индекс при достижении размера/возраста, алиас переключается на новый индекс. Реплики: `PUT /index/_settings` с `number_of_replicas` — увеличивает отказоустойчивость и пропускную способность чтения. Rebalance можно ограничить (throttle) при добавлении узлов. Мониторинг через Cat API (`_cat/allocation`, `_cat/health`) и метрики узлов.

## Q20. (!) Как фильтровать и агрегировать данные?

В `Elasticsearch` фильтры и агрегации широко используются для выполнения сложных запросов и анализа данных. Вот как их использовать:

1. Фильтры:
 1. Терминирующие фильтры (term, terms): Позволяют фильтровать документы, у которых значение поля совпадает с определённым термом или набором термов.
2. Диапазонные фильтры (range): Позволяют фильтровать документы, у которых значение поля находится в определенном диапазоне.
3. Существующее поле (exists): Позволяет фильтровать документы, у которых определенное поле существует или не существует.
4. Географический фильтр (`geo_distance`): Позволяет фильтровать документы, находящиеся в определённом расстоянии от указанной точки.
5. Логические фильтры (bool): Позволяют комбинировать несколько фильтров с помощью операций `AND`, `OR`, `NOT`.

Пример использования фильтров в `Elasticsearch`:

```http
GET /index_name/_search
```

```json
{
  "query": {
    "bool": {
      "filter": [
        { "term": { "field1": "value1" } },
        { "range": { "field2": { "gte": 10, "lte": 20 } } },
        { "exists": { "field": "field3" } },
        {
          "geo_distance": {
            "distance": "10km",
            "location": {
              "lat": 42.1234,
              "lon": -73.5678
            }
          }
        }
      ]
    }
  }
}
```

2. Агрегации:
1. Метрические агрегации (sum, avg, min, max, stats): Позволяют выполнять вычисления на числовых полях документов, например, сумму, среднее значение, минимум или максимум.
 2. Терминовые агрегации (terms): Позволяют группировать документы по определённому полю и подсчитывать количество документов в каждой группе.
 3. Гистограммные агрегации (histogram): Позволяют создавать группы значений на основе числового поля и вычислять количество документов в каждой группе.
4. Гео-агрегации (`geo_bounds`, `geo_centroid`): Позволяют выполнять агрегации на географических данных, таких как определение границ или центра области.

Пример использования агрегаций в `Elasticsearch`:

```http
GET /index_name/_search
```

```json
{
  "size": 0,
  "aggs": {
    "group_by_field": {
      "terms": {
        "field": "field1",
        "size": 10
      },
      "aggs": {
        "avg_field": {
          "avg": {
            "field": "field2"
          }
        },
        "max_field": {
          "max": {
            "field": "field3"
          }
        }
      }
    }
  }
}
```

Это только небольшое введение в использование фильтров и агрегаций в `Elasticsearch`. Существует множество других типов и параметров, которые можно использовать для выполнения более сложных запросов и анализа данных. Дополнительную информацию и примеры можно найти в официальной документации `Elasticsearch`.

## Q21. (!) Какие алгоритмы и индексы используются для поиска?

`Elasticsearch` использует различные алгоритмы и индексы для эффективного поиска и индексации данных. Вот основные из них:

1. Инвертированный индекс: Это основной индекс, используемый `Elasticsearch`. Он состоит из отображения каждого уникального терма в список документов, содержащих этот терм. Инвертированный индекс позволяет быстро и эффективно находить документы, соответствующие определённому запросу.
2. `TF-IDF` (`Term Frequency-Inverse Document Frequency`): Это статистический алгоритм, используемый для оценки важности термов в документах. `TF-IDF` учитывает частоту терма в документе (`TF`) и обратную частоту терма в коллекции документов (`IDF`). Чем выше `TF-IDF` для терма в документе, тем более значимым считается этот терм для запроса.
3. `BM25` (`Best Match` 25): Это алгоритм ранжирования, который оценивает релевантность документов для определённого запроса. `BM25` учитывает не только частоту термов в документе, но и длину документа, среднюю длину документов в коллекции и другие факторы, чтобы определить наиболее подходящие результаты.
4. Поиск фраз: `Elasticsearch` также поддерживает поиск фраз, который ищет документы, содержащие определённую фразу или последовательность термов. Для этого используется индекс позиций, который сохраняет информацию о позициях термов в каждом документе.
5. Индексирование геоданных: `Elasticsearch` предоставляет индексы и алгоритмы для индексации и поиска географических данных. Это позволяет выполнять запросы, связанные с географическим положением, например, поиск документов в определённом радиусе от указанной точки.

Это только небольшой обзор алгоритмов и индексов, используемых в `Elasticsearch`.`Elasticsearch` также предлагает возможность настройки и расширения поиска с помощью различных параметров и дополнительных модулей, таких как ранжирование релевантности, фасетный поиск, анализ текста и т. д.

## Q22. (!) Как выполнять поиск по полному тексту?

В `Elasticsearch` поиск по полному тексту выполняется с использованием `Query DSL`, который позволяет создавать мощные и гибкие запросы. Вот несколько основных способов выполнения поиска по полному тексту:

1. `Match Query`: Этот тип запроса ищет документы, содержащие указанный текст в определённом поле. Например, для поиска документов, содержащих слово "apple" в поле `title`, вы можете использовать следующий запрос:

```http
GET /index/_search
```

```json
{
    "query": {
        "match": {
            "title": "apple"
        }
    }
}
```

2. `Multi Match Query`: Этот тип запроса выполняет поиск в нескольких полях одновременно. Например, для поиска слова "apple" в полях `title` и `description`, вы можете использовать следующий запрос:

```http
GET /index/_search
```

```json
{
    "query": {
        "multi_match": {
            "query": "apple",
            "fields": ["title", "description"]
        }
    }
}
```

3. `Match Phrase Query`: Этот тип запроса ищет документы, содержащие указанную фразу в определённом порядке в поле. Например, для поиска документов, содержащих фразу "red apple", вы можете использовать следующий запрос:

```http
GET /index/_search
```

```json
{
    "query": {
        "match_phrase": {
            "title": "red apple"
        }
    }
}
```

4. `Boolean Query`: Этот тип запроса позволяет выполнять логические операции, такие как объединение, исключение и должны быть. Например, для поиска документов, содержащих слова "apple" и "fruit", вы можете использовать следующий запрос:

```http
GET /index/_search
```

```json
{
    "query": {
        "bool": {
            "must": [
                { "match": { "title": "apple" } },
                { "match": { "title": "fruit" } }
            ]
        }
    }
}
```

Это только небольшой обзор способов выполнения поиска по полному тексту в `Elasticsearch`. `Elasticsearch` предлагает множество других возможностей, таких как ранжирование релевантности, фильтрация, агрегация и т. д., чтобы помочь вам настроить поиск согласно вашим потребностям.

## Q23. Как использовать `Aggregation`?

В `Elasticsearch` механизм агрегаций используется для получения статистических данных на основе запросов к индексам.

Чтобы использовать агрегации, вам необходимо создать запрос с соответствующей структурой:

```json
{
    "size": 0,
    "aggs": {
        "aggregation_name": {
            "aggregation_type": {
                "aggregation_field": "field_name"
            }
        }
    }
}
```

Здесь `aggregation_name` — это название вашей агрегации, `aggregation_type` — это тип агрегации, который определяет, какую статистику вы хотите получить, `aggregation_field` — это поле, по которому проводится агрегация.

Например, если вы хотите получить общее количество документов в индексе, вы можете использовать агрегацию `cardinality` (количество уникальных значений):

```json
{
    "size": 0,
    "aggs": {
        "total_docs": {
            "cardinality": {
                "field": "field_name"
            }
        }
    }
}
```

Если вы хотите получить статистику по числовому полю (например, среднее `Value`, минимальное и максимальное), вы можете использовать агрегацию stats:

```json
{
    "size": 0,
    "aggs": {
        "numeric_stats": {
            "stats": {
                "field": "numeric_field"
            }
        }
    }
}
```

Вы также можете комбинировать несколько агрегаций, используя их вложенность:

```json
{
    "size": 0,
    "aggs": {
        "aggregation_name": {
            "type": "aggregation_type",
            "field": "field_name",
            "aggs": {
                "nested_aggregation": {
                    "type": "nested_aggregation_type",
                    "field": "field_name"
                }
            }
        }
    }
}
```

Замените `aggregation_name` и `aggregation_type` на соответствующие значения выбранной вами агрегации и её типа.

В `Elasticsearch` доступно множество типов агрегаций и каждый из них имеет свои особенности и параметры настройки. Для получения более подробной информации о типах агрегаций и их настройке, вы можете обратиться к официальной документации `Elasticsearch` или использовать инструменты и библиотеки, предоставляемые `Elasticsearch` для создания и визуализации агрегаций.

## Q24. Как использовать `Elasticsearch` для полнотекстового поиска в `Java`?

Клиент **Elasticsearch `Java API` Client** (официальный) или `RestHighLevelClient` (deprecated): создание индекса с mapping, индексация документов, запросы (match, `match_phrase`, bool). В `Spring` — **ElasticsearchRepository** (`Spring Data Elasticsearch`) для `CRUD` и кастомных запросов через `NativeQuery`.

Для полнотекстового поиска: `QueryBuilders`.`matchQuery()`, `multiMatchQuery()`; настройка анализаторов и синонимов; для фразового поиска — `matchPhraseQuery`; для фильтрации без влияния на score — `boolQuery()`.must().filter(). Полнотекстовый поиск: `QueryBuilders`.`matchQuery()`, настройка анализаторов и синонимов.

**Пример (`Spring Data Elasticsearch`):** репозиторий с методом `searchByTitle(`String` title)` и кастомным запросом через `NativeSearchQuery` с `QueryBuilders.`multiMatchQuery`(title, "title", "description")`. Индексация — вызов `repository.save(entity)`; mapping задаётся в `@Document` или через `IndexOperations`. Для фразового поиска — `matchPhraseQuery`; для фильтрации без влияния на score — `boolQuery().must(...).filter(...)`.

## Q25. (!) Как работает механизм оптимистической блокировки?

Механизм оптимистической блокировки в `Elasticsearch` используется для управления конкурентным доступом к данным. Он обеспечивает возможность управлять ситуациями, когда несколько клиентов или потоков одновременно пытаются изменить один и тот же документ.

Работа механизма оптимистической блокировки в `Elasticsearch` основана на использовании версий документов. Когда документ сохраняется в индексе `Elasticsearch`, ему присваивается определённая версия — числовое значение, обычно представленное в виде целого числа. Каждое обновление или удаление документа увеличивает версию на единицу.

При каждом запросе на изменение документа клиент указывает текущую версию документа, с которой он работает.`Elasticsearch` проверяет, соответствует ли указанная версия текущей версии документа в индексе. Если версии совпадают,`Elasticsearch` выполняет операцию изменения. Если же версии не совпадают, это означает, что другой клиент уже изменил документ, и операция не выполняется.

Если клиент пытается выполнить операцию обновления или удаления документа, но указывает устаревшую версию,`Elasticsearch` отклоняет запрос и возвращает ошибку. В этом случае клиент может повторить операцию с актуальной версией документа, чтобы избежать потери данных.

Механизм оптимистической блокировки позволяет избежать известных коллизий при параллельном доступе к данным. Он особенно полезен в системах с высокой нагрузкой, где несколько клиентов одновременно обновляют один и тот же документ. При правильном использовании оптимистической блокировки можно снизить вероятность потери данных и обеспечить целостность данных в `Elasticsearch`.

## Q26. (!) Как использовать `Transaction`?

`Elasticsearch` является распределённой системой и не поддерживает транзакции в классическом смысле, как это делает реляционная база данных. Однако, начиная с версии `7.0`, `Elasticsearch` предоставляет "bulk" `API`, который позволяет выполнять операции индексации, обновления и удаления нескольких документов в одном запросе и гарантирует атомарность выполнения этих операций. `Bulk API` позволяет отправлять несколько запросов в одном запросе `HTTP`, и `Elasticsearch` обрабатывает их пакетно, что увеличивает производительность. `Bulk API` также предоставляет опцию "refresh" для немедленного обновления индекса после выполнения операций, что может быть полезным при работе с транзакциями во время индексации данных.

Пример использования `Bulk API` для выполнения пакетных операций:

```http
POST /index_name/_bulk
```

```json
{"index": {"_id": "1"}}
{"field1": "value1"}
{"update": {"_id": "2"}}
{"doc": {"field2": "value2"}}
{"delete": {"_id": "3"}}
```

В этом примере выполняются следующие операции:

1. Индексируется документ с идентификатором "1" и полем "field1".
2. Обновляется документ с идентификатором "2", добавляется поле "field2".
3. Удаляется документ с идентификатором "3".

Эти операции будут выполнены в порядке, указанном в запросе bulk, и гарантируют атомарность. При неудаче выполнения одной из операций, это приведёт к откату всех предыдущих успешно выполненных операций.

Важно отметить, что `Bulk API` в `Elasticsearch` не предоставляет возможности блокировки записи на чтение или обновление конкретного документа, как это делает реляционная база данных с использованием транзакций. Когда индексация данных или обновление документов являются частыми и конкурентными операциями, `Elasticsearch` рекомендует использовать оптимистическую параллельную модель для управления конфликтами и обновлений данных.

## Q27. Как использовать `Elasticsearch` для логирования?

`Elasticsearch` является отличным выбором для реализации системы логирования, так как он обладает мощными возможностями по обработке и поиску данных. Вот несколько шагов, которые помогут вам использовать `Elasticsearch` для этой цели:

1. Создайте индекс: начните с создания индекса в `Elasticsearch`, который будет использоваться для хранения логов. Вы можете определить структуру логов, включая поля, такие как дата, уровень важности, сообщение и другие метаданные, которые могут быть полезны для поиска.
2. Индексируйте логи: Когда приложение генерирует логи, индексируйте их в `Elasticsearch` с помощью `API` индексации. Вы можете использовать библиотеки `Elasticsearch` для вашего языка программирования или отправлять запросы напрямую через `HTTP`.
3. Оптимизируйте индексацию: Чтобы индексация была эффективной, рекомендуется использовать буферизацию и пакетное индексирование, чтобы уменьшить количество запросов к `Elasticsearch` и повысить производительность.
4. Настройте анализ и фильтрацию: `Elasticsearch` предлагает широкий набор инструментов для анализа и фильтрации данных. Вы можете использовать анализаторы, токенизаторы и фильтры, чтобы структурировать и нормализовать логи для более эффективного поиска и анализа.
5. Выполняйте поиск и анализ логов: `Elasticsearch` предоставляет мощные возможности для поиска и агрегации данных. Вы можете использовать поисковые запросы, фильтры, сортировку и агрегации, чтобы извлекать нужные логи и получать ценную информацию из логов.
6. Настройте мониторинг и алертинг: Для обеспечения стабильной и надежной системы логирования, необходимо настроить мониторинг `Elasticsearch` и создать оповещения при возникновении проблем или критических событий.
7. Расширьте функциональность: `Elasticsearch` позволяет интегрировать с другими инструментами и плагинами, такими как `Kibana` (для визуализации и аналитики) и `Logstash` (для сбора и обработки логов).

Учет этих шагов поможет вам эффективно использовать `Elasticsearch` для реализации системы логирования. Он обеспечит быстрый и гибкий поиск, анализ и мониторинг ваших логов, что поможет обнаруживать проблемы, анализировать данные и улучшать работу вашего приложения.

## Q28. (!) Как оптимизировать производительность?

В `Elasticsearch` существует несколько оптимизаций производительности, которые можно применить для улучшения работы системы. Вот некоторые из них:

1. Использование индекса времени — Для оптимизации производительности поиска и запросов, можно использовать индексирование временных данных с помощью отдельных индексов для каждого временного периода. Это позволяет ускорить поиск, так как `Elasticsearch` может ограничить область поиска только на необходимом количестве индексов.
2. Настройка числа реплик и распределения `Shard` — Можно настроить количество реплик и `Shard`, чтобы достичь оптимального баланса между доступностью и производительностью. Добавление дополнительных реплик может увеличить производительность чтения, но при этом может потребоваться больше ресурсов. Распределение `Shard` между узлами кластера также может существенно повлиять на производительность.
3. Кеширование запросов — `Elasticsearch` предлагает возможность кеширования запросов. При активации кеширования `Elasticsearch` будет кешировать результаты запросов и в дальнейшем использовать их при повторном выполнении запросов с такими же параметрами. Это может значительно ускорить выполнение запросов, особенно запросов с высокой вычислительной сложностью.
4. Настройка индексирования и анализа — Правильная настройка процесса индексирования и анализа также может повысить производительность. Например, можно уменьшить количество анализаторов или фильтров, применяемых к полям при индексировании данных.
5. Использование фильтров — Вместо выполнения сложных запросов, в `Elasticsearch` можно использовать фильтры для ограничения множества документов, возвращаемых запросом. Фильтры выполняются быстрее, так как они просто исключают документы, не соответствующие условиям фильтра.
6. Масштабирование — `Elasticsearch` предлагает горизонтальное масштабирование путем добавления новых узлов в кластер. Это позволяет увеличить пропускную способность и обработку запросов. Также масштабирование может быть достигнуто путем разделения индексов на несколько `Shard` и их распределения между узлами.
7. Оптимизация запросов — Анализ запросов и использование корректных подзапросов, агрегаций и фильтров может существенно повысить производительность системы. Оптимизация запросов под конкретные потребности может снизить нагрузку на `Elasticsearch` и сократить время выполнения запросов.

Это лишь некоторые оптимизации, которые можно применить в `Elasticsearch` для повышения производительности. В каждом конкретном случае может потребоваться индивидуальная настройка в зависимости от требований и особенностей приложения.

## Q29. Что такое `Index Lifecycle Management` (`ILM`)?

**ILM** — политики управления жизненным циклом индекса: **hot** (активная запись и чтение), **warm** (только чтение, оптимизация), **cold** (архив), **delete**. Позволяет автоматически перемещать индексы по фазам по возрасту или размеру, уменьшать число реплик, force merge, удалять старые индексы.

Фазы задаются в index template или при создании индекса: `min_age` и actions (rollover, shrink, forcemerge, delete). `Rollover` по размеру или возрасту создаёт новый индекс и переключает алиас; в warm/cold уменьшают реплики и выполняют force merge. Используется для логов и временных данных: снижение стоимости и сохранение производительности для «горячих» данных.

Политика задаётся в index template или при создании индекса: фазы с `min_age` и actions (rollover, shrink, forcemerge, delete). `Rollover / hot 7` дней с 1 репликой, `warm 30` дней с force merge, delete через 90 дней.

**Практика:** создать policy через API (`PUT _ilm/policy/logs_policy`) с фазами hot (rollover `max_size` 50gb или `max_age` 1d), warm (`min_age` 7d, forcemerge, shrink), delete (`min_age` 90d). Привязать к index template: `index.lifecycle.name: logs_policy`, `index.lifecycle.rollover_alias: logs`. Индексы создаются с алиасом `logs`; при достижении условий rollover создаётся новый индекс и алиас переключается. Мониторинг: Cat API `GET _cat/indices?v&h=index,status,pri,rep` — текущая фаза индексов.

## Q30. Как обеспечить безопасность `Elasticsearch`?

Аутентификация: встроенный или внешний (**LDAP**, **SAML**) realm; пользователи и роли в **X-Pack** (платная подписка) или `Open Distro`. **TLS**: шифрование трафика между узлами и между клиентом и кластером; сертификаты в конфигурации.

В `Open Source`: `Search Guard` или `Open Distro` дают базовую аутентификацию и `TLS`. Роли ограничивают доступ к индексам (read, write, `delete_index`). В production: `xpack.security.enabled`: `true` (при подписке), настройка `PKI` или встроенного realm. Сетевая изоляция: кластер не доступен снаружи; доступ только через `API Gateway` или приложение. Регулярное обновление и аудит доступа.

В `Open Source`: `Search Guard` или `Open Distro` for `Elasticsearch` дают базовую аутентификацию и `TLS`. Роли ограничивают доступ к индексам (read, write, `delete_index`). В production: `xpack.security.enabled`: `true` (при подписке), настройка `PKI` или встроенного realm; `TLS` для transport и http. Секреты и сертификаты — из `Vault` или переменных окружения, не в конфиге в репозитории.

**Практика:** в `Kubernetes` кластер `Elasticsearch` в отдельном namespace без `Ingress` на данные-ноды; доступ только из приложений по внутреннему `Service`. При использовании X-Pack — секреты и роли в настройках. `TLS` для transport включать между узлами кластера; для клиентов — `HTTPS` или `TLS` до балансировщика.
