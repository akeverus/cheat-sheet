## Q1. (!) Что такое граф и какие виды бывают?

**Граф** `G = (V, E)` — это множество **вершин** (V) и множество **рёбер** (E), где каждое ребро соединяет пару вершин. Всё, что описывается как «объекты и связи между ними», — это граф: люди и дружба, города и дороги, классы и зависимости.

Виды отличаются по трём независимым осям — направление рёбер, наличие весов, наличие циклов, — и эти оси комбинируются (граф может быть одновременно ориентированным, взвешенным и ацикличным — это и есть DAG).

**Классификация:**

| Тип | Описание |
|-----|----------|
| **Ориентированный (directed)** | Рёбра имеют направление |
| **Неориентированный (undirected)** | Рёбра двунаправленные |
| **Взвешенный (weighted)** | Каждое ребро имеет вес |
| **Невзвешенный** | Все рёбра одинаковы |
| **Циклический** | Содержит хотя бы один цикл |
| **Ациклический (DAG)** | Нет циклов, ориентированный |
| **Связный** | Между любыми двумя вершинами есть путь |
| **Полный** | Все вершины попарно соединены |
| **Bipartite (двудольный)** | Вершины разбиваются на 2 группы, рёбра только между группами |
| **Tree** | Связный, ациклический, с `V - 1` рёбрами |

**Где встречается:**
- Социальные сети (друзья, подписки)
- Маршрутизация (карты, интернет)
- Зависимости (Maven/Gradle, Spring beans)
- Рекомендации (e-commerce)

**Что часто спрашивают дальше:** дерево — это всегда граф (связный ациклический с `V - 1` рёбрами), но не всякий граф — дерево.


## Q2. (!) Как представляют графы в коде?

Граф не хранят как картинку — хранят информацию «кто с кем соединён». Есть три способа, и выбор между ними определяет, какие операции дешёвые, а какие дорогие.

**1. Матрица смежности — `boolean[V][V]` или `int[V][V]`.** Ячейка `[u][v]` хранит вес ребра (или признак его наличия). Проверка ребра — мгновенная, но память всегда `O(V²)`, даже если рёбер мало.

```java
int[][] matrix = new int[V][V];
matrix[u][v] = weight; // ребро u → v с весом
matrix[v][u] = weight; // для неориентированного
```

**2. Список смежности — `List<List<Integer>>` или `Map<V, List<V>>`.** Для каждой вершины храним список её соседей. Память `O(V + E)` — пропорциональна реальному числу рёбер. Это формат по умолчанию для большинства задач.

```java
List<List<int[]>> adj = new ArrayList<>(); // список пар {to, weight}
for (int i = 0; i < V; i++) adj.add(new ArrayList<>());
adj.get(u).add(new int[]{v, weight});
```

**3. Список рёбер — `List<Edge>`.** Просто перечень всех рёбер. Удобен, когда алгоритм перебирает рёбра целиком, а не соседей конкретной вершины (Краскал, Беллман-Форд).

```java
record Edge(int from, int to, int weight) {}
List<Edge> edges = new ArrayList<>();
```

**Рекомендация:** для production-кода на Java не изобретайте свою структуру — берите библиотеку **JGraphT**, она даёт готовые типы графов и реализации алгоритмов.


## Q3. Когда матрица, а когда список смежности?

Коротко: матрица — когда рёбер почти столько же, сколько пар вершин (плотный граф) и нужна мгновенная проверка «есть ли ребро `u→v`». Список смежности — во всех остальных случаях, и это дефолт. Разница видна в таблице операций:

| Критерий | Матрица | Список смежности |
|----------|---------|-------------------|
| Память | `O(V²)` | `O(V + E)` |
| Проверка ребра `(u, v)` | `O(1)` | `O(degree(u))` |
| Перебор соседей `u` | `O(V)` | `O(degree(u))` |
| Добавление ребра | `O(1)` | `O(1)` |
| Удаление ребра | `O(1)` | `O(degree(u))` |
| Лучше для | Плотных графов | Разреженных графов |

**Эмпирическое правило:** если `E ≈ V²` — матрица, если `E ≈ V` — список.

На практике почти всё реальное — список: в соцсети миллионы пользователей, но средний фолловинг ~100 (матрица `10⁶ × 10⁶` не влезет в память); на дорожной карте у перекрёстка ~10 связей. Матрица оправдана в задачах с маленьким плотным графом — например, Floyd-Warshall на 200 городах.


## Q4. Что такое плотный и разреженный граф?

Это про соотношение числа рёбер и числа вершин — оно напрямую определяет, какую асимптотику давать на собеседовании.

- **Плотный (dense):** `E ≈ V²`, рёбер почти столько, сколько максимально возможно (`V·(V-1)/2`).
- **Разреженный (sparse):** `E << V²`, часто `E = O(V)` — рёбер примерно столько же, сколько вершин.

Большинство реальных графов **разреженные** (соцсети, дорожные карты, граф зависимостей). Поэтому, когда спрашивают сложность, важно уточнить: для разреженного графа `O(V + E)` фактически означает `O(V)`, а для плотного — `O(V²)`.

| Алгоритм | Sparse `E ≈ V` | Dense `E ≈ V²` |
|----------|----------------|-----------------|
| BFS/DFS | `O(V)` | `O(V²)` |
| Dijkstra (с heap) | `O(V log V)` | `O(V² log V)` |
| Dijkstra (с массивом) | `O(V²)` | `O(V²)` |
| Floyd-Warshall | `O(V³)` | `O(V³)` |

**Нюанс:** на плотном графе версия Dijkstra на куче даёт лишний `log V`, поэтому матричная реализация на массиве (`O(V²)`) может оказаться быстрее куч-версии.


## Q5. (!) Как работает BFS (обход в ширину)?

**BFS (Breadth First Search)** обходит граф **по уровням**: сначала стартовая вершина, затем все её соседи (расстояние 1), затем соседи соседей (расстояние 2) и так далее. Расходясь равномерными «волнами» от старта, BFS гарантирует, что вершина впервые достигается по кратчайшему (в числе рёбер) пути.

**Почему очередь.** Порядок обработки — FIFO: вершину, обнаруженную раньше, и обрабатываем раньше. Именно очередь удерживает «фронт волны». Помечать вершину посещённой нужно **в момент добавления в очередь**, а не извлечения, — иначе одна вершина попадёт в очередь несколько раз.

```java
void bfs(List<List<Integer>> adj, int start) {
    boolean[] visited = new boolean[adj.size()];
    Queue<Integer> queue = new ArrayDeque<>();
    queue.offer(start);
    visited[start] = true;

    while (!queue.isEmpty()) {
        int u = queue.poll();
        process(u);
        for (int v : adj.get(u)) {
            if (!visited[v]) {
                visited[v] = true;
                queue.offer(v);
            }
        }
    }
}
```

**Сложность:** `O(V + E)` по времени (каждую вершину и каждое ребро трогаем один раз), `O(V)` по памяти на очередь и массив `visited`.

**Где применяют:**
- Кратчайший путь в невзвешенном графе (главная причина выбрать BFS вместо DFS)
- Найти все вершины на расстоянии ровно K от старта
- Проверка двудольности (раскраска в 2 цвета)
- Web crawling, «друзья друзей» в соцсети


## Q6. (!) Как работает DFS (обход в глубину)?

**DFS (Depth First Search)** идёт «вглубь» по одной ветке, пока не упрётся в тупик (все соседи посещены), затем откатывается на шаг назад (backtrack) и пробует следующего непосещённого соседа. В отличие от BFS, который растекается вширь, DFS сначала исчерпывает один путь до конца.

**Почему стек.** Нужен порядок LIFO — последняя обнаруженная вершина обрабатывается первой; это и есть «погружение». Стек либо явный, либо неявный — стек вызовов при рекурсии. Рекурсивная версия короче, но на больших графах стек вызовов может переполниться (`StackOverflowError`), поэтому для глубоких графов берут итеративную версию с собственным `Deque`.

```java
// Рекурсивный
void dfs(List<List<Integer>> adj, int u, boolean[] visited) {
    visited[u] = true;
    process(u);
    for (int v : adj.get(u)) {
        if (!visited[v]) dfs(adj, v, visited);
    }
}

// Итеративный через стек
void dfsIterative(List<List<Integer>> adj, int start) {
    boolean[] visited = new boolean[adj.size()];
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(start);
    while (!stack.isEmpty()) {
        int u = stack.pop();
        if (visited[u]) continue;
        visited[u] = true;
        process(u);
        for (int v : adj.get(u)) {
            if (!visited[v]) stack.push(v);
        }
    }
}
```

**Сложность:** `O(V + E)` по времени, `O(V)` по памяти (стек + `visited`). Глубина рекурсии доходит до `O(V)` — на длинных цепочках это и есть причина переполнения стека.

**Где применяют:**
- Топологическая сортировка (порядок post-order даёт ответ сразу)
- Обнаружение циклов (back edge — это цикл)
- Поиск компонент сильной связности (Tarjan, Kosaraju)
- Backtracking, генерация перестановок
- Поиск выхода из лабиринта


## Q7. (!) Чем BFS отличается от DFS?

Оба обходят весь граф за `O(V + E)` и посещают каждую вершину один раз — разница в **порядке** обхода и, как следствие, в том, для каких задач они годятся. BFS идёт по уровням (структура — очередь), DFS — вглубь (структура — стек/рекурсия).

| Критерий | BFS | DFS |
|----------|-----|-----|
| Структура данных | Queue (FIFO) | Stack (LIFO) или рекурсия |
| Память | `O(w)`, w = ширина уровня | `O(h)`, h = глубина |
| Кратчайший путь | Невзвешенный — да | Не находит |
| Топологическая сортировка | Да (Кан) | Да |
| Обнаружение цикла | Да (с осторожностью) | Естественно |
| Поиск SCC | Не подходит | Tarjan/Kosaraju |
| Память для очень глубоких | Хуже (широкий слой) | Хуже (deep recursion) |
| Память для очень широких | Хуже | Лучше |

**Как выбрать:**
- **BFS** — когда нужен кратчайший путь по числу рёбер или обработка по уровням.
- **DFS** — когда нужна топологическая сортировка, обнаружение циклов, SCC или backtracking.
- По памяти: BFS тяжелее на «широких» графах (огромный фронт уровня), DFS — на «глубоких» (длинная рекурсия).


## Q8. (!) Как найти кратчайший путь в невзвешенном графе?

Ответ — **BFS**. Поскольку BFS расходится волнами и впервые достигает каждой вершины по минимальному числу рёбер, расстояние, на котором вершина обнаружена, и есть длина кратчайшего пути. Никакая куча (как в Dijkstra) тут не нужна — все рёбра равны 1, обычная очередь даёт правильный порядок.

```java
int bfsShortestPath(List<List<Integer>> adj, int start, int end) {
    boolean[] visited = new boolean[adj.size()];
    Queue<int[]> queue = new ArrayDeque<>(); // {вершина, расстояние}
    queue.offer(new int[]{start, 0});
    visited[start] = true;

    while (!queue.isEmpty()) {
        int[] curr = queue.poll();
        int u = curr[0], dist = curr[1];
        if (u == end) return dist;

        for (int v : adj.get(u)) {
            if (!visited[v]) {
                visited[v] = true;
                queue.offer(new int[]{v, dist + 1});
            }
        }
    }
    return -1;
}
```

**Как восстановить сам путь, а не только длину:** при посещении соседа запоминай `parent[v] = u`. Дойдя до `end`, иди по `parent` обратно до `start` и разверни список — получишь сам маршрут.

**Сложность:** `O(V + E)` по времени, `O(V)` по памяти.


## Q9. Что такое двунаправленный BFS (bidirectional BFS)?

**Bidirectional BFS** запускает два поиска одновременно — из `start` и из `end` — и останавливается, как только их фронты встретятся. Смысл: один обычный BFS на расстояние `d` раздувает фронт до `O(b^d)` вершин; два встречных BFS пробегают лишь по `d/2` уровней каждый, поэтому суммарный фронт — `O(b^(d/2))`, что экспоненциально меньше.

**Условия применимости:** известны обе конечные точки, граф обратим (можно идти из `end` назад), и важно расширять **меньший** из двух фронтов — это держит обе волны компактными.

```java
int bidirBFS(List<List<Integer>> adj, int start, int end) {
    if (start == end) return 0;

    Set<Integer> visitedFromStart = new HashSet<>(Set.of(start));
    Set<Integer> visitedFromEnd = new HashSet<>(Set.of(end));
    int distance = 0;

    while (!visitedFromStart.isEmpty() && !visitedFromEnd.isEmpty()) {
        // Расширяем меньший фронт
        if (visitedFromStart.size() > visitedFromEnd.size()) {
            Set<Integer> tmp = visitedFromStart;
            visitedFromStart = visitedFromEnd;
            visitedFromEnd = tmp;
        }

        Set<Integer> next = new HashSet<>();
        for (int u : visitedFromStart) {
            for (int v : adj.get(u)) {
                if (visitedFromEnd.contains(v)) return distance + 1;
                next.add(v);
            }
        }
        visitedFromStart = next;
        distance++;
    }
    return -1;
}
```

**Сложность:** в среднем `O(b^(d/2))` вместо `O(b^d)`, где `b` — коэффициент ветвления, `d` — расстояние между концами. На практике это даёт экспоненциальный выигрыш над обычным BFS — особенно заметно в задачах вроде Word Ladder.


## Q10. (!) Как работает алгоритм Дейкстры?

**Dijkstra** находит кратчайшие пути от одной вершины до всех остальных в графе с **неотрицательными весами**. Это жадный алгоритм: на каждом шаге из ещё не зафиксированных вершин берётся ближайшая к старту, её расстояние объявляется окончательным, после чего релаксируются (обновляются) её соседи.

**Почему это работает.** Раз все веса неотрицательны, путь не может «подешеветь» по дороге. Значит, ближайшая из оставшихся вершин уже не получит более короткого пути — её можно фиксировать. Куча (`PriorityQueue`) на каждом шаге быстро выдаёт минимум. Запись `if (d > dist[u]) continue` отбрасывает устаревшие копии вершины в куче — это «ленивое удаление» вместо дорогого `decrease-key`.

```java
int[] dijkstra(List<List<int[]>> graph, int start) {
    int n = graph.size();
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[start] = 0;

    // {distance, vertex}
    PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[0]));
    pq.offer(new int[]{0, start});

    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];
        if (d > dist[u]) continue; // устаревшая запись

        for (int[] edge : graph.get(u)) {
            int v = edge[0], w = edge[1];
            int newDist = dist[u] + w;
            if (newDist < dist[v]) {
                dist[v] = newDist;
                pq.offer(new int[]{newDist, v});
            }
        }
    }
    return dist;
}
```

| Реализация | Сложность |
|------------|-----------|
| С массивом | `O(V²)` |
| С бинарной кучей | `O((V + E) log V)` |
| С Fibonacci heap | `O(V log V + E)` |

На собеседовании достаточно знать вариант с бинарной кучей — `O((V + E) log V)`.

**Где применяют:** GPS-навигация, IP-маршрутизация (OSPF), расчёт сетевой задержки.


## Q11. (!) Как работает алгоритм Беллмана-Форда?

**Bellman-Ford** находит кратчайшие пути от одной вершины и, в отличие от Dijkstra, **работает с отрицательными весами** и умеет **обнаружить отрицательный цикл**. Платит за это скоростью: `O(V · E)` вместо `O((V+E) log V)`.

**Почему `V−1` итерация.** Алгоритм `V−1` раз релаксирует **все** рёбра. Кратчайший путь без циклов содержит не более `V−1` ребра, и каждая итерация гарантированно «дотягивает» правильное расстояние ещё на одно ребро дальше от старта. После `V−1` прохода все кратчайшие пути зафиксированы.

**Как ловится отрицательный цикл.** Делаем ещё один проход: если хоть одно расстояние всё ещё уменьшается — значит, есть цикл с отрицательной суммой (по нему можно крутиться бесконечно, делая путь всё короче). В нём кратчайшего пути просто не существует.

```java
int[] bellmanFord(int n, List<int[]> edges, int start) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[start] = 0;

    // V-1 итераций релаксации всех рёбер
    for (int i = 0; i < n - 1; i++) {
        for (int[] edge : edges) {
            int u = edge[0], v = edge[1], w = edge[2];
            if (dist[u] != Integer.MAX_VALUE && dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
            }
        }
    }

    // Проверка отрицательного цикла
    for (int[] edge : edges) {
        int u = edge[0], v = edge[1], w = edge[2];
        if (dist[u] != Integer.MAX_VALUE && dist[u] + w < dist[v]) {
            throw new IllegalStateException("Negative cycle detected!");
        }
    }
    return dist;
}
```

**Сложность:** `O(V · E)` — медленнее Dijkstra, но универсальнее. **Где применяют:** поиск арбитража на forex (цикл с отрицательной суммой логарифмов курсов = возможность заработать на конвертациях), маршрутизация, где у рёбер бывают «доплаты» (отрицательные веса).


## Q12. Когда Dijkstra не работает?

**Dijkstra ломается на отрицательных весах.** Алгоритм построен на допущении, что зафиксированную вершину уже нельзя удешевить. Отрицательное ребро это допущение нарушает: жадно зафиксировав вершину как «ближайшую», алгоритм может позже обнаружить путь до неё короче — но возвращаться и пересчитывать он уже не станет.

Пример:
```
A → B: 5
A → C: 4
C → B: -2
```
Правильный ответ от A: `dist[B] = 4 + (-2) = 2`. В этом мелком примере Dijkstra случайно даёт верный результат (зафиксирует `dist[C] = 4`, затем дотянет B через C до 2). Но стоит появиться ситуации, где вершина фиксируется раньше, чем найден её отрицательный объезд, — и ответ становится неверным. Гарантий нет, поэтому Dijkstra на таких графах попросту не применяют.

**Что использовать вместо.** Для отрицательных весов берут **Bellman-Ford** (он же ловит отрицательные циклы) или его ускоренный вариант **SPFA**.

**Второй случай.** На плотном графе версия Dijkstra на куче проигрывает из-за лишнего `log V` — там лучше реализация на массиве `O(V²)`.


## Q13. (!) Как работает Floyd-Warshall (кратчайшие пути между всеми парами)?

**Floyd-Warshall** считает кратчайшие пути **между всеми парами** вершин разом. Работает с любыми весами (отрицательные допускаются, отрицательные циклы — нет).

**Идея — динамическое программирование по «разрешённым промежуточным вершинам».** Внешний цикл по `k` означает: разрешаем использовать вершины `0..k` как промежуточные. На каждом шаге для каждой пары `(i, j)` проверяем, не короче ли пройти через `k`: `dist[i][k] + dist[k][j]`. Перебрав все `k`, мы перебрали все возможные промежуточные вершины — и получили точные кратчайшие пути. Ключевой нюанс: цикл по `k` обязан быть **внешним**, иначе ответ будет неверным.

```java
int[][] floydWarshall(int[][] graph) {
    int n = graph.length;
    int[][] dist = new int[n][n];
    for (int i = 0; i < n; i++) dist[i] = graph[i].clone();

    for (int k = 0; k < n; k++) {
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (dist[i][k] != Integer.MAX_VALUE
                    && dist[k][j] != Integer.MAX_VALUE
                    && dist[i][k] + dist[k][j] < dist[i][j]) {
                    dist[i][j] = dist[i][k] + dist[k][j];
                }
            }
        }
    }
    return dist;
}
```

**Сложность:** `O(V³)` по времени, `O(V²)` по памяти. Идеален для **малых плотных графов** (до ~500 вершин) благодаря простоте и хорошей константе. Для больших графов выгоднее запустить Dijkstra (или Bellman-Ford при отрицательных весах) от каждой вершины.


## Q14. Что такое A* (A-star) поиск?

**A\*** — это Dijkstra, дополненный **эвристикой**, которая направляет поиск к цели. Dijkstra расширяется во все стороны равномерно; A\* предпочитает вершины, которые «на вид» ближе к финишу, поэтому до цели добирается, осмотрев заметно меньше вершин.

Приоритет вершины определяется суммой двух слагаемых:

```
f(n) = g(n) + h(n)
g(n) — фактическое расстояние от start до n
h(n) — эвристическая оценка от n до end (admissible — не переоценивает)
```

Эвристика `h` должна быть **допустимой (admissible)** — никогда не переоценивать реальное расстояние до цели; только тогда A\* гарантированно находит оптимальный путь. Крайние случаи: при `h(n) ≡ 0` A\* вырождается ровно в Dijkstra, а при точной `h` — идёт прямо к цели, не отвлекаясь.

**Где применяют:** игровая навигация (поиск пути для NPC), GPS, робототехника.

```java
// Эвристика для grid: Manhattan / Euclidean distance
int manhattan(int[] a, int[] b) {
    return Math.abs(a[0] - b[0]) + Math.abs(a[1] - b[1]);
}
```


## Q15. (!) Что такое MST (минимальное остовное дерево)?

**Minimum Spanning Tree (MST)** — это подмножество рёбер взвешенного связного графа, которое соединяет **все** вершины (остов), не образует циклов (дерево) и имеет **минимальную суммарную стоимость** рёбер. В MST всегда ровно `V − 1` ребро.

**Интуиция:** «как соединить все точки самым дешёвым способом». Циклы запрещены не случайно — лишнее ребро в цикле можно выбросить и стоимость только уменьшится.

**Где применяют:**
- Прокладка кабельной/дорожной сети с минимальной длиной
- Организация коммуникаций (telecom)
- Кластеризация (выбросить самые «дорогие» рёбра MST — получить кластеры)
- Приближённые алгоритмы для задачи коммивояжёра (TSP)

Два классических алгоритма строят MST: **Краскала** и **Прима**.


## Q16. (!) Как работает алгоритм Краскала?

**Kruskal** строит MST «по рёбрам»: сортирует все рёбра по весу и идёт от самого дешёвого, добавляя ребро только если оно **не образует цикл**. Жадность тут безопасна: самое дешёвое ребро, соединяющее две разные части графа, всегда входит в какой-то MST.

**Почему Union-Find.** Проверка «образует ли ребро цикл» сводится к вопросу «лежат ли его концы уже в одной компоненте». Структура Union-Find (система непересекающихся множеств) отвечает на это почти за `O(1)`: `find` ищет корень компоненты, `union` сливает две компоненты. Если концы ребра уже в одной компоненте — ребро отбрасываем.

```java
int kruskalMST(int n, List<int[]> edges) {
    edges.sort(Comparator.comparingInt(e -> e[2])); // по весу
    UnionFind uf = new UnionFind(n);
    int totalWeight = 0, edgesUsed = 0;

    for (int[] e : edges) {
        int u = e[0], v = e[1], w = e[2];
        if (uf.union(u, v)) {
            totalWeight += w;
            if (++edgesUsed == n - 1) break;
        }
    }
    return totalWeight;
}
```

**Сложность:** `O(E log E)` — доминирует сортировка рёбер. Сами операции Union-Find с path compression и union by rank почти константны (`O(E · α(V))`, где `α` — обратная функция Аккермана, на практике ≤ 4).

**Когда выбирать:** для **разреженных графов** (мало рёбер) — там сортировать дёшево.


## Q17. (!) Как работает алгоритм Прима?

**Prim** строит MST «по вершинам»: начинает с одной вершины и выращивает дерево, на каждом шаге присоединяя **самое дешёвое ребро**, ведущее из уже построенного дерева наружу — к ещё не включённой вершине. Так дерево растёт единым связным куском (в отличие от Краскала, где рёбра могут собираться в разных частях графа и сливаться).

**Почему куча.** Чтобы быстро находить минимальное «выходящее» ребро, кандидаты складывают в `PriorityQueue`. Когда вершина включается в дерево, в кучу добавляются все её рёбра наружу. Проверка `if (inMST[u]) continue` отбрасывает устаревшие рёбра к уже включённым вершинам.

```java
int primMST(List<List<int[]>> adj) {
    int n = adj.size();
    boolean[] inMST = new boolean[n];
    PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[1]));
    pq.offer(new int[]{0, 0}); // {vertex, weight}
    int totalWeight = 0, edgesUsed = 0;

    while (!pq.isEmpty() && edgesUsed < n) {
        int[] curr = pq.poll();
        int u = curr[0], w = curr[1];
        if (inMST[u]) continue;
        inMST[u] = true;
        totalWeight += w;
        edgesUsed++;
        for (int[] edge : adj.get(u)) {
            if (!inMST[edge[0]]) pq.offer(new int[]{edge[0], edge[1]});
        }
    }
    return totalWeight;
}
```

**Сложность:** `O(E log V)` с бинарной кучей. **Когда выбирать:** для **плотных графов** (много рёбер) — Прим обходится без сортировки всех рёбер и растёт локально.


## Q18. Чем Краскал отличается от Прима?

Оба дают MST одинаковой стоимости — отличаются стратегией. Краскал смотрит на **рёбра глобально** (сортирует все и добавляет дешёвые, пока не образуют цикл), Прим растит дерево **локально из одной вершины**. Отсюда и разные структуры данных, и разная пригодность к плотности графа.

| Критерий | Kruskal | Prim |
|----------|---------|------|
| Структура | Сортировка + Union-Find | Priority queue |
| Сложность | `O(E log E)` | `O(E log V)` |
| Подход | Глобальный (по всем рёбрам) | Локальный (растёт из вершины) |
| Лучше для | Разреженных | Плотных |
| Параллелизация | Сложно | Легко |
| Связан ли граф | Не требуется | Требуется (иначе строит лес на одной компоненте) |

**Итог:** стоимость MST у обоих одинакова; при уникальных весах MST вообще единственный, и оба алгоритма выдают буквально одно и то же дерево.


## Q19. (!) Как обнаружить цикл в неориентированном графе?

**DFS с отслеживанием родителя.** Идём в глубину; если наткнулись на уже посещённую вершину, которая **не является родителем** текущей в дереве обхода, — это back edge, то есть цикл.

**Зачем исключать родителя.** В неориентированном графе ребро `u—v` видно с обеих сторон. Зайдя из `u` в `v`, мы тут же увидим `u` среди соседей `v` как «посещённую» — но это то самое ребро, по которому мы только что пришли, а не цикл. Поэтому возврат к непосредственному родителю не считается; цикл — только возврат к какой-то **другой** уже посещённой вершине.

```java
boolean hasCycle(List<List<Integer>> adj) {
    boolean[] visited = new boolean[adj.size()];
    for (int i = 0; i < adj.size(); i++) {
        if (!visited[i] && dfsCycle(adj, i, -1, visited)) return true;
    }
    return false;
}

boolean dfsCycle(List<List<Integer>> adj, int u, int parent, boolean[] visited) {
    visited[u] = true;
    for (int v : adj.get(u)) {
        if (!visited[v]) {
            if (dfsCycle(adj, v, u, visited)) return true;
        } else if (v != parent) {
            return true; // back edge — цикл!
        }
    }
    return false;
}
```

**Альтернатива — Union-Find:** перебираем рёбра и для каждого делаем `union` концов; если концы уже в одной группе — ребро замыкает цикл.

**Сложность:** `O(V + E)`.


## Q20. (!) Как обнаружить цикл в ориентированном графе?

**DFS с тремя цветами (состояниями).** Здесь приём с родителем из Q19 не работает — нужно отличать «вершину в текущей рекурсивной цепочке» от «вершины, уже полностью обработанной в другой ветке». Для этого вводят три состояния:

- **WHITE** — ещё не посещена;
- **GRAY** — сейчас в стеке текущего DFS (на пути от корня к текущей вершине);
- **BLACK** — полностью обработана, из неё уже вышли.

**Критерий цикла:** ребро ведёт в **GRAY**-вершину. Это означает, что мы вернулись к вершине, которая лежит выше нас на текущем пути, — то есть нашли back edge, замыкающий цикл. Попадание в BLACK циклом не является: та ветка давно завершена и к текущему пути отношения не имеет.

```java
boolean hasCycleDirected(List<List<Integer>> adj) {
    int n = adj.size();
    int[] color = new int[n]; // 0=WHITE, 1=GRAY, 2=BLACK
    for (int i = 0; i < n; i++) {
        if (color[i] == 0 && dfsDirected(adj, i, color)) return true;
    }
    return false;
}

boolean dfsDirected(List<List<Integer>> adj, int u, int[] color) {
    color[u] = 1; // GRAY
    for (int v : adj.get(u)) {
        if (color[v] == 1) return true; // back edge
        if (color[v] == 0 && dfsDirected(adj, v, color)) return true;
    }
    color[u] = 2; // BLACK
    return false;
}
```

**Сложность:** `O(V + E)`. **Альтернатива — алгоритм Кана:** если топологическая сортировка не сумела разложить все вершины (в результате осталось `< V` вершин) — в графе есть цикл.


## Q21. Как найти компоненты связности?

Речь о неориентированном графе. **Компонента связности** — это максимальный кусок графа, внутри которого из любой вершины достижима любая другая. Идея проста: запускаем DFS/BFS от первой непосещённой вершины — обход накроет ровно одну компоненту целиком. Повторяем, пока есть непосещённые вершины; сколько запусков понадобилось — столько и компонент.

```java
int countComponents(int n, List<List<Integer>> adj) {
    boolean[] visited = new boolean[n];
    int count = 0;
    for (int i = 0; i < n; i++) {
        if (!visited[i]) {
            dfs(adj, i, visited);
            count++;
        }
    }
    return count;
}
```

**Альтернатива — Union-Find:** делаем `union` по каждому ребру, затем считаем число уникальных корней — это и есть число компонент. Удобно, когда рёбра приходят потоком и компоненты надо пересчитывать на лету.

**Сложность:** `O(V + E)`.


## Q22. (!) Как найти компоненты сильной связности (SCC)?

Понятие из **ориентированных** графов. **SCC (strongly connected component)** — максимальный набор вершин, где из любой достижима любая другая в **обе** стороны (есть и путь `u → v`, и путь `v → u`). Это «сильная» версия компоненты связности из Q21, где направление рёбер игнорировалось.

**Алгоритм Косараджу (Kosaraju)** — два прохода DFS:

1. DFS по исходному графу, записываем вершины в порядке **завершения** (postorder) в стек.
2. **Транспонируем** граф — разворачиваем все рёбра.
3. DFS по транспонированному графу, беря вершины из стека (то есть в обратном порядке завершения). Каждое отдельное DFS-дерево на этом проходе и есть одна SCC.

**Почему транспонирование.** В обычном графе DFS из SCC может «утечь» в другие SCC по исходящим рёбрам. После разворота рёбер эти переходы блокируются — DFS оказывается заперт внутри одной SCC, и порядок из шага 1 гарантирует, что мы стартуем с правильной вершины.

```java
List<List<Integer>> kosaraju(List<List<Integer>> adj) {
    int n = adj.size();
    boolean[] visited = new boolean[n];
    Deque<Integer> stack = new ArrayDeque<>();

    // Шаг 1: DFS, заполняем стек по postorder
    for (int i = 0; i < n; i++) {
        if (!visited[i]) fillOrder(adj, i, visited, stack);
    }

    // Шаг 2: транспонировать
    List<List<Integer>> trans = transpose(adj, n);

    // Шаг 3: DFS на транспонированном
    Arrays.fill(visited, false);
    List<List<Integer>> sccs = new ArrayList<>();
    while (!stack.isEmpty()) {
        int u = stack.pop();
        if (!visited[u]) {
            List<Integer> scc = new ArrayList<>();
            dfsCollect(trans, u, visited, scc);
            sccs.add(scc);
        }
    }
    return sccs;
}
```

**Алгоритм Тарьяна (Tarjan)** решает ту же задачу за **один** проход DFS, отслеживая low-link значения (минимальный достижимый номер захода). Он сложнее в реализации, но эффективнее на практике — не нужно строить транспонированный граф.

**Сложность:** `O(V + E)` у обоих.


## Q23. Как проверить двудольность графа (bipartite)?

Граф **двудольный**, если его вершины можно разбить на две группы так, что любое ребро идёт строго между группами, а не внутри одной. Эквивалентная формулировка: граф раскрашивается в 2 цвета без конфликтов.

**Способ — BFS с двумя цветами.** Красим стартовую вершину в 0, всех её соседей — в 1, их соседей — снова в 0, чередуя цвета по уровням. Конфликт `color[v] == color[u]` (ребро между одинаково окрашенными вершинами) означает, что разбить вершины на две группы нельзя — граф **не** двудольный. Ключевой факт теории: граф двудольный тогда и только тогда, когда в нём нет циклов нечётной длины — именно такой цикл и даёт конфликт раскраски.

```java
boolean isBipartite(List<List<Integer>> adj) {
    int n = adj.size();
    int[] color = new int[n];
    Arrays.fill(color, -1);

    for (int i = 0; i < n; i++) {
        if (color[i] == -1) {
            Queue<Integer> queue = new ArrayDeque<>();
            queue.offer(i);
            color[i] = 0;
            while (!queue.isEmpty()) {
                int u = queue.poll();
                for (int v : adj.get(u)) {
                    if (color[v] == -1) {
                        color[v] = 1 - color[u];
                        queue.offer(v);
                    } else if (color[v] == color[u]) {
                        return false;
                    }
                }
            }
        }
    }
    return true;
}
```

**Сложность:** `O(V + E)`. **Где применяют:** паросочетания (matching) — например, распределение исполнителей по задачам, — и планирование (scheduling).


## Q24. (!) Что такое топологическая сортировка и зачем она нужна?

**Топологическая сортировка** выстраивает вершины ориентированного графа в линейный ряд так, что для каждого ребра `u → v` вершина `u` стоит **раньше** `v`. По сути это ответ на вопрос «в каком порядке выполнять задачи, чтобы каждая шла после всех своих зависимостей».

**Когда существует.** Только для **DAG** (Directed Acyclic Graph — ориентированный граф без циклов). Если есть цикл `A → B → A`, корректного порядка нет: A должна идти и раньше, и позже B одновременно. Поэтому попытка топологической сортировки заодно служит проверкой на циклы.

**Где применяют:**
- Сборка зависимостей (Maven/Gradle): собрать модуль после всех, от кого он зависит
- Порядок задач с предусловиями
- Граф зависимостей Spring-бинов (порядок инициализации)
- Парсинг конфигов со ссылками друг на друга
- Планирование курсов с пререквизитами


## Q25. (!) Как работает алгоритм Кана (топологическая сортировка через BFS)?

**Алгоритм Кана** делает топологическую сортировку через входящие степени (in-degree). Логика повторяет здравый смысл: сначала выполняем то, у чего нет невыполненных зависимостей.

1. Считаем для каждой вершины `inDegree` — число входящих рёбер (сколько у неё «предусловий»).
2. Кладём в очередь все вершины с `inDegree == 0` — у них нет зависимостей, их можно делать сразу.
3. Берём вершину из очереди, добавляем в результат и «выполняем» её: у каждого соседа уменьшаем `inDegree` на 1. Если у соседа `inDegree` упал до 0 — все его зависимости закрыты, кладём его в очередь.
4. Повторяем, пока очередь не опустеет.

```java
List<Integer> kahnTopologicalSort(int n, List<List<Integer>> adj) {
    int[] inDegree = new int[n];
    for (int u = 0; u < n; u++)
        for (int v : adj.get(u)) inDegree[v]++;

    Queue<Integer> queue = new ArrayDeque<>();
    for (int i = 0; i < n; i++)
        if (inDegree[i] == 0) queue.offer(i);

    List<Integer> order = new ArrayList<>();
    while (!queue.isEmpty()) {
        int u = queue.poll();
        order.add(u);
        for (int v : adj.get(u)) {
            if (--inDegree[v] == 0) queue.offer(v);
        }
    }

    if (order.size() != n) throw new IllegalStateException("Cycle!");
    return order;
}
```

**Сложность:** `O(V + E)`. **Бонус — обнаружение цикла:** если в итоге `order.size() < n`, значит, часть вершин так и не дошла до `inDegree == 0` — они замкнуты в цикл. Дополнительный плюс: вершины выходят из очереди «слоями», поэтому подход естественно ложится на параллельную обработку независимых задач одного уровня.


## Q26. Как сделать топологическую сортировку через DFS?

**Через DFS и порядок завершения (post-order).** Запускаем DFS; вершину кладём в стек **после** того, как полностью обработали всех её потомков (в момент выхода из рекурсии). Тогда вершина оказывается в стеке раньше всех тех, кто от неё зависит, и попадает «ниже» них. В конце разворачиваем стек — это и есть топологический порядок.

**Почему именно post-order.** Если `u → v`, то DFS из `u` сначала целиком обработает `v` (и положит его в стек), и только потом положит `u` — то есть `u` ляжет в стек **позже** `v` и при извлечении выйдет **раньше**. Ровно то, что требует топологический порядок.

```java
List<Integer> topologicalSortDFS(int n, List<List<Integer>> adj) {
    boolean[] visited = new boolean[n];
    Deque<Integer> stack = new ArrayDeque<>();

    for (int i = 0; i < n; i++) {
        if (!visited[i]) dfs(i, adj, visited, stack);
    }

    List<Integer> order = new ArrayList<>();
    while (!stack.isEmpty()) order.add(stack.pop());
    return order;
}

void dfs(int u, List<List<Integer>> adj, boolean[] visited, Deque<Integer> stack) {
    visited[u] = true;
    for (int v : adj.get(u))
        if (!visited[v]) dfs(v, adj, visited, stack);
    stack.push(u); // post-order
}
```

**Сложность:** `O(V + E)`. **Подводный камень:** эта версия не ловит циклы сама по себе — на графе с циклом она молча выдаст некорректный порядок. Чтобы обнаруживать циклы, её дополняют трёхцветной схемой из Q20 (GRAY-вершина в процессе = back edge = цикл).


## Q27. (!) Как решить Number of Islands (задача с матрицей)?

Дана сетка (grid) из `1` (земля) и `0` (вода). Нужно сосчитать количество островов — связных областей из `1`, соединённых по горизонтали и вертикали (4-связность).

**Ключевая идея:** сетка — это неявный граф, где соседи клетки — это четыре смежные ячейки. Перебираем клетки; найдя непосещённую землю, увеличиваем счётчик на 1 и запускаем DFS, который «затапливает» (flood fill) весь остров — помечает все связанные клетки `1`, чтобы их не пересчитать. Каждый запуск DFS соответствует ровно одному острову.

```java
int numIslands(char[][] grid) {
    int rows = grid.length, cols = grid[0].length;
    int count = 0;
    for (int r = 0; r < rows; r++) {
        for (int c = 0; c < cols; c++) {
            if (grid[r][c] == '1') {
                count++;
                dfsIsland(grid, r, c);
            }
        }
    }
    return count;
}

void dfsIsland(char[][] grid, int r, int c) {
    if (r < 0 || r >= grid.length || c < 0 || c >= grid[0].length
        || grid[r][c] != '1') return;
    grid[r][c] = '#'; // mark visited
    dfsIsland(grid, r + 1, c);
    dfsIsland(grid, r - 1, c);
    dfsIsland(grid, r, c + 1);
    dfsIsland(grid, r, c - 1);
}
```

**Сложность:** `O(R · C)` — каждую клетку посещаем один раз. **Альтернатива — Union-Find:** объединять соседние клетки земли в множества; удобно в варианте задачи, где землю добавляют динамически и число островов надо пересчитывать после каждого добавления.


## Q28. (!) Как решить Course Schedule (обнаружение цикла в зависимостях)?

Дано число курсов `numCourses` и список пререквизитов `[[a, b], ...]`, означающий «чтобы пройти `a`, сначала нужно пройти `b`» (ребро `b → a`). Вопрос: можно ли пройти все курсы?

**Суть задачи — это проверка DAG.** Пройти все курсы можно тогда и только тогда, когда в графе зависимостей нет цикла (иначе курсы взаимно блокируют друг друга). Применяем алгоритм Кана: если топологическая сортировка уложила все вершины (`taken == numCourses`) — циклов нет, расписание существует.

```java
boolean canFinish(int numCourses, int[][] prerequisites) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
    int[] inDegree = new int[numCourses];

    for (int[] p : prerequisites) {
        adj.get(p[1]).add(p[0]);
        inDegree[p[0]]++;
    }

    Queue<Integer> queue = new ArrayDeque<>();
    for (int i = 0; i < numCourses; i++)
        if (inDegree[i] == 0) queue.offer(i);

    int taken = 0;
    while (!queue.isEmpty()) {
        int u = queue.poll();
        taken++;
        for (int v : adj.get(u)) {
            if (--inDegree[v] == 0) queue.offer(v);
        }
    }
    return taken == numCourses;
}
```

**Связь с теорией:** «можно завершить» = «существует топологический порядок» = «граф ацикличен». **Сложность:** `O(V + E)`. Вариант Course Schedule II просит вернуть сам порядок прохождения — для этого достаточно отдать накопленный список вместо счётчика.


## Q29. Как решить Word Ladder (кратчайшая трансформация слов)?

Нужно превратить `beginWord` в `endWord`, меняя за шаг ровно одну букву, причём каждое промежуточное слово обязано быть в словаре. Найти минимальное число шагов.

**Почему BFS.** Это замаскированная задача о кратчайшем пути в невзвешенном графе: вершины — слова, ребро между двумя словами есть, если они отличаются на одну букву. Все «рёбра» равноценны (1 шаг = 1 буква), поэтому кратчайший путь даёт именно BFS (см. Q8). Соседей слова не хранят заранее, а генерируют на лету: перебирают каждую позицию и подставляют все 26 букв, проверяя получившееся слово по словарю. Удалять найденное слово из словаря (`dict.remove`) — это и есть пометка «посещено», она же не даёт зациклиться.

```java
int ladderLength(String begin, String end, List<String> wordList) {
    Set<String> dict = new HashSet<>(wordList);
    if (!dict.contains(end)) return 0;

    Queue<String> queue = new ArrayDeque<>();
    queue.offer(begin);
    int level = 1;

    while (!queue.isEmpty()) {
        int size = queue.size();
        for (int i = 0; i < size; i++) {
            String word = queue.poll();
            if (word.equals(end)) return level;
            for (int j = 0; j < word.length(); j++) {
                char[] arr = word.toCharArray();
                for (char c = 'a'; c <= 'z'; c++) {
                    arr[j] = c;
                    String next = new String(arr);
                    if (dict.contains(next)) {
                        queue.offer(next);
                        dict.remove(next); // mark visited
                    }
                }
            }
        }
        level++;
    }
    return 0;
}
```

**Сложность:** `O(N · L · 26)`, где N — число слов, L — длина слова (на каждое слово перебираем L позиций × 26 букв). **Оптимизация:** двунаправленный BFS из Q9 заметно ускоряет, ведя поиск с обоих концов навстречу.


## Q30. Как решить Network Delay Time (задача на Dijkstra)?

Дан список рёбер `times = [[u, v, w], ...]` (сигнал идёт из `u` в `v` за `w` времени) и `n` узлов. Найти время, за которое сигнал из узла `k` достигнет **всех** узлов.

**Почему Dijkstra.** Веса (задержки) положительны, источник один — классический случай для Dijkstra (Q10). Считаем кратчайшее время до каждого узла. Сигнал дойдёт до всех ровно тогда, когда дойдёт до самого дальнего, поэтому ответ — **максимум** среди всех расстояний `dist[i]`. Если хоть один узел остался недостижим (`dist[i] == MAX_VALUE`), возвращаем `-1` — сеть не покрывается из `k`.

```java
int networkDelayTime(int[][] times, int n, int k) {
    List<List<int[]>> adj = new ArrayList<>();
    for (int i = 0; i <= n; i++) adj.add(new ArrayList<>());
    for (int[] t : times) adj.get(t[0]).add(new int[]{t[1], t[2]});

    int[] dist = new int[n + 1];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[k] = 0;

    PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[0]));
    pq.offer(new int[]{0, k});

    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];
        if (d > dist[u]) continue;
        for (int[] e : adj.get(u)) {
            int v = e[0], w = e[1];
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.offer(new int[]{dist[v], v});
            }
        }
    }

    int max = 0;
    for (int i = 1; i <= n; i++) {
        if (dist[i] == Integer.MAX_VALUE) return -1;
        max = Math.max(max, dist[i]);
    }
    return max;
}
```

Это прямое применение Dijkstra без модификаций; вся «задачность» — в правильной интерпретации ответа как максимума расстояний (последний достигнутый узел) с проверкой на недостижимость.


## Q31. (!) Как решить Clone Graph (глубокое копирование графа)?

Нужно построить глубокую копию графа: новые объекты-вершины с теми же значениями и той же структурой рёбер, не ссылающиеся на оригинал.

**Главная трудность — циклы и общие соседи.** В графе вершина A может ссылаться на B, а B обратно на A; наивный рекурсивный обход уйдёт в бесконечный цикл и наплодит дубликаты. Решение — `Map<оригинал, копия>`: перед тем как клонировать соседей вершины, кладём её копию в map. Если вершина уже встречалась, возвращаем готовую копию из map вместо повторного клонирования. Это и обрывает рекурсию на циклах, и гарантирует, что каждая вершина оригинала клонируется ровно один раз.

```java
class Node { int val; List<Node> neighbors; }

Node cloneGraph(Node node) {
    if (node == null) return null;
    Map<Node, Node> visited = new HashMap<>();
    return dfs(node, visited);
}

Node dfs(Node node, Map<Node, Node> visited) {
    if (visited.containsKey(node)) return visited.get(node);
    Node copy = new Node();
    copy.val = node.val;
    copy.neighbors = new ArrayList<>();
    visited.put(node, copy);
    for (Node n : node.neighbors) {
        copy.neighbors.add(dfs(n, visited));
    }
    return copy;
}
```

**Сложность:** `O(V + E)` — проходим каждую вершину и каждое ребро по разу. HashMap здесь несёт двойную нагрузку: и кэш «оригинал → копия», и множество «уже посещённых».

## Q33. Что такое graph database и когда её выбирать?

**Graph database** — это БД, где узлы и рёбра являются объектами первого класса, а движок оптимизирован под обход связей (traversal). Примеры: **Neo4j**, ArangoDB, Amazon Neptune, JanusGraph.

**В чём выигрыш перед реляционной БД.** «Друзья друзей друзей» в SQL — это три самосоединения (self-join) таблицы связей, и стоимость растёт с глубиной экспоненциально. В графовой БД переход по ребру — это следование по указателю, поэтому глубокие обходы дешёвы и почти не зависят от размера всей базы. Именно поэтому выбор сводится к вопросу «насколько связи между данными важнее самих данных».

**Когда выбирать:**
- Запросы с **множественными переходами по связям** (соцсети — «друзья друзей друзей»)
- Графы знаний и онтологии
- Антифрод — поиск подозрительных паттернов связей
- Рекомендательные движки
- Анализ сетевой топологии

**Когда НЕ выбирать:**
- Простые CRUD-операции — реляционная БД проще и привычнее
- Аналитика по агрегатам — выгоднее column store (ClickHouse)

**Языки запросов:** **Cypher** (Neo4j), Gremlin, SPARQL.


## Q34. (!) Как работает PageRank?

**PageRank** (Пейдж и Брин, 1998) оценивает важность веб-страницы по входящим ссылкам. Базовая интуиция: страница важна, если на неё ссылаются другие важные страницы. Определение рекурсивно (важность зависит от важности соседей), поэтому считается итеративно до сходимости.

**Модель «случайного сёрфера».** Представим пользователя, который с вероятностью `d` (демпфирующий фактор, обычно 0.85) переходит по случайной ссылке текущей страницы, а с вероятностью `1−d` телепортируется на случайную страницу. PageRank страницы — это доля времени, которую такой сёрфер на ней проводит. Слагаемое `1−d` решает две проблемы: спасает от «тупиков» (страниц без исходящих ссылок) и гарантирует сходимость.

```
PR(p) = (1-d)/N + d · Σ (PR(q) / L(q))   для q → p
```

Итеративный алгоритм:
1. Инициализировать PR всех страниц = 1/N
2. Обновлять PR по формуле
3. Повторять до сходимости

```java
double[] pageRank(int n, List<List<Integer>> adj, int iterations) {
    double[] pr = new double[n];
    Arrays.fill(pr, 1.0 / n);
    double damp = 0.85;

    for (int iter = 0; iter < iterations; iter++) {
        double[] next = new double[n];
        for (int u = 0; u < n; u++) {
            int outDegree = adj.get(u).size();
            if (outDegree == 0) continue;
            double share = damp * pr[u] / outDegree;
            for (int v : adj.get(u)) next[v] += share;
        }
        for (int i = 0; i < n; i++) next[i] += (1 - damp) / n;
        pr = next;
    }
    return pr;
}
```

**Где применяют:** ранжирование в поиске Google (исходная задача), сети цитирования научных статей, выявление влиятельных узлов в соцсетях.
