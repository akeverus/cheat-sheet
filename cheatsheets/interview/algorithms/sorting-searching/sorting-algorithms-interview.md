## Q1. (!) Какие свойства характеризуют алгоритм сортировки?

Алгоритм сортировки описывается не одной только асимптотикой: на собеседовании ждут, что вы назовёте несколько независимых характеристик и поймёте, какая из них важна в конкретной задаче.

- **Сложность** — время в лучшем, среднем и худшем случае плюс расход памяти. Самый базовый критерий, но не единственный.
- **Stable (стабильность)** — сохраняет относительный порядок равных элементов. Критично при многоэтапной сортировке.
- **In-place** — использует не больше `O(1)`–`O(log n)` дополнительной памяти помимо входного массива.
- **Adaptive (адаптивность)** — работает быстрее на уже частично отсортированных данных.
- **Online** — может сортировать поток: принимает элементы по одному, не зная заранее весь вход.
- **Comparison-based vs non-comparison-based** — сравнивает элементы попарно либо использует их структуру (цифры, ключи) напрямую. От этого зависит, упирается ли алгоритм в нижнюю границу `O(n log n)`.
- **External** — умеет сортировать данные, которые не помещаются в оперативную память, обращаясь к диску.

**Рекомендация:** при выборе алгоритма сначала спросите себя, какие из этих свойств для задачи обязательны (стабильность? ограничение по памяти? поток?), а уже потом смотрите на асимптотику.

## Q2. (!) Чем stable отличается от unstable сортировки?

**Stable-сортировка сохраняет исходный относительный порядок элементов, которые равны по ключу сортировки.** Unstable такой гарантии не даёт — равные элементы могут поменяться местами.

В примере ниже сортируем людей по возрасту. Alice и Carol обе имеют возраст 30, и во входе Alice идёт раньше:

```
Вход:  (Alice, 30), (Bob, 25), (Carol, 30)   — сортируем по возрасту
Stable:   (Bob, 25), (Alice, 30), (Carol, 30)   — Alice раньше Carol
Unstable: (Bob, 25), (Carol, 30), (Alice, 30)   — порядок может поменяться
```

- **Stable:** Insertion, Merge, Tim, Bubble, Counting (при корректной реализации).
- **Unstable:** Quick, Heap, Selection (наивная), Shell.

**Зачем это нужно.** Стабильность позволяет сортировать по нескольким критериям последовательно. Отсортировали список сначала по фамилии, затем стабильно — по возрасту: внутри каждого возраста фамилии остаются в алфавитном порядке от первого прохода. С unstable-сортировкой результат первого прохода был бы потерян.

**Подводный камень:** для примитивов стабильность бессмысленна (два равных `int` неотличимы), поэтому Java спокойно использует для них unstable Quick Sort. А вот для объектов с несколькими полями стабильность важна — там применяется TimSort.

## Q3. (!) Что такое in-place сортировка?

**In-place — это сортировка, которая обходится `O(1)` или `O(log n)` дополнительной памяти помимо самого входного массива.** Она переставляет элементы прямо на месте, а не строит копию.

`O(log n)` тоже считается in-place, потому что эта память уходит на стек рекурсии (как у Quick Sort), а не на дублирование данных.

| Алгоритм | In-place |
|----------|----------|
| Bubble, Selection, Insertion | Да (`O(1)`) |
| Quick Sort | Да (`O(log n)` стек) |
| Heap Sort | Да (`O(1)`) |
| Merge Sort | **Нет** (`O(n)`) |
| Counting Sort | Нет (`O(k)`) |
| Radix Sort | Нет |
| Tim Sort | **Нет** (`O(n)`) |

**Когда это важно:** при работе с очень большими массивами или в средах с жёстким лимитом памяти лишний `O(n)`-буфер может просто не поместиться. Тогда in-place-алгоритм (Quick, Heap) — единственный вариант, даже если он в чём-то уступает Merge Sort.

**Как читать таблицу.** Comparison-based алгоритмы (верхние семь) упираются в `O(n log n)` — это нижняя граница для сортировки сравнениями. Non-comparison (Counting, Radix, Bucket) выходят за неё и достигают линейного времени, но платят за это ограничениями: работают только с целыми/ключами в известном диапазоне и тратят дополнительную память. Quick — единственный в группе `O(n log n)`, у кого есть деградация до `O(n²)`; зато он in-place и на практике обычно самый быстрый.

## Q5. Как работает Bubble Sort?

**Bubble Sort несколько раз проходит по массиву, сравнивая соседние элементы и меняя их местами, если они стоят в неправильном порядке.** За один проход самый большой элемент «всплывает» в конец, поэтому каждый следующий проход короче. Сортировка завершается, как только проход прошёл без единого обмена.

```java
void bubbleSort(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                int tmp = arr[j]; arr[j] = arr[j+1]; arr[j+1] = tmp;
                swapped = true;
            }
        }
        if (!swapped) break; // оптимизация: уже отсортировано
    }
}
```

Флаг `swapped` даёт ранний выход: если за проход не было ни одного обмена, массив уже отсортирован — отсюда лучший случай `O(n)`. Среднее и худшее — `O(n²)`.

**Где применять:** на практике почти нигде. Insertion Sort делает то же самое, но быстрее на тех же данных (меньше обменов), поэтому Bubble Sort держат в голове ради понимания принципа, а не для реального кода.

## Q6. Как работает Selection Sort?

**Selection Sort на каждом шаге находит минимум в неотсортированной части массива и ставит его на текущую позицию.** Граница между отсортированной (слева) и неотсортированной (справа) частями сдвигается вправо на один элемент за итерацию.

```java
void selectionSort(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        int minIdx = i;
        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[minIdx]) minIdx = j;
        }
        if (minIdx != i) {
            int tmp = arr[i]; arr[i] = arr[minIdx]; arr[minIdx] = tmp;
        }
    }
}
```

`O(n²)` всегда — даже на отсортированном массиве алгоритм всё равно ищет минимум во всём остатке, поэтому он не adaptive.

**Главное преимущество — минимальное число обменов: ровно `O(n)`** (не больше одного swap за итерацию). Это ценно, когда сам обмен дорогой: например, элементы — это крупные записи (large records) и каждое перемещение копирует много байт. Selection Sort переставляет элементы реже всех остальных `O(n²)`-алгоритмов.

**Подводный камень:** наивная реализация **unstable** — обмен может «перепрыгнуть» через равный элемент и нарушить их исходный порядок.

## Q7. (!) Как работает Insertion Sort?

**Insertion Sort строит отсортированный массив по одному элементу: берёт очередной элемент и вставляет его на правильное место в уже отсортированную левую часть, сдвигая большие элементы вправо.** Так работают, когда разбирают карты в руке.

```java
void insertionSort(int[] arr) {
    for (int i = 1; i < arr.length; i++) {
        int key = arr[i];
        int j = i - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }
        arr[j + 1] = key;
    }
}
```

`O(n²)` в среднем, но **`O(n)` на уже отсортированном массиве** — внутренний цикл `while` сразу останавливается. Stable, in-place и **adaptive** (тем быстрее, чем ближе вход к отсортированному). Именно это сочетание делает Insertion Sort самой полезной из `O(n²)`-сортировок.

**Где применять:**
- Малые массивы (< ~50 элементов) — за счёт маленьких констант обгоняет `O(n log n)`-алгоритмы, у которых выше накладные расходы.
- Почти отсортированные данные — приближается к `O(n)`.
- **Внутри TimSort** — им сортируются короткие runs.
- Online-сценарий — элементы можно вставлять по одному прямо в процессе поступления.

## Q8. (!) Как работает Merge Sort?

**Merge Sort — классический алгоритм «разделяй и властвуй» (divide and conquer): массив делится пополам, каждая половина рекурсивно сортируется, затем две отсортированные половины сливаются в одну.** Вся работа происходит на этапе слияния (`merge`), а само разбиение тривиально.

```java
void mergeSort(int[] arr, int left, int right) {
    if (left >= right) return;
    int mid = left + (right - left) / 2;
    mergeSort(arr, left, mid);
    mergeSort(arr, mid + 1, right);
    merge(arr, left, mid, right);
}

void merge(int[] arr, int left, int mid, int right) {
    int[] tmp = new int[right - left + 1];
    int i = left, j = mid + 1, k = 0;
    while (i <= mid && j <= right) {
        if (arr[i] <= arr[j]) tmp[k++] = arr[i++]; // <= для stability
        else                   tmp[k++] = arr[j++];
    }
    while (i <= mid) tmp[k++] = arr[i++];
    while (j <= right) tmp[k++] = arr[j++];
    System.arraycopy(tmp, 0, arr, left, tmp.length);
}
```

`O(n log n)` гарантированно во всех случаях — деградации в `O(n²)`, в отличие от Quick Sort, нет. Stable (условие `<=` в merge удерживает равные элементы в исходном порядке), но **не in-place**: на слияние нужен буфер `O(n)`.

**Где применять:**
- **Связные списки** — слияние работает через указатели, random access не нужен (а Quick Sort на списке неэффективен).
- **Внешняя сортировка** на диске — слияние читается последовательными потоками, что идеально для I/O.
- **Параллельная сортировка** — независимые половины легко считать на разных ядрах.

## Q9. (!) Как работает Quick Sort?

**Quick Sort выбирает опорный элемент (pivot), выполняет partition — переставляет элементы так, что слева оказываются меньшие, справа большие, — и затем рекурсивно сортирует обе части.** После partition pivot стоит на своей финальной позиции, поэтому его уже не трогают.

```java
void quickSort(int[] arr, int left, int right) {
    if (left >= right) return;
    int pivotIdx = partition(arr, left, right);
    quickSort(arr, left, pivotIdx - 1);
    quickSort(arr, pivotIdx + 1, right);
}

int partition(int[] arr, int left, int right) {
    int pivot = arr[right]; // последний как pivot
    int i = left - 1;
    for (int j = left; j < right; j++) {
        if (arr[j] <= pivot) {
            i++;
            int tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp;
        }
    }
    int tmp = arr[i + 1]; arr[i + 1] = arr[right]; arr[right] = tmp;
    return i + 1;
}
```

`O(n log n)` в среднем, но `O(n²)` в худшем случае — когда pivot всё время оказывается минимумом или максимумом (классический пример: уже отсортированный массив при выборе крайнего элемента в качестве pivot). Тогда одна часть после partition пуста, и глубина рекурсии вырастает до `n`. In-place, **unstable**.

При этом на практике Quick Sort в среднем **в 2–3 раза быстрее Merge Sort**: он работает прямо в массиве (in-place, без буфера) и обращается к памяти последовательно, что даёт отличную cache locality. Именно поэтому он — стандартный выбор для сортировки примитивов.

## Q10. (!) Какие есть оптимизации Quick Sort?

Базовый Quick Sort уязвим к худшему случаю и пробуксовывает на дубликатах. Реальные реализации лечат это набором приёмов:

1. **Random pivot** — случайный выбор опорного элемента. Делает вероятность худшего случая ничтожной даже на отсортированном входе, на который наивный pivot реагирует как раз `O(n²)`.
2. **Median-of-three** — pivot = медиана из первого, среднего и последнего элементов. Дешёвая эвристика, дающая обычно более сбалансированный partition.
3. **3-way partition (Dutch flag)** — делит массив на три зоны `<`, `=`, `>`. На данных с большим числом дубликатов резко ускоряет: все равные pivot элементы выпадают из дальнейшей рекурсии.
4. **Переход на Insertion Sort для малых подмассивов** — на коротких отрезках накладные расходы рекурсии не окупаются, и простой Insertion быстрее.
5. **Хвостовая рекурсия** — рекурсивно обрабатываем только меньшую половину, а большую проходим итеративно. Это гарантирует глубину стека `O(log n)` и защищает от переполнения.
6. **Dual-Pivot Quicksort** — два опорных элемента делят массив сразу на три части; на практике обычно быстрее одинарного pivot (используется в Java для примитивов).

## Q11. (!) Как работает Heap Sort?

**Heap Sort превращает массив в max-heap (двоичную кучу, где родитель не меньше потомков), а затем многократно забирает максимум из корня и кладёт его в конец массива.** После каждого извлечения куча уменьшается на один элемент и восстанавливается через `siftDown`. В итоге максимумы накапливаются справа — массив отсортирован по возрастанию.

```java
void heapSort(int[] arr) {
    int n = arr.length;
    // 1. Build max-heap — O(n)
    for (int i = n / 2 - 1; i >= 0; i--) siftDown(arr, n, i);
    // 2. Extract elements — O(n log n)
    for (int i = n - 1; i > 0; i--) {
        int tmp = arr[0]; arr[0] = arr[i]; arr[i] = tmp;
        siftDown(arr, i, 0);
    }
}

void siftDown(int[] arr, int size, int i) {
    while (true) {
        int l = 2*i+1, r = 2*i+2, largest = i;
        if (l < size && arr[l] > arr[largest]) largest = l;
        if (r < size && arr[r] > arr[largest]) largest = r;
        if (largest == i) break;
        int tmp = arr[i]; arr[i] = arr[largest]; arr[largest] = tmp;
        i = largest;
    }
}
```

`O(n log n)` гарантированно во всех случаях — это и есть главное преимущество перед Quick Sort, который может скатиться в `O(n²)`. К тому же in-place (`O(1)` памяти). Минусы: **unstable** и на практике медленнее Quick Sort, потому что `siftDown` прыгает по дереву кучи и постоянно промахивается мимо кэша (плохая cache locality).

**Где применять:** именно из-за гарантии worst-case Heap Sort служит «страховкой» внутри **Introsort** — когда Quick Sort уходит в слишком глубокую рекурсию, происходит переключение на Heap Sort.

Подробнее — в [Кучи](../data-structures/heaps-interview.md).

## Q12. (!) Что такое TimSort и почему его выбрали в Java?

**TimSort (Tim Peters, 2002) — это гибрид Merge Sort и Insertion Sort, заточенный под реальные данные.** Реальные массивы редко бывают случайными — в них почти всегда есть уже упорядоченные куски. TimSort находит такие готовые отсортированные подпоследовательности (**runs** — возрастающие или убывающие участки) и сливает их вместо того, чтобы сортировать всё с нуля. Короткие runs он достраивает Insertion Sort.

Именно из-за умения использовать существующий порядок TimSort стал стандартом во множестве платформ:
- Java `Arrays.sort()` для **объектов** (начиная с Java 7).
- Java `Collections.sort()`, `Stream.sorted()`.
- Python `sorted()`, `list.sort()`.
- Android, движок V8 в JavaScript.

**Сложность:**
- Лучший случай: `O(n)` (вход уже отсортирован — это один большой run).
- Средний и худший: `O(n log n)`.
- Память: `O(n)`.
- Stable: да.

**Почему выбрали именно его:**
- **Adaptive** — на реальных данных с упорядоченными участками заметно быстрее «честного» Merge Sort.
- **Stable** — сохраняет порядок при многоэтапной сортировке объектов по нескольким полям.
- **Гарантия `O(n log n)`** в худшем случае — нет деградации, как у Quick Sort.

## Q13. Что такое Introsort и где он применяется?

**Introsort (Musser, 1997) — гибрид Quick Sort, Heap Sort и Insertion Sort, который берёт скорость Quick Sort, но страхуется от его худшего случая.** Идея: использовать быстрый Quick Sort, но как только он начинает деградировать, переключаться на Heap Sort с гарантией `O(n log n)`.

- Начинает с **Quick Sort** — самого быстрого в среднем.
- Если глубина рекурсии превысила `2 · log n` (признак, что pivot-ы выбираются плохо и дело идёт к `O(n²)`) — переключается на **Heap Sort**.
- Малые подмассивы досортировывает **Insertion Sort** — на коротких отрезках он эффективнее.

**Где применяется:**
- C++ STL `std::sort` (GCC libstdc++).
- .NET `Array.Sort()`.

**Сложность:** гарантированно `O(n log n)` в худшем случае — ровно благодаря fallback на Heap Sort.

## Q14. (!) Почему сравнительные сортировки не быстрее O(n log n)?

**Это фундаментальная нижняя граница: любая сортировка, опирающаяся только на попарные сравнения элементов, в худшем случае делает как минимум `Θ(n log n)` сравнений.** Доказывается через аргумент дерева решений (decision tree):

- Любой алгоритм на сравнениях можно представить **бинарным деревом решений**: каждый внутренний узел — это одно сравнение «a < b?», а ветвление — два возможных исхода.
- Чтобы алгоритм был корректен, каждая из `n!` возможных перестановок входа должна приводить к своему листу. Значит, листьев минимум `n!`.
- Высота дерева равна числу сравнений в худшем случае. У бинарного дерева с `n!` листьями высота не меньше `log₂(n!)`.

По формуле Стирлинга `log(n!) = Θ(n log n)`. Отсюда и берётся граница: **никакая** сортировка сравнениями не может стабильно работать быстрее `O(n log n)`.

**Как её обойти.** Non-comparison-сортировки (Counting, Radix, Bucket) вообще не сравнивают элементы попарно — они используют значения как индексы или раскладывают по цифрам. Поэтому достигают `O(n)`, но ценой ограничений: работают только с целыми/ключами в известном диапазоне.

## Q15. (!) Как работает Counting Sort?

**Counting Sort не сравнивает элементы, а подсчитывает, сколько раз встречается каждое значение, и по этим счётчикам раскладывает элементы по местам.** Поэтому он работает за линейное `O(n + k)` время, где `k` — размер диапазона значений, но подходит только для целых чисел в небольшом диапазоне.

```java
void countingSort(int[] arr) {
    int min = Arrays.stream(arr).min().getAsInt();
    int max = Arrays.stream(arr).max().getAsInt();
    int range = max - min + 1;

    int[] count = new int[range];
    for (int x : arr) count[x - min]++;

    // Cumulative count для stability
    for (int i = 1; i < range; i++) count[i] += count[i - 1];

    int[] output = new int[arr.length];
    for (int i = arr.length - 1; i >= 0; i--) {
        output[count[arr[i] - min] - 1] = arr[i];
        count[arr[i] - min]--;
    }
    System.arraycopy(output, 0, arr, 0, arr.length);
}
```

Накопительная сумма (`count[i] += count[i - 1]`) превращает счётчики в позиции, а обратный проход по входу (`for i = n-1 .. 0`) укладывает равные элементы в исходном порядке — отсюда **стабильность**. Время `O(n + k)`, память `O(n + k)`. Работает **только** для целых чисел в ограниченном диапазоне.

- **Сценарий применения:** когда диапазон сопоставим с числом элементов, то есть `k = O(n)` — например, оценки 0–100 или частоты с ограниченным ключом. Тогда Counting Sort обгоняет любой `O(n log n)`.
- **Подводный камень:** разреженные большие диапазоны. Для `int` от 0 до `10⁹` массив счётчиков `count` потребует терабайты памяти, даже если самих элементов мало.

## Q16. (!) Как работает Radix Sort?

**Radix Sort сортирует числа поразрядно: проходит по цифрам от младшей к старшей (LSD) или наоборот (MSD) и на каждом разряде применяет стабильный Counting Sort.** Поскольку Counting Sort стабилен, порядок, установленный на предыдущих (младших) разрядах, сохраняется — и после прохода по всем цифрам массив полностью отсортирован.

```java
void radixSort(int[] arr) {
    int max = Arrays.stream(arr).max().getAsInt();
    for (int exp = 1; max / exp > 0; exp *= 10) {
        countingSortByDigit(arr, exp);
    }
}

void countingSortByDigit(int[] arr, int exp) {
    int n = arr.length;
    int[] output = new int[n];
    int[] count = new int[10];

    for (int x : arr) count[(x / exp) % 10]++;
    for (int i = 1; i < 10; i++) count[i] += count[i - 1];

    for (int i = n - 1; i >= 0; i--) {
        int digit = (arr[i] / exp) % 10;
        output[count[digit] - 1] = arr[i];
        count[digit]--;
    }
    System.arraycopy(output, 0, arr, 0, n);
}
```

`O(d · (n + k))`, что сводится к `O(n)`, когда число разрядов `d` ограничено константой (а основание `k` мало, обычно 10). Stable.

**Сценарий применения:** ключи фиксированной длины, которые удобно резать на разряды — строки фиксированной длины, IPv4-адреса, даты.

## Q17. Как работает Bucket Sort?

**Bucket Sort распределяет элементы по `k` корзинам (bucket) в зависимости от их величины, сортирует каждую корзину по отдельности (обычно Insertion Sort) и затем считывает корзины по порядку.** Если входные данные распределены равномерно, в каждой корзине оказывается мало элементов — и сортировка корзин дёшева.

```java
void bucketSort(double[] arr) {
    int n = arr.length;
    List<List<Double>> buckets = new ArrayList<>();
    for (int i = 0; i < n; i++) buckets.add(new ArrayList<>());

    for (double x : arr) {
        int idx = (int)(x * n); // assume 0 <= x < 1
        buckets.get(idx).add(x);
    }

    for (List<Double> b : buckets) Collections.sort(b);

    int k = 0;
    for (List<Double> b : buckets)
        for (double x : b) arr[k++] = x;
}
```

`O(n + k)` в среднем при равномерном распределении, но `O(n²)` в худшем — если все элементы попадают в одну корзину, всё сводится к одному медленному Insertion Sort. Stable, если стабильна внутренняя сортировка корзин.

**Сценарий применения:** равномерно распределённые вещественные числа в диапазоне `[0, 1)`, где формула индекса `(int)(x * n)` раскидывает их по корзинам поровну.

## Q18. (!) Что внутри Arrays.sort()?

**Java выбирает алгоритм в зависимости от типа: примитивы сортируются Dual-Pivot Quicksort, объекты — TimSort.**

| Тип | Алгоритм |
|-----|----------|
| `int[]`, `long[]`, ... (примитивы) | **Dual-Pivot Quicksort** |
| `Object[]` | **TimSort** |

**Почему именно так:**
- Для примитивов стабильность не имеет смысла — два равных `int` неотличимы, переставить их «не туда» нельзя. Значит, можно взять самый быстрый по среднему времени Quick Sort (in-place, без буфера).
- Для объектов стабильность критична: при сортировке по нескольким ключам (multi-key sort) нужно сохранять порядок предыдущих проходов. Поэтому выбран стабильный TimSort, который к тому же adaptive на реальных данных.

```java
int[] arr = {3, 1, 4, 1, 5};
Arrays.sort(arr); // Dual-Pivot Quicksort

Integer[] objs = {3, 1, 4, 1, 5};
Arrays.sort(objs); // TimSort
```

**Parallel sort** доступен с Java 8: `Arrays.parallelSort(arr)` использует Fork/Join framework и выигрывает на **больших** массивах (> 8K элементов).

## Q19. (!) Чем отличается Arrays.sort и Collections.sort?

**`Arrays.sort` работает с массивом напрямую, а `Collections.sort` под капотом всё равно сводится к `Arrays.sort` — но с лишними копированиями.** Алгоритм при этом ещё зависит от типа данных.

`Collections.sort(list)` делает три шага:
1. `list.toArray()` — копирует список в массив.
2. `Arrays.sort(array)` — сортирует его (объекты → **TimSort**).
3. `ListIterator.set()` — переписывает отсортированные значения обратно в список.

То есть два лишних прохода на копирование туда-обратно. Сам алгоритм сортировки зависит от типа:
- `Arrays.sort(int[])` — Dual-Pivot Quicksort (примитивы).
- `Arrays.sort(Integer[])` — TimSort (объекты).

**Рекомендация:** начиная с Java 8 используйте `List.sort(Comparator)` вместо `Collections.sort` — он сортирует список без промежуточного копирования в массив и обратно.

```java
list.sort(null); // natural ordering (Comparable)
list.sort(Comparator.naturalOrder());
list.sort(Comparator.comparing(User::getName));
```

## Q20. Как устроен parallel sort в Java?

**`Arrays.parallelSort()` распараллеливает сортировку через Fork/Join pool: массив рекурсивно делится на части, части сортируются на разных ядрах, затем сливаются параллельным merge.** Это та же стратегия «разделяй и властвуй», что и у Merge Sort, но ветки рекурсии выполняются одновременно.

```java
int[] arr = new int[1_000_000];
// ... fill ...
Arrays.parallelSort(arr); // на много-ядерных CPU быстрее
```

**Когда выигрывает:**
- Большие массивы — параллелизм включается только выше порога ~8K элементов; меньшие части досортировываются обычной последовательной сортировкой.
- Есть несколько свободных ядер CPU, между которыми можно раскидать работу.
- Доступ к памяти не является узким местом.

**Когда проигрывает:**
- Малые массивы — накладные расходы на разбиение и синхронизацию съедают весь выигрыш.
- Одно ядро или уже перегруженный CPU — параллелить просто негде.

В Stream API аналогичный механизм включается через `parallelStream().sorted()`.

## Q21. (!) Что такое Dutch National Flag (3-way partition)?

**«Голландский флаг» (Dijkstra) — алгоритм, который за один проход и `O(1)` памяти раскладывает массив из трёх различных значений (`0`, `1`, `2`) по группам.** Тремя указателями `low`, `mid`, `high` он поддерживает четыре зоны: уже разложенные нули, единицы, ещё не просмотренные элементы и уже разложенные двойки.

```java
void sortColors(int[] arr) {
    int low = 0, mid = 0, high = arr.length - 1;
    while (mid <= high) {
        if (arr[mid] == 0) {
            int tmp = arr[low]; arr[low++] = arr[mid]; arr[mid++] = tmp;
        } else if (arr[mid] == 1) {
            mid++;
        } else { // == 2
            int tmp = arr[mid]; arr[mid] = arr[high]; arr[high--] = tmp;
        }
    }
}
```

**Сценарий применения:** та же идея лежит в основе **3-way Quick Sort** — деление на `<pivot`, `=pivot`, `>pivot` резко ускоряет сортировку массивов с большим числом дубликатов, потому что все равные pivot элементы сразу выпадают из дальнейшей рекурсии.

## Q22. Как работает внешняя сортировка (external sort)?

**Внешняя сортировка нужна, когда данные не помещаются в оперативную память и приходится сортировать их на диске.** Стандартное решение — external merge sort: разбить данные на куски размером с RAM, отсортировать каждый в памяти, а потом слить отсортированные куски.

**External merge sort по шагам:**
1. Разбиваем входной файл на куски, каждый из которых влезает в RAM.
2. Сортируем каждый кусок целиком в памяти (например, TimSort).
3. Записываем отсортированные куски обратно на диск.
4. **Multi-way merge** — открываем все куски сразу, читаем из них по одному элементу и через PriorityQueue выбираем минимум, сливая всё в один отсортированный поток.

```java
// Псевдокод
void externalSort(File input, File output, long memoryLimit) {
    List<File> chunks = splitAndSortChunks(input, memoryLimit);
    mergeChunks(chunks, output);
}
```

`O(n log n)` сравнений плюс `O(n log n)` дисковых операций. **Сценарий применения:** Hadoop MapReduce, реляционные БД при `ORDER BY` на больших таблицах — везде, где объём данных превышает доступную память.

## Q23. (!) Как отсортировать почти отсортированный массив (k-sorted)?

**Если каждый элемент стоит не дальше `k` позиций от своего финального места (k-sorted массив), его можно отсортировать за `O(n log k)` с помощью min-heap размера `k+1` — заметно быстрее общего `O(n log n)`.**

Идея: минимум всего массива гарантированно лежит среди первых `k+1` элементов. Держим в куче скользящее окно из `k+1` элементов — её корень и есть очередной элемент результата. Извлекли минимум, добавили следующий элемент входа — повторяем.

```java
int[] sortKSorted(int[] arr, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();
    for (int i = 0; i <= k && i < arr.length; i++) heap.offer(arr[i]);

    int[] result = new int[arr.length];
    int idx = 0;
    for (int i = k + 1; i < arr.length; i++) {
        result[idx++] = heap.poll();
        heap.offer(arr[i]);
    }
    while (!heap.isEmpty()) result[idx++] = heap.poll();
    return result;
}
```

`O(n log k)` время, `O(k)` память. Альтернатива — Insertion Sort: он даёт `O(n · k)` и выгоден лишь при совсем маленьком `k`; на больших окнах heap-подход заметно лучше.

## Q24. Чем топологическая сортировка отличается от обычной?

**Обычная сортировка упорядочивает значения по их величине; топологическая упорядочивает вершины DAG так, чтобы каждая зависимость шла раньше зависящего от неё элемента.** Это разные задачи: одна сравнивает значения, другая разрешает порядок по рёбрам графа.

У топологической сортировки нет единственного «правильного» результата — допустимых порядков может быть несколько, лишь бы соблюдались зависимости. **Сценарий применения:** разрешение зависимостей — порядок сборки в build systems, расписание курсов с пререквизитами, инициализация Spring-бинов.

Подробнее — в [Графы](../data-structures/graphs-interview.md).

## Q25. (!) Как сортировать кастомным компаратором?

**Comparator задаёт правило сравнения двух объектов; в Java 8+ его удобно собирать декларативно через `Comparator.comparing` и комбинировать `thenComparing` для нескольких критериев.** Лямбда нужна только когда логика сравнения не сводится к одному полю.

```java
List<User> users = ...;

// Java 8+ — Comparator.comparing
users.sort(Comparator.comparing(User::getName));

// Multiple criteria
users.sort(Comparator.comparing(User::getName)
                     .thenComparingInt(User::getAge)
                     .reversed());

// Compare с null safety
users.sort(Comparator.comparing(User::getName, Comparator.nullsLast(Comparator.naturalOrder())));

// Кастомная логика
users.sort((a, b) -> {
    if (a.isVip() != b.isVip()) return a.isVip() ? -1 : 1;
    return a.getName().compareTo(b.getName());
});
```

**Подводный камень:** компаратор должен быть согласованным — антисимметричным и транзитивным. Если из лямбды можно вернуть несогласованные результаты (например, `a < b`, `b < c`, но `c < a`), TimSort бросит `IllegalArgumentException: Comparison method violates its general contract`.

## Q26. Стабильна ли сортировка с Comparator.thenComparing?

**Да, стабильна — для объектов Java сортирует TimSort, который стабилен по определению.** `thenComparing` лишь добавляет «запасной» критерий: если по первому полю элементы равны, сравнение переходит ко второму; а если равны по всем критериям сразу — TimSort оставляет их в исходном порядке входа.

```java
users.sort(Comparator.comparing(User::getDepartment)
                     .thenComparing(User::getName));
// Сначала по department, внутри department — по name
```

## Q27. Что такое natural ordering?

**Natural ordering (естественный порядок) — это порядок по умолчанию, заданный методом `compareTo()` интерфейса `Comparable`.** Его используют сортировки и структуры, когда им не передали явный Comparator. У встроенных типов он определён заранее:
- `Integer`, `Double` — по возрастанию значения.
- `String` — лексикографический (по кодам символов).
- `LocalDate` — хронологический (раньше — меньше).

```java
class User implements Comparable<User> {
    private String name;

    @Override
    public int compareTo(User other) {
        return this.name.compareTo(other.name);
    }
}

// Используется по умолчанию:
Collections.sort(users); // natural ordering
TreeMap<User, Integer> map = new TreeMap<>(); // ключи по natural ordering
```

**Подводный камень:** если у типа нет `Comparable` и не передан Comparator, `Collections.sort` или `TreeMap` упадут с `ClassCastException` в рантайме. Поэтому для своих классов либо реализуют `Comparable`, либо всегда передают Comparator явно.

Подробнее — в [Java Core](../../programming-languages/java/java-core-interview.md).

## Q28. (!) Когда O(n²) сортировка выиграет у O(n log n)?

Асимптотика описывает поведение на больших `n`, но в реальных задачах часто решают константы и свойства данных. На практике Insertion Sort обгоняет `O(n log n)` в нескольких сценариях:

1. **Малые массивы** (< ~50 элементов) — у Insertion Sort крошечные константы, и накладные расходы Merge/Quick (рекурсия, буфер) не окупаются. Именно поэтому **TimSort** досортировывает короткие runs (< 32–64 элементов) Insertion Sort.
2. **Почти отсортированные данные** — Insertion Sort adaptive и работает за `O(n)`, когда переставлять почти нечего.
3. **Online-сортировка** — элементы поступают по одному, и Insertion вставляет каждый сразу на место, не дожидаясь всего входа.
4. **Жёсткий лимит памяти** — Insertion обходится `O(1)` дополнительной памяти, тогда как Merge требует буфер `O(n)`, который может просто не поместиться.

## Q29. (!) Что такое cache locality в контексте сортировки?

**Cache locality — это насколько последовательно алгоритм обращается к памяти, и от неё напрямую зависит реальная скорость, а не только асимптотика.** CPU читает данные блоками (cache lines, ~64 байта): если следующий нужный элемент уже лежит в загруженной строке кэша, доступ почти бесплатный. Алгоритмы с последовательным доступом редко промахиваются мимо кэша (cache miss) и потому выигрывают на практике.

| Алгоритм | Cache locality |
|----------|----------------|
| Insertion Sort | **Отличная** (последовательный доступ) |
| Merge Sort | Хорошая (последовательно по двум массивам) |
| Quick Sort | **Отличная** (in-place, partition по соседним) |
| Heap Sort | **Плохая** (siftDown прыгает по дереву) |
| Tim Sort | Отличная |

Отсюда важный вывод: **у Heap Sort та же асимптотика `O(n log n)`, что и у Quick Sort, но на практике он в 2–3 раза медленнее** — `siftDown` прыгает по дереву кучи и постоянно промахивается мимо кэша, тогда как Quick Sort обходит память почти линейно.

## Q30. (!) Как защититься от worst-case Quick Sort?

Худший случай `O(n²)` возникает, когда pivot систематически делит массив на пустую и почти полную части. Чтобы этого избежать, применяют несколько техник:

1. **Random pivot** — случайный выбор pivot делает вероятность худшего случая ничтожной: злоумышленный или отсортированный вход больше не «ломает» алгоритм детерминированно.
2. **Median-of-three** — берём медиану из первого, среднего и последнего элементов, что обычно даёт более сбалансированное деление.
3. **Introsort** — отслеживаем глубину рекурсии и при превышении `2 log n` переключаемся на Heap Sort с гарантией `O(n log n)`.
4. **3-way partition** — спасает на массивах с большим числом дубликатов, выводя все равные pivot элементы из рекурсии.
5. **Dual-Pivot** — два опорных элемента делят массив на три части (используется в Java `Arrays.sort` для примитивов).

**Рекомендация:** production-реализации не выбирают что-то одно, а комбинируют эти приёмы — random/median-of-three для среднего случая плюс fallback на Heap Sort для гарантии worst-case.

## Q31. Почему гибридная сортировка почти всегда лучший выбор?

**Гибридная сортировка комбинирует несколько алгоритмов так, чтобы в каждом сценарии работал самый подходящий из них и компенсировались слабости остальных.** У каждого «чистого» алгоритма есть и сильная, и слабая сторона: Quick Sort быстр, но деградирует до `O(n²)`; Merge стабилен, но не in-place; Insertion отличен на коротких данных, но `O(n²)` на больших. Гибрид берёт от каждого только сильную сторону.

- **TimSort:** Merge + Insertion (для коротких runs).
- **Introsort:** Quick + Heap (страховка от worst-case) + Insertion (малые подмассивы).
- **Pdqsort (Pattern-Defeating Quicksort):** Quick + Insertion + 3-way partition + умный выбор pivot.

**Плюсы:**
- В каждом режиме срабатывает лучший случай соответствующего алгоритма.
- Гарантия `O(n log n)` в худшем случае (за счёт fallback на Heap/Merge).
- Adaptive — быстрее на реальных данных с упорядоченными участками.

Поэтому в современном production **«чистый» Quick Sort или Merge Sort не используют почти нигде** — стандартные библиотеки всегда отдают гибрид.
