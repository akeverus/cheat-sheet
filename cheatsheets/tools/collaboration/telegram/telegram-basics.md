# Telegram: основы

Каналы, группы, боты и API для командной коммуникации, алертов и автоматизации.

## Введение

Telegram — мессенджер с акцентом на скорость, шифрование и открытый API. Помимо личной переписки широко используются каналы (односторонняя рассылка), группы и супергруппы (до 200 000 участников), боты для уведомлений, поддержки и автоматизации. Многие команды используют Telegram для алертов из мониторинга и CI/CD, для групповых чатов по проектам и для ботов с тикетами или справкой. Документ охватывает основы каналов, групп, ботов и Bot API в контексте корпоративной и командной работы.

## Каналы и группы

**Канал (Channel)** — односторонняя рассылка: подписчики получают сообщения от имени канала; комментировать можно только в связанной «дискуссии» (группе), если она включена. Подходит для объявлений, новостей, логов деплоев или алертов «только чтение». Создаётся через меню → **New Channel**; можно сделать публичным (ссылкой-приглашением или по имени @channelname) или приватным (приглашение по ссылке). Администраторы канала управляют постами и подписчиками.

**Группа (Group)** и **супергруппа (Supergroup)** — общий чат, где все участники могут писать. В супергруппе доступны история сообщений для новых участников, треды, админ-права (модерация, закрепление, права на удаление). Группы до 200 участников можно «преобразовать» в супергруппу в настройках. Для командной работы обычно создают супергруппу по проекту или команде; для алертов — канал или отдельную группу, куда бот шлёт уведомления.

**Приватность**: в публичных каналах/группах любой может найти их по имени или ссылке. Для внутренних обсуждений используют приватные каналы/группы (приглашение только по ссылке; ссылку можно отзывать).

## Сообщения, треды и форматирование

Сообщения поддерживают **Markdown**-подобное форматирование: жирный (`*текст*` или `**текст**` в **Bot API**), курсив (`_текст_`), моноширинный (`` `код` ``), ссылки. В **Bot API** используется режим **MarkdownV2** или **HTML**; в клиенте — свой синтаксис. Закрепление сообщения (**pin**) — важные объявления остаются вверху чата.

**Треды (Topics)** в супергруппах — подтемы внутри одного чата; сообщения привязываются к топику, что упорядочивает обсуждения в больших группах. Упоминание участника: @username; уведомление всех в группе (если разрешено): @admin или настройки группы.

## Боты: создание и возможности

**Бот** в **Telegram** — аккаунт, управляемый через **Bot API**. Пользователи пишут боту в личку или добавляют его в группы/каналы; бот получает обновления (**updates**) и может отвечать сообщениями, кнопками, инлайн-режимом.

**Создание бота**: в приложении написать [@BotFather](https://t.me/BotFather), отправить `/newbot`, задать имя и username (оканчивается на `bot`). **BotFather** выдаёт **token** вида `123456789:AAH...`. Этот токен используется во всех запросах к **Bot API**; хранить его нужно в секрете (переменные окружения, секретное хранилище).

**Возможности бота**: отправка и приём текста, фото, файлов; клавиатуры (**reply keyboard**, **inline keyboard**); инлайн-режим (результаты по запросу в любом чате); обработка команд (`/start`, `/help` и свои); получение обновлений через **long polling** или **webhook**. В группах бот видит сообщения (если не отключена приватность в **BotFather**) и может реагировать на команды и ключевые слова.

## Bot API: отправка и приём сообщений

**Отправка сообщения** — **HTTP POST** на `https://api.telegram.org/bot<token>/sendMessage` с параметрами `chat_id` и `text`. `chat_id` для лички — числовой **id** пользователя; для группы или канала — отрицательный **id** (например `-1001234567890`). Узнать **chat_id** группы можно: добавить бота в группу и вызвать метод `getUpdates` после отправки сообщения в группу — в обновлении будет `message.chat.id`.

**Приём сообщений** — два подхода. **Long polling**: периодически вызывать `getUpdates` с параметром `offset`; сервер возвращает новые обновления (сообщения, нажатия кнопок, callback-запросы). **Webhook**: указать **URL** через `setWebhook`; **Telegram** будет отправлять **POST** на этот **URL** при каждом обновлении. Webhook требует **HTTPS** и быстрый ответ (в течение короткого таймаута); обработку лучше выполнять асинхронно и отвечать сразу **200 OK**.

**Формат текста**: параметр `parse_mode` — `HTML` или `MarkdownV2`; при **MarkdownV2** спецсимволы нужно экранировать. Для длинных сообщений можно разбивать на несколько или использовать **parse_mode** без разметки.

**Документация методов**: [core.telegram.org/bots/api](https://core.telegram.org/bots/api) — `sendMessage`, `sendPhoto`, `editMessageText`, `getUpdates`, `setWebhook`, `answerCallbackQuery` и др.

## Интеграции: алерты и CI/CD

Типичный сценарий: бот создаётся через **BotFather**; бота добавляют в группу или канал (или пользователи пишут ему в личку). Сервер мониторинга или **CI** при событии (падение сборки, алерт **Prometheus**, деплой) выполняет **HTTP POST** к своему внутреннему сервису; сервис вызывает **Bot API** `sendMessage` с нужным `chat_id` и текстом. Таким образом команда получает уведомления в **Telegram** без установки отдельного клиента для **Slack**/**Mattermost**.

**Реализация**: скрипт на **Python** (**python-telegram-bot**, **aiogram**), **Node.js**, **Go** или любой язык с **HTTP**-клиентом. Хранить **token** и `chat_id` в переменных окружения или в секретном хранилище; не коммитить в репозиторий. Для **CI** (**GitLab CI**, **GitHub Actions**, **Jenkins**) — шаг в пайплайне: вызов скрипта или **curl** к внутреннему сервису, который шлёт сообщение в **Telegram**; либо прямой вызов **Bot API** из пайплайна, если **token** подставлен из секретов.

**Канал только для алертов**: создать канал, добавить бота как администратора с правом публикации; рассылать уведомления в этот канал по `chat_id` канала. Участники подписываются на канал и не засоряют общий чат.

## Примеры сообщений и типы чатов

**Текст с разметкой (HTML):** в **Bot API** при `parse_mode=HTML` поддерживаются теги `<b>`, `<i>`, `<code>`, `<a href="...">`. Пример: «<b>Алерт</b>: сервис payment недоступен. <a href="https://grafana.example/dashboard">Дашборд</a>» — выделение и кликабельная ссылка.

**Типы чатов для бота:** (1) **Личка** — пользователь пишет боту; `chat_id` положительный. (2) **Группа/супергруппа** — бота добавляют в чат; `chat_id` отрицательный (например `-1001234567890`). (3) **Канал** — бот добавлен как админ с правом публикации; `chat_id` вида `-100xxxxxxxxxx`. Для алертов чаще используют канал (односторонняя лента) или отдельную группу, чтобы не мешать общему чату.

**Пример тела для sendMessage (JSON):** `{"chat_id": "-1001234567890", "text": "Деплой v1.2.0 на prod завершён.", "parse_mode": "HTML"}`. Для длинного текста — разбить на несколько сообщений или отправить файл (метод `sendDocument`).

## Интеграция с **Spring Boot**

Отправка сообщений в **Telegram** из приложения выполняется через **Bot API**: **POST** на `https://api.telegram.org/bot<token>/sendMessage` с параметрами `chat_id` и `text`. Достаточно **spring-boot-starter-web** и **WebClient** (или **RestTemplate**).

**Конфигурация (`application.yml`):**

```yaml
telegram:
  bot-token: ${TELEGRAM_BOT_TOKEN}
  chat-id: ${TELEGRAM_CHAT_ID}
```

**Сервис отправки сообщений:**

```java
package com.example.telegram.service;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.MediaType;
import org.springframework.stereotype.Service;
import org.springframework.web.reactive.function.client.WebClient;

import java.util.Map;

@Service
public class TelegramNotificationService {

    private static final String SEND_MESSAGE = "https://api.telegram.org/bot{token}/sendMessage";

    private final WebClient webClient;
    private final String botToken;
    private final String defaultChatId;

    public TelegramNotificationService(
            WebClient.Builder builder,
            @Value("${telegram.bot-token}") String botToken,
            @Value("${telegram.chat-id}") String defaultChatId) {
        this.botToken = botToken;
        this.defaultChatId = defaultChatId;
        this.webClient = builder.build();
    }

    public void sendMessage(String text) {
        sendMessage(defaultChatId, text, null);
    }

    public void sendMessage(String chatId, String text, String parseMode) {
        var body = new java.util.HashMap<String, Object>(Map.of("chat_id", chatId, "text", text));
        if (parseMode != null) {
            body.put("parse_mode", parseMode);
        }
        webClient.post()
                .uri(SEND_MESSAGE, botToken)
                .contentType(MediaType.APPLICATION_JSON)
                .bodyValue(body)
                .retrieve()
                .toBodilessEntity()
                .block();
    }

    public void sendAlert(String level, String service, String message, String link) {
        String text = String.format("<b>%s</b>: %s\n%s%s",
                level, service, message,
                link != null ? "\n<a href=\"" + link + "\">Подробнее</a>" : "");
        sendMessage(defaultChatId, text, "HTML");
    }
}
```

**Токен** и **chat_id** храните в переменных окружения или в секретах; не коммитить в репозиторий. Для приёма обновлений (команды, кнопки) настройте **webhook** или **long polling** и отдельный контроллер/сервис, который обрабатывает входящие **POST** от **Telegram** и отвечает **200 OK** до таймаута.

## Кейсы использования с **n8n**

**n8n** поддерживает узлы **Telegram**: триггер «новое сообщение» или «callback» (нажатие inline-кнопки) и действие «отправить сообщение». Это позволяет связывать **Telegram** с мониторингом, формами, **Jira** и **Slack** без написания кода.

### Кейс 1: Алерт мониторинга → Telegram

- **Триггер:** **Webhook** — система мониторинга (**Prometheus**, **Grafana**, внутренний сервис) при срабатывании алерта вызывает **URL** n8n с телом (сервис, метрика, ссылка на дашборд).
- **Шаг 2:** **Code** или **Set** — сформировать короткий текст для **Telegram** (уровень, сервис, ссылка).
- **Шаг 3:** узел **Telegram** — отправить сообщение в заданный чат/канал (учётные данные **Telegram** в n8n: **Bot Token**).

Итог: алерты приходят в **Telegram** в едином формате; дедупликацию и пороги можно реализовать в n8n.

### Кейс 2: Форма или заявка → Telegram

- **Триггер:** **Webhook** от формы (Google Forms, Typeform, внутренняя форма) или **HTTP Request** из приложения при отправке заявки.
- **Шаг 2:** маппинг полей формы в текст сообщения.
- **Шаг 3:** **Telegram** — отправить в группу поддержки или канал заявок с текстом и при необходимости кнопкой-ссылкой.

Итог: заявки из форм сразу попадают в **Telegram** без ручной пересылки.

### Кейс 3: Команда или сообщение в Telegram → Jira / Slack

- **Триггер:** узел **Telegram** — «новое сообщение» в личке бота или в группе (фильтр по ключевому слову или команде, например `/ticket`).
- **Шаг 2:** разбор текста (название задачи, описание); при необходимости запрос к **Jira** за проектом.
- **Шаг 3:** узел **Jira** — создать задачу (**Create Issue**); получить ключ.
- **Шаг 4:** узел **Telegram** — ответить пользователю: «Создана задача PROJ-789: <ссылка>». Опционально: узел **Slack** или **Mattermost** — продублировать уведомление в канал команды.

Итог: создание тикетов и уведомление команды из **Telegram** через n8n без отдельного бэкенда.

В n8n в учётных данных **Telegram** указывается **Access Token** бота; для отправки в канал нужен **chat_id** канала (указывается в узле **Telegram**).

## Безопасность и конфиденциальность

- **Токен бота** — секрет; утечка позволяет управлять ботом и рассылать сообщения от его имени. Не хранить в коде и не логировать.
- **Чаты**: в группах и каналах участники видят друг друга (в группах — список участников). Для сугубо внутренних обсуждений и данных с ограниченным доступом предпочтительны корпоративные мессенджеры с развёртыванием на своей инфраструктуре (**Mattermost**, **Slack** в корпоративном режиме).
- **Шифрование**: **Telegram** использует **MTProto**; в режиме «Secret Chat» — end-to-end шифрование (доступно только в личке, не в группах/каналах). Для ботов и каналов трафик идёт через серверы **Telegram**; при необходимости соблюдения строгих требований к данным — учитывать политику компании.
- **Ссылки-приглашения**: в приватных группах и каналах ссылку можно отзывать и перевыпускать; не передавать ссылку третьим лицам.

## Лучшие практики

- Отдельный канал или группа для алертов (#alerts, «Alerts»); не смешивать с общим чатом команды.
- Бот для алертов — только отправка; не давать лишних прав в других чатах.
- Хранить token и chat_id в секретах (CI, облако, vault); не коммитить в репозиторий.
- Единые форматы сообщений: краткий текст, ссылка на дашборд/тикет, уровень (info/warning/critical).
- В группах: закреплять правила и ссылки на документацию; использовать треды для обсуждений.
- Критичные решения и итоги встреч дублировать в Confluence/Jira; Telegram — канал коммуникации, а не единственное хранилище знаний.
- При использовании webhook — отвечать 200 OK быстро; тяжёлую обработку выполнять в фоне.
- Ограничивать частоту отправки (батчинг, дедупликация, порог по критичности).
- Для production-ботов использовать HTTPS и проверку входящих запросов (secret в webhook).
- Документировать, какой бот за что отвечает и в какие чаты шлёт уведомления; при смене владельца — обновить токен и доступы.

## Частые вопросы

**Как получить chat_id группы или канала?**  
Добавьте бота в группу/канал и отправьте в чат любое сообщение. Вызовите `getUpdates` (или посмотрите логи webhook): в объекте `message.chat` будет поле `id` — это `chat_id`. Для каналов id обычно вида `-100xxxxxxxxxx`.

**Чем канал отличается от группы?**  
Канал — односторонняя рассылка от имени канала; подписчики только читают (и при включённой дискуссии могут комментировать в привязанной группе). Группа/супергруппа — общий чат, все пишут от своего имени.

**Можно ли отправлять сообщения в Telegram из Jenkins/GitLab CI?**  
Да. Создайте бота, получите token и chat_id чата. В пайплайне добавьте шаг: вызов API (`curl` к `api.telegram.org/bot<token>/sendMessage` с `chat_id` и `text`) или вызов вашего скрипта/сервиса. Token храните в секретах CI.

**Поддерживается ли webhook для ботов?**  
Да. Вызовите `setWebhook` с HTTPS-URL. Telegram будет отправлять POST с телом в JSON (поле `update_id` и объект `message`/`callback_query` и т.д.). Сервер должен отвечать 200 в течение короткого времени; иначе Telegram может повторить запрос.

**Как ограничить спам от бота при массовых алертах?**  
На стороне вашего сервиса: батчинг (собирать события за N секунд и отправлять одним сообщением), дедупликация по ключу алерта, порог по критичности (отправлять только critical или critical + warning), rate limiting по chat_id.

## Глоссарий

| Термин | Описание |
|--------|----------|
| **Channel** | Канал — односторонняя рассылка; подписчики получают посты от имени канала. |
| **Supergroup** | Супергруппа — группа с историей, тредами, расширенными правами (до 200 000 участников). |
| **Bot** | Аккаунт, управляемый через **Bot API**; получает и отправляет сообщения по **token**. |
| **BotFather** | Официальный бот **Telegram** для создания ботов и получения **token**. |
| **Bot API** | HTTP-**API** для управления ботом: отправка сообщений, получение обновлений, webhook. |
| **chat_id** | Идентификатор чата (личка, группа или канал); используется в методах **Bot API**. |
| **Webhook** | Режим получения обновлений: **Telegram** отправляет **POST** на ваш **URL**. |
| **Long polling** | Режим получения обновлений: периодические запросы `getUpdates` с `offset`. |
| **Pin** | Закрепление сообщения вверху чата. |

## Чек-листы

### Создание бота для алертов

- [ ] Написать [@BotFather](https://t.me/BotFather), создать бота (`/newbot`), сохранить token в секретное хранилище.
- [ ] Создать группу или канал для алертов; добавить бота (в канал — как администратора с правом публикации).
- [ ] Получить chat_id (отправить сообщение в чат, вызвать `getUpdates` или посмотреть в логах webhook).
- [ ] Реализовать сервис или скрипт: при событии вызывать `sendMessage` с этим chat_id и token.
- [ ] В CI/мониторинге добавить вызов сервиса или прямой вызов API; token и chat_id — из секретов.

### Настройка группы для команды

- [ ] Создать супергруппу (или преобразовать группу в супергруппу).
- [ ] Задать название и описание; при необходимости включить треды (Topics).
- [ ] Закрепить сообщение с правилами и ссылками (Confluence, Jira).
- [ ] Ограничить кто может приглашать участников (приватная ссылка или права админов).

### Безопасность

- [ ] Token бота не в коде и не в логах; только в переменных окружения или vault.
- [ ] Ссылки на приватные группы/каналы не публиковать; при утечке — отозвать и перевыпустить.
- [ ] При использовании webhook — только HTTPS; при необходимости проверять источник запросов.

## Решение проблем

| Симптом | Возможная причина | Действие |
|--------|-------------------|----------|
| Бот не отвечает | Неверный token или бот не в чате | Проверить token; убедиться, что бот добавлен в группу/канал и имеет право писать. |
| «Unauthorized» при вызове API | Неверный или отозванный token | Перевыпустить token в BotFather (`/token` → выбрать бота); обновить секреты. |
| Webhook не получает обновления | Неверный URL, нет HTTPS, таймаут ответа | Проверить setWebhook; убедиться, что URL доступен по HTTPS и сервер отвечает 200 быстро. |
| Не могу получить chat_id | Бот не добавлен или не было сообщения в чате | Добавить бота в чат; отправить сообщение; вызвать `getUpdates` (или посмотреть логи webhook). |

Для строгих требований к размещению данных и аудиту рассмотрите самохостируемые решения (Mattermost).
