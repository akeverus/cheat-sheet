# Mattermost: основы

Самохостируемый корпоративный мессенджер: каналы, потоки, интеграции, боты и API.

## Введение

Mattermost — открытая платформа для командной коммуникации с возможностью развёртывания на своей инфраструктуре. По функциональности близок к Slack: каналы (публичные и приватные), потоки ответов (threads), входящие вебхуки (Incoming Webhooks), боты, slash-команды, интеграции с GitHub, Jira, Jenkins и др. Подходит командам, которым важны контроль над данными, соответствие требованиям безопасности и отсутствие привязки к облачному провайдеру.

## Развёртывание и варианты

Mattermost поставляется в виде серверного приложения (Mattermost Server), которое можно установить на Linux (Docker, пакеты, бинарник), в Kubernetes (официальный Helm chart) или использовать облачный вариант Mattermost Cloud. Для малых команд достаточно одного сервера; для высокой доступности и масштабирования — кластер с HA-базой данных (PostgreSQL) и при необходимости балансировкой приложения. Реплики и кластеризация описаны в [официальной документации](https://docs.mattermost.com/scale/).

Клиенты: веб-интерфейс, десктоп (Windows, macOS, Linux), мобильные приложения (iOS, Android). Единый сервер и единый аккаунт для всех платформ.


## Команды и каналы

**Team (команда)** в **Mattermost** — верхний уровень изоляции: у каждой команды свои каналы и участники. Пользователь может входить в несколько команд и переключаться между ними.

**Каналы** внутри команды:

- **Публичные** — видны всем участникам команды; любой может присоединиться. Типичные примеры: `town-square` (общий канал по умолчанию), `off-topic`, каналы по проектам (`#project-alpha`, `#dev-backend`).
- **Приватные** — только по приглашению; для чувствительных обсуждений, совещаний, HR.

Именование каналов: строчные буквы, цифры и дефисы (lowercase, без пробелов). Рекомендуется единая схема: префиксы по типу (`#proj-*`, `#team-*`, `#incident-*`) или по продукту/проекту. Описание канала и закреплённое (pinned) сообщение с правилами и ссылками упрощают онбординг новых участников.


## Сообщения и потоки

Сообщения в канале отображаются в хронологическом порядке. **Threads (потоки)** — ответы на конкретное сообщение в отдельной ветке; основная лента канала не засоряется. Для обсуждения задачи или поста лучше отвечать в потоке; уведомления по потокам настраиваются в профиле пользователя (все ответы в потоке или только при упоминании).

**Реакции** (эмодзи на сообщение) используются для быстрого согласия («принято», «сделано») без отдельного ответа. **Закрепление (pin)** — важные сообщения (правила канала, ссылки на документацию) отображаются в блоке «Pinned posts» вверху канала.

Форматирование: **Markdown** (жирный, курсив, списки, код, ссылки). Блоки кода — тройные обратные кавычки с указанием языка для подсветки. Упоминание пользователя: `@username`; упоминание канала: `~channel-name`.


## Упоминания и уведомления

- **@channel** — уведомляет всех участников канала (включая неактивных). Использовать редко: только для важных объявлений.
- **@all** — то же, что **@channel** в контексте канала.
- **@username** — уведомление конкретного пользователя.
- **@here** (если включено в настройках) — уведомление тех, кто в данный момент в сети в канале.

В настройках учётной записи можно задать расписание **Do Not Disturb** (DND), отключить звук для отдельных каналов, настроить ключевые слова для уведомлений и приоритет каналов. Это снижает шум и позволяет не пропускать важные сообщения.


## Интеграции: вебхуки и боты

**Incoming Webhooks** — способ отправлять сообщения в канал из внешних систем без полноценного бота. В настройках канала создаётся **webhook**; вы получаете **URL**. **POST**-запрос с телом в **JSON** (поле `text` и при необходимости `attachments`) публикует сообщение в канал от имени интеграции. Типичное использование: уведомления из **CI/CD** (Jenkins, GitLab CI, GitHub Actions), алерты мониторинга (Prometheus, Grafana), скрипты деплоя.

**Outgoing Webhooks** — на заданное ключевое слово или команду **Mattermost** отправляет **POST** на ваш **URL** с текстом сообщения; ваш сервис может ответить текстом, который будет опубликован в канал. Удобно для простых ботов и интеграций.

**Боты (Bot accounts)** — отдельные учётные записи с типом «Bot». Бот может публиковать сообщения, отвечать в потоках, реагировать на события через **API** и **WebSocket**. Создаётся в **System Console** **Integrations** **Bot Accounts**; для доступа используется **access token**. Боты используются для сложной логики, диалогов и интеграций с **Jira**, **GitHub** и др.


## Slash-команды и плагины

**Slash-команды** — команды вида `/команда [аргументы]`. Встроенные примеры: `/shortcut`, `/invite`, `/leave`, `/mute`. Пользовательские slash-команды настраиваются через **Integrations** **Slash Commands**: при вводе команды **Mattermost** отправляет запрос на указанный **URL**; ответ отображается в канале. Так можно реализовать справку, создание тикетов, запросы к внутренним сервисам.

**Плагины (Plugins)** — расширения на **Go** или **JavaScript** (React), работающие на сервере или в веб-клиенте. Каталог плагинов: [Mattermost Marketplace](https://integrations.mattermost.com/). Примеры: интеграции с **GitHub**, **Jira**, **Jenkins**, кастомные slash-команды и кнопки в сообщениях. Для собственной разработки — [Plugin API](https://developers.mattermost.com/integrate/plugins/).


## API и автоматизация

**REST API** и **WebSocket** позволяют автоматизировать публикацию сообщений, управление каналами и пользователями, чтение истории. Аутентификация: **personal access token** или **OAuth 2.0**. Документация: [api.mattermost.com](https://api.mattermost.com/).

Примеры использования: скрипты для массового создания каналов, экспорт истории, боты с сложной логикой, интеграция с внутренними системами (тикеты, биллинг). Для простых уведомлений достаточно **Incoming Webhook**; для интерактивных сценариев — бот с **API** или плагин.


## Примеры сообщений и вебхуков

**Простое сообщение:** тело **POST** на **Incoming Webhook URL**: `{"text": "Сборка backend прошла успешно."}` — Markdown поддерживается. Для алертов удобно добавить имя интеграции и иконку (настраиваются при создании вебхука в Integrations Incoming Webhooks).

**Сообщение с вложениями (attachments):** цветная полоска слева и поля для заголовка и текста. Пример:

```json
{
  "text": "Деплой v2.1.0 на staging",
  "attachments": [{
    "color": "#32CD32",
    "title": "Staging",
    "text": "Версия: 2.1.0\nОкружение: staging\nВремя: 2026-02-06 14:00 UTC"
  }]
}
```

**Ошибка сборки:** `"color": "#DC143C"` для красного; в `text` указать ссылку на **Jenkins**/**GitLab** и ветку. Имя интеграции, например «Jenkins», задаётся при создании вебхука, чтобы в канале было понятно источник.


## Интеграция с Spring Boot

Отправка уведомлений в **Mattermost** из приложения проще всего реализуется через **Incoming Webhook**: один **POST** на **URL** вебхука с телом в **JSON** (поле `text` и при необходимости `attachments`). Никаких дополнительных зависимостей кроме **spring-boot-starter-web** не требуется.

**Конфигурация (`application.yml`):**

```yaml
mattermost:
  webhook-url: ${MATTERMOST_WEBHOOK_URL}
```

**Сервис отправки сообщений:**

```java
package com.example.mattermost.service;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.MediaType;
import org.springframework.stereotype.Service;
import org.springframework.web.reactive.function.client.WebClient;

import java.util.List;
import java.util.Map;

@Service
public class MattermostNotificationService {

    private final WebClient webClient;
    private final String webhookUrl;

    public MattermostNotificationService(
            WebClient.Builder builder,
            @Value("${mattermost.webhook-url}") String webhookUrl) {
        this.webhookUrl = webhookUrl;
        this.webClient = builder.build();
    }

    public void sendMessage(String text) {
        webClient.post()
                .uri(webhookUrl)
                .contentType(MediaType.APPLICATION_JSON)
                .bodyValue(Map.of("text", text))
                .retrieve()
                .toBodilessEntity()
                .block();
    }

    public void sendMessage(String text, List<Map<String, Object>> attachments) {
        Map<String, Object> body = Map.of(
                "text", text,
                "attachments", attachments);
        webClient.post()
                .uri(webhookUrl)
                .contentType(MediaType.APPLICATION_JSON)
                .bodyValue(body)
                .retrieve()
                .toBodilessEntity()
                .block();
    }

    public void sendDeployAlert(String env, String version, String status) {
        String color = "success".equals(status) ? "#32CD32" : "#DC143C";
        sendMessage("Деплой " + version + " на " + env,
                List.of(Map.of(
                        "color", color,
                        "title", env,
                        "text", "Версия: " + version + "\nСтатус: " + status)));
    }
}
```

**URL** вебхука храните в переменной окружения (MATTERMOST_WEBHOOK_URL) или в секретах, не в коде. Для интерактивных сценариев (ответ на команду, кнопки) используйте **Mattermost REST API** с **Bot token** (см. [API Reference](https://api.mattermost.com/)).


## Кейсы использования с n8n

**n8n** позволяет связывать **Mattermost** с **Jira**, мониторингом и другими системами через визуальные воркфлоу. Узлы **Mattermost** (триггер «новое сообщение», действие «отправить сообщение») и **HTTP Request** (для вызова Incoming Webhook) дают гибкость в сценариях.

### Кейс 1: Новая задача в Jira уведомление в Mattermost

- **Триггер:** **Webhook** от **Jira** (событие «Issue created») или узел **Jira** по расписанию с **JQL** по новым задачам.
- **Шаг 2:** фильтр по проекту/типу при необходимости; форматирование текста (ключ, название, ссылка).
- **Шаг 3:** узел **Mattermost** — отправить сообщение в канал (или HTTP Request на Incoming Webhook URL с телом `{"text": "..."}`).

Итог: в **Mattermost** появляются уведомления о новых задачах без ручной настройки в **Jira**.

### Кейс 2: Алерт мониторинга Mattermost

- **Триггер:** **Webhook** от **Prometheus**/**Grafana**/**Alertmanager** или внутренней системы мониторинга (вызов URL n8n при срабатывании алерта).
- **Шаг 2:** **Code** или **Set** — сформировать краткий текст (сервис, метрика, порог, ссылка на дашборд).
- **Шаг 3:** **Mattermost** (или HTTP Request на вебхук) — отправить в канал `#alerts` с красным attachment при критичном алерте.

Итог: единая точка входа для алертов в **Mattermost** с возможностью доп. логики (дедупликация, эскалация).

### Кейс 3: Сообщение или команда в Mattermost создание задачи в Jira

- **Триггер:** узел **Mattermost** — «новое сообщение» в заданном канале или при вводе slash-команды (если команда настроена на вызов n8n).
- **Шаг 2:** разбор текста (например, первая строка — название задачи); при необходимости запрос к **Jira** за проектом и типом.
- **Шаг 3:** узел **Jira** — создать задачу (Create Issue); взять ключ из ответа.
- **Шаг 4:** **Mattermost** — ответить в канал или в поток: «Создана задача PROJ-456: <ссылка>».

Итог: создание тикетов из **Mattermost** без переключения в **Jira**; подходит для быстрых заявок и внутренних процессов.


## Безопасность и права

- **Роли**: системный администратор, администратор команды, участник. Администратор команды управляет каналами и участниками своей команды; системный администратор — настройками сервера, пользователями, интеграциями.
- **Права на каналы**: кто может создавать публичные/приватные каналы, приглашать в команду, управлять интеграциями — настраивается в **System Console** и на уровне команды.
- **Аудиты и политики**: **Mattermost** поддерживает аудит логов, политики паролей, **SSO** (SAML, OAuth 2.0, LDAP), что важно для корпоративного использования и соответствия требованиям безопасности.
- **Шифрование**: трафик между клиентом и сервером по **TLS**; при необходимости — шифрование данных в покое на уровне БД или диска (настраивается на инфраструктуре).


## Лучшие практики

- Один канал — одна тема или проект; не смешивать общий чат и алерты без необходимости.
- Разворачивать Mattermost за обратным прокси (nginx, Caddy) с TLS; использовать PostgreSQL как единственную рекомендованную БД для production.
- Критичные решения и итоги встреч фиксировать в Confluence или Jira; в Mattermost — ссылки и краткое резюме.
- Использовать потоки для обсуждений, чтобы не засорять канал.
- Единые соглашения по именованию каналов и использованию @channel/@here; закреплять правила в закреплённых сообщениях.
- Для алертов и уведомлений из CI/мониторинга — отдельные каналы (#builds, #alerts); не дублировать одни и те же вебхуки в множество каналов без нужды.
- Регулярно обновлять сервер и плагины; следить за [релизами и security advisories](https://docs.mattermost.com/install/self-managed-changelog.html).
- Архивировать неактивные каналы; ограничивать создание публичных каналов при необходимости.
- Интеграции и боты — с минимальными правами; вебхуки только в нужные каналы; не хранить секреты в открытых каналах и в логах.
- Резервное копирование БД и конфигурации по расписанию; при высокой доступности — тестировать восстановление из бэкапа.


## Частые вопросы

**Чем Mattermost отличается от Slack?**
Mattermost — открытый продукт с возможностью полного самохостинга; данные остаются на вашей инфраструктуре. Функционально близок к Slack (каналы, потоки, вебхуки, боты, slash-команды). Slack — облачный сервис с богатой экосистемой интеграций; Mattermost сильнее там, где нужен контроль и соответствие внутренним требованиям.

**Как отправить сообщение в канал из скрипта?**
Создайте Incoming Webhook в настройках канала и отправляйте POST на выданный URL с телом вида `{"text": "Текст сообщения"}`. Для сложного форматирования используйте поля `attachments` по [документации API](https://docs.mattermost.com/developer/webhook-incoming.html).

**Как создать бота?**
System Console Integrations Bot Accounts Add Bot Account. Скопируйте token и используйте его в заголовке `Authorization: Bearer <token>` при вызовах API. Бот может состоять в командах и каналах, публиковать сообщения и реагировать на события через WebSocket или плагин.

**Поддерживается ли SSO?**
Да: SAML 2.0, OAuth 2.0 (GitLab, Google, Office 365 и др.), LDAP/Active Directory. Настройка в System Console Authentication.

**Как мигрировать с Slack на Mattermost?**
Используйте [официальный инструмент миграции](https://docs.mattermost.com/onboard/migrating-to-mattermost.html) или экспорт из Slack и импорт в Mattermost (каналы, пользователи, сообщения — в зависимости от поддерживаемого формата и версии).


## Глоссарий

| Термин | Описание |
|--------|----------|
| **Team** | Команда — верхний уровень; у команды свои каналы и участники. |
| **Channel** | Канал — публичный или приватный чат внутри команды. |
| **Thread** | Поток — ветка ответов на одно сообщение. |
| **Incoming Webhook** | **URL** для отправки сообщений в канал извне (POST). |
| **Outgoing Webhook** | Интеграция: по ключевому слову **Mattermost** вызывает ваш **URL** и публикует ответ. |
| **Bot Account** | Учётная запись типа «бот» для интеграций и автоматизации. |
| **Slash command** | Команда вида `/команда`; может вызывать внешний **URL** или плагин. |
| **Pin** | Закрепление сообщения вверху канала. |
| **System Console** | Административный веб-интерфейс для настройки сервера. |

### Интеграция с CI/CD

- [ ] Создать Incoming Webhook в канале (#builds, #deploy и т.п.).
- [ ] В Jenkins/GitLab CI/GitHub Actions добавить шаг: POST на URL вебхука с текстом (успех/падение сборки, деплой).
- [ ] Не дублировать одни и те же уведомления в несколько каналов без необходимости.


## Решение проблем

| Симптом | Возможная причина | Действие |
|--------|-------------------|----------|
| Сообщения вебхука не появляются в канале | Неверный URL или отключён вебхук | Проверить URL в настройках канала; убедиться, что вебхук включён. |
| Бот не может писать в канал | Бот не добавлен в канал или нет прав | Добавить бота в канал (/invite @botname или через API). |
| Не приходят уведомления | DND или отключён звук канала | Проверить настройки уведомлений в профиле и для канала. |
| Ошибки при установке плагина | Несовместимая версия или конфликт | Проверить совместимость с версией Mattermost; обновить сервер и плагин. |


## Заключение

Для углублённой настройки и разработки интеграций используйте [официальную документацию](https://docs.mattermost.com/) и [API](https://api.mattermost.com/).
