# Slack: основы

Каналы, сообщения, интеграции и эффективная коммуникация в Slack.

## Введение

Slack — мессенджер для команд: каналы по темам/проектам, прямые сообщения, интеграции с Jira, CI/CD, мониторингом. Понимание каналов, потоков и интеграций помогает не терять контекст и снижать шум.

## Каналы и организация

- **Публичные каналы** — видны всем в workspace (#general, #dev, #project-x).
- **Приватные каналы** — только по приглашению; для чувствительных обсуждений.
- Именование: префиксы по типу (#proj-*, #team-*, #incident-) или по проекту/продукту.
- Описание канала и закреплённое сообщение с правилами и ссылками помогают новым участникам.


## Сообщения и потоки

- **Threads (потоки)** — ответы в ветке сообщения; не засоряют канал. Использовать для обсуждения конкретного поста.
- **@channel** — уведомляет всех в канале; использовать редко (важные объявления).
- **@here** — только активные в данный момент.
- **Закрепление** — важные сообщения (правила канала, ссылки) в верх канала.


## Интеграции

- **Incoming Webhooks** — отправка сообщений из скриптов, CI/CD (успех/падение сборки, деплой).
- **Jira** — уведомления о создании/изменении задач; ссылки на задачи в сообщениях.
- **PagerDuty / Opsgenie** — алерты и инциденты в канал #incidents.
- **Bot** — боты для команд (статус, справка, создание тикетов).

Настройка прав и каналов для ботов: только нужные каналы, без спама.

Incoming Webhook создаётся так: канал → «Настроить канал» → «Интеграции» → Incoming Webhooks → «Добавить в Slack» → выбрать канал → скопировать Webhook URL. URL имеет вид `https://hooks.slack.com/services/T00000000/B00000000/XXXXXXXXXXXXXXXXXXXXXXXX`. Один вебхук привязан к одному каналу; для другого канала создаётся отдельный вебхук.


## Примеры сообщений: алерты и деплой

Чтобы уведомления было легко читать и действовать по ним, полезно придерживаться единого формата.

**Пример удачного сообщения о падении сборки (простой текст):**

```text
🔴 Сборка упала: my-service (branch: main)
Job: https://ci.company.com/job/my-service/123
Коммит: abc123 — fix: login validation
Автор: @dev
```

**Пример с блоками (Block Kit) — для вебхука можно передать JSON с полем `blocks`:** структурированные блоки с заголовком, текстом, кнопкой-ссылкой. Так сообщение выглядит аккуратно и кликабельно. Минимальный payload для вебхука с одним текстовым блоком:

```json
{
  "text": "Резюме для уведомлений (fallback)",
  "blocks": [
    {
      "type": "section",
      "text": {
        "type": "mrkdwn",
        "text": "*Сборка упала:* `my-service` (branch: main)\n<https://ci.company.com/job/123|Открыть Job>"
      }
    }
  ]
}
```

**Пример сообщения о деплое:** указать окружение, версию, ссылку на пайплайн и при необходимости список изменений. Тогда команда сразу видит, что выкатилось и куда смотреть при проблемах.


## Поиск и уведомления

- Поиск по тексту, каналу, человеку, дате; фильтры по типу файла.
- Настройка уведомлений: Do Not Disturb в нерабочее время; ключевые слова для упоминаний; mute малополезных каналов.


## Интеграция с Spring Boot

Отправка сообщений в Slack из Spring Boot через Incoming Webhook сводится к HTTP POST на URL вебхука с телом в JSON. Ниже — минимальная реализация без сторонних библиотек (достаточно `spring-boot-starter-web`).

**Зависимость (`pom.xml`):**

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

**Конфигурация (`application.yml`):**

```yaml
slack:
  webhook-url: ${SLACK_WEBHOOK_URL:https://hooks.slack.com/services/T00/B00/XXX}
  # Опционально: канал для алертов и деплоев
  channel-alerts: "#alerts"
  channel-deploys: "#deploys"
```

**Сервис отправки сообщений:**

```java
package com.example.notify.service;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.MediaType;
import org.springframework.stereotype.Service;
import org.springframework.web.reactive.function.client.WebClient;

import java.util.Map;

@Service
public class SlackNotificationService {

    private final WebClient webClient;
    private final String webhookUrl;

    public SlackNotificationService(
            WebClient.Builder webClientBuilder,
            @Value("${slack.webhook-url}") String webhookUrl) {
        this.webhookUrl = webhookUrl;
        this.webClient = webClientBuilder.build();
    }

    /**
     * Отправка простого текста в канал, привязанному к вебхуку.
     */
    public void sendMessage(String text) {
        sendMessage(Map.of("text", text));
    }

    /**
     * Отправка сообщения с блоками (Block Kit) или кастомным username/icon.
     */
    public void sendMessage(Map<String, Object> payload) {
        webClient.post()
                .uri(webhookUrl)
                .contentType(MediaType.APPLICATION_JSON)
                .bodyValue(payload)
                .retrieve()
                .toBodilessEntity()
                .block();
    }

    /**
     * Пример: уведомление о падении сборки.
     */
    public void sendBuildFailed(String jobName, String branch, String jobUrl, String commitAuthor) {
        String text = String.format(
                "🔴 Сборка упала: %s (branch: %s)\n<%s|Открыть Job>\nАвтор: %s",
                jobName, branch, jobUrl, commitAuthor);
        sendMessage(Map.of(
                "text", text,
                "username", "CI",
                "icon_emoji", ":x:"));
    }
}
```

**Использование из кода (например, обработчик события или планировщик):**

```java
@RestController
@RequestMapping("/api/webhooks")
public class CiWebhookController {

    private final SlackNotificationService slack;

    public CiWebhookController(SlackNotificationService slack) {
        this.slack = slack;
    }

    @PostMapping("/build")
    public void onBuildComplete(@RequestBody BuildEvent event) {
        if ("FAILURE".equals(event.getStatus())) {
            slack.sendBuildFailed(
                    event.getJobName(),
                    event.getBranch(),
                    event.getJobUrl(),
                    event.getAuthor());
        }
    }
}
```

**Важно:** Webhook URL храните в переменной окружения (`SLACK_WEBHOOK_URL`) или в секретном хранилище, не в репозитории. Для разных каналов (алерты, деплой) создайте отдельные вебхуки и отдельные свойства в `application.yml`.


## Кейсы использования с n8n

n8n — open-source платформа для автоматизации рабочих процессов (workflow): триггеры (webhook, расписание, события из приложений) и действия (отправка в Slack, создание задачи в Jira, запрос к API). Узлы (nodes) соединяются в цепочки; данные передаются между шагами. Ниже — типовые сценарии Slack + n8n.

**Что понадобится в n8n:** узел Slack (для отправки сообщений нужны OAuth2 или Access Token приложения Slack; для приёма событий — подписка на события в канале/личке). Либо использовать HTTP Request и отправлять POST на Incoming Webhook URL — тогда не нужен OAuth, только URL.

### Кейс 1: Jira — новая задача → уведомление в Slack

- **Триггер:** Webhook (n8n отдаёт URL; в Jira настраивается Webhook при создании/обновлении задачи) или узел Jira с опросом (менее предпочтительно).
- **Шаг 2:** отфильтровать только нужные проекты/типы (например, Story в проекте MYPROJ).
- **Шаг 3:** узел Slack — отправить сообщение в канал (например, `#jira-new`) с полями: ключ задачи, название, ссылка, исполнитель. Текст можно собрать из `{{ $json.fields.summary }}`, ссылку — `https://company.atlassian.net/browse/{{ $json.key }}`.

Итог: при появлении задачи в Jira команда сразу видит сообщение в Slack с ссылкой на задачу.

### Кейс 2: Внешний webhook (мониторинг) → форматирование → Slack

- **Триггер:** узел Webhook (n8n выдаёт URL; Prometheus Alertmanager или другой мониторинг шлёт POST при алерте).
- **Шаг 2:** Code или Set — привести тело запроса к удобному формату (извлечь имя алерта, severity, аннотации).
- **Шаг 3:** Slack — отправить сообщение в `#alerts` с текстом и при необходимости кнопкой-ссылкой на дашборд.

Итог: алерты из мониторинга приходят в Slack в едином формате без написания кода в системе мониторинга.

### Кейс 3: Сообщение в Slack как триггер → создание задачи в Jira

- **Триггер:** узел Slack — событие «новое сообщение в канале» или «реакция на сообщение» (например, эмодзи 🎫 = «создать тикет»).
- **Шаг 2:** условие: только сообщения с определённой реакцией или из определённого канала.
- **Шаг 3:** узел Jira — создать задачу (Create Issue): проект, тип (Task/Story), summary из текста сообщения, описание со ссылкой на Slack.
- **Шаг 4 (опционально):** Slack — ответить в тред сообщением «Создана задача PROJ-123».

Итог: команда создаёт задачи из Slack реакцией или командой без перехода в Jira.

**Где брать узлы:** в n8n встроены узлы Slack, Jira, Webhook, HTTP Request. Для Incoming Webhook достаточно узла HTTP Request (метод POST, URL вебхука, body — JSON с полем `text` или `blocks`).


## Лучшие практики

- Один канал — одна тема/проект; не смешивать общий чат и алерты.
- Создавать каналы под проекты и инциденты; архивировать неактивные.
- Критичные решения и итоги встреч дублировать в Confluence/Jira, а не только в Slack.
- Не использовать Slack как единственное хранилище знаний; ссылки на документы и задачи.
- Соглашения по использованию @channel и реакций (например, 👍 = принято к сведению).
- Интеграции настраивать централизованно; не дублировать одни и те же алерты в несколько каналов.
- Не обсуждать пароли и секреты в открытых каналах.


## Частые вопросы

**Чем публичный канал отличается от приватного?**
Публичный видят все в workspace; любой может присоединиться. Приватный — только по приглашению; для чувствительных обсуждений.

**Что такое Thread (поток)?**
Ответы в ветке сообщения; не засоряют канал. Уведомления по потоку настраиваются отдельно.

**Когда использовать @channel и @here?**
@channel — все в канале (включая неактивных). @here — только те, кто в сети. Использовать редко; в остальных случаях — потоки или личные сообщения.

**Как закрепить сообщение?**
Навести на сообщение → «…» → Pin to channel.

**Что такое Incoming Webhook?**
URL для отправки сообщений в канал из скриптов, CI/CD, мониторинга. Настраивается в Integrations канала.

**Как интегрировать Slack с Jira?**
Установить приложение Jira для Slack из Slack App Directory. Подключить workspace Jira; выбрать каналы для уведомлений.

**Как отключить уведомления в нерабочее время?**
Профиль → Preferences → Notifications → Do Not Disturb (DND). Задать расписание.

**Что такое Slack Workspace?**
Workspace — организация/команда в Slack; свои каналы, пользователи, приложения. Вход по ссылке приглашения или по домену (например company.slack.com).


## Глоссарий

| Термин | Описание |
|--------|----------|
| **Channel** | Канал — общий чат по теме/проекту (#general, #dev). |
| **DM** | Direct Message — личная переписка. |
| **Thread** | Поток — ответы в ветке сообщения. |
| **@channel** | Упоминание всех в канале. |
| **@here** | Упоминание активных в канале. |
| **Pin** | Закрепление сообщения вверху канала. |
| **Webhook** | Incoming Webhook — URL для отправки сообщений в канал извне. |
| **Bot** | Приложение, отвечающее на команды в каналах и DM. |
| **Workspace** | Организация/команда в Slack; свои каналы и пользователи. |


## Чек-листы

### Создание канала

- [ ] Выбрать тип: публичный или приватный.
- [ ] Имя: префикс по типу (#proj-*, #team-*, #incident-) или по проекту.
- [ ] Описание канала: цель и правила.
- [ ] Закрепить сообщение с правилами и ссылками (Confluence, Jira).
- [ ] При необходимости настроить интеграции (Jira, CI, мониторинг).

### Настройка уведомлений

- [ ] Do Not Disturb: расписание нерабочего времени.
- [ ] Ключевые слова для упоминаний (если нужны).
- [ ] Mute малополезных каналов; приоритет важных.
- [ ] Уведомления в потоках: все ответы или только упоминания.

### Интеграция с CI/CD

- [ ] Incoming Webhook для канала (#deploy, #builds).
- [ ] Отправлять только важные события (успех/падение сборки, деплой).
- [ ] Не дублировать одни и те же алерты в несколько каналов.


## Решение проблем

| Симптом | Возможная причина | Действие |
|--------|-------------------|----------|
| Не приходят уведомления | DND или mute канала | Проверить Preferences → Notifications; снять mute с канала. |
| Webhook не отправляет сообщения | Неверный URL или права | Проверить URL в настройках канала; пересоздать Webhook при необходимости. |
| Не вижу канал | Приватный канал, нет приглашения | Запросить приглашение у участников или админов workspace. |
