# Sourcegraph Cody: основы

Sourcegraph Cody — AI-ассистент, тесно интегрированный с **поиском по коду и индексом Sourcegraph**. Его ключевая особенность — умение:

- находить и использовать **релевантный контекст** из большого репозитория;
- опираться на **code graph**, а не только на открытые файлы;
- работать с **Prompt Library и командами**, которые можно переиспользовать в команде.

**Цель документа** — показать, как практически использовать Cody в IDE и через веб-интерфейс Sourcegraph.

## Введение

В отличие от «локальных» ассистентов, работающих только с открытыми файлами, Cody:

- тесно интегрирован с Sourcegraph;
- умеет строить **code graph** (связи между файлами, символами, вызовами);
- использует несколько механизмов поиска контекста:
  - Sourcegraph Search;
  - keyword search;
  - анализ структуры кода.

Это делает Cody особенно полезным для:

- больших монорепозиториев;
- проектов с богатой историей и сложной архитектурой;
- сценариев, где важно **быстро находить нужные фрагменты** по смыслу, а не только по тексту.

## Установка и подключение к Sourcegraph

Cody доступен:

- как расширение для:
  - VS Code;
  - JetBrains IDE;
  - Visual Studio;
- как часть веб-интерфейса Sourcegraph.

Общий поток:

1. Установить расширение в IDE.
2. Подключить его к вашему инстансу Sourcegraph (cloud или self-hosted).
3. Авторизоваться с помощью аккаунта Sourcegraph.

После этого:

- Cody получает доступ к индексированным репозиториям;
- может использовать code graph и поиск как источники контекста.

## Основные возможности

### Чат

Чат в Cody:

- принимает промпты в духе:
  - «объясни этот код»;
  - «найди все места, где используется X»;
  - «предложи рефакторинг».
- использует:
  - открытый файл;
  - репозиторий;
  - дополнительно указанный контекст (через `@`).

### Команды

Sourcegraph предоставляет готовые команды (по документации):

- `explain` — объяснение кода;
- `doc` — генерация документации;
- `test` — генерация юнит-тестов;
- `edit` — правка и исправление кода;
- `smell` — улучшение качества.

Также поддерживаются **custom commands** (в формате JSON), которые можно:

- настраивать под свои процессы;
- делиться ими внутри команды;
- привязывать к специфическим сценариям (анализ логов, линтер-отчётов и т.п.).

### Prompt Library

Prompt Library позволяет:

- сохранять и переиспользовать удачные промпты;
- делиться ими с коллегами;
- создавать каталог «рецептов» под разные задачи:
  - ревью;
  - миграции;
  - тестирование;
  - документация.

## Контекст в Cody

### Code graph и поиск

Cody использует:

- **code graph** для:
  - понимания зависимостей и связей;
  - поиска вызовов и реализаций;
- **Sourcegraph Search** для:
  - полнотекстового поиска;
  - поиска по структуре (regexp/structural search).

Это позволяет:

- находить контекст не только по точному тексту, но и по структуре;
- привязывать ответы к реальным местам в коде, а не к абстрактным примерам.

### Управление контекстом через @

В промптах можно явно указывать контекст:

- `@repo` — репозиторий;
- `@file` — файл;
- `@symbol` — символ;
- `@url` — веб-страница (для некоторых клиентов).

Это полезно, когда:

- вы хотите сузить область поиска;
- нужен конкретный набор файлов/символов;
- вы комбинируете несколько источников (несколько репозиториев).

## Типовые сценарии

### Объяснение и поиск кода

Примеры запросов:

- `Объясни, где и как в этом репозитории реализована аутентификация пользователей.`
- `Найди все места, где используется интерфейс PaymentProvider, и опиши их роли.`

### Рефакторинг и улучшение качества

Используя команды вроде `smell` и `edit`, можно:

- находить «пахнущий» код (избыточная сложность, дублирование);
- предлагать локальные улучшения;
- постепенно приводить проект к более чистому стилю.

### Генерация тестов и документации

С помощью `test` и `doc`:

- генерировать черновики тестов;
- писать краткие описания модулей;
- формировать skeleton-документацию, которую вы потом дорабатываете вручную.

## Лучшие практики

- Использовать Cody не как замену обзору кода, а как помощника в навигации и первичном анализе.
- Чётко указывать контекст через `@`, особенно в больших монорепах.
- Хранить важные промпты и команды в Prompt Library, а не держать всё в голове.
- Синхронизировать использование Cody с архитектурной документацией:
  - чтобы ответы не противоречили установленным правилам и паттернам.
