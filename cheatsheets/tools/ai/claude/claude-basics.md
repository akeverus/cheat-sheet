# Claude Code: основы

Claude Code — это AI-ассистент от Anthropic, ориентированный на работу с кодом в IDE (VS Code, JetBrains) и терминале. Сильные стороны Claude — **длинный контекст**, аккуратная работа с диффами и хороший «аналитический» режим: объяснение сложного кода, рефакторинг, разбор архитектуры.

**Цель этого документа** — показать, как настроить и использовать Claude Code в типичном рабочем процессе разработчика: от установки до продвинутых сценариев с длинным контекстом.

## Введение

Claude Code позиционируется как «AI coding agent»:

- умеет **читать и понимать большие куски кода**;
- предлагает изменения через **чёткие диффы**;
- показывает **план действий** перед тем, как вносить изменения.

По сравнению с другими ассистентами:

- сильнее в **длинном контексте и анализе**;
- часто даёт более развёрнутые и аккуратные объяснения;
- удобен для задач вида «разберись с этим большим модулем и предложи рефакторинг».


## Установка и активация

### Поддерживаемые IDE

На момент 2026 года Claude Code официально поддерживает:

- **VS Code** (основная и самая зрелая интеграция);
- **JetBrains IDE**:
  - IntelliJ IDEA;
  - PyCharm;
  - WebStorm;
  - GoLand;
  - PhpStorm;
  - Android Studio.

### Установка в VS Code

1. Откройте VS Code.
2. Перейдите в Extensions (`Ctrl+Shift+X` / `Cmd+Shift+X`).
3. Найдите расширение `Claude Code` от Anthropic.
4. Установите и перезапустите IDE при необходимости.

После установки появятся:

- иконка Claude в боковой панели;
- пункт контекстного меню для работы с выделенным кодом;
- горячие клавиши для открытия панели Claude (смотрите описание расширения).

### Установка в JetBrains IDE

1. Откройте `Settings` `Plugins`.
2. Найдите `Claude Code` (или `Anthropic Claude Code`) в JetBrains Marketplace.
3. Установите плагин и перезапустите IDE.
4. После перезапуска появятся:
   - панель Claude;
   - горячие клавиши (например, `Cmd+Esc`/`Ctrl+Esc`) для вызова ассистента;
   - пункты меню для работы с выделенным кодом.

### Авторизация через Anthropic

Для работы Claude Code требуется:

- аккаунт Anthropic;
- действующая подписка/доступ к Claude (в зависимости от тарифа).

Обычно процесс авторизации:

- при первом запуске ассистента IDE предложит войти в аккаунт;
- откроется браузер с подтверждением доступа;
- после успешного входа IDE сохранит токен и включит AI-функции.


## Основные возможности Claude Code

### Чат с учётом контекста IDE

Claude Code предоставляет чат-панель, в которой:

- можно задавать вопросы про конкретный файл или выделенный код;
- ассистент автоматически подтягивает:
  - содержимое активного файла;
  - выбранный фрагмент;
  - иногда диагностические сообщения (ошибки компиляции, линтера).

Примеры запросов:

- `Объясни, что делает этот класс и как он вписывается в общую архитектуру.`
- `Предложи рефакторинг этого метода, чтобы его было проще тестировать.`
- `Помоги исправить эту ошибку компиляции / линтера.`

### Диффы и план изменений

Ключевая особенность Claude Code:

- он **редко меняет код «тихо»**;
- обычно:
  - сначала предлагает **план** (список шагов/файлов);
  - затем показывает **диффы** в удобном формате;
  - даёт возможность принять/отклонить изменения.

Преимущества:

- легче контролировать, что именно меняется;
- проще объяснить изменения в PR (можно использовать план и комментарии Claude);
- снижает риск «скрытых» изменений в неожиданных местах.

### Упоминания файлов и диапазонов строк

Claude Code поддерживает ссылку на файлы и конкретные строки, например:

- `@src/orders/OrderService.java#12-80`;
- `@frontend/components/Checkout.tsx#all`.

Это упрощает:

- указание контекста (не нужно копировать весь код в чат);
- обсуждение нескольких файлов сразу;
- ссылку на конкретные участки кода в обсуждениях.

### Длинный контекст

Модели Claude известны **большим контекстным окном**:

- они могут «держать в голове» значительную часть проекта;
- это полезно для:
  - обзорных задач;
  - анализа архитектуры;
  - миграций в нескольких модулях.

Тем не менее:

- «бесконечного» контекста нет — лучше всё равно **сузить область** явно;
- полезно давать ассистенту краткое текстовое резюме перед большим объёмом кода.


## Claude Code в VS Code

### Запуск и интерфейс

Обычно в VS Code:

- слева появляется иконка Claude;
- кликая по ней, вы открываете чат-панель;
- можно запускать Claude и через горячую клавишу (смотрите настройки расширения).

Типичный поток:

1. Открыть файл/файлы, с которыми вы работаете.
2. Выделить фрагмент кода (опционально).
3. Открыть чат Claude.
4. Задать вопрос или описать задачу.

### Типичные горячие клавиши

Точные комбинации зависят от версии расширения и вашей раскладки, но обычно есть:

- **открытие панели Claude**;
- **вызов действий над выделенным кодом** (например, «объяснить», «рефакторинг», «написать тесты»).

Рекомендуется:

- проверить описание расширения в VS Code Marketplace;
- при необходимости переназначить ключевые команды под свою раскладку.

### Поток работы с диффами

При запросах вида «перепиши», «отрефакторь», «исправь ошибку» Claude Code:

- генерирует **предложенные изменения**;
- показывает их в виде диффа:
  - слева — старый код;
  - справа — новый;
- даёт возможность:
  - принять изменения полностью;
  - частично;
  - отклонить.

Хорошая практика:

- просматривать диффы **как при обычном ревью**;
- проверять:
  - не изменилось ли поведение неожиданным образом;
  - не нарушены ли неформальные инварианты;
  - не добавлены ли лишние зависимости.


## Claude Code в JetBrains IDE

### Интеграция с диагностикой IDE

Плагин Claude Code для JetBrains умеет:

- использовать сообщения компилятора и линтера как часть контекста;
- помогать исправлять ошибки, ссылаясь на диагностику:
  - «исправь предупреждения в этом файле»;
  - «помоги переписать этот участок так, чтобы исчезла ошибка X».

Это особенно полезно, когда:

- много подсвеченных проблем в одном файле;
- нужно быстро привести код к «зелёному» состоянию.

### Диффы через встроенный viewer

JetBrains IDE имеет мощный встроенный дифф-viewer:

- Claude Code использует его для отображения предлагаемых изменений;
- вы видите дифф так же, как при сравнении веток или коммитов.

Преимущество:

- знакомый интерфейс;
- интеграция с остальными инструментами IDE (аннотации, поиск, навигация).


## Claude Code CLI

### Базовые команды

Claude Code предоставляет CLI-интерфейс (конкретный бинарь и флаги уточняйте в официальной документации), который обычно поддерживает команды вида:

```bash
claude          # запуск интерактивной сессии
claude -p       # запуск с промптом из файла
claude -c       # работа с сохранёнными сессиями/контекстами
```

В терминале IDE это позволяет:

- работать с Claude параллельно с разработкой;
- запускать сценарии, не отвлекаясь на GUI.

### Рабочие сценарии в терминале

Примеры:

- быстрые вопросы по синтаксису и API;
- генерация CLI-утилит и скриптов;
- объяснение логов/трейсов (при условии, что вы не нарушаете политику по данным).


## Работа с контекстом и большими проектами

### Как Claude выбирает контекст

Claude Code учитывает:

- активный файл и выделенный текст;
- иногда — соседние файлы/модули;
- открытые вкладки;
- сообщения диагностики.

Важно:

- **яно выделенный** фрагмент почти всегда считается важным;
- текстовое описание задачи помогает ассистенту правильно расставить приоритеты.

### Явное управление контекстом

Чтобы улучшить ответы:

- указывайте файлы и строки явно через `@file#start-end`;
- давайте краткое текстовое резюме:

```text
Это модуль, который отвечает за выставление счетов.
Основные сценарии: создание, обновление, отмена инвойса.

Посмотри на @src/billing/InvoiceService.kt#10-220 и
@src/billing/InvoiceRepository.kt#all и:
- опиши общую архитектуру;
- предложи улучшения по разделению ответственности.
```

### Стратегии для монореп и больших кодовых баз

В монорепах и больших проектах:

- не пытайтесь «кормить» ассистенту сразу весь репозиторий;
- делите задачу:
  - сначала обзор архитектуры (несколько ключевых модулей);
  - затем работа с конкретным модулем/фичей;
  - потом — интеграция изменений.

Полезно:

- иметь краткие overview-документы по модулям;
- давать Claude ссылки именно на них как начальный контекст.


## Типовые сценарии использования

### Объяснение и навигация по legacy-коду

Claude особенно полезен, когда:

- вы впервые заходите в большой legacy-модуль;
- документация устарела или отсутствует;
- нужно быстро понять, «как всё устроено».

Пример промпта:

```text
Я впервые смотрю на модуль @modules/legacy-orders/.

Задача:
- опиши, какие здесь есть основные сущности и сервисы;
- нарисуй текстовую картинку потока обработки заказа:
  - от приёма запроса до записи в БД;
- укажи, какие части кода выглядят хрупкими или требуют рефакторинга.
```

### Рефакторинг с предварительным планом

Один из сильных паттернов Claude:

- сначала просить **план рефакторинга**;
- затем — реализацию по шагам.

Пример:

```text
Нужно отрефакторить @src/payments/PaymentService.ts:
- слишком много обязанностей;
- трудно покрыть тестами.

Сделай, пожалуйста:
1) Предложи план рефакторинга (шаги, цели каждого шага).
2) Покажи, как будет выглядеть новый интерфейс сервиса.
3) Предложи пример разделения на под-сервисы или helper-классы.
```

### Подготовка и ревью PR

Claude может:

- кратко описать изменения;
- подсветить риски;
- предложить вопросы к автору.

Пример:

```text
Посмотри на изменения между main и branch feature/new-discounts.

Сделай:
- краткое описание изменений по модулям;
- список возможных рисков (перформанс, совместимость, безопасность);
- 5–7 вопросов к автору PR.
```

### Генерация тестов и сценариев

Claude хорошо справляется с:

- генерацией тестов на основе бизнес-описания;
- предложением edge-cases.

Пример:

```text
Вот описание бизнес-правил для скидок (см. @docs/discount-rules.md).

Посмотри также код @src/discounts/DiscountService.kt и:
- предложи полный набор тест-кейсов;
- сгенерируй unit-тесты в стиле существующих тестов в @src/discounts/DiscountServiceTest.kt;
- отдельно перечисли boundary-cases, которые важно не забыть.
```


## Лучшие практики

- Всегда начинать с **плана** при больших изменениях.
- Указывать ограничения:
  - не менять публичный API;
  - не добавлять новые зависимости;
  - не ломать контракт по логированию/метрикам.
- Делить задачи на шаги:
  - сначала архитектурное предложение;
  - потом реализация в одном модуле;
  - затем распространение паттерна.
- Использовать длинный контекст осознанно:
  - не загружать всё подряд;
  - давать ассистенту краткое summary в начале.


## Распространённые ошибки и анти-паттерны

- Просить Claude «сделать всё сразу» на уровне всего репозитория.
- Принимать диффы без ревью.
- Пытаться использовать Claude как «одиночный компилятор архитектурных решений» без участия команды.
- Игнорировать лимиты контекста и давать хаотичный набор файлов без объяснений.


## Частые вопросы

**Q: Чем Claude Code отличается от обычного Claude в браузере?**
A: IDE-интеграция даёт доступ к коду, структуре проекта, диагностике и удобным диффам. В браузерной версии всё это нужно подгружать вручную.

**Q: Можно ли использовать Claude Code вместе с другими AI-инструментами (Copilot, Cursor и т.п.)?**
A: Технически да, но важно не создавать «зoo из ассистентов», где каждый вносит свои изменения. Лучше договориться, какой инструмент за что отвечает.

**Q: Насколько безопасно использовать Claude Code с приватным кодом?**
A: Ответ зависит от политики Anthropic и вашей компании. Обязательно изучите официальные документы по безопасности и согласуйте использование с ответственными лицами.


## Чек-листы

### Перед использованием Claude Code в проекте

- [ ] Проверены юридические и безопасностные требования.
- [ ] Понятно, для каких задач мы будем использовать Claude Code.
- [ ] Настроены базовые инструкции/документация по архитектуре проекта.

### Для задач по рефакторингу

- [ ] Есть чётко сформулированная цель рефакторинга.
- [ ] Я попросил(а) сначала план, а не сразу изменения.
- [ ] Я ревьюю каждый дифф перед применением.
