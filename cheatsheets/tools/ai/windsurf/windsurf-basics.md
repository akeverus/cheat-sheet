# Windsurf: основы

Windsurf — это IDE от Codeium, изначально спроектированная как **AI-first редактор**. В отличие от классических IDE с «добавленным» ассистентом, Windsurf строится вокруг:

- **Command** — инлайн-команд для изменения кода по описанию;
- **Cascade** — агентного чат-режима;
- **глубокой интеграции с терминалом и web search**.

Этот документ фокусируется на практическом использовании Windsurf как основного рабочего инструмента разработчика.

## Введение

Windsurf стремится объединить:

- классическую продуктивность VS Code-подобных IDE;
- мощный AI-ассистент (Codeium);
- агентный режим с поддержкой web search.

Если Cursor делает упор на агентов и MCP, а Copilot — на автодополнение, то Windsurf:

- фокусируется на **Command** как основном инструменте редактирования;
- предлагает **Cascade** как «долгоживущего» помощника с памятью и веб-поиском;
- тесно связывает AI с терминалом (включая авто-предложения команд).


## Установка и первый запуск

### Поддерживаемые платформы

Согласно документации, Windsurf поддерживает:

- macOS (Yosemite и новее);
- Windows 10+;
- Linux (Ubuntu 20.04+, glibc 2.28+ или совместимые дистрибутивы).

### Onboarding и импорт настроек

При первом запуске Windsurf предлагает:

- **Start fresh** — начать с чистой конфигурации;
- **Import from VS Code** — импорт тем, keybindings, расширений;
- **Import from Cursor** — если вы мигрируете с Cursor.

Рекомендации:

- импортируйте только то, что действительно нужно (темы, шрифты, ключевые плагины);
- не тащите весь исторический «мусор» расширений;
- настройте keybindings так, чтобы не конфликтовать с Command/Cascade.


## Ключевые компоненты Windsurf

### Autocomplete

Codeium Autocomplete:

- даёт контекстно-зависимые подсказки по коду;
- работает в большинстве распространённых языков;
- может использовать контекст файла и проекта.

Используйте его как:

- способ ускорить написание повторяющихся конструкций;
- черновик кода, который вы потом дорабатываете.

### Command

Command — это «режим трансформации кода»:

- запускается через горячую клавишу (например, `Cmd+I` / `Ctrl+I`);
- вы применяете его к:
  - выделенному коду;
  - целому файлу;
  - иногда — к нескольким файлам (зависит от сценария).

Типичные запросы:

- «Перепиши на async/await»;
- «Сделай этот код более идиоматичным для Go»;
- «Удалить дублирование с функцией X».

Результат:

- Windsurf показывает предложенный diff;
- вы можете принять/отклонить/отредактировать его.

### Cascade (чат-агент)

Cascade — чат-агент с:

- поддержкой нескольких моделей (Llama 3, GPT-4o, Claude 3.5 и др., в зависимости от тарифа);
- памятью и историей разговоров;
- возможностью использовать web search.

Cascade хорош для:

- сложных архитектурных вопросов;
- пошаговых сценариев (разработка фичи, миграция, оптимизация);
- объяснения кода и генерации документации.

### Интегрированный терминал

Терминал Windsurf:

- интегрирован с AI:
  - можно просить Command сгенерировать команду;
  - можно позволить агенту предлагать действия;
- может иметь уровни auto-execution (какие команды можно выполнить автоматически).

Рекомендуется:

- не разрешать автоматический запуск **разрушительных команд**;
- всегда просматривать, что именно предлагает агент в терминале.

### Web Search

Web Search в Cascade позволяет:

- подтягивать актуальную документацию;
- сверять версии библиотек;
- получать свежие ответы по экосистеме.

Нужно учитывать:

- web search расходует кредиты (для платных тарифов) — следите за лимитами;
- ответы могут содержать внешние ссылки, проверяйте их сами.


## Рабочие сценарии

### Рефакторинг через Command

1. Откройте файл с целевым кодом.
2. Выделите фрагмент, который хотите изменить.
3. Нажмите горячую клавишу Command.
4. Опишите цель:
   - «разбить на более мелкие функции»;
   - «обработать ошибки через Result-тип»;
   - «убрать дублирование с методом X».
5. Просмотрите diff и примените изменения.

### Использование Cascade для сложных задач

Для задач вида «спроектировать новую фичу» или «разобраться в большом модуле»:

1. Откройте ключевые файлы.
2. Запустите Cascade.
3. Кратко опишите контекст проекта и модуль.
4. Попросите:
   - обзор архитектуры;
   - план изменений;
   - пример реализации для одного из шагов.

### Комбинация Chat + Terminal

Пример сценария:

- вы хотите:
  - настроить новый сервис;
  - добавить миграции БД;
  - обновить CI-пайплайн.

Паттерн:

1. В Cascade описать цель и окружение.
2. Попросить предложить команды/конфиги.
3. В терминале:
   - просмотреть предложенные команды;
   - выполнить вручную или с минимальной автоматизацией.


## Настройка под проект и команду

Рекомендуется:

- договориться в команде, будет ли Windsurf **основной IDE** или дополнительной;
- документировать:
  - какие фичи Windsurf использовать (Command, Cascade, web search);
  - какие — отключать или ограничивать (например, авто-выполнение команд в терминале).

Полезно завести внутренний документ:

- «Как мы используем Windsurf»;
- с разделами:
  - допустимые сценарии;
  - анти-паттерны;
  - примеры удачных промптов.


## Лучшие практики

- Использовать Command для **локальных и понятных изменений**, а не для тотальной переработки всего файла.
- Для больших задач — сначала обсуждать план в Cascade.
- Не полагаться на web search как на единственный источник правды; сверяться с официальной документацией.
- Хранить сложные успешные промпты (и сценарии) в документации проекта.


## Распространённые ошибки

- Давать Windsurf полную свободу менять проект без ревью.
- Пытаться решить через один промпт сложную миграцию.
- Разрешать автоматическое выполнение команд в терминале без логирования и контроля.
