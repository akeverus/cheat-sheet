# Datadog APM

Единая платформа мониторинга: метрики, логи, трейсы и мониторинг пользователей.

## Введение

**Datadog** объединяет метрики инфраструктуры и приложений, логи и distributed tracing в одном интерфейсе. Поддерживает Java (dd-trace-java), Kubernetes, облака и сотни интеграций.

## Основные возможности

- **APM**: транзакции, зависимости, ошибки, latency по сервисам.
- **Infrastructure**: хосты, контейнеры, Kubernetes, облачные метрики.
- **Logs**: централизованные логи, корреляция с трейсами и метриками.
- **RUM**: мониторинг фронтенда и мобильных приложений.
- **Synthetic Monitoring**: проверка доступности и сценариев извне.


## Интеграция с Java

Добавить Java Tracer при запуске:

```bash
java -javaagent:/path/to/dd-java-agent.jar \
  -Ddd.service=my-app \
  -Ddd.env=prod \
  -jar app.jar
```

Переменные: `DD_API_KEY`, `DD_SITE` (например, `datadoghq.com`). Агент автоматически инструментирует HTTP, JDBC, Redis, Kafka и другие библиотеки.


## Метрики и дашборды

- **APM**: Service Map, список сервисов, latency, throughput, error rate.
- **Metrics**: встроенные и кастомные метрики, агрегации по тегам.
- **Dashboards**: виджеты по метрикам, логам, трейсам; шаблоны для типовых стеков.


## Логи и трейсы

- Логи можно отправлять через агент или сторонние сборщики; привязка к trace_id/span_id для корреляции.
- Distributed tracing из коробки при использовании одного агента в цепочке сервисов.


## Лучшие практики

- Единообразное тегирование (env, service, version) для фильтрации и алертов.
- Настроить sampling трейсов при высокой нагрузке.
- Хранить API key в секретах; использовать отдельные ключи для dev/stage/prod.
- Использовать Service Map для понимания зависимостей и узких мест.


## Решение проблем

| Симптом | Возможная причина | Решение |
|--------|-------------------|---------|
| Трейсы не появляются в UI | Агент не подключён или неверный `DD_API_KEY` | Проверить логи агента (`dd-trace-java`), убедиться в корректности API-ключа и `DD_SITE` |
| Высокое потребление памяти агентом | Слишком большой объём трейсов (все запросы без sampling) | Включить sampling (`DD_TRACE_SAMPLE_RATE`), ограничить буфер трейсов |
| Логи не связываются с трейсами | Не настроена injection trace_id в логи | Добавить `dd.trace_id` и `dd.span_id` в MDC логгера (Logback/Log4j2) |

## Частые вопросы

**Чем Datadog отличается от open-source решений (Prometheus + Grafana)?**
Datadog — SaaS-платформа «всё в одном»: метрики, логи, трейсы, RUM и алерты с единым UI. Prometheus + Grafana требуют самостоятельного развёртывания и интеграции отдельных компонентов, но дают полный контроль и отсутствие vendor lock-in.

**Как снизить стоимость Datadog при большом объёме данных?**
Настроить sampling трейсов, ограничить количество custom-метрик, использовать фильтры логов для исключения шума, настроить политики retention.

**Можно ли использовать Datadog вместе с OpenTelemetry?**
Да. Datadog поддерживает приём данных по протоколу OTLP. Можно инструментировать приложение через OpenTelemetry SDK и отправлять данные в Datadog.
