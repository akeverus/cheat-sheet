## Введение

**Burp Suite** — набор инструментов для тестирования безопасности веб-приложений (PortSwigger). Редакции: **Community** (бесплатная — базовый Proxy и ручные инструменты) и **Professional** (платная — автоматический Scanner, Collaborator, расширенные функции). Трафик браузера идёт через **Burp Proxy**; запросы и ответы можно просматривать, менять и пересылать в Repeater, Intruder, Scanner и др.

### Зачем Burp Suite

- **Единая платформа** — Proxy, Scanner, Repeater, Intruder, Decoder, Comparer в одном приложении; общая история и контекст.
- **Ручное тестирование** — перехват запросов, подстановка payload, проверка граничных значений и инъекций.
- **Автосканирование** (Professional) — поиск уязвимостей по OWASP Top 10 и другим векторам.
- **Расширяемость** — BApp Store, расширения (Python, Java), макросы и обработка сессии для обхода защиты и автоматизации.
- **Отчёты** — экспорт в HTML, интеграция с трекерами (Jira и др.).

### Основные концепции

| Концепция | Описание |
|-----------|----------|
| **Proxy** | HTTP/HTTPS-прокси; браузер шлёт трафик на Burp (например, `127.0.0.1:8080`); Burp перехватывает, показывает и может менять запросы/ответы. |
| **Intercept** | Режим перехвата: запросы останавливаются в Burp до нажатия **Forward** или **Drop**. |
| **Target** | Карта хостов и путей по трафику; задаёт область сканирования. |
| **Scanner** (Pro) | Автосканирование на уязвимости (SQLi, XSS, SSRF и т.д.); настраиваемые конфигурации сканирования. |
| **Repeater** | Ручная отправка запроса с редактированием; удобен для воспроизведения и вариаций одного запроса. |
| **Intruder** | Автоматическая подстановка payload в выбранные позиции (фаззинг, перебор паролей, поиск скрытых параметров). |


## Установка и настройка

### Требования

- **Java** 11 или 17 (рекомендуется для Burp Suite 2023+). Проверка: `java -version`
- **ОС:** Windows, macOS, Linux

### Установка

1. Скачать установщик или JAR с [portswigger.net/burp/communitydownload](https://portswigger.net/burp/communitydownload) (Community или Professional).
2. **Windows/macOS:** запустить установщик и следовать шагам.
3. **JAR:** `java -jar burpsuite_community.jar` или `burpsuite_pro.jar`.
4. При первом запуске — временный проект или сохранение проекта на диск.

### Настройка браузера для Proxy

1. В Burp: **Proxy Options** — включён **Proxy listener** (по умолчанию `127.0.0.1:8080`).
2. В браузере: ручной HTTP/HTTPS-прокси на `127.0.0.1`, порт `8080`.
3. Установить **CA-сертификат Burp** для HTTPS: в браузере открыть `http://burp` или **Proxy Options Import / export CA certificate** установить в доверенные корневые центры.

После настройки весь трафик идёт через Burp; при **Intercept is on** запросы останавливаются для просмотра и правки.

### Проверка

- Открыть любой HTTPS-сайт в браузере — в **Proxy HTTP history** должны появиться запросы.
- Отправить запрос из истории в **Repeater** (ПКМ Send to Repeater) и нажать **Send** — должен прийти ответ.


## Proxy

### Intercept

- **Intercept is on** — запросы (и при необходимости ответы) останавливаются; кнопки **Forward**, **Drop**, **Intercept is off**.
- Редактирование: изменить метод, URL, заголовки, тело — нажать **Forward**.

### HTTP history

- Список всех запросов и ответов через Proxy; фильтры по хосту, методу, статусу, поиску.
- Действия: **Send to Repeater**, **Send to Intruder**, **Send to Comparer**, **Send to Scanner** (Pro), **Request in browser**.

### WebSockets

- **Proxy Options** — включить перехват сообщений WebSocket; история в **WebSockets history**.

### Match and Replace

- **Proxy Options Match and Replace** — правила автоподстановки в запросах/ответах (User-Agent, удаление токена, подстановка Cookie и т.д.).

### Invisible proxy и Scope

- **Target Scope** — что входит в область тестирования (in scope / out of scope); в Proxy и Scanner можно показывать только in-scope.
- **Proxy Options Intercept Client Requests** — какие запросы перехватывать (по URL, методу); можно исключить статику (картинки, CSS).


## Scanner

*Доступен в Burp Suite Professional.*

### Запуск сканирования

1. **Target** — добавить в scope нужный хост/URL или использовать карту из трафика.
2. **Dashboard New scan** — URL, **Crawl and audit** (обход + проверки) или только **Crawl**; выбрать **Scan configuration**.
3. Результаты в **Dashboard**; по завершении — список **issues** (уязвимости и информационные находки).

### Scan configurations

- Определяют, какие проверки выполнять (SQL injection, XSS, SSRF и т.д.), агрессивность обхода, лимиты и исключения.
- Можно создавать свои конфигурации на основе шаблонов и отключать отдельные проверки.

### Issues

- У каждой находки: тип, серьёзность (Severity), описание, путь, параметр, рекомендации, доказательство (request/response).
- **Report Export** — HTML или формат для трекера.

### Live scan и Insertion points

- **Live passive scan** — Burp пассивно анализирует трафик и добавляет замечания.
- **Audit** — активные запросы с payload; точки вставки (insertion points) задаются автоматически или вручную.


## Repeater

**Repeater** — ручная отправка HTTP-запросов с редактированием. Запрос берётся из Proxy history, Scanner или вводится вручную; после изменений — **Send**; ответ показывается рядом.

- **Вкладки** — несколько вкладок (Request 1, Request 2, …) для сравнения вариантов; переименование: ПКМ **Rename**.
- **История и комментарии** — история в текущей вкладке; можно добавлять комментарии к запросу.
- **Представления** — Raw, Pretty (JSON/HTML), Render (ответ как HTML в мини-браузере).
- **Send group** — сгруппировать вкладки и отправить все запросы группы по порядку (например, логин запрос с токеном).


## Intruder

**Intruder** — автоматическая подстановка **payload** в выбранные позиции. Применение: перебор паролей/токенов, фаззинг параметров, поиск скрытых директорий/параметров, подбор значений по коду ответа.

### Режимы (Attack type)

| Режим | Позиции | Payload | Когда использовать |
|-------|---------|---------|--------------------|
| **Sniper** | Одна (или по очереди) | Один набор | Перебор одного поля (пароль, токен) |
| **Battering ram** | Несколько | Один и тот же во все | Один payload во все позиции |
| **Pitchfork** | Несколько | Несколько наборов (i-й в i-ю позицию) | Пары имя–значение (параметр + значение) |
| **Cluster bomb** | Несколько | Несколько наборов | Все комбинации (осторожно: много запросов) |

### Позиции (Positions)

- Выделить значение в запросе **Add §** — создаётся пара маркеров **§value§**; между ними подставляется payload.
- **Clear §** — снять все; **Auto §** — автоматические позиции по параметрам (query, body, cookie).

### Payloads

- **Payload type:** Simple list, Numbers (диапазон), Brute forcer, Runtime file и др.
- **Payload Options** — файл со списком, префикс/суффикс, кодирование (URL, Base64).
- **Payload Processing** — преобразования (prefix, suffix, replace, regex, hash).

### Запуск и анализ

- **Start attack** — в таблице: запросы, статус, длина ответа, время, совпадения (Grep – Match). Сортировка и фильтры по столбцам — поиск аномалий (другая длина, код, текст).
- **Grep – Match** — подсветка ответов с заданными строками; **Grep – Extract** — извлечение значений из ответов в столбец.

### Пример

**Перебор пароля:** одна позиция в поле пароля; payload type **Simple list** из файла; анализировать по коду (200 vs 401), длине или тексту ответа.


## Decoder и Comparer

### Decoder

- Кодирование и декодирование: текст, hex, Base64, URL и т.д.; **Decode** или **Encode**; цепочка операций (например, Base64 decode URL decode).
- Используется для расшифровки токенов, анализа JWT, подготовки payload для Repeater/Intruder.

### Comparer

- Сравнение двух запросов или двух ответов (побайтово или по словам). Данные из Proxy history или Repeater (ПКМ Send to Comparer). Удобно для отличий при разных параметрах (подбор пароля, проверка timing-атак).


## Расширения (BApp, Store)

### BApp Store

- **Extender BApp Store** — встроенные расширения PortSwigger: Logger++, Autorize, Software Vulnerability Scanner и др. Установка одной кнопкой.

### Extensions (Store)

- **Extender Extensions Add** — из BApp Store или из файла (Java JAR или Python через Jython/CPython).
- Python-расширения требуют Jython или встроенного Python; скрипты могут обрабатывать запросы/ответы, добавлять вкладки, вызывать API Burp.

### Макросы и Session handling

- **Project Settings Sessions Session handling rules** — правила подстановки сессии (повторный логин по макросу при истечении сессии). **Macros** — записанная последовательность запросов (логин + получение токена); правило запускает макрос при редиректе на логин, коде 401 и т.д.
- Удобно для сканирования и Intruder на приложениях с короткой сессией или защитой от CSRF.


## Отчёты и экспорт

### Scanner (Professional)

- **Issue Report Export** — отчёт по одной находке или по всем в HTML; request/response, рекомендации. Интеграция с Jira, GitHub через плагины или экспорт в CSV/JSON.

### Proxy history и Repeater

- Копирование в буфер или сохранение в файл вручную; расширения (например, Logger++) — экспорт истории в файл или БД.

### Файл проекта

- **Project Save project** — сохранение состояния (история, настройки, расширения); **Open project** — продолжить работу.


## Лучшие практики

1. **Scope** — задавать Target scope до сканирования и перехвата, чтобы не захватывать лишние домены.
2. **HTTPS** — всегда устанавливать CA-сертификат Burp в браузер.
3. **Перехват** — использовать Intercept выборочно; отключать для статики через Intercept Client Requests.
4. **Repeater** — сохранять типовые запросы во вкладках с понятными именами; использовать Send group для сценариев.
5. **Intruder** — начинать с малого набора payload и лимита запросов; анализировать по длине, коду, Grep – Extract.
6. **Scanner** — кастомные Scan configurations под стек приложения; не запускать деструктивные проверки на продакшене без согласования.
7. **Проект** — сохранять на диск для воспроизведения и отчётности.
8. **Расширения** — только из доверенных источников; проверять права доступа.


## Решение проблем и FAQ

### Таблица типичных проблем

| Проблема | Возможная причина | Решение |
|----------|-------------------|---------|
| Браузер не открывает страницы через Burp | Прокси не настроен или порт занят | Проверить Proxy listener (8080); в браузере 127.0.0.1:8080; закрыть другие прокси |
| HTTPS не расшифровывается | CA-сертификат не установлен | Proxy Options CA certificate установить в доверенные корневые центры |
| Запросы не перехватываются | Intercept выключен или фильтр исключает | Включить Intercept is on; проверить Intercept Client Requests |
| Scanner не находит уязвимости | Scope не задан, проверки выключены, нужен логин | Добавить URL в scope; включить проверки в Scan configuration; настроить Session handling / Macros |
| Intruder слишком долго работает | Много позиций или payload (Cluster bomb) | Уменьшить набор; Sniper или Pitchfork; лимит запросов |
| OutOfMemoryError | Большая история, много данных | Увеличить heap Java (-Xmx); очистить HTTP history; сохранить и перезапустить |
| Расширение не загружается | Несовместимая версия Java/Python | Extender Errors; обновить Jython/CPython; проверить версию Burp |

### Вопросы и ответы

**Community или Professional?**
Community — бесплатно: Proxy, Repeater, Intruder, Decoder, Comparer, ручное тестирование. Professional — платная подписка: автоматический Scanner, Burp Collaborator, расширенные опции и отчёты. Для обучения и ручного тестирования достаточно Community.

**Как тестировать API с Bearer-токеном?**
Получить токен (логин через браузер или Repeater), подставить в заголовок `Authorization: Bearer <token>` в Repeater или задать правило подстановки заголовка в Session handling из макроса.

**Как снизить риск блокировки по IP в Intruder?**
Включить **throttle** (задержка между запросами), уменьшить число потоков; при необходимости — прокси-лист (Intruder Options Request Engine); тестировать на тестовой среде с отключённым rate limit.

**Запуск Burp в headless/CI?**
Burp Suite Professional поддерживает **Burp Suite Headless** для сканирования без GUI; в CI запускают headless и парсят отчёты. Community не имеет официального headless; альтернатива — OWASP ZAP с API и скриптами для CI.

**Экспорт всех запросов из Proxy history?**
Расширение Logger++ или вручную: выделить запросы и копировать; либо сохранить проект и извлечь данные из файла проекта (ZIP с XML/JSON).

## Заключение

Burp Suite — стандартный инструмент для ручного и полуавтоматического тестирования безопасности веб-приложений. Proxy, Repeater и Intruder покрывают перехват, ручную проверку и фаззинг; Scanner (Professional) ускоряет поиск уязвимостей. Используйте scope, Session handling и расширения для эффективной работы.
