## Введение

**sqlmap** — открытый инструмент для автоматического обнаружения и эксплуатации **SQL-инъекций**. Поддерживает множество СУБД (MySQL, PostgreSQL, Oracle, MSSQL, SQLite и др.), техники (boolean-based blind, time-based blind, UNION query, stacked queries и др.), обход **WAF** через **tamper**-скрипты. Запуск из командной строки; можно передать URL с параметром, сохранённый запрос из **Burp**/**ZAP** (файл или строка), cookie и заголовки для аутентификации.

### Зачем sqlmap

- **Автоматизация** — обнаружение точки инъекции и извлечение данных без ручного подбора payload.
- **Широкий охват** — множество СУБД, техник и параметров (GET, POST, Cookie, User-Agent, Referer и т.д.).
- **Tamper-скрипты** — обход WAF и фильтров (кодирование, замена ключевых слов, комментарии).
- **Интеграция** — использование запросов из Burp/ZAP (копировать запрос в файл и передать в sqlmap).
- **Этика** — использовать только на приложениях, на тестирование которых есть явное разрешение.

### Основные концепции

- **Точка инъекции** — параметр (GET, POST, Cookie, заголовок), в котором возможна подстановка SQL (например, `id=1` в URL или в теле POST).
- **Техника** — способ извлечения данных: **boolean-based blind** (по разнице ответов true/false), **time-based blind** (по задержке), **UNION query** (добавление строк в результат), **stacked queries** (несколько запросов подряд).
- **Tamper** — скрипт, преобразующий payload перед отправкой (например, замена пробелов на комментарии, кодирование кавычек).
- **Level** и **risk** — глубина тестирования (1–5) и риск (1–3); повышение увеличивает число payload и вероятность обнаружения, но может увеличить нагрузку и ложные срабатывания.


## Установка и настройка

### Требования

- **Python** 2.6+ или 3.x (рекомендуется 3.x). sqlmap — Python-скрипт.
- Проверка: `python --version` или `python3 --version`

### Установка

1. Клонировать репозиторий: `git clone --depth 1 https://github.com/sqlmapproject/sqlmap.git` или скачать архив с [sqlmap.org](https://sqlmap.org/).
2. Перейти в каталог: `cd sqlmap`.
3. Запуск: `python sqlmap.py -u "http://example.com/page?id=1"` или `python3 sqlmap.py -u "http://example.com/page?id=1"`.

Проверка:

```bash
python sqlmap.py --version
```

Ожидается вывод версии sqlmap.

### Виртуальное окружение (опционально)

```bash
python3 -m venv venv
source venv/bin/activate  # Linux/macOS
# или: venv\Scripts\activate  # Windows
pip install -r requirements.txt  # если есть
python sqlmap.py -u "http://example.com/page?id=1"
```


## Базовое использование

### Простой GET-запрос

```bash
python sqlmap.py -u "http://example.com/page?id=1"
```

sqlmap определит параметр **id** как потенциальную точку инъекции, отправит тестовые payload и выведет результат (уязвим ли параметр, какая СУБД, техника и т.д.).

### POST-запрос

```bash
python sqlmap.py -u "http://example.com/login" --data="username=admin&password=test"
```

**--data** — тело POST-запроса; sqlmap тестирует параметры **username** и **password**.

### Запрос из файла (Burp/ZAP)

Сохранить запрос из **Burp** (HTTP history → ПКМ → Copy to file) или **ZAP** (Copy as cURL или сохранить вручную) в файл `request.txt`. Запуск:

```bash
python sqlmap.py -r request.txt
```

sqlmap разберёт запрос и протестирует все параметры (GET, POST, Cookie, заголовки при необходимости).

### Указание конкретного параметра

```bash
python sqlmap.py -u "http://example.com/page?id=1&name=foo" -p id
```

**-p id** — тестировать только параметр **id**. Иначе sqlmap тестирует все параметры (id, name).

### Cookie для аутентификации

```bash
python sqlmap.py -u "http://example.com/page?id=1" --cookie="session=abc123; token=xyz"
```

**--cookie** — строка cookie для запросов; необходимо для доступа к защищённым страницам (например, после логина в Burp скопировать cookie и передать в sqlmap).


## Параметры и опции

### Основные

| Параметр | Описание |
|----------|----------|
| **-u URL** | URL с параметрами (точка инъекции) |
| **-r FILE** | Запрос из файла (Burp/ZAP) |
| **--data=DATA** | Тело POST-запроса |
| **-p PARAM** | Тестировать только указанный параметр(ы) |
| **--cookie=COOKIE** | Строка cookie |
| **--level=LEVEL** | Уровень тестирования (1–5, по умолчанию 1) |
| **--risk=RISK** | Уровень риска (1–3, по умолчанию 1) |
| **--dbms=DBMS** | Указать СУБД (mysql, postgresql, mssql, oracle и т.д.) для ускорения |
| **--technique=TECH** | Техники (B=boolean, E=error, U=union, S=stacked, T=time, Q=query) |
| **--tamper=TAMPER** | Список tamper-скриптов (через запятую) |
| **--batch** | Не задавать вопросов (все по умолчанию) |
| **--random-agent** | Случайный User-Agent |
| **--proxy=URL** | Прокси (например, http://127.0.0.1:8080 для Burp) |

| Параметр | Описание |
|----------|----------|
| **--dbs** | Перечислить базы данных |
| **-D DB** | Указать базу данных |
| **--tables** | Перечислить таблицы |
| **-T TABLE** | Указать таблицу |
| **--columns** | Перечислить столбцы |

| **--dump-all** | Извлечь данные всех таблиц (осторожно: много данных) |

## Техники инъекций

- **B (boolean-based blind)** — подстановка условий типа `AND 1=1` / `AND 1=2`; по разнице ответа (разная длина, разный текст) определяется истинность условия; посимвольное извлечение данных.
- **E (error-based)** — подстановка выражений, вызывающих ошибку СУБД с утечкой данных в сообщении об ошибке.
- **U (UNION query)** — добавление **UNION SELECT** для вывода данных в ответе приложения (если приложение отображает результат запроса).
- **S (stacked queries)** — выполнение нескольких запросов подряд (например, `; SELECT ...`); возможно при поддержке СУБД/драйвера.
- **T (time-based blind)** — подстановка выражений с задержкой (например, `SLEEP(5)`); по времени ответа определяется истинность условия; посимвольное извлечение данных.
- **Q (inline query)** — инъекция внутри запроса (например, в значении ORDER BY).

По умолчанию sqlmap пробует все техники; **--technique=BE** — только boolean-based и error-based (быстрее, меньше запросов).


## Tamper-скрипты

Tamper-скрипты преобразуют payload перед отправкой для обхода WAF и фильтров. Примеры:

- **space2comment** — замена пробелов на комментарии `//`.
- **space2plus** — замена пробелов на `+`.
- **between** — замена `>` на `BETWEEN 0 AND #` (обход фильтра `>`).
- **randomcase** — случайный регистр ключевых слов (SELECT → SeLeCt).
- **charencode** — кодирование символов (например, в CHAR()).
- **base64encode** — кодирование payload в Base64 (для отдельных параметров).
- **equaltolike** — замена `=` на `LIKE` (обход фильтра `=`).

Использование:

```bash
python sqlmap.py -u "http://example.com/page?id=1" --tamper=space2comment,randomcase
```

Несколько tamper через запятую применяются по порядку. Полный список: каталог **tamper/** в репозитории sqlmap.


## Извлечение данных

После обнаружения уязвимости:

```bash
# Перечислить базы данных
python sqlmap.py -u "http://example.com/page?id=1" --dbs

# Перечислить таблицы в базе
python sqlmap.py -u "http://example.com/page?id=1" -D mydb --tables

# Извлечь данные таблицы
python sqlmap.py -u "http://example.com/page?id=1" -D mydb -T users --dump

# Извлечь только столбцы username, password
python sqlmap.py -u "http://example.com/page?id=1" -D mydb -T users -C username,password --dump
```

**--dump** сохраняет данные в каталог **output** (или --output-dir). При большом объёме использовать **--start** и **--stop** для постраничного извлечения.


## Интеграция с Burp и ZAP

### Burp

1. В Burp перехватить запрос с параметром (например, `id=1`).
2. ПКМ → **Save to file** (или Copy) → сохранить в `request.txt`.
3. Запустить sqlmap: `python sqlmap.py -r request.txt`.
4. При необходимости указать прокси Burp для просмотра запросов в Burp: `--proxy=http://127.0.0.1:8080`.

### ZAP

1. В ZAP в **History** найти запрос с параметром.
2. ПКМ → **Copy as cURL** или сохранить запрос вручную в файл.
3. Если скопирован cURL: вставить в файл `request.txt` (формат raw HTTP) или запустить sqlmap с **-r** и вставить содержимое запроса в файл в формате HTTP (первая строка `GET /page?id=1 HTTP/1.1`, затем заголовки, пустая строка, тело если есть).
4. Запустить sqlmap: `python sqlmap.py -r request.txt`.

### Прокси

Для просмотра запросов sqlmap в Burp/ZAP указать прокси:

```bash
python sqlmap.py -u "http://example.com/page?id=1" --proxy=http://127.0.0.1:8080
```

В Burp/ZAP включить перехват и настроить браузер/инструмент на прокси; sqlmap отправит запросы через прокси — они появятся в History.


## Лучшие практики

1. **Разрешение** — использовать только на приложениях, на тестирование которых есть явное письменное разрешение (заказчик, bug bounty, своё приложение).
2. **Точка инъекции** — по возможности указывать **-p** для тестирования только подозрительного параметра; иначе sqlmap тестирует все параметры (дольше и больше запросов).
3. **Cookie и заголовки** — при тестировании защищённых страниц передавать **--cookie** (и при необходимости --headers) из сохранённого запроса Burp/ZAP.
4. **Level и risk** — начинать с **--level=1 --risk=1**; при необходимости повышать (level 2–3 для Cookie и User-Agent, risk 2–3 для более агрессивных payload).
5. **Tamper** — при наличии WAF пробовать tamper (space2comment, randomcase, between и т.д.); комбинировать несколько.
6. **--batch** — в CI использовать **--batch** для неинтерактивного режима (все вопросы по умолчанию).
7. **--output-dir** — сохранять логи и дампы в отдельный каталог для отчётности и воспроизведения.


## FAQ и решение проблем

| Проблема | Возможная причина | Решение |
|----------|-------------------|---------|
| Не находит инъекцию | Параметр не уязвим, WAF блокирует | Проверить вручную (`'`), попробовать `--tamper`, повысить `--level`/`--risk` |
| 403/401 на все запросы | Нужна аутентификация | Передать `--cookie` из Burp/ZAP; `--headers` с Authorization |
| Слишком долго | Много параметров, time-based | Указать `-p` для одного параметра; `--technique=BE` |
| Connection refused | Неверный URL или прокси | Проверить URL; при `--proxy` проверить, что Burp/ZAP на порту 8080 |
| Ложное срабатывание | Разные ответы не из-за SQL | `--string`/`--not-string` для привязки к контенту |

**sqlmap или ручная проверка?** sqlmap ускоряет обнаружение и извлечение после первичного выявления подозрительного параметра. Для первичного поиска — Burp/ZAP, затем передать запрос в sqlmap.

**POST с JSON?** Сохранить запрос из Burp/ZAP в файл → `-r request.txt`. Либо `--data='{"id":1}' -p id`.

**Обход WAF?** `--tamper` (space2comment, randomcase, between, charencode); `--random-agent`; повышать `--level`/`--risk`.

**CI?** Запускать с `--batch`, `-u`/`-r`, `--dbs`/`--tables`; при наличии уязвимости — fail. Только на тестовых стендах.

**Заголовки?** `--headers="Authorization: Bearer token\nX-Custom: value"` или `-r` с файлом запроса.


## Глоссарий

| Термин | Описание |

| **Stacked queries** | Выполнение нескольких запросов подряд (;) |
