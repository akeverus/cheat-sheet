## Введение

**k6** — открытый инструмент нагрузочного тестирования. Сценарии пишутся на **JavaScript** (ES6+), запуск из командной строки. Поддержка **HTTP**, **WebSocket**, **gRPC**; метрики и отчёты по умолчанию; интеграция с **Grafana**, **InfluxDB**, **Prometheus** и k6 Cloud.

### Зачем k6

- **Один язык** — JavaScript, низкий порог входа для фронтенда и Node.js.
- **Гибкая нагрузка** — VUs, stages (разгон, стабильная нагрузка, снижение), сценарии с разными исполнителями.
- **Thresholds** — критерии успеха/провала по метрикам (время отклика, доля ошибок); удобно для CI.
- **Расширяемость** — xk6 для своих протоколов.

### Основные концепции

| Концепция | Описание |
|-----------|----------|
| **VU (Virtual User)** | Виртуальный пользователь; выполняет итерации сценария |
| **iteration** | Одно выполнение цикла (функция `default` или сценария) |
| **stage** | Фаза нагрузки: длительность + целевое число VUs |
| **scenario** | Именованный сценарий со своей логикой и executor |
| **threshold** | Критерий по метрике (например, p(95) < 500 ms, доля ошибок < 1%) |
| **check** | Проверка в коде (`response.status === 200`); влияет на метрику `checks` |


## Установка и запуск

- **Node.js** не обязателен — k6 поставляется одним бинарником. Установка: [k6.io/docs/get-started/installation](https://k6.io/docs/get-started/installation/).

**Примеры установки:**

```bash
# macOS
brew install k6

# Linux (Debian/Ubuntu) — ключ и репозиторий
sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg \
  --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update && sudo apt-get install k6

# Windows
choco install k6
```

**Проверка и запуск:**

```bash
k6 version
k6 run script.js
k6 run --vus 10 --duration 30s script.js
k6 run --stage 10s:5,30s:10,10s:0 script.js
```


## Структура теста

### Минимальный скрипт (VUs и итерации)

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 10,
  duration: '30s',
};

export default function () {
  const res = http.get('https://example.com');
  check(res, { 'status is 200': (r) => r.status === 200 });
  sleep(1);
}
```

- **options** — конфигурация: `vus`, `duration`. Каждый VU в цикле выполняет `default`; `sleep(1)` — пауза 1 с (think time).
- **check** — при неудаче метрика `checks` фиксирует провал.

### Stages (разгон и снижение нагрузки)

```javascript
export const options = {
  stages: [
    { duration: '30s', target: 10 },   // разгон до 10 VUs
    { duration: '1m', target: 10 },    // стабильно 10 VUs
    { duration: '30s', target: 0 },    // снижение до 0
  ],
};
```

### Scenarios (несколько сценариев)

```javascript
export const options = {
  scenarios: {
    browse: {
      executor: 'constant-vus',
      vus: 5,
      duration: '1m',
      exec: 'browse',
    },
    api: {
      executor: 'ramping-vus',
      startVUs: 0,
      stages: [
        { duration: '30s', target: 10 },
        { duration: '1m', target: 10 },
      ],
      exec: 'api',
    },
  },
};

export function browse() {
  http.get('https://example.com');
  sleep(2);
}

export function api() {
  http.get('https://example.com/api/status');
  sleep(1);
}
```

**Executor:** `constant-vus`, `ramping-vus`, `constant-arrival-rate`, `ramping-arrival-rate`, `per-vu-iterations`, `shared-iterations`. Поле **exec** — имя функции-сценария.

### Thresholds (критерии успеха/провала)

```javascript
export const options = {
  thresholds: {
    http_req_duration: ['p(95)<500', 'p(99)<1000'],
    http_req_failed: ['rate<0.01'],
    checks: ['rate>0.99'],
  },
};
```

- **http_req_duration** — время отклика; **p(95)<500** — 95-й перцентиль < 500 мс.
- **http_req_failed** — доля неуспешных запросов; **rate<0.01** — меньше 1%.
- **checks** — доля успешных проверок **check**; **rate>0.99** — больше 99%.

При нарушении любого порога тест завершается с ненулевым кодом (удобно для CI).


## HTTP, checks, группы

**Методы:** `http.get(url)`, `http.post(url, body)`, `http.put(url, body)`, `http.del(url)`; универсальный — `http.request(method, url, body, params)`. В **params**: `headers`, `tags`, `timeout`. Ответ: `status`, `body`, `headers`, `timings`.

**Пример POST с JSON и проверкой:**

```javascript
const payload = JSON.stringify({ name: 'test', email: 'test@example.com' });
const res = http.post('https://example.com/api/users', payload, {
  headers: { 'Content-Type': 'application/json' },
});
check(res, { 'status is 201': (r) => r.status === 201 });
const body = res.json();
if (body.id) console.log('Created user id:', body.id);
```

**group** — группировка запросов в одну метрику по времени группы:

```javascript
import { group } from 'k6';

export default function () {
  group('Главная', function () {
    http.get('https://example.com/');
    http.get('https://example.com/style.css');
  });
  group('API', function () {
    http.get('https://example.com/api/status');
  });
  sleep(1);
}
```


## Параметризация и данные

- **SharedArray** — общий массив (один раз в памяти для всех VUs): `import { SharedArray } from 'k6/data';` и `new SharedArray('name', fn)`.
- **open(path)** — чтение файла (CSV, JSON) из каталога скрипта; при больших объёмах предпочтительнее SharedArray.
- Переменные окружения: в коде `__ENV.VAR_NAME`; запуск: `k6 run -e VAR_NAME=value script.js`.
- **__VU** — номер VU (1..N); **__ITER** — номер итерации. Удобно для уникальных данных (например, `userId = __VU + __ITER * 1000`).

**Пример: SharedArray + CSV (papaparse):**

```javascript
import { SharedArray } from 'k6/data';
import http from 'k6/http';
import { check, sleep } from 'k6';
import papaparse from 'https://jslib.k6.io/papaparse/5.1.1/index.js';

const users = new SharedArray('users', function () {
  const csv = open('./users.csv');
  return papaparse.parse(csv, { header: true }).data;
});

export const options = { vus: 10, duration: '30s' };

export default function () {
  const user = users[__VU % users.length];
  const res = http.get(`https://example.com/api/users/${user.id}`);
  check(res, { 'status 200': (r) => r.status === 200 });
  sleep(1);
}
```

**Пример: авторизация (логин + токен):**

```javascript
const BASE_URL = __ENV.BASE_URL || 'https://example.com';

export default function () {
  const loginRes = http.post(`${BASE_URL}/api/login`, JSON.stringify({
    username: 'test',
    password: 'test',
  }), { headers: { 'Content-Type': 'application/json' } });
  check(loginRes, { 'login 200': (r) => r.status === 200 });
  const token = loginRes.json('access_token');
  if (!token) return;
  const apiRes = http.get(`${BASE_URL}/api/me`, {
    headers: { Authorization: `Bearer ${token}` },
  });
  check(apiRes, { 'api 200': (r) => r.status === 200 });
  sleep(1);
}
```


## Отчёты и метрики

**Основные метрики:**

| Метрика | Описание |
|---------|----------|
| **http_req_duration** | Время отклика запроса |
| **http_req_failed** | Доля неуспешных запросов (0/1) |
| **http_reqs** | Количество запросов |
| **iterations** | Количество итераций |
| **vus** | Текущее число VUs |
| **checks** | Доля успешных check |

**Вывод:** по умолчанию — текстовая сводка в консоль. Опции: `--out json=results.json`, `--out influxdb=...`, `--summary-trend-stats` (перцентили в сводке). HTML/интерактивные отчёты — k6 Cloud (`--out cloud`) или сторонние репортеры.

**Кастомные метрики:**

```javascript
import { Trend, Rate } from 'k6/metrics';

const myDuration = new Trend('my_duration');
const myRate = new Rate('my_errors');

export default function () {
  const start = Date.now();
  const res = http.get('https://example.com');
  myDuration.add(Date.now() - start);
  myRate.add(res.status !== 200);
  sleep(1);
}
```

`Trend` — время; `Rate` — доля (0 или 1). Можно использовать в **thresholds**.


## WebSocket и gRPC

**WebSocket (k6/ws):**

```javascript
import ws from 'k6/ws';
import { check } from 'k6';

export default function () {
  const url = 'wss://example.com/ws';
  const res = ws.connect(url, function (socket) {
    socket.on('open', () => socket.send(JSON.stringify({ type: 'ping' })));
    socket.on('message', (data) => {
      const msg = JSON.parse(data);
      check(msg, { 'pong': (m) => m.type === 'pong' });
    });
    socket.setTimeout(() => socket.close(), 5000);
  });
  check(res, { 'status 101': (r) => r && r.status === 101 });
}
```

**gRPC (k6/net/grpc):**

```javascript
import grpc from 'k6/net/grpc';
import { check, sleep } from 'k6';

const client = new grpc.Client();
client.load(['.'], 'service.proto');

export default function () {
  client.connect('localhost:50051', { plaintext: true });
  const response = client.invoke('package.Service/Method', { requestField: 'value' });
  check(response, { 'status OK': (r) => r && r.status === grpc.StatusOK });
  client.close();
  sleep(1);
}
```


## Лучшие практики

1. **Stages** — плавный разгон и снижение нагрузки; не стартовать все VUs сразу.
2. **Thresholds в CI** — задать `http_req_duration`, `http_req_failed`, `checks`, чтобы тест падал при деградации.
3. **check** для критичных ответов — статус и при необходимости тело (JSON).
4. **sleep** для think time — например `sleep(Math.random() * 2 + 1)` для реалистичности.
5. **SharedArray** для больших данных — экономия памяти при многих VUs.
6. **group** и **tags** в запросах (`tags: { name: 'GetItem' }`) — для группировки и фильтрации метрик в отчётах и Grafana.
7. Не логировать в цикле под нагрузкой — `console.log` в `default` даёт огромный вывод; использовать выборочно.


## Таблицы справки

### Основные опции options

| Опция | Описание |
|-------|----------|
| **vus** | Число виртуальных пользователей |
| **duration** | Длительность теста ('30s', '5m') |
| **stages** | Массив `{ duration, target }` для ступенчатой нагрузки |
| **scenarios** | Именованные сценарии с executor и exec |
| **thresholds** | Критерии по метрикам |
| **maxRedirects** | Максимум редиректов (по умолчанию 10) |

### Типы executor (scenarios)

| Executor | Описание |
|----------|----------|
| **constant-vus** | Постоянное число VUs |
| **ramping-vus** | Линейное изменение VUs (stages) |
| **constant-arrival-rate** | Постоянная скорость итераций (rate, timeUnit, duration) |
| **ramping-arrival-rate** | Ступенчатая скорость итераций |
| **per-vu-iterations** | Каждый VU — фиксированное число итераций |
| **shared-iterations** | Общее число итераций распределено между VUs |

### Команды CLI

| Опция | Описание |
|-------|----------|
| **k6 run script.js** | Запуск теста |
| **--vus N** | Число VUs |
| **--duration D** | Длительность (30s, 5m) |
| **--stage D:N** | Ступень (можно несколько через запятую) |
| **--out json=file.json** | Экспорт метрик в JSON |
| **--out influxdb=URL** | Отправка в InfluxDB |
| **-e KEY=VAL** | Переменная окружения (__ENV.KEY в скрипте) |
| **--summary-trend-stats** | Перцентили в сводке |


## Решение проблем

### Таблица типичных проблем

| Проблема | Причина | Решение |
|----------|---------|---------|
| Тест падает по threshold | Порог не достигнут (p95, ошибки) | Ослабить порог или оптимизировать систему |
| Out of memory | Много VUs или большие данные | Уменьшить VUs; SharedArray; больше памяти для k6 |
| connection refused | Сервер недоступен или неверный URL | Проверить BASE_URL и доступность |
| check не срабатывает | Неверное условие или структура ответа | Проверить status/body; try/catch для JSON |
| Скрипт не найден | Неверный путь | Запускать из каталога скрипта или указать полный путь |
| __ENV не подставляется | Переменная не передана | Передать `-e VAR=value` или задать env в CI |


## Частые вопросы

- **k6 или JMeter?** — k6: JavaScript, низкие накладные расходы, удобные thresholds и CI. JMeter: GUI, много протоколов. Выбор по команде и протоколам.
- **Тело запроса из файла?** — `http.post(url, open('./body.json'), { headers: { 'Content-Type': 'application/json' } })` или подстановка через `JSON.parse(open('./body.json'))`.
- **Ограничить длительность?** — `duration` в options или в executor сценария; для stages — последняя ступень `target: 0`.


## Заключение

**k6** — удобный инструмент нагрузочного тестирования на JavaScript с гибкой настройкой VUs, stages и scenarios и встроенными thresholds для CI. Используйте **check** и **group** для валидации и группировки метрик; **SharedArray** — для эффективной параметризации. Подробнее: [k6 Documentation](https://k6.io/docs/), смежные шпаргалки — JMeter, Gatling, Artillery, обзор инструментов.
