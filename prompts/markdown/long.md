**Пример ответа (по запросу «Расскажи подробно про ConcurrentHashMap»):**
«**Под капотом:** С Java 8 вместо сегментов используется массив узлов (`Node[]`). При коллизии список в бакете преобразуется в сбалансированное дерево (RB-tree) при большом количестве элементов, что гарантирует O(log n) даже в худшем случае. Блокировка на уровне отдельного бакета (с помощью `synchronized`) или CAS-операций для head-узла.
**Из практики:** Использовал для кэша сессий в высоконагруженном API. `ConcurrentHashMap` снял узкое место, которое возникало при глобальной синхронизации `Collections.synchronizedMap`. Ключевым было использование метода `computeIfAbsent` для атомарной условной вставки.
**Нюансы:** Итераторы слабо согласованы (weakly consistent). Метод `size()` — приблизительный, `mappingCount()` точнее. Не подходит, если нужна блокировка на время всей операции (например, для атомарного перемещения данных между ключами) — нужна внешняя синхронизация.
**Код по запросу (реализация LRU-кэша):**
```java
public class ConcurrentLruCache<K, V> {
    private final ConcurrentHashMap<K, V> map = new ConcurrentHashMap<>();
    private final ConcurrentLinkedDeque<K> order = new ConcurrentLinkedDeque<>();
    private final int maxSize;

    public V get(K key) {
        // Атомарно обновляем порядок использования ключа, перемещая его в начало дека
        if (order.remove(key)) {
            order.addFirst(key);
        }
        return map.get(key);
    }

    public void put(K key, V value) {
        // Гарантируем, что старый ключ будет удален из порядка перед добавлением нового
        order.remove(key);
        order.addFirst(key);
        map.put(key, value);

        // Выполняем вытеснение по достижении лимита, удаляя самый старый элемент
        if (order.size() > maxSize) {
            K eldest = order.pollLast();
            if (eldest != null) {
                map.remove(eldest);
            }
        }
    }
}
```
**Итог:** Позволяет достичь высокой конкурентности при операциях `get`/`put`. Сложность операций в среднем O(1), но в худшем случае (дерево) O(log n). Потребление памяти выше, чем у `HashMap`, из-за накладных расходов на конкурентность.»
