# Design Brief: Editorial-редизайн (cheat-sheet quiz)

> Полная пересборка UI/UX с чистого листа. Старый «developer console» дизайн
> и все связанные файлы удаляются. Аутентичная эстетика — **Editorial / журнальная**.
> Стек неизменен: Spring Boot + Thymeleaf SSR, vanilla CSS + JS, PostgreSQL, seed-first MCQ.

## Problem

Человек готовится к техническому собеседованию. Он садится надолго: читает вопрос,
думает, отвечает, потом читает развёрнутый разбор с кодом, диаграммами и таблицами.
Текущий интерфейс мешает этому: он перегружен, «кривой», визуально шумный, не уважает
контент. Глаз не знает, куда смотреть; длинные разборы читать тяжело; ощущение —
не «спокойный кабинет для подготовки», а «сырая консолька». Пользователь сказал прямо:
текущий UI/UX максимально отвратительный, нужно с нуля.

## Solution

Превратить приложение в **журнал для подготовки**: каждый экран — разворот, где
контент (вопрос и разбор) — главный герой, а интерфейс отступает в тень. Сильная
колоночная сетка, крупная типографика-серифы для заголовков, комфортная длина строки
для чтения, тонкие линейки вместо теней-коробок, один акцентный цвет — и тот несёт
смысл (выбор / верно / важно), а не украшает. Тёмная и светлая темы — обе первого класса,
тёплые, не инвертированные. Ничего кривого: всё стоит на модуле сетки.

## Experience Principles

Три принципа, каждый разрешает напряжение. Любое дизайн-решение сверяется с ними.

1. **Чтение прежде интерфейса** — контент (вопрос, разбор, код, диаграмма) визуально
   доминирует; хром (нав, кнопки, чипы) тих и вторичен. *Разрешает:* приложение богато
   функциями ↔ нужна спокойная концентрация. Функции есть, но не кричат.
2. **Уверенность через структуру** — жёсткая колоночная сетка, ясная типографическая
   иерархия (display → heading → body → caption), тонкие линейки как разделители.
   Ничего «на глаз», всё на модуле. *Разрешает:* красота ↔ строгость. Достигаем обе через сетку.
3. **Тишина по умолчанию, акцент по делу** — один акцентный цвет = смысл (выбранный
   вариант, правильный ответ, важное); анимация только смысловая (причина→следствие),
   не декоративная; reduced-motion уважается. *Разрешает:* выразительность ↔ шум.

## Aesthetic Direction

- **Philosophy:** Editorial / Magazine (см. `/frontend-design`). Контент-led вёрстка,
  типографика делает основную работу: каждый экран — как полоса журнала.
- **Tone:** спокойный, премиальный, сосредоточенный, уважительный к читателю. Не
  «корпоративный SaaS», не «неоновая консоль», не «детская геймификация».
- **Reference points:** длинная редактура (NYT/The Guardian longread), Stripe-docs по
  ясности иерархии, Readwise/Reader по комфорту чтения, печатные учебники с фолио-нумерацией
  и колонтитулами.
- **Anti-references:** generic-AI-эстетика (фиолетовые градиенты на белом, Inter,
  предсказуемые карточные гриды), «developer console» неон, тяжёлые тени-коробки,
  эмодзи как иконки, пёстрые акценты-радуга.

### Типографика (направление; точную пару фиксирует фаза design-tokens + ui-ux-pro-max)

- **Display / заголовки:** характерный variable-сериф (кандидат — **Fraunces**): крупный
  масштаб, выразительный для заголовков вопросов и разделов.
- **Body / чтение:** читаемый сериф для длинных разборов (кандидат — **Newsreader** или
  **Source Serif 4**), line-height 1.6–1.75, длина строки 60–72ch. Журнальное чтение.
- **UI-метки / eyebrow / нав:** мелкий гротеск ИЛИ small-caps серифа с трекингом — для
  служебных подписей (FOCUS, Q14/50, лейблы). Минимум одного семейства.
- **Code:** **JetBrains Mono** (оставляем — единственный носитель «инженерности», к месту).
- **Бюджет шрифтов:** максимум 3 семейства (display-сериф + reading-сериф + mono),
  `font-display: swap`, preload только критичных. Перф важен (CLS, FOIT).

### Цвет (направление; палитру фиксирует фаза design-tokens)

- Минимализм: **бумага + чернила + один акцент**. Тёплые тона, не холодные.
- **Light:** тёплая бумага (off-white, не чистый белый), почти-чёрные чернила для текста,
  один редакторский акцент.
- **Dark:** тёплый near-black (warm charcoal, НЕ синий navy), off-white текст (не #fff),
  тот же акцент со сдвигом светлоты под контраст.
- **Акцент:** один редакторский цвет, несущий смысл. Кандидат — глубокий «editorial»
  оттенок (тёплый кирпично-красный / жжёная охра / чернильный сине-зелёный). Финал в токенах.
- Семантика (верно/ошибка/важно) — цвет ВСЕГДА дублируется иконкой/текстом (color-not-only).
- Оба контраста ≥ WCAG AA (4.5:1 body, 3:1 large), проверяем в Playwright по факту.

### Layout / детали

- Колоночная сетка (mobile 1 кол → desktop多-кол с заданными гаттерами). Асимметричный,
  но выверенный баланс.
- Тонкие **линейки (rules)** как структурные разделители вместо box-shadow-карточек.
- **Фолио-метаданные:** прогресс «Q14 / 50», тема-раздел как колонтитул.
- Drop-cap / pull-quote-приёмы для разбора и для блока «правильный ответ».
- Скругления — минимальные и единообразные (или отсутствуют, если того требует строгость).
- Тени — почти нет; глубина через линейки, типографику и воздух.

## Existing Patterns

Что в кодовой базе и как с этим обойтись (полную карту даёт server-contract-map workflow):

- **Typography (старое):** Syne / DM Sans / JetBrains Mono — DM Sans/Syne уходят,
  JetBrains Mono остаётся.
- **Colors (старое):** navy bg + indigo #7c8ff5 + amber — **удаляется целиком**, новая
  палитра в `DESIGN_TOKENS.css`.
- **Spacing:** старая шкала `--space-*` — заменяется новой 4/8-базовой шкалой в токенах.
- **CSS-файлы (удаляются):** `styles.css` (2912), `mobile-fixes.css` (73),
  `ui-refinements.css` (393). Новый единый источник — токены + посекционный CSS.
- **Шаблоны / JS (переписываются с нуля, но СОХРАНЯЮТ серверный контракт):** имена вью
  (`focus-training`, `result`, `settings`, `stats`, `session-summary`, `error`),
  model-атрибуты, POST-эндпоинты и имена полей, API (`/api/answer|hint|regenerate|favorite|feedback`),
  inline-JSON (`#topic-stats-data`), th:utext-поля, DOM-хуки для JS, a11y-каркас.
  Карту контракта см. в `SERVER_CONTRACT.md` (генерируется параллельно).
- **CSP (SecurityConfig):** style-src/script-src `'self'` + `'unsafe-inline'` + CDN
  (cdnjs, jsdelivr, fonts.googleapis/gstatic). Новый CSS — только из `/css/` своего origin;
  новые внешние хосты (иконки/шрифты) — ТОЛЬКО после добавления в CSP.
- **Тема:** `data-theme` на `<html>`, pre-paint inline-скрипт (no-FOUC) + тогл в header.
  Контракт `[data-theme=light]`/dark + `@media(prefers-color-scheme)` сохраняем.

## Key Interactions

- **Ответ на MCQ:** выбор варианта (клик/клавиша 1–9) → подсветка выбора акцентом →
  «Проверить» → плавная (150–250ms, смысловая) реакция: верный вариант помечается
  иконкой+цветом, неверный — гасится, появляются разборы по каждому варианту и кнопки
  уверенности. Без перезагрузки (AJAX), live-update stats-grid.
- **Флешкарта:** вопрос → «Показать ответ» (reveal) → оценка (grade) → следующий.
- **Навигация по сессии:** настройка фильтров → старт → поток вопросов с фолио-прогрессом
  → финиш → сводка. Чёткая «обратная дорога», предсказуемый back.
- **Тема:** тогл мгновенно меняет токены без FOUC; уважает системную тему по умолчанию.

## Responsive Behavior

- Mobile-first (375 одна колонка), `min-width` брейкпоинты 375/768/1024/1440.
- Колоночная сетка раскрывается на desktop (контент + боковые метаданные/прогресс), но
  не «десктоп, сжатый в телефон» — на мобиле реорганизация, не масштабирование.
- Touch-таргеты ≥ 44×44, инпуты ≥ 16px (нет iOS-зума), нет горизонтального скролла.
- Длина строки чтения 35–60ch (mobile) / 60–72ch (desktop).

## Accessibility Requirements

- Контраст ≥ WCAG AA в обеих темах (проверяем робастным аудитором в Playwright по факту).
- Полная клавиатура: tab-порядок = визуальный; 1–9 выбор, стрелки навигация, Enter сабмит;
  видимые focus-ring (2–4px); focus-trap в оверлее горячих клавиш.
- Семантика: заголовки по порядку, landmark-и (header/main/nav), label у инпутов,
  role=radiogroup/progressbar, aria-live для AJAX-фидбека, aria-sort у таблицы.
- color-not-only: верно/ошибка/важно — всегда иконка+текст, не только цвет.
- `prefers-reduced-motion`: отключаем/упрощаем анимации.
- Сохраняем существующий a11y-каркас (skip-link, visually-hidden, aria-keyshortcuts).

## Out of Scope

- Java-контроллеры, сервисы, доменная логика, SM-2/adaptive-difficulty алгоритм.
- Структура MCQ JSON-сидеров (`seed/mcq/<category>/<topic>.json`) — не трогаем.
- БД, миграции, persistence-слой.
- Контент шпаргалок (`cheatsheets/**`).
- AI/LLM-пайплайн (seed-first остаётся дефолтом).
- Серверный контракт (вью-имена/эндпоинты/поля) — сохраняется; меняется только под
  IA-реворк и только осознанно, с правкой контроллеров в паре.
